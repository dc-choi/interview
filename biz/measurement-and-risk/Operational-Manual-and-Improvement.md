# 업무 매뉴얼과 운영 개선

업무 매뉴얼은 반복 업무의 수행 방법과 확인 기준을 공유하는 문서다. 문서 작성, 현장 적용과 효과 확인은 서로 다른 단계다. 매뉴얼이 있다는 사실만으로 업무가 표준화됐거나 생산성이 높아졌다고 판정하지 않는다.

## 표준 절차와 현장 개선을 연결한다

표준은 현재의 수행 기준으로 쓰고, 현장에서 발견한 문제와 개선안을 다시 절차에 반영한다. 작업자가 사용하는 기준과 관리자가 승인한 기준이 다른 상태를 방치하지 않는다.

공개 사례로 MUJI의 2013년 연수 기록은 일상 업무에 MUJIGRAM을 사용하고, 관련 부서가 매뉴얼을 구성하며 품질 관리의 실제 점검표로 교육한 방식을 설명한다. MUJI REPORT 2025는 매장에서 발견한 문제와 개선안을 공유하고, 교대 일정 작성과 식품 기한 점검 등의 개선 절차를 MUJIGRAM으로 다른 매장에 전파한다고 설명한다. 이는 회사가 공개한 운영 사례이며, 매뉴얼만의 독립적인 생산성 효과를 입증한 실험은 아니다.

## 반복 업무 하나를 기준으로 작성한다

### 여러 업무를 맡을 때는 수행과 확인 책임을 나눈다

작은 사업에도 재무, 인력, 마케팅과 영업, 설비, 보안과 비상 대응처럼 서로 다른 운영 업무가 있다. 미국 SBA의 사업 관리 안내는 이 영역을 구분하고, 회계 업무에는 전문가나 온라인 서비스의 도움을 받는 선택지도 제시한다. 사업에 필요한 기능이 많다는 사실이 대표 한 사람이 모든 분야의 전문가가 되어야 한다는 뜻은 아니다. 이 구분은 운영 범위를 정하는 참고이며 미국의 세무와 고용 규정을 다른 나라에 적용하는 근거가 아니다.

다음은 소규모 사업에 적용하는 제안이다. 각 반복 업무에 **실행 담당, 결과 확인자, 완료 증거, 예외 판단자**를 붙인다. 한 사람이 여러 역할을 겸하더라도 수행 완료와 검수 완료를 따로 표시한다. 예를 들어 사진 제작을 외주로 맡겼다면 대표는 직접 촬영하는 기술보다 사용 목적, 납기와 결과물의 확인 기준을 정할 수 있다. 문의 대응은 답변 속도와 해결 여부를, 정산은 매출과 실제 입금의 대조를 확인한다. 위임이나 문서화만으로 성과가 좋아졌다고 보지 않고 재작업과 누락을 함께 관찰한다.

### 문서화할 단위를 고른다

다음은 작은 사업에 적용하기 위한 제안이다. 처음부터 회사 전체 업무를 문서화하기보다 반복 오류나 인계 공백이 있는 업무 하나를 고른다.

| 항목 | 기록할 내용 |
|---|---|
| 목적과 결과 | 누구에게 어떤 결과를 전달하며 무엇을 완료로 보는가 |
| 시작 조건 | 필요한 입력, 접근 권한과 먼저 끝나야 할 작업 |
| 수행 단계 | 실제 작업 순서와 중요한 단계의 이유 |
| 확인 기준 | 누락, 오류와 재작업을 발견할 점검 항목 |
| 예외와 책임 | 기준대로 처리할 수 없을 때 멈출 조건과 판단 담당 |
| 개정 정보 | 변경 이유, 적용 시점과 현재 정본의 위치 |

실제 업무를 수행하며 빠진 조건을 채운다. 다른 작업자가 문서를 보고 수행해 보거나, 작성자가 시간을 두고 다시 실행해 이해가 필요한 지점을 찾을 수 있다. 아직 실행해 보지 않은 단계는 검증된 절차와 구분한다.

## 개선 여부를 확인하고 개정한다

아래 순서는 현장 개선과 매뉴얼 전파 사례를 작은 업무에 연결한 운영 제안이다. 특정 주기나 수치가 보편적인 최적값이라는 뜻은 아니다.

1. **변경 전 상태:** 처리 시간, 재작업이나 누락 중 해당 업무의 문제를 보여주는 항목을 고른다.
2. **바꿀 가설:** 어떤 단계를 왜 바꾸며 무엇이 나아질지 적는다.
3. **현장 확인:** 바뀐 절차로 작업하고 고객 반응, 오류와 소요 시간을 확인한다.
4. **해석:** 작업 난도, 물량과 담당자 등 함께 바뀐 조건을 살핀다. 결과 개선을 절차 변경 하나의 효과로 단정하지 않는다.
5. **공유와 후속 확인:** 채택한 변경을 정본에 반영하고 적용 대상에게 알린다. 정기 검토 시점과 예외 발생 시 재검토 조건을 둔다.

작업 속도를 높이는 동안 품질이나 필수 검수가 나빠지지 않았는지도 함께 본다. 단순히 문서가 짧아졌거나 단계 수가 줄었다는 이유만으로 개선 완료로 처리하지 않는다.

## 작성과 이해를 따로 확인한다

완성된 문장을 읽을 수 있다는 사실과 단계의 이유를 설명하고 실행할 수 있다는 사실은 다르다. 사람이 쓰거나 AI가 보조했는지와 별개로 실제 담당자가 입력, 예외와 완료 기준을 대조해야 한다. 이는 검증을 위한 제안이며, 매뉴얼 작성에서 AI를 금지해야 한다는 연구 결과가 아니다.

## 이해 확인

- 절차를 바꾼 뒤 처리 시간이 줄었다면 어떤 조건을 더 확인해야 하는가?
- 매뉴얼에 없는 예외가 생겼을 때 작업자와 판단 담당자는 각각 무엇을 남겨야 하는가?
