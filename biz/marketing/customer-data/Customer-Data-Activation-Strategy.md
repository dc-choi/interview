# 고객 데이터 활성화의 도입 판단

고객 데이터를 통합하는 목적은 필요한 고객에게 적절한 행동을 실행하는 데 있다. 프로필을 만들고 조회할 수 있는 상태와 캠페인이 고객 행동을 바꾼 상태를 구분한다.

## 통합, 대상 선정과 실행을 나눈다

AWS의 CDP 참조 구조는 여러 접점의 데이터 수집, 고객 식별, 세그먼트 분석과 activation을 연결한다. 여기서 activation은 분석 결과를 캠페인이나 개인화 접점에서 사용하는 단계다. 통합 데이터의 보유 자체가 매출 증가를 증명하지는 않는다.

다음은 도입 전에 작성할 판단표다. 제품의 보장 사항이나 모든 기업에 적용되는 성과 공식이 아니다.

| 결정 | 확인할 질문 |
|---|---|
| 실행할 행동 | 첫 구매 안내, 재구매 제안 등 어떤 행동을 바꿀 것인가 |
| 대상 조건 | 고객군의 기간, 구매 정의와 제외 조건을 현업과 데이터 담당자가 같은 뜻으로 이해하는가 |
| 유효한 시점 | 대상 추출부터 발송까지 얼마나 늦어져도 제안이 유효한가 |
| 실행 경계 | 채널별 발송 자격, 빈도와 중단 조건을 어디서 확인하는가 |
| 측정 | 운영 시간의 변화와 고객 행동의 변화를 어떤 지표로 나누어 볼 것인가 |

예를 들어 첫 구매를 하지 않은 가입 고객에게 안내한다면, 구매 취소를 포함할지, 대상 추출 뒤 구매한 고객은 제외할지, 발송 시점에 어떤 상태를 재확인할지 먼저 정한다. CDP 도입 여부와 관계없이 필요한 운영 계약이다.

## 작은 실행 단위로 도입 가설을 검증한다

다음은 데이터 통합 구조에서 도출한 도입 점검 제안이다.

1. 한 고객군과 한 행동을 고르고, 현재 대상 추출 및 검토에 드는 시간과 오류를 기록한다.
2. 필요한 원천과 식별 규칙, 갱신 지연 및 실행 채널을 확인한다. 전체 데이터를 모으는 것을 첫 성공 조건으로 삼지 않는다.
3. 도입 전후의 준비 시간, 잘못 포함된 대상, 중복 요청과 기한 초과를 비교한다. 운영 개선과 구매 효과를 분리한다.
4. 구매 효과를 판단하려면 비교군과 기간 등 실험 조건을 별도로 설계한다. 단순 발송량, 클릭 수나 전체 매출 증가를 도구 도입의 인과 효과로 확정하지 않는다.

통합형 제품과 개별 도구의 조합을 비교할 때는 구독료뿐 아니라 연결 유지보수, 데이터 정제, 운영 인력과 이전 비용을 함께 검토한다. 구성 요소가 줄었다는 이유만으로 비용 절감률이나 매출 상승률을 고정하지 않는다.

데이터 연결과 큐 재시도 등 기술 경계는 [[Customer-Data-Activation-Pipeline|고객 데이터 통합과 활성화 파이프라인]]에서 다룬다. 이 문서는 도입 판단 기준이며 특정 서비스의 효과를 실측한 기록이 아니다.
