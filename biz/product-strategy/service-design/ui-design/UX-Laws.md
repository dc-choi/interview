# UX 심리학 10가지 법칙 (Laws of UX)

인지 심리학 연구를 UI 설계 원칙으로 정리한 법칙 모음. 이론 암기로는 실무에서 떠오르지 않는다 — 구체적 서비스 사례에 대입해 체득해야 설계할 때 무의식적인 감으로 작동한다.

## 10가지 법칙

| 법칙 | 정의 | 적용 예 |
|---|---|---|
| 제이콥의 법칙 | 사용자는 다른 서비스에서 익힌 UI 패턴을 기대한다 | 상품 상세를 일반 커머스와 같은 레이아웃으로 — 학습 비용 제거 |
| 피츠의 법칙 | 타겟 도달 시간은 거리와 크기의 함수 | 참여 기능(댓글, 작성)을 엄지가 닿는 중하단에 배치 |
| 힉의 법칙 | 선택지가 늘면 탐색과 결정 시간이 늘 수 있다 | 열린 질문 대신 사전 정의된 선택지 제공 (거래 후기) |
| 밀러의 법칙 | 7±2는 역사적 추정치이며 작업과 청킹 조건에 따라 용량이 달라진다 | 항목을 의미 단위로 묶고 실제 사용성으로 검증 |
| 포스텔의 법칙 | 원전은 입력을 폭넓게 받고 출력을 보수적으로 만들라는 견고성 원칙 | 동등한 날짜 입력 형식을 받아 정규화하고 표준 형식으로 출력 |
| 피크엔드 법칙 | 경험에 대한 회고적 평가는 강한 순간과 마지막 순간의 영향을 받을 수 있다 | 작성 완료 시 뱃지 보상, 거래 후 상호 후기로 끝맛 설계 |
| 심미적 사용성 효과 | 아름다운 디자인은 더 쓰기 쉽다고 인지된다 | 오류 페이지에 캐릭터를 넣어 부정 경험을 완화 |
| 폰 레스토프 효과 | 비슷한 것들 사이 다른 하나가 기억된다 | 핵심 액션에만 포인트 컬러 — [[Visual-Hierarchy\|시각적 위계]] |
| 테슬러의 법칙 | 일부 복잡성은 사용자와 시스템 사이에서 이동한다는 설계 휴리스틱 | 동네 범위를 직접 고르게 하지 않고 슬라이더로 — 복잡성을 시스템이 흡수 |
| 도허티 임계 | 0.4초는 역사적 상호작용 연구에서 나온 휴리스틱이지 보편적 제한이 아니다 | 제품별 측정으로 응답 목표를 정하고 지연 시 진행 상태 제공 |

## 백엔드 관점의 연결

- **0.4초를 API SLO로 그대로 옮기지 않는다** — 사용자가 기다리는 전체 경로, 네트워크와 렌더링을 측정해 p95 목표를 정한다. 즉시 완료할 수 없으면 진행 상태, 낙관적 업데이트나 비동기 처리를 검토한다.
- **포스텔의 법칙은 검증 생략 원칙이 아니다** — 신뢰 경계에서는 허용 형식을 명시하고 검증한다. 호환성을 위해 받아들인 동등한 표현만 정규화하고, 출력은 하나의 표준 형식으로 만든다.
- **테슬러의 법칙은 정량적인 보존 법칙이 아니다** — 불필요한 복잡성은 제거하고, 업무상 남는 복잡성만 사용자보다 시스템이 처리할 수 있는지 판단하는 휴리스틱이다.

## 면접 체크포인트

- 성능 목표는 실제 사용자 경로와 지연 분포로 정하고, 도허티의 0.4초는 역사적 참고값으로만 설명한다.
- 입력 검증 설계를 포스텔의 법칙으로 — 프론트 입력 제약(1차)과 서버 검증(최종 방어선)의 역할 분담.
- 기능 단순화 요구에 테슬러의 법칙으로 — 복잡성은 사라지지 않고 이동할 뿐이므로, 누가(사용자 vs 시스템) 감당할지의 의사결정임을 짚는다.
