# 업무용 제품의 처리 흐름 설계

업무용 제품은 고객의 신청부터 담당자의 검토와 처리, 결과 안내까지 연결한다. 화면 조작뿐 아니라 서류 준비, 대기와 재작업을 함께 살펴야 고객이 결과를 받는 시간을 줄일 개선 지점을 찾을 수 있다.

## 화면을 고치기 전에 업무를 관찰한다

담당자가 실제로 처리하는 한 건을 따라가며 단계, 필요한 정보와 다음 행동을 기록한다. 전화, 이메일, 엑셀과 수기 메모도 흐름에 포함한다. 도구 밖의 작업을 빠뜨리면 화면은 단순해져도 실제 부담은 그대로 남을 수 있다.

다음은 업무 관찰에 사용할 질문이다.

| 관찰 대상 | 확인할 질문 |
|---|---|
| 반복 안내 | 어떤 조건이나 제출 요건을 고객이 이해하지 못했는가? |
| 전화 확인 | 단순 설명인가, 신청 자격이나 예외를 판단하는 일인가? |
| 복사와 업로드 | 이미 받은 정보를 다시 입력하거나 옮기는 이유는 무엇인가? |
| 별도 메모 | 제품에서 표현하지 못하는 상태나 판단 근거는 무엇인가? |
| 대기 | 고객, 담당자와 다른 조직 중 누구의 다음 행동을 기다리는가? |

각 단계가 달성해야 할 목적과 현재 수행 방식을 나눈다. 꼭 필요한 확인은 유지하되 중복 입력, 불필요한 전달과 수작업 정리는 줄일 후보로 둔다. 법적 제약과 권한에 따른 확인을 화면 단순화만을 이유로 없애지 않는다.

## 접수 단계에서 보완 왕복을 줄인다

- **신청 조건을 먼저 확인한다.** 제품이 확정할 수 있는 조건은 초기에 안내한다. 불명확한 예외는 담당자 검토 경로로 보낸다.
- **상황에 맞는 자료를 요청한다.** 질문의 답에 따라 필요한 서류와 포함할 정보를 설명한다. 왜 묻는지 알리고 불필요한 정보는 받지 않는다.
- **이미 받은 정보는 재사용한다.** 고객이나 담당자가 같은 내용을 다시 옮기지 않도록 신청 정보와 제출 자료를 연결한다.
- **신청을 마칠 수 없는 경우도 살핀다.** 준비를 접수 이전으로 옮겼다면 제출 후 시간뿐 아니라 준비 시간과 중도 이탈을 함께 확인한다.

이 방식은 모든 질문을 자동 판정하라는 뜻이 아니다. 잘못된 거절과 예외 누락이 생길 수 있는 조건은 사람이 검토할 수 있어야 한다.

## 어드민은 다음 행동을 드러낸다

아래는 반복적인 신청 검토 업무에 적용할 수 있는 설계 패턴이다. 모든 제품에 같은 상태나 화면 구성을 강제하지 않는다.

| 패턴 | 적용 방법 | 확인할 한계 |
|---|---|---|
| 행동에 따른 목록 구분 | 지금 처리할 건, 외부 응답을 기다릴 건, 종료된 건을 구분 | 긴급도와 처리 기한이 다르면 접수 순서만으로 정렬하지 않음 |
| 단계별 상세 화면 | 현재 단계에 필요한 정보와 조작을 우선 배치 | 이전 판단과 이력도 필요할 때 확인할 수 있어야 함 |
| 자료와 입력 화면의 동시 조회 | 서류와 검토 항목을 함께 보여 화면 왕복을 줄임 | 작은 화면, 확대와 키보드 탐색에서도 사용 가능한지 확인 |
| 판단 근거를 포함한 체크리스트 | 확인할 대상 값과 기준을 항목 가까이에 배치 | 해당 없음이나 추가 검토가 필요한 경우를 예외 경로로 남김 |
| 보완 요청 초안 | 부족한 항목을 모아 고객에게 필요한 조치를 안내 | 자동 생성 문구의 정확성과 수신 대상을 확인 |

체크리스트는 기억 부담을 덜기 위한 도구다. 규칙 변경 시 누가 항목을 갱신할지 정하고, 목록에 없는 상황을 억지로 예 또는 아니요에 맞추지 않는다.

## 효과를 확인할 때의 측정 제안

고객 관점의 경과 시간과 담당자의 실제 작업 시간을 구분한다. 다음은 개선안을 평가하기 위한 제안이며, 특정 조직의 성과 수치를 재현한다는 보장은 아니다.

1. 신청 준비 시작, 제출, 검토 시작과 완료의 경계를 정한다. 영업일과 달력일도 구분한다.
2. 전체 소요 시간, 보완 요청 횟수와 담당자의 건당 작업 시간을 함께 본다.
3. 처리량이 늘어도 오류, 재접수나 잘못된 거절이 늘지 않았는지 확인한다.
4. 전후 비교에서는 신청 유형, 접수량과 인력 등 조건 변화를 함께 기록한다.

접수 후 시간이 줄었다는 사실만으로 고객의 전체 대기나 조직의 총작업량이 같은 비율로 줄었다고 결론 내리지 않는다. 작은 흐름 하나부터 바꾸고 [[User-Feedback|사용자 피드백]]과 관측 결과로 다음 변경을 정한다.
