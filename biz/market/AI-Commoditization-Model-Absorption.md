# 기반 모델의 기능 흡수와 AI 사업의 방어력

기반 모델이 좋아질수록 현재 모델의 부족을 메우던 기능은 차별점을 잃기 쉽다. 이 문서는 AI 응용 사업의 어느 층이 그런 흡수에 노출되고 방어력이 모델 밖의 업무 흐름, 고객 데이터, 유통, 책임과 통합 가운데 어디에 남는지 가늠하는 판단 틀과 2026년 조사, 회사 대응 사례를 정리한다.

## 정의와 핵심 질문

모델 흡수는 응용 제품이 따로 제공하던 기능이 모델 자체의 성능 향상이나 모델 공급자의 기본 기능 추가로 존재 이유를 잃는 현상을 가리킨다. 경쟁사가 기능을 베끼는 복제와 달리 언제 어떤 기능이 모델 성능이나 공급자의 기본 기능으로 들어올지 미리 알기 어렵고, 새 모델이 나올 때마다 다시 따져야 한다. 결과물이 흔해질 때 서비스 사업의 가치 이동은 [[AI-Commoditization-Differentiation|AI 범용화와 사업 차별화]]에서, 모델 공급자가 응용 시장에 직접 들어오는 위험은 [[AI-Software-Replication-and-Due-Diligence|AI 소프트웨어 복제와 기술 실사]]에서 다룬다.

- 이 기능은 지금 모델의 어떤 부족을 메우는가. 그 부족이 사라져도 고객이 계속 돈을 낼 이유가 남는가.
- 사업 계획은 모델이 지금 수준에 머문다고 가정하는가, 계속 좋아진다고 가정하는가.
- 다음 세대 모델이 나오면 우리 제품의 상대 가치가 줄어드는가, 같은 제품의 품질이 오르고 원가가 내려가는가.

## Mental model

### 두 가지 계획 가정

| 가정 | 제품을 쌓는 방식 | 모델이 좋아질 때 |
|---|---|---|
| 모델이 지금 수준에 머문다 | 현재 모델의 오답, 용어 이해 부족, 짧은 입력 한도를 메우는 기능을 쌓는다 | 메우던 부족이 줄어 기능의 차별점도 함께 줄어든다 |
| 모델이 계속 좋아진다 | 모델 능력은 빌려 쓰는 재료로 두고 모델 밖의 업무 흐름, 데이터와 책임을 쌓는다 | 같은 제품의 품질이 오르거나 원가가 내려간다 |

어느 가정이 맞을지는 미리 알 수 없으므로 두 가정에서 각각 매출과 원가를 계산해 본다. 첫째 가정에서만 성립하는 사업이라면 흡수를 사업 위험 목록에 올린다. [[AI-Commoditization-Differentiation#모델 출시와 SaaS 재평가|AI 범용화와 사업 차별화]]가 소개한 Sequoia의 구분, 곧 도구를 파는 회사는 모델과 경주하고 일을 파는 회사는 모델이 좋아질수록 서비스가 빨라지고 싸진다는 구분과 맞닿아 있다.

### 층별 흡수 노출

아래 표는 판단 틀이며 흡수 시점을 예측하지 않는다.

| 층 | 예 | 노출 | 이유 |
|---|---|---|---|
| 도메인 용어 보완 | 업종 용어와 문서 형식을 익히려는 미세조정 | 큼 | 범용 모델이 용어와 형식을 이미 처리하면 품질 차이가 준다. 가중치는 기반 모델을 바꿀 때마다 다시 학습해야 하고, 다시 쓰는 자산은 학습과 평가 데이터다 |
| 짧은 입력 한도 우회 | 컨텍스트 창이 작던 시기에 문서를 잘게 나눠 고르던 검색 래퍼 | 큼 | 작은 문서 묶음에서는 모델이 긴 입력을 직접 받아 우회 장치의 몫이 줄어든다. 코퍼스가 컨텍스트 창보다 크거나 계속 늘 때, 질의마다 전체를 넣는 토큰 비용과 지연, 긴 입력의 정보 활용 저하([[Context-Engineering#Context Rot\|Context Rot]]), 최신 정보, 권한과 출처 추적 때문에 검색은 남으므로 주로 노출되는 것은 검색 자체가 아니라 우회용 래퍼다([[RAG-Retrieval-Engineering\|RAG 검색 엔지니어링]]) |
| 모델 간 차이 보완 | 질의 난이도에 따라 상위 모델과 저가 모델을 고르는 라우팅 | 중간에서 큼 | 모델 간 가격과 성능 차이가 줄거나 공급자가 자동 선택을 기본 제공하면 독립 상품의 차별점이 준다. 라우팅을 위해 쌓은 평가 데이터와 고객별 품질 기준은 남는다([[LLM-Model-Tiers\|LLM 모델 티어 선택, 라우팅]]) |
| 업무 흐름 소유 | 고객 업무의 시작, 승인, 예외 처리와 결과 기록 | 작음 | 모델이 좋아질수록 같은 흐름의 품질과 원가가 나아진다 |
| 고객 데이터 | 업무 중에 계속 쌓이고 갱신되는 기록과 판정 신호 | 작음 | 고객 업무에서만 생기는 데이터라 모델이 좋아져도 따라 생기지 않는다([[Data-Flywheel-Moat\|데이터 플라이휠과 제품 해자]]) |
| 유통 | 고객의 업무 화면과 구매 절차 안의 위치 | 작음 | 모델이 같아질수록 고객의 업무 화면과 조달 절차 안에 먼저 들어가 있는 쪽이 새 기능도 먼저 붙인다([[AI-Commoditization-Differentiation#모델 출시와 SaaS 재평가\|AI 범용화와 사업 차별화]]) |
| 책임 | 결과 보증, 오류 보상, 규제 준수 | 작음 | 계약과 운영 체계가 필요해 모델 성능 향상만으로 생기지 않는다([[AI-Native-Services\|결과를 파는 AI 네이티브 서비스]]) |
| 통합 | 고객 시스템 연동, 권한, 감사 추적 | 작음에서 중간 | 고객별 설정과 이전 비용이 쌓인다. 표준 연동만 제공하면 모델 공급자의 연동 기능과 겹칠 수 있다 |

노출이 작다는 말은 모델 개선만으로 사라지지 않는다는 뜻이지 경쟁이 없다는 뜻이 아니다. 모델 공급자나 기존 소프트웨어 회사가 같은 업무 흐름에 직접 들어올 수 있다. 미세조정도 작은 모델로 지연과 원가를 줄이거나 데이터를 외부 모델에 보내지 않으려는 목적이라면 용어 보완과 따로 판단한다([[Task-Specific-Small-Models|작은 특화 모델]]).

## 근거

### 미세조정 경험의 감소

Theory Ventures의 AI in Practice Survey 2026은 2026-09-22에 기술 빌더 455명을 조사해 2025년 조사(413명)와 비교했다(2026-11-02 조사 페이지 확인 기준).

- 미세조정을 한 번이라도 해 본 팀은 81%에서 51%로 줄었다. 직원 1,000명 이하 기업(조사 표의 구분은 1,000명 미만)은 82%에서 38%로, 1,000명 이상 기업은 79%에서 61%로 줄었다.
- 1,000명 미만 기업에서 OpenAI RFT나 다른 유료 서비스로 미세조정했다는 응답은 두 항목을 합쳐 77%(57%와 20%)에서 19%(9%와 10%)로 줄었고, 자체 라이브러리로 했다는 응답은 5%에서 19%로 늘었다.
- 제품이 ChatGPT, Claude, Gemini 같은 프런티어 모델을 직접 쓰는 것보다 나은지 어떻게 판단하는지 묻는 2026년 조사 문항에서 7.9%가 현재로서는 목표 작업에서 프런티어 모델보다 낫지 않다는 항목을 골랐다(복수 응답 문항). 사전에 정한 평가로 판단한다는 응답은 48.8%였다.
- 질의를 여러 모델에 나누는 라우팅은 직접 만든 라우터 23.7%, proprietary 라우터(선택지 표현) 21.5%였고, 모든 질의에 같은 모델을 쓴다는 응답은 54.7%였다.

### 전문 AI 검색 서비스의 웹 방문 추세

Similarweb이 2026-08-02 공개한 분석은 2026년 5월까지의 데이터로 ChatGPT, Gemini, Claude, Perplexity를 비교했다. perplexity.ai의 방문과 순방문자는 2025년 10월 무렵 정점을 찍은 뒤 대부분의 달에 줄었고, 네 서비스 가운데 최근 추세가 하락인 곳은 Perplexity뿐이었다(2026-11-02 확인 기준). 분석은 감소 원인을 다루지 않으므로 범용 AI 서비스의 검색 기능 강화를 원인으로 단정하지 않는다. 같은 분석은 앱 월간 사용자 기준으로 Perplexity의 사용자층이 지난 1년간 Gemini보다 빠르게 늘었다고 적으므로, 웹 방문 감소를 서비스 전체 이용 감소로 읽지 않는다.

### 창업자의 위협 인식

Wilbur Labs가 2026-04-28 공개한 2026 Report on Startup Failure는 미국 기술 창업자 200명을 2026-02-03~12에 조사했다. 조사 진행은 Wakefield Research가 도왔고, 오차는 95% 신뢰수준에서 ±6.9%p다(2026-11-02 보고서 도표 확인 기준).

| 향후 12개월 생존의 가장 큰 위협 | 응답 |
|---|---|
| 기술 교란(AI와 신기술) | 50% |
| 경쟁(새 스타트업이나 기존 경쟁자) | 48% |
| 팀이나 채용 문제(채용 어려움, 저성과 팀) | 47% |
| 재무(버틸 만큼 돈이 들어오지 않음) | 39% |
| 규제(개인정보 법, 준수 규칙) | 39% |
| 파트너나 고객 위험(핵심 파트너나 고객 의존) | 33% |

응답 합이 100%를 넘는 복수 응답이며, 59%는 향후 12개월 생존을 걱정한다고 답했다. 각 항목 추정치의 표본오차가 ±6.9%p라 3%p 이내인 상위 세 항목의 차이로 순위를 가르기 어렵고, AI를 경쟁이나 채용보다 뚜렷하게 큰 위협으로 읽을 근거는 되지 않는다.

## 대응 사례

2026-11-02 각 회사의 공식 발표와 사이트로 확인한 방향이다. 회사가 스스로 밝힌 위치이며 전환 뒤의 매출이나 유지율을 확인한 자료는 아니다.

- **라이너:** 자사 서비스 운영에서 쌓은 모델 평가 역량을 B2B 상품으로 만든 사례다. 2026-09-15 출시한 라이너 모델 API는 코딩, 수학, 복합 추론이 필요한 고난도 질의를 상위 모델에, 나머지를 효율적인 모델에 배정하는 오케스트레이션 상품이다. 라이너는 라이너 검색, 라이너 스콜라 같은 에이전트 제품을 운영하며 만든 모델 평가 체계를 근거로 들고, 실사용 데이터 자체 평가에서 고성능 모델 배정 비중이 약 43%였으며 답변 품질을 유지하면서 토큰 비용을 50% 이상 줄이도록 설계했다고 밝혔다. 라우팅은 위 표의 모델 간 차이 보완 층이라, 평가 데이터와 운영 경험이 공급자의 기본 기능보다 나은 결과를 계속 내는지가 관건이다.
- **Jasper:** 2023-07-10 CEO 글에서 Jasper는 빠른 기술 발전과 소비자용 AI 도구의 급증으로 업계가 크게 바뀌었다고 설명하고, 중견기업과 대기업 마케팅 팀을 도울 때 가장 효과적이라며 일부 직무를 없애 초점을 좁힌다고 밝혔다. 현재 공식 사이트는 기업 마케팅용 응용 AI를 내걸고 현장 배치 전문가, 맥락, 거버넌스와 에이전트를 한 시스템으로 묶는다고 소개한다. 브랜드, 제품과 고객층 정보를 모든 산출물의 맥락으로 쓰는 Jasper IQ, 캠페인의 빠른 출시와 지역별 현지화, 마케팅 업무를 끝까지 수행하는 전용 에이전트를 앞세운다. 글 생성 결과물보다 기업 고객의 브랜드 맥락과 업무 흐름에 무게를 둔다.
- **Copy.ai:** 공식 사이트는 자사를 GTM(시장 진출) AI 플랫폼으로 소개하며 여러 코파일럿과 단일 기능 도구 대신 하나의 플랫폼을 내세운다. 계정과 연락처를 조사해 영업 메시지 초안을 쓰는 기능, CRM 데이터 보강, 프로세스와 모범 사례를 AI 워크플로로 옮기는 기능을 앞세운다. 2026-05-27 자사 블로그는 에이전트형 AI가 작업을 자동화한다면 워크플로는 프로세스를 자동화한다고 설명한다. 단일 생성 작업보다 여러 단계 업무 흐름과 고객 시스템 연동을 상품 단위로 둔다.
- **Perplexity:** 공식 페이지에서 Comet을 사용자를 위해 일하는 AI 브라우저로 소개하고 작업 자동화, 웹 조사, 이메일 정리를 예로 든다. 답변 제공에서 작업 위임으로 범위를 넓힌 형태이며, 앞의 방문 추세와의 인과는 확인하지 않았다.

## 적용 점검

- 핵심 기능마다 지금 모델의 어떤 부족을 메우는지 적고, 다음 모델이 그 부족을 없앴을 때도 고객이 남을 이유를 한 문장으로 쓴다. 이유가 없는 기능은 수익원보다 과도기 비용으로 본다.
- 새 모델이 나올 때마다 같은 평가 세트로 우리 제품과 프런티어 모델 직접 사용을 비교하고, 비교 결과 없이 차별점을 주장하지 않는다.
- 사업 계획을 모델 정체와 계속 개선의 두 가정으로 계산해, 개선 가정에서 원가가 내려가고 품질이 오르는 구조인지 확인한다.
- 미세조정, 검색 파이프라인과 라우팅에 들인 투자를 모델을 바꿔도 다시 쓰는 자산(평가 데이터, 고객 데이터, 운영 기록)과 특정 모델의 약점에 맞춘 우회 기능으로 나눈다.
- 업무 흐름의 어느 구간을 소유하는지, 고객 데이터가 계속 갱신되는 경로, 책임지는 범위와 연동한 고객 시스템을 표로 채운다. 빈칸이 많으면 흡수에 취약할 가능성이 높다.
- 라우팅이나 오케스트레이션을 상품으로 만든다면 모델 공급자가 같은 기능을 기본 제공해도 남는 것(고객별 품질 기준, 비용 보고, 평가 데이터)을 먼저 적는다.
- 1인 개발자나 소규모 에이전시는 모델 성능을 끌어올리는 기능보다 특정 고객 업무를 끝까지 처리하고 결과에 책임지는 일을 상품 단위로 삼는 편이 흡수 노출이 작다. 사업 유형과 진행 순서는 [[AI-Solo-Software-Business|AI 시대 1인 소프트웨어 사업의 유형과 순서]]에서 본다.

## 한계

- Theory Ventures 조사는 투자사가 모은 응답자의 자기 보고다. 조사 페이지는 2026년 응답자가 2025년보다 직급이 높고 대기업 비중이 크다고 밝히므로 연도 비교에는 표본 구성의 차이가 섞여 있다. 다만 같은 페이지는 두 해 모두 직원 201명 이상 기업으로 좁혀도 주요 변화의 방향과 대략적 크기가 유지된다고 밝힌다. 직급 구성의 차이는 이 확인으로 걸러지지 않으며, 미세조정 감소를 모델 개선의 효과로만 읽지 않는다.
- Wilbur Labs 조사는 AI 기업에 한정하지 않은 미국 기술 창업자의 자기 보고이고, 위협 인식은 실제 폐업 원인과 다른 지표다.
- Similarweb 수치는 perplexity.ai 도메인의 웹 방문 추정치이며 앱 사용은 별도 지표다. Similarweb도 생성형 AI 추적 보고서에서 증감률이 도메인 단위 방문 기준이라 API 사용과 연동을 담지 않는다고 밝힌다. 웹 방문이나 방문 점유율은 매출이나 시장 점유율이 아니다([[LLM-Market-Landscape|생성형 AI 시장 경쟁 구도]]).
- 대응 사례는 회사의 공식 발표와 사이트에 적힌 자기 설명이고, 라이너의 비용 절감 수치도 독립 검증이 없는 자체 평가다. 내세운 방향이 실제 방어력으로 이어졌는지는 확인하지 않았다.
- 층별 노출 표는 판단 틀이다. 어떤 기능이 언제 흡수될지 예측하지 않으며, 노출이 작은 층도 영구히 안전하다고 보지 않는다.
