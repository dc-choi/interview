# AI 소프트웨어 복제와 기술 실사

소프트웨어의 관찰 가능한 동작을 다시 만드는 비용과 고객이 안심하고 업무를 옮기는 비용은 다르다. AI가 구현 비용을 낮추더라도 호환성, 데이터 이전, 성능, 운영 책임과 고객 신뢰를 따로 평가한다. 재구현이 쉬운 제품도 유통과 운영에서 가치가 있을 수 있고, 코드가 복잡한 제품도 수익성이 없을 수 있다.

## 기능 동등성과 업무 대체 가능성

| 확인 층위 | 확인할 내용 |
|---|---|
| 화면과 기능 목록 | 메뉴와 버튼이 존재하는가 |
| 실제 동작 | 같은 입력에서 원하는 결과가 나오는가 |
| 경계 조건 | 큰 파일, 장시간 작업, 실패와 복구에서도 동작하는가 |
| 호환성 | 파일 왕복 저장과 외부 연동에서 정보가 보존되는가 |
| 전문 업무 | 색상, 글꼴, 접근성, 감사와 지원 조건까지 충족하는가 |
| 총비용 | 구축, 검수, 수정과 운영까지 감당하는가 |

비슷한 화면을 빠르게 만든 데모와 전문 사용자의 전환 가능성을 같은 지표로 재지 않는다. 바이너리 크기와 코드 줄 수도 실제 메모리, 지연과 안정성의 대용 지표로 고정하지 않는다.

### 자동화 가능성과 납품 품질을 따로 평가한다

편집기를 스크립트나 에이전트로 조작할 수 있으면 반복 작업을 자동화할 후보가 된다. 그러나 조작 경로가 있다는 사실만으로 결과물의 품질, 파일 호환성이나 고객의 업무 전환 가능성이 입증되지는 않는다.

PhotoCraft의 공개 README는 UI, CLI, JSON 제어 채널과 MCP가 같은 명령을 호출한다고 설명하며, 이미지 폴더에 같은 작업 목록을 적용하는 일괄 처리 예제를 제공한다(2026-10-22 문서 대조). 같은 README는 아직 일상적인 전문 작업에서 Photoshop을 대체할 수준이 아니라고 명시한다. 여기서 확인한 것은 프로젝트가 문서화한 기능과 제한이며, 실행 성능이나 납품 적합성을 직접 검증한 결과가 아니다.

사업 적용 시에는 반복 작업 하나를 정해 수작업 대비 처리 시간, 검수와 수정 시간, 고객이 실제로 여는 파일의 호환성을 함께 측정한다. 이 항목은 도입 평가 제안이며, 자동화로 비용이 줄었다는 측정 결과가 아니다. 기존 편집기를 전면 교체하는 결정과 제한된 보조 작업에 활용하는 결정을 나누어 검토한다.

## 해자가 남는 조건

- **책임:** 실패 시 누가 복구하고 배상하는지, 그 약속을 지킬 품질 체계와 재원이 있는지 본다.
- **지속적으로 생성되는 데이터:** 데이터를 보유했다는 사실보다 적법한 접근권, 갱신 과정과 개선 효과를 본다.
- **유통과 신뢰:** 고객의 조달, 보안 심사와 업무 흐름에 자리 잡았는지 확인한다.
- **실물 운영:** 설치, 물류나 현장 지원은 코드 재생성만으로 복제되지 않는다. 인건비와 자본 부담도 함께 생긴다.

기능 복제의 비용 하락이 모든 해자의 소멸을 뜻하지는 않는다. 고객이 결과를 얻도록 책임지는 모델은 차별화 후보지만 책임 비용이 가격을 넘으면 성립하지 않는다.

## 모델 공급자가 응용 사업을 모두 직접 하지 않는 이유

모델이 그렇게 뛰어나다면 모델 회사가 직접 수많은 회사를 세우면 되지 않느냐는 질문(Hacker News, 2026-10-22)에는 소프트웨어를 만드는 능력과 사업을 운영하는 능력을 구분하는 논거가 모였다. 참여자들의 의견을 정리한 것이며 AI 기업의 실제 전략을 확인한 자료는 아니다.

| 논거 | 사업 판단에 옮길 질문 |
|---|---|
| 유통, 신뢰와 관계 | 첫 고객이 제품을 만든 속도가 아니라 기존 관계로 왔는가 |
| 무엇을 만들지 고르는 능력 | 실패 원인이 구현보다 잘못된 요구사항과 시장 부적합에 있는가 |
| 사용량 매출의 구조 | 우리 매출이 고객 성과와 무관한 사용량 매출이라면, 원가와 가격 경쟁을 뺀 뒤에도 이익이 남는가 |
| 집중과 조직 | 새 업종에 들어갈 때 그 업종의 제품 관리, 영업, 지원과 운영 조직을 따로 갖출 여력이 있는가 |
| 고객과의 경쟁 | 우리가 기대는 공급자가 같은 기능을 직접 내놓아도 고객이 남을 이유가 있는가. 플랫폼이 인기 있는 외부 기능을 흡수해 온 전례(셜록킹)를 보고도 지금의 공급자가 앞으로 경쟁하지 않으리라고 가정하고 있지는 않은가 |

토론에서는 사용량 매출에 대해 고객의 성패와 무관하게 공급자가 돈을 번다는 주장과, 원가보다 싸게 팔면 그 구조도 이익을 보장하지 않는다는 반론이 함께 나왔다. 고객과의 경쟁에서는 공급자가 고객 사업을 복제하면 고객이 경쟁 공급자로 옮긴다는 논거와 셜록킹 전례가 맞섰다.

같은 토론의 한 참여자는 AI 코딩으로 개발과 유지보수 비용이 내려가, 이전에는 경제성이 없던 고객 서비스 업무 자동화를 만들었다고 소개했다. 이틀짜리 유료 일정의 둘째 날 불참으로 빈 자리를 이전 불참자에게 제안할 때 누구에게 먼저 연락하고 얼마나 기다릴지 같은 예외가 약 150가지였고, 수십 년간 수작업으로 쌓은 비공개 업종 지식과 수십 개 외부 시스템 연동이 필요해 겉의 동작만 보고 복제하기 어렵다고 답했다. 매일 수천 명이 쓰면서 새 예외가 계속 생긴다고도 했다(익명 커뮤니티 경험담, 독립 검증 없음). 위 해자 조건에 대어 보면 수십 개 외부 시스템 연동은 업무 흐름에 자리 잡은 정도(유통과 신뢰)에 가깝고, 수작업 운영에서 쌓인 비공개 예외 규칙은 데이터 항목보다 축적된 업무 지식에 가깝다.

적용 제안: 모델 공급자의 응용 진출 위험을 볼 때 우리 제품이 범용 AI 서비스의 기능 하나로 흡수될 수 있는 얇은 기능인지, 업종 지식, 외부 연동과 운영 책임이 함께 묶여 있는지 나눠 본다. 플랫폼에 기대는 유통 경로의 의존은 [[Platform-Power|플랫폼 파워]]에서 함께 본다.

## AI 기업의 기술 실사

재무 실사는 실제 매출, 유지율과 고객 집중도를 검증한다. 기술 실사는 그 매출을 앞으로도 유지할 시스템과 권리를 검증한다. 둘 중 하나를 다른 하나로 대체하지 않는다.

1. 외부 모델, 프롬프트, 자체 코드와 데이터가 각각 어떤 결과를 만드는지 실제 호출 경로로 확인한다.
2. 모델 가격 상승, API 중단, 품질 하락과 공급사 변경을 가정해 대체 비용과 마진을 계산한다.
3. 학습, 검색과 고객 데이터의 사용권, 갱신권과 계약 종료 시 처리 조건을 확인한다.
4. 핵심 인력이 빠져도 배포, 장애 복구와 평가를 재현할 수 있는지 확인한다.
5. 대표 고객 과제를 재현해 동작과 비용을 비교한다. 화면을 복제했다는 사실만으로 전체 사업을 복제했다고 판단하지 않는다.

얇은 API 연결 코드도 특정 고객 문제를 잘 풀면 유용하다. 인수 가격에서 독자 기술의 프리미엄을 주장할 때는 실제 차별성의 증거가 필요하다. 코드 줄 수를 자산 가치의 기준으로 삼지 않는다.

## 사례와 확인 수준 (2026-10-16)

- **Photoshop 복제 앱 비교:** 제공된 2026-10-13 GeekNews 발췌에는 8K × 8K 이상 캔버스의 브러시 지연, 복사와 실행 취소의 멈춤, 색상과 인쇄 프로파일 및 파일 호환성 문제가 기록돼 있다. 비교 글은 확인했지만 해당 앱을 직접 실행하지 않았다. 개발비 최소 2,000달러와 대안 구독료 비교는 글의 사례 수치이며 현재 가격이나 모든 복제 앱의 성능으로 일반화하지 않는다.
- **경쟁 해자 논쟁의 PhotoCraft 수치:** PhotoCraft 저장소는 Photoshop을 Rust로 다시 구현한 클린룸 프로젝트라고 소개하고, 공개 명세와 관찰된 동작만 썼으며 독점 코드, 셰이더와 자산은 쓰지 않았다고 밝힌다. 해자 에세이(2026-10-07)는 WebProNews가 프로젝트 로드맵을 읽고 Photoshop parity를 50% 미만으로 추정했다고 인용한다. 현재 parity 문서는 2026-10-05 평가를 예전 docs/roadmap.md 절에서 옮겨 보존했다고 밝히고 이 평가도 실제 parity가 50%에 한참 못 미친다고 적으므로, 이 수치는 외부의 독립 측정이 아니라 프로젝트 자체 평가에서 온 값으로 본다(WebProNews 원문은 미확인). 이 평가는 일반적인 Photoshop 사용자가 다루는 기능의 약 60~70%가 어떤 형태로든 있고 전문가가 일상 업무용으로 전환할 수 있는 수준은 약 25~35%라고 나눠 적었다. 진정한 1:1 parity에는 여러 달의 집중 작업이 필요하다고 봤고, 메뉴 항목이 모두 명령에 연결됐다는 수치는 동작에 대해 아무것도 말해 주지 않는다고 적었다. 체크리스트가 동작한다고 센 기본 기능에서도 텍스트 선택 위치 어긋남과 단축키 실패 214건 같은 결함이 발견됐다고 적었다. 같은 평가의 항목별 표는 텍스트 캐럿 위치 지정을 고쳤고 단축키 점검 실패가 214건에서 0건이 됐다고 함께 적었다. 다만 214건과 0건은 자체 시험이 센 값이고, 평가는 0.2.0 이후 수정의 대부분이 시험은 통과했지만 아직 사용자 검증을 거치지 않았다고 적었다.

  2026-10-13 로드맵은 PhotoCraft 0.6.0을 2026-10-10 설치본에서 측정한 Photoshop 2026(27.11.0)과 비교해 기능 범위를 약 76%(일부 측정, 근거에 메뉴 628개 연결 포함), 실무 투입 준비를 약 45%(추정, 범위 40~50%)로 적었다. 같은 로드맵의 진행 기록은 2026-10-05 0.2.0 시점의 실무 투입 준비를 25~35%로 적으므로, 앞의 25~35%와 이 45%는 시점이 다른 같은 항목의 자체 추정이다. 영역별 표는 성능의 준비도를 25%로 매기고, 그 근거로 예산을 둔 성능 시나리오 25개 중 3개만 목표를 충족했다는 측정을 붙였다. 이 측정은 2026-10-05에 부하가 높은 장비에서 잰 첫 기준선이다. scorecard의 시나리오 58개는 예산 안 3개, 초과 또는 실패 22개, 추적만 하는 것 9개, 미실행 19개, 아직 측정할 수 없는 것 5개로 나뉜다. README는 아직 일상 전문 작업을 대신하지 못한다고 하고, PSD를 열고 다시 저장한 결과가 psd-tools 시험 파일 309개 중 307개에서 같게 렌더링된다고 보고한다. 이 비교는 다시 저장한 파일을 PhotoCraft가 다시 읽어 자체 렌더 결과와 맞춘 값이며, 같은 저장소의 scorecard와 파일 형식 parity 문서는 이 왕복 저장의 강제 하한을 308/309로 적어 README의 수치와 다르다. 다시 저장한 파일은 원본과 바이트 단위로 같지 않고, 로드맵은 PhotoCraft가 쓴 PSD를 Photoshop이 아직 안정적으로 받아들이지 못한다고 적었다.

  같은 저장소의 parity 문서는 측정을 위해 설치된 Photoshop 2026을 실행하지 않은 채 Info.plist, 파일 형식 플러그인 플래그, 언어 팩, 기본 단축키 파일, 프리셋과 주 실행 파일의 문자열을 살펴봤다고 적는다. 클린룸 표방과 별개로 원본 설치 파일을 어디까지 참고했는지는 기술 실사에서 따로 확인할 대상이다(적용 제안). 모두 프로젝트의 자체 보고이며 코드 독립성, 전체 기능과 적법성을 검증한 결과가 아니다(2026-10-20 저장소 대조, 확인 시점의 최신 릴리스는 0.10.0). 메뉴 연결 수와 실제 동작이 다르고 성능 예산 충족, PSD 왕복 저장과 전문 업무 이전 정도도 서로 다른 값을 보이므로, 위 표의 층위를 따로 재야 하는 사례로 본다.
- **인수 실사 일화:** ARR 420만 달러, 성장률 40%, 약 600줄의 연결 코드로 된 기업의 인수를 철회했다는 소셜 게시물 발췌를 확보했다. 대상 회사, 계약과 코드에 접근하지 못해 독립 검증하지 않았다. 매출의 실재와 기술적 차별성이 다른 질문이라는 학습 후보로 보존한다.

후속 확인은 앱 버전과 동일한 파일을 고정한 성능 비교, PSD 왕복 저장 검증, 인수 사례의 공개 근거 대조다. 이 기록은 해당 제품을 사거나 팔라는 투자 판단이 아니다.
