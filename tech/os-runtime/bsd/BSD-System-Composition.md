# 운영체제 구성과 패키지 출처 정책

운영체제 배포판을 비교할 때 커널, libc, 기본 명령, 빌드 도구와 패키지 관리자를 별도로 본다. 사용자 공간의 익숙한 명령이 있다고 커널 ABI나 드라이버 지원이 다른 운영체제와 같아지는 것은 아니다.

## 구성 요소별 질문

| 구성 | 확인할 계약 |
|---|---|
| 커널과 드라이버 | 시스템 호출, 장치와 아키텍처 지원 |
| libc와 플랫폼 도구 | 바이너리 ABI, 헤더와 런타임 의존성 |
| shell과 기본 명령 | 옵션, 스크립트 호환성과 복구 환경 |
| 패키지 관리자 | 저장소 신뢰, 서명, 의존성 해결과 업데이트 |
| 소스 출처 정책 | 생성물의 허용 기준, 검토 주체와 예외 분류 |

이름이 비슷하거나 같은 패키지 관리자를 쓴다는 이유만으로 다른 배포판의 바이너리 저장소를 섞지 않는다. 생성 AI 사용 금지 정책도 코드의 무결성과 취약점 부재를 증명하지 않는다. 정책 준수, 재현 가능한 빌드와 보안 검토는 각각 확인해야 한다.

## 확인이 필요한 구성 사례

2026-10-29 제공된 AlpineBSD 발췌는 NetBSD 커널/libc/필수 도구에 apk-tools와 BusyBox를 결합하고 GNU make를 선호하는 개발 중 배포판으로 소개한다. 기본 시스템과 주 저장소에서 LLM 출력물을 제외하고, AI 생성물이 포함된 패키지는 사용자가 선택하는 tainted 저장소로 나눈다는 내용이다.

2026-11-02 공식 위키와 AI 정책 페이지를 조회했지만 본문을 확보하지 못했다. 위 구성, 저장소 구현과 실제 배포 가능 상태는 미확인이다. 후속 확인은 라이선스, 패키지 빌드 정의, AI 생성물 판정 기준과 예외 처리다. 이를 NetBSD 자체의 공식 정책이나 Alpine Linux의 파생 Linux 커널로 해석하지 않는다.
