# OS 개요와 동시성

## 운영체제 개요

운영체제는 CPU, 메모리, 장치와 저장 공간을 중재하고 프로그램에 실행, 격리, 입출력 같은 공통 서비스를 제공한다. 커널은 보호된 하드웨어 기능을 관리하고 사용자 프로그램은 정의된 인터페이스를 통해 이를 요청한다.

### 운영체제가 관리하는 것
- 프로세스 관리 / 메모리 관리 / 하드웨어 관리 / 파일 시스템 관리

### 운영체제 역사

| 시기 | 변화 |
|------|------|
| 초기 전자식 컴퓨터 | 작업마다 배선과 장비 설정을 직접 바꾸고 프로그램을 수동 적재 |
| 배치 처리 | 작업을 묶어 순차 실행하여 설정과 운영자 대기 비용을 줄임 |
| 멀티프로그래밍과 시분할 | I/O 대기 동안 다른 작업을 실행하고 여러 사용자의 대화형 작업을 지원 |
| 개인용, 네트워크 시대 | GUI, 개인용 장치, 네트워크와 분산 자원 관리로 역할 확장 |

### 운영체제 구조
- **커널**: 프로세스/스레드, 메모리, 파일시스템, 장치와 권한을 관리하는 특권 소프트웨어
- **시스템 콜**: 사용자 프로그램이 커널 서비스를 요청하는 보호된 진입점
- **라이브러리와 런타임**: 시스템 콜을 더 높은 수준의 API로 감쌀 수 있음
- **GUI/CLI**: 사용자 입력을 받아 일반 프로그램처럼 커널 서비스를 요청하는 인터페이스
- **드라이버**: 커널과 장치 컨트롤러 사이의 장치별 동작을 구현하는 소프트웨어. 장치 펌웨어와는 다른 층

### 부팅 과정
1. 플랫폼 펌웨어가 CPU 초기화 지점에서 시작해 필요한 하드웨어를 초기화한다.
2. 펌웨어 정책이 부팅 대상을 고른다. 레거시 BIOS/MBR와 UEFI의 `BootOrder`/UEFI 실행 파일 경로는 서로 다른 방식이다.
3. 선택된 부트 프로그램이 운영체제 커널과 필요한 초기 데이터를 메모리에 배치하고 제어를 넘긴다.
4. 커널이 메모리, 스케줄러, 드라이버와 루트 파일시스템을 준비하고 첫 사용자 공간 서비스를 시작한다.

모든 컴퓨터가 BIOS와 MBR을 거친다고 일반화하지 않는다. UEFI뿐 아니라 임베디드 보드와 보안 부팅 환경도 서로 다른 초기화 경로를 가질 수 있다.

### 인터럽트
- **인터럽트**: 장치, 타이머처럼 현재 명령과 독립적인 비동기 사건이 제어 흐름 전환을 요청한다.
- **예외**: 잘못된 명령, 페이지 폴트, 0으로 나누기처럼 현재 명령 실행과 연관된 동기 사건이다.
- **시스템 콜**: 프로그램이 의도적으로 커널 서비스를 요청하는 동기적 trap 경로를 사용할 수 있다.
- CPU는 필요한 실행 문맥을 보존하고 등록된 handler로 이동한 뒤, 처리 결과에 따라 원래 흐름으로 복귀하거나 다른 task를 스케줄한다.
- 인터럽트는 계속 상태를 확인하는 폴링을 줄일 수 있지만, 실제 I/O 경로는 부하와 장치 특성에 따라 인터럽트와 폴링을 함께 사용할 수 있다.

### 컴퓨터 하드웨어 (폰 노이만 구조)
- CPU와 메모리를 버스로 연결. 버스는 데이터를 전달하는 통로
- **메인보드**: 다른 하드웨어를 연결하는 장치
- **CPU**: 산술논리연산장치(ALU), 제어장치, 레지스터
- **메모리**: RAM, ROM

## 동시성vs병렬성

| 구분 | 정의 | 예시 |
|------|------|------|
| 동시성(Concurrency) | 여러 작업의 실행 구간이 겹치도록 구성하는 것 | 1개 CPU가 시분할로 여러 작업 처리 |
| 병렬성(Parallelism) | 같은 시점에 둘 이상의 연산이 실제 실행되는 것 | 멀티코어에서 여러 작업 실행 |

## 커널모드vs유저모드

### 컴퓨터를국가에비유
| 국가 | 컴퓨터 |
|------|--------|
| 영토/영공/영해 | 하드웨어 |
| 정부 조직 | OS (시스템 소프트웨어) |
| 국민 | 프로그램(프로세스) |
| 국민의 공간 | 프로세스 메모리 (다른 프로세스 침범 불가) |
| 경찰 | 디버거 (다른 프로세스 접근 가능) |

### 커널(Kernel)
- OS의 핵심, 컴퓨터의 법을 구현
- **역할**: 입출력 제어, 자원(CPU+RAM) 관리, 접근 제어
- OS는 하드웨어에 의존적 (64비트 OS → 64비트 CPU 필요)

### 두모드의관계

```
[유저 모드]  애플리케이션 → 라이브러리/런타임 → 시스템 콜
                                              ↓
[커널 모드]  시스템 콜 처리 → VFS/네트워크/메모리 하위 시스템 → 드라이버
                                                              ↓
[장치]                                                        컨트롤러/펌웨어
```

- Unix 계열의 **디바이스 파일**은 일부 장치를 파일 디스크립터 기반 API로 노출한다. 모든 커널 구성 요소가 디바이스 파일인 것은 아니다.
- 사용자 프로세스는 보통 시스템 콜과 권한 검사를 거쳐 장치 서비스를 사용한다.
- 드라이버는 커널 소프트웨어이고 펌웨어는 장치 또는 플랫폼에서 실행되는 코드다.

### 디스크접근예시
```
[하드웨어] 디스크
    ↑
[커널모드] 파일시스템/VFS → 블록 계층 → 디바이스 드라이버
    ↑
[유저모드] 파일시스템 추상화 인터페이스 → 프로세스
```

## 프로그램→프로세스→스레드

| 개념 | 설명 |
|------|------|
| 프로그램 | 실행 전의 코드와 정적 데이터가 담긴 실행 가능한 이미지 또는 스크립트 |
| 프로세스 | 실행 중인 프로그램 인스턴스이자 운영체제가 자원을 격리해 할당하는 경계 |
| 스레드 | 프로세스 안에서 스케줄링되는 실행 흐름, 같은 프로세스의 자원을 공유 |

### 메모리영역
| 영역 | 소유자 | 특징 |
|------|--------|------|
| 스택 | 스레드별 개별 소유 | 함수 호출, 지역 변수 |
| 힙 | 프로세스 전체 공유 | 동적 할당, 동시성 문제 발생 가능 |

- 프로세스마다 독립된 가상 주소 공간이 있다.
- 같은 프로세스의 스레드는 코드, 데이터와 힙을 공유하지만 스택과 실행 컨텍스트는 따로 가진다.
- 공유 메모리 덕분에 스레드 간 데이터 교환은 가볍지만, 같은 값을 동시에 변경하면 동기화가 필요하다.

### 프로세스 전환과 스레드 전환

프로세스 전환은 실행 컨텍스트와 함께 주소 공간을 바꿔야 하므로 메모리 관리와 캐시 관점의 비용이 크다. 같은 프로세스 안의 스레드 전환은 주소 공간을 유지할 수 있어 일반적으로 더 가볍다. 다만 스레드 전환도 레지스터 저장, 복원과 스케줄링이 필요하므로 비용이 사라지는 것은 아니다.

### 프로세스메모리구조(상세)
| 영역 | 저장내용 | 방향 |
|------|---------|------|
| 코드(Text) | 실행할 프로그램의 기계어 코드 | 고정 |
| 데이터(Data) | 전역 변수, static 변수 | 고정 |
| 힙(Heap) | 동적 할당 (new, malloc) | 낮은 주소 → 높은 주소 |
| 스택(Stack) | 함수 호출, 지역 변수, 매개변수 | 높은 주소 → 낮은 주소 |

힙과 스택의 성장 방향은 흔한 ABI 예시일 뿐 보장된 규칙이 아니다. 실제 주소 배치와 보호 영역은 아키텍처, ABI, 로더와 ASLR 정책에 따라 달라진다.

### Recursion이stack/heap에미치는영향
- 재귀 호출마다 스택 프레임이 쌓임 → 깊은 재귀는 **Stack Overflow** 발생
- 꼬리 재귀 최적화(TCO)가 없는 언어에서는 반복문으로 변환하는 것이 안전
- 재귀 내에서 동적 할당을 하면 힙도 함께 증가

### 단편화(Fragmentation)
| 종류 | 설명 |
|------|------|
| 외부단편화 | 할당/해제를 반복하면 메모리 사이에 사용할 수 없는 작은 빈 공간이 생김 |
| 내부단편화 | 할당된 블록이 요청보다 커서 블록 내부에 사용되지 않는 공간이 생김 |

- 외부 단편화 해결: 압축(Compaction), 페이징
- 내부 단편화 해결: 적절한 블록 크기 선택, 버디 시스템

### 메모리지역성(Locality)
| 종류 | 설명 |
|------|------|
| 시간적지역성(Temporal) | 최근 접근한 데이터에 다시 접근할 가능성이 높음 |
| 공간적지역성(Spatial) | 접근한 데이터 근처의 데이터에 접근할 가능성이 높음 |

- 캐시가 효율적으로 동작하는 근거
- 배열 순차 접근이 연결 리스트보다 빠른 이유 (공간적 지역성)
