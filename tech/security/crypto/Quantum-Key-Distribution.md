# 양자키분배(QKD): 보안 가정, 구현 한계와 PQC와의 관계

양자키분배(Quantum Key Distribution, QKD)는 두 지점이 양자 상태를 주고받아 공유 비밀키를 합의하는 키 합의 방식이다. 합의한 키는 대칭키 암호에 넣어 데이터를 보호한다. QKD는 데이터를 직접 암호화하지 않고 통신 상대를 인증하지도 않는다. 그래서 양자 컴퓨터 대비책으로 평가할 때는 키 합의, 인증과 데이터 암호화를 나눠 본다([[Public-Key-Cryptography#양자 위협을 구분하는 기준|양자 위협을 구분하는 기준]]).

## 구성과 동작

- **두 채널**: 광섬유나 위성의 자유공간 같은 양자 채널과 일반 통신망의 고전 채널을 함께 쓴다. 중간자 공격을 막으려면 고전 채널의 메시지가 인증돼야 한다.
- **키 생성**: 편광된 광자 같은 양자 상태를 주고받아 측정한 뒤, 인증된 고전 채널에서 후처리를 거쳐 측정 결과로부터 비밀키를 얻는다.
- **도청 탐지**: 양자 상태는 의미 있는 상호작용이 있으면 바뀐다. BB84 같은 방식에서는 송신 기저를 모르는 도청자가 광자를 측정하면 상태를 교란할 위험이 있고, 얻는 정보가 많을수록 수신 결과와 어긋날 확률의 하한이 커진다. 그래서 측정 결과의 일부를 공개 비교해 도청을 확률적으로 탐지한다.
- **BB84**: 1984년 Bennett과 Brassard가 제안한 프로토콜이다. 송신자는 무작위 비트열과 기저열을 고른다. 기저는 수평과 수직 편광의 직선 기저(rectilinear)와 45도와 135도 편광의 대각 기저(diagonal)이고, 0은 수평이나 45도, 1은 수직이나 135도 편광의 광자로 보낸다. 수신자도 광자마다 측정 기저를 무작위로 고른다. 이후 공개 채널에서 어떤 광자를 받았고 어느 기저가 맞았는지만 확인해 같은 기저로 주고받은 비트만 남긴다. 원 논문은 오류 없는 채널을 가정해, 남은 비트 중 무작위로 고른 일부를 공개 비교하고 모두 일치하면 의미 있는 도청이 없었다고 보고 공개하지 않은 나머지를 키로 쓴다. 전송이 교란됐으면 버리고 다시 보낸다.
- **공개 채널의 가정**: 원 논문은 이 공개 채널을 엿들을 수는 있어도 메시지를 끼워 넣거나 바꿀 수는 없는 채널로 가정한다. 두 사람이 미리 나눈 작은 비밀키로 Wegman-Carter 인증 태그를 붙이면 이 가정을 완화할 수 있다고 함께 설명한다. 처음부터 인증 수단이 필요하다는 뜻이다.

## 이론의 보장과 실제 구현

QKD 프로토콜의 이론적 보안은 수학 문제의 계산 난도가 아니라 양자물리 원리에 근거한다. 이론상으로는 계산 능력에 제한이 없는 공격자나 미래의 알고리즘 발전에도 안전하고, 지금 수집해 두었다가 나중에 해독하는 공격에도 안전하다고 주장된다. 다음 두 조건 때문에 이 보장이 실제 시스템으로 그대로 옮겨지지 않는다.

- **데이터 암호화 단계**: 계산 능력에 제한이 없는 공격자까지 막으려면 데이터를 one-time pad로 암호화해야 하고, 그러려면 데이터 채널과 같은 속도로 키를 만들어야 한다. 2024 입장문 기준으로 대부분의 실제 용도에서 QKD의 키 생성 속도는 이에 크게 못 미친다. 결국 키를 절대 보안이 없는 AES 같은 기존 대칭키 암호에 쓰게 되고, 이 순간 절대 보안 주장은 성립하지 않는다.
- **장치 구현**: 보안 증명은 이론 모델 안에서만 성립한다. 실제 구현은 다른 암호 구현처럼 결함이 있어 이론 모델에서 벗어나며, 장치의 물리적 특성을 노린 공격으로 안전하지 않음이 드러난 QKD 시스템들이 있다. 2010년 Lydersen 외 연구는 상용 QKD 시스템 두 종의 검출기를 특수하게 조정한 밝은 빛으로 완전히 원격 조종할 수 있음을 실험으로 보였고, 이를 이용하면 흔적 없이 비밀키 전체를 얻을 수 있다고 했다. 기성 부품으로 만들 수 있는 도청 장치를 제안했고, 단일광자 검출에 애벌랜치 포토다이오드를 쓰는 대부분의 QKD 시스템에 같은 취약점이 있을 가능성이 크다고 봤다. ANSSI, BSI 등 유럽 4개 기관은 QKD가 제공한다는 절대적, 무조건적 보안 주장이 실제 구현에는 적용될 수 없다고 정리했다.

물리 법칙 때문에 해킹이 불가능하다는 설명은 이론 모델의 성질을 장비와 운영 전체로 넓힌 과장이다. 평가는 프로토콜, 장비 구현, 인증 방식과 운영 경로를 함께 대상으로 한다.

## 실무 제약

아래 내용과 수치는 2024-01 공동 입장문의 정리를 따르며, 서비스 거부 행의 마지막 문장만 위 Lydersen 사례와 연결한 이 문서의 해석이다. 거리 수치는 입장문이 인용한 2022년 문헌에 근거한다. 그 밖의 기록으로 2023년 Liu 외 연구는 실험실의 광섬유 스풀에서 twin-field QKD로 1,002 km(점근 조건)와 952 km(유한 크기 효과 반영)에서 양의 비밀키율을 보고했는데, 1,002 km의 키율이 초당 약 0.0034비트라서 상용 링크의 거리와 구분한다.

| 제약 | 내용 | 확인할 것 |
|---|---|---|
| 전용 하드웨어와 비용 | 단일광자 광원과 검출기 같은 전용 장비가 필요해 일반 컴퓨팅 하드웨어로 구현할 수 없다. 장비 구입과 수명 주기 동안의 유지 비용이 크고, 모든 사용자에게 배포하거나 모바일 기기에 쓰기 어렵다 | 같은 구간을 PQC나 사전 공유 대칭키로 보호할 때의 비용 |
| 거리와 신뢰 노드 | 광섬유 손실은 거리에 따라 지수적으로 커진다. 시연은 최대 수백 km, 상용 시스템은 보통 약 100 km다(2022 문헌 기준). 더 먼 거리는 이웃한 노드 쌍마다 키를 합의하는 신뢰 노드를 두어야 해서, 현재 광섬유 기반 QKD로는 장거리 종단 간 보안을 얻을 수 없다 | 신뢰 노드의 위치, 운영 주체와 물리 보안 |
| 위성 링크 | 현재 구현은 대부분 정지궤도가 아닌 위성을 써서 하루 이용 시간이 짧고, 가용성은 날씨에도 좌우되어 실제 키 생성률이 더 낮아진다. 대부분의 구현에서 위성 자체가 신뢰 노드다 | 가용 시간과 키 생성률 |
| 서비스 거부 | 모든 도청 시도가 탐지된다는 QKD의 기본 주장대로라면 도청 시도 하나하나가 서비스 거부 공격이 된다. 공격자가 측정하지 않은 채널 간섭도 실제로는 서비스 거부로 이어진다. 이 서비스 거부 위협과 양자 채널을 지키는 비용은 아직 충분히 연구되지 않았다. 반대로 위 검출기 공격처럼 구현의 빈틈은 탐지 자체를 우회할 수 있다 | 키를 만들지 못할 때의 대체 경로와 허용 중단 시간 |
| 인증 | 고전 채널 인증에는 대표적으로 미리 배포하고 주기적으로 갱신하는 대칭키를 쓰거나, PQC 서명과 PKI를 쓴다. 후자라면 인증의 보안은 PQC에 의존한다 | 인증 키 배포와 갱신 절차, 서명 알고리즘 |

## 성숙도와 기관 입장

2026-11-02 아래 기관 문서의 원문을 대조했다.

- **유럽 4개 기관(2024-01-26)**: 프랑스 ANSSI, 독일 BSI, 네덜란드 NLNCSA와 스웨덴 국가통신보안청의 공동 입장문은 QKD를 현재 일부 니치 용도에서만 실제로 쓸 수 있다고 결론지었다. 고전 키 합의를 쓰는 대부분의 용도에는 QKD를 쓸 수 없고, 보안 측면에서 아직 충분히 성숙하지 않았다고 본다. 우선순위는 PQC 전환이나 대칭키 방식 채택이며, 결론 절은 PQC를 전통적 대칭키 방식이나 고전 공개키 암호와 함께 쓰는 하이브리드 전환을 권한다.
- **성숙도 부족의 근거**: 같은 입장문은 작성 기관이 아는 범위에서 NIST의 PQC 표준화처럼 수년에 걸친 공개 검증 절차를 거친 QKD 프로토콜이 없다는 점, 실무에 쓰이는 프로토콜의 보안 증명이 요건을 갖춘 완결된 형태로 정리되지 않았다는 점을 든다. 충분한 증명 없이 상용으로 쓰이다 나중에 안전하지 않은 것으로 드러난 프로토콜도 있었다. 장치는 물리 공격까지 포함해 평가해야 하는데, BSI가 지원해 ETSI와 만든 prepare-and-measure QKD용 Common Criteria 보호 프로파일과 QKD 보안 요구사항, 시험 평가 방법의 ISO/IEC 표준이 나왔지만 물리 공격 평가 방법론은 더 개발해야 한다고 본다.
- **영국 NCSC(2025-08-05)**: 정부와 군사 용도에 QKD를 지원하지 않으며 PQC를 양자 컴퓨터 위협의 주 대책으로 권고한다. 다른 분야에도 키 생성과 분배를 QKD에만 의존하지 말라고 하고, QKD 사용이 NCSC Cyber Assessment Framework의 전송 구간 보안 평가 근거가 되지 않는다고 밝힌다. QKD를 검토한다면 견고한 양자 내성 인증 수단을 함께 구현하고, 구성이 복잡해지면서 생기는 추가 보안 위험도 관리하라고 한다. 사전 공유 대칭키로만 인증하는 QKD 시스템은 통제된 환경에서는 쓸 수 있지만 인증 키의 배포와 관리 때문에 범용으로 확장하기 어렵다고 본다.

## PQC와 비교해 선택한다

| 기준 | QKD | PQC |
|---|---|---|
| 보안 근거 | 양자물리 원리(이론 모델) | 특정 수학 문제의 계산 난도(가정) |
| 배포 | 전용 광학 장비와 링크 | 기존 하드웨어와 통신 인프라에 구현 |
| 인증 | 제공하지 않음, 별도 수단 필요 | 서명 알고리즘으로 제공 |
| 범위 | 링크 구간, 장거리 광섬유는 신뢰 노드 경유 | 통신 프로토콜과 데이터 형식에 통합, 통합 작업이 상당히 진척(2024 입장문) |
| 표준 | NIST PQC 수준의 표준화를 거친 프로토콜 없음(2024 입장문, 작성 기관 인지 범위) | NIST FIPS 203~205(2024-08-13 발행)의 ML-KEM, ML-DSA, SLH-DSA([[Public-Key-Cryptography|공개키 암호]]) |

수집해 두었다가 나중에 해독하는 위협 때문에 장기 기밀성이 필요한 통신은 지금 키 합의 방식을 바꿔야 하고, 그 기본 경로는 PQC 전환이다. QKD 도입 제안을 받으면 다음을 묻는다.

1. 이 구간을 PQC나 사전 공유 대칭키로 보호할 수 없는 이유는 무엇인가?
2. 고전 채널 인증은 무엇으로 하며, 인증 키는 어떻게 배포하고 갱신하는가?
3. 신뢰 노드는 어디에 있고 누가 운영하는가? 종단 간 보안이 필요한 데이터인가?
4. 장비는 어떤 평가 기준으로 물리 공격 시험을 받았는가?
5. 도청 탐지나 장애로 키 생성이 멈추면 통신을 어떻게 유지하는가?

## 면접 체크포인트

- QKD가 해결하는 것은 키 합의이고 인증과 데이터 암호화는 별도인 이유
- 이론 모델의 무조건 보안과 실제 구현 보안의 차이, 밝은 빛으로 검출기를 원격 조종하는 구현 공격 사례
- 신뢰 노드 때문에 장거리 광섬유 QKD가 종단 간 보안을 주지 못하는 이유
- 유럽 4개 기관과 영국 NCSC가 PQC를 우선 대책으로 보는 근거
