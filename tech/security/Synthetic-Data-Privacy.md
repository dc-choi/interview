# 합성 데이터와 개인정보 보호

합성 데이터는 원본의 분포나 관계를 모델링한 뒤 새 표본을 생성한 데이터다. 원본과 같은 스키마를 제공할 수 있지만, 통계적 동일성이나 개인정보 보호가 자동으로 보장되지는 않는다.

## 생성 방식과 보호 보장을 구분한다

| 구분 | 확인할 것 |
|---|---|
| 식별자 제거 | 이름을 지워도 다른 속성과 외부 자료를 결합한 재식별이 가능한가 |
| 일반 합성 데이터 | 생성기가 원본의 민감한 특성을 누출하는가. 합성이라는 명칭만으로 안전성을 판단하지 않는다 |
| 차등 개인정보 보호(DP) 합성 데이터 | 생성 과정이 명시한 보호 단위와 프라이버시 파라미터에 맞는 보장을 제공하는가 |

DP는 개인 데이터의 참여 여부에 따른 출력 분포의 변화를 제한하는 수학적 틀이다. 보호 대상, 파라미터와 구현을 확인해야 하며, 합성 데이터라는 이유만으로 규제 검토가 끝났다고 판단하지 않는다.

## 유용성과 정확도

열별 분포가 비슷해도 열 사이의 상관관계가 보존됐다는 뜻은 아니다. 예를 들어 고객 연령과 상품 종류를 각각 독립적으로 생성하면 연령별 상품 선호를 잃을 수 있다.

DP를 만족한 결과만 후처리하면 같은 보호 보장을 유지하며, 그 후처리 결과를 공개하는 것만으로 추가 프라이버시 손실이 생기지는 않는다. 원본을 다시 조회해 별도 결과를 공개하는 작업은 이 후처리 보장에 포함되지 않는다. 원본에서 여러 DP 결과를 생성해 공개하면 합성(composition)에 따른 누적 프라이버시 손실을 따로 계산한다.

합성 과정은 원본의 표본 오차에 추가 오차와 편향을 더할 수 있다. 전체 평균뿐 아니라 중요한 하위 집단과 실제 분석 작업의 정확도를 확인한다. 특정 집계만 필요하다면 범용 합성 데이터보다 해당 집계를 직접 DP로 계산하는 접근도 비교한다.

## 적용 점검

- 원본을 학습과 생성에 사용하는 경로와 외부에 공개하는 산출물을 구분했는가?
- 개인정보 보호 주장에 보호 단위, 파라미터와 구현 검토 근거가 있는가?
- 필요한 관계와 하위 집단의 정확도를 실제 사용 목적에 맞춰 대조했는가?
- 생성 결과의 외형이 자연스럽다는 평가를 보호 보장이나 분석 정확도로 대체하지 않았는가?
