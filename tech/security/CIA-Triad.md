# CIA Triad

CIA Triad는 정보와 시스템을 보호할 때 함께 검토해야 하는 세 목표인 **기밀성(Confidentiality), 무결성(Integrity), 가용성(Availability)** 을 묶은 모델이다. 보안을 정보 유출 방지로만 보면 변조와 서비스 중단 위험을 놓친다.

## 기밀성

허가된 주체만 정보에 접근할 수 있어야 한다.

### 위협

- 개인정보와 인증정보 유출
- 비밀번호, API 키와 민감 데이터의 평문 저장
- 권한이 없는 내부자나 다른 사용자의 데이터 열람
- 로그, 백업과 분석 시스템을 통한 우회 노출

### 통제

- 전송 중, 저장 시 암호화와 안전한 키 관리
- 인증과 최소 권한 접근 제어
- 화면과 로그의 데이터 마스킹
- 데이터 분류, 보존 기간과 삭제 정책

암호화만으로 기밀성이 완성되지는 않는다. 복호화 권한을 넓게 부여하거나 로그에 평문을 남기면 암호화된 저장소가 있어도 정보는 노출된다.

## 무결성

정보와 시스템 동작이 허가 없이 생성, 변경, 삭제되지 않았음을 보장해야 한다.

### 위협

- 거래 금액, 계좌와 주문 상태의 임의 변경
- 인증 토큰과 메시지 위조
- 소스 코드, 배포 아티팩트와 설정 파일 변조
- 전송 중 데이터 손상과 승인되지 않은 운영 변경

### 통제

- 해시와 MAC을 이용한 메시지 무결성 확인
- 디지털 서명을 이용한 변경 여부와 발신자 검증
- DB 제약, 트랜잭션과 동시성 제어
- 코드 리뷰, 변경 승인, 감사 로그와 아티팩트 서명

해시는 값이 바뀌었는지 비교할 수 있지만 공격자가 원문과 해시를 함께 바꿀 수 있는 환경에서는 인증된 무결성을 제공하지 않는다. 비밀키 기반 MAC이나 개인키 기반 서명처럼 공격자가 새 검증값을 만들 수 없게 해야 한다.

## 가용성

허가된 사용자가 필요한 시점에 정보와 서비스를 사용할 수 있어야 한다.

### 위협

- DDoS와 자원 고갈
- 랜섬웨어와 데이터 손상
- 단일 장애점, 용량 부족과 잘못된 배포
- 백업은 있지만 복구되지 않는 상태

### 통제

- 이중화, 장애 조치와 오토스케일링
- rate limit, WAF와 DDoS 방어
- 백업, 복구 훈련과 재해 복구 계획
- 용량 계획, 관측성, 롤백과 장애 대응 절차

서버를 여러 대 두는 것만으로 가용성이 보장되지는 않는다. 모든 인스턴스가 같은 DB, 네트워크나 인증 시스템에 의존하면 그 공유 의존성이 단일 장애점으로 남는다.

## 세 목표의 관계

| 질문 | 우선 확인할 목표 | 예시 통제 |
|---|---|---|
| 누가 이 데이터를 볼 수 있는가 | 기밀성 | 암호화, 접근 제어, 마스킹 |
| 값이 승인 없이 바뀌지 않았는가 | 무결성 | MAC, 서명, DB 제약, 감사 로그 |
| 장애 중에도 필요한 기능을 쓸 수 있는가 | 가용성 | 이중화, rate limit, 백업과 복구 |

하나의 통제는 여러 목표에 영향을 준다. 강한 암호화와 추가 검증은 기밀성, 무결성을 높이지만 지연과 운영 복잡도를 늘릴 수 있다. 복제본과 공개 엔드포인트를 늘리면 가용성은 높아질 수 있지만 공격 표면과 키 배포 범위도 커진다. 장애 시 무조건 fail-open하면 가용성은 지키더라도 기밀성과 무결성을 훼손할 수 있다.

따라서 세 목표를 동일한 숫자로 최대화하려 하지 않고 자산과 업무의 실패 비용에 맞춰 우선순위를 정한다.

- 결제와 원장 데이터는 무결성 검증과 감사 가능성이 특히 중요하다.
- 개인정보와 인증정보는 기밀성과 접근 권한 회수가 중요하다.
- 재난 알림과 핵심 인증 인프라는 장애 중 가용성이 중요하다.

우선순위가 다르더라도 나머지 목표를 버리는 것은 아니다. 필요한 수준과 통제를 명시하고 남은 위험을 기록한다.

## 가장 약한 고리 찾기

전체 보안 수준은 가장 약한 경로에서 무너진다. 강한 방화벽이 있어도 공유 비밀번호가 노출되거나 복구되지 않는 백업만 있다면 시스템은 안전하지 않다.

설계 시 자산별로 다음 순서로 확인한다.

1. 보호할 정보와 기능을 식별한다.
2. 기밀성, 무결성, 가용성이 깨졌을 때의 영향을 각각 평가한다.
3. 외부 공격자, 내부자, 운영 실수와 장애 경로를 찾는다.
4. 예방, 탐지, 복구 통제를 배치한다.
5. 접근 검토, 변조 탐지와 복구 훈련으로 통제가 실제 작동하는지 검증한다.

## 면접 체크포인트

- 보안을 해킹 방지나 암호화 하나로 축소하지 않고 CIA 세 목표로 설명할 수 있는가
- 암호화, 서명과 이중화가 각각 어느 목표를 주로 지키는지 구분할 수 있는가
- 한 목표를 강화할 때 생기는 성능, 운영과 공격 표면의 트레이드오프를 설명할 수 있는가
- 가장 약한 고리를 자산, 위협, 통제와 검증 절차로 연결할 수 있는가
