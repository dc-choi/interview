# 표적형 사회공학: 채용 위장과 AI로 개인화한 사기

표적형 사회공학은 경력, 작품 소개처럼 공개된 정보로 상대에게 맞춘 신뢰를 만든 뒤 코드 실행, 정보 제공이나 송금을 요구하는 공격이다. 기술 취약점 없이도 정상 사용자의 손으로 첫 실행이 일어나므로, 방어는 탐지 도구 하나보다 업무 절차의 경계(어떤 기기에서 무엇을 실행해도 되는가)와 권한 경로의 분리에 둔다.

## 공개 정보가 신뢰 신호로 쓰이는 구조

- 공격자는 대상의 SNS와 이력 정보를 조사해 배경에 맞춘 채용이나 투자 제안을 만들고, 오래 대화하며 신뢰를 쌓은 뒤 악성코드를 전달한다(FBI 2024-09-03 공익 경보).
- 대량 사기는 아주 적은 비율만 속아도 비용을 회수한다. 생성형 AI는 상대의 공개 문장을 되비춰 개인화하는 비용을 낮추므로, 상대가 내 정보를 정확히 안다는 사실을 신뢰의 근거로 쓰지 않는다(해석).

## 채용 절차를 위장해 개발자 단말을 노린다

FBI는 2024-09-03 공익 경보(I-090324-PSA)에서 북한의 암호화폐 업계 표적 사회공학을 다음처럼 정리했다.

| 구분 | 내용 |
|---|---|
| 접근 | 피해자 배경에 맞춘 채용이나 투자 제안, 실존 인물이나 채용 회사 사칭(도용한 사진, 가짜 회사 웹사이트) |
| 실행 유도 | 낯선 코드를 실행해야 하는 사전 채용 시험이나 디버깅 과제(낯선 Node.js나 PyPI 패키지, 스크립트, GitHub 저장소), 화상 통화를 연다며 요구하는 스크립트나 소프트웨어 설치 |
| 징후 | 회사 기기나 내부망 기기에서 코드 실행이나 앱 설치 요구, 협상 없는 높은 보수, 대화를 다른 메신저로 옮기자는 요구, 간단한 일에 비표준 소프트웨어 고집 |
| 권고 | 연락한 사람의 신원을 독립된 채널로 확인, 사전 채용 시험 코드는 회사 기기에서 실행하지 않고 필요하면 회사 소유가 아닌 기기의 VM에서 실행, 자금 이동에 서로 연결되지 않은 네트워크의 다중 승인, 개발 파이프라인과 저장소 접근 제한 |

### 사례: 면접 과제에서 지갑 서명 서비스까지 (2026)

Binance의 2026-11-03 사고 보고서를 2026-11-09 대조했다. 아래는 Binance의 자체 조사 결과이며 외부 보안 업체의 독립 검토가 진행 중이다. Binance는 FBI가 북한을 공격 주체로 지목했다고 인용한다.

1. **검색으로 받은 도구(6월):** 지갑 DevOps 엔지니어가 검색 엔진으로 찾은 AI 코딩 도구를 설치하다 변조된 Homebrew 설치본을 받았다. 보안팀이 이상을 탐지해 기기를 바꾸고 관련 자격 증명을 교체했지만, 보고서는 그 엔지니어의 역할과 같은 팀 동료가 계속 공격자에게 노출돼 있었다고 적는다.
2. **채용 플랫폼 접근(9월):** 다른 엔지니어가 정상 구직 플랫폼에서 가짜 회사의 프로젝트 디렉터를 사칭한 사람에게 연락을 받았다. 1차 화상 면접의 인사 담당자 사칭자는 신뢰를 얻으려고 개인 사진과 영상이 있는 SNS 계정을 보여 줬다. 2차 면접은 채팅 앱에서 가짜 CEO와 진행했고, 끝에 악성 코드 저장소가 든 과제를 업무용 컴퓨터에 내려받게 했다.
3. **설정 단계의 실행과 지속성:** 저장소는 설정 중에 악성 코드를 실행했다. Homebrew 디렉터리에 `pyenv_` 실행 파일을 만든 뒤 정상 `pyenv`를 지우고 이름을 바꿔 심볼릭 링크를 고쳤고, 바뀐 `pyenv`가 zsh 프로세스를 띄워 외부 서버의 명령을 실행했다. 이 제로데이 악성코드는 당시 엔드포인트 보안 도구에 탐지되지 않았다.
4. **확산(10-20):** 공격자는 감염된 컴퓨터와 내부 AI 도구로 지갑 인프라 팀 엔지니어 두 명(6월에 기기를 바꾼 DevOps 엔지니어 포함)을 장악했고, 그 DevOps 엔지니어의 컴퓨터에서 컨테이너 배포 토큰을 찾았다. 내부 AI 도구를 어떻게 악용했는지는 보고서에 없다.
5. **서명 서비스 접근(10-29):** 훔친 자격 증명으로 컨테이너를 배포하고 악성 스크립트를 실행해 내부 지갑 서명 서비스에 닿았다. 이후의 서명 악용, 위임 철회와 동결은 [[HSM-Key-Custody#유효한 서명과 허가된 거래를 구분한다|HSM 키 보관의 서명 정책]]에 있다.

Binance는 2026년에 북한 연계로 의심되는 사이버 위협 57건을 탐지하고 막았다고 밝혔다. 후속 조치로는 지갑 시스템과 내부 AI 도구, 그 접근 통제를 새 환경에서 다시 만들고, 기기 교체, 관련 자격 증명과 토큰 폐기, 전 직원 기기 정밀 검사, AI 기반 행위 이상 탐지와 기기 통제 강화를 들었다.

읽을 때 구분할 것:

- Homebrew는 설치를 소유한 계정으로 빌드와 설치를 실행한다(Homebrew FAQ). 그래서 같은 계정 권한으로 도는 악성 코드가 관리자 권한 없이 그 경로의 개발 도구를 바꿀 수 있고, PATH에서 앞서는 개발 도구 경로는 지속성 거점이 된다(해석).
- 기기와 자격 증명을 교체한 뒤에도 같은 팀의 역할과 동료 관계가 표적으로 남았다. 단말 하나를 정리했다고 사건을 닫지 않고, 역할과 권한 경로 단위로 노출을 다시 본다(해석).

## AI로 개인화한 사기 메일과 광고

2026-08-28 한 작가가 개인 블로그에 기록한 사례다. 개인 관찰이며 규모나 발신자를 검증한 자료는 아니다.

- 작가는 자기 시집 소개 문구를 거의 그대로 되비추고, 구한 적 없는 첫 독자의 만점 평가를 언급하며 홍보를 제안하는 메일을 받았다. 누군가 AI 도구에 자기 페이지를 읽혀 만든 문안으로 보고, 정보나 돈을 노린 피싱이라고 판단했다.
- YouTube 광고에는 20일 만에 근육질이 된다는 운동 강좌, 어떤 도수에도 맞는 안경, 무제한 무료 인터넷 USB처럼 실재가 의심되는 상품이 반복된다. 작가는 아주 적은 비율만 속아도 비용을 회수할 수 있고 개인화가 응답률을 더 높일 것이라고 우려하며, 돈을 내면 플랫폼이 광고를 거의 받아 준다고 본다.

적용 제안(해석):

- 내 공개 문장을 정확히 인용하는 칭찬이나 제안은 상대가 그 문장을 읽었거나 도구로 읽혔다는 뜻일 뿐 관계나 신원의 증거가 아니다. 돈, 개인정보나 링크 클릭을 요구하면 상대가 메일에 적은 연락처가 아닌 독립된 경로로 확인한다.
- 광고 상품은 판매자와 상품의 실재를 별도로 확인한다.

## 점검 체크리스트

조직:

- 외부 과제나 낯선 저장소를 업무 기기에서 실행하지 않는 정책과, 실행이 필요할 때 쓸 격리된 일회용 환경이 있는가
- 개발 도구를 공식 문서의 설치 경로로만 받고, 검색 광고나 낯선 링크의 설치본을 막는가([[Supply-Chain-Security#배포 경로 우회|배포 경로 우회]])
- 개발 단말의 권한이 운영 배포 토큰과 서명 경로로 바로 이어지지 않는가. 배포 토큰의 수명과 사용 위치를 제한했는가
- 패키지 관리자 경로의 실행 파일 교체와 심볼릭 링크 변경을 탐지 신호로 모으는가(운영 제안)
- 사내 AI 도구가 다른 직원의 단말이나 계정에 대해 할 수 있는 일을 권한 목록으로 관리하는가

개인(구직자와 창작자):

- 면접 과제는 업무 기기가 아닌 개인 VM이나 컨테이너에서 열고, 실행 전에 `package.json`의 scripts와 설치 스크립트를 읽는다([[Supply-Chain-Security#설치 시점 자동 실행|설치 시점 자동 실행]])
- 채용 담당자와 회사는 회사 공식 사이트나 별도 채널로 확인하고, 화상 통화를 핑계로 한 프로그램 설치 요구는 거절한다
