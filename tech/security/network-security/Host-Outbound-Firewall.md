# 호스트의 앱별 아웃바운드 통제

단말에서 프로그램마다 외부로 나가는 연결을 허용하거나 막는 통제다. 인바운드 방화벽이 무엇이 들어오는가를 본다면, 이 통제는 이 기기의 어떤 프로그램이 어디로 나가는가를 묻는다. 처음 보는 프로그램의 연결을 사용자에게 물어 규칙을 쌓는 방식이 대표적이며, macOS의 Little Snitch가 이 범주로 알려져 있다.

## 네트워크 쪽 egress 통제와 보는 단위가 다르다

| 위치 | 판정 단위 | 놓치는 것 |
|---|---|---|
| 네트워크 프록시와 egress 허용 목록 | 목적지 도메인과 주소 | 같은 단말 안에서 어느 프로그램이 보냈는지 |
| 호스트의 앱별 방화벽 | 프로그램과 목적지 | 허용한 프로그램 안에서 일어나는 전송(그 프로그램이 불러온 확장, 플러그인과 코드) |

놓치는 것 칸은 판정 단위에서 도출한 해석이다. 편집기를 허용하면 그 안에서 실행되는 확장의 전송도 편집기의 연결로 보인다. 확장의 권한 구조는 [[IDE-Extension-Trust-Model#확장은 편집기와 같은 권한으로 돈다|IDE 확장 신뢰 모델]]에 있다.

## 구현 예: Windows 기본 방화벽 위에 질문 창을 얹는다

2026-11-16 PacketHound 제품 페이지(1.4.0)와 GitHub 저장소를 기준으로 정리했다. 실행해 보지는 않았다.

- **동작:** 기본 아웃바운드 정책을 차단으로 바꾸고 Windows가 기록한 차단 이벤트를 감시해, 규칙이 없는 앱이 연결하려 하면 앱 이름, 게시자, 접속 대상과 포트를 보여 주고 허용 여부를 묻는다. 결정은 `wf.msc`에서 보이는 일반 Windows 방화벽 규칙으로 저장돼 프로그램을 닫아도 유지된다. 커널 드라이버를 쓰지 않으며, 방화벽 설정 변경과 보안 이벤트 로그 읽기에 관리자 권한이 필요하다.
- **규칙 단위와 기간:** 기본은 앱 전체이고 IP, 호스트나 도메인으로 좁힐 수 있다. 기간은 영구, 1시간, 당일, 앱 종료까지 중에서 고른다.
- **자동 허용과 예외:** Windows 폴더에 있고 시스템이 소유하며 유효한 Microsoft Windows 서명이 있는 프로그램은 자동으로 허용한다. 다만 PowerShell, curl, certutil, mshta, rundll32처럼 악성코드가 파일을 내려받는 데 자주 쓰는 기본 도구는 Windows 구성 요소여도 연결 전에 묻는다. 서명된 OS 구성 요소라는 사실이 그 연결의 목적까지 보증하지는 않는다는 구분이다(해석).
- **배포 조건:** Windows 10과 11(x64, ARM64)을 지원하며 무료이고 계정과 광고가 없다고 밝힌다. 저장소 라이선스는 GPL-3.0이다.

## 이 방식의 제약

- **첫 연결은 막힌다:** 차단 기록을 보고 묻는 구조라 허용한 뒤 앱이 다시 시도해야 한다. 브라우저는 새로고침이 필요할 수 있고, 첫 차단 뒤 포기하는 설치 프로그램은 일시 중지 후 다시 실행하라고 안내한다.
- **규칙이 파일 경로에 묶인다:** 새 버전이 새 폴더에 설치되면 다시 묻는다.
- **주소 기반 규칙:** 이름을 해석한 뒤 주소를 규칙에 더하므로 새 주소로의 첫 연결은 재시도가 필요하고, CDN처럼 주소를 공유하는 사이트는 규칙도 공유된다.
- **임시 허용의 수명:** 앱 종료까지 허용한 규칙은 모든 프로세스가 끝나야 풀리므로, 백그라운드에 남는 앱은 오래 열려 있다.
- **관리 주체와 충돌:** 기업이 그룹 정책으로 방화벽을 관리하면 그 설정이 우선하고, 타사 보안 제품이 Windows 방화벽을 대체한 환경에서는 동작하지 않는다.
- **알림 피로:** 질문이 잦으면 결국 다 허용하게 됐다는 사용 경험담이 소개 글의 댓글에 있었다(일화). 자동 허용 범위를 넓히면 질문은 줄지만 자동 허용된 프로그램은 감시에서 빠진다(해석).

## 적용 점검

아래는 운영 제안이다.

- 새 도구와 확장이 자주 드는 개발 PC에서 처음 보는 외부 연결을 드러내는 용도로 쓴다. 허용한 프로그램 안의 전송은 가리지 못하므로 확장 허용 목록과 네트워크 쪽 egress 통제를 함께 둔다.
- 조직 단말이면 MDM, 그룹 정책과 EDR이 방화벽을 관리하는지 먼저 확인한다.
- 영구 허용 규칙을 주기적으로 검토해 쓰지 않는 프로그램의 규칙을 지운다.
- 도구 자체의 통신도 확인한다. PacketHound는 수집하는 데이터가 없고, 연결 대상의 이름을 보여 주려고 일반 DNS 조회를 하며, 끌 수 있는 주 1회 업데이트 확인만 보낸다고 밝힌다.
