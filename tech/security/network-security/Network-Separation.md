# 망분리: 네트워크 경로로 신뢰 영역을 나누는 통제

망분리(network separation)는 내부 업무망과 인터넷 같은 외부망 사이의 직접 통신 경로를 없애, 한쪽에서 생긴 침해가 다른 쪽으로 번지거나 내부 자료가 외부로 나가는 길을 구조적으로 막는 통제다. 분리 수단은 망 자체를 따로 두는 물리적 방식과, 가상화로 실행 환경을 나누는 논리적 방식으로 나뉜다. 분리된 망 사이에서 꼭 필요한 자료만 정책에 따라 옮기는 통로가 망연계다.

한 줄 요약: **망분리는 경로를 줄이는 통제이지 위협을 없애는 통제가 아니다. 남겨 둔 경로(자료 반입, 망연계, 가상화 공유 기능)와 망 안의 위협이 실제 보안 수준을 결정하므로, 차단보다 데이터가 어디서 어디로 흘러야 하는지를 먼저 설계한다.**

## 무엇을 막고 무엇을 못 막는가

막으려는 경로는 두 방향이다.

- **유입**: 인터넷에서 받은 악성코드나 원격 조작이 같은 단말을 거쳐 내부 업무 시스템에 닿는 경로
- **유출**: 내부 시스템의 자료가 감염 단말이나 사용자 실수로 인터넷에 나가는 경로

반대로 다음은 망분리만으로 막지 못한다.

- 이동식 저장매체, 망연계, 유지보수 장비처럼 일부러 열어 둔 반입과 반출 경로
- 이미 망 안에 있는 내부자, 탈취된 내부 계정, 감염된 반입 파일
- 공급망으로 들어온 소프트웨어와 업데이트

NIST SP 800-82 Rev. 3도 OT 시스템이 IT 망과 연결되는 상황에서 air gap 같은 전통적 수단만으로는 사이버 공격을 막기에 충분하지 않다고 적는다. 분리는 공격 경로의 수를 줄이지만, 남은 경로와 망 내부의 통제가 없으면 한 번 들어온 위협이 안에서 자유롭게 움직인다.

## 방식 비교: 물리적, 서버 기반 논리적, 단말 기반 논리적

| 방식 | 분리 지점 | 강점 | 한계 |
|---|---|---|---|
| 물리적 망분리 | 단말, 케이블, 스위치 등 네트워크 자체를 업무용과 인터넷용으로 따로 구성 | 두 망 사이의 네트워크 경로가 없음 | 장비와 공간, 관리 비용, 자료 이동에 별도 절차 필요 |
| 서버 기반 논리적 망분리 (SBC, VDI) | 한쪽 망의 환경을 서버의 가상 데스크톱에서 실행하고 단말에는 화면만 전송 | 데이터가 단말로 오지 않고 서버에서 중앙 관리 | 서버와 라이선스 비용, 가상화 계층과 VDI 게이트웨이가 새 공격 면 |
| 단말 기반 논리적 망분리 (CBC) | 단말 한 대 안에 가상화 영역을 만들어 인터넷용 실행 환경을 격리 | 도입 비용이 가장 낮은 편, 기존 단말과 주변기기 재사용 | 두 환경이 같은 하드웨어와 호스트 OS를 공유해 격리 강도가 구현에 의존 |

SBC와 CBC는 국내 업계에서 쓰는 분류다. 서버 기반 방식은 어느 망을 가상화하느냐에 따라 인터넷용 환경을 가상 데스크톱으로 두는 구성과 업무용 환경을 가상 데스크톱으로 두는 구성이 모두 가능하다. 국제 용어로는 NIST 용어집의 access cross domain solution에 대응한다. 사용자 데이터를 도메인 사이로 옮기지 않고 다른 보안 도메인의 플랫폼, 애플리케이션이나 데이터에 접근하게 하는 방식이다.

물리적 분리라도 USB 같은 이동식 매체가 자동으로 막히는 것은 아니다. 매체 통제는 별도 정책이며, 오히려 망 사이의 유일한 자료 이동 수단이 되기 쉬워 가장 먼저 설계해야 할 경로다.

## 가상화 격리의 한계와 스냅샷

논리적 망분리의 격리는 결국 하이퍼바이저와 가상화 소프트웨어가 보장한다. NIST SP 800-125는 이 격리의 약점을 다음처럼 정리한다.

- **탈출(escape)**: 게스트 OS에서 빠져나와 하이퍼바이저에 접근하면 그 위의 모든 게스트를 장악할 수 있다. 하이퍼바이저는 모든 게스트의 단일 실패 지점이다.
- **공유 기능**: 호스트와 게스트 사이의 파일, 디렉터리, 클립보드 공유 기능은 편의 기능이지만 악성코드 전달과 자료 접근의 경로가 될 수 있다. 망분리용 가상 환경에서는 클립보드, 파일 전송, 드라이브 매핑과 인쇄를 방향별로 정책화해야 한다.

스냅샷과 기준 이미지 복원은 감염된 환경을 알려진 정상 상태로 빠르게 되돌리고, 메모리를 포함한 감염 상태를 포렌식용으로 보존할 수 있다는 장점이 있다. 그러나 복원이 해결하지 못하는 것도 분명하다.

- 이미 반출된 자료와 탈취된 계정, 세션은 되돌아오지 않는다.
- 이미지와 스냅샷은 취약점을 고치지 않는다. 오래 보관한 이미지는 다시 켤 때 그동안 쌓인 취약점을 그대로 갖고 올라온다.
- 스냅샷에는 비밀번호와 개인정보 같은 민감 데이터가, 실행 중 스냅샷에는 RAM 내용까지 담긴다. 옮기기 쉬운 만큼 디스크보다 더 엄격하게 보호해야 한다.
- 감염된 시스템의 스냅샷을 저장했다가 다시 불러오면 악성코드를 재도입할 수 있다.

## 망연계: 분리된 망 사이의 통제된 통로

완전히 닫힌 망은 외부 기관과 자료를 주고받는 업무, 외부 라이브러리와 업데이트 반입을 처리하지 못한다. 망연계는 분리된 두 망 사이에서 정책에 맞는 자료만 옮기는 통로다. NIST 용어집의 transfer cross domain solution이 같은 개념으로, 서로 다른 보안 도메인의 시스템 사이에서 데이터 이동에 보안 정책을 강제하는 장치를 가리킨다.

설계할 때 확인할 것은 다음과 같다.

- **방향**: 반입과 반출을 따로 정의한다. 한 방향만 필요하면 단방향 게이트웨이(data diode)를 검토한다. NIST SP 800-82 Rev. 3은 data diode를 하드웨어가 한 방향 전송만 가능해 방화벽처럼 양방향으로 설정할 수 없는 장치로 설명한다.
- **대상**: 허용할 파일 형식, 크기, 목적지와 승인 절차
- **검사**: 반입 파일의 악성코드 검사와 무결성 검증
- **기록**: 누가 무엇을 언제 어느 방향으로 옮겼는지 남긴다.

망연계는 두 망에 동시에 걸친 장치이므로 그 자체가 높은 가치의 표적이다. 허용한 경로가 곧 공격 경로라는 점에서, 망연계 시스템의 패치와 관리자 접근 통제, 기록 점검은 분리된 망 내부보다 엄격해야 한다.

## 국내 규제가 요구하는 범위

2026-09-23 국가법령정보센터 현행본 기준이다. 규제는 조직, 시스템, 단말과 사용자 권한에 따라 범위가 다르고 모든 PC를 물리적으로 분리하라는 일률적 요구가 아니다. 실제 적용 여부는 현행 원문과 감독기관의 해석으로 확인한다.

**금융 (전자금융감독규정 제15조, 2026-07-15 시행본)**

- 내부통신망과 연결된 내부 업무용 시스템은 인터넷(무선통신망 포함) 등 외부통신망과 분리, 차단하고 접속을 금지한다(제1항 제3호). 이 호의 문언은 분리 방식을 물리적으로 한정하지 않는다.
- 전산실 내 정보처리시스템과, 그 시스템에 운영, 개발, 보안 목적으로 직접 접속하는 단말기는 외부통신망으로부터 물리적으로 분리한다(제1항 제5호).
- 두 호 모두 예외가 있다. 이용자의 고유식별정보나 개인신용정보(가명처리 행위규칙을 준수한 가명정보는 제외)를 처리하지 않는 연구, 개발 목적으로서 자체 위험성 평가 뒤 금융감독원장이 정한 망분리 대체 정보보호통제를 적용하고 정보보호위원회가 승인한 경우, 그리고 업무상 불가피해 금융감독원장이 확인하거나 인정한 경우다.
- 금융위원회는 2024-08-13 금융분야 망분리 개선 로드맵에서 규제 샌드박스로 생성형 AI 활용 허용, SaaS 이용 범위 확대, 연구, 개발 환경 개선을 추진하고 이후 가명정보가 아닌 개인신용정보까지 처리할 수 있도록 특례를 고도화하겠다고 발표했다. 샌드박스 특례는 부가조건이 붙는 개별 허용이므로 적용 여부는 해당 지정 내용을 확인한다.
- **SaaS 예외의 후속 변경**: 2026-04-20 시행된 시행세칙 개정은 보안통제를 조건으로 내부 업무망의 SaaS 이용에 제15조 제1항 제3호의 예외를 둔다. 별도 혁신금융서비스 심사 없이 이용할 수 있지만, 이용자의 고유식별정보와 개인신용정보 처리는 제외되고 가명정보 활용은 별도의 혁신금융서비스 지정이 필요하다. 평가를 거친 SaaS 이용, 접속 단말 보호, 반기별 통제 이행 평가와 정보보호위원회 보고가 조건이다(금융위원회 보도자료, 2026-10-01 확인). 모든 망분리 의무나 모든 클라우드 이용을 면제하는 규칙은 아니다.

**클라우드 이용 절차와 망분리 예외는 따로 확인한다**

제도 변경 이력 대조(2026-10-16): 금융위원회의 2022-11-23 발표는 2023-01-01 시행 개정에서 클라우드 이용 사전보고를 사후보고로 전환하고 CSP 평가항목을 141개에서 54개로 정비했다고 설명한다. 같은 발표는 연구개발 분야 망분리 예외를 별도 항목으로 다룬다. 따라서 2020년 자료의 7영업일 전 보고와 141개 평가항목을 현재 절차로 복사하지 않는다.

이는 2023년 제도 변경을 확인한 기록이며 현행 보고 대상, 기한과 평가항목 전체를 재검증한 것은 아니다. 적용 시에는 클라우드 이용 업무의 중요도와 이용 절차, 해당 데이터와 단말에 적용되는 망분리 조항 및 예외 조건을 각각 확인한다. 망분리 예외가 있다는 사실만으로 CSP 평가나 내부 심의가 면제된다고 판단하지 않는다.

**개인정보 (개인정보의 안전성 확보조치 기준 제6조의2, 2026-07-01 시행본)**

- 전년도 말 기준 직전 3개월간 개인정보가 저장, 관리되고 있는 이용자 수가 일일평균 100만명 이상인 개인정보처리자가 대상이다.
- 개인정보처리시스템의 접근 권한을 설정할 수 있는 취급자와, 개인정보를 다운로드하거나 파기할 수 있는 취급자의 컴퓨터 등에 인터넷망 차단 조치를 해야 한다.
- 클라우드컴퓨팅서비스로 개인정보처리시스템을 운영하면 해당 서비스 접속 외의 인터넷을 차단하는 방식이다.
- 다운로드와 파기 권한자는 내부 관리계획의 위험 분석 결과 위험이 현저히 낮거나 위험을 줄이는 보호조치를 적용한 경우 예외가 가능하다. 민감정보나 제7조 제1항, 제2항의 개인정보를 다운로드, 파기할 수 있는 취급자는 이 예외를 쓰지 못한다.

**공공 (국가 망 보안체계, N2SF)**

국가정보원이 2025-09-30 국가 망 보안체계(N2SF) 보안가이드라인 1.0을 공개했다고 보도됐다. 업무와 정보를 기밀(C), 민감(S), 공개(O) 등급으로 구분해 보안대책을 차등 적용하는 체계로, 기존의 획일적 망분리를 대체하고 보완하는 방향이다. 국정원 원문은 이 문서 작성 시 직접 열람하지 못해 보도 기준으로 적었다.

## 판단: 경계 모델의 위치

망분리는 네트워크 위치로 신뢰를 나누는 경계(perimeter) 모델이다. NIST SP 800-207은 제로 트러스트를 물리적 위치나 네트워크 위치만으로 자산이나 계정에 암묵적 신뢰를 주지 않는 모델로 정의하고, 경계가 뚫린 뒤에는 내부 이동을 막지 못하는 점을 경계 중심 보안의 한계로 든다. 망분리 환경도 망 안의 인증, 최소 권한, 접속 기록과 내부 분할이 있어야 이 한계를 줄인다.

NIST SP 800-207 3.1절은 제로 트러스트 구현 접근을 강화된 신원 거버넌스, 마이크로 세그멘테이션, 네트워크 인프라와 SDP(software defined perimeter)로 나누고, 완전한 솔루션은 세 접근의 요소를 모두 포함한다고 본다. 3.1.2절의 마이크로 세그멘테이션은 개별 자원이나 자원 묶음을 고유한 네트워크 세그먼트에 두고, 지능형 스위치나 라우터, 차세대 방화벽(NGFW), 전용 게이트웨이 또는 엔드포인트의 소프트웨어 에이전트나 방화벽을 정책 집행 지점(PEP)으로 삼아 요청마다 동적으로 접근을 허용한다. 완전히 작동하려면 신원 거버넌스 프로그램이 필요하고 PEP를 위협과 업무 흐름 변화에 맞춰 다시 구성할 수 있어야 한다. 덜 발전된 게이트웨이나 stateless 방화벽으로 일부 기능만 구현하는 방식은 관리 비용과 변화에 빠르게 맞추기 어려운 점 때문에 매우 나쁜 선택으로 본다.

물리적 분리가 네트워크 경로를 끊는 강도는 가장 높다. 그러나 비용과 불편이 커질수록 자료 이동이 이동식 매체나 비공식 우회 경로로 몰릴 수 있고, 그 경로가 통제되지 않으면 실제 보안 수준은 떨어진다. 금융 로드맵은 보안대책을 조건으로 붙인 샌드박스 특례로 인터넷 활용 제한을 단계적으로 풀고, 공공 N2SF는 중요도 등급별 차등 통제를 내세운다. 두 흐름 모두 일률적 차단에서 조건부 허용과 차등 통제로 옮겨 가는 방향이다. 판단 기준은 가장 강한 분리가 아니라 자료의 중요도, 필요한 데이터 흐름, 규제 범위와 운영 비용의 조합이다.

### 제로 트러스트 전환 사례와 정책 근거

Google BeyondCorp는 특권 사내망(privileged intranet)을 전제로 하지 않도록 업무 애플리케이션을 인터넷으로 옮겨 간 구현 사례다. 2014년 논문 기준으로 접근은 사용자가 어느 네트워크에 있는지가 아니라 기기와 사용자 자격 증명으로 판단하며(필요하면 접근 제어 엔진이 위치 기반 통제를 더할 수 있다고도 적는다), 사내 건물 안에 있는 기기도 외부망과 비슷한 비특권 네트워크에 둔다. 기기는 기기 인벤토리 데이터베이스와 기기별 인증서로, 사용자는 사용자 데이터베이스, 그룹 데이터베이스와 SSO로 식별하며, 인증서는 기기를 식별할 뿐 그 자체로 권한을 주지 않는다. 모든 업무 애플리케이션은 인터넷에 노출된 접근 프록시를 거치고, 프록시 안의 접근 제어 엔진이 사용자와 그룹, 기기 인증서와 인벤토리 정보, 추론한 신뢰 수준으로 요청마다 인가한다. 전통적인 VPN 없이 어느 네트워크에서나 같은 방식으로 업무 애플리케이션에 접근하는 것이 논문이 설명한 목표 모델이다.

BeyondCorp로의 전환은 단계적이었다. 스위치의 netflow 표본을 비특권 네트워크와 나머지 사내망 사이의 ACL에 대조하고, 사용자 기기에서 비특권 네트워크를 기록 모드와 차단 모드로 시뮬레이션해 기준을 넘은 사용자와 기기부터 옮겼다. VPN 권한은 필요가 입증된 사용자로 좁혀 나갔고, 논문 시점에도 이전은 진행 중이었으며 독점 프로토콜로 서버와 통신하는 팻 클라이언트 애플리케이션을 남은 과제로 꼽았다. NIST SP 800-207 7장도 대부분의 조직이 제로 트러스트와 경계 기반 방식을 혼합한 상태로 무기한 운영할 것으로 보고, 전환은 업무 프로세스 하나씩 진행할 수 있으며 착수 전에 자산, 주체, 데이터 흐름과 업무 흐름을 조사하라고 권한다.

2022-01-26 OMB 각서 M-22-09(Moving the U.S. Government Toward Zero Trust Cybersecurity Principles)는 연방정부가 더는 기존 경계 기반 방어에 의존할 수 없다고 보고, 연방 기관에 2024 회계연도 말까지 CISA 제로 트러스트 성숙도 모델(ZTMM)이 정한 다섯 축(pillar)인 신원, 기기, 네트워크, 애플리케이션과 워크로드, 데이터에 맞춘 목표를 달성하도록 요구했다. 특정 네트워크에서 애플리케이션에 접근한다고 공용 인터넷에서 접근할 때보다 덜 위험하다고 보지 않으며, MFA는 VPN 같은 네트워크 인증이 아니라 애플리케이션 계층에서 강제하고 기관 직원, 계약자와 파트너에게는 PIV나 WebAuthn 같은 [[FIDO-WebAuthn#피싱과 재사용 공격에 강한 이유|피싱 저항형 MFA]]를 요구했다. 접근을 인가할 때 사용자 신원과 함께 기기 수준 신호를 하나 이상 고려하게 했고, 네트워크 축은 환경 안의 DNS 요청과 HTTP 트래픽을 모두 암호화하고 경계를 격리된 환경으로 나누는 계획의 실행을 시작하는 것을 목표로 두었다.

ZTMM 2.0(2023년 4월판)은 이 다섯 축에 가시성과 분석, 자동화와 오케스트레이션, 거버넌스의 세 공통 역량을 두고, 축 사이의 조정이 필요해지기 전까지는 축마다 제 속도로 Traditional에서 Initial, Advanced, Optimal로 나아갈 수 있는 점진적 전환을 제시한다. 초기 구현은 비용을 늘리기 쉽지만 장기적으로는 제로 트러스트가 전사에 똑같이 투자하는 대신 가장 중요한 데이터와 서비스에 보안 투자를 배분하게 한다고 보며, 스스로를 여러 전환 경로 중 하나로 규정한다. 2026년 10월 확인 기준 CISA는 ZTMM 웹페이지를 보관 자료(Archived Content)로 표시하며, 2.0 이후 판은 확인하지 못했다. M-22-09는 미국 연방 기관에 대한 지시이고 ZTMM도 연방 기관에 맞춘 모델이므로, 국내 망분리 의무의 적용 여부는 앞의 국내 규정으로 판단한다.

## 개발과 운영 체크포인트

- 분리 전에 데이터 흐름 목록부터 만든다. 어떤 자료가 어느 망에서 어느 망으로, 얼마나 자주, 누구의 승인으로 이동해야 하는지 정해야 망연계 정책과 예외를 설계할 수 있다.
- 금융권에서 운영이나 개발 목적으로 전산실 시스템에 직접 접속하는 단말은 물리적 분리 대상이다. 외부 문서 열람과 개발 도구, 패키지 반입 경로(내부 패키지 저장소, 망연계 반입 절차)를 개발 생산성 요구로 함께 설계한다.
- 외부 라이브러리 반입은 망연계 검사와 별개로 버전 고정, 무결성 검증과 취약점 스캔을 적용한다. [[Supply-Chain-Security#방어|공급망 보안]]
- 개인정보 이용자 수 기준에 해당하면 클라우드 콘솔과 DB 접근 권한을 설정하는 관리자 PC가 인터넷 차단 대상인지 확인한다.
- VDI를 쓰면 클립보드, 파일 전송, 드라이브 매핑과 인쇄를 방향별로 통제하고, 기준 이미지를 주기적으로 패치한다.
- 금융권 SaaS는 위 시행세칙 예외에 해당하는지와 보안통제 조건을 먼저 확인한다. 가명정보 활용이나 그 밖의 생성형 AI 이용은 별도 특례의 대상과 부가조건을 구분한다. 다른 조직도 해당 규제의 인터넷 차단 범위를 확인한다.
- 분리된 망 안에서도 계정별 최소 권한과 접속 기록을 운영한다. 망분리를 내부 통제 생략의 근거로 쓰지 않는다.

### 연구개발 산출물 반입을 승인 절차로 구성한다

연구개발망에서 만든 코드나 모델을 내부망으로 옮길 때는 파일 전송과 보안 승인 단계를 분리한다. AWS 기반 구현 예시는 S3의 산출물을 보안 검사하고, Step Functions에서 검사 결과를 분기한 뒤 담당자 승인을 기다려 DataSync로 이관하는 흐름이다. 검사 실패는 전송으로 이어지지 않게 한다. 대상 버킷의 버전 관리, Object Lock과 로깅은 산출물 보존과 감사 추적을 위한 구성 요소다.

이 흐름은 구현 예시이며 특정 AWS 서비스를 쓰라는 법적 의무나 해당 구성의 적법성 인증을 뜻하지 않는다. 적용할 때는 다음을 설계 점검 항목으로 둔다.

- 검사한 산출물과 승인 및 전송 대상이 동일한 버전인지 확인한다.
- 승인 전에는 전송 권한을 행사할 수 없게 하고, 실패와 거절을 별도 결과로 남긴다.
- 검사 결과, 승인자, 전송 결과를 연결해 반입 근거를 추적한다.
- 태그나 전송 성공만으로 보안 검토가 끝났다고 판단하지 않는다.

AWS 예시의 처리 흐름을 2026-10-14 대조했다. 현행 규제 전체의 재검증이나 실제 배포 검증은 이 보강 범위에 포함하지 않는다.

## 면접 체크포인트

- 망분리가 막는 유입, 유출 경로와 막지 못하는 경로(반입 매체, 망연계, 내부자, 공급망)
- 물리적 분리, 서버 기반 논리적 분리(VDI), 단말 기반 논리적 분리의 격리 지점과 트레이드오프
- 가상화 격리의 한계(탈출, 공유 기능)와 스냅샷 복원이 해결하지 못하는 것
- 망연계의 역할, 방향별 정책, data diode와 방화벽의 차이
- 금융 규정에서 업무용 시스템의 분리와 전산실 시스템 및 직접 접속 단말의 물리적 분리가 다르다는 점
- 경계 모델로서 망분리의 한계와 제로 트러스트, 일률적 차단에서 조건부 허용과 차등 통제로의 이동
- 마이크로 세그멘테이션이 단순 방화벽 구획과 다른 점, BeyondCorp의 기기와 사용자 기반 접근과 단계적 이전, M-22-09의 요구와 CISA ZTMM의 다섯 축
