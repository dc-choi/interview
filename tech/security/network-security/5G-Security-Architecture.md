# 5G 보안 구조: 식별자 은닉, 상호 인증, 키 계층과 SBA 보호

5G 시스템(5GS)의 보안은 3GPP TS 33.501이 정한다. 핵심은 네 가지다. 가입자의 영구 식별자를 무선 구간에서 숨기고, 단말과 네트워크가 서로를 인증하고, 하나의 장기 키에서 용도별 키를 계층적으로 파생하고, 코어 네트워크 기능(NF) 사이의 API 호출을 TLS와 OAuth 2.0으로 보호한다. 이 문서는 TS 33.501 Release 18 v18.6.0(2024-07) 본문을 기준으로 정리했다. 3GPP 포털에는 같은 Release의 더 새 판(18.12.0)과 Release 19, 20 판이 있으므로 세부 절차를 구현에 쓸 때는 대상 Release의 최신 판을 다시 확인한다.

## 식별자: SUPI, SUCI, 5G-GUTI

| 식별자 | 의미 | 무선 구간 노출 |
|---|---|---|
| SUPI | 가입자의 전역 영구 식별자. IMSI 형식이나 NAI 형식이 있다 | 평문으로 보내지 않는 것이 원칙이다. MCC, MNC 같은 라우팅 정보만 예외다(5.2.5) |
| SUCI | SUPI의 가입자 식별 부분을 은닉한 식별자 | 초기 등록과 Identity Request 응답에 쓴다 |
| 5G-GUTI | AMF가 발급하는 임시 식별자 | NAS 보안 활성화 뒤에만 새로 발급한다 |

**SUCI 생성.** 단말은 홈 네트워크가 통제해 USIM에 넣은 홈 네트워크 공개키로 보호 방식(protection scheme)을 실행해 SUCI를 만든다(6.12.2). IMSI 기반 SUPI라면 MSIN만 은닉 대상이고, SUPI 유형, 홈 네트워크 식별자(MCC와 MNC), Routing Indicator, 보호 방식 식별자, 공개키 식별자는 평문으로 남는다. 표준 보호 방식은 Annex C에 있다. 단말(ME)이 SUCI를 계산할 때는 USIM의 우선순위 목록에 Annex C 방식만 넣을 수 있고, 운영자 고유 방식은 USIM이 SUCI를 계산하도록 정한 경우에 쓴다. 은닉을 푸는 일은 홈 네트워크의 UDM 안에 있는 SIDF가 홈 네트워크 개인키로 한다(6.12.5). Routing Indicator는 여러 UDM 인스턴스 가운데 해당 가입자를 처리할 인스턴스를 찾는 데 쓴다.

**null-scheme의 경계.** null-scheme은 은닉하지 않는 방식이다. 규격이 null-scheme 사용을 정한 경우는 다음과 같다(6.12.2, 6.12.4).

- 5G-GUTI 없이 인증되지 않은 긴급 세션을 여는 경우
- 홈 네트워크가 null-scheme을 쓰도록 설정한 경우
- 홈 네트워크가 SUCI 생성에 필요한 공개키나, 단말이 계산할 때 쓰는 보호 방식 우선순위 목록을 USIM에 넣지 않은 경우
- 긴급 서비스용으로 등록하는 단말이 Identity Request를 받은 경우

규격은 가입자 프라이버시 활성화를 홈 네트워크의 통제 아래 둔다(5.2.5). 따라서 5G라는 사실만으로 식별자 은닉이 켜졌다고 볼 수 없고, 운영자의 USIM 프로비저닝을 확인해야 한다. NAI 형식 SUPI는 사용자명 길이가 은닉된 SUCI의 길이로 새어 나갈 수 있어, 규격은 대응 예로 고정 길이 사용자명이나 패딩을 들고 실제 방법은 운영자에게 맡긴다.

**IMSI 캐처와의 관계.** IMSI 캐처는 가짜 기지국으로 단말이 영구 식별자를 드러내게 만드는 공격이다. 5G에서 Identity Request를 받은 단말은 SUPI를 보내지 않고 새로 계산한 SUCI로 답한다(6.12.2 NOTE 3, 6.12.4). null-scheme이 아니면 SUCI는 SUPI를 드러내지 않는다. 단말은 같은 5G-GUTI에 대한 Identity Request에 새 SUCI로 답하는 빈도를 제한해야 한다. 이전 세대 규격의 동작은 이 문서에서 대조하지 않았다.

## 1차 인증: 5G AKA와 EAP-AKA'

1차 인증과 키 합의의 목적은 단말과 네트워크의 상호 인증, 그리고 이후 보안 절차에 쓸 키 재료 생성이다(6.1.1.1). 공중망의 인증 방법은 5G AKA와 EAP-AKA' 두 가지이며(SNPN 같은 사설망에는 다른 방법을 허용하는 예외가 있다), 인증 요청을 받은 UDM/ARPF가 SUCI를 SUPI로 풀고 방법을 고른다(6.1.2).

5G AKA의 흐름(6.1.3.2)은 다음과 같다.

1. UDM/ARPF가 RAND, AUTN, XRES*, K_AUSF로 홈 환경 인증 벡터를 만든다.
2. AUSF가 XRES*를 보관하고 그 해시(HXRES*)와 K_SEAF를 계산한 뒤, K_SEAF를 뺀 RAND, AUTN, HXRES*만 서빙 네트워크의 SEAF에 준다.
3. SEAF가 RAND와 AUTN을 단말에 보낸다. USIM은 AUTN을 받아들일 수 있는지 확인해 값의 신선도를 검증하고, 받아들이면 응답을 계산한다. AUTN 검사의 세부는 TS 33.102를 따른다. 가짜 기지국이 정상 망의 RAND와 AUTN을 중계하면 이 검사만으로는 구별하기 어렵다고 해석할 수 있고, 규격도 서빙 네트워크 인증은 뒤이은 NAS 보안 모드 명령(SMC)과 이후 키 사용이 성공할 때 암묵적으로 완성된다(5.1.2, 6.1.3.2).
4. SEAF가 단말 응답의 해시를 HXRES*와 비교하고, 원래 응답(RES*)을 AUSF에 넘긴다.
5. AUSF가 RES*를 보관한 XRES*와 비교해 홈 네트워크 관점의 성공을 판정하고, 성공했을 때만 K_SEAF를 SEAF에 보낸다.

5G AKA는 방문 네트워크가 인증 확인 메시지로 홈 네트워크에 단말 인증 성공의 증거를 보내게 해 EPS AKA를 강화한다. 로밍에서 홈 네트워크의 통제가 커지는 이유다. 다만 규격은 인증 프로토콜만으로는 부정한 등록 요청 같은 사기를 막을 수 없고, 홈 네트워크가 인증 결과를 이후 절차와 연결해야 한다고 설명한다. 홈 네트워크가 그 결과로 무엇을 할지는 운영자 정책이다(6.1.4.1).

**가짜 기지국에 대한 해석.** 상호 인증이 있으면 키를 모르는 가짜 기지국은 정상 네트워크처럼 인증과 보안 설정을 마칠 수 없다. 그러나 이것이 가짜 기지국 공격의 원천 차단을 뜻하지는 않는다. 규격은 RRC 시그널링 대부분의 무결성 보호를 요구하지만 TS 38.331이 명시한 예외 메시지를 두고(5.3.3), 사용자 평면 무결성 보호와 기밀성 보호는 선택 사항이다(5.3.2, 5.3.3). 보안 활성화 전 단계와 예외 메시지, 운영자가 끈 보호 기능은 별도의 위협 면으로 본다.

## 키 계층

| 단계 | 키 | 만드는 곳 |
|---|---|---|
| 장기 키 | K | USIM과 UDM/ARPF. 단말에서는 변조 방지 보안 하드웨어 밖으로 평문으로 나가지 않는다(5.2.4) |
| 인증 | CK, IK(EAP-AKA'는 여기서 CK', IK'를 다시 파생) | CK, IK는 USIM과 UDM/ARPF, CK', IK'는 단말(ME)과 ARPF |
| 홈 네트워크 | K_AUSF | 단말과 AUSF(또는 ARPF) |
| 앵커 | K_SEAF | 단말과 AUSF가 K_AUSF에서 파생해 서빙 네트워크 SEAF에 준다 |
| 서빙 네트워크 | K_AMF | 단말과 SEAF가 K_SEAF에서 파생한다 |
| NAS | K_NASint, K_NASenc | K_AMF에서 파생한다 |
| 무선 접속 | K_gNB와 NH | K_AMF에서 파생한다. RRC 키(K_RRCint, K_RRCenc)와 사용자 평면 키(K_UPint, K_UPenc)는 K_gNB에서 파생한다 |
| 비3GPP 접속 | K_N3IWF | K_AMF에서 파생한다 |

계층의 의미는 노출 범위를 나누는 데 있다. 서빙 네트워크는 K_SEAF 아래의 키만 받으므로 K나 K_AUSF를 알지 못한다. 기지국은 K_gNB와 AMF가 보내는 {NH, NCC} 쌍, 그 아래의 키를 다룬다.

**키 갱신 시점.** 키는 메시지마다 새로 만들어지지 않는다. 무선 구간(AS) 키는 대체로 연결 단위로 새로 파생된다. 단말이 CM-IDLE에서 CM-CONNECTED로 바뀌어 새 AS 보안 컨텍스트를 세울 때 AMF와 단말은 상향 NAS COUNT를 넣어 K_AMF에서 새 K_gNB를 파생한다. 어느 NAS 메시지의 COUNT를 쓰는지는 앞선 NAS 보안 모드 명령의 유무에 따라 다르다(6.8.1.2). RRC_INACTIVE에서 연결을 재개할 때도 새 K_gNB를 파생한다(6.8.2). 핸드오버에서는 대상 셀의 PCI와 하향 주파수를 넣어 K_gNB를 다시 파생하며, 같은 K_gNB 사슬에서 이어 파생하는 수평 파생과 새 NH에서 시작하는 수직 파생이 있다(6.9.2.1.1). 같은 gNB-CU 안의 핸드오버에서는 현재 K_gNB를 유지할 수 있다(6.9.2.3.1). K_AMF와 NAS 키도 고정값이 아니다. 재인증, NAS와 AS의 key refresh와 re-keying 절차(6.9.4) 외에 AMF가 바뀌는 이동성 등록과 핸드오버의 K_AMF 수평 파생(6.9.3, 6.9.2.3.3), EPS와의 연동 같은 경우에도 바뀔 수 있다.

## 코어 네트워크의 서비스 기반 구조 보호

5G 코어는 NF가 HTTP/2 기반 서비스 API로 서로를 호출하는 서비스 기반 구조(SBA)다. TS 33.501 13절의 요구는 다음과 같다.

- **전송 보호.** 모든 NF는 상호 인증 TLS와 HTTPS를 지원해야 하고, 인증서의 신원으로 인증과 정책 검사를 한다(13.1.0). PLMN 안에서는 다른 수단으로 네트워크 보안을 제공하지 않는 한 TLS를 쓴다. 물리적으로 보호된 인터페이스처럼 신뢰할 수 있는 구간에서 암호 보호를 쓸지는 운영자가 정한다.
- **서비스 접근 인가.** NRF와 NF는 OAuth 2.0 기반 인가를 반드시 지원해야 하지만, 실제로 토큰을 쓸지는 선택이다. 토큰을 쓰지 않으면 로컬 정책에 따른 정적 인가를 쓴다(13.3.0). 토큰을 쓸 때는 NRF가 OAuth 2.0 인가 서버로서 Client Credentials Grant로 액세스 토큰을 발급하며, 토큰은 JWS로 서명하거나 MAC으로 보호한 JWT다(13.4.1). 기본 인가 단위는 NF 유형별 허용 서비스를 담은 scope이고, 알림(notification) 요청에는 이 OAuth 인가를 적용하지 않는다.
- **사업자 간 경계.** 다른 PLMN과의 연결은 경계에 SEPP를 두고 N32에서 사업자 간 보안을 적용한다(4.2.1). 제어용 N32-c는 TLS를 쓰고, 메시지를 전달하는 N32-f는 중간 로밍 사업자의 유무와 역할에 따라 TLS나 응용 계층 보호(PRINS)를 쓴다. 중간 사업자가 메시지를 보거나 수정해야 하면 PRINS가 필요하며, 어느 방식을 쓸지는 SEPP끼리 협상한다(13.1.2, 13.2, 13.5).

NF끼리 서로를 인증하고 요청을 인가하는 구조는 내부망을 신뢰하지 않는 설계와 방향이 같다. 다만 TLS 인증은 호출이 아니라 연결 단위이고, 운영자가 TLS 대신 NDS/IP나 물리적 보호에 기대는 구간과 토큰 대신 정적 인가를 쓰는 구성을 허용한다. 따라서 모든 호출의 검증이 규격으로 강제된다고 표현하지 않는다.

## 네트워크 슬라이싱과 보안

네트워크 슬라이싱은 하나의 물리 망 위에 용도별 논리 네트워크를 나누는 기능이다. TS 33.501은 1차 인증과 별도로 슬라이스 단위의 인증과 인가(NSSAA)를 사용 선택 기능으로 정의한다. NSSAAF가 서빙 AMF의 요청을 받아 AAA 서버(AAA-S)로 전달하며, AAA-S는 외부 제3자가 소유할 수도 있다(5.13, 16절). 슬라이스가 논리적으로 나뉜다는 사실만으로 한 슬라이스의 침해가 다른 슬라이스에 번지지 않는다고 단정하지 않는다. 이 문서는 규격의 슬라이스 간 격리 보장 범위를 대조하지 않았으므로, 격리 수준은 대상 망의 구성과 자원 배치에서 확인한다.

## 점검 포인트

- 5G 보안 설명에서 기능의 존재와 실제 적용을 구분한다. SUCI 은닉은 홈 네트워크의 공개키 프로비저닝, 기밀성 보호와 사용자 평면 무결성 보호는 운영자와 SMF 보안 정책에 따라 달라진다.
- 상호 인증은 단말과 네트워크가 서로를 확인하는 절차이고, 보안 활성화 전 메시지와 예외 메시지까지 보호하는 장치가 아니다.
- 키 계층은 키를 메시지마다 바꾸는 장치가 아니라 노출 범위를 나누는 장치다. 무선 구간 키는 연결 시작, 비활성 상태에서의 재개와 대부분의 핸드오버에서 새로 파생되고(같은 gNB-CU 안의 핸드오버는 예외가 될 수 있다), 상위 키의 변경 조건은 위 키 갱신 시점 설명을 따른다.
- SBA는 TLS, OAuth 2.0과 SEPP로 NF 사이의 호출을 보호하는 구조다. 토큰 사용, 내부 구간의 TLS와 N32-f 보호 방식에는 운영자 선택이 남아 있다.
