# 타입 특징

TypeScript는 JavaScript의 동적 실행 모델 위에 **정적 타입 시스템**을 얹어 실행 전에 타입 오류를 찾는다. 타입 시스템은 값이 어떤 집합에 속하는지 검사하고 컴파일 진단과 IDE 정보를 제공한다. 타입은 emit 결과에서 지워지므로 외부 입력의 런타임 검증까지 대신하지는 않는다.

## 정적 타입 시스템의 가치
1. **오류 조기 발견**: 잘못된 호출과 속성 접근을 실행 전에 찾는다.
2. **코드 문서화**: 함수 시그니처와 객체 타입으로 의도를 전달한다.
3. **IDE 경험**: 자동완성, 리팩터링, 타입 기반 이동이 타입 정보에 기반해 동작한다.

## 타입 계층과 집합론 관점
타입은 값들의 집합으로 해석할 수 있다. `unknown`은 모든 값을 안전하게 받을 수 있는 top type이고 `never`는 값이 없는 bottom type이다. 기본적으로 부분집합인 타입의 값은 상위 집합 타입에 대입할 수 있지만 그 반대는 보장되지 않는다.

`any`를 전체집합의 정상적인 최상위 타입으로 보면 안 된다. `any`는 대입과 연산 검사를 우회하며 타입 계층의 일반 규칙을 깨는 탈출구다.

자세한 타입 계층은 프로젝트에 포함된 `타입계층도.png` 이미지로 시각화되어 있다.

## 원시 타입 (Primitive)
값 하나로 표현되는 기본 타입이다.
- **`number`** — 정수, 실수 모두 포함. NaN과 Infinity도 number.
- **`string`** — 문자열.
- **`boolean`** — true / false.
- **`null`** — 값이 없음을 명시적으로 표현한다.
- **`undefined`** — 선언만 되고 값이 할당되지 않은 상태.
- **리터럴 타입**: `"left" | "right"`처럼 값 자체를 타입으로 사용한다. Union과 결합해 상태나 이벤트 종류를 표현할 때 강력하다.

대문자 `String`, `Number`, `Boolean`, `Symbol`은 박싱된 객체 타입이므로 일반 값의 타입으로 사용하지 않는다. 비원시 값 전체를 뜻할 때는 전역 `Object`가 아니라 `object`, 모든 값의 안전한 경계에는 `unknown`을 쓴다.

코드 예시는 `types/primitive/` 디렉토리의 `number.mts`, `string.mts`, `boolean.mts`, `literal.mts`, `null.mts`, `undefined.mts` 참고.

## 타입 추론과 넓힘 (Widening)
명시적 타입 없이 값만 대입하면 컴파일러가 타입을 추론하는데, 이때 **얼마나 넓게 잡느냐**가 선언 방식에 따라 갈린다.

- **`let`은 넓게(widening), `const`는 좁게** 추론된다. 재할당 가능한 `let`은 리터럴을 그 상위 원시 타입으로 넓히고, 재할당 불가한 `const`는 리터럴 그대로 유지한다.

```typescript
let a = "mark";   // string 으로 넓힘
const b = "mark"; // "mark" 리터럴 타입 유지
```

- **배열은 원소들의 공통 타입**으로 추론한다.

```typescript
const list = [1, 2, null]; // (number | null)[]
```

- **`as const`**로 넓힘을 막고 리터럴성과 순서, 읽기 전용성을 보존한다. 상태 목록이나 설정 상수를 유니언 타입으로 뽑아낼 때 유용하다.

```typescript
const direction = ["left", "right"] as const;
// readonly ["left", "right"]  →  typeof direction[number] = "left" | "right"
```

추론은 강력하지만 의도를 항상 맞히지는 않는다. 원하는 형태가 아니면 명시적 타입이나 `as const`로 바로잡는다. `as const` 활용 패턴은 [[TS-Enum-Antipattern|enum 대안]] 참고.

## 복합 타입 (Object / Array / Tuple)
- **Object**: TS는 구조적 타이핑을 따른다. 선언 이름이 달라도 필요한 필드 구조가 호환되면 대입할 수 있다. 선택적 속성(`?`)으로 옵셔널 필드를 표현할 수 있다.
- **Array**: 가변 길이이며 원소 타입은 동일하다. `T[]` 또는 `Array<T>` 문법을 쓴다.
- **Tuple**: 길이와 각 인덱스의 타입을 표현한 배열 타입이다.

인덱스 시그니처는 미리 알 수 없는 키의 값 타입을 표현한다. 문자열 인덱스 시그니처가 있으면 이름이 알려진 속성도 그 값 타입과 호환되어야 한다.

```typescript
interface Scores {
  [name: string]: number;
  total: number;
}
```

코드 예시: `types/object/object.mts`, `types/array/array.mts`, `types/type-index/typeIndex.mts`

## 특별한 타입 (any / unknown / void / never)
이 네 타입은 타입 검사의 경계와 함수 제어 흐름을 표현한다.

- **`any`**: 타입 검사를 사실상 포기하는 탈출구다. 점진적 마이그레이션의 임시 경계에도 범위를 좁혀 사용한다.
- **`unknown`**: 모든 값을 받을 수 있지만 사용 전에 타입을 좁혀야 하는 안전한 top type이다.
- **`void`**: 호출자가 반환값을 사용하지 않는 함수 계약을 표현한다.
- **`never`**: 값이 없는 공집합이다. 항상 예외를 던지거나 끝나지 않는 함수, exhaustive check에 사용한다.

`any`는 검사를 생략하고 `unknown`은 검사를 미룬다. 외부 데이터 경계에서는 `unknown`으로 받은 뒤 타입 가드나 schema validator로 좁힌다.

### `void`의 두 문맥

문맥상 `() => void`를 요구하는 곳에는 값을 반환하는 함수를 전달할 수 있다. 반환값을 호출자가 관찰하지 않겠다는 뜻이기 때문이다. 반면 `function f(): void`처럼 함수 선언에 반환 타입을 직접 적으면 값을 반환할 수 없다.

TypeScript 5.1부터 반환 타입이 `undefined`인 함수는 명시적인 `return`이 없어도 된다. `void`와 `undefined`를 같은 규칙으로 취급하지 않는다.

코드 예시: `types/any-unknown/any.mts`, `types/any-unknown/unknown.mts`, `types/void-never/void.mts`, `types/void-never/never.mts`

## 집합 연산 타입 (Union / Intersection)
집합론의 합집합, 교집합을 타입 시스템으로 가져온 것이다.

- **Union (`|`)** — A 또는 B에 속한 값을 허용한다. `number | string`을 사용할 때는 타입 좁히기로 어느 쪽인지 확인한 뒤 해당 타입의 메서드를 쓸 수 있다.
- **Intersection (`&`)** — A와 B를 모두 만족하는 값을 요구한다. 주로 객체 타입의 요구 조건을 합칠 때 사용한다. 원시 타입끼리 교집합을 내면 대부분 `never`가 된다(예: `string & number` = `never`).

## 타입 좁히기 (Type Narrowing)
Union 타입 값을 조건에 따라 더 구체적인 타입으로 좁혀 안전하게 사용하는 기법이다. 컴파일러는 조건문 블록 내부에서 값이 어떤 타입으로 좁혀졌는지 추적한다.

주요 좁히기 수단:
- **`typeof`** — 원시 타입 구분 (`typeof x === "string"`)
- **`instanceof`** — 클래스 인스턴스 구분
- **`in` 연산자** — 객체 속성 존재 여부로 구분
- **사용자 정의 타입 가드(`x is T`)** — 복잡한 조건을 타입 술어(type predicate) 함수로 추출
