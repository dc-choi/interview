# HBM 적층과 베이스 다이

HBM(High Bandwidth Memory)은 DRAM 다이를 수직으로 쌓고 TSV(Through Silicon Via)로 연결하는 고대역폭 메모리다. 저장 용량, 데이터 전송 대역폭, 연산 칩과 연결하는 회로를 나누어 보면 적층 수와 공정 이름만으로 성능을 판단하는 오류를 줄일 수 있다.

## 저장, 제어와 패키징의 역할

| 구성 | 역할 | 구분할 점 |
| --- | --- | --- |
| 코어 DRAM 다이 | 데이터를 저장하는 층 | DRAM 셀의 용량과 적층 수를 확인한다 |
| 베이스 다이 | 적층 아래에서 연산 칩과 연결되는 로직 층 | 저장용 DRAM과 다른 공정을 사용할 수 있다 |
| TSV | 실리콘을 수직으로 통과하는 칩 사이 연결 | 상하 적층 연결과 패키지 안의 수평 연결을 구분한다 |
| 인터포저와 패키징 | 연산 칩과 HBM을 하나의 패키지에서 연결 | CoWoS는 이런 통합에 쓰이는 TSMC의 패키징 기술이다 |

SK hynix의 2024년 협력 발표는 HBM4 베이스 다이에 TSMC의 로직 공정을 적용하고 CoWoS 통합을 최적화하는 계획을 설명했다. 이는 당시 계획의 근거이며 현재의 물량이나 모든 제품의 제조 경로를 증명하지 않는다. Samsung의 HBM 제품 페이지는 2026-10-28 확인 기준으로 HBM4에 1c DRAM과 4nm 로직 베이스 다이를 명시한다. 한 패키지의 저장층과 로직층이 서로 다른 공정을 쓰는 사례다.

베이스 다이를 어느 파운드리에서 만든다는 설명을 그 업체가 코어 DRAM도 제조한다는 뜻으로 확대하지 않는다. 회로 설계, 웨이퍼 제조와 패키지 통합은 각각 확인할 역할이다.

## 용량과 대역폭은 별도 계산이다

같은 밀도의 DRAM 다이를 사용한다는 단순화 아래 스택 용량은 다이 하나의 저장 비트 수에 적층 수를 곱해 계산한다. 외부 인터페이스의 이론 대역폭은 데이터 핀 수와 핀당 전송률로 계산한다.

- 용량 예시: 다이당 24 Gb, 12개 적층이라는 가정이면 `24 × 12 ÷ 8 = 36 GB`다.
- 대역폭 예시: 데이터 핀 2,048개, 핀당 8 Gb/s라는 가정이면 `2,048 × 8 ÷ 8 = 2,048 GB/s`다.

두 계산은 십진 단위를 사용한 설명용 예시이며 특정 제품의 실측값이 아니다. `Gb`는 비트, `GB`는 바이트다. 적층 수를 낮추면 첫 계산의 용량은 줄지만, 데이터 핀 수와 핀당 전송률이 유지된다면 두 번째 계산의 이론 대역폭까지 같은 비율로 줄지는 않는다. 실제 처리량은 메모리 접근 패턴과 시스템 제약을 따로 측정해야 한다.

용량이 충분해도 데이터를 가져오는 속도가 병목일 수 있다. 반대로 대역폭이 높아도 작업 데이터가 메모리에 들어가지 않으면 데이터 배치와 실행 방식을 다시 설계해야 한다. 용량, 대역폭과 지연을 같은 성능 지표로 취급하지 않는다.

## 맞춤형 베이스 다이는 연산 칩과의 경계를 바꾼다

NVHBM은 NVIDIA가 공개한 맞춤형 HBM 베이스 다이 기술이다. 2026-08-26 기술 설명은 메모리 컨트롤러를 3D HBM 스택으로 옮기고 맞춤형 PHY(물리 인터페이스)를 결합해 연산 칩의 인터페이스 면적 부담을 줄이는 구조를 제시한다. 이를 모든 표준 HBM이 같은 컨트롤러 배치를 쓴다는 뜻으로 읽지 않는다.

NVIDIA는 표준 HBM4e 대비 스택당 대역폭 최대 30% 증가와 HBM 전력 사용 최대 15% 감소를 제시한다. 이는 공급사가 발표한 비교 수치이며 이 문서에서 재현한 벤치마크가 아니다. 대역폭 개선율을 모든 애플리케이션의 속도 개선율로 바꾸거나 HBM 전력 감소율을 데이터센터 전체 전력 감소율로 바꾸지 않는다.

특정 고객의 3nm 제조 요구, 8단 발주와 공급 부족 전망은 이 문서의 확인 범위에 포함하지 않는다. 공식 구조 설명만으로 개별 계약 조건과 생산량을 확정할 수 없다.
