# 순위 결합과 레이팅 시스템

여러 순위나 대결 결과를 하나의 종합 순위로 만드는 방법은 하나가 아니다. 같은 입력도 집계 규칙에 따라 1위가 바뀐다. 따라서 종합 순위는 숫자라는 이유만으로 객관적인 답이 되지 않고, 무엇을 목표로 누구와 비교했으며 어떤 변환과 가중치를 썼는지를 함께 설명해야 의미가 정해진다.

방법은 입력의 형태로 나눠 볼 수 있다.

| 입력 | 방법 | 결과 |
|---|---|---|
| 여러 명이 낸 전체 순위표 | 위치 점수 합산(Borda), 쌍대 비교(Condorcet) | 한 번의 종합 순위 |
| 여러 시스템이 낸 검색이나 추천 순위 목록 | Reciprocal Rank Fusion(RRF) | 결합 목록 |
| 시간에 따라 쌓이는 1대1 대결 결과 | Elo 레이팅 | 계속 갱신되는 실력 점수 |

## 위치 점수 합산과 쌍대 비교

위치 점수 합산은 각 순위표에서 1위, 2위, 3위에 미리 정한 점수를 주고 합한다. 일반적인 위치 점수 규칙에서는 점수 배분을 설계자가 정하며, 후보가 n명일 때 n−1, n−2, …, 0점을 주는 경우를 Borda 방식이라 부른다.

후보 A, B, C에 대해 7명이 다음처럼 투표했다고 하자.

| 표 수 | 순위 |
|---|---|
| 3 | A > B > C |
| 2 | B > C > A |
| 2 | C > A > B |

1위 2점, 2위 1점, 3위 0점이면 A는 3×2 + 2×0 + 2×1 = 8점, B는 3×1 + 2×2 + 2×0 = 7점, C는 3×0 + 2×1 + 2×2 = 6점으로 A가 1위다.

같은 표를 둘씩 다수결로 비교하면(Condorcet 방식) 결과가 순환한다.

- A 대 B: A를 위에 둔 표가 3 + 2 = 5, B를 위에 둔 표가 2라 A가 이긴다.
- B 대 C: B를 위에 둔 표가 3 + 2 = 5, C를 위에 둔 표가 2라 B가 이긴다.
- C 대 A: C를 위에 둔 표가 2 + 2 = 4, A를 위에 둔 표가 3이라 C가 이긴다.

A > B > C > A가 되어 모든 상대를 이기는 후보(Condorcet 승자)가 없다. 합산 방식은 이 순환을 숫자 하나로 덮어 1위를 만들어 내고, 쌍대 다수결만으로는 순환이 드러날 뿐 1위가 정해지지 않는다. 실제 쌍대 비교 계열 방법(검색의 Condorcet Fuse 등)은 이런 경우에도 순위를 내도록 규칙을 더하며, 그 규칙 역시 설계 선택이다.

## Reciprocal Rank Fusion

여러 검색 시스템의 순위를 합칠 때 각 시스템의 점수는 척도가 달라 직접 더하기 어렵다. RRF는 점수를 버리고 순위만 쓴다.

```text
RRFscore(d) = Σ_r 1 / (k + r(d))
```

`r(d)`는 순위 목록 r에서 문서 d의 순위(1부터)다. k = 60이면 한 목록의 1위는 1/61, 10위는 1/70을 받고, 두 목록에서 모두 5위인 문서는 2/65를 받는다.

- 상위 순위일수록 기여가 크지만, 지수 함수처럼 하위 순위의 기여가 사라지지는 않는다. 상수 k는 한 시스템의 이례적인 상위 순위가 결과를 좌우하는 영향을 줄인다.
- k = 60은 원 논문이 예비 실험에서 정한 뒤 고정한 값이다. 논문은 60이 최적에 가깝지만 선택이 결정적이지 않다고 밝혔다. 예비 실험의 MAP는 k가 10에서 100 사이일 때 0.2123에서 0.2147로 비슷했고, k = 0(0.2072)과 500(0.2098)에서는 Condorcet Fuse(0.2074) 수준으로 떨어졌다. 극단값이 아니라면 값에 덜 민감하다는 뜻이다.
- 원 논문의 TREC 실험에서 RRF는 Condorcet Fuse보다 일관되게 좋았다. 점수 기반 결합인 CombMNZ는 TREC 3에서 RRF보다 높았고 LETOR 3에서도 근소하게 앞서(유의하지 않음), RRF가 모든 결합 방식을 항상 이기는 것은 아니다. 논문은 소수의 시스템만 높게 평가한 문서도 순위를 끌어올릴 수 있어 개별 순위의 다양성을 살리기 때문이라고 추정하며, 다수결 방식에서는 약한 선호의 다수가 강한 선호를 덮을 수 있다고 설명한다.
- 학습이나 전체 통계가 필요 없어 시스템별로 순위를 계산해 더하기만 하면 된다. 대신 1위와 2위의 점수 차이가 매우 커도 순위 차이로만 반영된다.

검색 엔진의 하이브리드 결합에서 쓰는 구체적인 설정은 [[OpenSearch-Hybrid-Search-RRF-Filtering|OpenSearch RRF와 filter 배치]]와 [[MongoDB-Vector-Search|MongoDB Vector Search]]에 있다.

## Elo 레이팅

Elo 방식은 대결이 끝날 때마다 실제 결과와 기대 결과의 차이만큼 점수를 옮긴다. 체스 레이팅처럼 1대1 대결이 계속 쌓이는 환경에 맞는 방식이다.

```text
ΔR = K × (실제 결과 − 기대 결과)   # 실제 결과: 승 1, 무 0.5, 패 0
```

- 점수가 같은 두 선수의 기대 결과는 각각 0.5다. K = 32라면 이긴 쪽은 32 × (1 − 0.5) = 16점을 얻고 진 쪽은 16점을 잃는다. 1500점 동점이었다면 1516점과 1484점이 된다.
- 기대 결과는 점수 차이로 정한다. 점수가 높은 쪽의 기대 결과가 크므로, 강한 상대를 이기면 많이 오르고 약한 상대를 이기면 조금 오른다. 한 경기로 움직일 수 있는 폭은 K를 넘지 않는다.
- 점수 차이가 승률 추정으로 바뀐다는 점이 쓸모다. 대진 편성, 이변 확률 추정과 매칭에 같은 숫자를 쓸 수 있다.

### 실제 규정의 예: FIDE

2024-03-01부터 적용된 FIDE 스탠더드 레이팅 규정은(래피드와 블리츠는 별도 규정) 기대 결과를 공식 대신 표(점수 차이 D와 득점 확률 PD)로 정한다.

| 점수 차이 D | 높은 쪽 PD | 낮은 쪽 PD |
|---|---|---|
| 0~3 | 0.50 | 0.50 |
| 198~206 | 0.76 | 0.24 |
| 392~411 | 0.92 | 0.08 |
| 735 초과 | 1.00 | 0.00 |

- 변동은 경기마다 `결과 − PD`를 구해 대회나 기간 단위로 합한 뒤 K를 곱하고, 반올림한다.
- K는 신규 선수가 30경기를 채우기 전 40, 2400 미만은 20, 공표 레이팅이 한 번 2400에 이른 선수는 이후 10이다. 18세가 되는 해의 말까지 2300 미만인 선수도 40이다. 한 기간의 경기 수 n과 K의 곱이 700을 넘으면 K × n이 700 이하가 되도록 K를 낮춘다.
- 점수 차이가 400을 넘으면 400으로 계산하되, 2025-10-01부터 2650 이상인 선수는 실제 차이를 그대로 쓴다.

K = 20, 점수 차이 200(높은 쪽 PD 0.76)에서 높은 쪽이 이기면 20 × (1 − 0.76) = 4.8점, 낮은 쪽이 이기면 20 × (1 − 0.24) = 15.2점이 오른다. 규정은 K를 발달 계수(development coefficient)라고만 부른다. 같은 결과에 대해 K가 크면 점수가 크게 움직이므로, 이 규정에서 신규 선수와 청소년의 점수는 빨리 움직이고 2400에 이른 선수의 점수는 느리게 움직인다.

## 설계 체크포인트

- 입력이 전체 순위표인지, 점수가 다른 시스템의 목록인지, 1대1 대결의 누적인지부터 정한다.
- 쌍대 비교에서 순환이 생길 수 있는지 확인한다. 합산 방식은 그 순환을 숫자 하나로 덮고, 쌍대 비교 계열은 순환을 푸는 규칙을 더하므로 어느 쪽이든 그 규칙을 설명에 남긴다.
- 위치 점수, RRF의 k, Elo의 K와 같은 상수는 결과를 바꾸는 설계 선택이다. 평가 데이터로 값을 비교하고 근거를 기록한다.
- 순위를 공개하는 서비스라면 점수 산정 기준을 설명하고, 잘못된 기록을 바로잡거나 이의를 제기할 경로를 둔다. 같은 입력도 위 예처럼 규칙에 따라 1위가 바뀌므로, 1위는 그 기준에서의 1위다.
