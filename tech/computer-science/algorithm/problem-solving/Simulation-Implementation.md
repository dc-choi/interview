# 시뮬레이션과 구현 문제

코딩 테스트의 시뮬레이션 유형은 특정 자료구조나 알고리즘에 묶이지 않고, 문제에 적힌 규칙을 그대로 코드로 옮기되 그 구현이 길고 까다로운 문제를 가리킨다. 배경 지식보다 구현력, 즉 풀이를 빠르고 정확하게 코드로 옮기는 능력이 승부를 가른다. 반복해서 쓰이는 몇 가지 기법을 틀로 익혀 두면 실수가 크게 줄어든다.

## 풀이 순서

1. 지문을 구현 단위로 쪼갠다. 예를 들어 CCTV 감시 영역 문제는 각 CCTV 방향을 정하기와 그 방향으로 감시 영역을 칠하고 사각지대를 세기로, 2048 게임은 한 번 기울이기와 다섯 번 기울이는 모든 경우 돌기로 나뉜다. 막히면 요구사항마다 주석을 달고 주석을 하나씩 코드로 바꾼다. 부분 추출은 `substr`, 뒤집기는 `reverse`, 정렬은 `sort`처럼 요구 동사를 표준 함수와 바로 잇는다.
2. 코드를 쓰기 전에 전체 경우의 수와 한 경우의 처리 비용을 곱해 시간 안에 드는지 확인한다([[Algorithm-Complexity|허용 복잡도 역산]]). 시간을 한 단위씩 흘리는 구현이 느리면 다음 event 시각으로 건너뛴다([[Greedy-Sweep-and-Two-Pointers#정렬과 Priority Queue|여러 창구 배정]]).
3. 경우마다 원본 판을 복사한 작업용 판에서 변형하고, 결과를 구한 뒤 버린다. 원본을 직접 바꾸면 다음 경우가 오염된다.
4. 방향, index 범위, 0-indexed와 1-indexed 변환을 한 규칙으로 통일한다. 이 유형의 오답은 대부분 한 칸 차이의 경계 실수다. 지문 번호가 1부터면 그대로 따르는 편이 변환 실수가 적지만, 나머지 연산을 쓰는 좌표는 0-based로 바꾼다(아래 왕복 주기).
5. 끝나지 않을 수 있는 시뮬레이션은 지문의 반복 상한(예: 1000턴)을 넘으면 정해진 값(-1 등)을 출력하고 멈춘다.

## 독립 선택의 모든 조합: 진법 열거

선택지가 서로 독립이고 각각 같은 수(k)의 값을 가질 때는 백트래킹 대신 0부터 kⁿ - 1까지의 정수를 k진법으로 풀어 각 자리를 선택으로 쓴다. CCTV가 n대이고 방향이 4가지면 `tmp`를 0부터 4ⁿ - 1까지 돌며 4로 나눈 나머지를 차례로 방향으로 쓴다. 선택지 수가 2나 1뿐인 CCTV도 4가지로 취급하고 `dir % 2`처럼 접어 쓰면 코드가 단순해지는 대신 중복 계산이 생기므로, 그 상한까지 시간 안에 드는지 먼저 본다.

```cpp
int total = 1;
for (int i = 0; i < n; i++) total *= 4;  // pow()는 double이라 쓰지 않는다
for (int tmp = 0; tmp < total; tmp++) {
  int brute = tmp;
  for (int i = 0; i < n; i++) {
    int dir = brute % 4;  // i번째 선택
    brute /= 4;
    // dir로 i번째 대상을 처리
  }
}
```

`<cmath>`의 `pow`는 실수를 받고 반환하므로 정수 거듭제곱은 반복 곱셈이나 정수 함수로 계산한다. 값이 커지면 double 유효 자릿수를 넘어 오차가 생긴다([[Cpp-Coding-Test-Workflow#정수와 실수 계산|정수와 실수 계산]]).

선택이 서로 영향을 주거나 선택마다 가능한 값 수가 달라 낭비가 크면 [[Exhaustive-Search-and-Backtracking|백트래킹]]으로 돌아간다. n개 중 r개를 고르는 조합은 0/1 mask와 `next_permutation`이 간단하다(치킨집 m곳을 고르고 각 집에서 가장 가까운 치킨집 거리를 합하는 유형).

## 2차원 배열 회전

R행 C열 배열을 시계 방향으로 90도 돌리면 C행 R열이 되고, 원래 `(i, j)`는 `(j, R - 1 - i)`로 간다. 좌표를 몇 개 적어 보고 규칙을 확인한 뒤 구현하면 헷갈림이 줄어든다.

```cpp
// a: r행 c열 -> 시계 방향 90도 회전 결과 b: c행 r열
for (int i = 0; i < r; i++)
  for (int j = 0; j < c; j++)
    b[j][r - 1 - i] = a[i][j];
```

스티커를 모눈종이에 붙이는 유형처럼 회전을 시도 순서에 넣을 때는 회전을 바깥 loop에 두고, 안쪽에서 모든 붙일 위치를 먼저 확인한다. 스티커가 판 밖으로 나가지 않는 시작 좌표 범위(`x + 스티커 행 수 <= 판 행 수`)에서 한 칸 차이 실수가 잦다.

## 한 방향만 구현하고 판을 돌린다

2048처럼 네 방향으로 기울이는 규칙은 왼쪽 하나만 구현하고, 판을 0, 90, 180, 270도 돌린 뒤 왼쪽으로 기울여 나머지 방향을 얻는다. 네 방향 코드를 따로 쓰면 비슷하지만 조금씩 다른 코드 네 벌을 디버깅하게 된다. 돌린 판을 원래 방향으로 되돌리지 않아도 답(최대 블록)이 같다면 복원 연산은 생략할 수 있지만, 그 이유를 스스로 설명할 수 있을 때만 생략한다.

한 줄 기울이기는 결과를 새 배열에 채우며 O(n)에 처리한다. `idx`를 다음에 채울 칸으로 두고, 빈칸이 아닌 값을 차례로 보며 `idx` 칸이 비었으면 놓고, 같은 값이면 합친 뒤 그 칸을 확정해 `idx`를 넘기고, 다르면 다음 칸에 놓는다. 한 번 합쳐진 블록은 같은 기울이기에서 다시 합쳐지지 않아야 한다.

## 전치와 1차원 펼치기

방향이나 축만 다를 뿐 같은 규칙이면 좌표 변환(회전, 전치, 1차원 펼치기)으로 입력을 바꾸고 로직은 하나만 둔다. 변환 방향(시계, 반시계)과 크기 변화는 작은 예로 먼저 확인한다.

**전치로 행 검사를 열에 재사용**: 길을 지날 수 있는지처럼 행과 열에 같은 규칙을 적용하면 행 검사 함수 하나만 만들고, `b[j][i] = a[i][j]`로 전치한 판에 한 번 더 돌려 결과를 합한다. 높이 차가 1인 곳에 길이 L의 경사로를 놓는 길 검사는 변수 하나로 끝난다. 같은 높이가 이어지면 cnt를 늘리고, 1 높아지면 이전 평지가 L칸 이상인지 본 뒤 cnt를 1로, 1 낮아지면 앞의 내리막 경사로를 다 놓았는지(cnt >= 0) 본 뒤 cnt를 1 - L로 둔다. 음수는 낮은 쪽에 평지가 더 필요하다는 빚이다. 오르막과 내리막 카운터를 따로 두는 풀이보다 분기가 줄어든다.

```cpp
bool passable(const std::vector<int>& h, int L) {
  int cnt = 1;  // 지금 높이로 이어진 칸 수, 음수면 아직 모자란 내리막 경사로 칸
  for (int j = 1; j < (int)h.size(); j++) {
    if (h[j] == h[j - 1]) cnt++;
    else if (h[j] == h[j - 1] + 1 && cnt >= L) cnt = 1;
    else if (h[j] == h[j - 1] - 1 && cnt >= 0) cnt = 1 - L;
    else return false;  // 높이 차 2 이상이거나 경사로 자리가 모자람
  }
  return cnt >= 0;
}
```

**테두리를 1차원으로 펼쳐 돌리기**: 정사각형 영역의 테두리를 한 칸씩 돌리는 연산은 바깥 층부터 안쪽 층까지, 꼭짓점에서 방향을 바꾸는 dy/dx 순회로 각 층의 좌표를 vector에 뽑는다. 값을 한 칸 돌린 뒤 같은 좌표 순서로 되돌려 쓴다. 회전할 좌표 추출과 실제 회전을 나누면 좌표 계산 실수가 준다. 연산 순서가 결과를 바꾸면 모든 순서를 순열로 보고(연산 6개면 720가지) 순서마다 원본의 새 복사본에서 시작한다.

```cpp
std::rotate(v.begin(), v.begin() + 1, v.end());     // 앞쪽으로 한 칸 (v[1]이 맨 앞)
std::rotate(v.rbegin(), v.rbegin() + 1, v.rend());  // 뒤쪽으로 한 칸 (마지막 원소가 맨 앞)
int n = v.size(), s = k % n;
std::rotate(v.begin(), v.begin() + (n - s) % n, v.end());  // 뒤쪽으로 k칸
```

`std::rotate(first, middle, last)`는 middle이 가리키던 원소가 맨 앞에 오도록 왼쪽으로 돌린다. 역방향 iterator로 같은 호출을 하면 방향이 반대가 된다.

**원형으로 이어진 줄**: 원판이나 톱니바퀴 하나를 vector나 string으로 두고, k칸 회전은 길이로 나눈 나머지만큼만 돌린다. 시계와 반시계는 정방향과 역방향 iterator 선택으로 나뉜다. 같은 원판 안의 이웃은 `(j + 1) % M`, `(j - 1 + M) % M`으로 감싸지만, 서로 다른 원판(행) 사이는 감싸지 않고 위아래만 본다.

## 여러 칸이 함께 도는 회전: 번호와 순환 표

큐브의 면 돌리기처럼 한 연산이 여러 칸을 동시에 옮기면 방향마다 if 분기를 손으로 쓰지 않는다. 칸(스티커)마다 1차원 번호를 매기고(면마다 10 단위 대역을 주면 면 id가 `i / 10`), 연산마다 함께 순환하는 index 묶음을 데이터로 적어 같은 회전 루틴으로 처리한다. 3 × 3 면 하나를 시계 방향으로 돌리면 그 면의 바깥 8칸은 2칸씩, 맞닿은 네 면의 테두리 12칸은 3칸씩 순환한다. 묶음은 펼친 그림 기준으로 미리 적고, 명령 문자(U, D, F, B, L, R)를 0~5로 바꿔 index로 참조한다. 반시계는 반대 방향 회전이나 시계 세 번이다. 표는 손으로 만들므로 같은 회전 네 번과 시계 다음 반시계가 항등인지, 색별 칸 수가 보존되는지를 작은 테스트로 먼저 확인하고, test case마다 상태를 초기화한다.

## 동시 갱신: 이전 상태에서 계산하고 한꺼번에 반영

규칙이 모든 칸에서 같은 시각에 일어나는데 한 칸씩 제자리에서 갱신하면, 앞에서 바뀐 값이 뒤 칸 계산에 섞여 오답이 된다. 이전 상태를 기준으로 변화량이나 대상을 모두 구한 뒤 한꺼번에 반영한다. 칸 처리 순서를 바꿨을 때 결과가 달라지면 이 실수다. 탐색과 함께 쓰는 형태는 [[Graph-Traversal-and-Shortest-Path-Grid-BFS#격자가 바뀌는 시뮬레이션|격자가 바뀌는 시뮬레이션]]에서 다룬다.

- **확산**: 모든 칸의 확산량을 이전 값 기준으로 계산해 temp 배열에 더하고 원래 칸에서는 퍼진 양만큼 뺀 뒤, 계산이 다 끝나면 temp를 원본에 반영한다.
- **고정 경로를 따라 한 칸씩 밀기**: 공기청정기 바람처럼 매번 같은 경로로 값이 한 칸씩 이동하면 경로를 처음에 좌표 목록으로 뽑아 둔다(끝에서 방향을 바꾸는 dy/dx 순회). 목록 끝(공기청정기로 빠져나가는 칸)부터 앞 칸의 값을 당겨 오고, 첫 칸에는 빈 값을 넣는다. 앞에서부터 밀면 다음 칸의 값을 덮어써 한 값이 끝까지 복사된다.
- **연쇄 범위를 먼저 확정**: 맞닿은 극이 다르면 이웃 톱니가 반대로 함께 도는 규칙은, 회전 전 상태로 왼쪽과 오른쪽으로 번지는 범위 [L, R]을 먼저 구한 뒤 범위 안을 돌린다. 방향은 기준 톱니와의 거리 홀짝으로 번갈아 정한다. 하나를 돌리고 나서 다음 톱니와 비교하면 이미 바뀐 극을 본다.
- **찾은 뒤 한꺼번에 삭제**: 인접한 같은 수를 모두 찾아 표시한 뒤 한 번에 지운다. 지운 칸을 0처럼 답에 끼지 않는 값으로 두면 이후 평균 계산에서 빼기 쉽다. 평균과의 비교는 `x * cnt > sum`처럼 정수로 할 수 있고, 남은 수가 없으면 나누지 않는다([[Cpp-Coding-Test-Workflow#정수와 실수 계산|정수와 실수 계산]]).
- **이동 결과를 temp 격자에 모은 뒤 충돌 해결**: 여러 객체가 동시에 움직이면 새 위치를 temp 격자에 기록하며 같은 칸에 둘 이상 오면 규칙(가장 큰 것만 남김)대로 정리하고, 이동이 끝난 뒤 원본에 반영한다.
- **같은 단계 안의 순서와 다음 단계로 미루기**: 한 칸에 여러 객체가 있고 처리 순서가 규칙이면(어린 나무부터 양분을 먹는다) 칸의 vector를 정렬한 뒤 처리한다. 죽은 나무처럼 다음 단계에서 쓰는 결과는 목록에 모았다가 그 단계에서 반영한다.

## 상태 인코딩

- **칸마다 container, 객체마다 상태**: 한 칸에 여러 객체가 쌓이면 칸 자체를 `vector<int> a[N][N]`으로 두고, 객체마다 (y, x, dir)을 별도 배열에 둬 번호로 바로 찾는다. 위에 쌓인 말이 함께 움직이는 규칙이면 칸의 vector에서 그 말 위치부터 끝까지를 옮기고(순서를 뒤집는 칸이면 뒤집어 붙인다) 원래 칸에서 erase한다.
- **반대 방향은 XOR 1**: 방향을 0-based로 바꾸고 반대 방향끼리 (0, 1), (2, 3)으로 짝지으면 `d ^ 1`이 반대 방향이라 if 분기가 사라진다. 두 위치를 오가는 토글도 0과 1로 두면 `pos ^ 1`이다. 입력 번호의 뜻은 문제마다 다르므로 짝이 맞게 재배치한다.
- **90도 회전은 modulo**: dy/dx를 시계 방향 순서로 두면 오른쪽 회전은 `(d + 1) % 4`, 왼쪽 회전은 `(d + 3) % 4`다. `d + 1 % 4`는 `%`가 먼저 계산돼 `d + 1`이 된다. 감시 카메라처럼 종류마다 보는 방향이 다르면 기준 방향 d에서 `{d}`, `{d, d + 2}`, `{d, d + 1}`, `{d, d + 1, d + 2}`, 네 방향 전체(모두 mod 4)로 표현해 확장 함수 하나로 처리하고, 기준 방향 4가지를 위의 진법 열거로 돈다(카메라 8대면 4⁸ = 65,536가지).
- **왕복 운동은 주기로 줄인다**: 속력만큼 움직이다 벽에서 방향을 바꾸는 객체를 한 칸씩 옮기면 시간 초과가 난다. 과정이 아니라 결과 위치가 중요하므로, 0-based 좌표에서 길이 n인 줄을 왕복하면 2(n - 1)걸음마다 같은 위치와 진행 상태로 돌아온다는 점을 써서 속력을 2(n - 1)로 나눈 나머지만큼만 움직인다. 1-based 좌표 그대로 나머지를 쓰면 0으로 떨어지는 경우 같은 보정이 늘어난다. n = 1이면 주기가 0이라 나머지 연산 전에 따로 처리한다. 복잡한 식은 중간 변수로 나눠 변수 혼동을 막는다.
- **앞뒤로 자라는 몸통은 deque와 점유 격자**: 뱀 게임은 머리 추가와 꼬리 삭제가 양 끝에서 일어나므로 몸 좌표를 deque에, 몸이 있는 칸을 점유 격자에 둔다. 매초 다음 머리 칸이 범위 밖이거나 점유돼 있으면 끝내고, 아니면 `push_front`하고 표시한다. 사과가 없으면 꼬리를 `pop_back`하고 표시를 지운다. 지문이 머리를 먼저 늘린 뒤 충돌을 보고 꼬리를 줄이는 순서라면 꼬리 칸으로 들어가는 이동도 충돌이므로, 꼬리를 먼저 빼면 이 경우를 놓친다. 방향 전환은 시각별로 저장해 두고 그 초의 이동이 끝난 뒤 적용한다.
- **기하처럼 보이면 규칙 찾기**: 코딩 테스트의 도형 문제는 복잡한 기하 계산 대신 규칙 찾기나 배열 카운팅으로 풀리는 경우가 많다([[Prefix-Sum-and-Range-Queries#끝점만 기록하는 도형 카운팅|끝점만 기록하는 도형 카운팅]]). 선분을 끝점 기준으로 90도 돌려 이어 붙이는 드래곤 커브는 좌표를 돌리지 않고 방향 목록으로 만든다. 방향 0~3이 오른쪽, 위, 왼쪽, 아래일 때 다음 세대는 이전 목록 뒤에, 이전 목록을 역순으로 읽으며 각 방향에 `(d + 1) % 4`를 적용한 값을 붙인 것이다. 세대를 미리 만들어 두고 꼭짓점을 표시한 뒤 네 꼭짓점이 모두 표시된 단위 정사각형을 센다.
- **불규칙한 보드는 칸 id graph**: 지름길이 있는 윷놀이 판처럼 경로가 갈라지면 점수를 index로 쓰지 않는다. 여러 경로에 같은 점수가 있어 서로 다른 칸이 합쳐진다. 칸마다 고유 번호를 주고 점수는 별도 배열에 두며 다음 칸을 인접 리스트로 잇는다. 기본 경로를 0번째, 지름길을 1번째로 넣어 두고 지름길 시작 칸에서 출발할 때만 첫 이동에 1번째를 쓴다. 도착 칸이 아닌 목적지에 다른 말이 있으면 그 이동은 불가능하다. 말 4개 중 하나를 고르는 10턴은 4¹⁰(약 105만)가지라 재귀로 모두 보고 말 위치를 원복한다.

## 체크포인트

- 지문을 구현 단위로 나누고, 각 단위를 함수로 분리했는가
- 경우의 수와 한 경우의 비용을 곱해 시간 안에 드는지 코드를 쓰기 전에 확인했는가
- 경우마다 원본을 복사해 작업했는가
- 진법 열거에서 정수 거듭제곱을 `pow` 없이 계산했는가
- 회전 좌표 공식과 시작 좌표 범위를 작은 예로 검증했는가
- 한 방향 구현과 회전으로 중복 코드를 줄였는가
- 같은 시각에 일어나는 변화를 이전 상태 기준으로 모아 한꺼번에 반영했는가
- `(d + 1) % 4`의 괄호와 반대 방향 짝(`d ^ 1`)을 확인했는가
- 나머지 연산을 쓰는 좌표를 0-based로 바꿨는가
- 손으로 만든 순환 표를 항등 연산과 개수 보존으로 검증했는가
