# 코딩 테스트 정수론 기초

코딩 테스트의 수학 문제는 대부분 소수, 약수와 최대공약수, 나머지, 경우의 수 몇 가지 도구로 풀린다. 공통 원리는 약수가 √n을 기준으로 짝을 이룬다는 성질과, 모든 후보를 보지 않고 조건을 만족할 수 있는 후보만 건너뛰며 보는 것이다.

## 소수

**판정 O(√n)**: 합성수 n의 1이 아닌 가장 작은 약수 x는 √n 이하다. x가 가장 작은 약수라면 `x <= n / x`이므로 `x² <= n`이다. 따라서 2부터 √n까지 나눠 떨어지는 수가 없으면 소수다. 반복 조건은 `sqrt()`의 실수 오차를 피해 `i * i <= n`으로 쓴다(`i`가 크면 곱이 넘치지 않게 `long long`).

**범위 전체 판정, 에라토스테네스의 체**: 1부터 n까지 모두 판정해야 하면 수마다 O(√n)을 반복하지 않는다. 모두 소수 후보로 두고 2부터 올라가며, 아직 지워지지 않은 수 p를 만나면 p의 배수를 지운다.

- p의 배수는 `p * p`부터 지운다. 그보다 작은 배수는 p보다 작은 소인수를 가져 이미 지워졌다.
- `p * p > n`이면 멈춘다. 남은 후보는 모두 소수다.
- 시간은 O(n log log n)으로 사실상 선형에 가깝다. C++에서는 `std::vector<bool>`이 원소당 1비트로 저장돼 메모리가 작고 캐시 효율도 좋다.

```cpp
std::vector<int> sieve(int n) {
  std::vector<bool> state(n + 1, true);
  state[0] = false;
  if (n >= 1) state[1] = false;
  for (int i = 2; 1LL * i * i <= n; i++) {
    if (!state[i]) continue;
    for (int j = i * i; j <= n; j += i) state[j] = false;
  }
  std::vector<int> primes;
  for (int i = 2; i <= n; i++) if (state[i]) primes.push_back(i);
  return primes;
}
```

**소인수분해 O(√n)**: i를 2부터 올리며 n이 i로 나눠지는 동안 i를 목록에 넣고 n을 i로 나눈다. i가 합성수일 때는 그 소인수들이 이미 n에서 빠졌으므로 목록에는 소수만 들어간다. `i * i > n`이 되면 남은 n에는 √n 이하의 소인수가 없으므로 멈추고, 남은 n이 1이 아니면 그 자체가 소인수다. 판정과 분해 모두 O(√n)이라 n이 10¹² 수준이어도 가능하다.

## 팩토리얼의 소인수 개수

n이 10억이면 n!은 만들 수 없다(10!만 해도 3,628,800). n! 끝자리 0의 개수는 결과에 곱해진 10의 개수이고 10 = 2 × 5이므로, 소인수 2의 개수와 5의 개수 중 작은 값이다. n! 안의 소수 p 개수는 p의 배수마다 1개, p²의 배수마다 1개 더, p³의 배수마다 또 1개를 세야 하므로 `⌊n/p⌋ + ⌊n/p²⌋ + ⌊n/p³⌋ + ...`다(Legendre 공식). p의 배수만 세면 4나 25처럼 p를 여러 번 가진 수를 덜 센다. 10!의 2는 5 + 2 + 1 = 8개, 25!의 5는 5 + 1 = 6개다. 항마다 `⌊n/2ᵏ⌋ >= ⌊n/5ᵏ⌋`이라 2가 5보다 적을 수 없으므로 5만 세면 답이다. 규칙이 떠오르지 않으면 작은 n으로 표를 그려 본다.

```cpp
long long trailingZeros(long long n) {
  long long cnt = 0;
  while (n) { n /= 5; cnt += n; }  // p *= 5로 거듭제곱을 키우면 n이 클 때 p가 넘칠 수 있다
  return cnt;
}
```

질의 하나에 O(log n)이다.

## 약수, 최대공약수, 최소공배수

- **약수 목록**: 곱해서 n이 되는 짝 중 작은 쪽은 √n 이하이므로 `i * i <= n`까지만 돌며 i와 `n / i`를 함께 넣는다. 제곱수는 √n이 두 번 들어가지 않게 처리한다.
- **유클리드 호제법**: a를 b로 나눈 나머지를 r이라 하면 `gcd(a, b) = gcd(b, r)`이고 `gcd(a, 0) = a`다. O(log min(a, b))로 매우 빠르다. C++17부터는 `std::gcd`, `std::lcm`이 있다.
- **최소공배수**: `a × b = gcd × lcm`이므로 `lcm = a / gcd(a, b) * b`로 계산한다. `a * b / gcd`처럼 곱부터 하면 a, b가 10⁹일 때 중간값이 넘친다.

```cpp
long long gcd(long long a, long long b) { return b == 0 ? a : gcd(b, a % b); }
long long lcm(long long a, long long b) { return a / gcd(a, b) * b; }
```

## 나머지 연산의 성질

덧셈과 곱셈은 중간마다 나머지를 취해도 마지막 나머지가 같다.

```text
(a + b) mod n = ((a mod n) + (b mod n)) mod n
(a × b) mod n = ((a mod n) × (b mod n)) mod n
```

그래서 자료형을 넘는 수도 나머지만 들고 다니며 판정할 수 있다. 1로만 이루어진 수 중 n의 배수가 되는 가장 작은 자릿수를 구할 때 1, 11, 111을 직접 만들면 금방 long long을 넘지만(n = 9901이면 12자리), 배수 판정에는 나머지만 필요하므로 `r = (r * 10 + 1) % n`으로 갱신하며 r이 0이 되는 자릿수를 센다. n이 2나 5의 배수면 끝자리가 1인 수는 n의 배수가 될 수 없어 끝나지 않고, n이 10과 서로소면 비둘기집 원리로 n자리 안에 0이 된다. 거듭제곱의 나머지도 같은 성질을 쓴다([[Algorithm-Recursion#분할 정복 거듭제곱|분할 정복 거듭제곱]]).

- 두 값을 n 미만으로 줄여도 곱은 n²까지 커지므로 n²이 자료형에 들어가는지 확인한다.
- 뺄셈도 성립하지만 C++처럼 나머지가 음수일 수 있는 언어에서는 `((x % n) + n) % n`으로 정규화한다.
- 나눗셈에는 성립하지 않는다. n이 소수면 페르마의 소정리로 구한 모듈러 역원을 곱한다.
- 식을 바꿔 코드에 넣기 전에 작은 범위(예: 값 1~100, n 2~100)에서 원래 식과 바꾼 식을 모두 계산해 비교하면 대수 실수를 빨리 잡는다.

## 연립합동방정식

N으로 나눈 나머지가 x이고 M으로 나눈 나머지가 y인 수를 찾을 때, 0부터 lcm(N, M) - 1까지 모두 보지 않는다. N으로 나눈 나머지가 x인 수는 x, x + N, x + 2N, ...뿐이므로 이것들만 M으로 나눈 나머지를 확인하면 후보가 lcm / N개(최대 M개)로 준다. 해의 주기가 lcm(N, M)이므로 그 범위에서 찾지 못하면 해가 없다. 두 나머지의 홀짝이 모순되는 경우처럼 해가 없을 수 있다(10으로 나눈 나머지 7은 홀수, 12로 나눈 나머지 2는 짝수). 범위를 `N × M`까지로 잡아도 lcm의 배수 구간을 반복해 볼 뿐 답은 같다. 반복 조건에 `lcm()` 호출을 넣으면 매번 다시 계산하므로 변수에 담아 둔다. 수가 10⁹ 규모면 모듈러 역원과 확장 유클리드 호제법을 쓰는 중국인의 나머지 정리로 로그 시간에 푼다.

## 이항계수

n개에서 순서 없이 k개를 고르는 수는 `C(n, k) = n! / ((n - k)! k!)`, 순서를 고려하면 `n! / (n - k)!`다. n이 조금만 커도 팩토리얼이 넘치므로 나머지를 요구하는 문제에서는 파스칼의 삼각형 점화식을 DP로 채운다.

`C(n, k) = C(n - 1, k - 1) + C(n - 1, k)` (n번째 원소를 고르는 경우와 고르지 않는 경우), `C(i, 0) = C(i, i) = 1`

덧셈만 쓰므로 매 칸 나머지를 취해도 된다. O(n²) 공간과 시간이라 n이 수천 이하일 때 적합하고, 더 크면 팩토리얼과 모듈러 역원(나머지 수가 소수일 때 페르마의 소정리)을 쓴다.

## 체크포인트

- 합성수의 가장 작은 약수가 √n 이하인 이유와 `i * i <= n` 조건을 쓰는 이유
- 에라토스테네스의 체에서 `p * p`부터 지우는 이유와 O(n log log n)
- 소인수분해 결과에 합성수가 들어가지 않는 이유
- n! 끝자리 0의 개수에서 5의 거듭제곱 배수까지 모두 세는 이유
- lcm을 `a / gcd * b` 순서로 계산해야 하는 이유
- 중간마다 나머지를 취해도 되는 연산과 안 되는 연산
- 연립합동방정식에서 한쪽 조건을 만족하는 후보만 건너뛰는 방식
- 이항계수를 팩토리얼 대신 파스칼 점화식으로 계산하는 경우
