# 본질적 복잡성과 우발적 복잡성 (Essential vs Accidental Complexity)

소프트웨어의 복잡성은 두 종류로 갈린다. 하나는 풀려는 문제 자체에 박혀 있어 도구를 바꿔도 사라지지 않고, 다른 하나는 문제를 푸는 과정과 도구에서 딸려와 더 나은 도구로 줄일 수 있다. 이 구분은 어떤 어려움을 도구로 없앨 수 있고 어떤 어려움이 끝까지 남는지를 가른다.

## 정의

- **본질적 복잡성(essential)**: 문제의 본성에 내재한 복잡성. 요구사항, 도메인 규칙, 상태와 관계의 얽힘, 동시성 하의 정합성. 무엇을 만들지가 복잡하면 도구를 아무리 바꿔도 그 복잡성은 남는다.
- **우발적 복잡성(accidental)**: 문제 자체가 아니라 그것을 구현하는 도구와 절차에서 생기는 복잡성. 언어의 제약, 프레임워크 설정, 빌드 절차, 반복되는 상용구. 도구가 좋아지면 줄어든다.
- Fred Brooks의 No Silver Bullet(1986)이 essence와 accident로 나눴다. 생산성을 한 번에 크게 끌어올리는 은총알이 없는 이유도 여기서 나온다. 남은 어려움의 큰 몫이 본질적이라 어떤 도구로도 걷어낼 수 없기 때문이다.

## Mental model — 도구는 우발적 복잡성만 없앤다

고수준 언어, 가비지 컬렉션, 컴파일러는 우발적 복잡성을 걷어낸 대표적인 도구다. 어셈블리의 레지스터 배정과 수동 메모리 관리처럼 문제와 무관하게 도구가 강요하던 부담을 언어가 흡수했다.

그러나 무엇을 만들지, 규칙이 서로 어떻게 얽히는지 같은 본질적 복잡성은 그대로 남는다. 좋은 설계란 우발적 복잡성을 최소로 걷어내 본질적 복잡성만 드러난 상태에 가깝다. 반대로 나쁜 코드는 본질적 복잡성 위에 도구발 잡음을 잔뜩 얹어 둘을 구분하기 어렵게 만든다.

## 결정론적 도구 vs 비결정론적 생성기

도구가 우발적 복잡성을 걷어낼 수 있었던 전제는 **예측 가능성**이다.

- 컴파일러는 대체로 결정론적이다. 같은 입력에 같은 출력을 내는 성질 덕에 흡수한 복잡성이 안정적으로 사라져, 개발자는 그 아래 계층을 매번 다시 검증하지 않아도 된다. 타임스탬프나 ASLR처럼 재현성을 깨는 요인이 있어 재현 가능한 빌드가 별도 과제로 다뤄지기도 한다.
- LLM 코드 생성기는 비결정론적이다. 같은 요청에도 다른 코드가 나오고, 문제에 맞지 않는 접근을 고르거나 지름길을 타면서 우발적 복잡성을 오히려 더하기도 한다. 필요 없는 추상화 계층, 상황에 안 맞는 패턴, 국소 대응용 특수 분기가 그 예다.

그래서 고수준 언어가 걷어냈던 우발적 복잡성을 생성 코드가 다시 들여올 수 있다. 도구가 무언가를 자동화한다고 해서 그것이 늘 복잡성 감소는 아니라는 뜻이다. 여기서 남는 가치는 무엇이 본질적 복잡성인지 판단하고, 생성물이 얹은 우발적 복잡성을 알아보고 걷어내는 능력이다. 도구 계층이 바뀌어도 이 판단은 사람에게 남는다.

## 예시

- 우발적: 같은 CRUD를 여러 계층에 손으로 복사해 붙이기, 프레임워크 설정 지옥, 언어 제약을 피하려는 우회 코드.
- 본질적: 주문에서 결제와 환불로 이어지는 상태 전이 규칙, 동시 요청 하의 정합성, 권한 위계와 예외.
- 생성 코드가 우발적 복잡성을 더하는 경우: 한 번 쓰고 말 인터페이스를 미리 뽑는 조기 추상화, 문제 규모에 안 맞는 패턴 적용, 테스트를 통과시키려는 특수 케이스 분기.

## 트레이드오프

- 우발적 복잡성 제거에 과몰입해 조기 추상화로 가면, 복잡성을 없애는 대신 미래로 미루게 된다. 추상화가 깨지는 지점의 위험은 [[Developer-Role-AI-Era|AI 시대 개발자 역할]]과 [[Tidy-First|Tidy First]]에서 다룬다.
- 본질적 복잡성은 제거되지 않고 위치만 옮겨진다. 어느 모듈, 어느 계층에 둘지가 설계 결정이다.
- 무엇이 본질이고 무엇이 우발인지의 구분 자체가 판단이라 자동화 대상이 아니다. 이 판단을 놓으면 생성 코드의 잡음을 본질로 착각해 그대로 안고 간다.

## 체크포인트

- 본질적 복잡성과 우발적 복잡성을 한 줄로 구분해 말할 수 있는가
- 고수준 언어와 컴파일러가 없앤 것은 어느 쪽인가, 왜 은총알이 없는가
- 결정론적 컴파일러와 비결정론적 LLM이 복잡성에 미치는 방향이 왜 다른가
- 생성 코드에서 우발적 복잡성을 어떻게 알아보고 걷어내는가
