# 실시간 입찰 광고 추천 산업 사례

광고 추천은 콘텐츠 추천과 같은 예측 문제 위에 가격과 예산을 얹는다. 콘텐츠 추천은 후보를 점수로 줄 세우면 끝나지만, 입찰형 광고는 예측한 가치를 돈으로 바꿔 경매에 내고, 정해진 예산을 하루에 걸쳐 나눠 쓰고, 며칠 뒤에야 도착하는 결과로 다시 학습한다. 이 문서는 수요 측 플랫폼(DSP)인 Moloco가 공개한 구조를 사례로 삼는다. 공급자가 자기 시스템을 설명한 자료이며 독립 검증된 명세가 아니다.

## 콘텐츠 추천과 다른 제약

| 항목 | 콘텐츠 추천 | 입찰형 광고 추천 |
|---|---|---|
| 요청의 주인 | 자기 서비스의 화면 | 외부 지면의 경매 요청 |
| 출력 | 순위 | 입찰 여부, 입찰가와 소재 |
| 목적 함수 | 참여, 만족 | 광고주별 목표(ROAS, 설치) 아래의 가치 대비 가격 |
| 자원 제약 | 화면 자리 | 캠페인 예산과 소진 속도 |
| 결과 관측 | 대부분 자기 로그 | 낙찰 여부만 즉시, 전환은 외부 측정 도구를 거쳐 지연 도착 |
| 응답 시간 | 화면 예산 | 경매가 정한 제한 시간 |

## 규모와 지연이 모델 선택을 정한다

Moloco는 하루 1조 건이 넘는 광고 기회를 수십 밀리초 안에 평가하고, 초당 약 1억 건의 예측을 낸다고 밝힌다(공식 글 기준, 2026-11-12 확인). 하루 1조 건은 초당 약 1,160만 건의 요청이다. 발표에서는 입찰 요청에서 응답까지를 100밀리초 안으로 설명했다(발표 기준).

이 두 제약이 경매 시점에 범용 LLM을 쓰지 못하게 한다. 요청 하나의 추론 비용에 1조를 곱하면 감당할 수 없고, 제한 시간 안에 응답할 수도 없다. 공식 글은 범용 모델이 광고 행동 신호가 없어 정밀한 가치 예측을 하지 못한다는 점도 든다. 가장 큰 모델은 경매 안에서 돌리기에 느리고 비싸므로 모델을 가격 대비 성능 곡선으로 평가하며, 모델 유형으로 multi-head 모델, transformer 계열 sequence 모델과 deep cross network를 든다. 생성 AI는 소재 구성 요소와 언어, 이미지, 영상 이해에 쓴다.

서빙 지연 예산을 단계별로 나누는 원칙은 [[Recommendation-System-Serving-Operations|추천 서빙 운영]]을 따른다.

## 여섯 영역

Moloco의 CARA(Compound Ad Recommendation Architecture)는 광고 집행을 여섯 영역으로 나눈다. 영역 이름은 공식 글 기준이고, 발표에서만 나온 설명은 (발표)로 표시한다.

| 영역 | 푸는 문제 | 추천시스템 용어로 |
|---|---|---|
| Campaign Automation | 광고주 목표의 달성. 하루 예산을 언제 얼마씩 쓸지 정하는 소진 속도 조절(발표) | 제약 아래의 배분, pacing |
| Supply | 어떤 거래소와 지면 경로로 살 것인가. 들어올 기회의 예측(발표) | 요청(트래픽)량 예측과 요청 경로 선택. 캠페인 관점에서는 살 수 있는 후보 기회의 공급 |
| Ad Recommendations | 노출마다 참여, 설치, 전환, 유지와 지출 가능성을 예측해 광고주 목표 기준의 가치 추정 | 다중 목표 ranking, value model |
| Bidding | 1차 가격 경매에서 경쟁 입찰을 모르는 채 입찰가 결정 | 가격 결정 |
| Creative | 사용자와 맥락에 맞는 소재 선택과 조립 | 소재 단위 선택 |
| Signals | 전환 이벤트, 지면 상호작용, 입찰 요청, 측정 도구 데이터와 SDK 활동의 통합 | 공유 feature와 label 계층 |

Ad Recommendations가 내는 값은 콘텐츠 추천의 value model과 구조가 비슷하다. 여러 행동의 예측 확률을 목표에 맞는 가치 하나로 합친다([[Recommendation-System-Ranking-Reranking|랭킹과 재정렬]]). 다만 콘텐츠 랭킹은 상대 순서만 맞으면 되지만, 광고는 합친 값이 광고주 목표 기준의 금액이어야 입찰가로 바뀌므로 보정된 절대값이 필요하다.

## 복리 구조: 영역이 서로의 입력이다

이름의 compound는 한 영역의 개선이 다른 영역의 개선으로 더해지지 않고 곱해진다는 주장이다. 가능하게 하는 것은 모든 영역이 Signals 계층을 함께 읽고 쓴다는 점이다.

- 가치 예측이 정확해지면 입찰이 노출의 값을 더 잘 매긴다. 더 많은 노출을 따내고, 그 결과 데이터가 모든 영역의 재학습에 들어간다(공식 글).
- 소재 선택이 나아지면 참여가 늘어 학습 데이터가 풍부해지고 Signals의 표현이 좋아진다(공식 글).
- 예산이 늘면 살 수 있는 기회가 늘 뿐 아니라, 좋은 기회를 놓쳤을 때의 대안이 더 나빠지므로 좋은 기회의 입찰가가 오른다(발표 기준).
- 전환율이 오르면 전에는 비싸서 사지 않던 지면이 살 만해지고, 사 본 결과가 그 지면의 가치 예측을 고친다(발표 기준).

마지막 항목은 탐색 문제다. 사지 않은 지면은 결과가 관측되지 않는다. 높게 추정된 지면은 사 보고 고쳐지지만 낮게 추정된 지면은 교정될 기회가 적다. 정책이 고른 표본만 관측되는 이 구조는 [[Recommendation-System-Feedback-Data#세 가지 편향|피드백 데이터]]의 Exposure bias와 같다. 적용 해석: 발표는 입찰 하나하나가 실험이라고 했는데, 이는 결과가 시차를 두고 도착한다는 설명이었다. 이 관점을 편향을 줄이는 탐색 예산으로 옮겨 볼 수 있다.

적용 해석: 영역이 서로의 입력이면 개선이 번지듯 오류도 번진다. 잘못 들어온 전환 신호 하나가 가치 예측, 입찰과 예산 배분을 함께 틀리게 한다. 공유 계층에는 [[Recommendation-System-Feedback-Data#세 가지 편향|피드백 데이터]]의 폐루프와 노출 편향 점검이 필요하다.

## 지연 피드백

입찰의 결과는 단계마다 다른 시점에 도착한다.

| 결과 | 도착 시점 | 비고 |
|---|---|---|
| 낙찰 여부 | 즉시 | 입찰자는 이겼는지와, 때로는 최소 낙찰가만 안다(공식 글) |
| 설치 | 몇 시간 안 | 발표 기준 |
| 구매 | 며칠 뒤 | 설치 뒤 7일 또는 28일에 도착할 수 있고, 측정 도구를 거치거나 SKAdNetwork로 압축돼 온다(공식 글) |

관측 창이 닫히기 전에 negative로 확정하면 늦게 도착하는 positive가 오염된다. label의 관측 창과 확정 시점을 예제에 남기는 원칙은 [[Recommendation-System-Feedback-Data|피드백 데이터]]에 있다. Moloco는 하루 60억 건 넘는 이벤트로 학습하고 모델을 짧게는 두 시간마다 배포하며, 실트래픽에서 100개 넘는 실험을 동시에 돌린다고 밝힌다(공식 글 기준). 빠른 재학습과 느린 label이 함께 있으므로 delayed feedback 처리가 필수다.

## 같은 구조를 다른 지면으로 옮긴다

Moloco는 모바일 앱 광고, 커머스 플랫폼 내부 광고와 CTV 광고를 같은 구조 위에서 만든다고 설명한다(발표 기준). 지면, 전환과 고객이 달라도 여섯 영역은 같다. CTV는 Supply(TV 지면)와 Signals(가구 단위 기기 연결) 두 영역을 바꿔 빠르게 출시했다는 설명이 있었다(발표 기준). TV 노출 자체에는 프로그램과 TV 모델 정도의 신호뿐이라, 같은 가정 네트워크의 모바일 기기에서 쌓인 신호를 이어 가치 예측에 쓴다. 측정 쪽의 문제는 [[CTV-Performance-Advertising|CTV 퍼포먼스 광고와 증분 측정]]에 있다.

이는 공통 사용자 표현을 여러 downstream이 재사용하는 구조([[Recommendation-System-Industry-Large-Scale-ML#공통 사용자 표현과 downstream 재사용|대규모 ML 사례]])와 같은 방향이다. 다만 서로 다른 기기를 한 가구로 묶는 연결은 추정이고 오류와 개인정보 제약을 가진다.

## 근거 경계

- 여섯 영역의 이름, 처리 규모, 학습 주기와 LLM을 쓰지 않는 이유는 Moloco 공식 글과 제품 문서로 확인했다. 수치는 회사 발표이며 독립 측정이 아니다.
- 캠페인 자동화의 소진 속도 조절과 공급 예측이라는 설명, 세 제품이 같은 구조 위에 있다는 설명, 예산과 입찰가의 상호작용, 전환율과 지면 탐색의 예, 100밀리초 제한, 설치 도착 시점과 CTV의 두 영역 교체는 MOLOCON 26(2026-11-05) 발표 기준이다. 공식 글에는 없다.
- 모델 구조, feature, 손실 함수와 pacing 알고리즘은 공개되지 않았다. 이 문서의 추천시스템 용어 대응은 해석이다.
- 발표 기준 수치를 현재 규모나 기대 성과로 재사용하지 않는다.

## 함께 볼 설계 질문

- 예측 가치와 입찰가를 분리해 두었는가. 가치 예측의 보정(calibration)이 틀리면 입찰가가 그대로 틀린다.
- 입찰하지 않은 기회의 결과를 어떻게 추정하는가.
- 관측 창이 다른 label(낙찰, 설치, 구매)을 한 모델에서 어떻게 다루는가.
- 공유 신호 계층의 오류가 번지는 범위를 어떻게 제한하는가.
- 응답 제한 시간 안에서 모델 크기와 예측 품질을 어떤 기준으로 바꾸는가.
