# 컨텍스트의 생성, 평가, 배포와 관찰

컨텍스트 개발 수명주기는 에이전트에 공급하는 지침, 업무 정의, 예시와 기억을 버전 있는 변경물로 관리하는 방식이다. 코드처럼 관리한다는 말은 문법 검사만으로 품질을 증명한다는 뜻이 아니다. 같은 작업에서 결과와 개입량이 달라지는지 측정해야 한다.

## 네 단계와 남겨야 할 증거

| 단계 | 작업 | 검토할 증거 |
|---|---|---|
| 생성 | 원문에서 정의, 제약과 예시를 추출 | 출처, 적용 범위, 충돌과 불확실성 |
| 평가 | 대표 과업에 후보 컨텍스트 적용 | 기존 버전과 성공률, 회귀, 비용 및 개입량 비교 |
| 배포 | 리뷰한 버전을 필요한 에이전트에 공급 | 버전, 소유자, 의존 자료와 되돌릴 기준 |
| 관찰 | 운영 로그, 실패와 사람의 수정 수집 | 어떤 컨텍스트가 어떤 행동에 영향을 줬는지 추적 |

평가에서는 모델, 하네스, 저장소 revision과 과업을 맞춘다. 같은 조건에서도 결과가 달라질 수 있어 여러 실행과 실패 사례를 살핀다. 비밀 정보와 실행 명령이 포함된 외부 자료는 신뢰 경계에 맞춰 필터링하고, 배포 승인 강도는 행동 위험에 맞춘다.

## 공유 패키지로 다루는 조건

공유할 단위마다 소유권, 변경 이력, 출처와 적용 대상을 둔다. 운영 로그에서 발견한 해결책은 바로 전역 규칙으로 승격하지 않는다. 특정 환경의 우회인지 재사용 가능한 조건인지 확인하고 회귀 과업에 추가한 뒤 배포한다. 이 순환이 학습 효과를 만들 수 있지만 컨텍스트를 많이 쌓는 것 자체가 품질 향상을 보장하지 않는다.
