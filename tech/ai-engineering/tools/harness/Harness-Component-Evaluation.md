# 코딩 에이전트 하네스 구성요소 평가

하네스 구성요소 평가는 계획, 행동 인터페이스, 컨텍스트 관리가 코딩 에이전트의 성공률과 비용에 미치는 영향을 구분하는 방법이다.

## 평가 단위

| 구성요소 | 변경 대상 | 관측 지표 |
|---|---|---|
| 계획 | 유지, 갱신, 턴별 주입 | 수정 전 종료, 중복 검증 |
| 행동 인터페이스 | 도구, 설명, 상태 추적, 진단 | 도구 오류, 왕복 횟수 |
| 컨텍스트 | 생략, 요약, 복구 | 초과 종료, 요약 비용 |

단일효과를 분리하려면 모델, 과제와 변경 대상 밖의 실행 조건을 고정한다. 성공률뿐 아니라 종료 사유, 턴 수와 비용을 기록하고 다른 작업에서도 재검증한다.

## 조건부 실험 결과

2026년 9월 공개된 네 모델, 두 벤치마크의 비교에서는 다음 경향이 관찰됐다.

- **컨텍스트**: 작은 창에서 초과 종료 방지의 이득이 컸다. 오래된 도구 출력 생략 후 필요한 경우만 요약하는 정책은 비슷한 성공률에서 비용이 낮았다. 원문 복구는 드물게 호출됐고 일관된 정확도 이득이 없었다.
- **계획**: 약한 모델은 수정 전 종료가 줄어 성공률과 비용이 함께 높아졌다. 강한 모델은 성공률 변화가 작고 중복 검증 비용이 줄었다.
- **도구**: 셸 사용이 약한 모델은 전용 도구가 유리했고, 능숙한 모델은 bash로 작업을 묶어 비용을 줄였다. 도구 설명, 상태 추적과 진단도 함께 바뀐 실험이므로 도구 개수만의 효과는 아니다.

컨텍스트는 32k~128k에서, 계획과 도구는 계층 컨텍스트 관리와 128k에서 비교했다. 한 구현의 결과이며 모델 크기가 능력을 정확히 대변하지는 않는다.

## 적용 체크포인트

현재 실패가 컨텍스트 초과, 수정 전 포기, 명령 오류 중 무엇인지 먼저 확인한다. 해당 실패를 줄이는 변경부터 시험하고, 성공률과 비용의 교환관계를 본다. 복구 기능이나 안전 제어의 필요성을 평균 벤치마크 점수만으로 판단하지 않는다.

## 코딩 도구의 비용 비교

같은 모델을 여러 도구에서 비교하는 실험과 한 도구에서 모델을 바꾸는 실험은 질문이 다르다. 모델까지 달라진 결과를 하네스만의 효과로 해석하지 않는다.

2026-10-07 공개 README 확인 기준, AWS의 `sample-agent-cost-bench`는 같은 과제의 비용, 검증 결과와 실행 시간을 비교한다. 자체 저장소와 검증 테스트를 넣을 수 있고, 비용은 USD와 도구별 사용량 단위로 표시한다. 설정 예제의 단가는 실행 시점의 공급자 가격과 대조해야 한다. 이 기능 설명은 벤치마크를 직접 실행한 결과가 아니다.

다음은 비교 결과를 해석할 때 적용할 실험 설계 기준이다.

- 저장소 revision, 과제, 합격 조건, 모델, 추론 설정과 실행 한도를 기록한다. 반복 횟수와 초기 작업 공간도 맞춘다.
- 인증 실패, 모델 사용 불가, 검증 환경 오류와 코드 실패를 구분한다. 실행되지 않은 작업을 비용 0의 성공으로 계산하지 않는다.
- 성공한 실행만 남겨 순위를 매기지 않는다. 전체 시도 수, 합격률, 실패와 재시도 비용을 함께 공개한다.
- 비교용 지표로 `전체 시도 비용 / 합격한 작업 수`를 사용할 수 있다. 합격 수가 0이면 계산하지 않으며, 비용 누락이 있으면 완전한 비교로 제시하지 않는다.
- 환산 사용량 비용과 구독 청구액, 사람의 검토와 재작업 시간은 구분한다. 특정 샘플의 절감률을 다른 업무의 보장값으로 옮기지 않는다.

토큰 종류와 수집 누락의 의미는 [[AI-Coding-Agent-Usage-Telemetry|사용량 텔레메트리]]와 함께 확인한다.
