# ChatGPT dots — 자기 클라우드 컴퓨터를 가진 상시 실행 에이전트와 위임 설계

dots는 OpenAI가 2026-09-29 DevDay 2026에서 공개한 ChatGPT의 상시 실행(always-on) 에이전트다. 공식 문서는 제품을 dots로, 사용자가 만든 개별 에이전트를 your dot으로 부른다. dot은 GPT-6 Astra로 동작하고 클라우드에 자기 컴퓨터와 브라우저를 가진다. 클라우드에서 하는 일은 사용자의 기기가 꺼져 있어도 이어 갈 수 있으며, dot은 진행 상황을 추적해 다음에 할 일을 스스로 정한다.

제품 동작은 2026-10-21에 확인한 ChatGPT Learn의 dots 문서(developers.openai.com/codex/dots가 이 문서로 리디렉션된다), Enterprise 관리자 문서, DevDay 2026 페이지와 GPT-6 Astra 시스템 카드 기준이다. 순차 배포 중인 기능이므로 계정의 실제 화면과 설정으로 다시 확인한다.

## 대화 답변이나 단일 작업이 아니라 계속 맡긴 책임을 진다

DevDay 2026 페이지는 dots를 지속적인 책임(ongoing responsibility)을 맡는 에이전트로 소개한다. 시작 안내도 대화마다 새 요청을 던지지 말고 계속 챙겨야 할 일부터 맡기라고 권한다. 공식 비교는 ChatGPT Work를 지금 또는 예약으로 맡기는 작업으로, dot을 계속 챙길 책임으로 구분한다. 아래 표는 영상의 회사 비유(동료, 개발자, 팀장)를 일의 단위로 옮긴 이 문서의 비교이며 제품 사양이 아니다.

| 구분 | 일의 단위 | 끝나는 시점 | 맥락이 남는 곳 |
|---|---|---|---|
| 대화 답변 | 질문 하나 | 답을 돌려줄 때 | 대화 스레드와 ChatGPT 메모리 |
| 단일 Codex 작업 | 작업 하나 | 작업을 마칠 때 | 그 작업의 대화와 실행 환경 |
| dot | 계속 맡긴 책임 | 사용자가 멈추거나 거둘 때까지, 대화 사이에도 진행 | dot의 메모, 자기 컴퓨터의 파일과 브라우저 세션 |

- **기억:** dot은 ChatGPT 메모리의 관련 맥락에서 출발해 선호, 결정, 진행 중인 일에 대한 자기 메모를 따로 쌓는다. 이 메모는 ChatGPT 저장 메모리와 분리돼 있고 대화 전체의 기록도 아니다. 저장 메모리 설정을 바꿔도 이미 쓴 메모는 그대로일 수 있다. Enterprise 관리자 문서도 ChatGPT 메모리를 끄면 공유만 멈추고 dot이 이미 가진 정보는 지워지지 않으며, dot을 삭제하면 dot 자신의 맥락은 지워지지만 dot이 만든 파일, Codex 스레드와 ChatGPT 대화는 따로 저장돼 함께 다 지워지지는 않는다고 설명한다.
- **분업:** dot은 병렬로 도는 백그라운드 에이전트에 일을 나눌 수 있고, 에이전트들은 결과를 dot에 보고한다. 코딩은 저장소와 설정을 갖춘 Codex 클라우드 환경이나 연결한 컴퓨터의 Codex 작업으로 맡기고 기존 로컬 Codex 작업도 이어 가게 할 수 있다. 연결한 컴퓨터에서는 로컬 Work 작업도 만들 수 있다.
- **위임 작업의 맥락:** 새 작업은 dot이 그 일에 맞춰 넘긴 지시와 맥락을 받고 대화를 따로 가진다. 사용자와 dot이 나눈 대화 전체가 자동으로 넘어가지는 않는다. 그래서 Codex 작업을 맡길 때는 프로젝트, 작업 이름과 위치를 특정한다. 공식 문서도 기존 로컬 Codex 작업을 이어 갈 때 그 작업과 바꿀 내용을 특정하라고 안내하며, 프로젝트와 위치까지 적는 것은 영상의 운영 제안이다.
- **사용량:** 2026-10-21 기준 dot과의 대화는 ChatGPT 사용량 한도에 들어가지 않는다. dot이 시작하거나 관리하는 Work와 Codex 작업은 Work와 Codex의 사용량 한도에 평소대로 포함된다. 요금제에는 더 깊은 작업(deeper work)을 위한 허용량이 포함되고 출시 후 첫 달에는 늘어난 한도가 적용되지만, 문서는 구체적인 수치와 첫 달의 기준일을 밝히지 않는다.

## 고정 예약과 스스로 정하는 후속 확인을 구분한다

| 방식 | 다음 실행을 정하는 것 | 지시에 넣을 것 |
|---|---|---|
| 저장된 예약 | 사용자가 정한 시각 | 실행 시각, 시간대, 있다면 종료일 |
| 자율 후속 확인 | dot의 판단 | 지켜볼 대상과 알릴 조건 |
| 이벤트 대응 | 연결 서비스의 이벤트(서비스가 지원할 때) | 반응할 이벤트 |

- 정해진 시각에 반복할 일은 저장된 예약으로 만든다. 공식 문서는 실행 시각과 함께 시간대와, 있다면 종료일을 정하라고 안내한다. 예약은 Scheduled에서 검토하거나 dot에게 목록 조회, 변경, 취소를 요청한다.
- 고정 예약으로 두지 않은 후속 확인은 dot이 언제 멈추고 다시 깨어날지 스스로 정할 수 있으므로, 모든 후속 작업을 고정 예약으로 만들 필요는 없다. 사용자가 작업을 시작할 시각이나 지원되는 이벤트를 지정할 수도 있다.
- 연결 서비스가 이벤트 모니터링을 지원하면 특정 이벤트에 반응하도록 맡길 수 있다. Slack 같은 출처를 연결하거나 dot을 채널에 추가하는 것만으로는 모니터링 작업이 생기지 않으므로, 확인할 채널과 지켜볼 내용, 알릴 시점을 지시한다.
- 실행이 끝났다고 해서 요청한 결과가 달성되거나 전달됐다는 뜻은 아니다. 공식 문서는 실행이 끝난 뒤에도 결과와 보고된 오류를 검토하라고 안내한다.

자율 후속 확인에서는 확인 간격을 dot이 정하므로 사용자가 실행 시각을 보장받지 못한다. 놓치면 안 되는 마감이나 정기 보고는 저장된 예약으로 하한을 두고, 변화 추적은 자율 확인에 맡기는 조합을 검토한다. 이는 문서 동작에서 도출한 설계 판단이다. 예약 요약과 이벤트 처리의 구분은 [[Agent-Email-Interface#예약 요약과 새 메일 이벤트를 구분한다|이메일 에이전트 인터페이스]]를, 트리거와 정지 조건으로 루프를 나누는 관점은 [[Agent-Loop-Engineering|루프 엔지니어링]]을 함께 본다.

## 선제적 리서치는 읽기 전용이고 이어지는 행동은 권한과 승인을 따른다

- **선제적 리서치:** dot은 맡은 일과 함께 읽기 권한이 있는 정보를 조사하고, 쓸모 있는 발견은 비공개 메모로 남길 수 있다. 백그라운드 에이전트가 찾은 내용을 dot에 보고하면 dot이 제안이나 질문으로 가져올 수 있다. 이 조사 자체는 메시지를 보내거나 연결 앱을 바꾸거나 브라우저와 컴퓨터를 조작하지 않는다. 이어지는 행동에는 그 작업에 적용되는 권한과 승인이 그대로 적용된다. OpenAI는 선제적 리서치와 그 비공개 메모로 모델을 직접 학습하지 않는다고 밝힌다. 다만 조사한 정보가 대상(원문 eligible)인 대화나 작업의 일부가 되면 사용자의 데이터 설정이 적용된다.
- **자동 검토:** 계정에 영향을 주거나 정보를 공유할 수 있는 행동 전에는 자동 검토(automatic review)가 사용자 지시, 권한, 사용자 정의 규칙과 내장 안전 요구 사항에 비춰 행동을 판정한다. 결과는 진행, 승인 요청, 사용자가 직접 할 단계 중 하나이며, 비밀번호 변경은 사용자가 직접 해야 하는 예다.
- **정보 사용과 공개:** 다른 연락 수단에서 얻은 정보라고 해서 새 대상에게 공유할 권한이 생기지는 않는다(Enterprise 관리자 문서). 공유하는 내용에도 기존 권한과 안전장치가 그대로 적용된다. Slack에서는 기본적으로 사용자에게 응답하고, 다른 사람과 대화하려면 지시가 필요하다. 비공개 대화의 정보를 다른 사람과 나누기 전에는 사용자가 허용했는지 확인한다.
- **앱:** dot은 계정에 설치하고 켠 지원 플러그인을 쓴다. 공식 문서의 예는 Gmail에서 관련 메일 찾기, Google Drive 문서 읽기와 수정, GitHub 이슈 조사와 pull request 준비다. 접근 범위는 플러그인에 연결한 계정, 권한과 실행 환경에 따라 정해지고, Enterprise 관리자는 Plugin controls로 쓸 수 있는 앱과 허용 행동을 정한다.

사용자 정의 규칙(custom rules)은 행동마다 다음 네 옵션 중 하나를 고른다.

| 옵션 | 동작 |
|---|---|
| Take action without asking | 승인 없이 지정한 행동을 한다 |
| Take action when you say so | 사용자가 명시적으로 요청하면 진행하고, 아니면 행동 직전에 묻는다 |
| Ask before taking action | 지정한 행동 전에 승인을 요청한다 |
| Hand off to you | 그 행동을 사용자에게 넘긴다 |

공식 예시는 고객에게 보내는 메시지에 Ask before taking action, 공유 프로젝트 파일 삭제에 Hand off to you를 쓰는 것이다. 다만 문서는 규칙이 dot이 따르려고 하는 지시이며 dot이 실수할 수 있다고 적는다. 규칙은 앱이나 컴퓨터 접근을 주지 않고, 내장 안전 요구 사항을 넘어서지 못하며, 저장된 로그인 사용 승인 같은 필수 확인도 없애지 못한다. 워크스페이스에서 규칙 기능을 끄면 저장된 규칙도 적용되지 않는다.

그래서 되돌릴 수 없는 행동의 1차 경계는 규칙 문장보다 연결한 계정의 권한과 허용 행동에 두고, 규칙과 자동 검토는 그 위의 두 번째 층으로 본다. 이는 문서 설명에서 도출한 판단이다. 도구 쪽에서 자격 증명과 정책을 좁히는 방법은 [[MCP-Security-Boundaries|MCP 보안 경계]], 사람 승인의 배치는 [[Harness-Engineering|하네스 엔지니어링]]을 따른다.

## 로그인은 대화가 아니라 원격 브라우저로 넘긴다

- 웹사이트가 로그인을 요구하면 dot은 비공개 양식(private form)이 담긴 요청을 보낼 수 있다. 사용자가 웹사이트에서 직접 로그인하는 쪽을 고를 수도 있다. 양식에 넣은 자격 증명과 인증 코드 같은 확인 정보는 대화 밖에서 원격 브라우저로 전달된다.
- 사용자가 직접 해야 하는 단계에서는 Take over로 dot 컴퓨터의 마우스와 키보드를 넘겨받고, 끝나면 Return control로 돌려준다. 컴퓨터 화면을 열기만 해서는 제어권이 넘어오지 않는다.
- dot의 클라우드 브라우저는 자기 세션을 쓰며 개인 브라우저의 로그인을 물려받지 않는다. 내 컴퓨터에서 로그인했다고 dot도 로그인된 것은 아니다.
- 웹사이트 세션은 로그아웃하거나 사이트가 만료시킬 때까지 이후 작업에 남을 수 있다. 저장된 로그인을 다시 쓰려면 사용자 확인이 필요하다.

채팅창에 비밀번호를 쓰면 이 경계를 우회하게 된다. 대화는 dot이 참고하는 맥락이고, dot의 메모는 대화와 연락 수단을 넘어 이어지며, 위임 작업은 dot이 넘기는 맥락을 받는다. 대화에 들어간 비밀값이 어디까지 퍼질지 사용자가 통제하기 어렵다. 확인한 문서는 채팅에 입력한 비밀번호의 처리 방식을 설명하지 않으므로 이는 문서 동작에서 도출한 판단이다. 같은 이유로 일회성 작업이 끝나면 dot 브라우저에 남은 민감한 사이트의 세션을 로그아웃한다(운영 제안).

## 실행할 컴퓨터는 일이 묶인 자원으로 고른다

| 기준 | dot의 클라우드 컴퓨터 | 연결한 내 컴퓨터 |
|---|---|---|
| 켜져 있어야 하는 것 | 사용자 기기는 꺼져 있어도 된다(진행할 수 있고, 사용 사이에 상태를 유지할 수 있다) | 컴퓨터가 온라인이고 ChatGPT 앱이 열려 있어야 한다 |
| 쓰는 자원 | dot 자신의 파일, 소프트웨어, 브라우저 세션 | 그 컴퓨터의 파일과 도구, 로컬 스킬 |
| Work와 코딩 작업 | 저장소와 설정을 갖춘 Codex 클라우드 환경의 코딩 작업 | 로컬 Work, Codex 작업 생성과 기존 로컬 Codex 작업 이어 가기 |
| 브라우저 | 클라우드 브라우저의 별도 세션 | 클라우드 브라우저를 막는 사이트의 대안, 클라우드 세션은 넘어가지 않는다 |
| 연결 수 | 해당 없음 | 한 번에 개인 컴퓨터 한 대 |

- 연결할 컴퓨터의 ChatGPT 앱에서 dot 프로필을 열고 Computers의 Your computer에서 Allow access를 고른 뒤, 확인 화면에서 다시 Allow access를 누른다. 이 로컬 컴퓨터 권한은 Codex에 컴퓨터를 연결하거나 Work Sync를 켜는 것과 별개다.
- 연결은 작업 사이에도 유지된다. Offline 표시는 컴퓨터를 지금 쓸 수 없다는 뜻이며 연결을 해제하지 않는다. 컴퓨터를 연결해도 기존 ChatGPT와 Codex 대화 전체에 접근할 수 있게 되지는 않는다.
- 작업 관리는 클라우드에 두고 연결한 컴퓨터의 파일과 도구만 쓰게 할 수 있다. 클라우드 브라우저를 막는 사이트는 연결한 컴퓨터로 다시 시도하게 할 수 있지만, 특정 로컬 브라우저 지원은 보장되지 않는다.
- Enterprise에서는 로컬 컴퓨터 접근에 별도의 관리자 옵트인이 필요하고, 클라우드 정책 중 하나라도 `enforce_residency`가 켜져 있으면 dots의 로컬 컴퓨터 접근을 쓸 수 없다.

판단 기준은 그 일이 내 파일, 로컬 Codex 작업, 로컬 스킬, 클라우드 브라우저를 막는 사이트 가운데 하나에 묶여 있는지다. 묶여 있지 않다면 사용자 기기가 꺼져도 이어 갈 수 있는 클라우드 컴퓨터가 상시 실행에 맞다. 연결한 컴퓨터에 맡긴 일은 그 컴퓨터의 전원, 잠자기와 재시작이 곧 작업의 가용성이 되므로 [[Agent-Always-On-Mac-Host|상시 실행 Mac 에이전트 호스트]]의 점검을 함께 적용한다. 위임 지시에는 어느 컴퓨터에서 할지를 적는다(영상의 팁). 그 밖의 기준은 문서의 조건에서 도출했다.

### 로컬 앱 조작은 OS 권한과 앱 승인을 함께 확인한다

2026-10-28 OpenAI의 Computer Use 문서를 부분 대조했다. dot의 연결 컴퓨터와 ChatGPT의 기존 앱 권한을 함께 사용할 때 다음 차이를 확인한다. 기존 요금제와 전체 기능의 검증일은 유지한다.

- macOS의 Screen Recording은 화면 확인, Accessibility는 클릭과 입력에 필요하다. 이 OS 권한과 ChatGPT 안에서 특정 앱 사용을 허용하는 승인은 별개다.
- macOS에서는 범위를 정한 작업을 백그라운드로 맡길 수 있다. Windows에서는 활성 데스크톱의 전경 입력을 사용하므로 같은 세션에서 사용자가 계속 작업하는 백그라운드 실행으로 보지 않는다.
- 대상 앱에 전용 plugin이나 MCP가 있다면 데이터 접근과 반복 작업에는 그 구조화된 연결을 우선 검토한다. 시각적 확인이나 조작이 필요한 경우 Computer Use를 사용한다.

메신저 업무에 적용할 때는 대화 조회, 요약, 다른 방에 전달, 답장 발송을 별도 행동으로 정하는 방식을 권한다. 앱 접근 허용을 모든 대화의 재공유 승인으로 확대하지 않고, 발송 대상과 본문을 검토할 지점을 둔다. 이 절은 일반 조작 계약이며 특정 메신저의 공식 지원, 전송 성공률이나 생산성 배수를 검증한 결과가 아니다. 실제 앱 조작과 메시지 발송은 수행하지 않았다.

## 위임 계약 — 소유, 완료, 호출 조건과 금지 행동

공식 시작 안내는 중요한 것과 관련 출처를 알려 주고, 어떤 결정에 사용자 입력이 필요한지와 업데이트를 보낼 곳, 사용자에게 끼어들 시점을 정하라고 권한다. 이를 네 항목으로 묶은 것이 아래 표다(이 문서의 정리). 완료 기준을 위임 전에 정하는 원리는 [[AI-Code-Delegation-Review|AI 구현 위임과 코드 리뷰]]의 구현 계약과 같다.

| 항목 | 정할 것 | 근거 |
|---|---|---|
| 일의 소유 | 계속 챙길 일의 범위와 기간, 실행할 컴퓨터 | 지속 책임으로 시작하라는 안내, 컴퓨터별 조건 |
| 완료 기준 | 무엇을 보여주면 끝으로 볼지(산출물, 원문 링크, 검증 결과) | 실행 완료가 결과 달성을 확인해 주지 않는다 |
| 호출 조건 | 사용자를 부를 결정과 그때 쓸 채널 | 사용자 입력이 필요한 결정, 업데이트 위치와 사용자에게 끼어들 시점 |
| 금지 행동 | 발송, 삭제, 배포처럼 되돌리기 어려운 행동 | dot을 삭제해도 연결 앱의 변경과 이미 전달된 메시지는 되돌려지지 않는다 |

영상의 사용 예를 일반화하면 다음 네 문장이 된다.

- 소유: 앞으로 [맡길 일]은 네가 챙겨줘. [실행할 컴퓨터]에서 해줘.
- 완료: [산출물]을 보여주면 완료로 볼게.
- 호출: [조건]일 때만 나를 불러.
- 금지: 답장은 초안까지만 쓰고 보내거나 지우지 마. 배포는 하지 마.

운영할 때 볼 점은 셋이다.

- 금지 문장과 사용자 정의 규칙은 모두 dot이 따르려는 지시라 어길 여지가 남는다. 발송과 삭제는 규칙에도 Ask before taking action이나 Hand off to you로 적고, 가능하면 연결 계정의 권한에서 막는다(문서 설명에서 도출한 운영 제안).
- 위임 작업은 dot이 넘긴 지시와 맥락만 받는다. 확인한 문서는 금지 조항이 위임 작업에 그대로 넘어간다고 설명하지 않으므로, 위임 지시에도 금지 조항을 다시 적게 하고 Activity에서 위임 작업의 진행과 결과를 확인한다(운영 제안).
- 진행 상황 전체를 묻기보다 사용자 승인이나 입력을 기다리는 작업만 묻는 편이 확인 비용이 적다(영상의 사용 예).

## 이용 조건 (2026-10-21 기준)

- 순차 배포 중이라 요금제 조건을 갖춰도 바로 보이지 않을 수 있다.
- Pro 100, Pro 200, Pro 500은 유럽경제지역(EEA), 영국, 스위스 밖의 18세 초과(원문 over 18) 사용자가 대상이다.
- Business Premium과 Enterprise는 전 세계에 순차 배포 중이다. Enterprise는 기본으로 꺼져 있어 워크스페이스 관리자가 켜야 하며, 관리자 문서의 권한 이름은 Use dots (Beta)다.
- dot은 ChatGPT 모바일 앱, 데스크톱 앱, 데스크톱 브라우저에서 만들며 모바일 웹은 지원하지 않는다. 같은 dot에게 ChatGPT, Slack, Microsoft Teams와 통화로 연락할 수 있고 문자 메시지는 준비 중이다. Enterprise 관리자 문서는 Microsoft Teams 접근이 초대받은 경우에만 쓸 수 있는 알파(원문 invite-only alpha)로 제한된다고 적는다. 연락 수단을 추가해도 앱이나 컴퓨터 접근은 생기지 않는다.

## 운영 점검

- Pause는 dot의 현재 주 작업을 멈추지만 모든 위임 작업을 멈추지는 않고 앞으로 예정된 예약 실행도 취소하지 않는다. 멈춰도 이미 끝낸 행동은 되돌려지지 않는다. 멈출 때 Activity의 위임 작업과 Scheduled의 예약을 따로 정리했는가
- dot을 삭제해도 연결 앱의 변경과 이미 전달된 메시지는 되돌려지지 않는다. 삭제 전에 결과를 저장하고 외부에 생긴 변경을 확인했는가
- Enterprise 관리자 문서 기준 dot이 만든 파일, Codex 스레드와 ChatGPT 대화는 따로 저장돼 dot과 함께 다 지워지지는 않는다. 삭제 확인 화면의 안내를 읽고, 남은 항목을 위치별 삭제 절차로 정리했는가
- ChatGPT 메모리 설정을 바꾼 것만으로 dot의 기존 메모까지 정리됐다고 보지 않았는가
- 더 쓰지 않을 연결 컴퓨터를 Offline 상태로 두고 끝내지 않고, 연결이 남아 있으면 Revoke access로 해제했는가
