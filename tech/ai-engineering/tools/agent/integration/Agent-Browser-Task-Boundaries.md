# 브라우저 에이전트의 작업과 권한 경계

브라우저 에이전트는 웹페이지와 계정의 문맥을 읽고 여러 단계의 탐색이나 조작을 수행한다. 작업의 지속성, 파일 접근, 계정 사용과 외부 서비스의 상태 변경을 각각 확인해야 한다. 같은 브라우저 안에 있다는 사실만으로 이 권한들이 하나의 경계가 되지는 않는다.

## 작업 요청을 검토 가능한 결과로 정한다

다음은 브라우저 작업에 적용할 설계 기준이다.

- 대상 사이트와 계정, 입력 자료, 결과 형식과 저장 위치를 정한다.
- 조사 결과와 실제 변경을 구분한다. 상품 비교표 작성과 구매, 답장 초안과 발송은 서로 다른 완료 조건이다.
- 실행 중 보완 요청은 현재 작업을 바꾸는지, 현재 작업 뒤에 처리하는지 확인한다.

Aside의 `Queue`는 현재 실행 뒤에 새 메시지를 적용하고, `Steer`는 진행 중인 실행에 전달한다. 대기나 승인 요청이 있는 작업도 있으므로 요청 접수와 작업 완료를 구분한다. 이 기능 구분은 제품 사용 문서 기준이며 실제 업무의 성공률을 측정한 결과가 아니다.

## 파일 권한과 계정 사용 권한을 따로 확인한다

### 작업 공간 분리와 로그인 공유

2026-10-26에 확인한 ego(lite)의 제품 설명에서 `Space`는 에이전트가 별도 탭 영역에서 작업하는 공간이다. 사용자가 넘겨주지 않은 탭을 건드리지 않는 작업 분리와, 웹사이트 로그인 상태를 공유하는 것은 함께 성립한다. **별도 작업 공간을 별도 계정이나 권한으로 해석하지 않는다.** 실행 전에 대상 사이트의 현재 계정을 확인하고, 조회와 변경의 허용 범위를 따로 정한다(운영 제안).

ego(lite)는 Chromium 기반이며 엔진 안에서 semantic snapshot을 구성한다. 이를 페이지 렌더링을 하지 않는 제품이라는 뜻으로 확대하지 않는다. 이 설명만으로 특정 업무의 속도나 토큰 절감량을 보장할 수도 없다. 대표 작업의 성공 조건, 재시도 횟수와 전체 비용을 같은 조건에서 측정한다(검증 제안).

여러 봇이 컴퓨터를 함께 쓰는 자체 호스팅 비서에서도 같은 구분이 필요하다. 2026-10-27 공식 저장소 문서(main e37a428f06, Apache-2.0, 베타) 기준 Rakazo는 역할별 봇이 대화, 기억, 일정 작업과 기록을 유지하며 브라우저, 터미널, 파일과 데스크톱을 조작하게 한다. 기본 Team Computer에서는 활성 봇마다 별도 X 디스플레이와 Chrome 프로세스, 봇 신원에 묶인 영구 Chrome 프로필을 두어 로그인, 쿠키와 방문 기록을 논리적으로 나눈다. 그러나 문서가 정한 보안 경계는 컴퓨터 컨테이너다. Team 봇들은 같은 OS 사용자, 작업 공간, 셸과 X11 접근을 쓰므로 다른 봇의 프로필 파일에도 접근할 수 있다. 봇별 폴더는 작업 정리용이라 모든 Team 봇이 전체 작업 공간에 접근할 수 있다. 화면 lease는 도구 호출의 순서를 조율할 뿐 서로 믿을 수 없는 프로세스를 격리하지 않으므로, 격리가 필요한 업무에는 봇 전용 Private Computer를 쓴다. 봇별 프로필 분리를 봇 사이의 권한 경계로 해석하지 않는다.

### 제어권 인계와 게시 승인을 나눈다

ego(lite)의 공개 FAQ는 사용자가 Space에서 작업을 지켜보고 언제든 제어권을 넘겨받을 수 있다고 안내한다(2026-10-26 확인). 이 기능 설명만으로 모든 사이트의 게시 직전에 승인이 강제된다거나, 이미 실행한 변경이 취소된다고 판단하지 않는다.

운영 제안: 게시 작업은 계정, 대상 사이트, 제목과 본문을 검토할 수 있는 초안 단계와 실제 게시 단계로 나눈다. 사람이 제어권을 가져간 뒤에는 현재 화면과 이미 수행한 작업을 다시 확인하고 재개 범위를 정한다. 버튼을 누르기 전의 검토, 진행 중 제어권 인계와 실행 뒤 결과 확인은 각각 다른 점검이다. 여기서는 제품의 인계 기능을 직접 실행하거나 중단 시점을 측정하지 않았다.

인계 순서를 시스템이 강제하는 예도 있다. Rakazo에서 사용자가 봇 화면의 제어를 가져가면 그 화면의 배타적 제어 lease를 받는데, 봇이 실행 중이면 인계를 거부(HTTP 409)하고 봇을 먼저 멈추게 한다. 로그인, 2단계 인증이나 CAPTCHA처럼 보호된 입력이 필요하면 봇이 인계를 요청하고 기다린다. 실패한 조작은 확인된 진행과 결과가 불확실한지를 함께 보고하며, 문서는 현재 상태를 먼저 확인하고 완료됐거나 불확실한 조작을 자동으로 다시 실행하지 말라고 정한다.

### 화면 공유 협업의 원격 조작과 AI 조작 승인

2026-10-27 공식 저장소 문서(main 0fb9c45074, Apache-2.0, 1.0 이전) 기준 Petal은 공유한 창을 참여자의 데스크톱에 실제 네이티브 창으로 띄우는 원격 협업 앱이다. 다른 참여자에게 공유 창의 키보드와 마우스 조작을 넘길 수 있고, 기본값은 요청마다 공유자에게 동의 창을 띄우는 방식이다. 신뢰 모델은 인증된 회의 참여자를 모두 잠재적 조작자로 보되 호스트 쪽 검사로 막는다. 사용자별 허용 목록은 없고, 조작을 끄면 모든 조작자를 즉시 회수하며, 권한을 줄 때마다 새 토큰을 발급해 오래되거나 재전송된 입력을 막는다. 다만 이전 클라이언트와의 호환을 위해 토큰 없는 입력을 경고와 함께 받아 주는 기간이 아직 남아 있다고 문서가 밝힌다. Windows 공유에서 커서를 넘겨주는 전체 제어로 바꾸는 것은 공유자 승인으로만 일어나고, 실패한 조작이 더 강한 권한을 얻지 않는다.

조작 결과의 표현도 참고할 만하다. 대상 앱에서 의미 있는 효과를 관찰했을 때만 `applied`로, OS에 입력을 넣었지만 효과를 관찰하지 못하면 `submitted`로 보고해 전달을 과장하지 않는다. 에이전트의 화면 조작 결과도 실행 요청, 입력 전달과 효과 확인을 나눠 기록한다(운영 제안).

선택 기능인 공유 창 AI 대화는 기본으로 꺼져 있다. 켜면 회의의 누구든 공유 창에 Gemini Live 세션을 열 수 있고, 세션 동안 창 내용과 누르고 말하기로 보낸 음성이 Google로 전송된다. AI가 창을 클릭, 입력하거나 스크롤하려면 공유자만 보는 확인 창에서 한 번 허용, 세션 동안 허용, 거부 가운데 하나를 고르며, AI의 조작도 사람의 원격 조작과 같은 접근성 기반 입력 경로를 거친다. 문서는 Windows 지원과 원격 조작을 초기 단계로 표시한다. 두 제품 모두 설치와 실행은 하지 않았다.

### 파일 접근 모드와 도구 권한

2026-10-22 확인한 Aside의 세션 모드는 다음과 같다.

| 모드 | 문서에 명시된 범위 |
|---|---|
| `Read only` | 브라우저와 파일 문맥을 검사하되 파일을 변경하지 않음 |
| `Guard` | 승인된 폴더에서 작업하고 다른 폴더 접근 전에 질문 |
| `Full access` | 컴퓨터의 파일 읽기와 쓰기 범위를 확대 |

이 표의 파일 제한만으로 웹사이트에서의 결제, 게시나 메시지 발송까지 차단된다고 판단하지 않는다. 도구 권한은 별도로 `Allow`, `Ask`, `Deny`를 정하며 `Deny`가 우선한다. 명령의 OS 격리 여부도 Sandbox 설정에서 따로 관리한다.

저장 비밀번호는 AI에게 값을 보여주지 않고 자동 입력할 수 있다. 그러나 **비밀번호 값을 숨기는 것과 계정을 사용하지 못하게 하는 것은 다르다**. Aside는 비밀번호 접근 정책과 대상 URL을 검사하며, 전역 정책에 더해 항목별 정책을 둘 수 있다. 문서 기준 incognito 세션에서는 에이전트의 비밀번호 관리자 접근을 허용하지 않는다.

운영 점검 제안: 필요한 계정과 파일 범위를 좁힌 뒤 조회, 변경, 전송의 허용 조건을 각각 확인한다. 테스트용 계정에서 승인 요청과 거부 경로를 확인하기 전에는 모드 이름만으로 외부 효과의 통제를 입증하지 않는다.

## 정기 실행과 기억의 수명을 구분한다

Aside의 cron routine은 일정마다 새 작업을 만들고, heartbeat routine은 기존 대화를 깨워 이어 간다. 겹친 routine 실행은 건너뛰고 대상 대화를 사용할 수 없으면 routine을 일시 중지한다. 반복 업무 제안은 초안이며 검토 후 활성화하는 단계가 있다.

적용 제안: 독립된 주간 조사에는 새 작업을, 이전 대화의 진행 상황을 이어야 할 때는 기존 대화 재개를 검토한다. 일정 등록만으로 매번 실행됐다고 보고하지 않고 실행 상태와 결과를 확인한다. 한 번 성공한 작업도 다음 실행의 데이터와 로그인 상태를 다시 확인해야 한다.

기억 기능은 브라우징 이력, 대화와 작업의 맥락을 재사용한다. Aside에서는 기억 생성 여부와 episodic memory의 보존 기간을 설정하고, 저장 내용을 검토하거나 편집할 수 있다. 저장된 기억을 최신 사실이나 현재 작업의 승인으로 취급하지 않는다. 보존 기간 설정과 원래 작업 기록의 보존 범위도 따로 확인한다.

## 로컬 보관과 모델 전송은 다른 경계다

Aside의 작업 기록과 산출물은 로컬에 저장되지만, hosted model에는 실행에 필요한 문맥이 전달될 수 있다. 개인정보 처리방침은 프롬프트, 도구 결과, 선택한 브라우저 snapshot, screenshot과 파일 등을 모델이 볼 수 있는 문맥으로 설명한다. 계정, 결제, 동기화와 hosted AI 기능에도 서버 측 서비스가 쓰인다.

따라서 로컬 우선이라는 설명을 전체 작업의 무전송 보장으로 해석하지 않는다. 선택한 모델 제공자, 전달할 자료와 활성화된 동기화 기능을 함께 확인한다. 이 설명은 공개 정책의 데이터 흐름 범위이며 네트워크 패킷이나 제품 구현을 직접 감사한 결과가 아니다.

ego(lite)도 비밀번호, 쿠키, 북마크와 방문 기록의 로컬 보관을 설명하면서, 에이전트가 작업하는 페이지 내용은 선택한 모델로 전달된다고 명시한다. 저장 위치와 모델에 제공하는 문맥을 각각 확인해야 한다. 이 추가 내용은 2026-10-26 제품 설명과 대조했다. 이후 Rakazo와 Petal 추가 및 Rakazo의 공유 경계 재대조는 부분 검증이며, 기존 Aside 설명 전체를 다시 검증한 것은 아니다.
