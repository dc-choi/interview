# 브라우저 에이전트의 작업과 권한 경계

브라우저 에이전트는 웹페이지와 계정의 문맥을 읽고 여러 단계의 탐색이나 조작을 수행한다. 작업의 지속성, 파일 접근, 계정 사용과 외부 서비스의 상태 변경을 각각 확인해야 한다. 같은 브라우저 안에 있다는 사실만으로 이 권한들이 하나의 경계가 되지는 않는다.

## 작업 요청을 검토 가능한 결과로 정한다

다음은 브라우저 작업에 적용할 설계 기준이다.

- 대상 사이트와 계정, 입력 자료, 결과 형식과 저장 위치를 정한다.
- 조사 결과와 실제 변경을 구분한다. 상품 비교표 작성과 구매, 답장 초안과 발송은 서로 다른 완료 조건이다.
- 실행 중 보완 요청은 현재 작업을 바꾸는지, 현재 작업 뒤에 처리하는지 확인한다.

Aside의 `Queue`는 현재 실행 뒤에 새 메시지를 적용하고, `Steer`는 진행 중인 실행에 전달한다. 대기나 승인 요청이 있는 작업도 있으므로 요청 접수와 작업 완료를 구분한다. 이 기능 구분은 제품 사용 문서 기준이며 실제 업무의 성공률을 측정한 결과가 아니다.

## 파일 권한과 계정 사용 권한을 따로 확인한다

### 작업 공간 분리와 로그인 공유

2026-10-26에 확인한 ego(lite)의 제품 설명에서 `Space`는 에이전트가 별도 탭 영역에서 작업하는 공간이다. 사용자가 넘겨주지 않은 탭을 건드리지 않는 작업 분리와, 웹사이트 로그인 상태를 공유하는 것은 함께 성립한다. **별도 작업 공간을 별도 계정이나 권한으로 해석하지 않는다.** 실행 전에 대상 사이트의 현재 계정을 확인하고, 조회와 변경의 허용 범위를 따로 정한다(운영 제안).

ego(lite)는 Chromium 기반이며 엔진 안에서 semantic snapshot을 구성한다. 이를 페이지 렌더링을 하지 않는 제품이라는 뜻으로 확대하지 않는다. 이 설명만으로 특정 업무의 속도나 토큰 절감량을 보장할 수도 없다. 대표 작업의 성공 조건, 재시도 횟수와 전체 비용을 같은 조건에서 측정한다(검증 제안).

여러 봇이 컴퓨터를 함께 쓰는 자체 호스팅 비서에서도 같은 구분이 필요하다. 2026-10-27 공식 저장소 문서(main e37a428f06, Apache-2.0, 베타) 기준 Rakazo는 역할별 봇이 대화, 기억, 일정 작업과 기록을 유지하며 브라우저, 터미널, 파일과 데스크톱을 조작하게 한다. 기본 Team Computer에서는 활성 봇마다 별도 X 디스플레이와 Chrome 프로세스, 봇 신원에 묶인 영구 Chrome 프로필을 두어 로그인, 쿠키와 방문 기록을 논리적으로 나눈다. 그러나 문서가 정한 보안 경계는 컴퓨터 컨테이너다. Team 봇들은 같은 OS 사용자, 작업 공간, 셸과 X11 접근을 쓰므로 다른 봇의 프로필 파일에도 접근할 수 있다. 봇별 폴더는 작업 정리용이라 모든 Team 봇이 전체 작업 공간에 접근할 수 있다. 화면 lease는 도구 호출의 순서를 조율할 뿐 서로 믿을 수 없는 프로세스를 격리하지 않으므로, 격리가 필요한 업무에는 봇 전용 Private Computer를 쓴다. 봇별 프로필 분리를 봇 사이의 권한 경계로 해석하지 않는다.

OpenMausBot도 봇마다 쓸 컴퓨터를 따로 고르게 한다. 선택지는 유료 제3자 클라우드 데스크톱, 로컬 VM, macOS와 Ubuntu Xorg의 호스트 직접 제어(명시적 선택, Wayland에서는 꺼짐)다. 셸 명령과 파일 수정은 허용과 거부 카드로 승인받는다. harness는 로컬 루프백 주소에서 돌고 API 키를 0600 권한의 평문 설정 파일에 둔다. 호스트 직접 제어는 작업 공간 분리가 아니라 사용자 계정 그대로의 권한이므로 격리된 VM과 구분해 쓴다(2026-11-09 README 확인).

### 쓰던 브라우저를 빌려줄 때 가드레일과 데이터 경계를 나눈다

OpenCode Browse(anomalyco/browse, MIT)는 MCP 서버와 Chromium 확장으로 에이전트가 사용자의 실제 브라우저, 로그인 상태와 확장 프로그램을 쓰게 한다. OpenCode, Claude Code, Codex, Cursor 같은 MCP 클라이언트에 붙는다. 2026-11-18 README 기준 구조와 경계는 다음과 같다. 설치해 시험하지는 않았다.

- **연결 구조**: 에이전트가 띄운 stdio MCP 프록시가 `127.0.0.1`의 릴레이로 호출을 넘기고, 확장은 WebSocket으로 릴레이에 붙어 `chrome.debugger`로 명령을 실행한다. 릴레이 요청에는 사용자만 읽을 수 있는 토큰 파일이 필요하고, 브라우저는 10분 동안 한 번만 쓰는 코드로 페어링해 ECDH 키 합의로 자기 키를 받는다. 릴레이는 시작할 때와 매시간 새 릴리스를 확인해 기본값으로 스스로 설치하므로(알림만 받거나 설치하지 않게 바꿀 수 있다), 로그인된 브라우저를 조작하는 구성 요소의 갱신 경로도 신뢰 대상에 넣는다.
- **탭 소유와 인계**: 에이전트는 자기가 연 탭(접힌 백그라운드 그룹)과 사용자가 툴바 버튼으로 빌려준 탭만 쓴다. 로그인, 2단계 인증과 결제는 탭을 사용자에게 넘기고, 사용자가 카드나 툴바 버튼으로 Continue를 실제로 눌러야 이어 가므로 페이지가 인계 완료를 흉내 낼 수 없다. Cloudflare나 captcha 같은 봇 확인은 풀지 않고 사용자에게 넘긴다.
- **가드레일은 데이터 경계가 아니다**: `allowedOrigins`는 이동과 에이전트가 여는 탭을 제한할 뿐 페이지가 스스로 보내는 요청은 거르지 않는다. `readOnly`는 클릭과 입력을 막지만 `eval`은 페이지가 읽을 수 있는 모든 것을 읽고 페이지 자격으로 요청을 보낼 수 있다. README도 에이전트가 읽지 않기를 바라는 페이지는 이 브라우저에서 열지 말라고 적고, `execute` 스크립트의 QuickJS 샌드박스를 경계가 아니라 사용자 권한으로 도는 코드로 다루라고 한다. 쿠키 삭제, 브라우저 종료와 사이트 권한 변경 같은 CDP 명령은 거부한다.
- **가림의 범위**: `fill`은 비밀번호와 일회용 코드 칸의 값만 가리고, 네트워크 캡처는 이름과 형태로 자격 증명을 가리므로 평범한 이름에 든 비밀 값은 남을 수 있다. 페이지 글, 콘솔과 스크린샷은 그대로 돌려준다. README는 에이전트가 모델 제공자에게 보내는 것 말고는 컴퓨터 밖으로 나가는 것이 없다고 적는데, 이 문서의 아래 절처럼 그 전송이 곧 페이지 내용의 외부 전송이다.
- **사람처럼 보이는 입력**: 페이지가 감지할 수 있는 CDP 기능을 켜지 않고 곡선 마우스 경로와 속도를 조절한 입력을 써서 에이전트를 알아보기 어렵게 한다. 불가능하게 만들지는 않으며 디버깅 알림 막대는 보인다. 탐지를 피하기 쉽다는 것이 사이트의 자동화 허용 여부를 바꾸지는 않는다(적용 제안).

적용 제안: 실제 프로필을 빌려줄 때는 맡길 탭과 계정을 좁히고, 열린 탭의 내용이 모델로 전송된다는 전제로 작업을 고른다. 출처 제한과 읽기 전용 같은 설정은 에이전트가 엉뚱한 곳으로 가지 않게 하는 장치로 쓰고, 민감한 페이지를 지키는 수단으로 쓰지 않는다.

### 제어권 인계와 게시 승인을 나눈다

ego(lite)의 공개 FAQ는 사용자가 Space에서 작업을 지켜보고 언제든 제어권을 넘겨받을 수 있다고 안내한다(2026-10-26 확인). 이 기능 설명만으로 모든 사이트의 게시 직전에 승인이 강제된다거나, 이미 실행한 변경이 취소된다고 판단하지 않는다.

운영 제안: 게시 작업은 계정, 대상 사이트, 제목과 본문을 검토할 수 있는 초안 단계와 실제 게시 단계로 나눈다. 사람이 제어권을 가져간 뒤에는 현재 화면과 이미 수행한 작업을 다시 확인하고 재개 범위를 정한다. 버튼을 누르기 전의 검토, 진행 중 제어권 인계와 실행 뒤 결과 확인은 각각 다른 점검이다. 여기서는 제품의 인계 기능을 직접 실행하거나 중단 시점을 측정하지 않았다.

인계 순서를 시스템이 강제하는 예도 있다. Rakazo에서 사용자가 봇 화면의 제어를 가져가면 그 화면의 배타적 제어 lease를 받는데, 봇이 실행 중이면 인계를 거부(HTTP 409)하고 봇을 먼저 멈추게 한다. 로그인, 2단계 인증이나 CAPTCHA처럼 보호된 입력이 필요하면 봇이 인계를 요청하고 기다린다. 실패한 조작은 확인된 진행과 결과가 불확실한지를 함께 보고하며, 문서는 현재 상태를 먼저 확인하고 완료됐거나 불확실한 조작을 자동으로 다시 실행하지 말라고 정한다.

관리형 브라우저 에이전트 서비스인 Amazon Nova Act도 사람 개입을 두 패턴으로 나눈다. 2026-11-15 공식 문서 기준 Nova Act는 자연어 작업을 `act()` 호출로 넘기고 Python 코드로 여러 호출을 엮은 workflow를 AWS에 배포해 실행 기록을 콘솔에서 본다. 문서에 표시된 리전은 미국 동부(버지니아 북부)뿐이다. 사람 개입(HITL)은 두 패턴이다.

| 패턴 | 동작 |
|---|---|
| 사람 승인 | 현재 화면을 캡처해 검토자에게 보여 주고 승인, 거부나 선택지를 비동기로 받는다 |
| UI 인계 | 원격 브라우저 세션을 실시간 화면으로 넘겨 사람이 마우스와 키보드로 조작한다 |

HITL은 SDK가 제공하는 기능이며 문서는 관리형 AWS 서비스가 아니라고 밝힌다. 알림과 감독 화면은 자기 계정에 CDK로 배포하는 공개 패키지를 쓰거나 직접 만든다. 따라서 승인 단계를 workflow의 어느 지점에 둘지, 응답이 없을 때 언제 끝낼지는 작성자가 정한다. 문서도 세션 나이에 맞춘 시간 제한을 권한다. 서비스를 실행해 승인 흐름을 확인하지는 않았다.

### 화면 공유 협업의 원격 조작과 AI 조작 승인

2026-10-27 공식 저장소 문서(main 0fb9c45074, Apache-2.0, 1.0 이전) 기준 Petal은 공유한 창을 참여자의 데스크톱에 실제 네이티브 창으로 띄우는 원격 협업 앱이다. 다른 참여자에게 공유 창의 키보드와 마우스 조작을 넘길 수 있고, 기본값은 요청마다 공유자에게 동의 창을 띄우는 방식이다. 신뢰 모델은 인증된 회의 참여자를 모두 잠재적 조작자로 보되 호스트 쪽 검사로 막는다. 사용자별 허용 목록은 없고, 조작을 끄면 모든 조작자를 즉시 회수하며, 권한을 줄 때마다 새 토큰을 발급해 오래되거나 재전송된 입력을 막는다. 다만 이전 클라이언트와의 호환을 위해 토큰 없는 입력을 경고와 함께 받아 주는 기간이 아직 남아 있다고 문서가 밝힌다. Windows 공유에서 커서를 넘겨주는 전체 제어로 바꾸는 것은 공유자 승인으로만 일어나고, 실패한 조작이 더 강한 권한을 얻지 않는다.

조작 결과의 표현도 참고할 만하다. 대상 앱에서 의미 있는 효과를 관찰했을 때만 `applied`로, OS에 입력을 넣었지만 효과를 관찰하지 못하면 `submitted`로 보고해 전달을 과장하지 않는다. 에이전트의 화면 조작 결과도 실행 요청, 입력 전달과 효과 확인을 나눠 기록한다(운영 제안).

선택 기능인 공유 창 AI 대화는 기본으로 꺼져 있다. 켜면 회의의 누구든 공유 창에 Gemini Live 세션을 열 수 있고, 세션 동안 창 내용과 누르고 말하기로 보낸 음성이 Google로 전송된다. AI가 창을 클릭, 입력하거나 스크롤하려면 공유자만 보는 확인 창에서 한 번 허용, 세션 동안 허용, 거부 가운데 하나를 고르며, AI의 조작도 사람의 원격 조작과 같은 접근성 기반 입력 경로를 거친다. 문서는 Windows 지원과 원격 조작을 초기 단계로 표시한다. 두 제품 모두 설치와 실행은 하지 않았다.

### 파일 접근 모드와 도구 권한

2026-10-22 확인한 Aside의 세션 모드는 다음과 같다.

| 모드 | 문서에 명시된 범위 |
|---|---|
| `Read only` | 브라우저와 파일 문맥을 검사하되 파일을 변경하지 않음 |
| `Guard` | 승인된 폴더에서 작업하고 다른 폴더 접근 전에 질문 |
| `Full access` | 컴퓨터의 파일 읽기와 쓰기 범위를 확대 |

이 표의 파일 제한만으로 웹사이트에서의 결제, 게시나 메시지 발송까지 차단된다고 판단하지 않는다. 도구 권한은 별도로 `Allow`, `Ask`, `Deny`를 정하며 `Deny`가 우선한다. 명령의 OS 격리 여부도 Sandbox 설정에서 따로 관리한다.

저장 비밀번호는 AI에게 값을 보여주지 않고 자동 입력할 수 있다. 그러나 **비밀번호 값을 숨기는 것과 계정을 사용하지 못하게 하는 것은 다르다**. Aside는 비밀번호 접근 정책과 대상 URL을 검사하며, 전역 정책에 더해 항목별 정책을 둘 수 있다. 문서 기준 incognito 세션에서는 에이전트의 비밀번호 관리자 접근을 허용하지 않는다.

운영 점검 제안: 필요한 계정과 파일 범위를 좁힌 뒤 조회, 변경, 전송의 허용 조건을 각각 확인한다. 테스트용 계정에서 승인 요청과 거부 경로를 확인하기 전에는 모드 이름만으로 외부 효과의 통제를 입증하지 않는다.

## 화면의 팝업이 작업을 가로챈다

화면을 보고 조작하는 에이전트는 화면에 보이는 요소를 과제와 관련된 안내로 받아들일 수 있다. Zhang 외(ACL 2025)는 사람이라면 알아보고 무시할 적대적 팝업을 OSWorld와 VisualWebArena 시험 환경에 넣었다. 비전 언어 모델 에이전트는 평균 86%의 비율로 팝업을 눌렀고 과제 성공률은 47% 떨어졌다. 에이전트에게 팝업을 무시하라고 지시하거나 팝업에 광고 표시를 붙이는 기본 방어는 효과가 없었다. 2026-11-18 논문 초록과 대조했다.

적용 제안: 지시문만으로 방해 요소를 막는다고 가정하지 않는다. 결제, 게시, 설치처럼 상태를 바꾸는 조작은 위의 도구 권한과 승인 단계로 막고, 시험 세트에 팝업과 배너 같은 방해 요소를 넣은 경우를 따로 둔다. 사람에게 보이지 않게 숨긴 AI용 지시는 [[Web-Content-Manipulation-for-AI|AI가 읽는 웹 콘텐츠의 조작]]에서 다룬다.

## 정기 실행과 기억의 수명을 구분한다

Aside의 cron routine은 일정마다 새 작업을 만들고, heartbeat routine은 기존 대화를 깨워 이어 간다. 겹친 routine 실행은 건너뛰고 대상 대화를 사용할 수 없으면 routine을 일시 중지한다. 반복 업무 제안은 초안이며 검토 후 활성화하는 단계가 있다.

적용 제안: 독립된 주간 조사에는 새 작업을, 이전 대화의 진행 상황을 이어야 할 때는 기존 대화 재개를 검토한다. 일정 등록만으로 매번 실행됐다고 보고하지 않고 실행 상태와 결과를 확인한다. 한 번 성공한 작업도 다음 실행의 데이터와 로그인 상태를 다시 확인해야 한다.

기억 기능은 브라우징 이력, 대화와 작업의 맥락을 재사용한다. Aside에서는 기억 생성 여부와 episodic memory의 보존 기간을 설정하고, 저장 내용을 검토하거나 편집할 수 있다. 저장된 기억을 최신 사실이나 현재 작업의 승인으로 취급하지 않는다. 보존 기간 설정과 원래 작업 기록의 보존 범위도 따로 확인한다.

## 컴퓨터 사용의 경로 구분과 활동 기록 기억의 통제

2026-11-17 공개 발표에서 Codex 앱의 컴퓨터 관련 기능은 다음처럼 소개됐고, 2026-11-21 공식 Computer Use, Chrome 확장과 Computer History 문서로 대조했다. 기능을 실행하지는 않았고 이 절만 대조했으므로 문서의 `verified_at`은 그대로 둔다.

- **경로 구분:** 전용 플러그인이 없는 앱은 컴퓨터 사용으로 접근한다. 문서도 플러그인으로 없는 데이터 원천을 다룰 때 쓰고, 전용 플러그인이나 MCP 서버가 있으면 그쪽을 먼저 쓰라고 적는다. macOS에서는 사용자의 화면을 점유하지 않고 자기 커서로 백그라운드에서 돈다고 했는데, 문서는 macOS에서 범위를 정한 작업을 백그라운드로 돌리는 동안 다른 일을 할 수 있다고만 적고 별도 커서는 언급하지 않는다. Windows의 컴퓨터 사용은 활성 데스크톱에서 돌아 같은 세션을 쓰는 동안 백그라운드로 동작하지 못한다고 문서에 적혀 있다. 정보 수집과 iOS 시뮬레이터 앱 시험이 예로 나왔다. 웹사이트는 Chrome 확장으로 로그인된 맥락을 쓰고 Windows, Linux와 macOS에서 사용자가 다른 탭을 쓰는 동안 백그라운드로 작업한다고 했는데, 확장 문서는 이미 로그인한 사이트를 읽거나 조작한다고 적을 뿐 OS별 백그라운드 동작은 적지 않는다. [[ChatGPT-Dots#로컬 앱 조작은 OS 권한과 앱 승인을 함께 확인한다|dots의 로컬 앱 조작]]의 Windows 전경 입력도 데스크톱 앱 조작의 설명이므로, OS별 백그라운드 가능 여부를 한 문장으로 합치지 않고 경로마다 확인한다(이 문서의 해석).
- **활동 기록(Computer History):** 문서 기준 macOS의 ChatGPT 데스크톱 앱에서 Pro, Business와 Enterprise 사용자에게 제공되고 기본으로 꺼져 있다. Business와 Enterprise는 관리자가 접근을 허용해도 사람마다 따로 켜야 하며 Memories가 필요하다. 발표는 쓰는 동안 쌓이므로 켠 직후에는 효과가 없다고 설명했다. 문서는 클릭, 입력, 단축키, 앱 전환 같은 상호작용 이벤트와 macOS 접근성 기능으로 얻는 텍스트를 쓰고 스크린샷과 오디오는 기록하지 않는다고 적는다. 사용하는 앱과 도구의 습관을 배워 메모리로 쓰며, 블로그 초안을 쓰는 도구를 바꾼 변화도 따라갔다는 예가 있었다. 앞서 보던 문서를 찾아 달라는 요청에도 쓴다.
- **통제 수단:** 언제든 일시정지(메뉴 막대), 최근 기록을 소급해 지우기(문서 기준 최근 10분, 1시간, 1일 또는 전체), 특정 웹사이트와 앱을 제외하거나 고른 것만 포함하기가 문서와 같다. 비공개 모드의 웹 활동은 포함되지 않는다.

발표가 설명하지 않은 점 가운데 문서로 확인된 것은 다음과 같다. 기록을 지우면 해당 이벤트와 그것으로 만든 메모리가 함께 지워지고 되돌릴 수 없다. 이벤트 파일은 Mac에 최대 48시간 임시로 남고, OpenAI가 서버에서 처리해 메모리를 만든 뒤 법적 요구가 없으면 보관하지 않으며 학습에 쓰지 않는다고 적는다. 만들어진 메모리는 `~/.codex/memories/extensions/skysight/` 아래 암호화되지 않은 Markdown 파일로 남아 같은 macOS 사용자로 도는 다른 프로그램이 읽을 수 있고, 이후 대화에 맥락으로 들어가면 데이터 제어 설정에 따라 모델 개선에 쓰일 수 있다. 점검(적용 제안): 로컬 보관이라는 설명을 무전송으로 읽지 않는다. 제외한 앱과 사이트의 내용이 컴퓨터 사용이나 Appshots 같은 다른 경로로는 여전히 읽히는지는 문서에서 확인하지 못했으므로 민감한 작업 환경에서는 켜기 전에 설정 화면으로 확인한다. 위 기억 절의 원칙대로 학습된 습관을 현재 사실이나 작업 승인으로 취급하지 않는다.

## 로컬 보관과 모델 전송은 다른 경계다

Aside의 작업 기록과 산출물은 로컬에 저장되지만, hosted model에는 실행에 필요한 문맥이 전달될 수 있다. 개인정보 처리방침은 프롬프트, 도구 결과, 선택한 브라우저 snapshot, screenshot과 파일 등을 모델이 볼 수 있는 문맥으로 설명한다. 계정, 결제, 동기화와 hosted AI 기능에도 서버 측 서비스가 쓰인다.

따라서 로컬 우선이라는 설명을 전체 작업의 무전송 보장으로 해석하지 않는다. 선택한 모델 제공자, 전달할 자료와 활성화된 동기화 기능을 함께 확인한다. 이 설명은 공개 정책의 데이터 흐름 범위이며 네트워크 패킷이나 제품 구현을 직접 감사한 결과가 아니다.

ego(lite)도 비밀번호, 쿠키, 북마크와 방문 기록의 로컬 보관을 설명하면서, 에이전트가 작업하는 페이지 내용은 선택한 모델로 전달된다고 명시한다. 저장 위치와 모델에 제공하는 문맥을 각각 확인해야 한다. 이 추가 내용은 2026-10-26 제품 설명과 대조했다. 이후 Rakazo와 Petal 추가 및 Rakazo의 공유 경계 재대조는 부분 검증이며, 기존 Aside 설명 전체를 다시 검증한 것은 아니다.
