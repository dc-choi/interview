# 에이전트 데이터 분석과 보고서의 실행 경계

데이터 분석 에이전트는 질문을 분석 계획으로 바꾸고, 코드를 실행해 집계한 뒤 그 결과로 보고서를 만드는 시스템이다. 모델이 숫자를 추측하는 단계와 계산 도구가 실제 데이터를 처리하는 단계를 분리한다.

## 계획, 계산과 보고서

| 단계 | 산출물 | 확인할 경계 |
|---|---|---|
| 계획 | 질문, 사용할 데이터와 분석 항목 | 지표 정의, 기간과 누락된 조건 |
| 계산 | 실행 코드, 집계 결과와 차트 | 실행 성공, 입력 범위와 집계 정합성 |
| 추적 | 완료 항목과 추가 분석 필요 여부 | 실제 산출물과 계획의 일치 |
| 보고서 | 검토 가능한 설명과 결과 파일 | 모든 수치와 주장을 계산 결과에 연결 |

AWS의 공개 구현은 Planner, Coder, Supervisor와 Reporter 역할을 나누고, 계산 결과를 파일에 누적해 보고서 작성자가 읽도록 한다. 이 역할 구분을 에이전트 수의 필수 요건으로 보지는 않는다. 고정된 정기 집계라면 기존 SQL과 보고서 템플릿으로 처리하고, 분석 경로가 달라지는 질문에 동적 계획을 검토한다.

## 원본 데이터와 모델 문맥을 분리한다

큰 파일 전체를 프롬프트에 넣기보다 파일 위치, 스키마와 업무 정의를 주고 실행 도구가 대상 데이터를 읽게 한다. 모델에는 필요한 집계와 진단 결과를 반환한다. 다만 코드 실행도 메모리, 시간과 접근 권한의 제약을 받는다. 파일 전체를 읽었다는 사실은 올바른 분석의 증거가 아니다.

실행 환경의 선택지로 AgentCore Code Interpreter는 격리된 환경의 코드 실행과 데이터 분석을 제공한다. 이것이 앞선 공개 구현의 실행 환경과 같다는 뜻은 아니다. 네트워크 모드, 실행 역할과 접근 가능한 데이터는 별도로 설정하고 확인한다.

## 검증할 최소 계약

다음은 계산과 보고서의 분리 원리를 적용한 설계 제안이다.

1. 입력 파일 버전, 필터, 집계 기간과 코드 실행 결과를 연결한다. 같은 파일명에 내용이 바뀌는 경우도 구분한다.
2. 필터 전후 행 수, 결측값, 중복과 조인에 따른 행 증가를 검사한다. 전량 집계여도 잘못된 조인이나 지표 정의는 결과를 왜곡한다.
3. 실행이 실패하면 이전 실행의 결과를 이번 결과로 보고하지 않는다. 실패 지점과 남은 작업을 구분한다.
4. 보고서의 수치와 차트를 계산 산출물에 대조한다. 보고서 작성자가 빈 결과를 임의로 채우지 않게 한다.
5. 상관관계에서 원인을 단정하거나 자동으로 캠페인을 집행하지 않는다. 분석 완료, 사업 판단과 외부 실행은 서로 다른 상태다.

분석 결과의 사업 적용과 성과 측정은 [[AI-Marketing-Analysis|AI 마케팅 분석의 판단 경계]]에서 다룬다. 모델의 자기 검토는 계산 검산이나 독립 검토를 대신하지 않는다.
