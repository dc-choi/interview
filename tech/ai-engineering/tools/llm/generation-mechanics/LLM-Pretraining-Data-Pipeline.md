# LLM 사전학습 데이터 파이프라인: 웹 수집에서 데이터 혼합과 어닐링까지

인터넷 전체로 학습한다는 말은 실제로는 웹 크롤 원본에서 본문을 뽑고, 위험하거나 품질이 낮은 문서와 중복을 걸러 내고, 도메인 비율을 정하고, 학습 마지막에 고품질 데이터의 비중을 높이는 여러 단계를 거친 결과를 뜻한다. 단계마다 무엇을 버리는지와 그 선택을 무엇으로 검증하는지가 모델 품질을 정한다. 아래 예는 처리 단계를 비교적 자세히 공개한 Llama 3 보고서(2024)를 중심으로 한다. 상위: [[LLM-Generation-Mechanics|LLM 동작 원리]]. 데이터의 공개 범위와 재현성, 데이터셋 문서화는 [[LLM-Generation-Mechanics-Training#사전학습 데이터와 재현 가능한 공개 범위|사전학습 데이터와 재현 가능한 공개 범위]]에서 다룬다.

## 웹 크롤은 원재료다

Common Crawl은 2007년에 세워진 비영리 단체가 무료로 공개하는 웹 크롤 말뭉치다. 2026-11-18 홈페이지 기준 3,000억 페이지 이상을 담고 매달 30억~50억 페이지를 더한다. 원본 HTML에는 메뉴, 쿠키 안내, 반복되는 머리말과 꼬리말, 잘린 문장과 스팸이 섞여 있어 그대로 학습하면 이런 문서를 이어 쓰는 법도 배운다. 공개 연구 데이터도 이 원본을 정제해 만든다. LLaMA(2023)는 학습 데이터의 67%를 2017~2020년 Common Crawl 덤프 다섯 개에서 가져왔고, FineWeb(2024)은 스냅샷 96개에서 15T 토큰을 만들었다.

## 정제 단계

| 단계 | 하는 일 | Llama 3 보고서의 구현 |
|---|---|---|
| 안전과 개인정보 필터 | 위험한 도메인을 통째로 뺀다 | 위험한 콘텐츠나 개인정보가 많을 사이트, 자체 안전 기준상 유해한 도메인, 성인 콘텐츠 도메인을 제거 |
| 본문 추출 | HTML에서 본문만 남긴다 | 상용구 제거의 정밀도와 본문 재현율을 함께 맞춘 자체 파서. 수식과 코드 구조를 보존하고, 수식이 렌더링된 이미지로 들어가는 경우가 많아 이미지 alt 텍스트를 남겼다. 웹 위주 학습에서 Markdown 표기가 일반 텍스트보다 해롭다는 실험 결과에 따라 Markdown 표지를 지웠다 |
| 중복 제거 | 같은 페이지, 거의 같은 문서, 반복 줄을 줄인다 | URL 단위(최신 버전만 유지), 전체 데이터에 걸친 MinHash 문서 단위, 3,000만 문서 묶음마다 6번 넘게 나온 줄을 지우는 줄 단위 |
| 휴리스틱 필터 | 규칙으로 저품질 문서와 이상치를 거른다 | 반복 n-gram 비율로 로그와 오류 메시지 같은 반복 줄 제거, 금칙어 수로 차단 목록에 없는 성인 사이트 제거, 말뭉치 전체와 토큰 분포의 KL divergence로 이상 토큰이 많은 문서 제거 |
| 모델 기반 품질 필터 | 분류기 점수로 좋은 문서를 고른다 | 위키백과가 참조할 만한 글인지 맞히는 fastText 분류기, Llama 2의 판정으로 학습한 RoBERTa 계열 분류기(효율 때문에 DistilRoBERTa로 점수 계산) |
| 도메인별 처리 | 분포가 다른 데이터를 따로 다룬다 | 코드와 수학 추론 페이지를 고르는 별도 분류기와 추출기, fastText 언어 식별(176개 언어)과 언어별 중복 제거 |

- **중복 제거는 좋은 글도 지운다**: Llama 3의 줄 단위 중복 제거는 메뉴와 쿠키 안내 같은 상용구뿐 아니라 자주 나오는 좋은 문장도 지웠지만, 실험에서는 성능이 크게 좋아졌다. 지운 것의 내용과 최종 성능을 따로 확인한 사례다.
- **품질 분류기는 품질의 정의를 담는다**: LLaMA는 위키백과에서 참조된 페이지와 무작위 페이지를 가르는 선형 분류기를 학습하고, 참조 쪽으로 분류되지 않은 페이지를 버렸다. 이런 분류기는 참조 문헌과 닮은 글을 좋은 글로 정의하는 셈이므로, 과업에 필요한 영역의 문서가 함께 빠지지 않았는지 따로 본다(해석과 적용 제안).
- **규모 때문에 싼 분류기를 쓴다**: 필터는 수천억 페이지 규모에서 돌아야 하므로 fastText나 작은 분류기를 쓰고, 큰 모델은 그 분류기의 학습 라벨을 만드는 데 쓰는 구성이 Llama 3의 예다.

## 데이터 혼합은 실험으로 정한다

정제가 끝난 데이터도 웹에 많은 비율 그대로 넣지 않는다.

- **분류해서 비율을 조정한다**: Llama 3는 웹 문서가 담은 정보의 유형을 분류하는 분류기를 만들어, 웹에 과도하게 많은 범주(예: 예술과 엔터테인먼트)를 줄였다.
- **작은 모델로 혼합을 고른다**: 후보 혼합으로 작은 모델 여러 개를 학습해 큰 모델의 성능을 예측하고([[LLM-Scaling-Laws#작은 실험으로 큰 학습을 결정한다|스케일링 실험]]), 이를 반복해 고른 후보로 더 큰 모델을 학습해 주요 벤치마크로 확인했다.
- **최종 혼합**: 일반 지식 약 50%, 수학과 추론 25%, 코드 17%, 다국어 8%였다. 다른 모델과 과업에 그대로 옮길 비율이 아니라 이런 실험의 결과다.

규모의 기준점으로 The Pile(2020)은 22개 하위 데이터셋을 묶은 825 GiB 영어 말뭉치다. 학습 토큰 수는 LLaMA가 모델 크기에 따라 1.0T~1.4T, Llama 2가 2T, Llama 3 405B가 15.6T다. 2024년 공개 데이터셋 FineWeb은 15T 토큰이며, 교육적 가치로 거른 1.3T 토큰 부분집합 FineWeb-Edu로 학습한 모델이 MMLU와 ARC 같은 지식과 추론 벤치마크에서 크게 나았다고 보고됐다.

## 학습 마지막의 어닐링

어닐링은 사전학습 끝에서 학습률을 0 가까이 낮추면서 고품질 데이터의 비중을 높이는 단계다.

- **Llama 3 405B의 구성**: 마지막 40M 토큰에서 학습률을 0까지 선형으로 내리고, 품질이 매우 높은 데이터 출처를 더 많이 뽑았으며, 이 구간의 체크포인트를 평균(Polyak averaging)해 최종 사전학습 모델로 삼았다.
- **효과는 모델에 따라 다르다**: 소량의 고품질 코드와 수학 데이터로 어닐링하자 Llama 3 8B의 GSM8k와 MATH 검증 성능이 각각 24.0%, 6.4% 올랐지만 405B에서는 개선이 미미했다. 흔히 쓰는 벤치마크의 학습 세트는 어닐링 데이터에 넣지 않아 few-shot 능력과 분포 밖 일반화를 따로 평가할 수 있게 했다.
- **데이터 가치 시험**: 절반쯤 학습한 8B 모델을 40B 토큰 동안 학습률 0까지 어닐링하면서 새 데이터에 30%, 기존 혼합에 70% 가중치를 주는 방식으로 작은 도메인 데이터셋의 가치를 쟀다. 작은 데이터셋마다 스케일링 실험을 하는 것보다 효율적이다.

## 긴 문맥은 마지막에 늘린다

self-attention 연산은 시퀀스 길이의 제곱으로 늘어나므로 긴 시퀀스는 사전학습 후반에만 넣는다. Llama 3 405B는 8K에서 128K까지 여섯 단계로 문맥을 늘렸고 이 단계에 약 800B 토큰을 썼다. 단계마다 짧은 문맥 평가가 완전히 회복됐는지와 그 길이까지의 needle in a haystack 과제를 완벽히 푸는지를 보고 다음 단계로 넘어갔다. 지원 길이를 늘린 것과 긴 입력을 잘 쓰는 것은 다른 확인이다([[Long-Context-Evaluation|긴 문맥 평가]]).

## 안전 행동은 사후학습에서 따로 가르친다

표준 사전학습 목표는 다음 토큰 예측 하나이므로, 남긴 문서는 모두 이어 쓸 본보기가 된다. 그래서 위험한 문서는 넣고 감점하기보다 걸러 내고, 무엇을 거부하고 어떻게 답할지는 지시와 선호 데이터를 쓰는 [[LLM-Post-Training|사후학습]]에서 가르치는 구성이 대표적이다. Llama 3도 사전학습에서는 개인정보 사이트 필터와 학습 데이터 암기율 측정을, 사후학습에서는 위반율과 과잉 거부율을 함께 보는 안전 미세조정을 나눠 적용했다.

## 운영 체크포인트

- 필터 단계마다 남은 문서와 토큰 수, 제거 사유를 기록해 어느 단계에서 어떤 영역을 잃었는지 추적한다(적용 제안).
- 품질 필터와 혼합 비율은 같은 연산 예산으로 학습한 작은 모델과 학습에 쓰지 않은 평가 데이터로 비교한다.
- 벤치마크 문항과 학습 세트가 정제 데이터와 어닐링 데이터에 섞였는지 확인한다([[LLM-Perplexity-and-Benchmarks#학습 데이터 오염을 검사한다|오염 검사]]).

## 이해 점검

1. 줄 단위 중복 제거가 좋은 문장까지 지우는데도 쓰는 이유와, 그 판단에 필요한 근거는 무엇인가?
2. 위키백과 참조 페이지를 양성 예로 쓰는 품질 분류기는 어떤 문서를 불리하게 만들 수 있는가?
3. 어닐링 효과가 8B에서는 컸고 405B에서는 미미했다는 결과에서 무엇을 조심해야 하는가?
4. 긴 문맥 학습을 사전학습 마지막에 두는 이유와 단계별 통과 조건은 무엇인가?
