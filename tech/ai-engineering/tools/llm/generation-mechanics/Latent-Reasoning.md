# 잠재 추론: 토큰 대신 은닉 상태를 다음 입력으로 넘기는 추론

잠재 추론(latent reasoning)은 중간 추론을 토큰으로 디코딩하지 않고, 마지막 층의 은닉 상태를 다음 단계의 입력으로 되먹여 추론을 이어 가는 방식이다. 텍스트 사고 토큰(chain-of-thought, CoT)은 사람이 읽을 수 있고 그대로 도구 호출로 이어지지만, 단계마다 토큰 하나를 고르고 다시 임베딩한다. 잠재 추론은 이 과정을 건너뛰는 대신 사람이 읽기 어렵고 도구를 부르기 어렵다. 이 문서는 2026-11-02에 Coconut 논문(arXiv v4), HybridAgent 논문(arXiv 2610.18861 v1, 2026-10-13 제출), 공식 저장소와 Hugging Face 모델 카드를 대조한 기준이다. HybridAgent 논문의 저자 소속은 Stanford University, Together AI, UIUC, Meta이고 아래 HybridAgent 수치는 모두 저자 측정이다. 한 논문의 결과를 다른 모델과 과제의 일반 성질로 옮기지 않는다.

## 다음 입력으로 무엇을 넣는가

자기회귀 생성의 각 단계는 마지막 층 은닉 상태 `h_t`를 계산한 뒤 다음 위치의 입력을 정한다(HybridAgent 논문 Eq. 1).

- **텍스트 모드**: `h_t`를 어휘 투영으로 로짓으로 바꾸고 소프트맥스 분포에서 토큰 하나를 고른 뒤, 그 토큰의 임베딩을 다음 입력으로 쓴다([[LLM-Generation-Mechanics-Decoding#Logit에서 Token 선택까지|Logit에서 Token 선택까지]]). 앞 위치의 중간 층 표현은 어텐션의 KV로 계속 참조되지만, 마지막 층 은닉 상태는 토큰 선택을 거쳐서만 다음 입력에 반영된다.
- **잠재 모드**: `h_t`를 그대로 또는 변환해 다음 입력으로 쓴다. 토큰 선택과 재임베딩이 없다. Coconut(Chain of Continuous Thought)은 이 은닉 상태를 연속 사고(continuous thought)라 부르고 다음 입력 임베딩으로 바로 넣는다.
- **기대하는 이점**: Coconut 논문은 추론 문장의 토큰 대부분이 글의 연결을 위한 것이고 어려운 계획을 담은 토큰은 일부라고 본다. 연속 사고 하나는 여러 다음 단계 후보를 함께 표현할 수 있어, 한 경로를 확정해 가는 CoT와 달리 너비 우선 탐색처럼 동작할 수 있다고 분석한다.
- **학습(Coconut)**: CoT 데이터에서 출발해 단계 k마다 앞쪽 언어 추론 k단계를 연속 사고 k×c개로 바꾸는 커리큘럼을 쓴다. 커리큘럼 없이 학습한 모델은 CoT 없이 바로 답하는 기준선보다 낫지 않았다. 잠재 구간은 질문 뒤의 `<bot>`으로 열고 고정 길이로 닫았다(이진 분류기로 끝을 정하는 방식과 성능이 비슷했다). 잠재 사고가 n개면 학습 때 순전파를 n+1번 차례로 해야 해서 병렬화가 어렵다.

## 텍스트 사고 토큰과의 비교

| 항목 | 텍스트 CoT | 순수 잠재 추론(Coconut 방식) | 하이브리드(HybridAgent) |
|---|---|---|---|
| 다음 입력 | 고른 토큰의 임베딩 | 마지막 층 은닉 상태 | 텍스트 구간은 토큰 임베딩, 잠재 구간은 어댑터로 변환한 은닉 상태 |
| 잠재 단계의 출력 처리 | 해당 없음 | 디코딩 없음 | LM head와 토큰 임베딩 층 대신 어댑터 |
| 사람이 읽기 | 텍스트로 읽지만 실제 계산의 충실한 설명이라는 보장은 없다 | 직접 읽기 어렵다 | 최근접 토큰으로 근사한 의사 텍스트 |
| 도구 호출 | 텍스트로 생성 | 다중 턴 도구 호출의 기본 경로가 없다 | 텍스트 모드로 돌아와 호출 |
| 강화학습의 가능도 | 모든 생성 위치에 토큰 가능도 | 잠재 위치에는 토큰 가능도가 없다 | 텍스트 위치의 가능도만으로 계산 |

과제마다 결과가 다르다. Coconut 논문 Table 1(GPT-2)에서 Coconut은 계획 단계의 탐색이 많은 논리 과제 ProsQA에서 정확도 97.0%로 CoT 77.5%를 앞섰고 생성 토큰은 14.2개 대 49.4개였다. 초등 수학 문장제 GSM8k에서는 토큰을 8.2개 대 25.0개로 줄였지만 정확도는 34.1%로 CoT 42.9%보다 낮았다. 같은 논문은 Llama 3.2-3B와 Llama 3-8B에서 이득이 GPT-2만큼 뚜렷하지 않았고, 언어 중심 사전학습을 많이 거친 모델일수록 잠재 추론으로 옮기기 어려울 수 있다고 적는다.

## 순수 잠재 추론의 한계: 도구 호출과 가독성

- **도구를 부를 경로가 없다**: 도구 호출은 런타임이 해석하는 텍스트 출력이다([[LLM-Generation-Mechanics-Context-and-Agent#모델이 에이전트가 되는 지점|모델이 에이전트가 되는 지점]]). 연속 벡터에는 다중 턴 에이전트 추론에서 도구를 부를 기본 경로가 없다. 다음 턴에 대화를 텍스트로 다시 인코딩하는 일반 에이전트 방식으로는 앞 턴의 잠재 벡터도 되살릴 수 없다.
- **읽을 수 없으면 감독과 감사가 어렵다**: 연속 벡터는 사람이 읽을 의미를 드러내지 않아 학습 중 감독, 추론 시점의 감사와 디버깅이 어렵다(HybridAgent 논문 1절).
- **입력 공간 불일치**: 은닉 상태를 토큰 임베딩 자리에 그대로 넣으면 사전학습된 입력 공간과 표현이 어긋나 잠재 상태와 토큰 사이의 전환이 어렵다(3.1절). 14B 백본에서 정렬 없이 은닉 상태를 그대로 넣은 변형의 MATH500 정확도는 71.4%로, 2층 잔차 어댑터의 88.2%보다 낮았다(Table 6).
- **보이는 텍스트도 증거는 아니다**: CoT 설명이 실제 판단 과정을 충실히 반영한다는 보장은 없다([[LLM-Hallucination-Verification#설명은 증거가 아니다|설명은 증거가 아니다]]). 가독성은 감사의 출발점이지 정답의 증명이 아니다(이 문서의 판단).

## 하이브리드 구조: 잠재 공간에서 생각하고 텍스트로 행동한다

HybridAgent는 백본 구조를 그대로 두고 작은 어댑터 HybridLink와 특수 토큰 `<latent>`, `</latent>`를 더해, 한 생성 과정 안에서 잠재 추론과 텍스트 상호작용을 오간다. 백본은 Qwen3-Base 4B, 8B, 14B다.

1. **진입**: 텍스트 모드에서는 일반 LLM처럼 토큰을 샘플링한다. `<latent>`를 생성하면 다음 순전파부터 LM head와 토큰 임베딩 층 대신 HybridLink를 쓴다.
2. **HybridLink**: `R(h) = h + W₂σ(W₁h)`로, 선형 층 두 개 사이에 GELU를 두고 잔차 연결을 더해 마지막 층 은닉 상태를 입력 임베딩 공간으로 옮긴다. 잔차 연결이 은닉 상태의 의미를 대부분 보존하므로 어댑터는 분포 차이만 맞추면 된다는 설계다. 파라미터는 약 `2d_h²`개(d_h는 은닉 차원)이고 논문은 4B 모델에서 약 10M개로 예시한다(Qwen3-4B의 은닉 차원 2560으로 계산하면 약 13M개라 어림값이다). 세 크기 모두 같은 2층 설계를 쓴다.
3. **종료**: 어댑터 출력과 코사인 유사도가 가장 높은 어휘 임베딩이 `</latent>`이면 잠재 구간을 닫는다(Eq. 5). 구간의 길이와 빈도는 미리 정하지 않고 단계마다 정해지지만, 논문의 HybridRL 롤아웃과 평가 설정은 잠재 구간마다 최소 16단계, 최대 256단계를 강제했다(부록 H.3, Table 11, 12).
4. **도구 호출**: 텍스트 모드로 돌아와 Python 코드나 검색 질의를 텍스트로 쓰고 결과를 받아 이어 간다. 평가에서는 샌드박스 Python 해석기와 실시간 검색 엔진을 궤적당 최대 10회까지 쓰게 했다.
5. **의사 텍스트 판독**: 잠재 단계마다 어댑터 출력과 가장 가까운 토큰 임베딩을 찾으면 읽을 수 있는 의사 텍스트(pseudo-text)가 된다. 학습이 잠재 위치의 출력을 그 자리의 원래 텍스트 토큰 임베딩에 맞추므로 가능한 판독이다(아래 학습 절, Eq. 7과 Figure 8, 최종 체크포인트의 가독성은 Figure 2).
6. **작업 메모리**: 입력 문맥에서 시작해 텍스트, 잠재 사고와 도구 관찰의 KV 항목을 궤적별 KV 캐시에 계속 쌓고, 다음 턴을 그 캐시에서 이어 간다. 도구 결과도 기존 캐시에 KV를 덧붙일 뿐 앞 문맥을 다시 프리필하지 않는다.

저장소 README의 예시(14B, 섭씨 20도 공기에서 소리가 10km를 가는 데 걸리는 시간)에서 첫 잠재 구간(42단계, 가독성 0.84)의 판독문은 음속이 약 343m/s라고 떠올린 뒤 검색으로 확인하겠다는 내용이다. 이어 검색과 Python 계산(29.15초)을 거쳐 29를 답한다. 같은 판독문에는 단어가 반복되거나 깨진 부분이 있어 판독문은 근사다. 10단계짜리 잠재 구간도 보이는데, 논문 평가 설정의 최소 16단계보다 짧고 공개 코드의 기본값(최소 4단계)과는 값이 맞는다. README는 이 예시를 만든 설정을 밝히지 않는다(아래 공개 코드 항목).

## 학습: 자기 잠재 출력을 읽는 법부터 익힌다

- **데이터**: 기존 텍스트 에이전트 시연을 원자 단계로 나누고, 외부 LLM 판정(GPT-6.1-Sol, GPT-5.6-Luna)과 고정한 기반 모델로 잰 단계별 평균 토큰 엔트로피를 함께 써서 단계를 텍스트와 잠재로 나눈다. 엔트로피가 낮은 단계가 잠재 후보가 되고 도구 상호작용과 핵심 결정은 텍스트로 남긴다. 별도 LLM 비평가가 잠재 후보를 가린 궤적을 읽고 결정에 필요한 정보가 빠졌으면 그 단계를 텍스트로 되돌린다. 사람 라벨 없이 54K개 하이브리드 궤적을 만들었다(부록 E).
- **HybridSFT 활성화**: 텍스트 SFT로 두 특수 토큰을 내는 법을 익힌 뒤, 백본을 고정하고 HybridLink만 학습해 잠재 위치의 은닉 상태를 그 자리의 원래 텍스트 토큰 임베딩에 맞춘다(코사인 손실과 MSE).
- **HybridSFT 자기 조건화**: 첫 패스는 정답 하이브리드 시퀀스로 teacher forcing하고 HybridLink가 다음 패스의 잠재 입력을 만든다. 두 번째 패스는 정답 잠재 임베딩 대신 이 자기 출력을 넣고, 텍스트 위치는 교차 엔트로피, 잠재 위치는 회귀 손실로 백본과 HybridLink를 함께 학습한다. 백본이 자기 어댑터가 만든 잠재 입력으로 추론하게 해 학습과 추론의 불일치를 줄이는 단계다. 14B 백본의 MATH500은 활성화까지 73.8%, 자기 조건화 뒤 84.2%로 일반 텍스트 SFT 83.8%와 비슷해졌고, 같은 백본의 Coconut은 61.2%였다(Table 3).
- **HybridRL**: PPO와 GRPO는 모든 생성 위치에 토큰 가능도가 있다고 가정한다. 그래서 HybridLink를 고정하고 샘플링한 텍스트 위치의 가능도만으로 정책을 분해하며(Proposition 4.1), 롤아웃 때 기록한 잠재 입력을 그대로 넣어 한 번의 순전파로 가능도를 다시 계산한다. 보상은 정답, 형식, 도구 사용의 합이고 모드 사용에는 보상을 주지 않았다.
- **모드 사용의 변화**: 14B의 RL 학습 곡선(Figure 9)에서 텍스트 모드 토큰은 줄고 잠재 모드 단계는 늘어 마지막 지점에서 각각 499와 276이었고, 도구 사용 비율은 98.8%였다. 어느 단계를 잠재로 둘지는 SFT 데이터의 주석이 먼저 보여 주었으므로, 모드 선택을 처음부터 스스로 발견한 결과가 아니라 RL 단계에서 모드 보상 없이 잠재 비중이 늘어난 결과로 읽는다(이 문서의 해석).

## 측정 결과와 그 조건

이 문서가 인용하는 비교는 같은 백본과 학습 예산으로 학습한 기준선과의 비교다. 논문은 이 밖에 프런티어 LLM 에이전트(비공개와 공개 모델)와, Qwen3-14B를 백본으로 같은 도구와 예산을 준 에이전트 프레임워크도 함께 비교한다(5절, 부록 H.2). 평가는 H100에서 다섯 개 시드, temperature 0.6, top-p 0.95, top-k 20으로 했고(5절), 검색 결과 요약과 LLM 채점에는 GPT-5.6-Luna를 썼다(부록 H.3). 생성 예산은 텍스트 토큰과 잠재 단계를 함께 세어 수학과 지식 검색 과제 4,096, 에이전트 과제 24,000이었다. 자체 보고 수치를 읽는 일반 조건은 [[Model-Release-Claims|모델 발표 수치 읽기]]를 따른다.

- **정확도**: 11개 벤치마크(수학, 과학, 의학, 검색, 에이전트 과제)에서 5.1절은 같은 크기와 학습 예산의 텍스트, 잠재 기준선 대비 평균 향상을 SFT 단계 18.5%, RL 단계 10.4%로 요약한다. 초록은 같은 10.4%를 프런티어 LLM 에이전트와 에이전트 프레임워크까지 포함한 비교로 소개해 5.1절과 비교 대상의 표현이 다르며, 평균의 계산 방식은 확인하지 못했다. 차이는 과제마다 크게 다르다. MATH500은 8B에서 84.6% 대 ARPO 82.8%, 14B에서 88.2% 대 GRPO 87.4%였고(Table 2), GAIA 평균은 8B에서 43.7 대 ARPO 38.8이었다(Table 1).
- **잠재 벡터에 대한 의존(Table 5, MATH500)**: 잠재 구간을 다른 문제의 잠재 벡터로 바꾸면 8B는 84.6%에서 44.8%로, 14B는 88.2%에서 48.6%로 떨어졌다. 상대 교란 크기가 1.4인 이 교체가 크기 2.0인 가우시안 잡음(66.4%, 70.2%)보다 크게 떨어뜨리므로, 성능은 교란 크기만이 아니라 잠재 구간의 내용에 기댄다. 잠재 모드 진입을 막아 텍스트로만 추론하게 하면 80.4%, 78.8%였다. 각 잠재 벡터를 가장 가까운 토큰 임베딩으로 바꾸면(상대 거리 평균 0.2) 82.6%, 87.2%로 하락이 작았다. 이 교체는 원래 노름에 맞춰 크기를 다시 조정하므로, 학습된 잠재 입력이 토큰 임베딩과 방향이 가깝다는 뜻이며, 이 실험이 잠재 벡터가 토큰보다 정보를 얼마나 더 담는지를 재지는 않는다(이 문서의 해석).
- **생성 단계와 토큰(Figure 6)**: 같은 크기의 텍스트 에이전트 대비 텍스트 토큰과 잠재 단계를 합친 생성 단계가 4B 35%, 8B 52%, 14B 54% 줄었고, 텍스트 토큰만 보면 2.2배, 2.9배, 3.1배 적었다(그림 라벨 기준). 초록의 35.5%~54.7% 토큰 감소가 이 범위다. 잠재 단계도 백본 순전파 한 번이므로 텍스트 토큰 감소율을 연산 감소율로 읽지 않는다.
- **실행 시간(Figure 7)**: 4B, 8B, 14B를 합친 샘플당 wall-clock은 텍스트 에이전트 134초, HybridAgent 63초로 2.1배였고, 그림은 세 크기를 합친 막대에 45%~61% 단축을 표기했다(초록은 1.8~2.6배). 배치 크기와 도구 실행 시간의 포함 여부는 확인하지 못했다.
- **비용(Table 9)**: 청구액이 아니라 연산량 환산 추정이다. 텍스트와 잠재 단계를 각각 백본 순전파 한 번으로 세고 어휘 투영 또는 어댑터 비용을 더했으며, H100 시간당 $2.50와 BF16 최대 처리량의 10% 사용률(약 $0.007/PFLOP)을 가정했다. 프롬프트 프리필, 문맥 길이에 따른 어텐션, 외부 도구 실행은 뺐다. 질문당 연산은 4B 51.2에서 13.9, 8B 62.5에서 17.2, 14B 66.9에서 25.1 TFLOP이고, 100만 질문당 비용은 $359에서 $98, $439에서 $121, $470에서 $176로 3.7배, 3.6배, 2.7배 낮다. 잠재 단계마다 하는 최근접 토큰 판정(Eq. 5)의 비용이 어디에 들어갔는지, Figure 6과 같은 평가 묶음인지는 확인하지 못했으므로 두 배율을 서로 환산하지 않는다. 논문의 계산 규칙대로라면 연산 배율은 총 생성 단계 배율(Figure 6 막대 값 기준 약 1.6배, 2.1배, 2.4배)과 비슷해야 하지만 Table 9는 3.7배, 3.6배, 2.7배이고 크기별 순서도 반대다. 단계 수에서 연산량을 근사해 보면 14B는 Table 9와 대체로 맞지만 4B와 8B, 특히 텍스트 에이전트 쪽은 크게 어긋나므로, Table 9의 일부는 Figure 6의 단계 수로 설명되지 않고 그 원인은 논문에서 확인할 수 없다(이 문서의 해석). Figure 6 안에서도 14B의 라벨(−54%)과 막대 값(약 −59%)이 다르다.
- **텍스트 부분의 감사 가능성(Table 7)**: MATH500과 AIME25/26의 560문제에서 외부 관찰자에게 텍스트, 도구 호출과 결과만 보여 주고 잠재 구간은 가렸다. 텍스트 모드 토큰은 8B 302개(텍스트 에이전트 596개), 14B 284개(497개)였다. 정답 여부를 예측하는 감시자의 AUROC는 약한 감시자(GPT-4o-mini, MATH500)에서 8B 0.840 대 0.772, 14B 0.860 대 0.818, 강한 감시자(GPT-5.6-Luna, 전체 과제)에서 0.961 대 0.935, 0.989 대 0.990이었다. 결정에 필요한 단계를 텍스트로 남기도록 만든 학습 데이터(부록 E)로 학습한 모델의 결과다.

## 서빙과 운영 제약

- **엔진 지원(논문 시점)**: 논문은 기존 서빙 엔진이 다중 턴 하이브리드 생성을 지원하지 않는다고 적는다. verl과 vLLM의 인프라를 확장해 텍스트, 잠재, 도구 호출 전환과 궤적별 KV 작업 메모리를 하나의 생성 루프에서 다루고, 배치 안 시퀀스마다 상태, 어텐션 마스크와 위치를 따로 추적하며 대기 중인 도구 호출을 동시에 실행했다(5절, 부록 H.3).
- **공개 체크포인트(2026-11-02 확인)**: Hugging Face의 HybridAgent-8B-Agentic과 HybridAgent-14B-Agentic은 MIT 라이선스이고, 각각 Qwen3-8B-Base와 Qwen3-14B-Base에 HybridSFT와 HybridRL을 적용했다. HybridLink 가중치(`adapter.pt`, `adapter_config.json`)와 두 특수 토큰을 포함하지만, transformers만으로 불러오면 텍스트 전용 모델이 되고 잠재 모드와 도구를 쓰려면 저장소의 하이브리드 생성 엔진이 필요하다. 4B 체크포인트는 목록에 없다. 코드 저장소도 MIT이고 학습 데이터셋을 함께 공개했다.
- **공개 코드와 논문 설명의 차이(저장소 main 1b41ceb, 2026-10-18 기준)**: 공개 `hybridlink.py`는 어댑터 앞뒤에 LayerNorm을 두고(체크포인트 설정 `ln_res_adapter`), 공개 엔진은 백본 LM head 로짓의 argmax가 `</latent>`인지로 잠재 구간을 닫으며 코사인 최근접 토큰은 판독문 기록에만 쓴다. 실행 스크립트의 기본값은 잠재 구간 최소 4단계, 최대 200단계, 도구 호출 5회로 논문 평가 설정(16, 256, 10회)과 다르고, 의존성에 vLLM과 verl이 없는 transformers 기반 루프다. `repetition_penalty` 1.1과 검색 결과 길이 500자 같은 기본값도 논문에 없거나 논문 설정(1,000자)과 다르고, 종료 규칙은 실행 옵션으로 바꿀 수 없다. 옵션을 맞추는 것만으로는 논문의 Eq. 5 동작이 재현되지 않는다는 점을 감안해 논문 수치와 비교한다(운영 제안).
- **상태가 텍스트 기록 밖에 있다(이 문서의 판단)**: 다음 턴의 문맥이 텍스트 대화 기록이 아니라 궤적별 KV 캐시에 있으므로, 텍스트 로그를 다시 토큰화하는 것만으로는 같은 상태가 복원되지 않는다. 잠재 단계는 샘플링 없이 결정적으로 이어지므로(부록 C.1) 같은 가중치와 구간 위치로 순서대로 다시 계산하거나, 기록한 잠재 입력으로 한 번의 순전파에 KV를 다시 만들 수는 있다(4.2절). 다만 순서대로 다시 계산하면 비용이 크고, 수치 결정성이 깨지면 결과가 달라질 수 있다. 그래서 세션을 한 서빙 프로세스에 묶거나 KV와 잠재 벡터를 옮기는 설계를 검토하고, 세션이 길수록 KV 메모리가 커진다. 위 비용 추정은 이 부분을 뺐으므로 세션 단위로 다시 잰다([[LLM-Inference-Bottlenecks#에이전트 서빙은 세션 단위로 측정한다|에이전트 서빙은 세션 단위로 측정한다]]).
- **누가 잠재 구간을 읽는가**: 논문 8절은 잠재 사고가 제공자가 가진 HybridLink로만 판독된다고 보고, 제공자가 전체 판독으로 안전성을 평가하고 사용자에게는 도구 호출, 핵심 결정과 최종 답 같은 내용을 텍스트로 보여 주는 배포 방식을 제시한다. 공개 체크포인트는 어댑터 가중치를 MIT로 포함하므로 가중치를 직접 돌리는 쪽은 판독할 수 있다. 호스팅 모델의 사용자에게는 보이는 텍스트만 감사 대상이 된다는 뜻이다(이 문서의 판단). 보이지 않는 사고 토큰의 과금 구조는 [[LLM-Generation-Mechanics-Decoding#Token 단위가 만드는 운영상의 차이|사고 토큰 과금]]에서 다룬다.
- **가독성 점수는 대리 지표다**: 가독성은 잠재 입력과 가장 가까운 어휘 임베딩의 평균 코사인 유사도이고, 논문도 기하학적 대리 지표라고 부른다. 잡음 기준선은 가우시안 무작위 벡터 2,000개로 정했다(부록 F). 높은 가독성이 판독문이 실제 계산을 충실히 설명한다는 증명은 아니다(이 문서의 판단).

## 적용 판단 (운영 제안)

아래는 위 결과에서 도출한 운영 제안이며 논문이 검증한 결론이 아니다.

- **검토할 조건**: 가중치와 서빙 스택을 직접 운영하고, 긴 추론의 토큰 비용과 지연이 병목이며, 답을 기계로 채점할 수 있는 과제(논문이 평가한 수학, 지식 검색, 에이전트 검색 과제와 비슷한 업무)다.
- **보류할 조건**: 관리형 API만 쓰는 경우(직접 적용하려면 은닉 상태를 되먹이는 생성 루프와 어댑터를 직접 돌려야 한다), 표준 서빙 엔진과 상태 없는 복제 확장에 의존하는 경우, 정책상 전체 추론 과정을 사람이 읽을 수 있는 기록으로 남겨야 하는 경우다.
- **채택 전에 잴 것**: 같은 크기와 데이터로 학습한 텍스트 에이전트와 정확도, 도구 지연을 포함한 wall-clock, 세션당 최대 메모리를 함께 비교한다. 잠재 벡터 교체와 텍스트 강제 같은 개입(Table 5)을 자기 과제에 재현해 잠재 구간이 실제로 쓰이는지 본다. 결정에 필요한 단계와 도구 인자는 텍스트로 남기고 잠재 구간 기록(벡터 또는 판독문)의 보존 범위를 정한다.
- **추론 강도 설정과 구분한다**: 상용 추론 모델의 추론 강도 설정은 사고 토큰을 얼마나 생성할지를 바꾸고([[OpenAI-GPT-Generations|OpenAI GPT 세대]]의 effort), 잠재 추론은 다음 입력의 종류를 바꾸는 생성 인터페이스 변경이다. 상용 API가 잠재 추론을 제공하는지는 이 문서에서 확인하지 않았다.

## 확인 질문

1. 텍스트 모드와 잠재 모드에서 다음 위치의 입력은 각각 무엇이고, 잠재 모드에서 생략되는 계산은 무엇인가?
2. 순수 잠재 추론으로 다중 턴 도구 호출이 어려운 이유와, HybridAgent의 모드 전환과 작업 메모리는 각각 무엇을 해결하는가?
3. HybridLink에 잔차 연결을 둔 이유와, 은닉 상태를 그대로 입력에 넣을 때 생기는 문제는 무엇인가?
4. 다른 문제의 잠재 벡터로 바꾼 실험과 최근접 토큰으로 바꾼 실험은 각각 무엇을 보여 주고 무엇을 보여 주지 않는가?
5. 2.7~3.7배 비용 절감 추정에서 빠진 비용은 무엇이고, 운영에서는 무엇을 다시 재야 하는가?
6. 판독문이 읽힌다는 사실을 감사 근거로 쓸 때의 한계는 무엇인가?
