# 상호작용 영상 생성의 지연 예산

키보드로 시점을 옮기거나 물체를 끌면 그 효과를 담은 다음 장면을 바로 만들어 보여 주는 영상 모델은, 클립 전체를 만든 뒤 재생하는 생성과 지연의 정의부터 다르다. 행동에 반응해 다음 프레임을 만들어야 한다는 조건은 상호작용형 월드 모델과 같다([[World-Models|월드 모델]]). 이 문서는 2026-11-25에 FastFrames 논문(arXiv 2611.23226 v1, 2026-11-17 제출), Apple ML Research의 프로젝트 페이지와 Hugging Face 모델 카드를 대조한 기준이며, 수치는 모두 연구진이 NVIDIA B200에서 480p로 잰 값이다. 저자별 소속은 대조한 페이지에 표시되지 않았다.

## 지연은 입력에서 그 효과가 보이는 첫 프레임까지다

- **정의**: 새 입력 신호(예: 조향 명령)가 도착한 때부터 그 효과를 담은 첫 RGB 프레임을 보여 줄 때까지의 시간이다. 초당 응답 수(RPS)는 이 지연의 역수이고, 생성 단위 하나가 프레임을 몇 장 내든 응답 하나로 센다.
- **목표**: 연구진은 상호작용에 50ms 이하(20 RPS)를 목표로 둔다.
- **생성 단위가 지연을 정한다**: FastFrames와 기준 모델 Causal Forcing++(CF++)는 한 번에 잠재 프레임 하나를 만들고, 잠재 프레임 하나는 RGB 프레임 넷으로 디코딩된다. Self-Forcing처럼 잠재 프레임 셋을 묶어 만들면 한 번에 더 많은 프레임이 나와도 입력이 반영되기까지는 더 오래 걸린다. 초당 프레임 수와 입력 반영 지연은 다른 지표다(이 문서의 해석).

## 자기회귀 영상 확산의 한 단계

생성 단위마다 세 계산이 차례로 돈다.

1. **디노이징**: 확산 트랜스포머(DiT)가 잡음에서 잠재 프레임을 만든다. 두 단계로 증류한 모델은 DiT를 두 번(t=1000, t=833) 돌린다.
2. **KV 캐시 갱신**: 디노이징 중에 캐시에 들어간 key와 value는 잡음 섞인 입력에서 계산한 값이다. 기준 구현은 예측한 깨끗한 잠재 프레임을 t=0으로 넣어 DiT를 한 번 더 돌리고, 그 출력은 버린 채 캐시만 덮어쓴다. 다음 프레임은 이 캐시를 문맥으로 쓴다.
3. **디코딩**: VAE 디코더가 잠재 프레임을 RGB 프레임으로 바꾼다.

## 병목은 디노이징 밖에 있었다

B200 한 장, 480p에서 CF++(1.3B) 한 단계는 271.8ms였다. DiT 두 번이 각 41.6ms(합 83.2ms), 캐시 갱신용 DiT 한 번이 41.6ms, VAE 디코더가 147ms로 절반을 넘었다. 연구진은 확산 샘플링이 전체 시간의 30%뿐이라고 적는다. 샘플링 단계 수를 줄이는 증류만으로는 50ms에 닿지 않으므로, 단계마다 시간을 재고 가장 큰 구성부터 바꾸는 것이 출발점이다(이 문서의 해석).

## 바꾼 세 가지

- **VAE 디코더를 픽셀 디코더로**: DiT의 저해상도 토큰 격자(21×30×52) 위에서만 도는 인과적 3D ConvNeXt 형태 블록 셋과, 토큰 하나를 4×16×16 RGB 조각으로 펼치는 선형 층으로 바꿨다. 파라미터는 63.9M으로 VAE(73.3M)와 비슷하지만 디코딩은 147ms에서 1ms로 줄었다. 고정한 VAE의 출력을 재구성 손실로 따라 하게 학습한 뒤, 고정한 DINOv3 판별기로 적대적 미세조정을 했다.
- **캐시 갱신 패스를 KV 보정 네트워크로**: 공유 특징 추출기(DiT의 고정된 패치 임베딩과 가벼운 트랜스포머 블록 넷)와 층마다 둔 보정 헤드가, 깨끗한 잠재 프레임의 특징과 그 층의 잡음 섞인 key, value를 받아 잔차 보정값을 예측한다. 1.3B에서 약 2ms로 기준 구현보다 약 20배 빠르다.
- **시스템 최적화**: 기준 구현은 이미 BF16, cuDNN 어텐션, torch.compile을 썼다. 여기에 상주 KV 캐시 버퍼, 미리 계산한 RoPE 표와 조건, QKV 투영 융합, KV 시퀀스를 다섯 조각으로 나눠 병렬 계산한 뒤 softmax로 합치는 처리(13% 감소)와 CUDA graph를 더해 DiT 한 번이 1.3B에서 41.6ms에서 16.4ms, 14B에서 89.2ms에서 75.6ms가 됐다. GPU 8장에 NVLink 대칭 메모리로 문맥 병렬을 걸면 각각 5.8ms, 20.3ms다.

모델 카드의 FastFrames-S(1.3B, GPU 한 장, 전체 KV 캐시) 한 단계는 DiT 16.1ms와 16.2ms, KV 보정 2.2ms, 픽셀 디코더 0.9ms를 합친 35.4ms다(논문 표기 36ms).

## 결과와 비교 조건

| 모델 | 크기 | GPU 1장 지연 | GPU 8장 지연 | VBench 총점 |
|---|---|---|---|---|
| Causal Forcing++ | 1.3B | 272ms(3.68 RPS) | 표기 없음 | 84.11 |
| FastFrames-S | 1.3B | 36ms(27.8 RPS) | 14ms | 84.23 |
| Krea-Realtime | 14B | 1,675ms | 표기 없음 | 84.42 |
| FastFrames-L | 14B | 158ms | 45ms(22.2 RPS) | 84.44 |

- **품질 비교의 범위**: 같은 크기 기준선과의 VBench 차이는 0.1점 안팎이다. VBench는 자동 지표이고, 연구진은 화질, 프롬프트 준수, 구도와 글자 표현을 사례 영상으로 함께 비교한다. 같은 품질이라는 주장은 이 지표와 사례 비교의 범위에서 읽는다.
- **14B의 50ms는 8장 기준이다**: 14B를 GPU 한 장에서 돌리면 158ms로 목표의 세 배다.
- **출력 조건**: 모델 카드의 생성 예시는 832×480, 16fps, 81프레임이다.
- **시연**: 키보드로 카메라를 옮기는 LingBot(1.3B, 공식 구현 대비 16배 빠름)과 물체를 끌어 물리 반응을 보는 RealWonder를 같은 입력과 시간 조건의 공식 구현과 나란히 보였다.

## 한계와 적용 판단

- **해상도와 장비**: 대부분 480p이며 720p에서는 지연이 크게 늘어 추가 최적화가 필요하다고 연구진이 밝힌다. 측정은 B200이고, 기기 안 실행은 앞으로의 과제로 남겼다.
- **행동 조건 모델**: 기성 행동 조건 영상 모델은 대응하는 텍스트 조건 모델보다 느렸다. 연구진은 카메라 자세를 채널 차원으로 붙이는 식으로 처음부터 지연을 고려해 기반 모델을 학습하자고 제안한다. 긴 시간의 일관성과 물리적 개연성도 남은 과제다.
- **라이선스**: 가중치는 Apple의 연구용 라이선스로 표시되고, 함께 배포한 LingBot-World v2의 코드와 가중치는 CC BY-NC-SA 4.0이라 상업적 이용이 제한된다(2026-11-25 모델 카드 확인).

적용하면(운영 제안) 상호작용 제품의 지연은 위 정의대로 입력에서 첫 프레임까지 재고, 모델 밖의 입력 전달, 영상 인코딩과 네트워크 전송, 화면 표시 시간을 따로 더한다. 단계별 시간을 디노이징, 캐시 갱신, 디코딩으로 나눠 잰 뒤 줄일 곳을 고르며, 품질 비교는 같은 해상도와 GPU 수에서 한다. 실시간 음성의 첫 재생 지연처럼 첫 응답이 체감 품질을 정하는 구조는 [[Realtime-Voice-Architecture|실시간 음성 에이전트]]와 같다.

## 확인 질문

1. 한 번에 RGB 프레임 열두 장을 만드는 모델과 네 장을 만드는 모델이 같은 초당 프레임 수를 내면, 입력 반영 지연은 어느 쪽이 길고 왜 그런가?
2. 기준 구현이 디노이징 뒤에 DiT를 한 번 더 돌리는 이유는 무엇이고, 이를 작은 네트워크로 바꾸면 무엇을 잃을 위험이 있는가?
3. 확산 단계 수를 절반으로 줄여도 50ms 목표에 닿지 못하는 이유를 기준 구현의 시간 분해로 설명해 보라.
4. 14B 모델의 45ms를 자기 서비스의 지연 예산에 옮길 때 붙여야 할 조건은 무엇인가?
