# 자기 일관성과 샘플 투표

같은 질문에 모델 답을 여러 번 뽑은 뒤 가장 많이 겹치는 답을 고르는 추론 시점 기법이다. 모델 가중치를 바꾸지 않고 호출 수를 늘려 정확도를 사는 방식이라, 단일 호출 비용이 낮은 모델을 여러 번 부르는 설계에서 검토할 만하다. 이 문서는 2026-11-09에 아래 세 논문의 초록과 본문을 대조한 기준이다.

## 동작 방식

| 기법 | 후보 생성 | 고르는 방법 | 적용 조건 |
|---|---|---|---|
| Self-Consistency | 탐욕 디코딩 하나 대신 다양한 추론 경로를 샘플링 | 각 경로의 최종 답을 파싱해 다수결 | 최종 답이 고정된 답 집합에 속하는 문제 |
| Universal Self-Consistency(USC) | 여러 응답을 샘플링 | 응답들을 이어 붙여 LLM에게 가장 일관된 응답을 고르게 함 | 정확 일치 투표가 안 되는 자유 형식 출력 |
| Sampling and Voting(Agent Forest) | N개를 샘플링 | 다른 샘플과의 누적 유사도가 가장 높은 것 선택(닫힌 답은 빈도, 코드는 BLEU) | 닫힌 답과 코드 생성 |

- Self-Consistency는 추론 경로를 주변화(marginalize)해 최종 답만 센다. 경로가 달라도 같은 답에 도달하면 같은 표로 묶이므로, 답을 비교 가능한 형태로 추출하는 파서가 설계의 일부가 된다.
- USC는 그 추출 단계가 자유 형식 답에는 맞지 않는다는 한계에서 출발한다. 고르는 쪽도 LLM이라, 투표가 규칙이 아니라 또 한 번의 모델 판단이 된다.

## 보고된 효과와 조건

- **Self-Consistency(2022)**: 초록은 GSM8K +17.9%, SVAMP +11.0%, AQuA +12.2%, StrategyQA +6.4%, ARC-challenge +3.9%를 보고한다. 이 수치는 본문 표에서 code-davinci-002 행과 맞는다(예: AQuA 39.8에서 52.0). 주요 결과는 실행마다 40개 출력을 독립 샘플링해 10회 평균한 값이며, 본문은 경로를 많이(예: 40개) 뽑을수록 성능이 꾸준히 좋아졌다고 적는다. 한편 같은 논문은 계산 비용 증가를 한계로 들고, 5개나 10개 정도의 적은 경로로 이득 대부분을 얻으며 성능이 대개 빠르게 포화한다고 적는다. 또 최종 답과 일치한 샘플 비율이 정확도와 높은 상관을 보여(GSM8K), 일치율을 모델의 불확실성 추정으로 쓸 수 있다고 제안한다.
- **USC(2023)**: 초기 샘플은 8개다. PaLM 2-L GSM8K에서 탐욕 85.7, 다수결 90.4, USC 90.2로 다수결과 비슷하고, 다수결을 쓸 수 없는 요약(GovReport ROUGE-1 38.8에서 40.2)과 TruthfulQA GPT-judge(PaLM 2-L, 62.1에서 67.7)에서도 이득을 보고한다. 샘플 수를 늘리면 TruthfulQA와 BIRD-SQL은 계속 좋아졌지만 SummScreen은 5개 이후 개선이 없었고 GSM8K는 16개에서 정확도가 내려갔다. 저자들은 8개를 적정점으로 제안한다.
- **Sampling and Voting(2024)**: 초록은 성능이 인스턴스화한 에이전트(샘플) 수에 따라 늘고, 개선 폭이 과제 난이도와 상관된다고 적는다. 본문은 어려운 과제와 약한 모델에서 이득이 더 크다고 한다. 합성 과제에서 난이도를 세 축으로 나눠 보면, 고유 난이도가 오를수록 이득이 늘다가 줄었고, 추론 단계 수가 늘수록 이득이 커졌으며, 정답의 사전 확률이 높을수록 성능이 올랐다. 강화한 Llama2-13B가 GSM8K 59%로 단일 질의 Llama2-70B의 54%를 넘었다고 보고하지만, 같은 70B에 40개 앙상블을 적용하면 74%였다.

마지막 비교는 작은 모델을 여러 번 부르면 큰 모델 단일 호출을 넘을 수 있다는 근거이지, 큰 모델이 필요 없다는 근거는 아니다. GSM8K의 이 설정에서는 70B에도 40개 앙상블을 쓰면 다시 15점 앞선다(이 문서의 해석이며 다른 과제와 모델 쌍으로 일반화하지 않는다).

## 한계

- **답 형식**: Self-Consistency 논문은 최종 답이 고정된 답 집합에서 나오는 문제에만 적용할 수 있다고 적는다. 자유 형식 출력은 USC나 유사도 기반 선택처럼 다른 집계가 필요하다.
- **일관성은 정답이 아니다**: USC 논문은 가장 일관된 응답이 반드시 최선은 아니라고 밝힌다. 모든 샘플이 같은 오류를 공유하면 다수결은 그 오류를 확정한다.
- **비용과 문맥**: 호출 수만큼 비용과 지연이 늘어난다. USC는 선택을 위한 추가 LLM 호출이 필요하고, 다룰 수 있는 샘플 수가 선택 모델의 문맥 길이로 제한된다. 신뢰도 추정도 아직 제공하지 않는다고 적는다.
- **평가 조건**: 위 수치는 공개 벤치마크와 논문 당시 모델 기준이다. 사내 코드 리뷰처럼 정답을 자동 판정하기 어려운 업무로 옮길 때는 이 수치가 그대로 재현된다고 가정하지 않는다.

## 설계 체크포인트

다음은 논문 결과와 일반 설계 원칙에서 끌어낸 적용 제안이다(이 문서의 판단).

- 답을 비교 가능한 형태(선택지, 숫자, 판정 라벨)로 추출할 수 있으면 다수결을, 아니면 LLM 선택이나 유사도 선택을 고른다. 선택 모델을 따로 두면 그 모델의 판단 품질도 평가 대상에 넣는다.
- 샘플 수는 과제마다 포화와 역효과가 다르므로 작은 수에서 시작해 골든 셋으로 정확도 대비 비용 곡선을 잰다([[Eval-Golden-Set-and-Deploy-Gates|골든 셋과 배포 게이트]]).
- Self-Consistency 논문은 일치율을 불확실성 추정으로 쓸 수 있다고 제안한다(USC는 신뢰도 추정을 아직 제공하지 않는다). 일치율이 낮은 답을 사람 검토로 넘기는 문턱은 운영상 제안이며, 자기 골든 셋에서 정확도와 맞춰 보정한다.
- 투표 구조를 모델과 분리해 두면 같은 파이프라인에 더 나은 모델을 끼워 넣어 재평가하기 쉽다. 모델 교체 뒤에도 같은 평가 세트로 다시 재야 하며, 교체만으로 개선을 가정하지 않는다([[Eval-Model-Drift-Monitoring|모델 드리프트 모니터링]]).
- 정답을 테스트 같은 프로그램으로 판정할 수 있으면 다수결 대신 그 판정으로 고르는 편이 낫다는 것은 이 문서의 설계 판단이며, 세 논문이 직접 보인 결과는 아니다. USC 논문의 코드 비교 기준(SC-Exec)은 실행 결과가 같은 프로그램끼리 묶는 투표이고, USC는 코드를 실행하지 않고도 그 성능에 맞먹었다(BIRD-SQL 45.6 대 45.5). 평가기를 모델 밖에 두는 구성은 [[Evaluator-Guided-Program-Search|평가기 주도 프로그램 탐색]]을 참고한다.
