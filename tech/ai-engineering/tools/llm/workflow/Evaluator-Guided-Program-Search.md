# 평가기 주도 프로그램 탐색

LLM이 후보 프로그램을 제안하고, 모델 밖의 평가기가 정확성을 검사하고 비용을 점수로 매기며, 그 점수와 피드백을 다음 제안의 입력으로 돌려 개선을 반복하는 구성이다. 정답을 자동으로 판정할 수 있고 개선 정도를 숫자로 잴 수 있는 문제에 맞는다. 이 문서는 2026-10-27에 Google DeepMind의 AlphaEvolve 발표와 기술 보고서, Anthropic의 양자 회로 설계 연구 발표와 논문을 대조한 기준이고, 칩 설계 사례는 2026-11-21에 OpenAI 발표로, FPGA 추론 가속기 사례는 2026-11-25에 작성자의 실험 기록으로 대조했다.

## 구성 요소

| 구성 | 역할 | 설계 질문 |
|---|---|---|
| 명세 | 풀 문제와 허용 연산 | 자연어 명세를 평가기가 검사할 수 있는 계약으로 옮겼는가 |
| 제안기(LLM) | 새 후보와 프로그램 수정안 | 부모 후보, 평가 피드백, 다른 후보 표본과 메모 가운데 무엇을 넣는가 |
| 평가기 | 정확성 검사와 비용 점수 | 모델이 아닌 프로그램인가, 어디까지 표본으로만 검사하는가 |
| 보관소 | 후보와 점수 저장, 다음 부모 선택 | 탐색과 활용의 균형을 어떻게 잡는가 |

- AlphaEvolve(2025-05 발표)는 Gemini 모델의 제안을 답을 검증하는 자동 평가기와 짝지운다. 제안한 프로그램을 검증, 실행, 채점하고, 진화적 틀로 유망한 후보를 다음 프롬프트에 쓴다. 발표는 적용 대상을 해법을 알고리즘으로 기술하고 자동 검증할 수 있는 문제로 적는다.
- 평가기를 모델 밖 프로그램으로 두면 제안한 모델이 스스로 성공을 선언하지 못한다. 탐색기와 검사기를 나누는 원칙은 [[Energy-Based-Reasoning#낮은 에너지와 정답 증명은 다르다|에너지 기반 추론의 제약 검사]]와 같다.

## 점수는 목적이 아니라 대리 지표다

- 양자 회로 연구의 평가기는 Toffoli 게이트 수 T와 최대 큐비트 수 Q의 곱(T×Q)을 비용으로 썼다. 실행 시간의 대리 지표이며, 논문은 다른 계산 가능한 목적함수로도 탐색할 수 있다고 적는다. 목적함수를 바꾸면 최선의 회로도 바뀐다.
- 논문은 목적함수, 회로 인터페이스와 입력 분포처럼 과제를 정의하는 선택이 프레임워크의 한계라고 밝힌다. 사람이 정한 과제 정의 밖의 품질은 이 점수가 보장하지 않는다.
- 평가기는 지름길을 막아야 한다. 이 연구의 평가기는 출력, 바뀌면 안 되는 입력, 보조 큐비트(ancilla)의 복귀와 위상까지 검사하며, 더러워진 보조 큐비트를 리셋하거나 버리는 방식을 되돌리기(uncompute)의 대체로 인정하지 않는다.

## 정확성 검사의 범위를 기록한다

- **기저 상태 추적**: 허용 연산이 계산 기저 상태를 기저 상태로 보내므로, 시뮬레이터는 2^n개의 진폭 대신 비트열과 위상을 추적한다.
- **표본 검사와 실패율 경계**: 입력 공간이 크면 모든 경로를 검사하지 않고 표본을 뽑는다. 표본 검사는 드문 실패를 놓칠 수 있어 통계적 경계를 붙인다. DQI 디코더는 10만 회 시험에서 탐지된 부호 오류가 100회 이하인 구현만 받아들이고, 한 번의 시험이 실패를 적어도 2분의 1 확률로 탐지한다는 조건 아래 97.5% 신뢰수준에서 입력 분포 전체의 실패 확률 상한 2.434×10⁻³을 얻는다. 이 경계는 시험을 뽑기 전에 고정한 후보에만 적용된다. 논문은 모든 입력과 측정 기록의 쌍이 통과할 때만 선형성으로 양자적 정확성을 보장한다고 적는다.
- **별도 확인**: 발표 글은 디코더를 4억 300만 회 표본 디코딩으로 시험해, 저장해 둔 대체 값이 필요한 빈도를 쟀고 약 1만 회에 1회 실패해 과제가 허용한 오류율 안이었다고 적는다. 가역 divsteps 설계는 대규모 수치 시뮬레이션과 Lean 형식화로 확인했다.
- **하드웨어 실행 여부**: 결과는 평가기 점수와 미래 기계를 위한 자원 추정이다. 실제 양자 하드웨어에서 돌린 결과는 발표에 없다.

## 사례: Claude Mythos 5의 양자 회로 설계

2026-10-16 Anthropic 발표와 같은 시기 arXiv 논문(2610.22367) 기준이다.

- **과제와 결과**: 수치 계산, 화학, 최적화, 양자 시뮬레이션, 정수론에 걸친 8개 과제에서 Claude Mythos 5가 OpenEvolve 위에서 구조와 프로그램 수정을 제안했다. 논문은 7개 과제에서 발견한 회로가 과제별 기준선보다 Toffoli 수와 큐비트 수가 모두 적다고 보고한다(Table 1). 기준선에 자유 매개변수가 있으면 T×Q가 가장 작아지게 맞췄고, Hermitian DQI 디코더는 기존 가역 구현이 없어 단순 가역 구현을 기준선으로 썼다. 여덟 번째 과제인 소수 체 모듈러 역원에서는 divsteps를 가역 회로에서 쓸 수 있게 한 새 구조를 얻었고, 이 과제의 비용은 그 역원을 쓰는 타원곡선 점 덧셈 전체 회로로 잰다.
- **탐색 구조**: LLM이 서로 다른 구조를 여럿 제안해 각각을 가족으로 병렬 발전시키고 주기적으로 선두 프로그램을 공유한다. MAP-Elites로 (T, Q) 평면의 칸마다 T×Q가 가장 낮은 회로를 남긴다. 반복마다 부모 프로그램, 평가 피드백, 보관소 표본과 메모로 새 에이전트 세션을 시작하며, 세션 안에서 시험 실행과 서브에이전트를 쓸 수 있다.
- **대표 수치와 비교 기준**: 점 덧셈은 기존 설계마다 Toffoli와 큐비트를 다르게 맞바꿔, 논문이 단일 기준선과 개선 배율을 내지 않는다(Table S3). 발견한 divstep 회로(Toffoli 4.0×10⁶, 큐비트 935)는 큐비트가 가장 적은 기존 설계(Luo 외, 7.0×10⁷, 838)보다 큐비트를 12% 더 쓰고 Toffoli를 약 17분의 1로 줄였지만, Toffoli가 가장 적은 기존 설계(Schrottenloher, 1.9×10⁶, 1,446)보다는 Toffoli가 약 2배여서 T×Q도 크다(3.7×10⁹ 대 2.7×10⁹). 발표 글 본문은 앞의 비교를 들고 새 설계들이 큐비트 수와 실행 시간의 Pareto 경계를 넓혔다고 설명하며, 이 설계가 53시간 실행 한 번에서 나왔다고 적는다. 어느 기존 설계를 기준으로 삼느냐에 따라 같은 회로가 개선으로도 후퇴로도 읽힌다(이 문서의 판단). DQI에 쓰는 Reed-Solomon 디코더는 Google의 기존 구성(2025)보다 게이트를 12분의 1로 줄였다(논문 표의 T×Q 비 12, Toffoli 5.1×10⁶에서 4.4×10⁵). 모두 연구진이 보고한 자원 추정이다.
- **사람의 역할과 관찰된 약점**: 사람은 점 덧셈 과제의 한 문단 명세를 쓰고 가끔 탐색을 넓히라고 지시했다. 발표는 모델이 개선을 지나치게 의심하고 잘 알려진 접근을 선호하는 경향이 있어, 여러 병렬 접근을 요구하고 가끔 탐색을 넓히도록 유도했다고 적는다.
- **재현 범위**: 2026-10-27 공식 모델 페이지 기준 Mythos 5는 Cyber Verification Program 같은 Anthropic 검증 프로그램을 통과한 조직에만 제공되고(상태 Active), 현재 Mythos 모델은 2026-09-01 출시된 Mythos 5.1이다([[Claude-Fable-5-Mythos-5|Claude Fable 5, Mythos 5]]). 지금 재현하면 연구와 다른 판을 고르기 쉬우므로 쓴 모델 ID를 결과와 함께 기록한다(적용 제안). 같은 구성을 다른 모델로 돌린 결과는 이 연구가 보여 주지 않는다. 가족 수, 반복 횟수와 연산 예산은 논문 본문과 부록, 발표 글에서 찾지 못했다.

## 사례: 칩 설계의 RTL 재작성과 RISC-V 평가

2026-11-18 OpenAI 발표 기준이다. 결과는 모두 OpenAI의 보고이며 AMD의 검증도 OpenAI가 전한 내용이다.

- **구성**: 모델이 회로를 기술하는 SystemVerilog RTL을 다시 쓰고, Synopsys 도구로 각 재작성이 블록의 동작을 보존하는지 검증하고 전력, 성능, 면적(PPA)의 절충을 평가했다. 제안기와 모델 밖 평가기를 나눈 위 구성이 EDA 도구 위에서 돈 형태다.
- **보고된 결과**: OpenAI의 첫 자체 추론 칩 Jalapeño에는 2025년 초부터 o3-mini를 썼고, 모델이 제안한 변경으로 표준 셀 면적이 벡터 유닛에서 약 13%, 행렬 유닛에서 약 10% 줄었다고 팀이 추산하며 이 최적화가 실리콘 초기 구동(bring-up)에서 검증됐다고 적는다. 행렬 유닛의 한 곱셈기 재설계는 합성 기준 셀 면적을 약 15% 줄이면서 지연을 2클록에서 1클록으로 줄였고, 한 가산기 재설계는 2클록 지연을 유지한 채 면적을 약 15% 줄였다. AMD와는 주력 GPU IP에서 고도로 최적화된 기준선 대비 최대 14%의 PPA 개선을 냈고 일부는 최근 제조로 보낸 설계에 들어갔으며, 차기 주력 CPU의 주요 블록에서는 한 자릿수 %의 개선을 AMD가 검증했다고 적는다. 약 1년 분량의 진전을 5개월 안에 냈다는 표현은 OpenAI의 평가다.
- **세대 비교용 평가 설계**: 공개 32비트 RISC-V 코어 두 개(FPGA용 소형 PicoRV32, OpenTitan 보안 칩의 Ibex)로, 기존 RTL을 고쳐 처리량을 올리는 과제와 서면 요구사항과 연결 템플릿에서 코어를 새로 설계하는 과제를 냈다. 시뮬레이션 검사에 실패하거나 원래 코어 면적의 16배를 넘으면 0점이고, 통과하면 모델에게 숨긴 워크로드의 클록당 명령 수 기하평균에 Yosys로 추정한 최대 클록을 곱해 초당 명령 수를 추정한 뒤 같은 제약에서 관찰한 최고 처리량을 1.0으로 둔다. 평균에는 0점 시도도 넣었고, 두 과제, 두 코어, 모든 토큰 예산을 합쳐 9,881회를 채점했다.
- **결과와 해석의 경계**: 실행당 약 112,000토큰의 비교 예산에서 GPT-6.2 Astra가 두 코어 모두 평균 점수가 가장 높았고, 기존 PicoRV32를 고치는 과제에서는 GPT-6 Astra의 약 2배였다. 다섯 모델 모두 요구사항에서 새로 설계할 때 점수가 더 높았는데, OpenAI는 요구사항 과제가 성능 카운터나 추가 명령처럼 원래 코어에 있던 기능을 뺄 여지를 주고 그 기능이 시험 워크로드의 처리량에 거의 기여하지 않아 점수 우위의 일부를 설명할 수 있다고 적는다. 필요한 기능을 요구하고 면적 한도를 좁히고 물리 합성 뒤 타이밍을 검사해야 실제 칩 설계에 가까워진다고도 적는다.

평가기가 확인하지 않는 기능은 최적화 과정에서 빠질 수 있으므로 위 [[#점수는 목적이 아니라 대리 지표다|대리 지표]] 절의 사례로 읽는다(이 문서의 판단). 시뮬레이션 통과, 합성 결과, 실리콘 검증과 양산 반영은 서로 다른 단계라 결과를 인용할 때 어느 단계의 근거인지 붙인다([[AI-Scientific-Discovery-Loops#반도체 설계와 제조에 적용하는 조건|반도체 설계와 제조]]). OpenAI는 Synopsys와 함께 EDA 도구를 전문 설계자처럼 쓰도록 GPT-Synopsys를 학습한다고 밝혔다.

## 사례: 비트 일치를 관문으로 둔 FPGA 추론 가속기

2026-11-20 게시된 개인 실험 기록을 2026-11-25 대조한 기준이다. 수치는 모두 작성자 보고이며 외부 재현은 없다. 작성자는 FPGA와 Verilog를 다뤄 본 적이 없었고 본격적인 C++도 약 10년 만이었다.

- **구성**: Conductor에서 며칠간 돈 클라우드 코딩 에이전트가 실험을 골라 돌리며 C++와 Verilog로 삼진 가중치 LLM(DeepGrove의 구조를 따른 24층, 문맥 8,192토큰. 모델명과 파라미터 수는 기록에 없다)의 추론을 AWS F2(f2.6xlarge, 시간당 $1.98, FPGA HBM 16GB) 위에 구현했다. 사람은 주로 주기적으로 독려하고 가끔 조언(예: 추측 디코딩)을 보탰다. 수백 번의 실험에 걸쳐 약 300만 줄의 코드를 쓰고 출력 파일 약 3,000만 줄을 파싱했으며 Claude와 OpenAI 토큰에 약 $10,000를 썼다. 작성자는 Opus와 Astra가 이 작업에서 바꿔 써도 될 만큼 비슷했다고 적는다.
- **평가기는 비트 일치다**: 정답 조건은 고정한 CPU 기준 구현과 출력이 비트 단위로 같은 것이고(8개 대화 × 3턴의 24턴 전부), 점수는 그 조건에서의 초당 토큰이다. 낮은 정밀도, 정규화 지연, 8비트 KV 캐시, 온라인 softmax처럼 출력 비트를 바꾸는 지름길은 모두 기각했다. 검증은 블록 단위 테스트, 실제 체크포인트의 한 층, 24층 전체의 토큰 단위 비교, KV 캐시 바이트 계산 순으로 올렸다. 평가기가 막은 지름길은 탐색도 쓸 수 없으므로, 기능을 빠뜨릴 수 있었던 위 RISC-V 평가와 반대편의 사례다(이 문서의 해석).
- **개선은 작은 단계의 누적이었다**: 첫 비트 일치 구현의 6.43토큰/초에서 14단계를 거쳐 213.13토큰/초(약 33배)가 됐고, 단계마다 1.03~1.74배였다. 메모리 접근(버스트 어텐션, 메모리 포트, 가중치 패킹), 병렬화(병렬 라우터, 병렬 헤드 로더), 파이프라인(새 파이프라인, 어텐션 중첩)과 추측 디코딩(프롬프트 조회 초안, 호스트 CPU의 축소 초안 모델, 재추측)이 섞여 있다. 초안 방식의 토큰은 FPGA가 모두 검증해 비트 일치를 유지했다.
- **물리 장비는 따로 검증한다**: 231.25MHz 설정이 장시간 시험(soak test)에서 무작위 오류를 내 한 단계 낮은 225/425MHz 설정으로 내렸다. 기능 검증 통과와 장시간 실행의 안정성은 다른 관문이다.
- **사람의 몫과 잃은 시간**: 작성자는 가장 큰 기여로 몇 시간짜리 시뮬레이션을 피하고 실제 장비 결과를 빨리 받으라는 절차 조언을 꼽고, 사람은 빠른 반복과 정답의 정의를, 에이전트는 탐색을 맡는다고 정리한다. 반대로 긴 RTL 시뮬레이션을 건너뛴 탓에 두 번의 멈춤이 다음 날 장비에서야 드러났고 큰 통합 작업에서 38시간을 잃었다.
- **비교의 한계**: 같은 출력을 내는 CPU 구현(m8a.8xlarge 32스레드, 129.5토큰/초)보다 1.65배 빨랐지만, CPU와 GPU 쪽에는 같은 최적화 루프를 돌리지 않아 일대일 비교가 아니라고 작성자가 밝힌다. GPU 결과(35.7, 166.3토큰/초)는 비트 일치가 아니었다. 속도는 문맥이 길수록 떨어져 마지막 설계가 짧은 문맥 233토큰/초, 6K~8K 문맥 76토큰/초였고, 작성자는 8K 문맥 FPGA 구성을 실제 서비스용으로 권하지 않는다.

- 실행 시간과 비용 예산, 사람이 개입할 시점과 최종 검토 방법을 정했는가
