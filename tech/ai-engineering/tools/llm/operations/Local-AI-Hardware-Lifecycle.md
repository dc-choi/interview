# 로컬 AI 장비의 수명: 용량당 가격보다 쓸 수 있는 기간

로컬 추론 장비를 고를 때 메모리 용량당 가격만 비교하면 장비가 언제까지 쓸모 있는지가 빠진다. 장비는 고장 나기 전에 먼저 소프트웨어 지원이 끊기고, 쓰려던 모델이 커져 메모리에 들어가지 않게 된다. 그래서 가격을 예상 사용 기간으로 나눠 비교한다. 이 문서의 지원 범위와 API 가격은 2026-11-17 공식 문서 기준이고, 장비 가격과 속도 수치는 한 제작자가 2026-09 말~10-18에 모은 값으로 공식 출처와 대조하지 못했다.

## 세 가지 기한

| 기한 | 묻는 것 | 확인할 자료 |
|---|---|---|
| 소프트웨어 | 쓰는 런타임과 추론 엔진이 이 칩을 언제까지 지원하는가 | 런타임 릴리스 노트, 호환성 표, 엔진의 배포 대상 |
| 모델 | 쓰려는 모델이 이 메모리에 언제까지 들어가는가 | 모델의 가중치 크기와 양자화별 필요 메모리 |
| 비용 | 되팔 때의 값과 매달의 전력비는 얼마인가 | 중고 거래가, 소비 전력과 전기 요금 |

판매 글의 가격은 이 가운데 비용의 일부만 알려 준다.

## 소프트웨어 지원이 먼저 끊긴다

- **CUDA**: CUDA 13.0 릴리스 노트는 cuFFT에서 Maxwell, Pascal과 Volta GPU 지원을 제거했고 cuSPARSE에서 Turing 이전 아키텍처 지원을 중단했다고 적는다. Tesla V100은 Volta 세대다.
- **vLLM**: v0.20.0에서 PyPI 기본 wheel과 기본 이미지가 CUDA 13.0으로 바뀌었고, v0.33 릴리스 노트(rc3 태그 기준)는 CUDA 12.9 wheel과 이미지를 더 배포하지 않는다고 적는다. 정식판 v0.34.0(2026-11-16)의 설치 표에도 CUDA 13.0 항목만 있다. 구형 GPU가 한동안 쓸 수 있던 우회 경로가 배포물에서 사라진 것이다. 릴리스 노트에 Volta라는 이름은 나오지 않으며, 실제 실행 가능 여부는 재현하지 않았다.
- **ROCm**: AMD의 Linux 시스템 요구 사항 표는 Instinct MI50(gfx906)을 지원하지 않는 것으로 표시한다. 이런 카드는 커뮤니티 포크에 의존하게 된다(주장).
- 그 밖에 한 데스크톱 추론 앱의 CUDA 런타임이 V100을 인식하지 못한다는 것, Flash Attention 2가 처음부터 지원하지 않았다는 것, 다른 구형 카드의 실질 수명 전망은 대조하지 않았다.

구형 카드가 오늘 동작한다는 것과 앞으로 나올 엔진이 그 카드를 대상으로 삼는다는 것은 다르다. 중고 장비를 살 때는 그 카드가 돌릴 수 있는 가장 최신의 런타임 버전을 판매자가 아니라 공식 호환성 표에서 확인한다.

## 표기 용량과 쓸 수 있는 용량

표기된 메모리 전체를 모델에 쓸 수 없다.

- **macOS**: GPU가 쓸 수 있는 메모리에 기본 상한이 있다. MLX LM README는 모델이 RAM에 들어가는데도 느리면 `sudo sysctl iogpu.wired_limit_mb=N`으로 상한을 올리라고 안내하며, N은 모델 크기(MB)보다 크고 장비의 메모리보다 작게 잡는다. 기본 상한이 전체의 4분의 3쯤이라는 것과 재시동하면 설정이 풀린다는 것은 대조하지 않았다.
- **통합 메모리 장비**: NVIDIA DGX Spark는 사양상 최대 128GB 통합 메모리다. 256GB급을 맞추려면 두 대를 묶어야 하고, 묶은 구성의 분산 실행 조건은 [[Local-Inference-Deployment-Cases#MLX 분산 추론: 한 모델을 여러 Mac에 나눈다|분산 추론 사례]]와 [[LLM-Inference-Serving-Engines|추론 서빙 엔진]]의 텐서 병렬 사례를 본다.
- **여유분**: 운영체제와 대화 문맥이 차지하는 몫을 빼야 한다. 256GB 장비에서 모델에 220~235GB를 잡으라는 값과 미니 PC의 운영체제별 GPU 메모리 상한 수치는 제작자의 경험치다.

Apple의 Mac Studio 사양 페이지는 M5 Ultra의 메모리 대역폭을 1.2TB/s로 적고, Memory 절에서는 256GB와 512GB를 36코어 CPU와 80코어 GPU의 M5 Ultra 조건으로 적는다. 같은 페이지의 Configure to Order 절은 512GB에만 그 조건을 붙이고 256GB에는 붙이지 않아 두 절의 표기가 다르므로 구성 화면에서 확인한다. 가격은 확인하지 않았다.

## 모델이 커지면 같은 장비의 급이 내려간다

DeepSeek의 가격 문서는 `deepseek-flash`의 모델 버전을 DeepSeek-V4.1-Flash-1017로 적고, 이전 이름 `deepseek-v4-flash`의 모델은 종료돼 요청이 새 모델로 처리된다고 안내한다. vLLM은 v0.30.0(2026-09-22)에서 DeepSeek-V4.1-Flash 지원을 추가했다.

이전 판이 256GB 장비에 여유 있게 들어갔고 새 판은 공식 가중치가 약 510GB라 2비트 수준으로 줄여야 들어간다는 수치, 장비별 초당 토큰 수는 대조하지 못했다. 확인된 범위에서 남는 교훈은 장비가 바뀌지 않아도 대상 모델의 교체로 쓸 수 있는 품질이 내려갈 수 있다는 것이다. 양자화 크기와 평가를 나눠 읽는 기준은 [[Local-Inference-Deployment-Cases#Saluki: 양자화 크기와 도구 호출 평가를 나누어 읽는다|양자화 크기와 평가]]에 있다.

## 사용 연수로 나눈 가격

계산식은 `(구매가 - 예상 재판매가 + 사용 기간의 전력비) / 쓸 수 있는 연수`다. 연수는 가정이므로 가정을 바꿔 가며 본다.

제작자의 예시는 다음과 같다. 수치는 모두 대조하지 못한 값이고, 두 예시는 재판매가를 빼기 전 값이다.

- V100 8장의 중고 서버(약 5,900달러)는 1GB당 약 23달러로 새 GPU(1GB당 150~370달러)보다 훨씬 싸지만, 쓸 수 있는 기간을 2년으로 가정하면 연 3,000달러쯤이고, 3kW 장비(GPU 약 2.5kW)를 하루 8시간 쓰는 미국 기준 전기 요금 연 약 1,900달러를 더하면 5,000달러에 가까워진다.
- 256GB Mac Studio는 5년을 가정하면 전력 포함 연 2,000달러쯤이다(재판매 전). 가격은 256GB를 64코어 GPU 구성에서 고를 수 있으면 9,499달러, 아니면 10,799달러이고 자료마다 달라 구성 화면에서 확인하라는 것이 제작자의 단서다. 이전 세대 고용량 Mac의 중고가가 새 제품 가격에 가깝게 유지됐다는 관찰은 되팔면 연 비용이 더 낮아진다는 근거로 제시됐다.
- 새 GPU 여러 장 구성은 소프트웨어 지원이 가장 길지만 공급 부족 시기의 가격으로 사게 된다.

장비 유형별 성격도 제작자의 정리다. 통합 메모리 Mac은 출력이 빠르고 긴 프롬프트의 처리가 느리다. CUDA 장비는 새 도구가 가장 먼저 지원하고 긴 프롬프트를 다시 읽는 코딩 에이전트 작업에 유리하다. vLLM으로 모델을 여러 GPU에 고르게 나누려면 2, 4, 8장처럼 맞추라는 조언도 있으나 대조하지 않았다. 긴 프롬프트 처리와 출력 속도를 나눠 보는 이유는 [[LLM-Inference-Bottlenecks|LLM 추론 병목]]에 있다.

## 사기, 빌리기와 API

DeepSeek 가격 문서 기준으로 `deepseek-flash`의 출력은 100만 토큰당 비혼잡 시간 0.6달러, 혼잡 시간 1.2달러다. 비혼잡 요금은 혼잡 요금의 절반이다.

같은 모델을 9,499달러 장비에서 초당 21토큰으로 3년 동안 쉬지 않고 돌린다고 가정하면 생성량은 약 19억 9천만 토큰이고, 장비 값만으로 100만 토큰당 약 4.8달러다. 장비가 10,799달러면 약 5.4달러다(이 문서의 계산, 속도와 가격은 제작자 제시값. 제작자의 계산은 약 5.5달러이고 API가 5~9배 싸다고 봤다). 한 사람이 쓰는 조건에서는 API가 여러 배 싸고 줄이지 않은 모델을 쓴다. 가동률이 낮으면 차이는 더 벌어진다.

로컬이 비용으로 앞서는 조건은 높은 가동률이다. 여러 사용자의 요청을 동시에 처리해 장비가 종일 찬 경우에만 토큰당 비용이 API 아래로 내려간다는 것이 제작자의 계산이다. 상시 인스턴스와 API의 손익분기를 실제 유입량으로 계산하는 방법은 [[LLM-Cost-Optimization|LLM 비용 최적화]]를 따른다.

판매자가 내놓는 계산은 가정부터 확인한다. 한 AI 칩 회사의 엔지니어는 채용 행사 발표에서 약 8억 원짜리 자사 서버를 5년 감가로 30명이 나눠 쓰면 상위 모델 API의 4분의 1 비용이라고 주장했다(2026-11-16, 음성 인식 전사 기준). 이 계산은 가동률, 감가 기간, 공유 인원과 로컬 모델의 품질이 API 모델과 같다는 가정에 달려 있다. 발표는 그 가정의 근거를 제시하지 않았고 비교 대상 장비의 가격도 발표 안에서 엇갈렸다.

비용과 무관하게 장비를 사야 하는 경우도 있다. 코드, 고객 파일이나 환자 기록이 법적으로 외부로 나갈 수 없으면 클라우드 가격은 비교 대상이 아니다.

## 비용 밖의 이유: 호출당 요금, 교체 시점과 지연

로컬과 온프레미스를 고르는 이유는 토큰당 비용 비교만으로 드러나지 않는다. Moonshine Voice를 함께 만든 Pete Warden은 2026-11-19 게시된 대담(O'Reilly 팟캐스트에서 먼저 방송)에서 다음 이유를 들었다. 로컬 음성 모델을 만드는 사람의 견해이고 측정 근거가 함께 제시되지는 않았다.

- **호출당 요금이 사라지면 설계가 바뀐다**: 앱 개발자가 화면의 아이콘을 누를 때마다 몇 센트를 내야 한다면 앱을 전혀 다르게 설계하고 많은 앱은 아예 없었을 것이라며, 호출 비용이 1센트에서 0으로 가는 변화는 점진적 개선이 아니라 쓸 수 있는 용도를 넓힌다고 본다. 위의 토큰당 비용 비교와는 다른 축으로, 상시 듣기나 매 상호작용마다 모델을 부르는 기능처럼 호출 빈도 자체가 설계 변수인 경우에 해당한다(이 문서의 해석).
- **교체 시점을 직접 정한다**: 같은 모델 버전을 골라도 뒤에서 실제 동작이 날마다 바뀔 수 있어 안정성이 필요하면 적어도 자기 클라우드 인프라에 직접 호스팅해야 한다고 말한다. 언제 다른 모델로 바꿀지 스스로 정하고 단가가 하루아침에 크게 오르는 위험도 피한다는 것이다. 이름이 같아도 바뀌는 층은 [[Eval-Model-Drift-Monitoring#같은 이름 아래에서 바뀌는 네 층|서빙 모델 드리프트]]가 다룬다.
- **지연**: 음성 인터페이스가 반응한다고 느끼려면 일반 UX 연구에 따라 약 200ms 이하가 필요하고, 클라우드 음성 인터페이스는 보통 적어도 몇 초를 기다리게 한다고 말한다. 측정 조건은 제시하지 않았다.
- **감사할 수 있는 처리**: 로컬에서는 음성과 영상이 저장되지 않았음을 확인할 수 있지만 클라우드로 보낸 뒤에는 감사하기 어렵다고 본다.
- **로컬의 범위**: 노트북만이 아니라 온프레미스나 기업이 통제하는 클라우드 인스턴스도 로컬로 본다. 위의 구매와 API 비교에 자기 통제 아래의 임대 인스턴스라는 선택지가 더해지는 셈이다(이 문서의 해석).

같은 대담은 로컬 AI의 장벽이 모델 품질보다 사용성과 홍보에 있고, 로컬 모델은 구독 수익을 만들기 어려워 큰 회사가 밀지 않는다고 주장한다. 오픈 웨이트 모델이 상용 모델에 몇 달 뒤질 뿐이라며 벤치마크를 근거로 들지만 구체적인 수치는 없으므로, 품질이 충분한지는 자기 과업으로 잰다([[Model-Release-Claims#채택 전에 기록할 것|채택 전 기록]]).

## 구매 전 점검

1. 이 칩이 지원되는 가장 최신의 CUDA 또는 ROCm 버전은 무엇이고, 쓰려는 추론 엔진의 현재 배포물이 그 버전을 대상으로 하는가?
2. 표기 용량에서 운영체제, 문맥과 GPU 상한을 뺀 뒤 모델에 쓸 수 있는 메모리는 얼마인가?
3. 쓰려는 모델의 다음 판이 커지면 어떤 양자화까지 내려가야 하고 그 품질을 받아들일 수 있는가?
4. 쓸 수 있는 연수의 가정을 절반으로 줄여도 구매가 임대나 API보다 유리한가?
5. 데이터가 외부로 나갈 수 없는 제약이 실제로 있는가, 아니면 선호인가?
6. 전원, 소음과 설치 공간을 감당할 수 있는가?
7. 호출당 요금이 없어야 성립하는 기능이나 모델 교체 시점을 직접 정해야 하는 요구가 있는가, 있다면 자기 통제 아래의 클라우드 인스턴스로도 충족되는가?
