# LLM 워크플로 표현식과 실행 경계

모델이 생성한 계획을 제한된 연산과 데이터 변환으로 표현하면 실행기가 지원할 행동을 명시할 수 있다. 다만 언어를 바꾸는 것과 실행 권한을 제한하는 것은 별도 설계다. 선언적 표현식도 계산을 수행하며, 인터프리터에 연결한 함수는 외부 시스템을 바꿀 수 있다.

## 계획, 변환과 실행을 나눈다

다음은 [[LLM-Workflow-Patterns|Plan-and-Execute]]에 표현식을 적용하는 설계 예시다. 특정 라이브러리의 기본 기능을 뜻하지 않는다.

| 계층 | 맡기는 일 | 실행 전에 확인할 것 |
|---|---|---|
| 모델 | 사용할 작업과 데이터 변환을 제안 | 작업 이름, 인자, 단계 간 참조가 허용된 계약에 맞는가 |
| 표현식 평가기 | 주어진 JSON의 선택, 변환과 집계 | 입력 범위, 계산량, 결과 크기가 제한되는가 |
| 실행기 | 승인된 도구를 호출하고 결과를 기록 | 사용자와 대상의 권한, 부작용, 재시도 조건이 맞는가 |

예를 들어 주문 조회 결과를 지역별로 집계하는 단계에는 조회로 얻은 데이터만 전달한다. 외부 발송은 변환식에 감춰 넣지 않고 별도 작업으로 표현한다. 실행기는 허용 작업 목록과 인자를 검사하고, 발송이 필요한 경우 해당 서비스의 승인 정책을 적용한다. 변환 성공은 발송 성공의 증거가 아니다.

## JSONata의 표현력과 확장 경계

JSONata는 JSON을 조회하고 변환하는 언어이며, 함수와 재귀를 지원하는 **튜링 완전 함수형 언어**다. 따라서 실행되지 않는 데이터 형식으로 취급하거나, JSONata를 썼다는 이유만으로 샌드박스가 불필요하다고 결론내리지 않는다.

JavaScript 참조 구현에서는 `jsonata()`로 표현식을 파싱하고 `evaluate()`로 입력에 적용한다. `registerFunction()`으로 호스트 함수를 연결할 수 있으며, 선택적인 signature는 입력 인자의 타입을 검사한다. 2026-10-08 확인한 문서에서는 반환 타입은 아직 검사하지 않는다고 명시한다. 타입 검사는 접근 권한이나 업무상 허용 여부도 보장하지 않는다.

설계 적용 시에는 변환에 필요한 함수만 연결한다. 파일, 네트워크와 상태 변경 함수를 노출한다면 그 함수에서도 대상과 권한을 확인한다. 함수 등록 범위가 넓으면 표현식 언어를 도입해도 실행 가능한 행동의 범위는 넓게 남는다.

## 계산 제한과 남는 위험

아래 옵션은 2026-10-08 확인한 JSONata 2.2.0 문서의 **JavaScript 참조 구현** 기준이다. 다른 언어 구현에 같은 이름과 동작이 있다고 가정하지 않는다.

| 설정 | 제한하는 대상 | 초과 오류 |
|---|---|---|
| `stack` | 평가기의 eval-apply 반복 깊이, JavaScript 호출 스택 깊이와 관련됨 | `D1011` |
| `timeout` | 표현식 평가 시간, 밀리초 | `D1012` |
| `sequence` | 중간 결과를 포함한 시퀀스 길이 | `D2015` |

꼬리 재귀는 스택을 늘리지 않고 오래 실행될 수 있으므로 `stack`만으로 시간 제한을 대신하지 못한다. 공식 문서는 `stack`과 `timeout`을 함께 설정하도록 안내하지만 권장 수치나 기본값을 제시하지 않는다.

정규식 처리는 핵심 평가 루프 밖에서 실행되어 `timeout`으로 보호되지 않는다. `RegexEngine`으로 정규식 처리기를 바꿀 수 있지만, 특정 탐지기를 연결했다는 사실만으로 모든 자원 고갈을 막았다고 보지 않는다. 신뢰할 수 없는 표현식에는 입력과 출력 크기 제한, 외부에서 중단 가능한 실행 경계도 검토한다. 이는 남는 위험에 대한 설계 제안이다.

## 선택과 검증

- 필드 선택과 집계가 반복되고 입력이 JSON이면 표현식 언어를 검토한다. 고정된 변환 하나라면 기존 애플리케이션 코드가 더 단순할 수 있다.
- 범용 코드보다 지원 연산을 좁혀 검토하기 쉬워질 수 있지만, 인터프리터 운영, 오류 처리와 호스트 함수의 권한 검사는 남는다.
- 문법 오류, 예상 밖 결과 타입, 깊은 재귀, 큰 중간 결과, 오래 걸리는 정규식과 금지된 도구 요청을 따로 검사한다.
- 표현식의 평가 제한과 전체 워크플로의 시간, 단계 수 제한을 구분한다. 여러 번의 짧은 평가도 누적 비용을 만들 수 있다.
- 외부 작업의 결과가 불명확하면 재실행 전에 실제 상태를 조회한다. 표현식 언어가 [[LLM-Failure-Handling|멱등성과 부분 완료 처리]]를 대신하지 않는다.
