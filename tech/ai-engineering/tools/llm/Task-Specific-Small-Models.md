# 작은 특화 모델 — 한 가지 일을 맡기는 증류, 미세조정과 서빙

범용 대형 모델을 그대로 부르는 대신 작은 오픈 웨이트 모델을 한 과제에 맞춰 학습해 대량 배치나 기기 안에서 돌리는 구성이다. 입력과 출력 형식이 고정되고 호출량이 크거나, 네트워크 없이 로컬에서 돌아야 할 때 검토한다. 이 문서는 2026-10-27에 Pinterest 엔지니어링 블로그(2026-10-09)와 WorldTUI 작성자 블로그(2026-10-21)를 대조한 두 사례로 설명한다. 두 사례의 수치는 각 작성자가 자기 시스템을 잰 자체 보고다. 비용 손익분기와 크기 축소 절차는 [[LLM-Cost-Optimization#오픈 웨이트 소형 모델을 직접 서빙할 때|LLM 비용 최적화]], 티어 선택은 [[LLM-Model-Tiers|LLM 모델 티어 선택]]이 다룬다.

## 두 사례의 구성

| 항목 | 사용자 여정 추론(Pinterest) | 터미널 월드 모델(WorldTUI) |
|---|---|---|
| 과제 | 프로필과 최대 360일, 150개 이벤트의 활동 기록에서 사용자가 몇 주에서 몇 달에 걸쳐 이루려는 목표(여정) 목록을 순위대로 생성 | 키 입력이나 대기(WAIT 토큰)를 받아 실제 셸 없이 다음 터미널 화면을 예측 |
| 학습 자료 | 프런티어 모델(교사)이 활동 기록마다 만든 모범 여정 목록 | Docker 컨테이너에서 실제 프로그램을 돌리며 기록한 키 입력과 화면 33만 6천 에피소드(약 20억 토큰) |
| 학생 모델 | Qwen3 0.6B, 1.7B, 4B, 8B를 교사 답으로 SFT하고 LoRA로 adapter를 갱신한 뒤 4B 채택 | Qwen2.5-Coder-0.5B를 미세조정하고 임베딩 표를 줄여 약 4억 9,400만에서 약 3억 6천만 파라미터로 축소 |
| 출력 형식 | `{"journeys": [...]}` JSON, 최대 약 12개, 각 1~5단어, 사용자 언어 | 다시 쓸 행과 커서 위치. 어휘는 333개(바이트 256, 행 64, 특수 연산 몇 개) |
| 서빙 | NVIDIA Dynamo 뒤의 vLLM 디코드 워커, L40S GPU | int4 가중치(약 208MB)를 브라우저의 WebGPU로 실행 |

## 학습 자료를 어디서 얻는가

- **교사 모델의 답으로 학습한다(증류)**: 프런티어 모델은 수억 명의 기록을 정기적으로 돌리기에는 비싸서 직접 서빙하지 않고 학생의 학습 자료를 만드는 데 썼다. 교사에게 최종 답 전에 추론 토큰을 더 쓰게 하자 학습용 답의 품질이 좋아졌다. 학생 품질은 처음 수천 개 예시에서 빠르게 오른 뒤 거의 멈췄고, 비슷한 예시를 늘리기보다 어려운 통합 사례와 다국어 사례처럼 다양하고 질 높은 예시를 고르는 편이 더 도움이 됐다.
- **환경을 실행해 기록한다**: 정답을 만들 교사 대신 실제 프로그램을 돌려 입력과 결과 화면을 함께 기록하면 정답이 환경에서 나온다. WorldTUI는 사용자명, 호스트명, 터미널 크기, 페르소나와 활동을 무작위로 바꾸고 1.2% 비율의 오타와 앱 실행 중간에서 시작하는 세션(35%)을 넣었다. 학습과 이후 개선에 RTX 4090으로 약 75 GPU시간이 들었다.

## 출력 공간을 과제에 맞춘다

- **형식과 디코딩을 고정한다**: Pinterest는 temperature 0, 추론 토큰 끔, 최대 출력 300토큰으로 같은 기록에서 일관된 결과와 정해진 형식을 얻고 비용을 낮췄다. 문자열이 아닌 값은 버리고 대소문자를 무시해 중복을 없애며(먼저 나온 항목 유지), 디코딩이 실패하면 부분 목록을 저장하지 않고 그 사용자를 다시 처리한다. 유효한 빈 목록은 성공으로 친다. 형식 오류가 개인화 데이터의 누락으로 번지지 않게 하는 처리다([[LLM-Failure-Handling-Response-Validation#구조화 출력은 형식만 보장한다|응답 검증]]).
- **어휘와 연산을 과제에 맞게 만든다**: WorldTUI는 문자, 좌표와 작은 수에 바이트 토큰을 재사용하고 행 토큰과 몇 가지 특수 연산만 남겼다. 행을 옮기는 `COPY` 연산을 더해 스크롤 비용을 행당 약 96토큰에서 3토큰으로 줄였다. 디코딩은 문법으로 제한해 모든 예측이 유효한 화면 갱신이 되게 했다.
- **입력도 압축한다**: Pinterest는 행동을 검색, 저장, 좋아요, 클릭, 댓글, 싫어요로 줄이고 중요도를 검색과 저장, 댓글, 좋아요, 클릭, 싫어요 순으로 명시했다. 같은 날짜와 행동의 이벤트를 묶어 토큰을 줄였다.

## 자기 오류에서 회복하도록 학습한다

정답 시연만으로 학습한 모델은 추론 때 자기 실수로 생긴 낯선 상태를 만나면 오류가 이어지기 쉽다. WorldTUI는 모델이 이상적인 시연이 아니라 자기가 방문한 상태에서 배우게 하는 DAgger의 방식을 빌렸다. 모델이 몇 개의 이벤트를 예측하게 한 뒤 틀린 화면을 바로잡는 교정 예시를 만들되, 교정이 새로 넣는 단어는 앞선 실제 화면이나 사용자 입력에 있던 것으로 제한해 환각을 보상하지 않게 했다. 표본 세션의 약 3분의 1에서 쓸 만한 예시가 나왔고 세 차례 모았다. 추가 학습 자료와 함께 int4에서 자체 시험 PresetBench가 47개 중 24개에서 38개로 올랐다.

## 압축은 능력마다 다르게 깨진다

WorldTUI에서 재학습 없이 층을 빼면 다음 토큰 정확도는 높게 유지됐지만 앞서 쓴 파일 내용을 정확히 다시 보여 주는 기억 시험이 깨졌다. 16층 학생은 4비트 약 138MB로 기억 시험 64개를 모두 통과했지만 ShellBench에서 106개 중 65개를 맞혀 교사(이전 체크포인트)의 78개보다 낮았고, 작성자는 증류를 접었다. 평균 정확도 하나로 압축 결과를 판정하지 않고 정확한 회상처럼 따로 깨지는 능력을 별도 시험으로 잰다(적용 제안).

## 병렬 생성과 자기 검증

WorldTUI는 화면의 각 행을 배치의 별도 원소로 동시에 디코딩하고 커서는 마지막에 만든다. 행끼리 어긋나는 문제는 같은 모델이 병렬로 만든 행을 초안으로 삼고 순차로 검증하는 추측 디코딩으로 풀었다. 큰 화면의 p95 지연이 RTX 4090에서 6.7초에서 0.87초로 줄었고, M4 Mac에서 글자 하나의 갱신은 약 60ms였다. 초안과 검증의 설정은 [[LLM-Inference-Serving-Engines#초안 기반 디코딩의 설정을 함께 기록한다|추론 서빙 엔진]]처럼 함께 기록한다.

## 대량 서빙의 구성

- **오프라인 루프보다 서빙 스택이 빨랐다**: Pinterest는 같은 4B 모델을 오프라인 배치 흐름과 온라인 추론 스택으로 비교했고 처리량은 온라인 서빙이 앞섰다. PagedAttention과 continuous batching처럼 단순한 오프라인 루프가 기본으로 얻지 못하는 디코드 최적화를 이유로 든다.
- **같은 접두어를 같은 워커로 보낸다**: 프롬프트 구조를 공유하는 요청이 해당 접두어를 이미 가진 워커로 가도록 KV 캐시 인식 라우팅을 쓰고, prefix caching, chunked prefill과 워커별 동시 시퀀스 상한을 함께 둔다. 프런트엔드와 워커는 따로 확장한다([[LLM-Inference-Bottlenecks#라우팅, 과부하 거절과 확장을 따로 설계한다|라우팅과 확장]]).
- **처리량과 지연**: 약 100개 GPU 규모의 클러스터가 끝에서 끝까지 초당 약 775건을 처리했고 지연은 중앙값 약 1.2초, p95 약 3.0초였다.
- **일괄 작업을 잘게 나눈다**: 매일 대상 사용자 전체로 작업을 펼치되 작은 배치로 나누고 배치 안의 동시 실행 수를 제한해, 느린 응답이 파이프라인 전체가 아니라 한 조각에만 역압을 걸게 한다.
- **다시 계산하지 않을 대상을 고른다**: 매일은 최근 활동 사용자만 증분 처리하고 최근 이틀 정도 안에 추론한 사용자는 건너뛴다. 목표가 자주 바뀌지 않는 성질을 이용한 절감이며, 알고리즘이 바뀌면 전체를 다시 계산한다.

## 정답이 없는 과제의 평가

- **오프라인**: 사용자의 숨은 목표에는 정답 라벨이 없어 Pinterest는 같은 사용자의 기존 클러스터링 결과와 LLM 결과를 사람이 나란히 비교하고, 별도 모델이 관련성, 근거(프로필과 기록에 충실한지), 다양성, 세분성을 채점하게 했다. 근거를 가장 중요한 축으로 둔다([[Eval-LLM-Judge|LLM 판정기]]).
- **온라인**: 미국과 캐나다 실험에서 클러스터링 대조군보다 이메일 클릭률 1.1%, 푸시 열람률 1.3%가 올랐다.
- **자체 벤치마크**: WorldTUI의 ShellBench(명령 106개, 출력 완전 일치)에서 미세조정 모델은 80개를 맞혀 프롬프트만 쓴 Qwen2.5-Coder-0.5B의 52개, Qwen3-0.6B의 60개보다 높았고, 파일 다시 읽기는 13개 중 9개(대조군 2개, 3개)였다. 작성자가 만든 시험이며, 작성자도 중첩 디렉터리 이동과 Python 처리가 약해 아직 약한 월드 모델이라고 적는다. 가중치는 확인일 기준 공개 예정이다.

## 안전 경계

Pinterest는 프롬프트에 넣는 키워드와 생성된 여정 이름을 알림 콘텐츠 필터와 생성 콘텐츠 안전 필터에 통과시키고, 건강 상태, 정치, 성적 지향 같은 민감 주제를 추론하거나 겨냥하지 말라고 지시한다. 유럽경제지역, 스위스와 영국의 18세 미만은 현지 법 때문에 아직 대상이 아니다. 개인 활동에서 의도를 추론하는 모델은 출력이 맞더라도 민감 정보 추론이 될 수 있으므로 입력, 지시와 출력 세 곳에 경계를 둔다(적용 제안).

## 트레이드오프

| 선택 | 얻는 것 | 대가 |
|---|---|---|
| 교사 모델 증류 | 정답 라벨 없이 학습 자료를 대량으로 만든다 | 학생이 교사의 판단을 넘기 어렵고 교사 호출 비용이 든다 |
| 환경 실행 기록 | 정답이 환경에서 나온다 | 환경을 재현할 수 있는 과제로 한정되고 기록 인프라가 필요하다 |
| 작은 학생 | 처리량, 비용과 로컬 실행 | 어려운 사례에서 관련성과 일관성이 떨어진다(Pinterest의 0.6B, 1.7B) |
| 과제 전용 어휘와 문법 제약 | 토큰 수 감소와 항상 유효한 출력 | 범용 기능을 잃고 다른 과제로 옮기기 어렵다 |
| 층 제거와 증류 | 크기와 지연 감소 | 평균 지표에 드러나지 않는 능력이 깨질 수 있다 |

## 점검 체크포인트

- 범용 모델 호출을 작은 특화 모델로 바꿀 만큼 호출량과 형식이 고정됐는지 설명할 수 있는가
- 학습 자료의 정답이 교사 모델에서 오는지 환경에서 오는지 구분하고 각각의 한계를 말할 수 있는가
- 자기 오류 상태에서 배우는 학습(DAgger)이 필요한 이유와 교정 자료가 환각을 보상하지 않게 하는 조건을 말할 수 있는가
- 압축 뒤 평균 정확도 외에 따로 깨지는 능력을 시험하는가
- 정답이 없는 과제에서 사람 비교, LLM 판정기와 온라인 실험을 어떻게 나눠 쓰는가
