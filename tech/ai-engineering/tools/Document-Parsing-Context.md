# 페이지 간 문서 파싱과 제한된 참조 메모리

문서 파싱은 글자 인식뿐 아니라 읽기 순서, 표, 수식, 제목 계층과 페이지 사이의 연결을 복원하는 작업이다. 페이지마다 정확해 보여도 다음 페이지의 표를 새 표로 처리하면 문서 의미가 깨진다.

## 페이지 독립 처리와 연결 처리

| 방식 | 이점 | 따로 검증할 실패 |
|---|---|---|
| 페이지별 파싱 | 병렬 처리와 개별 재시도 | 끊긴 표, 반복 헤더와 문단의 연결 |
| 여러 페이지를 한 문맥으로 처리 | 이전 내용과 연결된 구조 활용 | 증가하는 시각 토큰, 메모리와 지연 |
| 제한된 참조 집합으로 순차 처리 | 활성 참조 범위 제한 | 버린 전역 정보와 잘못 고른 참조 |

긴 문서를 받는 입력 계약과 전체 내용을 보존하는 능력은 다르다. 무제한이라는 이름을 입력 파일 크기, 실행 시간과 출력 저장의 무제한 보장으로 사용하지 않는다.

## SR-SWA: 필요한 시각 참조만 유지한다

Unlimited OCR 2의 SR-SWA(Sparse Reference Sliding Window Attention)는 로컬 문맥에 더해 참조할 시각 토큰을 제한한다. Page Gate가 관련 페이지를 좁히고 Token Sieve가 고정 예산의 참조를 고른다. 모델 카드가 예로 든 참조 크기는 512토큰이다.

설계 목표는 문서 길이가 늘 때 매 디코딩 단계의 참조 비용과 KV 캐시 증가를 억제하는 것이다. 전체 문서를 출력하는 총시간과 출력량이 상수가 된다는 뜻은 아니다. 논문의 지연 비교는 batch 3, 페이지당 생성 1,024토큰 등 정해진 조건의 결과다.

## 평가 점수와 전역 구조의 한계

Baidu의 공개 논문 표에서 MPDocBench Overall은 84.59, MarathonDocBench는 77.06이다. 제공된 알림의 반올림 값 84.6과 77.1에 대응한다. MarathonDocBench는 100개 문서, 103~300페이지와 페이지 사이의 표/텍스트 연결을 포함한다. 개발팀의 평가이며 다른 언어, 스캔 품질과 자기 문서의 정확도를 직접 보장하지 않는다.

논문은 희소 참조가 **전역 문서 정보를 보존하지 못해 제목 계층 같은 문서 전체 구조의 이해가 제한된다**고 명시한다. 긴 문서 처리 가능성과 문서 전체 이해를 같은 능력으로 묶지 않는다.

## 파이프라인에 적용할 점검

다음은 위 한계를 고려한 적용 제안이다.

1. 페이지 ID와 원본 위치를 출력 블록에 연결해 누락과 순서 변경을 추적한다.
2. 한 페이지 인식과 페이지 사이 표/문단 연결을 별도 표본으로 평가한다.
3. 제목 계층과 문서 전체 관계는 별도 검수하고, 불명확한 연결은 보류한다.
4. 전처리, 모델 추론, 출력 조립의 시간과 최대 메모리를 각각 잰다.
5. 원문과 다른 숫자, 표 셀 이동과 반복 헤더를 확인한 뒤 검색 색인으로 넘긴다.

2026-11-02 모델 카드와 논문 본문을 대조했다. 모델 실행, 한국어 문서 평가와 설치 호환성은 확인하지 않았다.
