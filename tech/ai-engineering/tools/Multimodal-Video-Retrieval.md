# 멀티모달 영상 검색

영상 검색은 파일을 찾는 작업과 그 안에서 사건이 일어난 구간을 찾는 작업을 함께 다룬다. 대사 전사문만 검색하면 화면 속 행동이나 비언어적 소리를 놓칠 수 있다. 영상, 음성, 발화와 화면 텍스트를 함께 다루되 질문에 필요한 모달리티를 구분한다.

## 색인, 검색과 답변 생성

TwelveLabs의 Marengo는 영상 이해용 임베딩 모델이고, Pegasus는 영상에서 텍스트를 생성하는 모델이다. 이 역할 분리는 검색 결과를 찾는 능력과 그 결과로 설명을 만드는 능력을 따로 평가하게 한다.

| 단계 | 결과 | 확인할 경계 |
| --- | --- | --- |
| 업로드 | 재사용할 원본 asset | 업로드 성공과 후속 처리 준비 상태 |
| 색인 | 검색에 사용할 표현 | 비동기 색인의 완료와 실패 |
| 검색 | 영상 ID, 시작과 종료 시각, 순위 | 질문과 실제 구간의 관련성 |
| 답변 생성 | 설명, 요약이나 구조화된 결과 | 검색된 구간에 없는 사건을 덧붙였는지 |

TwelveLabs Search는 업로드와 색인 완료 뒤 조회한다. 2026-10-22 문서 기준 한 요청은 하나의 index를 대상으로 한다. 텍스트, 이미지와 둘을 조합한 질의를 지원하며, 검색 결과의 `start`와 `end`는 초 단위 구간이다. 파일 전체의 주제와 특정 구간의 근거를 혼동하지 않는다.

## 모델과 검색 API의 지원 범위

2026-10-22 공식 문서 기준 `/search`는 Marengo 3.5를 지원하지 않는다. 플랫폼 검색에는 Marengo 3.0을 사용하고, 3.5 임베딩은 자체 검색 시스템에서 조회한다. 두 버전의 임베딩은 호환되지 않으므로 3.5로 옮길 때 임베딩을 다시 생성한다.

모델이 입력으로 이해하는 모달리티와 특정 API가 질의로 받는 모달리티는 별도 계약이다. 발표에서 설명한 모델의 전체 역량을 현재 API의 입력 지원 목록으로 옮기지 않는다. 검색 색인의 선행 처리가 필요하다는 사실도 모든 영상 분석 API에 일반화하지 않는다.

## 원본, 미리보기와 검색용 표현을 나눈다

고해상도 원본, 미리보기 파일과 검색용 벡터는 역할이 다르다. Moments Lab의 S3 연동은 원본을 고객 버킷에 두고 가벼운 proxy를 만들어 색인, 조회와 클립 편집에 사용한다. 원본 상태의 렌더링이나 공유에는 원래 버킷의 master를 다시 사용한다(2026-10-22 제품 안내 대조). 벡터 저장소를 선택했다는 사실만으로 이런 원본 연결이나 미리보기 생성까지 제공되는 것은 아니다.

적용 시에는 원본 버전과 proxy의 시간 좌표를 연결하고, 검색 결과에서 원본 구간을 다시 여는 경로를 시험한다(설계 제안). 검색용 데이터가 준비돼도 원본이 다른 보관 계층에 있거나 읽기 권한이 없으면 최종 편집과 내보내기는 별도 문제가 된다. 색인 완료, 검색 응답, 원본 접근과 최종 출력의 시간을 각각 측정한다.

## 스냅샷 검색의 시간 해상도를 확인한다

March Networks AI Smart Search는 조정 가능한 시간 간격으로 추출한 카메라 스냅샷을 검색하며, 시간, 위치와 카메라 조건으로 결과를 좁힐 수 있다(2026-10-22 제품 안내 대조). 이 경로는 전체 연속 영상의 모든 프레임을 분석하는 것과 다르다.

운영 검증에서는 샘플링 간격보다 짧은 사건이 빠지는지 별도로 확인한다(설계 제안). 검색되지 않았다는 이유만으로 사건이 없었다고 판정하지 않고, 중요한 결과는 원본의 전후 구간과 대조한다. 예를 들어 빈 진열대가 보이는 스냅샷만으로 품절 지속 시간이나 보충 완료 시점을 확정하지 않는다. 저장과 처리량 절감의 가능성과 사건 탐지의 완전성은 서로 다른 평가 항목이다.

## 적용과 평가 제안

다음은 영상 검색을 제품에 연결할 때의 설계 제안이다.

1. 원본 파일의 버전, 구간과 파생 임베딩의 모델 버전을 연결한다. 원본을 편집하거나 교체하면 구간의 시간 좌표도 다시 확인한다.
2. 대사로 찾을 질문, 화면으로 찾을 질문, 시간 순서가 필요한 질문을 따로 평가한다. 정지 화면 하나에서 맞힌 결과를 사건의 전후 관계를 이해한 것으로 세지 않는다.
3. 검색 결과를 재생해 정답 구간의 누락과 잘못 포함된 구간을 확인한다. 답변에는 원본과 시간 위치를 붙이고, 생성 문장도 해당 구간과 대조한다.
4. 자산 읽기 권한을 검색과 원본 재생에 함께 적용한다. 임베딩 조회 성공을 원본 공개 권한으로 사용하지 않는다.
5. 총시간을 업로드, 색인, 검색, 생성과 검수로 나누어 측정한다. 반복 질의의 빠른 응답만으로 초기 수집 비용이 사라졌다고 계산하지 않는다.

예를 들어 제품 조립 영상에서 부품을 고정하는 장면을 찾는다면, 관련 영상만 반환하는 것보다 실제 작업의 시작과 끝을 돌려주는 결과가 검수에 유용하다. 단, 후보 구간이 적절한지와 설명이 사실인지는 별도로 확인한다.

2026-10-22 공개 문서와 발표 전사문을 대조했다. 영상 검색 API 호출이나 모델의 검색 정확도, 발표의 성능 우위와 시간 절감 수치는 재현하지 않았다.
