# LLM 위키와 지식 합성의 영속화

LLM 위키는 여러 원문에서 조합한 지식을 주제별 Markdown으로 저장하고 갱신하는 패턴이다. 질문마다 근거를 찾는 검색에 재사용할 합성 결과를 더한다. RAG를 대체해야 하는 구조는 아니며, 위키가 커지면 위키 자체를 검색할 수도 있다.

## 원문, 위키와 규칙의 분리

| 층 | 책임 |
|---|---|
| 원문 | 대조할 근거를 보존한다. 위키 작성 과정에서 원문을 수정하지 않는다 |
| 위키 | 개념, 엔티티와 비교를 정리하고 원문 및 관련 페이지를 연결한다 |
| 규칙 | 문서 구조, 출처 표기, 충돌 처리와 갱신 절차를 정한다 |

수집한 자료 하나가 기존 페이지 여러 개를 바꿀 수 있다. 질문의 답을 저장할 때도 기존 개념과 연결하고, 주기적으로 충돌, 오래된 주장과 끊긴 링크를 점검한다. 목차는 내용 탐색을, 변경 기록은 갱신 이력 확인을 맡는다.

## 채팅 링크 수집과 지식 반영의 구분

채팅에 올라온 링크를 표에 모으는 단계와 원문을 읽고 기존 개념에 연결하는 단계는 완료 조건이 다르다. 제목, 분류와 요약 열이 채워졌더라도 링크 본문을 확보했는지, 요약의 주장을 확인했는지는 별도로 남긴다. 다음은 원문과 파생 위키의 분리를 수집 자동화에 적용한 설계 예시다.

| 단계 | 남길 내용 | 완료 조건 |
|---|---|---|
| 수집 | 원문 위치, 수집 시각과 처리 식별자 | 나중에 원문을 다시 찾을 수 있다 |
| 초안 | 확보한 본문 범위, 생성 요약과 분류 | 제목만 본 경우와 본문을 읽은 경우가 구분된다 |
| 지식 반영 | 대조한 근거, 반영 문서와 검토 상태 | 기존 내용과의 중복 및 충돌을 확인했다 |

예를 들어 Slack Events API의 HTTP 전달은 실패한 요청을 재시도하며, 이벤트에는 고유한 `event_id`가 있다. Google Sheets의 `spreadsheets.values.append`는 지정 범위에서 표를 찾아 다음 행에 값을 추가한다. 따라서 이벤트를 받을 때마다 행을 추가하는 설계에는 재전달로 같은 자료가 여러 행에 들어갈 위험이 있다. 이 동작에서 도출한 설계 점검으로, 수집 식별자별 처리 상태와 저장 결과를 확인하고 중복 저장을 막는 절차를 둔다. 단순한 사전 조회만으로 동시 처리 경쟁까지 해결됐다고 보지 않는다.

위 API 사실은 2026-10-14 공식 문서 기준이다. 이는 직접 구성하는 수집 파이프라인의 검토 기준이며, 특정 AI 제품의 채팅 연동이나 자동 요약 기능이 같은 방식으로 구현되었다는 뜻은 아니다. 비공개 채팅의 원문 위치와 식별자는 접근이 제한된 수집 기록에 두고, 공개 위키에는 공개 가능한 근거와 개념만 반영한다.

## 자동 갱신의 검증 경계

다음은 2026-10-06 공개 강의의 위키 빌더 사례를 일반화한 설계 점검 항목이다. 특정 도구의 기본 기능이나 검증 정확도 보장이 아니다.

1. 변경할 문서와 근거를 먼저 정한다. 관련 없는 페이지까지 갱신하지 않는다.
2. 작성 중인 결과와 사용자가 조회하는 문서를 분리한다. 형식과 링크 검사는 코드로, 주장의 근거 대조는 별도 검토로 나눈다.
3. 검토자는 일정 제안을 확정 결정으로 바꿨는지, 원문의 조건을 빠뜨렸는지 확인한다. 두 문서가 상충하면 최신 날짜 하나로 해결하지 않고 권한, 적용 범위와 결정 상태를 대조한다.
4. 검토 실패, 판정 누락과 시간 초과를 통과로 간주하지 않는다. 근거를 확인하지 못한 변경은 보류한다.
5. 자동 생성 초안, 사람이 검토한 문서와 폐기된 내용을 구분한다. 형식 검사 통과가 사람의 사실 검토를 대신하지 않는다.

## 비용과 실패 조건

갱신은 여러 페이지의 재작성과 검토 비용을 만든다. 원문 변경이 위키에 반영되기 전에는 두 내용이 어긋나고, 잘못된 합성을 다음 답변의 근거로 반복하면 오류도 누적된다. 원문 링크와 변경 이력을 유지하며, 저장할 만한 재사용 가치와 검토 비용을 함께 판단한다.

문서 수가 늘었다는 사실만으로 답변 품질이 좋아졌다고 보지 않는다. 같은 질문으로 근거 누락, 잘못된 확정과 갱신 지연을 확인한다. 검색의 권한과 삭제 전파는 [[RAG-Retrieval-Engineering|RAG 검색 엔지니어링]]에서 함께 다룬다.
