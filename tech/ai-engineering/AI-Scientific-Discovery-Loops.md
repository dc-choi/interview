# AI 과학 발견 루프

AI를 과학과 공학에 적용하는 한 방법은 문제 정의, 후보 생성, 실험 실행, 결과 평가와 다음 실험 선택의 순환을 빠르게 만드는 것이다. 문헌을 요약하는 능력, 계산으로 후보를 제시하는 능력과 새 결과를 실험으로 확인하는 능력을 구분한다.

## 발견은 실행과 피드백을 포함한다

| 단계 | 사람과 시스템이 정할 일 | 남겨야 할 근거 |
|---|---|---|
| 문제 정의 | 무엇이 가치 있고 어떤 제약을 지킬지 정한다 | 목표, 비교 기준과 실패 조건 |
| 후보 생성 | 가설, 설계와 실험 변형을 만든다 | 후보를 고른 이유와 사용한 자료 |
| 실행 | 계산, 시뮬레이션이나 실제 실험을 수행한다 | 입력, 환경, 도구 버전과 원시 결과 |
| 평가 | 성공/실패를 판단하고 대안을 비교한다 | 측정값, 불확실성과 부작용 |
| 갱신 | 다음에 무엇을 시험할지 바꾼다 | 이전 결과와 다음 결정의 연결 |

바둑에서 신경망은 유망한 수를 평가하고 탐색은 가능한 이후 진행을 비교할 수 있다. 같은 방식으로 실험 루프에서도 후보의 질을 예측하는 모델과 후보를 실제 평가하는 탐색을 구분한다. 계산 자원을 늘리는 이익은 어떤 후보에 쓸지 선택하는 정책과 함께 본다.

실험 수를 늘리는 것과 좋은 실험을 고르는 것은 다르다. 같은 오류를 반복하거나 편향된 평가 점수를 최대화하면 반복 속도가 빨라도 지식이 늘지 않을 수 있다. 실패한 실험도 조건을 남기면 다음 탐색의 근거가 된다. 이는 강연의 실험 루프를 개발과 연구에 적용한 정리이며 특정 시스템의 검증된 성능 수치가 아니다.

## 예측 결과를 공동 자원으로 공개한다

AI 모델의 출력을 여러 연구자가 재사용할 수 있는 데이터베이스로 제공하면, 각자가 모델 훈련과 추론 인프라를 마련하는 부담을 줄일 수 있다. AlphaFold의 2022년 공개 사례는 2억 개 이상의 단백질 구조 예측을 데이터베이스로 제공한 예다. 예측은 실험으로 결정한 구조와 같은 종류의 증거가 아니며 신뢰도와 적용 조건을 확인해야 한다.

한 분야의 성공을 재료, 화학과 다른 공학 문제의 자동 해결로 일반화하지 않는다. 후보를 계산할 수 있어도 실험 장비, 시료 제작과 검증 시간이 병목으로 남을 수 있다. 연산, 데이터, 도메인 지식과 실험 기반이 함께 필요한 이유다.

## 반도체 설계와 제조에 적용하는 조건

반도체 설계는 전기, 열, 기계와 패키징의 제약이 결합된다. 에이전트는 자료 검색, 설계 변형 생성, 시뮬레이션 실행과 결과 비교를 연결할 수 있다. 제조에서는 센서와 장비 이력이 공정 최적화의 입력 후보가 된다.

- 센서 데이터가 많아도 불량 원인, 측정 오차와 공정 변경의 영향을 구분해야 한다.
- 시뮬레이션 점수 개선, 실제 수율, 생산 원가와 현장 안전은 서로 다른 평가다.
- 도메인 문서와 개인 메모를 검색해 답하는 것, 대화 기록을 보존하는 것과 모델 가중치를 새로 학습하는 것을 구분한다.
- 계획, 도구 실행, 메모리와 결과 보고를 분리하고, 자동 실행이 허용되는 범위와 되돌릴 수 없는 작업의 책임을 정한다.
- 여러 에이전트가 분업하면 전달 누락, 중복 실행과 검토 비용도 측정한다. 수를 늘리는 것만으로 생산성이 비례 증가하지 않는다.

김정호의 강연에 나오는 개인 에이전트 제작과 반도체 연구 적용은 소개된 연구/사용 사례다. 해당 연구실의 구현, 투자 수익, 공정 수율과 생산성 배수를 재현한 검증은 수행하지 않았다. 개인 에이전트에 의한 자동 투자 사례를 금융 성과나 실행 권고로 사용하지 않는다.

## 연구, 제품과 능력 평가를 분리한다

시제품이 유용해도 사실성, 안전성과 사용자 기대를 충족하는지는 별도 문제다. 검색처럼 사실을 기대하는 제품에서는 그럴듯한 대화 능력만으로 출시 품질을 판정하기 어렵다. 연구 노선이 겹치는 조직을 통합할 때에는 공통 기반을 모으는 이익과 탐색 방식의 다양성을 함께 본다. 이는 제프 딘의 연구/제품화 회고에서 추출한 고려사항이며 현재 조직의 내부 상태나 인사 사실을 뜻하지 않는다.

AI 능력도 하나의 AGI 도달 여부보다 과업별 강점과 약점을 분리해 본다. 어떤 과업에서는 뛰어나도 다른 과업에서는 크게 실패하는 비균일성이 있다. 한 단계가 빨라지면 다른 단계가 새 병목이 될 수 있으므로 무한한 가속을 전제하지 않는다([[Benchmark-Coverage-and-Workplace-Performance|벤치마크와 실제 업무 성능]]).

## 발표자가 제시한 사회적 전망과 확인 경계

다음은 2026년 EBS 강연에 담긴 관점이며 확정된 일정, 보장된 효과와 채용 기준이 아니다.

| 관점 | 핵심 내용 | 확인할 경계 |
|---|---|---|
| 제프 딘: 개인화 교육 | 답을 대신 주기보다 힌트와 다른 예제로 이해를 돕는 튜터를 기대한다 | 인간 개인교습의 효과를 AI 튜터가 재현한다는 증거는 별도로 필요하다 |
| 제프 딘: 생산성과 고용 | 코딩 비용이 줄면 이전에 경제성이 없던 소프트웨어와 새로운 직무가 늘 수 있다고 전망한다 | 개별 직무의 대체와 총고용 증가는 같은 질문이 아니다. 생산성 10배는 가정이다 |
| 제프 딘: 접근성 | 누구나 에이전트를 쓸 수 있어야 하며 일부는 수백만 개, 다수는 하나도 없는 격차를 경계한다 | 에이전트 개수만으로 권한, 품질과 실제 혜택이 같아지지는 않는다 |
| 제프 딘: 이중 용도 | 교육/과학의 이익을 키우고 허위정보와 비동의 이미지 생성 같은 피해를 제한해야 한다 | 기술적 제한과 정책 수단은 적용 문제와 검증 범위가 다르다 |
| 김정호: 노동과 분업 | 개인이 여러 에이전트를 지휘하고 에이전트가 일과 수익 창출을 맡는 미래를 전망한다 | 무중단 노동, 소득 공급과 1인 기업의 성과는 보장이 아니다 |
| 김정호: 학습과 개인화 | 평생 기록을 가진 개인화 에이전트와 직접 구축하는 교육을 강조한다 | 제품이 모든 대화를 영구 보관하거나 실시간 검색 때마다 가중치를 학습한다는 뜻은 아니다 |
| 김정호: 산업과 채용 | 반도체 설계/제조 자동화와 에이전트 데모가 중요해질 것으로 본다 | 10년 후 산업 승자, 생산성 배수와 데모 중심 채용은 전망이다 |
| 김정호: 자기 개선 | AI가 자체 구조를 개선하는 재귀적 자기 개선(RSI)을 전망한다 | 성능 향상에서 윤리성의 자동 획득이 따라오지는 않는다 |

김정호가 제시한 목표/가치함수, 메모리와 전력 제어는 사람이 통제할 수 있는 자원의 예다. 이를 AI를 통제하는 유일한 방법이나 충분한 안전 보증으로 받아들이지 않는다. 물리적 자원 제한, 실행 권한, 감시와 중단 가능성은 각각 확인할 문제다. 자율 행동, 온라인 정보 검색과 가중치 학습도 같은 기능으로 묶지 않는다.
