# 학습 중 옵티마이저를 고치는 에이전트

옵티마이저는 배치마다 가중치를 어느 방향으로 얼마나 움직일지 정하는 코드다. 보통은 옵티마이저, 학습률 스케줄과 하이퍼파라미터를 학습 전에 정하고 끝까지 고정하므로, 중간에 과적합이나 손실 급등이 보여도 같은 규칙을 계속 따른다. 에이전트 인 더 루프 옵티마이저는 학습을 주기적으로 멈추고 코딩 에이전트에게 진행 보고를 넘겨, 옵티마이저 코드를 학습 도중에 다시 쓰게 한다. 옵티마이저를 학습 전에 고르는 설정이 아니라 실행 중에 디버깅하는 프로그램으로 다루는 방식이다.

아래 구조와 수치는 2026-10 공개된 Reactive Optimizers 연구와 그 구현 OPAL(OPtimizer with an Agent in the Loop) v0.3.10 README를 2026-11-17 대조한 것이다. 개발 중인 라이브러리라 옵션 이름과 기본값은 바뀔 수 있다.

## 동작 구조

- 기존 PyTorch 옵티마이저를 한 줄로 감싼다. 에이전트는 매 스텝 실행되는 갱신 프로그램(`updater.py`)과 자신이 쓰는 분석 프로그램(`analysis.py`) 두 파일을 고친다. 처음 `updater.py`는 사용자의 옵티마이저와 스케줄러를 그대로 호출하므로, 에이전트가 무언가 바꾸기 전까지는 감싸지 않은 학습과 비트 단위로 같다.
- 기본 50스텝마다 손실을 읽고 유한하지 않은 손실을 잡아내며 분석 프로그램을 돌린다. 에이전트에게 묻는 횟수는 따로 정하지 않으면 대기 시간이 학습 자체 시간의 4배를 넘지 않도록 1~50회로 잡고, 그중 5분의 1을 학습 처음 5% 구간에 몰아 둔다. 결정마다 아무것도 바꾸지 않을 수도 있다.
- 에이전트는 목표 문장, 파라미터 이름과 형태, 학습 손실, 자기 분석 보고서, 학습 스크립트와 모델 코드의 읽기 전용 사본을 받는다. 검증 지표는 사용자가 보고하도록 설정한 것만 보고, 그냥 기록한 값은 따로 허용하지 않으면 보여 주지 않는다. 결정마다 본 것, 바꾼 것과 기대하는 결과를 근거로 남긴다.
- 바꿀 수 있는 범위는 옵티마이저 코드로 표현할 수 있는 것 전부다. 파라미터 그룹별 갱신 규칙, 학습률과 스케줄, 모멘텀과 β₂, preconditioning, gradient clipping, 손실 급등 방어가 여기에 들어간다.
- 기본 백엔드는 Claude Code이고 Codex 백엔드는 실험 기능이다. 기본값은 에이전트 응답을 기다리는 blocking 모드이며, 기다리지 않게 하면 빠르지만 결정이 실제 상태보다 늦게 반영된다.

## 권한 경계와 실패 처리

| 항목 | 동작 | 운영에서 볼 점 |
|---|---|---|
| 손대지 말 범위 | 모델, 데이터, 손실, 배치 크기, 스텝 수와 평가는 바꾸지 말라고 요청한다 | 샌드박스가 아니다. 에이전트가 쓴 프로그램은 학습 프로세스 안에서 돌므로 규칙일 뿐이다 |
| 평가 조작 감시 | 평가 때 파라미터를 다른 값으로 옮겼다가 되돌리는 프로그램을 표시한다(검증 사용 시 기본 켜짐, 에이전트에게는 알리지 않음) | 감지 장치이지 차단 장치가 아니다 |
| 새 프로그램 시험 | 새 프로그램을 20스텝 시험하고, 오류가 나면 이전 프로그램으로 돌아간다 | 첫 스텝 실패는 파라미터와 옵티마이저 상태 사본이 한도(기본 2GB) 안이면 정확히 되돌린다. 그 뒤의 실패는 되돌리지 않고 에이전트에게 알린다 |
| 학습 되감기 | 학습을 다시 시작하거나 되감지 못하고, 다음 결정에서 프로그램만 고친다 | 에이전트가 학습을 더 나쁘게 만들 수 있다. 모든 프로그램 버전이 남으므로 사후 분석에 쓴다 |
| 비용 상한 | 상한은 기본으로 없고, 설정한 상한도 Codex 백엔드에는 적용되지 않는다 | 장기 학습 전에 상한과 결정 횟수를 정한다 |

에이전트 코드가 학습 프로세스의 권한으로 실행되므로, 자격 증명이나 운영 데이터에 닿는 환경에서는 학습 환경 자체를 격리한다. multi-node, FSDP와 DeepSpeed는 README 기준 지원하지 않는다.

## 실험 결과를 읽는 법

라벨 잡음 실험은 ResNet-18(손실 조작을 막으려 출력 logit에 중심화한 LogitNorm을 적용한 변형)을 CIFAR-10으로 증강 없이 120에폭 학습한다. 학습 이미지의 10%를 정답 라벨 그대로 검증 세트로 떼고, 남은 45,000장 중 10%(4,500장)에 고정된 오답 라벨을 붙였다. 에이전트는 잡음 사실을 듣지 못했고 테스트 성능을 보지 못했다. 시작 레시피는 학습률 3e-3의 AdamW다.

| 실행 | 테스트 정확도 | 테스트 손실 | 오답 라벨 이미지에서 실제 라벨 / 붙은 오답을 답한 비율 |
|---|---|---|---|
| OPAL(검증으로 고른 96~117에폭 가중치 평균) | 78.6% | 0.685 | 77.5% / 3.7% |
| AdamW 마지막 가중치 | 73.5% | 2.493 | 0.0% / 100.0% |
| AdamW 검증 기준 조기 종료 | 72.9% | 1.010 | 59.7% / 19.4% |
| AdamW 학습 경로의 가중치 이동 평균을 검증으로 고른 것(OPAL에서 가져온 EMA) | 77.5% | 0.832 | 70.0% / 14.2% |

- 고정 레시피의 AdamW는 오답 라벨을 모두 외웠다. 조기 종료만으로는 정확도가 오르지 않았다.
- OPAL의 전략은 학습률을 점점 높이며 가중치를 평균하는 것이었다. 넷째 행은 그중 평균 부분만 에이전트 없이 기존 AdamW 학습 경로에 적용한 결과이고, 높인 학습률은 다시 돌리지 않았다. 표를 읽으면(저자의 결론이 아니라 이 문서의 해석) 73.5%에서 77.5%까지는 가중치 평균만으로 설명되고, 나머지 차이(78.6%와 77.5%, 붙은 오답 비율 3.7%와 14.2%)는 평균만으로 설명되지 않는다.
- 가중치를 평균하는 방식은 2018년 발표된 Stochastic Weight Averaging(SWA)과 가깝고, 에이전트의 분석 프로그램도 자기 전략을 확장 SWA라 불렀다. 학습 계기 영상은 에이전트가 기법을 발명했다기보다 실행 중에 문제를 진단하고 알려진 기법에 도달했다고 평가한다.
- 이미지 생성에서는 SiT-B/2(ImageNet 256, 40만 업데이트)의 FID-50K가 35.7에서 23.6으로 낮아졌다. 35.7은 저자들이 ADM 평가기로 다시 잰 기준선이며 SiT 논문은 33.0을 보고했고, 각 수치는 한 번 실행한 결과다. FID는 생성 이미지 분포와 실제 이미지 분포의 거리라 낮을수록 좋다.
- 이미 잘 조정된 레시피에서는 이득이 작거나 없다. modded-nanogpt 기록 #36의 검증 손실(낮을수록 좋음)은 공식 레시피 3.2781, OPAL 3.2749로 차이가 작았고, 이전 버전(0.2.0)으로 돌린 실행은 3.2878로 기록보다 나빴다. 짧고 잘 튜닝된 학습일수록 이득이 줄어든다.
- 대부분의 실험은 한 번, 일부만 세 번 실행했다. 저자들은 학습의 재현성이 낮아질 수 있고 사용자의 결과가 다를 수 있다고 밝힌다.

## 시간과 비용

- 결정 하나에 평균 약 40초가 걸린다. 연구의 네 실행(Goldfish Amharic, modded-nanogpt, LightningDiT-XL/1, RAEv2-B)에서 에이전트를 기다리지 않으면 전체 시간이 1.01~1.14배, 결정마다 기다리면 1.30~4.39배였다. 결정 횟수를 50회로 직접 정한 1~3분짜리 단일 GPU 스크립트는 기본 4배 상한이 적용되지 않아 27~31분으로 늘었다.
- LightningDiT 실험의 약 100회 결정은 Claude Opus 5.5 정가로 6.42달러였고, 같은 학습의 GPU 사용은 H100 약 74시간이었다. 토큰 비용은 긴 학습의 GPU 비용에 비해 작지만, 짧은 학습에서는 대기 시간이 학습 시간을 압도한다.

## 적용 판단

- 학습 시간이 길고 레시피가 덜 검증된 경우에 맞는다. 공개 레시피가 이미 잘 튜닝된 짧은 학습이면 학습률 탐색과 고정 레시피 비교가 먼저다.
- 에이전트가 보는 검증 세트와 최종 테스트 세트를 나눈다. 에이전트가 반복해서 본 검증 점수는 선택에 쓰인 낙관적 추정이다([[Supervised-Learning-Validation-and-Metrics|지도학습 검증과 평가 지표]]).
- 에이전트가 도달한 전략의 구성요소를 에이전트 없이 다시 돌려 비교한다. 위 실험의 가중치 평균처럼 한 요소만으로 이득의 대부분이 나오면 다음 학습부터는 그 요소를 고정 레시피에 넣고, 남는 차이만 에이전트의 몫으로 본다.
- 결정 근거와 프로그램 버전을 실험 기록에 남긴다. 손실 곡선만 남은 학습보다 원인 추적이 쉽지만, 같은 설정으로 다시 돌려도 같은 결과가 나온다고 기대하지 않는다.

## 이해 확인

1. 고정 옵티마이저가 오답 라벨을 모두 외운 이유와, 조기 종료가 그 문제를 충분히 풀지 못한 이유를 설명한다.
2. 위 표에서 에이전트의 기여와 가중치 평균 기법의 기여를 나눠 말한다.
3. 에이전트가 고친 프로그램이 학습 프로세스 안에서 돈다는 사실이 운영 환경 설계에 주는 제약을 두 가지 든다.
