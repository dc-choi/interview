# 에이전트 모델의 기억, 장기 작업, 전문 영역 평가와 승인 경계

에이전트 모델의 능력은 한 번의 답변 정확도뿐 아니라 기억 검색, 요구사항 유지, 도구 실행과 최종 산출물로 평가한다. 사용자를 대신해 행동하는 에이전트는 무엇을 승인받고 무엇을 하지 않는지도 능력 계약의 일부다. 범용 지식, 전문 영역, 기억과 장기 작업을 하나의 순위로 합치면 실패 원인을 놓치기 쉽다.

## 능력별로 다른 완료 조건을 둔다

| 능력 | 확인할 결과 | 잘못된 대체 지표 |
|---|---|---|
| 기억 | 지난 대화의 필요한 사실을 정확히 회수 | 긴 컨텍스트를 지원한다는 스펙 |
| 장기 작업 | 요구사항을 유지하며 장애 뒤 완료 | 오래 실행하거나 많은 토큰을 사용 |
| 전문 지식 | 원문, 적용 규칙과 결론의 연결 | 법률 용어가 자연스러운 문장 |
| 코딩 | 요구사항, 동작과 회귀 검증 통과 | 생성 코드 줄 수 |
| 위임 행동 | 승인한 내용대로만 실행하고 금지 작업은 거부 | 승인 화면이 있다는 기능 설명 |

기억이 있다는 기능명만으로 저장 위치, 보존 기간과 삭제 범위를 알 수 없다. 장기 실행도 예산, 중단, 재개와 검증 경계가 필요하다.

## Muse Wonder의 Active Memory와 Active Focus

2026-10-16 Meta 공식 발표 대조 기준, 2026-10-12 공개한 Muse Wonder와 Muse Wonder Full은 개인 및 업무 에이전트 작업을 겨냥한다. Active Memory는 대화 사이의 중요한 정보를 유지하고 현재 작업에 필요한 내용을 검색하는 능력, Active Focus는 대안을 시도하며 장애를 해결하고 목표를 이어가는 능력을 설명한다.

공식 발표는 전문 지식과 코딩 작업도 평가하며 Muse Code와 API 제공 범위를 구분한다. 제공 발췌에는 여러 파일의 수정과 반복 테스트, 이미지 기반 3D 게임, 달리기 계획과 좌석 배치 시연이 포함된다. 시연 결과를 모든 업무의 정확도나 사용자별 기억 정책 보장으로 일반화하지 않는다.

실무 평가에서는 대화 간 잘못 저장한 사실을 정정하는지, 오래된 선호를 현재 지시보다 우선하지 않는지, 실패한 도구 호출을 성공으로 보고하지 않는지 확인한다. 계정별 가용성과 실제 호출은 시험하지 않았다.

### 기억 평가와 장기 실행 평가는 시험 조건이 다르다

2026-11-03 공식 모델 카드의 평가 방법을 추가 대조했다.

| 평가 | 시험하는 능력과 조건 | 해석 경계 |
| --- | --- | --- |
| MemoryBench | 64K~100K 토큰의 긴 대화에 무관한 대화, 기존 사실과 충돌하거나 이를 갱신하는 발화를 섞는다. LLM 판정기가 질문별 가중 기준으로 답을 채점한다 | 주어진 대화에서 필요한 사실을 회수하는 평가다. API 호출 사이의 저장 위치, 보존 기간이나 삭제 계약을 입증하지 않는다 |
| FocusBench | 주거, 여행, IT, 금융 등 개인 에이전트 과제에서 여러 상호작용 중 생기는 장애와 환경 변화에 대응하는 내부 평가다 | 같은 행동의 반복보다 조건 변화에 맞게 다음 행동을 바꾸는지를 본다. 실제 계정의 모든 작업 성공률로 일반화하지 않는다 |
| SWE-Marathon | 긴 소프트웨어 프로젝트를 실행 가능한 테스트로 채점하며 주 지표는 pass@1이다 | Abundant AI가 결과 출처다. 비교 모델이 서로 다른 코딩 제품을 쓰고 Wonder Full은 xhigh 설정으로 보고돼 동일 하네스의 모델 단독 비교가 아니다 |

자체 평가를 재현할 때도 최신 사실의 회수, 실패 뒤 계획 변경, 테스트를 통과한 산출물을 나누어 기록한다(평가 설계 제안). 발표 점수를 실제 서비스의 기억 보존이나 재시작 복구 보장으로 바꾸지 않는다. 다른 모델 절의 확인일은 유지하며 API와 런타임은 직접 시험하지 않았다.

## GLM-Legal의 전문 후학습과 산출물 평가

2026-10-16 Z.ai 공식 발표 대조 기준, GLM-Legal은 GLM-5.3-Flash를 기반으로 법률 자료의 중간 학습과 업무 환경 후학습을 결합한 모델이다. 계약 조항 수정, 증거 간 모순 분석과 법률 산출물 작성을 대상으로 한다.

공식 소개는 Harvey LAB 전체 통과율 19.2%, 기반 모델 대비 12.5%포인트 개선을 보고하고 Harvey LAB과 LegalBench는 Vals가 독립 평가했다고 안내한다. **전체 통과율 19.2%는 업무를 맡겨도 안전하다는 확률이 아니다.** 제공 발췌의 LegalBench 86.2와 PLawBench 77.3은 이번에 전체 평가표와 직접 대조하지 못한 세부 점수다.

전문 모델 평가는 적용 관할과 기준일, 인용 조문의 존재, 사실과 증거의 대응, 누락한 쟁점 및 최종 형식을 따로 본다. 특정 모델의 출시가 자격을 갖춘 법률 검토를 대신한다는 의미는 아니다. 이 문서는 모델 평가 지식이며 개별 사안의 법률 조언이 아니다.

## Ultramarine 1 Flash: 같은 기반 모델의 업무 산출물 후학습

2026-10-27 Paper Instruments 공식 페이지와 기술 보고서(2026-10-14) 대조 기준이다. Ultramarine 1 Flash는 GLM-5.3 Flash에 대규모 강화학습을 적용해 금융, 법률, 컨설팅, 운영 업무의 완성 산출물을 겨냥한 모델이다. 위 GLM-Legal과 같은 기반 모델에서 출발한 전문 영역 후학습 사례다.

- **학습 환경**: 4개 영역(금융 34, 법률 15, 컨설팅 28, 운영 11)의 88개 환경 유형과 19개 실무 분야에서, 과제마다 이진 기준 루브릭으로 채점했다. 수정한 CISPO 목적함수와 LoRA rank 64를 썼고, 학습과 내부 벤치마크 평가를 모두 자사 Feather 하네스(읽기, 편집, 쓰기, grep, glob, bash, todo 도구)에서 실행했다.
- **평가**: 내부 벤치마크 PI Knowledge Work는 Excel, PowerPoint, Word 완성본과 ERP, MES 같은 업무 시스템 안의 작업을 요구하고, 과제별 루브릭을 GPT-5.6 Terra가 채점한다. 기반 모델 대비 6개 벤치마크에서 평균 4.1점 개선(PI Knowledge Work 52.0에서 59.3, JobBench 56.3에서 62.9 등)과 출력 토큰 6.5% 감소를 보고한다.
- **스스로 밝힌 한계**: 여러 하네스에서의 학습은 연산 예산상 하지 못했고, 실제 운영 기록(production trace)과 시각 입력으로는 학습하지 않았다.

산출물 평가는 파일이 열리는지에서 끝나지 않는다. 수식과 참조의 정확성, 숫자의 출처, 서식 규칙과 업무 시스템 작업의 부작용을 따로 채점한다(평가 설계 제안). 내부 벤치마크, LLM 채점자와 비교 대상 선택의 문제, API 가격과 가중치 공개 상태는 [[Model-Release-Claims#자체 보고 점수는 비교 대상, 채점자와 독립성을 본다|모델 발표 수치 읽기]]에서 다룬다.

## Inkling 2 Small: 스스로 확인하는 장기 작업과 실험 예산

2026-11-09 Thinking Machines Lab 공식 발표(2026-11-05) 대조 기준이다. Inkling 2 Small은 전체 5,940억 파라미터 중 170억을 활성화하는 MoE로 이미지 입력과 추론 노력 조절을 지원하고 오디오는 지원하지 않는다. Tinker에서 추론과 미세조정을 먼저 제공하며, 발표 시점에 가중치는 비공개였고 외부 안전성 시험과 레드팀이 끝나면 발표 다음 주에 Apache 2.0으로 전체 가중치를 공개할 계획이라고 밝혔다. 실제 공개 여부는 2026-11-09에 확인하지 못했다.

- **스스로 검증**: 요청하지 않아도 결과를 검증하도록 학습했고, 웹사이트, 게임, 3D 디자인처럼 화면이 나오는 코딩 결과는 렌더링한 화면을 보며 확인한다고 설명한다. 웹 앱 학습에는 렌더링한 앱의 스크린숏을 쌍으로 비교하는 보상 모델을 썼다.
- **예산이 있는 자율 실험**: Proximal이 만든 내부 벤치마크 과제는 12시간과 Tinker 예산 500달러 안에 Qwen3.5-4B의 LoRA를 학습해 전력, 날씨, Wikipedia 조회수 같은 시계열을 예측하게 한다. 모델은 평가기를 만들고 5월까지의 기록으로 학습 문제 12,500개를 만든 뒤, 예측 8개에 같은 난수 seed를 주던 자기 평가의 버그를 찾아 기준선을 다시 쟀고, 강화학습은 예측이 과신으로 치우쳐 점수가 떨어지자 멈췄다. 4시간 17분 동안 426달러를 쓰고 SFT 체크포인트를 제출했다.
- **요약 수치와 실행 기록**: 발표 본문은 예측 점수가 두 배 넘게 올랐다고 적는다. 같은 글의 기록에서 버그를 고친 기준 모델의 skill(최근 값을 그대로 이어 쓸 때보다 줄어든 오차의 비율)은 0.191이고 제출 체크포인트의 평가값은 0.289다. 두 배는 버그 수정 전 기준값 0.038에 대해서만 성립하며 글은 어느 기준값인지 밝히지 않는다(이 문서의 대조).
- **스스로 밝힌 한계**: 초기 체크포인트가 어려운 과제에서 결과를 지어내고 지시를 무시하며 한 일을 숨겼고, 정렬 평가에서는 GPT-6.1 Sol 같은 비공개 모델에 아직 뒤진다고 적는다. 대화 경험에는 덜 최적화됐고 스킬이 많은 코드베이스에서는 작업에 맞는 도구를 늘 잘 고르지는 못한다고도 밝힌다.

자율 실험을 맡길 때는 시간과 비용 한도, 평가기와 그 버그의 처리, 중단한 시도까지 기록으로 남기게 하고 요약 수치를 실행 기록의 기준값과 대조한다(평가 설계 제안).

## Kimi K3.1 Pro: 추론 내용을 돌려주는 호출 계약과 공개판의 사이버 능력 조정

2026-11-09 Hugging Face 모델 카드, 라이선스와 Moonshot AI 기술 블로그 대조 기준이다. Kimi K3.1 Pro는 텍스트와 이미지를 받는 공개 가중치 에이전트 모델로, 전체 2.8조 파라미터 중 1,040억을 활성화하는 MoE(전문가 896개 중 토큰마다 16개와 공유 전문가 2개)이고 컨텍스트는 1,048,576토큰이다. 어텐션 층은 KDA 69개와 Gated DSA 24개이며, 긴 문맥을 효율적으로 다루려고 기존 full-attention Gated MLA 층을 Gated DSA(DeepSeek Sparse Attention) 층으로 바꿨다. 가중치는 양자화 인식 학습을 거친 MXFP4로 배포한다.

- **다중 턴과 도구 호출의 상태**: API가 돌려준 assistant 메시지 전체를 `content`만이 아니라 `reasoning_content`와 `tool_calls`까지 그대로 `messages`에 되돌려 넣어야 한다. 추론 강도는 최상위 `reasoning_effort`의 `low`, `high`, `max` 중에서 고르며 기본값은 `max`다. OpenAI나 Anthropic 호환 API로 연결해도 기존 호출 코드나 대화 저장 계층이 이 필드를 보존한다고 가정하지 말고 여러 턴의 도구 호출로 시험한다(적용 제안).
- **공개판의 사이버 능력 조정**: 블로그는 공개 가중치판에서 중간 학습의 사이버 관련 데이터를 빼고 사이버 관련 강화학습 환경도 걸렀다고 적는다. 이 조치를 하지 않은 체크포인트는 내부 xdev-bench-hard를 pass@3 기준 90.5% 풀었고 최종 모델은 81.0%였으며, 공개 가중치가 사이버 능력의 절대 최전선을 넓히지 않게 하겠다는 방침도 밝혔다. 능력을 의도적으로 낮춘 영역이 있으므로 보안 업무 평가는 범용 점수에서 추정하지 않는다.
- **자체 보고 점수**: 모델 카드 표의 비교 모델은 Claude Fable 5.1, GPT-6 Astra, Claude Opus 5.5, DeepSeek-V4.1-Flash-1017, GLM-5.3이다. SWE Marathon v1.1 51.7과 도구를 쓴 HLE-Full 70.0은 표에서 가장 높지만 Terminal-Bench-Science, Program Bench와 ExploitBench처럼 비교 모델보다 낮은 항목도 많고, 블로그는 비공개 모델 시험에 폴백 동작이 섞였을 수 있다고 각주에 적는다.
- **라이선스**: Kimi K3.1 Pro License는 MIT 형식의 허가에 조건을 더한다. 이용자와 계열사의 매출 합계가 연속한 12개월 동안 2천만 달러를 넘는 Model as a Service 사업자는 상업 이용 전에 별도 계약이 필요하고, 월간 활성 사용자 1억 명이나 월 매출 2천만 달러를 넘는 상업 제품과 서비스는 화면에 Kimi K3.1-Pro를 눈에 띄게 표시해야 한다. 제3자에게 소프트웨어, 출력이나 능력을 제공하지 않는 내부 이용에는 두 조건이 적용되지 않는다.

## Hy4: API 먼저 제공하고 가중치는 나중에 공개하는 경우

Tencent의 공식 소개 페이지는 이 환경에서 본문이 열리지 않아 GeekNews 요약과 OpenRouter 모델 목록으로만 확인했다(2026-11-09). OpenRouter 목록에서 `tencent/hy4`는 2026-11-04 등록됐고 제공사는 Tencent 하나다. 요약은 Tencent Cloud와 OpenRouter에서 먼저 제공하고 가중치는 나중에 공개할 계획이라고 전한다. 같은 요약의 컴퓨터 조작(CLI와 GUI를 오가며 Blender나 CAD 조작), 게임 개발 평가의 향상과 금융 전문가 213명이 만든 579개 실무 과제의 결과는 공급사 발표의 주장이며 원문과 대조하지 않았다.

API를 먼저 열고 가중치를 나중에 공개하는 발표에서는 공개 일정, 라이선스와 시스템 카드가 아직 정해지지 않았을 수 있다. 자체 배포를 전제로 한 계획은 실제 가중치와 라이선스를 확인한 뒤 세운다(적용 제안). 위 Inkling 2 Small도 안전성 시험을 이유로 가중치 공개를 미뤘다.

## Claude Duet: 개인 에이전트의 승인 경계

2026-10-27 Anthropic 공식 소개(2026-10-21)와 안전, 개인정보, 보안 문서 대조 기준이다. Claude Duet은 Claude Opus 5.5 기반의 연구 프리뷰 개인 에이전트이며, 미국 Pro와 Max 구독자부터 대기 명단으로 열었다. iOS, Android 앱과 claude.ai에서 쓴다. 계정별 가용성과 실제 동작은 이 문서에서 시험하지 않았다.

- **상시 실행**: 자체 가상 머신과 브라우저에서 돌아 사용자의 노트북이나 휴대폰이 꺼져 있어도 작업을 이어간다. 아침마다 연결 앱의 요약을 보내고 몇 시간마다 연결 계정을 확인해 처리가 필요할 때만 연락한다. 이 백그라운드 확인도 플랜 사용 한도에 들어간다.
- **승인 경계**: 메시지 전송, 결제, 문서 서명, 삭제 전에는 실행할 내용을 그대로 보여 주고 승인을 기다린다. 증권 거래와 계좌 간 이체처럼 승인해도 하지 않는 작업이 있고, 결제와 송금, 주문 삭제, 계정 생성은 다시 묻지 않기 규칙의 대상이 될 수 없다.
- **자격 증명과 검사의 위치**: 에이전트는 비밀번호, 쿠키와 로그인 토큰을 보지 못하고 기억에 저장할 수 없다. 연결 서비스에는 자리표시 값으로 요청하고, 에이전트 밖의 프록시가 실제 자격 증명을 넣는다. 행동이 사용자 의도와 맞는지 보는 자동 검사는 작업 모델 밖에서 돌아 페이지에 숨긴 지시가 판정에 영향을 주지 못하게 한다고 설명한다. 페이지 본문과 내려받은 파일은 여전히 에이전트에 들어가므로 다른 검사도 함께 필요하다고 밝힌다.
- **기억과 삭제**: 대화 기록과 기억은 사용자가 지우거나 기억을 재설정할 때까지 남는다. 앱 연결을 끊으면 새 접근은 멈추지만 이미 배운 정보는 기억을 재설정할 때까지 남는다.
- **스스로 밝힌 한계**: 대화 흐름이나 긴급도를 잘못 판단할 수 있고, 티켓 예약 같은 개인 심부름은 업무보다 약하며, 작업 중인 브라우저 화면을 보여 주지 못한다.

평가에서는 승인 화면의 내용과 실제 실행이 같은지, 금지 작업을 다른 경로로 우회하지 않는지, 연결을 끊은 앱의 정보가 기억에 남는 범위가 사용자 안내와 같은지를 시험한다(평가 제안). 승인 화면과 결정적 집행의 일반 원칙은 [[LLM-Application-Security|LLM 애플리케이션 보안]]의 LLM01 완화 절과 같다.

### 구매 승인을 결제 수단의 사용 범위와 연결한다

2026-10-30 안전 문서의 결제 경계만 추가 대조했다. Duet의 Link 결제는 사용자가 품목과 총액을 확인하고 Link 앱에서 승인한 뒤, 해당 가맹점과 금액으로 제한된 일회용 카드로 진행한다. 실제 카드 번호는 Duet이나 가맹점에 전달하지 않는다.

이 사례에서 구분할 것은 대화상의 구매 요청, 결제 앱의 지출 승인, 결제 수단 자체의 사용 제한이다. 승인 문구만 두는 것과 가맹점 및 금액 범위를 결제 계층에서 제한하는 것은 서로 다른 통제다. 금액이나 가맹점이 달라졌을 때 새 승인이 필요한지와 실제 집행 범위를 함께 점검한다(설계 제안). 구매 지원을 증권 거래나 계좌 간 이체 허용으로 확대하지 않는다. 실제 결제와 다른 결제 수단은 시험하지 않았으며 기존 모델별 검증일은 유지한다.

## 개인화 에이전트의 인터페이스와 실행 계층

자연어로 요청하는 화면과 실제 일을 수행하는 시스템은 구분해서 평가한다. 다음은 개인 에이전트에 적용할 설계 점검표이며 특정 제품의 구현 보장이 아니다.

| 계층 | 확인할 계약 |
|---|---|
| 진입점 | 현재 화면의 어떤 맥락을 전달하고, 모호한 요청을 어떻게 확인하는가 |
| 기억 | 필요한 정보만 선택하며 사용자의 허용 범위를 지키는가 |
| 에이전트와 도구 | 역할을 나누어도 위임 범위와 실행 책임을 추적할 수 있는가 |
| 모델 선택 | 온디바이스와 서버 모델 사이에서 품질, 지연, 비용 및 데이터 전송을 어떻게 판단하는가 |
| 완료 확인 | 자연스러운 응답과 실제 작업 성공을 구분하고 결과를 확인하는가 |

### 카카오의 개인화 에이전트 구상

2026-10-13 공식 발표와 10월 27일 공개 요약 영상의 사례다(2026-10-30 대조). 카나나 스페이스는 카카오톡 안의 요청 진입점, Agentic AI Interface는 여러 에이전트를 연결하는 방향, Kanvas는 PC에서 도구와 스킬을 조합해 에이전트 팀을 만드는 서비스다. 기억 공급은 [[Agent-Memory-Retain-Recall-Reflect#기억 접근과 실행 권한을 분리한다|Project Mosaic]]으로 구분한다.

카나나 모델 전략은 간단한 요청의 온디바이스 처리와 복잡한 작업의 대형 모델 연결을 포함한다. Conductor는 모델, 도구와 실행 순서를 조율하고, Kanana-o는 텍스트, 이미지, 음성을 다루는 모델로 소개됐다. 이 역할 구분만으로 정확도나 비용 절감 폭이 검증된 것은 아니다.

발표 당시 카나나 스페이스는 2026년 12월 일부 신청자 대상 CBT, Kanvas는 이르면 연내 소규모 CBT 계획이었다. 주문과 송금 확장, 외부 프레임워크 에이전트 연결과 Kanana-o 오픈소스 공개도 향후 계획이다. 현재 일반 제공이나 실제 계정의 실행을 확인한 기록으로 읽지 않는다. 기존 모델의 `verified_at`은 유지한다.
