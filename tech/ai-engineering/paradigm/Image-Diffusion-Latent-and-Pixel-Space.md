# 이미지 생성 모델의 잠재 공간과 픽셀 공간

이미지 확산 모델은 노이즈를 단계적으로 걷어 내며 이미지를 만든다. 이 계산을 압축한 잠재 공간에서 할지 픽셀 공간에서 직접 할지에 따라 학습 비용, 해상도별 토큰 수와 결과의 한계가 함께 달라진다. 이 문서는 두 방식의 차이와, 저비용 학습을 내세운 모델 발표를 읽는 기준을 정리한다.

## 잠재 공간 확산은 압축을 먼저 학습한다

Latent Diffusion 논문(Rombach 외, CVPR 2022)은 픽셀 공간의 확산 모델 학습이 수백 GPU일을 쓰고 순차 평가 때문에 추론도 비싸다는 문제를 들어, 미리 학습한 오토인코더의 잠재 공간에서 확산 모델을 학습했다. 논문은 이 표현에서 처음으로 복잡도 감소와 세부 보존 사이의 거의 최적 지점에 이른다고 주장한다.

흐름은 이미지를 인코더(VAE 등)로 잠재 표현으로 바꾸고, 확산 모델이 잠재 표현을 생성한 뒤, 디코더가 다시 이미지로 바꾸는 순서다. 압축과 생성을 따로 학습하므로 압축 단계의 설계가 생성기가 다룰 수 있는 표현을 먼저 정한다. 상품 사진 편집에서 쓰는 VAE 인코딩 단계는 [[Generative-Product-Image-Workflow|생성형 상품 이미지 워크플로우]]에 있다.

## 픽셀 공간 확산은 큰 패치로 토큰 수를 줄인다

JiT 논문(Li와 He, 2025-11 arXiv)은 깨끗한 데이터를 예측하는 것과 노이즈가 섞인 양을 예측하는 것이 근본적으로 다르다고 본다. 자연 데이터는 저차원 다양체 위에 있다는 가정에서 깨끗한 이미지를 직접 예측하게 하면 용량이 작아 보이는 망도 고차원 픽셀 공간에서 작동한다고 주장하며, 고차원의 노이즈 섞인 양을 예측하면 크게 실패할 수 있다고 적는다. 토크나이저, 사전학습과 추가 손실 없이 픽셀 위의 큰 패치(16, 32) Transformer로 ImageNet 256과 512 해상도에서 경쟁력 있는 결과를 보고했다.

토큰 수는 (높이 / 패치 변) × (너비 / 패치 변)이다. 512×512 이미지는 32×32 패치로 256토큰, 16×16 패치로 1,024토큰이 된다. 패치 변을 두 배로 키우면 같은 해상도의 토큰 수는 4분의 1로 준다(이 문서의 계산). 어텐션 계산량은 토큰 수와 함께 커지므로 해상도를 올리는 계획은 패치 크기와 함께 세운다.

| 구분 | 잠재 공간 확산 | 픽셀 공간 확산 |
|---|---|---|
| 압축 | 별도로 학습한 오토인코더 | 생성 모델 안의 패치 표현 |
| 토큰 수를 줄이는 수단 | 인코더의 공간 압축과 잠재 패치 | 큰 픽셀 패치 |
| 먼저 확인할 것 | 오토인코더의 복원 품질과 압축률 | 패치 크기, 예측 대상과 해상도별 토큰 수 |

## 사례: Linum의 P-JiT

2026-11-09 Linum 공식 연구 노트(2026-11-04)와 Hugging Face 모델 페이지 대조 기준이다. Linum은 다음 영상 모델로 가는 개념 검증으로 P-JiT를 학습하고 코드와 가중치를 Apache 2.0으로 공개했다. 아래 수치는 공급사가 보고한 값이며 이 문서에서 실행하거나 재현하지 않았다.

- **구조**: 별도 VAE 없이 픽셀 공간에서 압축과 생성을 함께 학습한다. 이미지를 32×32 패치로 나눠 1,024차원으로 압축하며, Wan VAE와 DiT를 쓴 이전 Linum v2의 16×16 토큰 축소보다 어텐션 문맥이 4분의 1이다. 512² 이미지를 이전에 256² 이미지에 쓰던 토큰 수로 나타낸다.
- **크기**: 생성기는 샘플링 기준 21.8억 파라미터이고 학습 전용 헤드 약 2.4억을 더하면 약 24.2억이다. 텍스트 표현은 고정한 Qwen3.5-4B에서 가져오며 따로 내려받는다. 생성기 파라미터 수에 텍스트 인코더가 빠져 있으므로 실행 메모리는 둘을 더해 계산한다.
- **학습비**: 약 21,038달러는 사전학습 8,139 H100시간(H100 64장, 재시작 포함)과 사후학습 276 H100시간을 H100 시간당 2.50달러로 환산한 값이다. 학습 샘플은 512²에서 6억 1,027만 개, 1024²에서 4,997만 개다. 글은 이 금액에 ablation, 이전 실험이나 데이터 처리가 들어갔는지 밝히지 않는다.
- **수렴 주장**: Linum v2보다 11배 적은 샘플로 수렴했다고 적지만, 글에 보고된 평가 지표는 단계별 해상도의 정사각형 이미지 20,480장으로 잰 고정 검증 손실이고 FID나 사람 선호 평가는 없다. 수렴 속도와 생성 품질은 따로 확인한다.
- **데이터 선택이 만든 공백**: 렌더링한 글자, 인포그래픽, PDF와 슬라이드 같은 글자 중심 데이터를 모두 걸러 글자나 포스터를 만들지 못한다. 전신 인물, 군중처럼 개체가 많은 장면, 여러 사람의 상호작용과 세계 지식도 약하다고 밝힌다.

## 저비용 학습 발표를 읽는 기준

- **금액의 정의**: GPU 시간에 단가를 곱한 환산값인지 실제 청구액인지, 재시작, ablation, 실패한 실험, 데이터 처리와 인건비가 들어갔는지 확인한다.
- **파라미터의 범위**: 텍스트 인코더, 업샘플러처럼 함께 돌려야 하는 모델이 빠졌는지 본다([[Model-Release-Claims#파라미터 수는 무엇을 셌는지 확인한다|파라미터 수는 무엇을 셌는지]]).
- **지표의 종류**: 수렴 속도를 잰 지표(검증 손실 등)와 생성 품질 지표가 같은지 본다. 손실 값은 예측 대상, 표현 공간과 검증 데이터가 같은 모델끼리만 직접 비교한다(이 문서의 판단).
- **뺀 데이터와 필요한 능력**: 학습 데이터에서 걸러 낸 범주가 업무에 필요한 능력(글자 렌더링 등)과 겹치는지 먼저 본다.
- **공개 범위**: 코드와 가중치의 라이선스, 함께 써야 하는 모델의 라이선스를 각각 확인한다.
