# 에너지 기반 추론과 제약 검증

에너지 기반 모델(EBM)은 입력과 후보 상태의 조합에 스칼라 점수를 부여한다. 추론은 관측한 입력을 고정하고 낮은 에너지를 갖는 후보를 찾는 과정이다. 여기서 에너지는 전력 소비량이 아니라 학습한 적합성 점수다.

## 학습과 탐색을 구분한다

입력을 `x`, 답을 `y`, 잠재 변수를 `z`라 하면 에너지 함수를 `E(x, y, z)`로 나타낼 수 있다. 잠재 변수가 필요 없는 구성은 `E(x, y)`로 생각할 수 있다.

| 단계 | 바꾸는 것 | 목적 |
|---|---|---|
| 학습 | 에너지 함수의 파라미터 | 바람직한 상태의 에너지가 상대적으로 낮아지도록 만든다 |
| 추론 | 후보 답과 필요한 잠재 상태 | 주어진 입력에서 낮은 에너지의 구성을 찾는다 |

대조적인 학습은 원하는 상태의 점수를 낮추고 원하지 않는 상태의 점수를 높이는 방법이다. NYU의 예제에서는 원하는 상태의 에너지만 낮추는 손실이 모든 입력에 같은 점수를 주는 붕괴를 일으켰고, margin loss가 이를 막았다. 이를 모든 EBM이 같은 손실이나 음성 샘플링 방법을 써야 한다는 뜻으로 확대하지 않는다.

EBM이라는 분류만으로 연속 잠재 공간이나 경사하강법 사용을 가정하지 않는다. 변수의 표현, 에너지 함수와 탐색 방법을 함께 확인한다.

## 에너지 기반 추론 모델의 구성 예시

EBRM은 에너지로 답이나 중간 추론 상태를 평가하고 수정하는 구성이다. 공개된 Kona 설계 설명은 연속 잠재 공간의 추론 경로를 전체적으로 평가하고, 근사 gradient 정보로 일부 상태를 고치는 방식을 제시한다. LLM은 자연어 입출력과 조정을, 별도 추론 모델은 제약을 다루게 하는 조합도 제시한다. 이는 공급사가 공개한 설계 설명이며 내부 학습 코드와 실제 실행을 재현한 결과는 아니다.

자기회귀 토큰 생성과 비교할 핵심은 이름보다 수정 단위다. 이전 선택을 바꿀 때 무엇을 다시 계산하는지, 중간 상태를 어떻게 평가하는지, 최종 결과를 어떤 검사기가 받아들이는지 확인한다. EBRM의 장점을 곧바로 모든 LLM 기반 시스템의 한계로 옮기지 않는다.

## 낮은 에너지와 정답 증명은 다르다

학습한 점수가 낮다는 사실과 명시한 제약을 만족했다는 사실은 구분해야 한다. 다음은 제약이 명확한 과제에 적용하는 설계 제안이다.

1. 문제의 입력 조건과 허용할 결과를 정한다.
2. 모델이나 탐색기가 후보를 만든다.
3. 별도 검사기가 제약을 확인한다.
4. 실패하면 정해 둔 시간과 반복 예산 안에서 다시 탐색한다. 예산이 끝나면 미해결로 반환한다.

스도쿠에서는 행, 열과 작은 격자의 중복 여부뿐 아니라 처음 주어진 숫자를 보존했는지도 검사한다. 검사기를 통과해도 검사하지 않은 조건까지 맞았다는 뜻은 아니다. 같은 구조를 일정 배정에 적용한다면 중복 배정 금지와 근무 시간 상한 등 실제 요구를 먼저 계약으로 만들어야 한다(설명용 예시).

## 성능 비교는 과제와 실행 조건을 보존한다

2026-02-03 공개된 공급사 데모 보고는 어려운 스도쿠에서 Kona의 해결률 96.2%, 평균 313ms와 비교 LLM 집단의 해결률 약 2%를 제시했다. 비교한 모델은 GPT-5.2, Claude Opus 4.5와 Sonnet 4.5, Gemini 3 Pro, DeepSeek V3.2이며 코드 실행을 끄고 LLM을 스도쿠에 미세조정하지 않은 조건이었다. 2026-10-22에 이 발표를 확인했으며 현재 모델 순위로 해석하지 않는다.

이 수치는 공급사의 자기 보고다. 학습 노출, 전체 실행 설정과 독립 재현을 확인하지 않았으므로 아키텍처만의 인과 효과를 확정하지 않는다. 코드 실행을 허용한 LLM과 일반 제약 솔버의 비교도 별도로 필요하다. GPU 실행비와 API 청구액은 비용 범위가 다르므로 이를 바로 운영 총비용 절감률로 환산하지 않는다(비교 설계상의 판단).

## 적용 전에 확인할 것

- 정답 조건을 기계가 판정할 수 있는가. 자연어 요청을 제약으로 옮기는 단계의 누락은 어떻게 찾는가.
- 에너지 감소가 실제 제약 위반 감소와 연결되는가. 다른 분포의 입력에서도 검사기로 확인했는가.
- 학습 데이터와 추론 비용, 검사 비용, 재시도와 실패를 같은 범위로 계산했는가.
- 기존 솔버나 LLM과 도구의 조합보다 나은지 같은 문제와 시간 예산으로 비교했는가.

이 목록은 도입 평가를 위한 제안이며 특정 업무에 EBRM을 채택하라는 결정은 아니다. 상업 제품의 가용성, 가격과 운영 신뢰성은 여기서 검증하지 않았다.
