# AI 도구, 자동화와 학습

AI를 도구로 부를지 자동화로 부를지는 용어의 정의에 따라 달라진다. 실제 적용에서는 사람이 무엇을 직접 수행하고 무엇을 위임하는지, 결과를 통제하고 검토할 방법이 무엇인지 적는 편이 유용하다. 편의와 산출, 독립 수행 능력을 따로 평가한다.

## 두 정의를 같은 사실 판단으로 착각하지 않는다

| 관점 | 강조점 | 확인할 질문 |
|---|---|---|
| 직접 통제하는 도구와 자동화의 구분 | AI가 수행 과정을 대신하면 그 과정의 감각적 피드백과 연습이 줄 수 있음 | 직접 판단하고 수정하는 구간은 어디에 남는가 |
| 목적에 사용하는 넓은 의미의 도구 | 자동화 기능이 있어도 사람이 지시하고 오류를 해석하며 결과를 고칠 수 있음 | 목적에 맞게 다루고 실패를 발견하는 능력이 있는가 |

Rich Hickey의 'AI' is Not a Tool은 첫 관점에서 통제, 예측 가능성과 숙련 형성을 문제 삼는다. AI Is a Tool. Using It Well Takes Skill.은 두 번째 관점에서 자동화와 도구가 양립하며 품질의 한계가 도구 여부를 결정하지 않는다고 반박한다. 두 글은 서로 다른 정의를 사용하는 논증이다. 명칭만으로 유용성, 안전성이나 학습 효과가 증명되지는 않는다(2026-10-16 두 원문 확인).

## 위임할 때 남길 세 가지

1. 목적과 좋은 결과의 기준을 사람이 설명한다.
2. 결과를 원문, 실행과 외부 기준에 대조한다.
3. 배우려는 부분은 도움 없이 다시 설명하거나 수행한다.

코드가 실행되고 설명이 유창해도 사용자의 이해가 늘었다고 판단하지 않는다. 반대로 AI를 사용했다는 사실만으로 직접 사고가 사라졌다고 평가하지 않는다. 실제 사용 방식과 독립 수행 결과로 확인한다.

## 창작 노동과 연습의 가치

프로그래밍의 기능적 결과와 표현, API 경험 및 문제를 다듬는 과정은 함께 평가할 수 있다. 일상적인 구현도 숙련을 쌓는 기회이므로 반복 작업을 자동화할 때 어떤 연습이 없어지는지 본다. 모든 반복 작업을 보존하거나 자동화를 금지해야 한다는 뜻은 아니다.

Programming Isn’t Special 에세이는 프로그래밍을 예술과 분리해 AI 사용만 다르게 정당화하기 어렵다고 논증한다. Deferred를 불편한 콜백 전달과 API 미학을 개선한 사례로 들며 평범한 창작 업무의 연습 기회를 강조한다. 이는 창작과 학습에 관한 가치 판단이지 AI 사용의 보편적인 금지 규칙이나 효과 추정이 아니다.

## 경제적 수요와 활동의 의미

생계를 위한 사고, 학습과 창작의 즐거움, 사회적 기여는 서로 연관되지만 같은 가치가 아니다. 어떤 일이 자동화될 수 있다는 전망만으로 그 활동이 무의미해지거나 개인이 즉시 진로를 포기해야 한다고 결론 내리지 않는다.

Thinking Will Become a Hobby 에세이는 성능, 비용과 가용성의 우위 때문에 인지 노동이 여가로 옮겨갈 수 있다고 전망한다. 사냥과 서예 등의 역사적 유추는 미래의 경로를 설명하는 비유이며 인지 노동 전체의 대체를 실증한 결과가 아니다. 인간 정보 처리 능력의 하락 주장과 전환 속도는 추가 근거 확인이 필요하다. 남는 책임, 업무 조건과 전환 비용을 실제 과제로 확인한다.

## 공급사 선택과 통제권

모델의 가중치 공개, 모델을 실행하는 사업자와 데이터를 보관하는 주체는 다른 선택이다. 오픈 웨이트를 외부 호스팅으로 쓰면 그 제공자의 데이터 처리와 운영을 확인해야 한다. 학습 사용 거부는 보관, 운영 접근과 재위탁까지 모두 금지한다는 뜻으로 확대하지 않는다.

제공된 OpenAI와 Anthropic을 단호히 거부하자 발췌는 공급사 의존, 접근 승인권과 개인정보에 대한 비판, 로컬 및 보안 인클레이브 대안을 제시한다. GLM-5.3과 Claude Opus 5.5의 유사 성능은 개인 경험이며 일반 평가가 아니다. 정치적 평가와 불매 권고는 출처의 의견이다. 해당 업체들의 현재 정책, 가격과 인클레이브 보장은 별도 검증하지 않았으므로 이 기록을 공급사 추천이나 보안 보증으로 쓰지 않는다.

후속 확인은 목표 과제의 동일 조건 평가, 실제 데이터 처리 약정과 로그, 실행 환경의 검증 범위다. 코드 생성에서 절약한 시간과 검토, 이해 회복에 필요한 시간을 함께 센다.
