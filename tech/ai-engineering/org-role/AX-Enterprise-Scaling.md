# 전사 AX 확산 — 플랫폼, 프로세스, 사람

좋은 AI를 들여오는 일보다 그 AI가 실제로 일할 수 있는 회사를 만드는 일이 어렵다. 전사 확산은 플랫폼(안전하게 쓸 수 있는 접근 기준과 기반), 프로세스(개인 생산성을 조직 성과로 잇는 재설계), 사람(사용 수준의 격차를 줄이는 변화관리)을 함께 움직일 때 정착한다. 조직 구조와 평가까지 바꾸는 변혁의 축은 [[AX-Transformation|AX 조직 전환]], 활용 측정은 [[AI-Adoption-Measurement|전사 AI 활용 측정]], 고객 현장의 업무 재설계는 [[FDE-AX-Delivery|FDE 기반 AX 수행]]에서 다룬다. 기업 사례는 2026년 9월 발표 기준의 회사 발표다.

## 확산 단계를 그리는 공급사의 틀

| 발표 | 단계 |
|---|---|
| OpenAI와 국내 IT 서비스 기업 | 개인 역량(업무 속도와 결과물 품질) → 팀 생산성(공유 지식과 협업) → 프로세스 혁신(장기, 반복 업무 자동화와 엔드투엔드 협업) → 전사 경쟁력(제품, 서비스, 운영 모델을 AI 중심으로 재설계) |
| Anthropic과 같은 기업 | 파일럿(상위 사용 사례, 거버넌스 틀, AI 리터러시와 초기 ROI) → 확산(팀 워크플로, 고객 응대, 인사, 재무 같은 핵심 프로세스, KPI와 내부 챔피언) → 전환(AI 중심 프로세스 재설계, 맞춤 앱과 새 수익원, 혁신 문화) → AI 네이티브(모든 결정과 프로세스의 AI, 파트너와 고객에게 AI 역량 제공, 새 사업 모델) |
| Google Cloud와 같은 기업 | 개인 생산성(어시스턴트의 검색, 조사, 생성) → 업무 단위 자동화(단일 에이전트) → 전사 혁신(에이전트 기반 워크플로와 오케스트레이션) |

세 틀은 모두 개인 도구 사용에서 출발해 프로세스 재설계를 거쳐 사업 모델의 변화로 끝난다. [[AX-Transformation#핵심 명제|AX 조직 전환]]의 사용, 도입, 전환 구분과 겹치지만 공급사가 고객을 다음 단계로 이끌려고 쓰는 틀이므로 단계의 경계와 기간은 표준이 아니다(해석). Anthropic 쪽 발표는 대부분의 한국 기업이 파일럿과 확산 사이에 있다고 했지만 근거 자료는 내놓지 않았다.

단계를 받치는 조건으로 OpenAI 쪽 발표는 리더십(확산 방향과 우선순위), 보안(데이터, 권한, 위험 통제), 현업 참여(변화 리더와 구성원), 성과 측정(사용, 생산성, 사업 KPI의 연결)을 들고, 이를 신뢰할 수 있는 보안, 측정 가능한 생산성, 지속 가능한 확산의 세 항으로 요약했다. Google Cloud 쪽 발표가 든 전사 규모의 요구도 같은 방향이다. 수천에서 수십만 명이 안정적으로 쓰는 규모와 그에 따른 용량, 비용, 성능 관리, ERP, SCM, CRM, MES 같은 핵심 시스템과 데이터의 연결, 시범 검증을 곧 운영으로 잇는 실행 속도, 거버넌스와 보안이다.

## 3P로 본 정체 신호

한 국내 IT 서비스 기업은 자사 AX를 플랫폼, 프로세스, 사람의 세 축(3P)으로 돌아봤다. 축마다 투자했는데도 남은 문제가 다음 과제가 됐다.

| 축 | 먼저 한 투자 | 남은 문제 |
|---|---|---|
| 플랫폼 | 최고 수준(SOTA) 기술 확보 | 불분명한 사용 기준과 원칙이 활용을 막았다 |
| 프로세스 | 엔드투엔드 시스템 연계와 데이터 표준 정비 | 사용 사례는 늘었지만 가시적 성과는 적었다 |
| 사람 | AI 현장 담당자와 전담 조직 신설 | 활용이 우수 사용자에게 몰렸다 |

같은 기업은 표준화, 디지털화되고 서로 연결된 업무 프로세스와 데이터를 AX의 출발점으로 둔다. 연결된 프로세스와 데이터가 있어야 AI가 판단과 실행에 참여할 수 있다는 뜻이다([[AI-Ready-ERP-Transformation|AI 활용 기반으로서의 ERP 전환]]).

## 플랫폼: 차단에서 관리로

외부 AI를 일률적으로 막던 조직이 관리하며 쓰는 쪽으로 옮길 때는 세 가지를 순서대로 정한다.

1. **무엇을:** 기밀 데이터를 정의하고 관리 대상을 확정한다.
2. **누가:** 기밀을 다루는 사람이 누구인지 파악한다.
3. **어떻게:** 기밀 데이터는 외부 AI에 넣지 않고, 인증된 기업용 계약을 맺은 서비스만 허용하는 기준과 통제 수단을 갖춘다.

데이터 등급별 허용 범위와 전송 전 차단 장치는 [[Agent-Governance-Controls#데이터 등급이 외부 AI 허용 범위를 정한다|데이터 등급이 외부 AI 허용 범위를 정한다]]에 있다. 위 기업은 이 기준을 근무 위치와 묶었다.

| 근무 유형 | 기준 |
|---|---|
| 사내 근무, 기밀 취급 | 내부 AI가 원칙이고 필요하면 가상 데스크톱(VDI)에서 외부 AI를 쓴다 |
| 사내 근무, 기밀 미취급 | 업무 환경에서 허용된 외부 AI를 자유롭게 쓰고 비용을 고려해 내부 AI와 섞어 쓴다 |
| 사외 근무(고객 현장) | 고객과 협의해 고객사에 GPU를 둔 설치형 AI를 쓰고, 고객이 허용하면 외부나 고객사 서비스를 쓴다 |

허용된 외부 서비스는 체크리스트 기반 보안 검증과 기업용 계약을 거친다. 사용자 쪽에서는 외부 접속과 개인 계정 사용을 막고 통합 인증으로만 들어오게 하며, 데이터 쪽에서는 사전 분류, 질의 필터링, 모니터링, 이상 탐지와 조치를 잇는다. 개인 계정을 막는 이유는 허용된 경로 밖의 사용이 통제와 기록에서 빠지기 때문이다(해석).

### 기업용 계약이 보장하는 것을 확인한다

보장 범위는 공급사 문서와 실제 계약으로 확인한다. 2026-11-23 대조한 OpenAI 기업용 개인정보 페이지(2026-01-08 갱신)는 ChatGPT Enterprise 등에서 기본적으로 업무 데이터를 학습에 쓰지 않고(명시적으로 공유에 동의한 경우는 예외), 저장 데이터를 AES-256으로, 전송 구간을 TLS 1.2 이상으로 암호화하며, SAML SSO, 세부 접근 통제, 관리자가 정하는 보존 기간(삭제한 대화는 법적 보존 의무가 없으면 30일 안에 제거), Enterprise Compliance API로 보는 대화와 GPT의 감사 로그를 제공한다고 적는다. 데이터 보관 위치는 이 페이지에서 다루지 않는다. 같은 회사의 도입 안내는 첫 초대를 보내기 전에 SSO와 기업용 작업 공간의 SCIM을 설정하라고 강하게 권한다. 페이지의 문구는 공급사의 약속이므로 계약서와 관리 콘솔의 실제 설정으로 확인한다(운영 제안).

### 바뀌는 구성요소를 표준으로 감싼다

모델의 구조와 능력, 에이전트 프레임워크, 대화형, 코파일럿, 에이전트 앱 같은 화면 방식, 온프레미스와 클라우드 인프라는 계속 바뀐다. 이 변화를 표준(공통 인터페이스와 프로토콜로 교체 비용을 줄인다), 자산(성공과 실패, 평가 결과를 쌓아 다음 개발에 쓴다), 운영(상태, 품질, 비용을 관측하며 고친다)의 세 축으로 관리하자는 제안이 있다. 연결 지점마다 표준을 두면 한쪽을 바꿔도 다른 쪽을 고치지 않아도 된다.

| 연결 | 표준 | 교체 효과 |
|---|---|---|
| 에이전트와 도구, 데이터 | [[MCP]] | 도구 교체 비용이 준다 |
| 서비스와 백엔드 | Open API(자료 표기, OpenAPI 명세인지는 자료에 없음) | 서비스를 바꿔 끼우기 쉽다 |
| 에이전트와 에이전트 | A2A([[A2A-CLI\|A2A CLI]]) | 공급사가 다른 에이전트와 연동한다 |
| 에이전트와 사용자 화면 | AG-UI | 에이전트와 일하는 화면 방식을 표준화한다 |

MCP는 2025-12-09 Linux Foundation이 만든 Agentic AI Foundation(AAIF)의 창립 프로젝트로 기증됐고, A2A는 2025-06-23 Linux Foundation 프로젝트가 됐다(각 보도자료 2026-11-23 대조). AG-UI 문서는 자신을 에이전트와 사용자 대면 애플리케이션을 잇는 이벤트 기반 개방 프로토콜로 소개하고, 사용자 상호작용은 AG-UI, 도구와 데이터는 MCP, 에이전트 사이는 A2A로 층을 나눈다. 중립 재단으로의 이관은 특정 공급사에 묶일 위험을 줄이는 근거지만 버전 호환과 보안 검토를 대신하지는 않는다(해석).

같은 제안은 노코드(업무 사용자), 로우코드(프로세스 설계자), 프로코드(개발자)와 코딩 에이전트로 만든 에이전트가 모두 같은 등록, 평가, 배포, 운영 절차를 거치게 한다. 만드는 방법이 달라도 운영 경로가 하나여야 [[Agent-Governance-Controls#자산은 등록과 공유를 나눈다|자산 등록과 공유]], 추적과 비용 통제가 같은 기준으로 걸린다(해석). 작업 식별자 하나로 요청, 에이전트 판단, 모델과 도구 결과, 사람 승인, 응답을 묶는 추적은 [[Agent-Governance-Controls|에이전트 거버넌스 통제]]에, 호출, 권한과 비용 경계를 거는 단일 접점은 [[LLM-Gateway|LLM 게이트웨이]]에, 요청별 모델 선택은 [[Agent-Governance-Controls#비용은 같은 관문에서 고르고 센다|관문의 모델 등급 선택]]과 [[LLM-Model-Tiers|모델 티어 선택]]에, DevOps 위에 프롬프트와 도구, 에이전트 메타데이터, 추적과 평가, 가드레일과 비용을 더하는 운영은 [[Agent-Operations-Foundations|에이전트 운영 기반]]에 있다. 자산 축의 예로, 레거시 코드 전환 에이전트가 분석, 변환, 검증을 반복하고 사람이 검수한 뒤 성공과 실패 패턴을 다음 전환의 자산으로 쌓는 흐름이 소개됐다([[Agentic-Legacy-Code-Conversion|에이전트 기반 레거시 코드 전환]]). 데이터도 같은 축에 있다. ERP, SCM 같은 정형 데이터와 문서, 메일 같은 비정형 데이터를 의미, 권한, 품질, 출처와 함께 연결해 에이전트가 근거로 쓰게 하고, 실행과 평가 이력을 다시 데이터 자산으로 쌓는다([[Agent-Ready-Data|에이전트가 쓰는 데이터]]).

## 프로세스: 개인 생산성을 조직 성과로 잇는다

개인의 업무 만족도와 단위 업무 지표가 좋아져도 회사의 엔드투엔드 업무 시간 같은 경영 성과는 크게 줄지 않을 수 있다. 위 기업은 그 원인으로 사내 규정과 절차, 협업과 역할 분담(R&R) 체계, 데이터 연결을 들고, 기존 업무에 AI를 더하는 수준이 아니라 AI를 전제로 한 프로세스가 필요하다고 정리했다. 승인 대기와 핸드오프가 그대로면 개인의 산출 속도만 오른다는 [[AX-Transformation#문화와 시스템이 AI 효과를 좌우하는 조건|문화와 시스템 조건]]과 같은 관찰이다(해석).

대상은 마케팅에서 경영지원까지의 가치사슬을 L5 단위 업무까지 내린 뒤 사업 가치와 실현 가능성의 곱으로 1차 선별하고, 고른 업무를 재설계하면서 에이전트를 붙이는 순서로 정한다. 아래 두 재설계의 공통점은 사람이 하던 점검과 합의를 에이전트의 협업 구조로 옮기고 사람을 예외와 사후 검증에 남긴 것이다.

- **제안 지원:** 담당자의 경험과 역량에 따라 품질이 갈리던 사람 중심 절차를 사람과 AI의 협업 절차로 표준화하는 재설계다(자료는 To-Be 절차로 제시했고 적용을 마쳤는지는 밝히지 않았다). 에이전트가 시장과 RFP 분석, 사례 검색, 초안 생성을 맡고 앞 단계 결과를 자동으로 이어 받으며, 사람은 검토와 승인, 차별화 전략에 집중한다. 기존 제안서, 회의록, 상품 자료 같은 비정형 문서와 고객사 기본 정보, 사업 실적 같은 정형 데이터를 함께 연결하는 구성이다.
- **경비 처리:** 영수증 이미지를 OCR과 VLM으로 읽고, 검증 에이전트가 오타를 고치며, 신규와 특이 건은 LLM이 판단하고, 금액 일치와 계정 허용 여부를 확인해 자동 승인하거나 사유와 함께 반려한다. 사람은 이의 신청 건과 월 1회 LLM 사후 검증 결과를 본다. 다른 발표는 같은 업무를 에이전트가 증빙 인식, 규정 판단(적격, 조건부, 부적격), 계정 분류, 예외 판별을 하고 RPA가 경비 시스템 입력, 증빙 첨부, 결과 회신을 맡는 분업으로 설명했다. 판단은 에이전트에, 정해진 화면 입력은 RPA에 둔다.

자동 승인분은 사람이 보지 않으므로 표본 감사와 사후 검증 주기를 따로 정한다(운영 제안, [[Citizen-Development-AI#사례: 치과 업무의 로컬 AI 자동화|자동 확정분의 표본 감사]]).

## 사람: 상향 평준화와 수준별 변화관리

사용량이 일부에 몰린 조직의 변화관리는 두 갈래다. 위 기업은 상위 5%가 사용량의 52%를 쓰고 하위 50%는 1%에 못 미치는 분포에서, 상위 사용자에게는 토큰 효율화 모범 사례를, 나머지에게는 활용 모범 사례 전파와 역량 강화를 적용해 비용 최적화와 성과 확대를 함께 노린다고 밝혔다. 같은 기업의 설문에서 단순 대화형 사용자는 교육 강화(44%)와 모범 사례 공유(40%)를, 고급 사용자는 토큰 확대(33%), 교육 강화(28%), API 연계(22%)를 주로 원했다. 수준에 따라 필요한 지원이 다르다.

| 단계 | 목표 | 과정 예 |
|---|---|---|
| 1. AI 기반 업무 리딩 | AI 개념 이해와 서비스 도구 활용 | 생성형 AI의 원리와 활용법, 외부 AI 실습 |
| 2. AI 기반 개발 리딩 | AI 기본 기술로 개발 생산성 향상 | 분야별 AI 기술, 코드 에이전트 과정 |
| 3. AI 소프트웨어 개발 리딩 | AI 심화 기술로 AI 소프트웨어 구축 | AX 전문가 과정, 자사형 FDE 양성 |
| 4. AI 사업 리딩 | 대규모 AX 프로젝트 리딩 | AX 심화 전문가 과정 |

집중 변화관리로는 현장 조직마다 뽑은 AI 전문가(진행자, 멘토, 챔피언 역할)의 활동 지원과 분기 워크숍, 연중 밋업, 사내 모범 사례를 모은 행사, 경영진 대상 역멘토링, 임직원 1일 교육, 해커톤을 한 해 일정으로 잡았다(10월과 11월 행사는 발표 시점의 계획). 가르칠 사람을 키워 확산을 곱셈으로 만드는 구조는 [[AI-Capability-Transfer|AI 역량 이전]]과 같다.

비용 인식도 사람 쪽 과제다. 위 기업은 업무 난이도별로 경량 모델(단순 디버깅 로그 분석, 코드 요약과 문서화, 테스트 케이스 초안), 표준 모델(화면, API, PoC 개발과 버그 수정, 영향도 분석과 리팩터링 설계), 최상위 모델(아키텍처 변경, 복잡한 엔진 개발, 대규모 저장소의 핵심 기능 변경)을 고르도록 안내하고 개인 대시보드로 자기 사용 비용을 보게 했다. 질의 수준에 따라 모델을 고르는 라우터는 예정으로 발표됐다. 등급의 구분과 자동 선택의 조건은 [[LLM-Model-Tiers|모델 티어 선택]]을 따른다.

## 거버넌스: 허브와 스포크

| 층 | 구성 | 역할 |
|---|---|---|
| 전사 협의체 | CEO가 주관하는 월간 AI 협의체 | 전사 방향과 로드맵, 추진 현황 공유와 의사결정(하향식) |
| 허브 | CAIO와 전사 AX 총괄 조직 | AX 전략과 거버넌스, KPI, 과제 관리 |
| 스포크 | 현장 조직과 HR, IT, 보안 협업 부서 | 격주 실무 협의체에서 과제 실행, 변화관리, 보안과 기술 지원, 현황과 성과 공유(상향식) |
| 현장 전문가 | 현장 전 조직에서 뽑은 AI 전문가 | 진행자, 멘토, 챔피언 |

성과는 매출 확대, 비용 절감, 생산성 개선의 세 범주로 AI 생산성 KPI를 두고 AI 활용 예산, 과제 관리, 임원 평가에 연결했다. 중앙이 기준을 정하고 현장이 실험하는 연합형 운영([[AX-Transformation#4. 거버넌스 (Governance) — 부서별 → 중앙 통합|중앙 통합 거버넌스]])의 한 형태다. 임원 평가에 AI 지표를 넣으면 사용량 맞추기로 흐를 수 있으므로 사용량, 과제 성과, 비용 가운데 무엇을 평가하는지 나눠 정한다(운영 제안, [[AI-Adoption-Measurement|전사 AI 활용 측정]]).

OpenAI의 공식 도입 안내도 비슷한 내부 태스크포스를 권한다. 경영진 후원자(비전 공유, 자원 확보, 사용 시범), 프로젝트 리드, 부서장, HR과 학습 조직, 작업 공간 관리자(SSO, 보존 기간, 접근 통제 설정), 챔피언(시연, 현장 피드백 수집, 모범 사례 공유, 신규 사용자 멘토링)이다. AI 사용 정책은 법무, 보안, 개인정보, HR, 사내 커뮤니케이션 담당과 챔피언이 함께 만들고, 사실 확인과 결과물의 최종 책임, 넣어도 되는 데이터의 범위, 권장 용도와 금지 용도를 적으라고 한다. OpenAI와 국내 기업의 공동 발표는 이를 규정 준수 기반 접근, 전략 정렬, 역량 강화, 변화관리(챔피언 네트워크), 가치 측정의 다섯 요소로 묶었는데, 이 다섯 이름으로 된 OpenAI 공개 문서는 찾지 못했다.

## 클라이언트 제로: 팔기 전에 먼저 쓴다

클라이언트 제로는 새 기술을 사내에 먼저 적용하고 검증한 뒤 그 경험을 외부 고객에게 넓히는 전략이다(2026-07-25 삼성SDS 보도자료의 정의). 공급사나 SI가 고객에게 권하기 전에 자기 조직에서 SSO, 보안, 거버넌스를 먼저 풀어 플레이북으로 만들고, 실제 업무로 엔지니어를 훈련하며, 고객이 참고할 사례를 만든다는 논리다(발표가 든 이유는 신뢰성, 플레이북, 인재, 증거).

사내 적용이 고객 현장의 데이터, 규제와 시스템 차이를 대신하지는 못한다. 같은 그룹 안의 확산은 의사결정 구조와 인프라가 비슷해 외부 고객보다 쉬울 수 있으므로 사내 수치를 외부 도입 성과의 근거로 옮기지 않는다. 확인할 대상은 사내에서 정리한 기준(데이터 등급, 접근 통제, 측정 지표)이 다른 조직에서도 쓰이는 자산인지다(해석).

## AI 네이티브 단계의 운영 모습

Anthropic은 자사 개발 방식을 소개하며 AI 네이티브 조직의 운영을 이렇게 그렸다(발표 기준의 제안).

- **절차를 적어 두면 복리로 쌓인다:** 에이전트가 생산을 맡고 사람은 무엇을 만들지 정하고 결과가 좋은지 판단한다. 검토, 계획, 장애 대응, 분기 마감 같은 일하는 방식을 한 번 적어 두면 쓴 사람이 없어도 어느 팀이든 실행하고, 절차를 고치면 다음 실행자 모두가 그 개선을 물려받는다([[Agent-Skills|에이전트 스킬]]).
- **하네스 전담 팀:** 기능이 아니라 시스템(도구, 테스트, 평가, 루프, 스킬, 환경, 가드레일)을 제품으로 삼는 엔지니어를 따로 두면 매주의 개선이 모든 에이전트에 한꺼번에 반영된다. 에이전트에게 스스로 검증할 수단(모의 객체, 스테이징, 시뮬레이터, 테스트, 브라우저)을 주고, 지연이나 비용 같은 숫자를 목표로 개선을 반복하게 하며, 배포마다의 낭비 감사, 퍼징과 카오스 실험, A/B 실험, 릴리스마다의 레드팀을 맡기는 예를 들었다([[Harness-Adoption-Ladder|하네스 도입 단계]]).
- **에이전트에게 신원을 준다:** 에이전트를 직원처럼 계정, 접근 권한, 소유자, 활동 기록과 함께 발급하고 역할마다 필요한 권한만 준다. 넓게 읽는 에이전트와 좁게 실행하는 에이전트를 나누는 식이다([[Agent-Governance-Controls#신원과 권한|신원과 권한]]).

## 사례 (회사 발표, 2026년 9월 기준)

- **외부 AI 전면 활용 전환:** 위 IT 서비스 기업은 2025년 10월부터 외부 AI 활용을 시범 검증하며 2026년 1월까지는 외부 접근을 막았고, 기밀 취급자(임직원의 10%)를 파악한 뒤 6월부터 외부 AI 전면 활용으로 바꿨다. 두 달 관측과 설문 결과는 [[AI-Adoption-Measurement|전사 AI 활용 측정]]에 있다.
- **재설계 사례의 효과 주장:** 같은 기업은 제안 지원 재설계 사례에서 제안 생산성 향상으로 전사 전담 부서의 지원 제안 규모를 3배까지 확대한다고 제시했다. 자료 문구에 시제가 없어 달성한 실적인지 목표인지 확인되지 않고, 비교 기간과 품질 지표도 공개되지 않았다.
- **클라이언트 제로의 규모:** 같은 기업은 Claude의 월간 활성 사용자 62,000명, Claude Code 사용자 33,400명(자료 표기는 활성 사용자의 약 45%), 6월 도입 뒤 메시지 3,800만 건 이상, 20개 관계사 제공을 발표했다. 33,400명은 62,000명의 약 54%라 45%와 분모가 맞지 않으며, 45%의 분모는 자료에 정의되지 않았다. 2026-07-25 보도자료는 20개 관계사 약 7만 명에게 제공한다고 밝히고, 자사 직원 기준으로는 도입 초기 몇 주 동안 메시지가 100만 건을 넘었으며 사용자의 절반 가까이가 Claude Code를 쓴다고 적었다. OpenAI와의 공동 발표에서는 대내 23개 관계사(현업 사용 사례 확산, 2026-06-12부터)와 대외 기존 고객 24개사(2026-02-01부터)를 들고, 잠재 고객 열에는 18.2만 명 규모의 대규모 확산을 적었지만 무엇을 센 값인지는 밝히지 않았다.
- **Claude Code 팀의 기능 개발:** Anthropic은 슬랙 질문 하나에서 시안 여섯 개, 구현 계획, 테스트 49개를 포함한 PR 초안까지 4.5시간이 걸렸고, A/B 시험에서 안내를 본 사람의 21%가 열었으며 처리군이 세션당 약 11배 많은 피드백을 보냈다고 발표했다. 공개된 1차 자료는 찾지 못했다.

## 점검 질문

- 외부 AI 허용 기준이 데이터 등급, 기밀 취급자, 근무 위치별로 정해져 있고 개인 계정 경로가 막혀 있는가
- 기업용 계약의 학습 제외, 보존 기간, 감사 로그, 인증 설정을 계약서와 관리 콘솔에서 확인했는가
- 연결 지점마다 교체 가능한 표준을 쓰고, 만드는 방법과 상관없이 같은 등록과 평가 절차를 거치는가
- 사용 사례 수가 아니라 엔드투엔드 업무 시간이 줄었는지 보고, 줄지 않았다면 규정, R&R, 데이터 연결 가운데 무엇이 막는지 찾았는가
- 상위 사용자와 하위 사용자에게 다른 변화관리(효율화와 역량 강화)를 적용하는가
- 허브와 현장 사이에 정기 협의 경로가 있고, KPI가 사용량이 아니라 성과에 연결돼 있는가
