# AI 불안과 FOMO를 다루는 법

AI 코딩 에이전트가 일상 도구가 되면서, 쌓아 온 전문성이 빠르게 대체되는 것 같다는 불안과 우울을 호소하는 개발자가 늘었다. 이런 상태를 클로드 블루(Claude Blue)라고 부르기도 한다. 기술 변화에 대한 불안은 늘 있었지만, 지능이라는 영역을 빠르게 건드린다는 점과 바이브 코딩, 프롬프트, 컨텍스트, 하네스처럼 새로운 엔지니어링 용어가 매주 쏟아진다는 점이 압박을 키운다. 수면 문제나 사회적 위축으로 이어진다면 혼자 버티지 말고 동료, 리더나 전문 상담과 나눈다.

## 공포는 대상보다 무지에서 온다

어둠 속의 정체 모를 소리가 무서운 이유는 정체를 모르기 때문이다. 바람에 흔들린 나뭇가지라는 걸 알면 공포는 사라지고, 정말 위험한 동물이더라도 무엇인지 알면 피할지 버틸지 판단할 수 있다. AI도 같다. 두려운 것은 AI 자체보다 그것이 어떻게 동작하는지, 무엇을 할 수 있고 무엇을 못 하는지 모른다는 사실에 가깝다. 정체를 이해하면 마법이 기술로 보이고, 기술은 배울 수 있고 한계가 있다.

## 정체: 다음 토큰 예측과 API 호출

- **모델**: LLM은 입력된 문맥에서 다음에 올 토큰을 하나씩 예측해 생성한다. 규모가 커지면서 추론, 번역, 코드 작성까지 해내지만 원리는 같다. [[LLM-Generation-Mechanics]]
- **서비스**: 대화 메시지를 HTTP API로 보내고 생성된 토큰을 스트리밍으로 받는다. 코딩 에이전트도 이 호출을 감싼 프로그램이다.
- **모델과 실행 환경의 구분**: 모델에는 문맥 길이와 오류의 한계가 있고, 최신 자료 조회나 파일 실행은 연결한 도구와 권한에 달려 있다. 대화 이력을 보관하는 방식은 API와 서비스마다 다르다. 예를 들어 Claude Messages API는 stateless 대화를 지원하지만, 이를 모든 서비스가 이력을 보관할 수 없다는 뜻으로 확대하지 않는다. [Anthropic, Create a Message](https://platform.claude.com/docs/en/api/messages/create)(2026-10-01 확인).
- **엔지니어링 용어들의 정체**: 이 한계를 메우는 방법에 붙은 이름이다. 질문을 잘 쓰는 것(프롬프트), 출력 형식과 도구 호출을 정하는 것(구조화 출력, 함수 호출, MCP), 무엇을 보여줄지 설계하는 것(컨텍스트), 작업을 작은 컨텍스트로 나누는 것(스킬, 압축, 서브에이전트), 실행 환경에 가이드와 센서를 채우는 것(하네스)으로 이어진다. [[Harness-Engineering#AI 활용의 진화: 프롬프트 → 컨텍스트 → 하네스 → 루프|AI 활용의 진화]]

결국 모두 모델 API에 적절한 입력을 보내고 응답을 받아 처리하는 일이다. 외부 API를 호출하고, 응답을 파싱하고, 오류를 처리하고, 결과를 가공하는 일은 개발자가 이미 해 온 일이다. 새 용어가 나오면 이 구조의 어느 칸에 들어가는 이야기인지로 자리를 잡아 주면 된다.

### 용어를 외운 뒤에는 실행 흐름으로 확인한다

용어 지도는 처음 보는 개념의 위치를 잡는 학습 도구다. 제품마다 같은 이름의 기능 범위가 다를 수 있으므로 이름만으로 실행 방식이나 안전성을 판단하지 않는다. 2026-10-16 Anthropic의 에이전트 패턴과 샌드박싱 설명에서 다음 구분을 대조했다.

- **흐름을 누가 정하는가:** 미리 정한 코드 경로로 모델과 도구를 연결하는 워크플로우와, 모델이 다음 단계와 도구를 동적으로 고르는 에이전트를 구분한다. 중앙 모델이 작업을 나누고 작업자 모델의 결과를 합치는 구성도 있으므로 여러 모델이 참여한다는 말만으로 서로 직접 통신한다고 가정하지 않는다.
- **무엇을 보고 멈추는가:** 반복 호출의 존재보다 도구 실행 결과, 완료 기준, 최대 반복 횟수와 사람에게 넘기는 지점을 확인한다. 자동 반복이 작업의 성공을 보장하지는 않는다.
- **어디까지 접근할 수 있는가:** 샌드박스라는 이름 대신 파일 접근과 네트워크 접근의 실제 제한을 확인한다. 두 경계와 허용 범위는 별도로 살펴야 하며, 모래놀이터 비유만으로 외부 시스템 전체가 보호된다고 판단하지 않는다.

이 구분을 적용한 학습 연습으로, 작은 작업 하나의 입력, 검색 자료, 도구 호출, 결과 확인과 종료 조건을 그려 본다. 각 단계의 실행 주체와 권한을 설명할 수 있는지 확인하고, 설명이 막힌 부분만 공식 문서와 실행 기록으로 보완한다. 용어 수나 도구 설치 수를 숙련도의 증거로 삼지 않는다.

## FOMO를 거르는 질문

뒤처진다고 겁을 주거나 매일 판이 뒤집힌다고 말하는 콘텐츠를 계속 보면, 이미 쓰고 있어도 제대로 못 쓰는 것처럼 느끼게 된다. 다음 질문으로 거른다.

- **무엇을 해결했는가**: 10분 만에 만들었다는 이야기는 과정을 압축했다는 말이지 문제를 해결했다는 말이 아니다. 일의 가치는 속도가 아니라 무엇을 했는가다. 개인용 도구와 제품은 성공 기준이 다르다. [[Developer-Role-AI-Era#개인용 도구와 제품의 성공 기준|개인용 도구와 제품의 성공 기준]]
- **새 패러다임인가, 기존 개념의 변형인가**: 위의 구조 중 어디에 해당하는지 대입해 본다.
- **나에게 필요한가**: 내 문제에 도움이 안 되면 지금 하던 대로 하면 된다. AI는 도구이고, 망치가 발명됐다고 모두가 망치를 들어야 하는 것은 아니다. 기대치도 사람마다 다르다.
- **사실인가, 과장인가**: 주장의 근거와 조건을 확인한다.

## 불안을 줄이되 과신으로 바꾸지 않는다

AI를 이해하고 사용해 보는 것과 결과를 신뢰할 근거를 얻는 것은 별개다. NIST AI 600-1의 Human-AI Configuration은 과도한 회피와 과도한 의존을 모두 위험으로 다룬다. 자동화 편향은 자동화된 결과를 지나치게 따르는 경향이며, 환각이나 편향의 영향을 더 키울 수 있다. 이 구분은 2026-10-26 해당 문서의 2.7절과 대조했다.

실무 적용 제안은 답변의 설득력과 검증 가능한 내용을 나누는 것이다. 중요한 주장 하나를 골라 원문, 입력 데이터와 실행 결과를 확인하고, 틀렸을 때의 영향에 맞춰 검토 강도를 정한다. 친근한 말투나 여러 모델의 동의만으로 사실 확인을 대신하지 않는다. 사람의 검토를 거쳤다는 표시도 검토 범위와 근거가 없으면 정확성의 증거가 아니다.

파일 변경과 외부 실행 권한은 이런 판단 절차와 별도로 제한한다. 에이전트가 공유 자원을 통해 협력할 때의 실행 경계는 [[Agent-Swarm-Containment|에이전트 군집 격리]]에서 다룬다. 모델의 동작 원리를 이해했다는 이유로 도구 권한까지 안전하다고 판단하지 않는다.

## 무엇을 할 수 있는가

- 직접 써 본다. 같은 질문을 프롬프트만 바꿔 보내며 결과가 달라지는 것을 체험하면 원리가 몸으로 이해된다.
- 한 걸음 더 가고 싶다면 API 키로 모델을 직접 호출하는 작은 에이전트를 만들어 본다. 메시지 구성, 도구 호출, 응답 처리의 전 과정이 한 번에 보인다.
- 구현이 싸질수록 무엇을 만들지 정하고 결과를 검증하는 판단이 남는다. 그 판단을 떠받치는 기초 지식이 오히려 중요해진다. [[Expertise-Formation-AI]]

5년 뒤 개발자의 역할이 어떻게 바뀔지는 아무도 모른다. 그래도 정체를 알고 불안을 다루는 것과, 모른 채 안개 속을 헤매는 것은 다른 상황이다.

## 체크포인트

- AI 불안이 기술 자체보다 동작 원리를 모르는 데서 커지는 이유
- LLM 서비스와 코딩 에이전트를 다음 토큰 예측과 API 호출 루프로 설명하기
- 프롬프트, 컨텍스트, 하네스 같은 용어를 하나의 구조 안에 배치하기
- 속도 자랑과 문제 해결을 구분하는 FOMO 필터

## 역사 비유와 고용 예측을 분리한다

과거의 도구 변화 뒤에도 개발이 계속됐다는 사례는 역할의 변화를 상상하는 데 도움이 된다. 그러나 과거에 직업이 남았다는 사실만으로 이번에도 같은 채용 규모와 경로가 유지된다고 예측할 수는 없다. 기술 능력, 조직의 도입과 노동시장 결과는 서로 다른 증거로 확인한다.

종말론이나 낙관론을 접하면 예측 시점, 대상 업무와 반증할 조건을 적어 본다. 미래 전체를 맞히려 하기보다 현재 업무 하나에서 직접 사용하고 실패와 검증 비용을 기록한다. 코드 작성이 줄어들 때 남는 요구 해석, 설계, 결과 검증과 책임을 어느 작업에서 연습할지 정한다. 이는 불확실성에 대응하는 실천이며 일자리를 보장하는 처방은 아니다.
