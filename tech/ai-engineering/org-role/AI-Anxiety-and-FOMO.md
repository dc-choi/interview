# AI 불안과 FOMO를 다루는 법

AI 코딩 에이전트가 일상 도구가 되면서, 쌓아 온 전문성이 빠르게 대체되는 것 같다는 불안과 우울을 호소하는 개발자가 늘었다. 이런 상태를 클로드 블루(Claude Blue)라고 부르기도 한다. 기술 변화에 대한 불안은 늘 있었지만, 지능이라는 영역을 빠르게 건드린다는 점과 바이브 코딩, 프롬프트, 컨텍스트, 하네스처럼 새로운 엔지니어링 용어가 매주 쏟아진다는 점이 압박을 키운다. 수면 문제나 사회적 위축으로 이어진다면 혼자 버티지 말고 동료, 리더나 전문 상담과 나눈다.

## 공포는 대상보다 무지에서 온다

어둠 속의 정체 모를 소리가 무서운 이유는 정체를 모르기 때문이다. 바람에 흔들린 나뭇가지라는 걸 알면 공포는 사라지고, 정말 위험한 동물이더라도 무엇인지 알면 피할지 버틸지 판단할 수 있다. AI도 같다. 두려운 것은 AI 자체보다 그것이 어떻게 동작하는지, 무엇을 할 수 있고 무엇을 못 하는지 모른다는 사실에 가깝다. 정체를 이해하면 마법이 기술로 보이고, 기술은 배울 수 있고 한계가 있다.

## 정체: 다음 토큰 예측과 API 호출

- **모델**: LLM은 입력된 문맥에서 다음에 올 토큰을 하나씩 예측해 생성한다. 규모가 커지면서 추론, 번역, 코드 작성까지 해내지만 원리는 같다. [[LLM-Generation-Mechanics]]
- **서비스**: 대화 메시지를 HTTP API로 보내고 생성된 토큰을 스트리밍으로 받는다. 코딩 에이전트도 이 호출을 감싼 프로그램이다.
- **한계**: 모델은 상태가 없어 매번 대화 전체를 다시 보내야 하고, 입력 길이에 제한이 있으며, 학습 이후 정보를 모르고, 그럴듯하게 틀린 내용을 만들고, 혼자서는 파일을 읽거나 코드를 실행하지 못한다.
- **엔지니어링 용어들의 정체**: 이 한계를 메우는 방법에 붙은 이름이다. 질문을 잘 쓰는 것(프롬프트), 출력 형식과 도구 호출을 정하는 것(구조화 출력, 함수 호출, MCP), 무엇을 보여줄지 설계하는 것(컨텍스트), 작업을 작은 컨텍스트로 나누는 것(스킬, 압축, 서브에이전트), 실행 환경에 가이드와 센서를 채우는 것(하네스)으로 이어진다. [[Harness-Engineering#AI 활용의 진화: 프롬프트 → 컨텍스트 → 하네스 → 루프|AI 활용의 진화]]

결국 모두 모델 API에 적절한 입력을 보내고 응답을 받아 처리하는 일이다. 외부 API를 호출하고, 응답을 파싱하고, 오류를 처리하고, 결과를 가공하는 일은 개발자가 이미 해 온 일이다. 새 용어가 나오면 이 구조의 어느 칸에 들어가는 이야기인지로 자리를 잡아 주면 된다.

## FOMO를 거르는 질문

뒤처진다고 겁을 주거나 매일 판이 뒤집힌다고 말하는 콘텐츠를 계속 보면, 이미 쓰고 있어도 제대로 못 쓰는 것처럼 느끼게 된다. 다음 질문으로 거른다.

- **무엇을 해결했는가**: 10분 만에 만들었다는 이야기는 과정을 압축했다는 말이지 문제를 해결했다는 말이 아니다. 일의 가치는 속도가 아니라 무엇을 했는가다. 개인용 도구와 제품은 성공 기준이 다르다. [[Developer-Role-AI-Era#개인용 도구와 제품의 성공 기준|개인용 도구와 제품의 성공 기준]]
- **새 패러다임인가, 기존 개념의 변형인가**: 위의 구조 중 어디에 해당하는지 대입해 본다.
- **나에게 필요한가**: 내 문제에 도움이 안 되면 지금 하던 대로 하면 된다. AI는 도구이고, 망치가 발명됐다고 모두가 망치를 들어야 하는 것은 아니다. 기대치도 사람마다 다르다.
- **사실인가, 과장인가**: 주장의 근거와 조건을 확인한다.

## 무엇을 할 수 있는가

- 직접 써 본다. 같은 질문을 프롬프트만 바꿔 보내며 결과가 달라지는 것을 체험하면 원리가 몸으로 이해된다.
- 한 걸음 더 가고 싶다면 API 키로 모델을 직접 호출하는 작은 에이전트를 만들어 본다. 메시지 구성, 도구 호출, 응답 처리의 전 과정이 한 번에 보인다.
- 구현이 싸질수록 무엇을 만들지 정하고 결과를 검증하는 판단이 남는다. 그 판단을 떠받치는 기초 지식이 오히려 중요해진다. [[Expertise-Formation-AI]]

5년 뒤 개발자의 역할이 어떻게 바뀔지는 아무도 모른다. 그래도 정체를 알고 불안을 다루는 것과, 모른 채 안개 속을 헤매는 것은 다른 상황이다.

## 체크포인트

- AI 불안이 기술 자체보다 동작 원리를 모르는 데서 커지는 이유
- LLM 서비스와 코딩 에이전트를 다음 토큰 예측과 API 호출 루프로 설명하기
- 프롬프트, 컨텍스트, 하네스 같은 용어를 하나의 구조 안에 배치하기
- 속도 자랑과 문제 해결을 구분하는 FOMO 필터
