# LLM 기본 답 쏠림과 응답 다양성 측정

사용자의 취향, 조건이나 상황 없이 열린 질문(책 추천, 사업 아이디어, 투자처, 이주할 도시)을 받으면 LLM은 같은 답으로 쏠리기 쉽다. 이 문서는 그 답을 기본 답이라 부르고, 기본 답이 얼마나 강한지 재는 방법, 생기는 단계, 제품과 평가에서 바꿀 점을 다룬다. 사용자 의견에 맞춰 답을 바꾸는 아첨([[LLM-Sycophancy-Evaluation|LLM 아첨 편향 평가]])과는 방향이 반대다. 아첨은 사용자 맥락에 과하게 끌려가는 실패이고, 기본 답 쏠림은 사용자 맥락이 비었을 때 모델의 사전 분포가 그대로 드러나는 현상이다. 상위: [[eval|AI 모델 평가, 신뢰성, 캘리브레이션]].

아래 사례 수치는 A90이 2026-11-20 측정해 공개한 실험(30개 기업의 모델 65개, 답 127,918개)을 2026-11-25 대조한 것이다. A90이 자체 공개한 실험 보고이며 동료 심사와 외부 재현이 없다. 조직의 성격과 이해관계는 확인하지 못했고 이 문서에서 재실행하지 않았다.

## 한 대화 안의 다양성과 새 대화 사이의 다양성은 다르다

같은 대화에서 추가 추천을 요청하면 모델은 앞서 낸 답을 문맥으로 보고 피하므로 답이 달라진다. 새 대화는 같은 입력을 처음부터 다시 받으므로 같은 분포에서 다시 뽑는다. 사용자가 보는 다양성은 대화 기록이 만든 것이고, 사용자마다 받는 첫 답은 같을 수 있다(이 문서의 해석).

- **사례(2026-11-20)**: 인생을 바꿀 책 한 권을 Claude Opus 5.5에게 한 대화 안에서 여덟 번 받으면(추가 요청은 `another one, please`) 서로 다른 책 여덟 권이 나왔지만, 새 대화 여덟 개에서는 매번 Man's Search for Meaning(죽음의 수용소에서)이었다. Claude Sonnet 5.5, GPT-6.2 Sol, Gemini 4 Neon, Grok 4.7, DeepSeek V4 Pro 0813도 같았다고 기록돼 있지만 모델별 수치는 공개되지 않았다. 두 번째 책을 물으면 여섯 모델 중 다섯이 Meditations(명상록)를 골랐다.
- **평가에 옮기면(운영 제안)**: 추천과 조언 기능의 다양성은 독립된 새 세션을 반복해 잰다. 한 대화에서 받은 목록이 다양하다는 사실로 사용자 사이의 다양성을 판정하지 않는다.

## 측정: 새 대화를 반복하고 고른 답만으로 비율을 낸다

실험은 OpenRouter에서 모델마다 한 공급 경로를 골라 시스템 프롬프트 없는 기본 설정으로 물었다. 사고 기능은 끄거나 가장 낮게 두었고(사고 기능을 비교한 시험만 예외), 요약 표는 질문마다 모델당 20~200번 물었다고 적지만 차트별 설명은 더 넓다. 일상 조언과 돈, 생활 질문은 모델당 10번, 한 단어 질문과 인물 지어내기는 50번, 1~100 숫자는 200번, 농담과 bash 도구 시험은 20번이다. temperature는 공개되지 않았다. 한 단어로 답하는 질문에는 `Reply with the ... only.` 형식의 지시를 붙였다.

| 지표 | 정의 | 읽는 법 |
|---|---|---|
| 최빈 답 비율 | 무언가를 고른 답 가운데 가장 흔한 답의 비율. 고르기를 거절한 비율은 따로 센다 | 분모를 확인하지 않으면 거절이 많은 질문의 쏠림이 과장되거나 가려진다 |
| 두 새 대화의 일치 확률 | 같은 모델의 새 대화 두 개가 같은 답을 낼 확률 | 모델 하나의 반복성. 21개 일상 질문, 39개 모델에서 33%(MiMo-V2.6-Pro, Phi 4)부터 91%(Mistral Medium 3.5)까지였고 Claude Sonnet 5.5와 Claude Fable 5.2는 84%였다 |
| 엔트로피(비트) | 답 분포의 불확실성. 1~100에서 숫자 하나를 고를 때 공정한 주사위면 log2(100) ≈ 6.64비트, 늘 같은 답이면 0 | 모델 사이, 학습 단계 사이의 비교에 쓴다 |

| 질문 | 최빈 답 | 비율 | 거절 |
|---|---|---|---|
| 인생을 바꿀 책 한 권 | Man's Search for Meaning | 73%(649개 답) | 표기 없음 |
| 한 문장 사업 아이디어 | 정기 배송 구독 상자 | 76%(648개 답) | 표기 없음 |
| 1만 달러 투자처 | 광범위한 지수 펀드 | 98% | 6% |
| 대학 전공 | 컴퓨터과학 | 90% | 10% |
| 이주할 국가 | 캐나다 | 55% | 23% |
| 1~100 무작위 숫자(모델마다 200번) | 65개 중 57개 모델이 42, 47, 73 중 하나를 가장 자주 골랐다 | 100개 숫자 중 36개는 한 번도 나오지 않았다 | 해당 없음 |

분모가 약 650개인 행은 모델 65개에 10번씩 물은 답이고(65 × 10), 비율은 무언가를 고른 답 가운데의 값이다. 모델당 10번이라 모델 하나의 비율로 읽기에는 거칠고, 숫자 행만 모델당 200번(답 12,993개)이다.

- **사고 기능은 쏠림을 풀지 않았다**: 돈과 생활 질문 8개 가운데 사고를 켜면 4개에서 최빈 답이 더 흔해졌고 4개는 차이가 없었으며, 최빈 답이 바뀐 질문은 없었다(예: 이주할 미국 도시 Austin 47%에서 57%).
- **언어를 바꿔도 남는다**: 10년 보유할 주식 한 종목을 물었을 때 Berkshire Hathaway의 비율은 영어 31%, 스페인어 39%, 독일어 37%, 일본어 31%, 힌디어 40%, 포르투갈어 38%였다.
- **모델은 자기 쏠림을 모른다**: 자기 답을 다른 사람이 얼마나 받을지 묻자 Austin을 약 15%로 짐작한 모델이 실제로는 100번 중 80번 Austin을 냈다. 질문 여덟 개 모두에서 모델들의 짐작(중앙값)이 실제 최빈 답 비율(10번 중)보다 낮았다(이주할 도시 15% 대 80%, 전공 34% 대 100%).

## 어디서 생기는가: 사후학습 첫 단계에서 분포가 좁아진다

학습 단계가 공개된 모델로 1~100 숫자 선택의 확률을 표본이 아니라 정확히 계산하면 쏠림이 생기는 단계가 보인다.

- **OLMo 2 1B**: 사전학습 6.51비트, SFT 4.95비트, DPO 4.97비트, 최종(RL) 4.98비트였다. 가장 자주 고르는 숫자는 SFT에서 나타났고 뒤 단계는 거의 바꾸지 않았다.
- **Qwen 2.5**: 1.5B는 사전학습 6.21비트에서 instruct 2.65비트(52% 확률로 73), 7B는 6.14비트에서 1.05비트(66% 확률로 42)로 줄었다.
- **학습 데이터에 답이 그대로 있지는 않았다**: OLMo의 공개 SFT 혼합(Tülu 3, 866,138개 예시)의 assistant 턴에는 그 숫자도, 지어낸 인물에 몰린 나이 34도 없었다. 반면 지어낸 인물 이름 Elara는 4,269번 나왔고 그중 3,233번이 ChatGPT 대화를 모은 WildChat에서 왔다. 다른 모델이 만든 대화가 SFT 데이터로 들어가 기본값이 옮겨 갈 수 있다는 단서지만, 이 실험이 인과를 보인 것은 아니다(이 문서의 해석).
- **같은 회사 모델끼리 닮는다**: 답 분포로 본 최근접 모델이 같은 회사인 경우가 59%(무작위면 4%)였고, 부모가 알려진 공개 미세조정 모델 23개 중 22개의 계열을 맞혔다(무작위면 33%). 비슷한 답은 같은 부모의 증거가 아니라 학습 데이터를 공유한 결과일 수도 있다는 단서가 실험에 함께 붙어 있다.

SFT 데이터의 다양성이 응답 품질에 주는 영향은 [[LLM-Post-Training#데이터는 양보다 다양성과 품질|사후학습의 데이터 다양성]]에서 다룬다.

## 지어낸 값은 평가 데이터와 세상으로 퍼진다

모델마다 무작위 인물을 50번씩 지어내게 하자 3,151명 가운데 69%가 정확히 34세였다(중앙값 34세, 미국 성인은 47세). 60세 넘는 인물은 0.1%(미국 성인 29%), 여성은 81%(51%), Portland나 Seattle 거주는 46%(0.4%), 해양생물학자는 15%였다. 계열마다 선호하는 이름도 있었다(Claude는 Marisol Okafor, Gemini는 Elena Vance, GPT-6.2는 Mira Calder). Elena Vance는 2026년 새 GitHub 저장소 684곳에 나왔고 그 전 6년에는 없었다고 보고됐다. 같은 기록이 인용한 존재하지 않는 저자의 Zenodo 논문 1,655편과 Elara Voss 명의의 Amazon 책 62권은 다른 조사의 수치이며 이 문서에서 확인하지 않았다.

테스트 사용자, 페르소나와 합성 질문을 모델에 맡겨 그냥 지어내게 하면 이 분포가 그대로 평가 데이터에 들어간다. 사용자 유형, 의도, 난도 같은 차원을 먼저 정하고 조합을 만든 뒤 문장으로 바꾸는 절차는 [[LLM-App-Three-Gulfs#분석을 시작하는 실무 기준|합성 입력을 차원으로 만든다]]를 따른다.

## 무작위성과 비밀번호는 모델이 쓴 값으로 만들지 않는다

- **비밀번호**: 이메일용 강한 비밀번호를 요청하자 생성된 비밀번호의 25%에 `vL`이 들어 있었다(무작위면 0.21%). Mistral Medium 3.5는 30번 중 19번 같은 비밀번호를 냈다. 반면 보안 난수 생성기를 쓰는 세션 토큰 코드는 390번 중 384번 맞게 작성했다.
- **도구가 있으면 대부분 도구를 쓴다**: bash 도구를 준 63개 모델 중 54개가 실제 난수 생성기를 호출했다. 가장 많이 쓴 명령은 28개 모델이 `echo $((RANDOM % 100 + 1))`, 20개 모델이 `shuf -i 1-100 -n 1`, 5개 모델이 Python의 `randint(1, 100)`이었고, 중국 연구소 모델은 대체로 앞의 것을, 미국 연구소 모델은 대체로 `shuf`를 썼다. 6개 모델은 명령 없이 기억으로 답했고, 한 모델은 `echo $RANDOM`만 써서 범위가 0~32,767로 틀렸다. bash의 `$RANDOM`은 32,768개 값을 내므로 100으로 나눈 나머지에 1을 더한 값은 1~68이 69~100보다 조금 더 자주 나온다(32,768 = 327 × 100 + 68, 실험 기록도 같은 치우침을 적는다).

운영 제안: 비밀번호, 토큰, A/B 배정과 표본 추출의 무작위 값에는 모델이 텍스트로 낸 값을 쓰지 않는다. 운영체제의 암호학적 난수원을 쓰는 코드를 모델이 작성하게 하거나 도구로 호출하게 하고, 그 코드의 범위와 편향을 리뷰한다.

## 기본 답을 비키는 방법과 그 대가

여섯 질문에서 모르는 사람이 같은 답을 받을 확률(65개 모델, 질문과 방법마다 10번)은 묻는 방법에 따라 다음처럼 달랐다.

| 방법 | 같은 답 확률 |
|---|---|
| 그냥 묻기 | 34% |
| 무작위 시드 주기 | 19% |
| 가장 흔한 답은 빼 달라고 요청 | 15% |
| 10개를 나열하게 하고 7번째 고르기 | 7% |
| 자기 소개(나이, 직업과 지역, 좋아하는 것) 주기 | 4% |

- **자기 정보가 쏠림을 가장 크게 줄였다**: 자세한 사용자 정보를 넣자 평소 기본 답의 비율이 53%에서 11%로 줄었고, N번째 고르기는 17%였다. 다만 한 줄짜리 직업과 지역 정보는 사용자를 그 집단의 다른 공통 답으로 옮길 뿐이었다. 답이 집단 안에서는 일관됐고 개인마다 달라지지는 않았다.
- **잘 빠지지 않는 답이 있다**: Berkshire Hathaway는 모든 방법에서 12% 이상 남았다.
- **흔한 답이 틀린 답은 아니다**: 1만 달러 투자처처럼 대부분에게 맞는 답이 하나인 질문도 있고, 실험 기록도 더 다양한 것이 더 나은 것은 아니라고 단서를 단다. 목표는 다양성 자체가 아니라 답이 사용자의 조건을 반영하는지다(이 문서의 해석).

## 제품과 평가에 옮기기

다음은 위 결과에서 도출한 운영 제안이다.

- **조건 민감도를 잰다**: 같은 질문에 사용자 조건(예산, 목적, 제약)만 바꾼 입력 쌍을 넣어 답이 조건에 따라 바뀌는지 본다. 조건이 달라도 같은 답이면 기본 답이 조건을 덮은 것이다.
- **새 세션 반복을 기록한다**: 같은 입력을 새 세션으로 N번 반복해 최빈 답 비율, 거절 비율과 엔트로피를 남기고 모델을 바꿀 때 비교한다.
- **추천 기능은 사용자 맥락을 입력에 넣는다**: 맥락 없는 열린 질문을 그대로 넘기면 사용자 모두가 같은 첫 답을 받는다. 후보를 여러 개 생성하게 하고 고르는 일은 코드가 맡는 편이 모델의 기본 답에 덜 묶인다.
- **같은 계열 모델의 다수결은 독립 표본이 아니다**: 같은 회사 모델끼리 기본 답을 공유할 수 있으므로, 여러 모델의 투표로 확신을 높일 때 계열이 같은지 확인한다([[Self-Consistency-Voting|자기 일관성과 샘플 투표]]).

## 한계

- 질문당 모델마다 50번이면 계열의 경향은 보이지만 두 모델 사이의 작은 차이로 순위를 매기기에는 부족하다는 단서가 실험에 붙어 있다.
- 모델마다 한 공급 경로로 물었으므로 다른 경로나 이후 갱신에서는 다를 수 있다. temperature가 공개되지 않았고 기본 설정은 경로마다 다를 수 있다.
