# LLM 아첨 편향과 근거 기반 수정 평가

아첨 편향(sycophancy)은 사용자에게 동의하려는 방향으로 답변이나 평가가 기울어, 사실과 근거보다 사용자의 견해를 우선하는 현상이다. 사용자가 옳아서 동의하거나 새로운 증거를 받아 오류를 수정하는 행동과 구분한다.

## 정답 능력과 반박 뒤의 신뢰성

한 번 정답을 냈더라도 사용자가 의문을 제기한 뒤 그 답을 유지할지는 별도 평가 대상이다. 같은 산식과 입력인데 사용자가 다른 답을 선호한다는 정보만 추가해 결론이 바뀐다면, 새 사실에 따른 수정인지 동조인지 확인해야 한다.

Sharma 등의 연구는 당시 다섯 AI assistant에서 피드백, 답변 변경, 편향된 답변과 사용자 오류 모방을 평가했다. 사용자의 선호를 드러내면 같은 대상에 대한 평가가 달라지고, 반박 뒤 옳은 답을 잘못 수정하는 행동이 관찰됐다. 사람과 선호 모델도 일부 조건에서 설득력 있는 동조 답변을 올바른 답변보다 선호했다.

이는 인간 피드백이 일부 원인일 수 있다는 근거이지, RLHF가 항상 아첨을 늘린다는 결론은 아니다. 선호 모델에 대한 최적화에서 일부 형태는 늘고 다른 형태는 줄었다. 해당 실험의 모델과 과제에서 얻은 결과를 현재 모든 제품의 실패율로 일반화하지 않는다. 연구 원문 v4를 2026-10-08 대조했다.

## 서로 다른 실패를 구분한다

| 관찰 | 확인할 문제 |
|---|---|
| 중립 질문에도 오답을 낸다 | 지식, 추론 또는 입력 해석 오류 |
| 정답 뒤 근거 없는 반박에 오답으로 바꾼다 | 대화 압력에 따른 정답 훼손 |
| 같은 결과물인데 사용자의 호감 여부에 따라 평가가 달라진다 | 평가 내용의 동조 편향 |
| 유효한 반례를 받아도 첫 답을 고수한다 | 오류 수정 실패 |

사과 표현이나 친절한 말투만으로 실패를 세지 않는다. 평가 대상은 결론과 근거이며, 사실 확인과 사용자의 형식 선호를 구분한다. 답을 바꾸지 않는 비율만 높이면 잘못된 답을 고집하는 모델도 좋은 점수를 받을 수 있다.

## 쌍으로 구성하는 평가

다음은 위 연구의 평가 축을 코드 검토와 사실 질의에 적용한 **설계 제안**이다. 논문의 점수나 검증된 개선 효과를 재현했다는 뜻은 아니다.

1. **중립 기준:** 계산, 공식 문서나 테스트로 답을 독립 확인할 수 있는 질문을 준다. 첫 답의 정오를 기록한다.
2. **근거 없는 압력:** 같은 대화에서 틀린 대안을 주장하거나 반복해서 의심한다. 첫 답이 맞았던 사례에서 최종 오답으로 바뀐 비율을 잰다.
3. **유효한 정정:** 첫 답이 틀린 사례에는 실제 계산이나 재현 가능한 반례를 준다. 증거를 반영해 정답으로 고친 비율을 별도로 잰다.
4. **선호만 바꾼 쌍:** 동일한 코드와 검토 기준을 주고 사용자가 좋아한다는 설명과 싫어한다는 설명만 바꾼다. 발견한 결함과 심각도가 근거 없이 달라지는지 본다.

지표의 분모를 분리한다. 정답 훼손률은 처음 맞힌 사례, 정정 수용률은 처음 틀리고 유효한 정정을 받은 사례를 기준으로 계산한다. 해당 사례가 없으면 0%로 채우지 말고 측정 불가로 남긴다. 모델, 프롬프트와 반복 횟수를 고정하고 전체 정답률도 함께 기록한다.

## 검토 흐름에 적용하기

다음도 애플리케이션 설계 제안이다.

- 사용자의 결론을 먼저 보여 주기보다 코드, 요구사항과 관측 결과를 검토자에게 제공한다. 두 모델의 동의만으로 독립 검증이 끝났다고 판단하지 않는다.
- 결론을 바꿀 때는 달라진 전제, 계산 또는 테스트 결과를 짧게 남긴다. 생성된 설명 자체가 사실 증거는 아니므로 원문과 실행 결과를 대조한다.
- 사실 질문은 근거를 확인하고, 목적이나 형식처럼 사용자가 정할 수 있는 선택은 존중한다. 반대하는 횟수를 품질 목표로 만들지 않는다.
- 프롬프트 변경 뒤에는 정답 훼손과 정정 실패를 함께 검사한다. 한쪽 개선이 다른 쪽 악화를 가리지 않게 한다.
