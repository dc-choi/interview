# 멀티모달 이미지 검색

텍스트 질의로 이미지를 찾으려면 두 입력을 비교할 수 있는 임베딩 공간이 필요하다. CLIP은 이미지와 텍스트 쌍으로 학습한 두 인코더를 사용한다. 같은 차원의 벡터라는 이유만으로 서로 다른 모델의 출력을 비교할 수 있는 것은 아니다. 아래 설명은 원본 CLIP 논문과 공개 구현을 기준으로 하며, 프레임 추출은 FFmpeg 필터 문서, 시각 언어 모델 예시는 원 LLaVA 논문을 따른다.

## 검색 흐름

다음은 CLIP의 인코더를 이미지 검색에 적용한 설계 예다.

1. 이미지 적재 시 모델에 맞는 전처리와 이미지 인코더로 벡터를 만든다.
2. 이미지 식별자와 원본 위치, 모델 버전, 전처리, 정규화 방식과 벡터를 함께 저장한다.
3. 검색 시 같은 체크포인트의 텍스트 인코더로 질의를 변환한다.
4. 코사인 유사도 등 모델에 맞는 척도로 이미지 벡터를 정렬하고 검색 결과를 원본 이미지와 연결한다.

텍스트에서 이미지로 찾는 검색과 이미지에서 가까운 이미지를 찾는 탐색은 같은 저장 벡터를 재사용할 수 있다. 다만 후자의 순위가 사용자의 취향이나 다음 행동을 맞히는 추천 품질까지 보장하지는 않는다.

CLIP 공개 구현의 `encode_image`와 `encode_text`는 각 입력의 특징을 반환한다. 예제는 특징 벡터를 길이 1로 정규화한 뒤 내적을 계산한다. 정규화된 벡터의 내적과 코사인의 관계는 [[Vector-Similarity-Search#거리 계산 방식|거리 계산 방식]]을 따른다.

## 썸네일을 영상의 대리 표현으로 쓸 때

영상 서비스에서 썸네일 벡터를 사용하면 정지 이미지의 시각적 특징을 검색할 수 있다. 하지만 이미지에 없는 발화, 시간 순서와 사건을 검색했다고 볼 수는 없다. 대표 이미지가 본문과 다르면 결과도 빗나갈 수 있다.

| 필요한 결과 | 확인할 입력과 한계 |
| --- | --- |
| 비슷한 색감이나 시각적 장면 | 썸네일 이미지. 실제 관련성 라벨로 순위를 평가한다 |
| 영상 안의 특정 설명이나 발화 | 자막이나 전사문을 별도로 검색하는 경로를 검토한다 |
| 여러 장면 사이의 행동과 시간 순서 | 단일 썸네일로 충족되지 않는다. 시간 정보를 보존하는 표현이 필요하다 |

이 구분은 입력에 담긴 정보에서 도출한 설계 판단이다. 어떤 질의까지 썸네일로 충분한지는 실제 자료로 확인한다. 제목, 자막과 이미지 점수를 결합할 때도 같은 척도라고 가정하지 말고 결합 전후 품질을 비교한다.

## 프레임을 뽑아 영상 속 장면을 찾을 때

썸네일 한 장 대신 일정 간격으로 프레임을 뽑아 각각을 이미지로 색인하면, 텍스트 질의로 영상 안의 장면 위치를 찾을 수 있다.

1. FFmpeg의 `fps` 필터는 프레임을 복제하거나 버려 영상을 지정한 고정 프레임레이트로 바꾼다. 출력 프레임레이트를 1로 주면(`-vf fps=1`) 약 1초 간격의 표본이 된다.
2. 각 프레임을 위의 검색 흐름대로 인코딩하고, 영상 식별자와 프레임의 시각을 벡터와 함께 저장한다.
3. 질의 결과는 프레임 시각으로 영상의 해당 구간에 연결한다.

다음은 이 구성의 한계에서 도출한 설계 판단이다.

- 표본 간격보다 짧게 지나가는 장면은 색인에 없을 수 있다. 간격을 좁히면 저장량과 인코딩 비용이 프레임 수에 비례해 는다. 표본 간격과 주변 구간 확인의 일반 원칙은 [[Multimodal-Video-Retrieval|멀티모달 영상 검색]]을 따른다.
- `fps` 필터는 시작 시각 가정(`start_time`)과 타임스탬프 반올림(`round`, 기본값 `near`) 옵션을 가진다. 프레임 번호로 시각을 역산하면 실제 표시 시각과 어긋날 수 있으므로 찾은 장면의 앞뒤 구간을 함께 확인한다.
- 이미지 인코더는 프레임의 화면만 본다. 화면에 거의 보이지 않는 대상이나 화면 밖의 원인을 쓴 질의보다 보이는 대상, 표정과 행동을 묘사한 질의가 맞기 쉬울 것으로 보고, 정답을 단 질의로 실제 차이를 시험한다. 질의 문장의 형식도 결과에 영향을 줄 수 있으며, CLIP 공개 구현의 zero-shot 분류 예제는 라벨을 `a photo of a {c}` 문장으로 감싸 텍스트 인코더에 넣는다.
- 발화와 시간 순서는 여전히 프레임에 담기지 않는다. 위 표처럼 자막이나 전사문 검색 경로를 따로 둔다.

### softmax 비율은 후보 집합 안의 상대값이다

CLIP 공개 구현에서 `model(image, text)`가 반환하는 logits는 이미지와 텍스트 특징의 코사인 유사도에 100을 곱한 값이다. README 예제는 이미지 한 장과 텍스트 여러 개를 넣고 `logits_per_image.softmax(dim=-1)`로 후보 텍스트 사이의 확률처럼 보여 준다. 질의 문장 하나로 여러 프레임을 비교할 때는 이미지 축으로 정규화해야 하므로 `logits_per_text.softmax(dim=-1)`를 쓴다. README 줄을 그대로 옮기면 텍스트가 하나뿐이라 모든 프레임이 1.0을 받는다.

이 비율은 그 실행에 넣은 후보들 사이에서만 정규화된다. 프레임 15장 중 한 장이 98%를 받아도 그 장면이 질의와 맞는다는 절대 판정이 아니다. 맞는 장면이 없는 영상에서도 상대적으로 가장 가까운 프레임이 높은 비율을 받을 수 있고, 후보 수가 바뀌면 같은 프레임의 비율도 달라진다. 정답 없는 질의를 포함한 평가 자료로 유사도 원값의 기준을 정하고, 비율은 후보 안의 순위 표시로만 쓴다(설계 판단). 일반 원칙은 [[Vector-Similarity-Search#높은 점수와 관련성 판정은 구분한다|점수와 관련성 판정의 구분]]을 따른다.

### 찾기, 설명하기와 위치 찾기는 기본 출력이 다르다

| 필요한 결과 | 모델 계열 | 확인할 점 |
| --- | --- | --- |
| 문장과 가까운 프레임의 순위 | CLIP 같은 이미지와 텍스트 임베딩 모델 | 유사도 점수만 주며 장면의 이유를 설명하지 않는다 |
| 찾은 프레임에 대한 질문과 설명 | 시각 언어 모델(VLM) | 답은 생성 결과라 사람이 프레임과 대조한다 |
| 프레임 안 물체의 위치 | 객체 탐지 모델 | 검색 순위와 별도의 라벨과 평가 지표가 필요하다 |

표는 계열별 기본 출력의 구분이며, 한 모델이 여러 출력을 함께 낼 수도 있다. 어느 모델이 위치를 내든 위치 결과는 별도 라벨과 지표로 평가한다. 두 번째 계열의 예로 원 LLaVA 논문(2023)은 사전학습된 CLIP 시각 인코더(ViT-L/14)의 이미지 특징을 학습 가능한 projection으로 언어 모델의 단어 임베딩 공간에 넣는다. 검색에 쓴 인코더와 설명 모델의 시각 인코더가 같은 계열일 수 있지만, 검색 점수가 높다고 설명 모델의 답이 맞는다는 보장은 없다. 이 문서는 위 단계를 직접 실행하거나 정확도를 측정한 기록이 아니다.

## 저장소와 평가

PostgreSQL을 이미 사용한다면 [[pgvector|pgvector]]로 벡터를 함께 저장하고 검색할 수 있다. pgvector는 임베딩을 생성하는 모델이 아니며, 별도의 인코딩 단계가 필요하다. 작은 자료에서는 exact 검색을 기준선으로 삼고 지연과 부하가 요구를 넘을 때 ANN을 비교한다.

다음은 운영 적용을 위한 확인 항목이다.

- 문서와 질의 인코더가 같은 공간에 정렬돼 있는지 확인한다. 모델을 바꾸면 기존 벡터와 섞지 않는다.
- ANN의 exact 대비 Recall@K와 사람이 판단한 검색 관련성을 따로 측정한다. 근접 탐색이 정확해도 임베딩 자체가 질의 의도를 놓칠 수 있다.
- 대표 질의에 정답 없는 질의, 썸네일과 본문이 다른 사례, 실제 서비스 언어를 포함한다.
- 공개 CLIP 모델 카드는 영어 이외 언어와 세밀한 분류, 개수 세기 등의 한계를 명시한다. 한국어 서비스에 그대로 적용할 수 있다고 가정하지 않는다.
- 원본 모델 카드는 상업적 여부와 무관하게 배포 용도를 범위 밖으로 둔다. 제한된 환경의 비배포 이미지 검색도 도메인 내 검증 없이 권장하지 않으므로, 검색 시연의 성공을 배포 적합성으로 해석하지 않는다.
