# 프로그래밍에서의 인지 편향

인간의 뇌는 **빠른 판단을 위해 지름길(휴리스틱)**을 쓴다. 대부분은 유용하지만, 복잡한 엔지니어링 결정에서는 체계적 오류를 만든다. 편향을 없앨 수는 없지만 **이름을 알고 있으면** 토론에서 호명해 의사결정 품질을 높일 수 있다.

## 1. Hyperbolic Discounting — 즉시 이익 선호

**나중에 받을 큰 이익보다 지금의 작은 이익을 선호하는 경향.**

- 테스트 작성 미루기 → 당장 구현 속도는 빠르지만, 몇 주 뒤 회귀 버그 추적에 수 배의 시간 소비
- 익숙한 키보드 단축키만 쓰고 새 단축키 학습을 미룸 → 평생 느린 타이핑
- 리팩토링을 "지금 바쁨"으로 계속 미룸 → 몇 달 뒤 손댈 수 없는 코드

**대응**
- 미래의 비용을 **정량화**해 현재의 불편과 비교 — 테스트 15분 vs 디버깅 3시간
- 스프린트에 **기술 부채 할당 비율** 강제 (예: 20%)
- Invest vs Improve를 명시적 주기로 평가

## 2. IKEA Effect — 내가 만든 것 과대평가

**직접 만든 것에 과도한 가치를 부여하는 편향.**

- 사내 도구가 비슷한 오픈소스보다 열등해도 "우리가 만들었으니까 유지"
- 몇 달 들여 만든 아키텍처에 애착이 생겨 **더 나은 대체안이 와도 인정 못함**
- NIH(Not Invented Here) 증후군의 인지적 뿌리

**대응**
- **Build vs Buy** 결정을 설계 초기에 기록 (시간이 지나면 sunk cost와 얽힘, 판단 틀은 [[Build-vs-Buy|Build vs Buy]])
- 정기적인 **도구, 라이브러리 재평가** 세션
- 외부 리뷰어, 컨설턴트에게 "이거 왜 자체 제작해?" 질문받기

**스스로 고른 것도 과대평가하는가**: 직접 만든 것이 아니라 직접 고른 것에 대해서도 비슷한 주장이 있다. Langer(1975)는 복권을 직접 고른 사람이 배정받은 사람보다 그 복권을 되팔거나 바꾸기를 더 꺼렸다고 보고했고, 선택이 통제 착각을 만든다는 근거로 널리 인용됐다. 그러나 17개 실험(10,825명)으로 다시 검증한 Klusowski 외(2021)는 선택이 실제로 결과를 바꾸지 않는 한 좋은 결과가 날 것 같다는 느낌을 거의 키우지 않았고, 효과가 보일 때도 선택이 착각을 만든 것이 아니라 같은 조건의 선택지를 다르다고 믿던 기존 생각이 선택에 드러난 것이라고 결론지었다. 고객에게 고르게 하면 더 가치 있게 여긴다는 설득 요령의 근거로 이 복권 연구를 쓰지 않는다. 설득 기법의 원 연구와 경계는 [[Persuasion-Principles-and-Boundaries|설득 원리와 정직한 사용의 경계]]에서 다룬다.

## 3. Premature Optimization — 시기상조 최적화

**실제 병목을 측정하기 전에 코드를 최적화하는 경향.**

- 쓰이지도 않을 캐시 레이어를 미리 넣기
- 전혀 병목이 아닌 함수를 인라인화, 메모이제이션
- 엔진이 고장난 차에 공기역학 스포일러 다는 꼴

Donald Knuth의 명언: *"Premature optimization is the root of all evil."*

**대응**
- **측정 먼저** — 프로파일러, APM으로 실제 병목 확인 후에만 최적화
- "Make it work → Make it right → Make it fast" 순서 준수
- "이 최적화가 사용자 지연을 몇 ms 줄이는가?"를 질문

## 4. Planning Fallacy — 일정 과소추정

**작업에 걸리는 시간을 일관되게 짧게 추정하는 경향.**

- "하루면 끝날 줄" → 실제 3일
- **90-90 법칙**: 코드의 처음 90%는 개발 시간의 90%를, **나머지 10%가 또 90%를** 차지 → 체감 90%지점에서 실제는 반만 끝남
- 낙관 편향과 결합하면 **프로젝트 전체**가 수 배 지연

**대응**
- **과거 유사 작업의 추정과 실제 소요 시간 기록**에서 초과율을 구해 여유분을 넣기 전의 추정에 한 번만 적용한다. 이 보정분이 버퍼이므로 고정 배수 버퍼를 따로 더하지 않는다 ([[Reference-Class-Forecasting|참조 집단 예측]])
- 큰 일정은 여러 명이 각자 추정한 뒤 차이의 근거를 논의하고 다시 추정해 범위를 좁힌다 (Wideband Delphi)
- 일단 작은 범위로 프로토타입 → 실측 후 재추정

## 5. Recency Bias — 최근 경험 과대평가

**최근에 겪은 문제, 패턴을 다른 상황에도 쉽게 투영하는 경향.**

- 방금 쓴 디자인 패턴을 모든 문제에 적용하려 함
- 최근 장애 원인을 다음 설계 논의에서 과도하게 방어
- 새로 배운 프레임워크를 맞지 않는 도메인에 도입

**대응**
- **다양한 맥락**에서 같은 문제를 다뤄본 동료의 의견 수렴
- 아키텍처 결정을 **내리기 전 며칠 숙고** — 뜨거운 직후 결정 금지
- "이게 진짜로 지금 문제에 맞는가?"를 문서로 근거 작성

## 추가로 자주 등장하는 편향

### Confirmation Bias — 확증 편향
원하는 결론에 맞는 증거만 수집. 장애 분석에서 초기 가설에 맞는 로그만 읽음 → 진짜 원인 놓침.

**대응**: "이 가설을 **반증**할 증거는?"을 의식적으로 질문. PR 리뷰에서 "문제없는 것 같다"가 아닌 "무엇이 문제일 수 있을까"로 접근.

### Dunning-Kruger Effect
특정 과제의 수행 수준과 자기평가 사이의 오차를 다룬다. 1999년의 네 연구에서는 유머, 문법과 논리 과제의 하위 사분위 참가자가 자신의 수행을 크게 과대평가했다. 상위 사분위는 동료 대비 위치를 과소평가하는 경향이 있었지만, 이는 자신이 맞힌 문항 수에 대한 판단과 구분된다.

따라서 자신감이 높으면 실력이 낮고 조심스러우면 실력이 높다는 개인 판별법으로 쓰지 않는다. 이 연구는 개발자의 연차별 의사결정이나 한 사람이 성장하며 거치는 자신감 곡선을 검증하지 않았다. 모르는 것을 인식하는 능력이 수행 능력과 관련될 수 있다는 결과를 모든 과신의 유일한 원인으로 확대하지 않는다.

**대응 제안**: 코드나 설계의 예상 결과, 확신 정도와 근거를 남긴 뒤 테스트, 실행 결과와 독립적인 피드백에 대조한다. 틀린 결론뿐 아니라 근거가 부족한데 확신했던 지점도 수정한다. 질문하는 태도와 실제 수행을 따로 평가하며, 이 절차 자체의 효과를 위 연구가 검증한 것으로 제시하지 않는다.

### 평균 이상 효과 (Better-Than-Average Effect)

다수가 자기 능력이나 성과를 평균보다 높게 평가하는 경향이다. 모든 아이가 평균 이상이라는 가상의 마을 이름을 따 워비곤 호수 효과라고도 부른다. Svenson(1981)은 미국과 스웨덴의 운전자 표본에게 다른 참가자와 비교한 자신의 운전 안전성과 기술을 물었고 다수가 자신을 중앙값보다 위에 놓았다. 2023년의 사전 등록 재현 연구(Koppel 외, 1,203명)도 다수가 자기 운전 기술과 안전성을 평균 이상으로 평가해 원 연구와 일치하는 결과를 얻었다.

Dunning-Kruger와는 질문이 다르다. Dunning-Kruger는 특정 과제의 수행 수준에 따라 자기평가 오차가 어떻게 달라지는지를 보고, 평균 이상 효과는 집단 전체가 자기 위치를 평균보다 높게 놓는 분포를 본다. 숙련자가 남의 능력을 깎아 본다는 식의 설명은 위 Dunning-Kruger 절의 원 논문 설명과 다르므로 옮기지 않는다.

**대응 제안**: 일정 추정, 코드 리뷰 자체 평가와 성과 자기평가처럼 자기 판단이 기준이 되는 곳에는 과거 실측, 동료 비교 자료나 외부 리뷰처럼 자신 밖의 기준을 붙인다. 자기 점검표로 상위 성과자의 특성을 확인하는 방식도 대부분이 자신을 평균 이상으로 평가한다는 점 때문에 결론을 내리기 어렵다.

### Sunk Cost Fallacy — 매몰 비용 오류
이미 투입한 시간, 비용이 아까워 실패하는 방향을 계속 추진. "이만큼 했는데 지금 접을 순 없잖아."

**대응**: "만약 지금 **처음부터** 시작한다면 이 방식을 선택할까?"를 매 의사결정에서 질문.

### Availability Heuristic — 가용성 휴리스틱
쉽게 떠오르는 예시에 가중치 부여. 최근 뉴스의 장애 유형, 유명 회사 사례가 과대평가됨.

**대응**: 실제 확률, 빈도 데이터 수집. 일화 대신 통계로 근거.

## 편향을 조직 차원에서 줄이는 장치

- **의사결정 기록**(ADR, 테크스펙) — 당시의 근거를 남겨 사후 확증 편향 방지
- **사전 부검(Pre-mortem)** — "이 프로젝트가 실패했다고 가정하고 원인을 나열" → 낙관 편향 상쇄
- **디바이스 어드보킷(Devil's Advocate)** 지정 — 반대 입장을 의도적으로 맡기기
- **체크리스트** — 편향이 개입할 틈을 없앰 (항공, 의료에서 검증된 기법)
- **다양한 경력의 팀 구성** — 공통 편향을 줄이기 가장 효과적

## 면접 체크포인트

- 본인이 **과거에 겪었던 편향 경험**과 극복 방법
- "측정 없이 최적화" 같은 **Premature Optimization의 구체 사례**
- **90-90 법칙**을 아는가, 일정 추정에서 어떻게 반영하는가
- **사전 부검(Pre-mortem)** 기법의 의미
- **Dunning-Kruger**의 과제별 자기평가 오차와 연차, 자신감만으로 실력을 판별하는 오류를 구분하는가
- **평균 이상 효과**가 자기평가 중심의 일정 추정과 성과 평가에 주는 위험과 외부 기준을 붙이는 방법
- 편향을 **조직 차원 장치**(ADR, 테크스펙, 체크리스트)로 줄이는 방법
