# 기술 로드맵 수립

제품과 기술의 중장기 방향을 단계별로 설계하고 관리하는 역량이다. 로드맵은 "지금 뭘 해야 하는가"와 "왜 이 순서인가"에 대한 답이다.

## 로드맵 설계 원칙

### 1. 단계별 가치 전달
각 단계가 독립적으로 사용자에게 가치를 전달해야 한다. 4단계를 모두 완료해야 의미 있는 것이 아니라, 1단계만으로도 핵심 문제를 해결한다.

### 2. 의존성 기반 순서
기능 간 의존 관계를 분석하여 순서를 결정한다. "인증/권한 설계"가 완료되어야 "조직 기반 기능"이 가능하다.

### 3. 리스크에 맞춘 순서
비용과 계약 부담이 큰 외부 연동은 보통 핵심 가치와 수요를 먼저 검증한 뒤 투자한다. 다만 해당 연동이 제품 성립 자체를 좌우하는 기술적, 규제적 feasibility risk라면 전체 구현을 앞당기기보다 작은 spike나 사전 확인으로 조기에 위험을 줄인다.

## school-manage 조건부 로드맵, 2026-08-26 스냅숏

| 단계 | 전략 | 목표 |
|---|---|---|
| 1단계 | 재직 중 선택지 보존 | Free Core 최소 운영, 장애와 보안 대응, 데이터 보호 및 프로젝트 고정비 절감. 자발적 신규 사용은 허용하되 능동적 모집과 수동 온보딩은 보류 |
| 2단계 | 전환 gate 후 계측 정비 | 같은 코호트의 단체 생성, 학생, 출석과 복귀 행동을 연결 |
| 3단계 | 제한된 기간의 Paid Parish Operations 후보 실험 | 진단과 학기 운영지원의 실제 수납, 납품 부담과 공헌이익 검증 |
| 4단계 | 실험 종료 gate 후 장기 옵션 판단 | Basic/Pro, 광고, 외부 연동과 전 그룹 확장 여부 재검토 |

**핵심 전략: 선택지 보존 → 전환 gate → 계측 신뢰성 확보 → 운영지원 실수납 → 장기 옵션 판단**
- 2026-08-26 현재 1단계이며, 재직 중에는 신규 기능, 마케팅과 유료 실험을 열지 않는다.
- 전환 gate는 퇴사를 실제로 확정하고 사용자가 출석부 활성화를 명시한 때 통과한다.
- gate 통과 후에도 소프트웨어 유료 기능을 먼저 만들지 않는다.
- 현재 상태와 계측 준비를 확인한 뒤 실험 시작일과 종료 조건을 별도로 정한다.
- 운영지원 후보 실험은 구독 전환율이 아니라 실제 수납, 제공 부담과 노동 조정 공헌이익을 검증한다.

## 기술 부채와 로드맵

로드맵에 기술 부채 해결을 명시적으로 포함한다.

**심각도 기반 분류:**
| 심각도 | 예시 | 대응 |
|---|---|---|
| Critical (빨강) | 보안 취약점(IDOR, RTR 미구현) | 즉시 대응, 기능 개발 중단 |
| Warning (노랑) | 성능(ErrorBoundary, 번들 최적화) | 다음 스프린트 포함 |
| Low (초록) | DX 개선(컴포넌트 분리) | 여유 있을 때 |

## 로드맵 관리

### 진행 추적
- 재직 중에는 school-manage의 장애, 보안, 데이터 보호와 비용 변경이 있을 때만 운영 상태를 확인하고 기록한다.
- 전환 gate 뒤에는 현재 상태와 핵심 지표의 기준일 스냅숏을 갱신한다. 비공개 운영 수치는 접근이 통제된 정본에 두고, 공개 문서에는 측정 원칙만 남긴다.
- 실험 중에는 미리 정한 주기로 스냅숏을 비교하되 단일 수치만으로 추세를 단정하지 않는다.

### 유연한 조정
로드맵은 고정이 아니다. 데이터에 기반하여 조정한다.
- 주일학교 중고등부에서 모든 가톨릭 모임으로 넓히는 포지셔닝 전환 가설은 보류한다. 2026-08-26 현재 중고등부 PMF 타깃을 유지하고 운영지원 후보 실험의 종료 gate 뒤 재평가한다.
- 우선순위 변경: 보안 취약점 발견 시 기능 개발보다 보안 패치 우선

### 완료 기준 명확화
각 단계의 완료 조건을 사전에 정의한다.
- 계측 단계: 가입 사용자와 단체의 `first_*` 이벤트를 같은 코호트로 연결
- 운영 단계: 후보 운영 목표는 전환 gate 뒤 다시 검토하며 사업 검증의 진입 조건으로 사용하지 않음
- 유료 실험: 실제 수납, 제공 가능한 납품 부담과 노동 조정 공헌이익을 확인한 뒤에만 장기 제안을 검토

## 면접 포인트

Q. 기술 로드맵을 어떻게 수립하는가?
- 의존성 기반 순서 설계: 선택지 보존 → 계측 신뢰성 → 운영지원 실수납 → 손익 gate → 장기 제품 옵션
- 각 단계가 독립적 가치를 전달하도록 설계
- 비용이 큰 외부 연동은 가치 검증 뒤로 두되, 성립을 좌우하는 feasibility risk는 작은 검증으로 일찍 확인

Q. 로드맵은 어떻게 관리하는가?
- 재직 중에는 school-manage의 선택지 보존에 필요한 운영 사건과 비용 변경만 확인하고, 전환 gate 뒤 기준일과 단위가 있는 스냅숏으로 핵심 지표 추적
- 데이터 기반으로 유연하게 조정 (포지셔닝 전환, 우선순위 변경)
- 기술 부채를 심각도별로 분류하여 로드맵에 명시적 포함
