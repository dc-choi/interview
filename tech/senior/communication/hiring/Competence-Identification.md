# 개발 역량을 과제와 설명으로 확인하기

직무에서 필요한 역량을 먼저 정하고, 실제와 가까운 작업과 구조화된 질문으로 근거를 모은다. 1시간 리팩터링 과제는 사용할 수 있는 한 방법이다. 그 결과만으로 드레퓌스의 Competent 이상을 인증하거나, 면접만으로는 실력을 전혀 알 수 없다고 단정하지 않는다.

## 직무와 평가 방법을 연결한다

OPM은 작업 표본 평가를 실제 업무와 같거나 유사한 과제를 수행하게 하는 방식으로 설명한다. 입사 시 이미 필요한 역량과 입사 후 교육할 역량을 구분해야 한다. 구조화된 면접은 공통 질문과 채점 기준으로 경험과 상황 판단을 평가한다.

두 방법을 개발 채용에 적용할 때는 구현, 변경 안전성, 문제 분석과 협업 중 무엇을 확인하려는지 정한다. 아래 구성은 적용 예시이며 검증된 공통 합격 공식은 아니다.

## 리팩터링 과제 운영 예시

1. **과제 선정**: 실제 역할과 관련된 작은 코드를 제공한다. 공개 권한, 라이선스와 개인정보를 확인하고 실제 고객 자료는 사용하지 않는다.
2. **조건 통일**: 시간, 개발 환경, 검색과 AI 사용 범위, 질문 가능 여부를 사전에 안내한다. 1시간은 운영 예시이며 직무에 맞게 조정한다.
3. **성공 기준**: 기존 동작 유지, 필요한 변경과 검증 범위를 명시한다. 숨은 정답 구조를 맞히게 하지 않는다.
4. **수행 관찰**: 요구를 확인하는 방식, 위험을 찾는 순서와 테스트 결과를 본다.
5. **설명 확인**: 선택한 변경, 유지한 구조와 버린 대안의 이유를 묻는다.

자료를 찾아본다는 사실만으로 숙련 부족이라고 판단하지 않는다. 반대로 도구가 만든 결과물을 설명하지 못하면 해당 판단 능력은 확인되지 않은 것으로 남긴다.

## 무엇을 채점할 것인가

| 관찰 항목 | 확인할 증거 | 피할 대리 지표 |
|---|---|---|
| 요구 이해 | 모호한 동작과 제약을 질문하고 정리한다 | 질문이 적을수록 우수하다는 판단 |
| 변경 안전성 | 중요한 기존 동작과 실패 조건을 검증한다 | 테스트 개수와 커버리지 수치만 비교 |
| 설계 판단 | 변경 비용과 복잡성을 비교하고 이유를 설명한다 | 패턴과 인터페이스 수가 많을수록 우수 |
| 코드 이해 | 입력부터 결과까지 실제 흐름을 추적한다 | 함수 줄 수만으로 합격 판정 |
| 협업 | 지적을 확인하고 근거에 따라 수정하거나 설명한다 | 면접관 취향에 즉시 동의하는 태도 |

예를 들어 반복되는 `switch`가 변경을 어렵게 만들면 다른 구조를 검토할 수 있다. 단순한 분기를 유지하는 편이 명확하다면 Strategy나 Adapter를 추가하지 않는 판단도 타당하다. 관련 기준은 [[Code-Quality-Criteria|코드 품질의 기준]]에서 확인한다.

## 평가자의 판단도 검증한다

- 질문과 기준을 후보자마다 임의로 바꾸지 않고, 관찰한 행동과 해석을 구분해 기록한다.
- 가능하면 평가자가 먼저 독립적으로 채점한 뒤 차이의 근거를 논의한다.
- 제한 시간의 성과가 도구 적응이나 낯선 도메인에 좌우됐는지 확인한다.
- 하나의 과제가 측정하지 못한 역량은 다른 질문이나 작업으로 보완한다.

1시간 과제의 성공을 전반적인 성과 예측으로 확대하지 않는다. 해당 조직에서 평가 결과가 실제 업무 수행과 연결되는지도 돌아봐야 한다.

## 드레퓌스 모형의 적용 한계

[[Dreyfus-Skill-Model|드레퓌스 기술 습득 모형]]은 판단 방식의 변화를 설명하는 참고 틀이다. 책 없이 1시간이면 Competent, 5~15분이면 Proficient라는 채점표는 모형에서 검증한 기준이 아니다. 코칭 자격, 팀 생산성 배수와 적정 단계별 인원 비율도 도출하지 않는다.

숙련된 구성원의 리뷰와 교육이 도움이 되는지는 실제 오류, 재작업과 동료의 독립 수행 변화를 확인한다. 조직 전체에 특정인의 방식을 강제하는 것과 지식을 나누는 것은 구분한다.

## 채용 과정 구성 예시

직무에 필요한 기본 조건을 확인한 뒤 작업 과제, 결과 설명과 구조화된 경험 질문을 조합할 수 있다. 모든 역할에 동일한 알고리즘, 리팩터링과 시스템 설계 단계를 요구하지 않는다. [[Hiring-Interview|채용 인터뷰]]와 [[Hiring-Under-Uncertainty|불확실성 속 채용]]에서 역할과 조직 조건을 함께 검토한다.
