# 기술 용어를 쉽게 설명하고 원어와 연결하기

쉬운 전문용어는 개념을 덜 정확하게 만드는 번역이 아니다. 독자가 이해할 표현으로 의미를 풀되, 원문과 기존 용어로 다시 찾아갈 연결을 남기는 방식이다. 순우리말만 쓰는 규칙도 아니다. 이미 익숙한 외래어는 그대로 쓸 수 있다.

## 뜻을 확인한 뒤 표현을 고른다

1. 해당 분야에서 용어가 뜻하는 대상, 동작과 적용 범위를 먼저 확인한다.
2. 독자가 모를 표현은 쉬운 설명을 붙이거나 더 구체적인 말로 바꾼다.
3. 새 번역을 제안하면 원어와 기존 용어를 함께 적어 검색과 원문 대조를 돕는다.
4. 한 원어에 여러 의미가 있으면 문맥별로 풀어 쓴다. 같은 문서의 같은 개념은 일관되게 부른다.

Google의 문서 작성 지침은 한 번만 쓰는 전문용어는 풀어 설명하고 괄호에 용어를 붙이거나 정의로 연결하도록 권한다. 반복할 용어는 처음 등장할 때 짧게 설명한다. 검색에 필요한 용어와 독자가 이미 아는 용어까지 일괄 제거할 필요는 없다.

## 쉬운 표현은 정의를 대신하지 않는다

공개 용어 제안 사이트 easyword.kr의 continuation 항목에는 마저할일, 앞으로 할 계산 같은 제안이 있다. 이는 직관을 돕는 번역 후보이며 표준 번역의 확정이나 프로그래밍 언어별 동작을 증명하는 자료가 아니다.

실무 문서에서는 **쉬운 설명, 원어, 구체적 예, 적용 범위**를 함께 적는 방법을 제안한다. 새 표현만 외우게 하기보다 독자가 원래 문서와 코드를 찾아갈 수 있게 한다. 명령어, API 이름과 코드 식별자는 번역하지 않고 설명을 붙인다.

## 검토할 질문

- 독자가 용어를 몰라도 무엇을 해야 하는지 이해할 수 있는가?
- 쉬운 말로 바꾸면서 조건이나 예외가 사라지지 않았는가?
- 원어와 기존 용어를 검색해 같은 개념으로 돌아갈 수 있는가?
- 번역 제안을 공인된 정의나 학습 효과의 실증 결과로 과장하지 않았는가?
