# 신뢰와 존중의 팀워크

팀워크를 특정한 성격 조합이나 친분으로 설명하면 재현하기 어렵다. Google의 Project Aristotle은 자사 180개 팀을 연구해 누가 팀에 있는가보다 팀이 어떻게 함께 일하는가가 더 중요했다고 보고했고, 심리적 안전, 신뢰할 수 있는 수행, 구조와 명료성, 의미와 영향이라는 다섯 동학을 제시했다. 이는 Google 내부 표본에서 나온 결과이므로 모든 조직의 보편 법칙으로 단정하지 않는다.

## 다섯 동학을 행동으로 바꾼다

| 동학 | 확인할 행동 |
|---|---|
| 심리적 안전 | 실수, 질문, 반대 의견과 도움 요청을 불이익 우려 없이 꺼낼 수 있는가 |
| 신뢰할 수 있는 수행 | 맡은 품질과 기한을 지키고, 위험이 생기면 늦기 전에 알리는가 |
| 구조와 명료성 | 목표, 역할, 결정권과 완료 기준이 분명한가 |
| 의미 | 구성원이 일이 자신에게 왜 중요한지 설명할 수 있는가 |
| 영향 | 일이 사용자와 조직의 결과에 어떻게 연결되는지 확인할 수 있는가 |

심리적 안전은 기준을 낮추거나 모든 의견에 동의하는 상태가 아니다. 문제를 드러내도 처벌받지 않으면서 품질 기준과 책임은 분명한 상태다. 실패를 다루는 구체적인 절차는 [[Failure-Tolerant-Culture|실패에 관대한 문화와 심리적 안전]]을 따른다.

## 신뢰와 존중의 운영 방식

- 약속한 결과와 기한을 지키되, 지키기 어렵다는 신호를 발견하면 영향과 대안을 함께 알린다.
- 위임할 때 목표, 경계와 확인 시점을 합의하고 방법의 주도권은 담당자에게 둔다.
- 피드백은 사람의 성격이 아니라 관찰한 행동, 영향과 다음 기대를 다룬다.
- 다른 의견은 숨기지 않되 상대의 맥락을 먼저 확인하고 판단 근거를 공개한다.
- 도움 요청과 모른다는 표현을 무능의 증거가 아니라 위험을 일찍 드러내는 행동으로 취급한다.

존중은 에둘러 말하는 것과 다르다. [[Radical-Candor-Feedback|Radical Candor]]가 설명하듯 상대를 사람으로 존중하면서도 필요한 문제는 직접 제기할 수 있다.

## 면접 체크포인트

- "협업에서 중요하게 생각하는 것은?" → 심리적 안전, 수행 신뢰와 목표 명료성을 실제 행동으로 설명한다.
- "동료와 갈등이 있었다면?" → 관찰 사실, 영향, 서로의 근거와 합의한 다음 행동을 분리한다.
- "기한을 못 지킬 것 같으면?" → 늦기 전에 영향, 원인과 선택 가능한 대안을 공유한 경험으로 답한다.
