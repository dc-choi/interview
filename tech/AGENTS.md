# Technical Knowledge Domain Rules

이 파일은 `tech/` 아래의 기술 지식 문서, 카테고리 인덱스와 기술 메모에 적용한다. 메모 입력을 문서화할 때는 `memo` 스킬도 함께 사용한다.

`tech/senior/`에서 조직 문화, 의사결정, 피드백, 회고와 OKR을 다룰 때는 `fit/AGENTS.md`도 읽는다.

## 현재 실무 기술 축

- 현재 주력 ORM은 TypeORM이다. ORM 학습, 기술 문서와 면접 답변에서는 `@nestjs/typeorm`, QueryRunner 트랜잭션과 마이그레이션 CLI를 우선하고 Prisma는 과거 실무 사례로 활용한다.

## 기술 문서 최신성

- AWS, OpenAI, Anthropic, Node.js, TypeScript, Kubernetes, 데이터베이스 제품과 보안 표준처럼 변동성이 큰 기술 문서는 공식 1차 출처를 확인한 날짜를 frontmatter의 `verified_at: YYYY-MM-DD`로 기록한다. 비공식 출처가 정본인 경험 기반 문서는 아래 예외를 따른다.
- `verified_at`은 그 문서의 본문과 출처를 실제로 대조한 경우에만 갱신한다. 문서 일부만 대조한 부분 검증도 갱신 사유이지만, 새로 추가하거나 수정한 사실을 공식 1차 출처와 대조했고 문서에 남은 버전 민감 주장이 그 출처와 상충하지 않음을 확인했을 때만 갱신하며, 문서 전체를 다시 대조했다는 뜻은 아니다. 다른 문서에서 검증한 사실을 링크로 참조만 하거나 자동 스캔, 파일 이동만 한 경우에는 갱신하지 않고, `## 출처`가 없는 순수 TOC 인덱스에는 두지 않는다.
- 분할로 새로 만든 문서의 `verified_at`은 옮긴 내용을 마지막으로 공식 출처와 대조한 날짜로 쓴다. 옮긴 내용의 대조 날짜가 섞여 있으면 가장 오래된 날짜를 쓰고, 분할 시점에 전부 다시 대조했으면 그날로 쓴다. 부모의 현재 날짜를 자동으로 물려받지 않는다.
- 발표, 밋업 같은 비공식 출처만이 정본인 경험 기반 문서에는 `verified_at`을 두지 않고, 버전 민감 주장에는 본문에 기준을 명시한다 (예: 발표 기준, MySQL 8.4 문서 기준). 공식 1차 출처가 본문의 버전 민감 주장 전부를 직접 뒷받침하게 되면 그때 `verified_at`을 둘 수 있다.
- 가격, quota, 지원 정책, 시험 범위, 제품 버전과 API 동작은 공식 출처와 검증 기준일 없이 현재 사실처럼 단정하지 않는다. 검증 기준일은 frontmatter `verified_at` 또는 본문의 기준 명시로 제공한다.
- `항상`, `무조건`, `제한 없음`, `지원 종료`, `무료`, `동일`과 `완전` 같은 절대 표현은 공식 규격이나 정책이 전체 범위를 보장하고 출처를 함께 제시할 때만 쓴다. 그렇지 않으면 버전, 리전, 에디션, 시점과 예외 조건을 명시한다.
- 사실 관계를 수정했다면 관련 문서의 상충 표현과 출처를 함께 확인하고, 위의 갱신 조건을 만족한 문서에 한해 `verified_at`을 갱신한다.

## 출처 표기

- `## 출처`의 유형은 셋으로 나눈다: 1) 블로그, 아티클과 발표(그 밖의 출처 포함) 2) 레퍼런스 매뉴얼과 명세(버전 표기가 없는 벤더 제품 문서인 Documentation, User Guide, Reference류 포함) 3) 강의. 항목을 추가할 때는 그 문서에 있는 같은 유형 항목의 표기를 그대로 따르고, 표기가 섞여 있으면 같은 유형의 다수 표기, 동수면 기본형을 따른다. 기존 항목을 다른 표기로 일괄 변환하지 않는다. 단, 루트 표기 규칙이 금지한 표기는 선례라도 따르지 않고 그 자리에서 고친다. 2026-08-25 벤더 제품 문서 표기 정규화는 사용자 지시로 수행한 일회성 예외다.
- 같은 유형의 선례가 없으면 기본형을 쓴다. 블로그, 아티클과 발표는 제목 뒤에 em-dash로 매체나 저자를 붙인 `- [제목 — 매체](URL)`를 쓰고, 매체와 저자를 함께 쓰면 `- [제목 — 매체, 저자](URL)`로 잇는다. 책, 저장소, 릴리스 노트 같은 그 밖의 출처도 이 형태를 쓴다. 레퍼런스 매뉴얼과 명세는 매체를 앞에 둔 쉼표형 `- [매체, 문서명](URL)`을 쓴다. 강의는 `- [플랫폼, 강좌명 또는 강사명, 강의명](URL)`을 쓰고 가운데 항목은 식별에 필요하지 않으면 생략한다.
- 문서 전체를 인용해 라벨이 매체명 자체일 때는 쉼표형 대신 구분자 없이 그대로 쓴다 (예: `- [MySQL 8.4 Error Message Reference](URL)`).
- 새 지식 문서 하단 절 순서는 `## 출처` 다음 `## 관련 문서`를 기본으로 한다. 기존 문서의 반대 순서는 재배치하지 않고 유지한다.

## 카테고리 인덱스

- `tech/` 카테고리 최상위 인덱스는 루트의 leaf 폴더 분할 규칙에서 제외한다.
- 기술 메모를 추가하거나 이동할 때 대상 카테고리 인덱스를 함께 갱신한다.
