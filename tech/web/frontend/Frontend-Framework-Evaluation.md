# 프론트엔드 도구의 개발 비용과 유지보수 평가

프레임워크 선택에는 처음 만드는 비용, 결과물의 사용자 경험과 오래 유지할 비용이 함께 들어간다. AI가 코드를 생성하더라도 기능 검증, 접근성, 업데이트와 장애 대응은 남는다.

## 같은 조건에서 비교하기

| 축 | 측정할 내용 |
|---|---|
| 생성 비용 | 모델/추론 설정, 입력 문서, 도구 호출, 토큰과 재시도 |
| 완료 기준 | 기능 적합성, 실패한 실행을 포함한 성공률 |
| 사용자 경험 | 전송 JS, 로딩과 상호작용, 실제 보조 기술과 키보드 사용 |
| 유지보수 | 변경 난이도, 의존성, 보안 수정과 브라우저 지원 |

API 단가로 환산한 금액과 구독에서 실제 추가 지출한 금액은 다르다. 비용 중앙값만 비교하지 말고 반복 간 분산과 실패를 포함한다. Lighthouse 접근성 점수는 자동 검사의 결과이며 모든 사용자의 접근성을 증명하지 않는다.

## AI 생성 비교의 범위

2026-10-28 Nolan Lawson의 실험은 Opus 5.5 high로 콘텐츠 중심 포켓몬 앱을 12개 조합에서 만들었다. 각 조합을 5회 실행했으며 Angular는 두 번 측정 가능한 앱을 만들지 못해 일부 지표에 3회만 사용했다. API 환산 비용 중앙값은 Hono+htmx 2.67달러, Angular 4.97달러였다. 공식 MCP/스킬도 제공했다.

한 앱과 모델의 결과로 모든 제품의 최적 프레임워크를 정하지 않는다. 문서 탐색과 생성 코드량이 비용에 영향을 줬다는 설명은 가능한 원인이다. 제공 발췌의 Astro 8.2분, Hono+htmx 8.6분, Angular 17.2분과 Lighthouse 97~100점 수치도 이 실험 범위에 한정하며 독립 재현값은 아니다.

## 작은 CSS 의존성의 종료 판단

2026-11-02 확인한 Pico CSS 저장소는 v2.1.1을 마지막 릴리스로 유지보수 종료를 안내한다. 기존 파일 사용 가능성과 앞으로 수정본이 나온다는 보장은 별개다. 프로젝트 유지보수자는 AI로 필요한 CSS를 생성할 수 있다는 판단과, Sass 및 오래된 구조를 현대 CSS로 바꾸는 전면 재작성 부담을 종료 이유로 제시한다. 이는 모든 제품에서 CSS 프레임워크가 불필요하다는 실증 결과가 아니다.

기존 제품은 즉시 재작성하기보다 사용 기능, 브라우저 변화와 수정 책임을 확인한다. 독립 CSS로 옮길 때도 focus, 대비, 반응형과 폼 상태를 검증한다. 버전 고정, 자체 유지보수와 대체 도구 전환 중 실제 위험과 변경 비용에 맞는 선택을 한다.
