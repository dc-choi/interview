# 네트워크 기능 가상화(NFV)

NFV(Network Functions Virtualisation)는 통신망의 방화벽, 라우터, 이동통신 코어 같은 네트워크 기능을 전용 하드웨어 장비 대신 범용 서버, 스위치, 스토리지에서 도는 소프트웨어로 구현하는 접근이다. 2012-10 독일 다름슈타트의 SDN and OpenFlow World Congress에서 13개 통신사업자가 공동 발표한 소개 백서가 출발점이며, 이후 ETSI의 NFV ISG(Industry Specification Group)가 아키텍처 프레임워크(GS NFV 002) 등 규격을 냈다. 아래 아키텍처 설명은 ETSI GS NFV 002 V1.2.1(2014-12) 기준이며 이후 판과 상세 규격은 대조하지 않았다.

## 해결하려던 문제

백서는 통신사업자 망에 기능마다 다른 독자 하드웨어 장비가 늘어나는 상황을 문제로 든다.

- 새 서비스를 낼 때마다 또 다른 장비가 필요하고, 그 장비를 둘 공간과 전력을 확보하기가 점점 어려워진다.
- 에너지 비용, 설비 투자 부담, 복잡한 장비를 설계하고 통합, 운영할 인력의 희소성이 겹친다.
- 하드웨어 장비가 빨리 수명을 다해 조달, 설계, 통합, 배치 주기를 수익이 거의 없이 반복하게 되고, 기술 혁신이 빨라질수록 수명 주기가 더 짧아진다.

NFV는 표준 IT 가상화 기술로 여러 장비 유형을 데이터센터, 네트워크 노드, 최종 사용자 구내에 둘 수 있는 대량 생산 범용 서버, 스위치, 스토리지로 모으려 한다. 기능을 소프트웨어로 구현하므로 새 장비를 설치하지 않고도 망의 여러 위치로 옮기거나 새로 띄울 수 있다. 백서는 고정망과 이동통신망의 데이터 평면 패킷 처리와 제어 평면 기능 전반에 적용할 수 있다고 본다. 예시로 BNG, CG-NAT, 라우터, MME, SGSN, PDN-GW, 홈 라우터와 셋톱박스 기능, IPSec/SSL VPN 게이트웨이, DPI, IMS, CDN, 로드 밸런서, 방화벽과 침입 탐지를 든다.

## 기대 이점과 과제

백서가 내세운 이점은 장비 통합과 IT 산업의 규모의 경제로 장비 비용과 전력 소비 절감, 출시 시간 단축, 같은 인프라에서 운영, 시험, 참조 환경을 함께 돌리기, 지역이나 고객군에 맞춘 서비스 도입과 빠른 확장 및 축소, 원격 소프트웨어 프로비저닝, 멀티테넌시, 한가한 시간대에 작업을 적은 서버로 모으고 나머지를 끄는 에너지 절감이다. 이는 2012년 저자들이 기대한 이점이며 측정 결과가 아니다.

같은 백서는 풀어야 할 과제도 함께 적는다.

| 과제 | 내용 |
|---|---|
| 이식성과 상호운용성 | 다른 공급사의 하드웨어와 하이퍼바이저 사이에서 가상 장비를 옮겨 실행할 통일된 인터페이스 |
| 성능 저하 | 가속 엔진 같은 전용 하드웨어를 쓰지 않으므로 지연, 처리량과 처리 오버헤드의 손실을 최소화해야 한다. 백서는 Enablers 절에서 고속 멀티코어 CPU, 스마트 NIC, 인터럽트 대신 poll-mode 드라이버(예: DPDK)로 고성능 패킷 처리가 가능하다고 설명한다 |
| 기존 장비와 공존 | 물리 장비와 가상 장비가 섞인 망에서 기존 EMS, NMS, OSS/BSS와 호환되고, 같은 기능의 물리 장비와 연동해야 한다 |
| 관리와 오케스트레이션 | 많은 가상 장비를 레거시 관리 시스템과 함께 일관되게 관리, 조율해야 한다 |
| 자동화 | 모든 기능을 자동화할 수 있어야 확장된다 |
| 보안과 복원력 | 가상 장비의 보안은 하이퍼바이저와 그 설정의 보안에 기댄다. 장애 뒤 기능을 다시 만들어 가용성을 높일 수 있다는 기대도 함께 적는다 |
| 망 안정성 | 기능 재배치, 재구성, 장애와 공격 상황에서 여러 제어와 최적화 메커니즘이 엇갈려 불안정해지지 않게 해야 한다 |
| 단순성과 통합 | 운영 부담을 다른 형태의 부담으로 바꾸지 않고, 여러 공급사의 서버, 하이퍼바이저, 가상 장비를 큰 통합 비용과 종속 없이 조합해야 한다 |

## SDN과의 관계

백서는 NFV와 SDN이 서로를 크게 보완하지만 의존하지는 않는다고 설명한다. NFV는 SDN 없이 기존 데이터센터 기법으로도 구현할 수 있고 그 반대도 가능하다. 다만 SDN처럼 제어 평면과 데이터 전달 평면을 분리하면 성능, 기존 구성과의 호환, 운영과 유지보수를 개선할 수 있고, NFV는 SDN 소프트웨어가 돌 인프라를 제공할 수 있다. 같은 기능을 무엇으로 구현하느냐(NFV)와 망의 전달 동작을 어떻게 제어하느냐(SDN)를 나눠 읽는다(해석).

## 아키텍처 구성요소 (GS NFV 002 V1.2.1)

규격은 NFV를 세 작업 영역으로 나눈다. NFVI 위에서 도는 네트워크 기능의 소프트웨어 구현인 VNF, 물리 자원과 그 가상화를 포함해 VNF 실행을 지원하는 NFVI, 그리고 이들의 오케스트레이션과 수명 주기 관리를 맡는 NFV Management and Orchestration이다.

| 기능 블록 | 역할 |
|---|---|
| VNF | 기존 비가상화 망의 네트워크 기능(NF)을 가상화한 것이다. 기능 동작과 외부 운영 인터페이스는 물리 네트워크 기능(PNF)과 같을 것으로 기대한다. 한 VNF가 여러 VM에 나뉘어 배치될 수도, 한 VM에 통째로 배치될 수도 있다 |
| EM(Element Management) | 하나 이상의 VNF에 대한 통상적인 관리 기능 |
| NFVI | VNF가 배치, 관리, 실행되는 환경을 이루는 하드웨어와 소프트웨어 전체다. 여러 위치(NFVI-PoP)에 걸칠 수 있고 위치 사이를 잇는 망도 포함한다. 가상화 계층(예: 하이퍼바이저)이 하드웨어를 추상화해 VNF의 수명 주기를 하드웨어와 분리한다. 하이퍼바이저와 VM은 대표적 방식일 뿐이며 비가상화 서버의 OS 위나 bare metal에서 VNF를 돌리는 방식도 규격이 언급한다 |
| VIM(Virtualised Infrastructure Manager) | NFVI의 컴퓨트, 스토리지, 네트워크 자원 목록, 할당과 회수, 장애와 용량 정보 수집. 여러 인스턴스를 둘 수 있다 |
| NFV Orchestrator | NFVI와 소프트웨어 자원의 오케스트레이션과 관리, NFVI 위에서 네트워크 서비스 실현 |
| VNF Manager | VNF 수명 주기 관리(생성, 갱신, 조회, 확장과 축소, 종료). VNF마다 둘 수도, 하나가 여러 VNF를 맡을 수도 있다 |
| Service, VNF and Infrastructure Description | VNF 배치 템플릿, VNF Forwarding Graph, 서비스와 인프라 정보 모델 |
| OSS/BSS | 사업자의 운영 지원과 사업 지원 시스템 |

네트워크 서비스는 종단점과 네트워크 기능을 노드로 둔 forwarding graph로 표현한다. 웹 서버 앞의 방화벽, NAT, 로드 밸런서 체인처럼 VNF 사이의 연결을 명시한 것이 VNF-FG이고, 연결을 명시하지 않은 웹 서버 풀 같은 묶음이 VNF Set이다. 주요 참조점으로 Os-Ma(OSS/BSS와 NFV MANO), Or-Vnfm, Vi-Vnfm, Or-Vi, Nf-Vi, Ve-Vnfm이 있고, 실행 참조점으로 VNF와 NFVI 사이의 Vn-Nf, 가상화 계층과 하드웨어 사이의 Vl-Ha를 따로 둔다. 규격은 기능 수준의 틀이며 특정 구현을 제안하지 않고, 어떤 기능을 가상화할지는 망 소유자의 결정으로 둔다.

## 읽을 때 주의할 점

- 가상화로 장비 비용과 전력이 줄어든다는 말은 백서의 기대 이점이다. 같은 백서가 성능 저하, 통합 비용, 운영 단순성을 과제로 함께 적었으므로 TCO 절감을 결론처럼 일반화하지 않는다.
- NFV의 E2E 서비스 동작은 가상화 여부와 관계없이 같아야 한다는 것이 규격의 전제다. 서비스 관점에서는 위치 인식이나 이중화 같은 특정 정책 제약을 보장하는 경우를 빼고 VNF의 물리 배치가 보이지 않지만, 설정과 진단, 장애 처리를 위해서는 VNF와 인프라가 보여야 한다.
- 일반 서버 가상화의 개념(하이퍼바이저와 VM)은 [[Virtual-Machines-and-Hypervisors|가상 머신과 하이퍼바이저]]에서, 교환과 서비스 로직을 분리한 이전 세대 통신망 구조는 [[Intelligent-Network|지능망]]에서 이어 읽는다.
