# LAN과 WAN: 크기가 아니라 주소 체계로 구분한다

LAN(Local Area Network)과 WAN(Wide Area Network)을 좁으면 LAN, 넓으면 WAN이라는 거리 기준으로만 나누면 경계가 흐려진다. 캠퍼스 하나를 덮는 LAN이 있고, 방 두 개 사이를 잇는 WAN 회선도 있다. 더 정확한 기준은 데이터가 어느 주소 체계로 상대를 찾는가다. 같은 링크 안에서 MAC 주소로 직접 닿는 범위가 LAN이고, IP 주소와 라우터를 거쳐야 닿는 연결이 WAN이다.

## 정의

| 구분 | LAN | WAN |
|---|---|---|
| 도달 방식 | 프레임이 같은 링크의 상대에게 직접 도달 | 패킷이 라우터를 거쳐 다른 네트워크로 전달 |
| 식별자 | MAC 주소 (인터페이스 고유, L2) | IP 주소 (네트워크 위치, L3) |
| 범위의 경계 | 브로드캐스트가 도달하는 범위 | 라우팅 테이블이 아는 네트워크의 집합 |
| 성격 | 하드웨어와 물리 연결 중심 | 물리 네트워크들을 논리적으로 묶은 추상화 |
| 대표 기술 | Ethernet, Wi-Fi, 스위치 | IP, 라우터, 전용선과 ISP 망 |

인터넷은 여러 물리 네트워크를 IP라는 하나의 논리 네트워크로 묶은 것이고, 이 상호 연결(internetwork)에서 이름이 나왔다. 그래서 WAN의 본질은 거리가 아니라 물리 링크 위에 얹힌 논리 주소 체계다.

## 동작 원리: 호스트는 어떻게 LAN 안팎을 가르는가

1. 호스트는 목적지 IP가 자기 인터페이스와 같은 서브넷에 있으면 로컬, 아니면 원격으로 판단한다. 서브넷 마스크로 네트워크 부분을 비교하는 것이 기준이다.
2. 로컬이면 ARP로 목적지 IP의 MAC을 알아내 프레임을 직접 보낸다. 브로드캐스트 프레임(FF:FF:FF:FF:FF:FF)이 닿는 범위가 곧 이 로컬 범위다. 실무에서 LAN의 경계는 브로드캐스트 도메인과 같다고 보면 되고, 한 브로드캐스트 도메인에 서브넷이 여럿 올라가는 예외는 있다.
3. 원격이면 프레임의 목적지 MAC을 게이트웨이 라우터의 MAC으로 채우고, 라우터가 IP 헤더를 보고 다음 네트워크로 넘긴다. IP 주소는 끝까지 유지되고 MAC은 구간마다 바뀐다.

같은 판단을 라우터도 반복하므로, 인터넷은 LAN들의 연쇄다. 각 LAN 안에서는 MAC이, LAN 사이에서는 IP가 상대를 찾는다.

## 물리 네트워크와 논리 네트워크

컴퓨터가 하드웨어와 소프트웨어로 나뉘듯 네트워크도 물리 계층과 논리 계층으로 나뉜다. 케이블, 스위치, 무선 링크가 물리 네트워크이고, 그 위에 IP 주소와 라우팅으로 만든 연결이 논리 네트워크다.

이 구분이 크기 기준을 흔드는 이유는 논리 네트워크가 물리 배치와 어긋날 수 있기 때문이다.

- **VLAN**: 한 스위치에 꽂힌 장비를 여러 브로드캐스트 도메인으로 나눈다. 물리적으로 옆자리여도 다른 LAN이다.
- **VPN과 오버레이**: 지구 반대편 장비를 같은 사설 네트워크처럼 보이게 한다. 물리적으로 멀어도 논리적으로 한 네트워크다.
- **가상화와 컨테이너**: 한 호스트 안의 가상 브리지가 독립된 L2 네트워크를 만든다. 물리 케이블 없이도 LAN이 생긴다 ([[Docker-Bridge-Networking]]).
- **클라우드 VPC**: 서브넷과 라우팅 테이블을 소프트웨어로 정의한다. LAN과 WAN의 경계가 설정 값이 된다.

## 판별 예시

| 상황 | 판단 | 근거 |
|---|---|---|
| 집 공유기에 연결된 노트북에서 같은 공유기의 프린터로 인쇄 | LAN | 같은 서브넷, ARP와 MAC으로 직접 전달 |
| 집에서 회사 서버에 HTTPS 접속 | WAN | 기본 게이트웨이를 거쳐 여러 라우터를 경유 |
| 회사 VPN에 붙은 뒤 사내 파일 서버 접속 | 논리적으로는 사내 네트워크, 물리적으로는 WAN | 터널이 IP 경로를 감쌀 뿐 라우팅은 여전히 필요 |
| 같은 스위치의 다른 VLAN에 있는 동료 PC | 다른 LAN | 브로드캐스트가 닿지 않고 L3 장비를 거쳐야 함 |

## 트레이드오프와 흔한 오해

- **LAN이라고 항상 빠르고 안전하지는 않다.** 브로드캐스트 도메인이 크면 ARP와 브로드캐스트 트래픽이 모든 장비에 닿아 성능과 보안이 나빠진다. 그래서 큰 LAN은 VLAN과 라우팅으로 나눈다.
- **WAN이라고 항상 멀지는 않다.** 두 건물 사이의 전용선도, 클라우드 리전 안의 VPC 간 피어링도 라우팅을 거치면 WAN 성격이다.
- **MAC은 전 세계 식별자가 아니다.** 보통 제조 시 고유하게 부여되지만 라우터를 넘어가지 않고 구간마다 교체되므로 인터넷 규모의 식별과 전달에는 IP가 필요하다.
- **물리 배치가 논리 경계를 보장하지 않는다.** 같은 방의 장비가 다른 네트워크일 수 있고, 다른 대륙의 장비가 같은 사설 네트워크일 수 있다. 장애 분석에서는 케이블이 아니라 서브넷과 라우팅 테이블을 먼저 본다.

## 면접 체크포인트

- LAN과 WAN을 거리가 아니라 MAC 직접 전달과 IP 라우팅으로 구분하는 기준
- LAN의 경계가 브로드캐스트 도메인과 일치하는 이유와 이를 나누는 장비(VLAN, 라우터)
- 호스트의 로컬과 원격 판단 절차와 ARP, 게이트웨이의 역할
- 인터넷이 물리 네트워크들을 IP로 묶은 논리 네트워크라는 점과 이름의 유래
- VLAN, VPN, 컨테이너 브리지, VPC가 물리 크기 기준을 무의미하게 만드는 이유
