# IPv4 서브넷팅과 주소 관리

서브넷팅은 하나의 IP 주소 블록을 더 긴 프리픽스의 작은 블록으로 나누는 것이다. 필요한 호스트 수에 맞춰 주소 공간을 배분하고, 라우팅과 관리 단위를 정한다. 주소 공간의 크기는 회선 대역폭과 다르며, 서브넷을 나눴다는 사실만으로 처리 속도나 보안이 개선되지는 않는다.

## 네트워크와 호스트의 경계 이동

IPv4는 32비트다. `/24`는 앞 24비트를 네트워크 프리픽스로, 뒤 8비트를 호스트 부분으로 사용한다. 마스크는 `255.255.255.0`이다. 현재 설계는 A/B/C 클래스가 아니라 CIDR의 프리픽스 길이를 기준으로 한다. 기본 개념은 [[Network-Layer]].

호스트 부분에서 1비트를 가져와 `/25`로 늘리면 2개의 서브넷이 된다. 마스크는 `255.255.255.128`이고, 각 서브넷에는 `2^7 = 128`개 주소가 있다.

- `/p`를 동일한 크기의 `/q`로 나눌 때 서브넷 개수: `2^(q-p)` (`p < q ≤ 32`)
- 각 서브넷의 전체 주소 수: `2^(32-q)`
- 일반적인 IPv4 브로드캐스트 서브넷의 호스트 할당 가능 수: `2^(32-q) - 2`. `/31`, `/32`에는 이 공식을 적용하지 않는다.

## 예시: 192.168.10.0/24를 두 /25로 분할

| 항목 | 첫 번째 서브넷 | 두 번째 서브넷 |
|---|---|---|
| CIDR | `192.168.10.0/25` | `192.168.10.128/25` |
| 네트워크 주소 | `192.168.10.0` | `192.168.10.128` |
| 호스트 할당 범위 | `192.168.10.1`~`192.168.10.126` | `192.168.10.129`~`192.168.10.254` |
| 브로드캐스트 주소 | `192.168.10.127` | `192.168.10.255` |
| 호스트 할당 가능 수 | 126 | 126 |

네트워크 주소는 **호스트 부분**의 비트가 모두 0이고, 브로드캐스트 주소는 호스트 부분이 모두 1이다. 전체 32비트가 0 또는 1이라는 뜻이 아니다. 마지막 옥텟이 `.0`이나 `.255`인지로만 판단하지 않고 프리픽스와 함께 계산한다.

단말 100개에 게이트웨이 1개를 할당한다면 위 `/25` 하나에 들어가고 25개가 남는다. 남은 `/25`는 다른 용도로 할당할 수 있다. 성장분과 추가 장비를 포함해 필요한 주소 수를 먼저 계산한다. 서브넷마다 크기가 다르면 VLSM으로 다른 프리픽스 길이를 배분할 수 있다.

## 예약 주소, 게이트웨이와 예외

게이트웨이 주소는 프로토콜상 사용할 수 없는 주소가 아니라 라우터 인터페이스에 **실제로 할당하는 호스트 주소**다. 위 예시에서 `.1`을 게이트웨이로 쓰면 단말용 주소는 125개지만, 네트워크에 반드시 3개의 미사용 주소가 있는 것은 아니다. 게이트웨이가 반드시 첫 번째 주소여야 하는 규칙도 없다.

- **`/31` 점대점 링크**: RFC 3021에 따라 두 주소를 양 끝의 호스트 주소로 사용한다. 양쪽 장비의 지원을 확인한다.
- **`/32`**: 단일 주소를 가리키는 호스트 경로 등에 사용한다. 일반 LAN의 호스트 수에서 2개를 빼는 계산을 적용하지 않는다.
- **서비스별 예약**: 클라우드나 가상 네트워크는 추가 주소를 예약할 수 있다. 해당 서비스의 현재 규칙을 따로 확인한다.
- **IPv6**: 주소 길이가 128비트이고 브로드캐스트를 사용하지 않으므로 IPv4의 주소 수 공식을 그대로 옮기지 않는다.

`/24`의 일반 호스트 주소는 254개지만 두 `/25`에서는 합계 252개다. 네트워크/브로드캐스트 예약이 늘기 때문이다. 잘게 나누면 관리 단위를 맞추기 쉽지만 예약 주소, 경로와 정책 관리가 늘어나는 비용이 있다.

## 브로드캐스트 통제와 보안의 조건

주소 프리픽스를 나누는 L3 서브넷팅과 이더넷의 L2 브로드캐스트 도메인 분리는 다른 작업이다. 같은 VLAN에 서로 다른 IP 서브넷을 설정해도 이더넷 브로드캐스트의 전달 범위는 그대로다.

일반적인 LAN 설계에서는 VLAN이나 별도 링크로 L2 영역을 나누고 각 영역에 다른 서브넷을 배치한다. 라우터는 로컬 브로드캐스트를 다른 서브넷에 그대로 전달하지 않으며, DHCP 릴레이 같은 별도 기능은 필요한 요청을 중계한다. 영역 사이의 통신 허용 여부는 라우팅과 ACL/방화벽으로 정한다.

장치가 많으면 브로드캐스트 처리 부담이 커질 수 있지만, 장치 수만으로 성능이 급격히 저하된다고 단정하지 않는다. 실제 브로드캐스트 발생률, 링크 이용률과 장비 처리량을 보고 분할 효과를 판단한다. 사설 주소와 서브넷 분할만으로 내부 장치를 신뢰하거나 접근을 허용하지 않는다.

## 설계 체크포인트

- 단말, 게이트웨이, 가상 IP, 예약과 성장분을 합산했는가?
- 서브넷 경계가 올바르고 다른 사내망이나 VPN 대역과 겹치지 않는가?
- 주소 관리만 나누려는지, L2 브로드캐스트와 접근 권한도 분리하려는지 정했는가?
- VLAN, 라우팅, DHCP와 방화벽 정책이 같은 설계를 따르는가?
