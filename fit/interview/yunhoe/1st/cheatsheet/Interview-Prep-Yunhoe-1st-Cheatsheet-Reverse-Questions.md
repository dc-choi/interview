# 윤회 1차 치트시트, 역질문

질문은 확인하려는 이유를 한 문장 붙여 정중하게 묻는다. 받은 답은 제3자 발화 원문이 아니라 내 판단에 필요한 역할 기반 요약으로 회고에 남긴다.

도입은 역할을 오래 책임지려면 몇 가지를 확인하고 싶다는 취지로 짧게 한다. 질문을 검사처럼 나열하지 않고, 답변 흐름에 맞는 항목을 네 개 안팎으로 고른다.

1. 이 역할이 처음 해결해야 할 가장 중요한 문제와 첫 몇 달의 성공 기준은 무엇인가?
2. 데이터 생애주기와 외부 연동에서 지금 가장 위험하다고 보는 지점은 무엇이며, 어떤 책임을 먼저 맡게 되는가?
3. 기술 결정, 코드 리뷰, 배포, 장애 대응은 어떤 방식으로 이루어지고 책임 경계는 어떻게 나뉘는가?
4. 표준이나 외부 파트너의 요구가 달라질 때 데이터 모델, API, 마이그레이션은 어떤 절차로 검증하는가?
5. 제품, 디자인, 운영과는 어떤 API 계약과 피드백 흐름으로 협업하는가?
6. 리드 역할의 의사결정 범위와 온보딩, 평가 기준은 무엇인가?
7. 고용 조건과 평가 기준은 어느 공식 단계에서 서면으로 확인할 수 있는가?

## 질문 원칙

- 고객 계약, 투자, 인력 계획, 내부 기술 구성은 공개 자료로 확인되지 않았다면 추정하지 않고 질문한다.
- 개인 일정과 전형 상태는 기록할 수 있다. 개인 처우 금액, 연락처와 비공개 회사 정보는 남기지 않는다.
- 답변이 보류된 항목은 상태와 다음 확인 시점을 적고, 다음 공식 단계에서 짧게 다시 묻는다.
