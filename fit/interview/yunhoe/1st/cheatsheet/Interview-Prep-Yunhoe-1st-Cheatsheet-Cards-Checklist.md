# 윤회 1차 치트시트, 어필 카드와 체크리스트

## 어필 카드

| 카드 | 짧은 답변 |
|---|---|
| 상태 전이와 정합성 | 동시 요청이 같은 상태를 바꿀 때 잠금, 멱등성, 짧은 트랜잭션, 재시도와 복구를 함께 설계했다. |
| 이벤트 자동화 | 핵심 상태와 후속 효과를 분리하고, 소비자 멱등성, 실패 큐, 관측으로 재처리 가능성을 확보했다. |
| 물리, 외부 데이터 | 장치나 외부 시스템의 입력은 지연, 중복, 순서 뒤바뀜을 전제로 검증하고 상태 전이를 명시했다. |
| 성능과 운영 | 실행 계획과 데이터 분포를 보고 인덱스와 조회 방식을 고쳤고, 로그와 지표, 알림으로 운영했다. |
| 품질과 AI | 당시 Claude Code와 계층형 `CLAUDE.md`로 맥락을 나누고, 작은 변경, 편집 범위 검사, 자체 리뷰와 테스트를 한 흐름으로 연결했다. |

개인 사이드 프로젝트는 취미나 별도 경험을 직접 물을 때만 꺼낸다. 관리 흐름을 해결하려고 만든 다중 사용자 도구에서 권한, 계층, 이력 보존을 다뤘다는 수준으로 설명하고 사용자 수, 기술 구성, 운영 수치는 말하지 않는다.

## 보조 답변

### 업무 강도와 지속 가능성

필요한 순간 책임 있게 집중한 경험은 있지만, 일시적 헌신을 장기 운영 방식으로 삼지는 않는다. 긴급한 품질 문제나 마감에는 원인을 좁히고 우선순위를 세워 대응한 뒤, 테스트, 알림, 역할 분담으로 재발을 줄였다. 면접에서는 온콜, 배포 후 대응, 회복을 위한 지원 체계를 정중하게 확인한다.

### 디버깅

재현, 원인 가설, 분리 검증, 해결, 영향 범위 점검, 회고 순서로 답한다. 당시 Prisma 사례에서는 `relationJoins`가 비활성인 구성에서 관계 조회가 분리되는 것을 APM, 로그와 실행 계획으로 확인했다. 기능을 활성화하고 `relationLoadStrategy: 'join'`을 적용한 뒤, MySQL 생성 SQL이 correlated subquery와 JSON 집계 형태인지 확인하고 다른 경로의 영향을 관측했다. 특정 지연 시간이나 내부 모델은 말하지 않는다.

### 의사결정 대안

읽기 경로 분리는 최신성이 필요한 요청과 분석성 조회를 구분한 뒤 일관성, 복제 지연, 비용, 장애 전파를 비교한다. 컨테이너 최적화는 이미지 크기만 보지 않고 런타임 의존성과 네이티브 모듈 호환성, 배포와 롤백 시간을 함께 검증한다.
