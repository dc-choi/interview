## 2. 서비스 모델 — 양방향 + AI URL 구매

- **sazo.shop (2024.05, 일본)**: 일본 거주자가 한국 상품 직구 (역직구). 수수료 0엔.
- **사줘 sazo.kr (2025.8~9, 한국)**: 한국 소비자가 일본 상품 직구. 제휴몰 입점 상품 검색 구매 + **임의 쇼핑몰 URL 입력 → AI가 페이지 분석 → 환율, 관세, 배송비 포함 최종 결제 금액 사전 확정 → 1회 결제 → 통관, 배송 자동 처리**. 금액 확정 후 추가 청구 없음, 대행수수료 0원.
- 일본 현지 물류센터에서 검수 후 국제 배송. 피규어, 만화, 게임, 굿즈 등 일본 한정 상품이 주력.
- 채용공고 표현: 세계 최초 AI 기반 크로스보더 구매 경험 상용화. AI-First 조직 (팀 전체가 AI를 핵심 워크플로우로).

**BM의 기술적 의미**: 공개 서비스 흐름상 결제, 구매대행, 검수와 국제배송의 여러 단계가 연결된다. 각 단계를 회사가 직접 소유하는지, 외부 파트너와 어떻게 나누는지, 어떤 시스템을 쓰는지는 공개 정보만으로 단정하지 않는다.

## 3. 크로스보더 커머스 설계 질문

아래는 사줘의 실제 구현 설명이 아니라 공개된 사용자 흐름에서 파생한 일반 설계 질문이다.

| 문제 영역 | 일반 설계 고려사항 | 확인할 사실 |
|---|---|---|
| 외부 상품 정보 | 계약 변경 감지, 스키마 검증, 실패 분류와 신선도 | 공식 API, 제휴 연동과 페이지 분석의 실제 경계 |
| 가격과 환율 | 견적 시점, 유효시간, 가격 변동과 재계산 정책 | 표시 가격과 결제 금액을 확정하는 기준 |
| 관세와 통관 | 품목과 거래 조건에 따라 규정이 달라지므로 관세청 공식 자료와 전문가 검토를 정본으로 사용 | 회사 시스템과 관세사 또는 물류 파트너의 책임 경계 |
| 배송 추적 | 외부 상태 코드 정규화, 중복과 지연 이벤트 처리 | 연동하는 배송사와 제공받는 이벤트 계약 |
| 주문 상태 | 멱등성, 부분 실패, 취소와 환불 같은 보상 흐름 | 실제 주문 단계와 상태 전이의 정본 |
| 검수와 출고 | 재고 식별, 검수 결과, 합배송과 분할배송의 추적성 | 자체 물류와 외부 물류의 책임 범위 |
| 상품 검색 | 다국어 표기, 동의어, 품절과 색인 신선도 | 검색 엔진 사용 여부와 품질 지표 |

## 4. 내 경험 매핑 (직격도 순)

| 사줘 도메인 문제 | 내 경험 | 직격도 |
|---|---|---|
| 멀티 캐리어 추적 (API + 스크래핑 혼합) | 외부 연동의 변경 감지와 실패 분류 원칙 | **직격** — 깨지는 외부 의존성을 관측으로 다루는 동일 문제 구조 |
| 환율 처리 | 외부 금융 데이터의 갱신, 재시도와 중복 실행 방지 원칙 | **직격** — 외부 금융 API 실패 내성과 연결 |
| 통관 | 시점별 데이터 스냅샷과 외부 메타데이터의 갱신 원칙 | **강한 전이** — 규정 변경과 데이터 정합성의 판단 기준 |
| OMS, WMS | 상태 머신, 감사 추적과 재처리 설계 | **강한 전이** — 국제물류 주문과 창고 도메인 모델링 |
| 이벤트 기반 주문 상태 전이 (Kafka) | 큐, 실패 격리와 재시도 정책 | **강한 전이** — 브로커가 달라도 멱등성과 실패 격리 원리는 동일 |
| 중고 단품처럼 재고가 1개일 수 있는 상품의 동시 주문 race | 트랜잭션 잠금과 멱등성으로 동시 갱신 제어 | **강한 전이** — 동시성 정합성 원리를 적용 |
| 조회 성능, 대량 데이터 | 실행계획과 복합 인덱스로 병목을 확인하는 방법 | 전이 — 검색 엔진 도입 여부를 판단하는 근거로 사용 |
| 파서 성공률 메트릭 운영 | 지표, 로그와 경보를 연결하는 원칙 | 전이 — 파서 SLO의 목표 기간과 오류 예산은 새로 정의해야 함 |

**요약: 외부 연동, 상태 전이, 동시성, 관측과 재처리의 판단 기준을 사줘 JD의 문제에 연결한다.**

## 5. 도메인 이해를 설명하는 예시

1. "API가 없는 외부 소스는 스크래핑으로 다룰 수 있지만, 본질은 만드는 것보다 깨짐을 빨리 아는 데 있습니다. 사줘의 파서 파이프라인도 소스별 성공률과 구조 변경 감지가 핵심이라고 생각합니다."
2. "표시 환율, 결제 시점 환율, 관세청 고시 환율은 서로 다른 시점의 문제입니다. 직구 가격 엔진은 환율 스냅샷을 주문에 어떻게 고정하느냐가 핵심이라고 봅니다."
3. "메루카리의 중고 단품처럼 재고가 1개일 수 있는 상품은 상품 정보 조회 또는 동기화 시점과 구매 시점 사이 품절 race가 생길 수 있습니다. 내부 상태 갱신은 잠금과 멱등성으로 보호하고, 외부 품절은 별도 실패 경로로 모델링해야 합니다."
4. "구매대행 주문은 결제 시점에 재고를 소유하지 않는 긴 상태 머신이라, 단계 전이를 이벤트로 풀고 실패를 DLQ와 보상 플로우로 다루는 설계가 자연스럽습니다."
5. "합산과세는 합포장 자체가 아니라 동일 해외공급자, 같은 구매일, 분할반입이나 하나의 B/L 또는 AWB 분할 조건으로 판단되므로, WMS가 그 입력값을 보존해 세금 엔진으로 넘겨야 한다고 봅니다."

> 양방향 포인트: 사줘는 직구 + 역직구 **양방향**. 한국 상품을 일본에 파는 역방향(일본 수입 통관, 엔화 결제)까지 언급하면 조사 깊이 시그널.

## 6. 도메인 특화 예상 질문 5

| 질문 | 답변 방향 |
|---|---|
| 일본 쇼핑몰 개편으로 파서가 깨지면 어떻게 감지, 대응? | 필드 단위 결측률 메트릭 + 임계 알림, 골든 URL 회귀 테스트, 소스별 파서 모듈 격리, 실패 건 DLQ 적재 후 파서 수정 뒤 재처리 |
| 재고가 1개일 수 있는 메루카리 중고 단품에 두 유저가 동시 주문하면? | 단일 DB 재고라면 수량 조건부 UPDATE와 트랜잭션을 우선한다. 여러 자원에 걸친 분산락이 필요하면 owner token 기반 해제, lease 갱신, fencing token이나 DB 상태 전이로 만료 뒤 stale writer까지 막는다. 외부 품절은 막을 수 없으므로 주문 = 구매 시도로 모델링하고, 실패 시 자동 환불 보상 플로우를 1급 시나리오로 둔다. 내부 정합성과 외부 불확실성을 분리한다. |
| 환율은 어떻게 다루나? 표시가와 결제가가 달라지면? | 환율 3종 분리(표시 실시간, 결제 스냅샷, 관세청 고시). 견적 유효시간 + 주문에 환율 박제 + 스프레드 버퍼. 배치 실패 시 이전 값 폴백과 알림을 둔다. |
| 관부가세 150달러와 합산과세를 시스템에 어떻게 반영? | 목록통관 면세기준과 수입신고 과세가격을 분리한다. 해외공급자, 구매일, B/L/AWB를 주문과 출고에 보존하고, 합포장만으로 세금을 단정하지 않는다. 배제 품목은 카테고리 분류 단계 플래그로 두고, 세금 계산은 최신 통관 규정과 연계 |
| 주문 → 구매 → 입고 → 검수 → 출고를 MSA + Kafka로 설계한다면? | 단계별 서비스가 도메인 이벤트로 전이하는 코레오그래피 Saga를 검토한다. 멱등 컨슈머, 단계별 DLQ와 재시도 차등, 보상 이벤트(구매 실패 → 환불)를 둔다. 입고 매칭과 부분 실패를 엣지로 먼저 언급한다. |
