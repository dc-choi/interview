# 스페이스맵 1차 면접 — 30분 훑기용 치트시트

## 0. STM 도메인 30초 (★ 회사 핵심 — [[Interview-Prep-SpaceMap-Domain|도메인 브리프]])

- 스페이스맵 = **SDA/STM**(우주영역인식, 우주교통관리). 위성, 우주물체 추적→**충돌 위험(Pc) 예측**→회피 의사결정 지원. **'42 Talks'** 실시간 협업 플랫폼.
- **STM 데이터 흐름 = 내 파이프라인 골격**: 다중 소스 관측 수집 → 큐 → **궤도전파, 충돌 스크리닝(CPU 바운드, O(N²))** → Pc → 경보, 서빙. = 수집→정합성→**분산 연산**→서빙.
- 흘릴 용어 1~2개: **conjunction screening**, **Pc**, 시계열 **catalog**. (전문가인 척 X, "골격이 같더라" 톤)
- O(N²) 질문 → **apogee-perigee 필터로 프루닝 + 무거운 연산 워커 분리**.
- 정합성 이유 → 오탐=불필요 연료기동, 미탐=위성 손실. "조용히 틀리면 안 됨".

## 1. 1분 자기소개 — 마지막 문장

> "스페이스맵의 **STM**은 위성 충돌 위험을 예측하려면 **다중 소스 관측을 시계열로 수집하고, 무거운 궤도 연산을 거쳐 경보로 서빙**해야 합니다. 수집, 정합성, 분산 연산과 서빙이라는 백엔드 문제를 연결해, **백엔드 개발자** 자리에서 데이터 엔진과 API 서버 양쪽에 기여하고 싶어 지원했습니다."

## 2. 5년+ 갭 정면 돌파 — 한 줄

> "연차는 약 1년 모자라지만 다룬 문제의 깊이와 범위로 기여하겠습니다. 동시성 정합성, 수집 파이프라인, 인덱스 최적화, 아키텍처 전환과 관측성 구축을 경험했으며 내부 규모와 수치는 공개하지 않습니다."

## 3. 이전 역할 이직 사유 — 옵션 B

> "배치와 테스트 게이트를 통해 운영 품질을 배웠고, 동시에 **기술 결정이 사업 단계와 분리될 수 없다**는 점을 체감했습니다. 지금은 기술 도입 시 전달 보장, 운영 부담, 복구 가능성과 제품 단계의 적합성을 함께 비교합니다."

## 4. 워라밸 답변 ★★★ (JD "강한 몰입, 업무 강도" 명시 — 100% 들어옴)

> "의미 있는 일에는 책임 있게 몰입하되, 특정 단기 대응 사례를 성과처럼 포장하지 않습니다. 지속 가능한 운영을 위한 미션 공감, 팀워크와 성과 인정 구조를 확인하고 싶습니다."

당시 공개 자료에서 확인한 미 우주군과 우주청 과제, 방산혁신기업 100 선정 이력을 회사의 도전 맥락으로 연결하되, 실제 고객, 계약과 내부 수행 방식은 추정하지 않는다.

⚠️ "괜찮습니다" = 절박 / "힘들겠다" = 부정 → 둘 다 회피, **역질문으로 마이크 넘김**.

## 5. 왜 백엔드 — 한 줄 (정체성)

> "백엔드는 **물리적 사물, 데이터, 시간을 디지털로 연결하는 일**. 스페이스맵 우주 데이터도 본질은 같음 — 위성 궤도, 추적 시계열을 안정적으로 수집, 연산해 결과로 만드는 일."

## 6. Python/FastAPI/Airflow 갭 — 솔직 인정 + 전이 가능성

| JD 스택               | 본인                    | 전이 근거                                                                    |
| ------------------- | --------------------- | ------------------------------------------------------------------------ |
| Python/FastAPI      | 없음                    | NestJS **데코레이터, DI** 깊이가 FastAPI 전이 토대 (ASGI 비동기 모델 공통)                   |
| Airflow             | batch, 스케줄 경험          | **DAG=의존 그래프, 스케줄, 재시도, 멱등성 개념 동일**. 사용한 스케줄러와 Airflow의 차이를 구분해 설명 |
| PostgreSQL          | MySQL 깊음              | RDB 공통. MVCC 구현, 인덱스(GIN/GiST), 격리수준 차이만 학습                                |
| NoSQL (Mongo/Redis) | Mongo→MySQL 마이그, Redis | 강함                                                                       |

## 7. 데이터 파이프라인 최강 무기 (JD 첫 줄 매핑)

> "다수 장비의 실시간 데이터 수집에서 정합성, 이벤트 기반 후속 처리와 최신 상태 조회 최적화를 함께 다뤘습니다. 내부 데이터 규모와 성능 수치는 공개하지 않습니다."
