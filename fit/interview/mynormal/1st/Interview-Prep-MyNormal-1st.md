# 마이노멀컴퍼니 인아웃 백엔드 1차 면접 준비

> **자료 한계**: 포트폴리오를 제공받지 않아 이력서 공개 본문과 common 마스터만으로 매칭했다. 포트폴리오의 설계 도식, 수치의 측정 조건과 사이드 프로젝트 세부는 이 문서에 반영되지 않았다.
> **지원 경로**: 2026-09-18 원티드 지원 제안을 받고 지원했다. 정확한 지원일은 미확인이다.
> **공고**: [원티드 387842, 인아웃 백엔드 개발자 3년 이상](https://www.wanted.co.kr/wd/387842), 2026-09-29 원문 대조. 상시채용, 경력 3~8년 필터, 근무지 서울 강남대로 502.
> **전형 상태**: 2026-09-22 서류 통과와 과제 안내(기능 구현 과제, 수령일 포함 4일), 2026-09-28 과제 제출 요청 메일, 2026-09-30 과제 제출(사용자 확인, 마감 2026-10-01), 결과 대기 중이다. 공고의 전형은 서류, 온라인 과제, 1차 화상 인터뷰, 2차 대면 인터뷰, 최종 합격과 처우 협의 순서이므로 이 문서는 1차 화상 인터뷰를 대상으로 한다. 면접일은 미정이다.
> **기준 템플릿**: [[Interview-Prep-Template]]. 이전 회고는 없다.

회사 사실은 공개 JD와 원티드 회사 페이지로 확인한 것만 적는다. 회사 자체 소개 문구는 회사 주장으로 표시한다. 제3자 실명과 연락처, 개인 처우 금액, 비공개 회사 정보는 기록하지 않는다.

## 0. 면접 전략

- 이 공고는 기술명보다 판단 과정을 반복해서 요구한다. 자격요건이 대안과 선택 이유, 실제 발생한 문제의 해결, AI 제안 코드의 검증, 모호한 요구사항의 확인을 직접 적고 있다. 모든 답을 문제, 선택지, 선택 이유, 검증, 한계 순서로 말한다.
- 1차 화상은 제출한 과제 코드를 중심으로 리뷰한다고 안내됐다. 과제 방어를 최우선으로 준비하고, 이력서 딥다이브도 함께 나올 수 있으니 동시성, 비동기 처리, 쿼리 개선, 인프라 전환 네 사례를 꼬리질문 3단계까지 말할 수 있게 준비한다.
- LLM 기능의 실서비스 경험은 없다. 인정, 전이 가능한 판단 기준, 첫 과제에서 검증할 방법의 3단으로 답하고 경험처럼 포장하지 않는다.
- 직전 회사를 짧게 마친 이유는 FIT 문서 C1의 확정 답변으로 30초 안에 끝내고 트라이포드랩 경험으로 넘어간다. 개인 사업 활동은 먼저 꺼내지 않는다.
- 제품을 설치해 식단, 체중, 운동 기록과 알림 흐름을 직접 써 보고 관찰한 사실 한두 개만 말한다. 내부 구현은 추정해 말하지 않고 질문으로 바꾼다.

## 4. 강점

1. 공고의 운영 축과 이력서가 거의 일대일로 맞는다. 동시성 정합성, 예약 작업과 이벤트 처리, 쿼리와 인덱스, 인프라 전환, 관측을 모두 직접 다뤘다.
2. 공개 이력서에 정량 근거가 있다. 슬로우 쿼리 99.3% 개선, API 응답 90% 향상, 이미지 43.6% 감소와 배포 26.3% 단축. Read Replica 40%는 기준선 기록이 없어 수치 대신 원칙으로 말한다.
5. 식단과 식품 도메인에 가까운 이력이 있다. 시솔지주의 영양정보 데이터 정형화(MongoDB에서 MySQL), 이썸테크의 농식품정보서비스 대시보드(R9).
3. AI 도구를 검증 책임과 함께 팀 규약으로 만든 경험이 있어, 자격요건의 AI 제안 검증과 우대사항의 개발 과정 효율화에 동시에 대응한다.
4. 국제 배송 서비스의 번역, 환율 배치 경험이 글로벌 사용자 고려라는 직무 소개와 연결된다.

## 5. 갭

1. LLM API를 서비스 데이터와 연결해 운영한 경험이 없다. 우대사항이자 주요 업무의 한 축이다. 개인 프로젝트의 검색 평가 경험(R11)으로 일부 메운다.
2. 모바일 B2C 앱의 대량 푸시 알림과 사용자 기록 데이터를 직접 운영한 경험이 없다. 리포트형 알림톡과 이메일 통보까지가 근거다.
3. 건강 기록처럼 민감할 수 있는 데이터를 다룬 경험은 없다. 영양정보 정형화 경험은 있다.
4. 백오피스를 별도 제품으로 설계한 사례가 이력서에 약하다. 내부 업무 자동화와 리포트로 전이한다.
5. 직전 회사를 수습 기간 중 마쳐 짧은 재직 질문이 나올 가능성이 높다. 답변은 확정했지만 첫인상의 부담은 남는다.

## 6. 우선 준비 사항

1. 이력서의 키노라이츠 재직중 표기와 요약 문단의 현재 시제를 고친다(원본 수정은 사용자 몫). 마이노멀에 낸 판본이 재직중이었다면 1차 면접 경력 흐름에서 9월 중순에 마쳤다는 사실을 먼저 밝히고 C1로 잇는다. C1 답변을 소리 내어 30초 안에 말하는 연습을 한다.
2. LLM 기능 설계 답변을 입에 붙인다. 입력 데이터 최소화, 구조화 출력 검증, 타임아웃과 재시도, 비동기 처리, 캐시, 토큰 비용 가시성, 평가 세트의 순서다(JD 기술 문서 J1~J3).
3. 이력서 수치는 무엇을 전후 비교했는지까지만 말하고, 환경과 표본 기록이 없다는 점은 먼저 인정한 뒤 같은 조건 재측정 방법으로 답한다(R3, R5).
4. 알림 예약 발송 설계를 말로 그려 본다. 사용자 시간대, 중복 방지, 실패 재시도, 발송 폭주 흡수다(서비스 문서 S2).
5. 인아웃 앱을 직접 사용해 기록, 알림, AI 기능 흐름을 관찰하고 한두 문장으로 정리한다.
6. 제출한 과제를 방어할 준비를 한다. 요구사항 해석, 선택한 설계와 대안, 트레이드오프, 테스트 범위, 다시 한다면 바꿀 점이다. 1차 화상 인터뷰는 과제 코드 리뷰가 중심이라고 안내됐다. 과제 원문과 코드는 저장하지 않고 공개 가능한 요약은 [[Interview-Prep-MyNormal-1st-Assignment|과제 방어 문서]]에 둔다.

## 7. 미해결 확인 사항

- 트라이포드랩은 2024.02~2026.05로 확인했다(2026-09-29 이력서 PDF). 이력서 PDF에는 키노라이츠가 2026.06 재직중으로 적혀 있어 실제 근무 종료(2026-09-15)와 다르다.
- 퇴사 사유와 현재 상태 답변은 2026-09-29 확정했다(동기 마스터 현재 사이클). 개인 사업 활동은 먼저 밝히지 않는다.
- 마이노멀에 낸 이력서는 2026-09-29 받은 PDF와 같은 판본이다(사용자 확인). 면접관은 키노라이츠 재직 중으로 알고 있으므로 1차에서 먼저 바로잡는다(FIT 자기소개 조건).
- 제출한 이력서의 골든 케이스 약 145건 문구는 부정확하다. 실제는 74개 질문(BM25, 임베딩, RRF)과 이를 포함한 94개 질문(리랭커) 비교이며, 모두 채택하지 않았다(2026-09-29 ontology/evaluation 대조). 면접에서 물으면 먼저 바로잡고, 이력서 원본도 고친다.
- 이력서의 개발 지식 온톨로지 프로젝트는 키노라이츠 경력 아래에 있지만 개인 프로젝트다(사용자 확인). 면접에서 먼저 개인 프로젝트라고 밝히고, 이력서도 개인 프로젝트 항목으로 옮긴다.
- 요청 식별자를 메트릭 라벨에 넣었다가 로그로 옮긴 경험은 사실로 확인했다. R6와 기술 카드 5를 그 흐름으로 고쳤다.
- @nestjs/schedule과 @nestjs/bullmq의 실제 용도, NOWAIT를 고른 구체 이유는 확인 전까지 말하지 않는다.
- 과제 결과, 1차 화상 인터뷰 일정과 참여 역할이 미정이다. 과제 방어 답변은 2026-09-30 제출 전 자체 검토 수정본까지 반영한 과제 코드(잠금 밖 발송, 최대 한 번 전달, 사용자별 실패 격리)를 기준으로 [[Interview-Prep-MyNormal-1st-Assignment|과제 방어 문서]]에 채웠다. 과제는 2026-09-30 제출했다.
- 인아웃 회원 규모 표기가 170만과 300만으로 다르다. 면접에서는 회사 소개 수치를 인용하지 않거나 출처를 붙여 말한다.
- 회사의 DB 제품, 캐시, 관측 도구, 사용 중인 LLM 제공자, 개발 조직 규모는 공개되지 않았다.
