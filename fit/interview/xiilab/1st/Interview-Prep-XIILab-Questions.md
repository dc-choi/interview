# 씨이랩(XIILab) 1차 면접 준비, 역질문과 체크리스트

> 질문은 공개 정보로 확인할 수 없는 역할의 경계와 협업 방식을 확인하는 데 쓴다. 아래 목록은 1차 면접 전 준비한 질문과 학습 항목이며, 실제 면접에서 받은 질문으로 쓰지 않는다. 회사와 차수, 채용 진행 상태와 개인 일정은 기록할 수 있지만 내부 조직도와 제3자 발화는 추정하거나 원문으로 옮기지 않는다.

## 역질문

1. Product Engineer가 제품 기능을 시작부터 운영까지 책임지는 실제 범위와 성공 기준은 무엇인가요?
2. 제품별 담당 경계와 프론트엔드, 백엔드, 모델 또는 플랫폼 역할의 협업 방식은 어떻게 정하나요?
3. 데이터 모델, API 계약, 배포와 장애 대응의 책임은 어디까지이며, 기술 선택의 근거와 검증 결과는 어떻게 공유하나요?
4. 코드 리뷰와 배포 주기, 품질 문제를 발견했을 때의 우선순위와 복구 판단은 어떻게 하나요?
5. 새 구성원이 제품과 운영 맥락을 이해하도록 어떤 문서와 피드백 흐름을 제공하나요?
6. 이 역할의 초기 3개월 기대치와 장기적인 성장 경로는 무엇인가요?
7. AI 도구를 사용할 때 결과 검증, 보안과 최종 책임은 어떤 기준으로 나누나요?

## 복습 체크리스트

- [ ] API 계약, 인증, 권한, 오류 경계를 설명할 수 있다.
- [ ] 트랜잭션, 잠금, 인덱스, 실행 계획의 선택 기준을 설명할 수 있다.
- [ ] 큐, 멱등성, Outbox, DLQ의 실패 경계를 설명할 수 있다.
- [ ] 컨테이너 배포, 롤백, 설정 주입, 관측성의 연결을 설명할 수 있다.
- [ ] AI 도구의 위임 범위와 검증 책임을 설명할 수 있다.

## 당시 보강한 기술 영역

| 영역 | 설명할 판단 |
| --- | --- |

| 데이터와 성능 | 격리 수준, 잠금, 실행 계획, 복합 인덱스, 정규화와 비정규화의 선택 기준을 실제 조회 패턴과 함께 설명한다. |

## 과제와 실무 인터뷰 대비

- [ ] 작은 기능 하나를 화면, API, 데이터 모델, 오류 처리와 테스트까지 수직으로 설명한다.
- [ ] 요구가 모호할 때 가정, 질문, 대안과 검증 방법을 먼저 문서화한다.
- [ ] 마이그레이션이나 변경은 백업, 호환 기간, 데이터 검증, 롤백의 순서로 설명한다.
- [ ] 장애 시 사용자 영향, 원인 후보, 완화 조치, 복구와 재발 방지 기준을 분리해 말한다.
- [ ] AI 도구 결과는 공식 문서, 테스트, 코드 리뷰와 실제 실행으로 검증하고 최종 책임은 직접 진다.

## 당시 연결할 경력 증거

| 주제 | 보존할 사실 | 면접에서 연결할 판단 |
| --- | --- | --- |
| FIDO와 WebAuthn | 표준을 읽고 서버 검증 요건을 정리했으며, 공개 오픈소스 이슈로 규격 준수 문제를 확인하고 기여했다. | 보안 요구는 라이브러리 사용 여부가 아니라 명세, 재현과 검증으로 판단한다. |
| DB 모델링과 마이그레이션 | 문서형 데이터를 관계형 모델로 옮길 때 데이터 검증, 백필, 읽기 전환과 되돌림을 단계로 나눴다. | 변경은 한 번의 배포가 아니라 데이터 정합성과 운영 복구까지 포함한다. |
| 테스트와 품질 | 핵심 로직, 경계 통합, 주요 흐름을 나눠 자동 검증을 설계했다. | 커버리지 수치보다 위험한 규칙이 실제로 실패하는지 확인한다. |
| 관측성 | 로그와 메트릭으로 원인 후보를 좁히고 배포, 복구와 회고의 기준을 남겼다. | 경보는 담당자가 행동할 수 있는 사용자 영향 기준으로 만든다. |
| 공개 기술 공유 | ORM 조회 성능의 검증 방법을 공개 발표로 설명하고, 백엔드 멘토링으로 이해의 빈틈을 점검했다. | 개인의 해결을 다른 사람이 재현 가능한 판단 기준으로 바꾼다. |
| 제품 전 과정 | 요구를 기능, API, 데이터, 오류 처리와 운영 검증까지 연결해 본 경험이 있다. | Full Stack 역할에서도 구현 범위를 사용자 결과와 복구 가능성까지 넓힌다. |
| AI 도구 활용 | 반복 작업에는 도구를 활용하되 공식 문서, 테스트와 리뷰로 결과를 검증한다. | 도구의 출력과 최종 설계 책임을 혼동하지 않는다. |

## 확인할 질문

1. Product Engineer가 제품 기능을 시작부터 운영까지 책임지는 실제 경계는 어디까지인가?
2. 과제와 실무 인터뷰에서 결과물 자체와 판단 과정을 각각 어떻게 평가하는가?
3. AI 모델, 제품, 플랫폼 역할 사이의 API 계약과 장애 대응 책임은 어떻게 나뉘는가?
4. 데이터 모델 변경과 배포에 필요한 검증, 롤백과 관측 기준은 무엇인가?
5. AI 도구를 사용한 결과의 보안, 리뷰와 최종 검증은 어떤 기준으로 운영하는가?

## 주의사항

- 과거 회사의 고객, 처리량, 비용, 임계값을 성과 증거로 사용하지 않는다.
- 공개되지 않은 조직 구조나 팀 문화는 사실처럼 말하지 않는다.
- 질문에는 사실, 선택, 검증, 결과를 구분해 답한다.
