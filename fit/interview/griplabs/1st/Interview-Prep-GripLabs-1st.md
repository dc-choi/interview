## 0. 1차 전략

- **공고의 필수 요건은 기본기 검증형이다.** TypeScript 강타입, NestJS 레이어드 아키텍처, OOP의 역할과 책임, SQL JOIN과 Subquery, 실행 계획 튜닝, HTTP와 REST, Git 브랜치 전략, Linux 명령, 테스트 코드까지 나열돼 있다. 1차에서 개념 질문이 이력서 딥다이브와 섞여 나올 가능성을 전제로, 각 개념을 내 경험 한 장면과 연결해 답한다.
- **가장 강한 카드는 실행 계획 기반 튜닝이다.** 공고가 명시한 실행 계획을 통한 인덱스와 쿼리 튜닝 경험과 이력서의 복합 인덱스, Prisma 쿼리 통합 사례가 정확히 겹친다. 수치는 측정 조건을 설명할 수 있을 때만 말한다.
- **AI 서비스 백엔드는 인접 경험으로 연결한다.** 공고의 AI 활용 서비스와 회사의 뉴스 요약, 번역, 투표, 대화형 AI 제품은 LLM 호출 자체보다 외부 연동, 비동기 처리, 캐시, 재처리와 관측 문제로 백엔드에 나타난다. LLM 모델 개발 경험은 없다고 먼저 밝히고 전이 가능한 설계 판단으로 답한다.
- **현재 커리어 서사는 확정 답변만 쓴다.** 퇴사 사유는 [[My-Motivation-Reasons]]의 현재 이직 사이클 답변을 fork했다. 자기소개 첫 문장에 현재 소속을 넣지 않고, 개인 사업과 창업 계획은 먼저 꺼내지 않는다.
- 답변 마무리는 공개된 역할(신규 사업의 B2B와 B2C 웹 서비스, AI 활용 서비스 백엔드)에 한 문장으로 연결한다. 확인되지 않은 신규 사업 내용, 트래픽, 팀 구성은 사실처럼 말하지 않는다.

## 1. 핵심 요약

### 강점

| 강점 | 근거 (이력서 공개 서술) | 공고 연결 |
|---|---|---|
| TypeScript와 NestJS 실무 | 트라이포드랩에서 NestJS, Prisma, MySQL 기반 서비스 설계와 개발, @nestjs/schedule, bullmq, axios 사용 | 필수 요건 1번과 주요 업무 전체 |
| 실행 계획 기반 성능 개선 | 복합 인덱스로 슬로우 쿼리 99.3% 개선, Prisma N개 쿼리를 단일 쿼리로 통합해 API 응답 90% 향상, 하코 커뮤니티 발표 | 실행 계획을 통한 인덱스와 쿼리 튜닝 요건 |
| 정합성과 비동기 처리 | 수천 대 IoT 동시 요청의 Race Condition을 DB Lock으로 해결, EventBridge와 SQS 기반 발주 자동화 | B2B, B2C 시스템 아키텍처 운영 |
| 모듈 경계와 계층 설계 | 도메인별 모듈 분리로 잦은 요구사항 변경 수용 | 레이어드 아키텍처, OOP 요건 |
| 운영과 관측 | CloudFront, ELB, ECS 전환, Read Replica 도입, Grafana, Prometheus, Loki 관측과 알림 | 백엔드 서버 개발과 운영 |
| AI 협업 개발 방식 | 팀 AI 협업 규약과 작업 종료 시점 자동 검증 루프 구축 | AI 활용 서비스 개발 환경 |
| 외부 연동과 번역 | 시솔지주에서 Google API 연동 번역 기능 개선 70%, 배송 정보 스크래핑, 환율 배치 | 번역 엔진, 뉴스 수집 계열 서비스와 인접 |

### 갭

| 갭 | 수준 | 대응 |
|---|---|---|
| PostgreSQL 실무 | 약 | MySQL, MariaDB만 사용했다고 밝힌다. MVCC와 VACUUM, `EXPLAIN (ANALYZE, BUFFERS)`, JSONB와 GIN 차이를 설명하고 실행 계획을 읽는 방법론은 동일하다고 연결한다 |
| Java, Kotlin 최근 실무 | 중 | Java와 Spring은 이썸테크와 부트캠프 과제 경험이다. 공고는 강타입 언어 예시로 적었으므로 TypeScript 경험을 주 근거로 둔다 |
| LLM, 추천, 클러스터링 모델 | 약 | 모델 개발과 평가 경험은 없다. 모델을 호출하고 결과를 서빙하는 백엔드 경계(타임아웃, 비용, 캐시, 폴백, 평가 데이터 수집)로 답한다 |
| 경력 연수 경계 | 확인 필요 | 이력서 연월 합산은 월 단위 근사로 키노라이츠를 빼면 약 3년 10개월, 키노라이츠 약 2개월 반(2026.06.29~09.15)을 더하면 약 4년이다. 공고의 4~10년과 경계라서 사용자가 경력 산정을 확인해야 한다 |
| 전공 우대 | 중 | 정보관리보안학과 학사(고려사이버대학교)다. 우대 전공인 컴퓨터, 시스템공학과 인접 전공이며 42서울과 CS 학습을 보완 근거로 둔다 |

### 우선 준비 사항

1. **재직 이력 정합성(확정)**: 트라이포드랩 재직은 2024.02~2026.05다. 이력서 PDF에는 키노라이츠가 이미 있으나 2026.06 재직중(4개월)으로 적히고 요약 문단이 현재 시제다. 실제 근무는 2026.06.29~2026.09.15에 끝났으므로 2026.06~2026.09와 과거 시제로 고친다(2026-09-29, 원본 수정은 사용자 몫). 공고에 레퍼런스 체크 단계와 허위사실 발견 시 채용 취소 유의사항이 있다.
2. **이직 사유와 현재 상태(확정)**: 퇴사, 이직, 짧은 재직, 현재 활동 답변은 [[Interview-Prep-GripLabs-1st-FIT|FIT 문서]] 3절 C3, C4, C5를 그대로 쓴다.
3. 실행 계획 카드(이력서 R3, R4)와 JD 개념 질문(J4, J5)을 한 흐름으로 말하는 연습. MySQL과 PostgreSQL 계획 노드 차이까지 꼬리 2단계.
4. 레이어드 아키텍처, OOP, 테스트 질문(J2, J3, J7)을 NestJS 모듈 경계 경험으로 연결하는 연습.
5. 그립랩스 공개 제품(뉴밍 앱, 번역, 댓글, 퀴즈, 대화형 AI)을 직접 확인하고, 관찰한 사실 한 문장과 백엔드 관점 질문 하나를 준비한다.

## 2. 미해결 확인 사항

| 항목 | 상태 | 필요한 결정 또는 확인 |
|---|---|---|
| 재직 기간 차이 | 확정 | 트라이포드랩 2024.02~2026.05로 확정(이력서와 일치). 이력서 키노라이츠의 재직중 표기와 현재 시제 요약 문단을 고친다(2026-09-29, 원본 수정은 사용자 몫) |
| 현재 이직 사유 | 확정 | 마스터의 현재 이직 사이클(2026-09-29 사용자 확정) 답변을 FIT 문서 C3에 fork했다 |
| 키노라이츠 재직 기간 | 확정 | 2026.06.29~2026.09.15, 수습 기간 중 본채용으로 이어지지 않음 |
| 사업 병행 | 확정 | 먼저 꺼내지 않고, 직접 묻는 질문에는 사실대로 답한다. 겸업 규정은 회사 기준을 따른다 |
| 경력 연수 산정 | 확인 필요 | 4년 이상 조건 충족 여부를 어떤 기준(이력서 연월, 4대보험 기간)으로 말할지 정한다 |
| 신규 사업 내용 | 미확인 | 공고의 신규 사업이 기존 제품(뉴밍, Mingo, iRevue, Crossword, AI Chat)의 확장인지 별도 사업인지 공개 근거가 없다 |
| 회사 단계, 재무, 조직, 고객 계약 | 미확인 | 홈페이지의 파트너 로고와 보도 외에 투자, 매출, 팀 규모, 계약 형태의 공식 근거가 없다. 역질문으로만 다룬다 |
| 기술 구현 | 미확인 | 실제 사용 DB(MySQL, PostgreSQL), LLM 호출 구조(자체 모델, 외부 API), 인프라는 공개되지 않았다 |
| 온톨로지 프로젝트 위치 | 확인 필요 | 이력서에서 개발 지식 온톨로지 프로젝트가 키노라이츠 경력 아래에 있지만 개인 프로젝트다(2026-09-29 사용자 확인). 면접에서 먼저 개인 프로젝트라고 밝히고, 이력서도 개인 프로젝트 항목으로 옮긴다(원본 수정은 사용자 몫) |
| 이력서 145건 문구 | 정정 필요 | 이력서의 골든 케이스 약 145건은 부정확하다. 145건짜리 세트는 없고 실제로는 74개 질문으로 검색 방식을, 그 74개를 포함한 94개 질문으로 리랭커를 비교했다. 이력서 문구 정정 필요(원본 수정은 사용자 몫), 면접에서는 먼저 바로잡는다 |
| 1차 형식 | 미확인 | 면접관 역할, 라이브 코딩이나 과제 여부 미공지 |
