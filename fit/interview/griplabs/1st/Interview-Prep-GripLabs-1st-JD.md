# 그립랩스 1차, JD와 회사 분석

> [[Interview-Prep-GripLabs-1st|1차 메인]]의 하위 문서다. 회사 사실은 2026-09-29에 공고 원문, 공식 홈페이지와 공개 보도에서 확인한 것만 쓰고 출처를 단다. 공개 근거가 없는 단계, 재무, 조직, 고객, 기술 구현은 `미확인`으로 두고 역질문으로 넘긴다.

## 1. 공개된 회사 개요

| 항목 | 확인한 내용 | 출처 |
|---|---|---|
| 법인과 소재지 | 주식회사 그립랩스(Grip Labs Inc.), 서울 영등포구 국회대로70길 23, 7층 (여의도 용산빌딩) | 공식 홈페이지 하단, 공고 근무지 |
| 자기 소개 | AGENTIC AI LAB. 독자와 미디어를 잇는 AI 기술을 만들고, 주요 언론사와 AI 기반 저널리즘의 새 시대를 연다고 소개한다 | 공식 홈페이지 |
| 연구 방식 | 각 연구는 자체 플랫폼에서 매일 검증되고, 검증된 결과는 파트너 환경에서도 운영된다고 설명한다 | 공식 홈페이지 |
| 자체 IP 4개 | Persona Agent(페르소나를 생성하고 진화시켜 잠재 고객을 매칭하는 엔진), 고유명사 DB(한, 영, 일, 중, 베트남어 5개 언어의 인명, 지명, 고유 용어 매칭), Dynamic Poll(댓글 옆에서 작동하는 AI 투표 엔진, 본문과 댓글 두 모드), NewsBlock(실시간 뉴스 클러스터링과 요약, 키워드와 인사이트 자동 추출) | 공식 홈페이지 |
| 운영 제품 5개 | 뉴밍(Newming, 뉴스와 미디어 콘텐츠 앱, 직접 운영하는 메인 연구 현장), Mingo(다국어 AI 번역 엔진), iRevue(댓글 모니터링 솔루션), Crossword(기사 기반 AI 낱말퀴즈 생성), AI Chat(직접 개발하고 운영하는 대화형 AI) | 공식 홈페이지 |
| 뉴밍 | 한국 7대 메이저 언론사 콘텐츠 흐름 위에서 매일 작동한다고 소개하며, 개인화 추천, 다단계 AI 투표, 언론사 이슈 클러스터링 기능을 적는다. iOS와 Android 앱이 공개돼 있다 | 공식 홈페이지, 앱 스토어 링크 |
| 핵심 파트너 표기 | 매일경제, 파이낸셜뉴스, 중앙일보, 한국경제, 한겨레, 한국일보, 경향신문, 스포츠조선 로고를 핵심 파트너로 게시한다. 계약 형태와 범위는 미확인 | 공식 홈페이지 |
| 등록 사항 | 인터넷뉴스서비스사업 등록번호와 통신판매업 신고번호가 게시돼 있다 | 공식 홈페이지 하단 |

| 사업 단계, 투자, 매출, 인원 | 미확인 | 공개 공식 근거 없음 |
| 비즈니스 모델 | 미확인. 자체 앱 운영과 파트너 환경 운영이 함께 있다는 설명만 공식 확인. 과금 방식과 B2B 계약 구조는 추정하지 않는다 | 역질문 대상 |

### 공고가 말하는 역할

| 항목 | 공고 원문 요약 |
|---|---|
| 주요 업무 | 신규 사업 웹 서비스의 백엔드 서버 개발과 유지보수, 다양한 B2B 사업의 웹 서버 개발과 운영, B2C와 B2B 시스템 아키텍처 개발과 운영, AI 활용 서비스의 백엔드 시스템 담당 |
| 근무 조건 | 정규직(수습 3개월), 급여 면접 후 결정, 주 5일 09:00~18:00, 탄력근무제 |
| 채용 절차 | 서류 → 전화 인터뷰(필요시) → 1차 면접 → 2차 면접 → 레퍼런스 체크, 컬처핏 인터뷰(필요시) → 처우 협의와 입사일 조정 |
| 접수 | 2026-09-27부터 상시, 사람인 온라인 이력서, 필요시 포트폴리오 |
| 유의 사항 | 입사지원 서류에 허위사실이 발견되면 채용 확정 이후라도 취소될 수 있다 |

사람인 직무 분류 태그에는 풀스택, 데이터엔지니어, 앱개발, 모델링, Python, SpringBoot도 붙어 있다. 공고 본문의 요건이 아니라 분류 태그이므로 역할 범위의 근거로 쓰지 않고 확인 질문으로만 둔다.

## 2. 핵심 키워드

- **기본기**: TypeScript와 강타입 언어, NestJS, RDBMS 설계와 SQL, 실행 계획 튜닝, HTTP와 REST, Git 브랜치 전략, Linux
- **설계 원칙**: OOP의 역할, 책임, 협력과 메시지, 레이어드 아키텍처가 왜 필요한지
- **품질**: 테스트 프레임워크 기반 테스트 코드
- **도메인**: 뉴스와 미디어, B2B(언론사 대상 솔루션으로 보이는 제품군)와 B2C(자체 앱), AI 활용 서비스

## 3. 자격 요건과 내 경험 매칭

| 자격 요건 | 매칭 | 이력서 근거 | 보강할 점 |
|---|---|---|---|
| TypeScript, NestJS 기반 백엔드 개발 | 강 | 트라이포드랩 TypeScript, NestJS, Prisma, MySQL 서비스 설계와 개발. 시솔지주 TypeScript, Express | NestJS 요청 수명 주기와 DI 스코프를 말로 정리 |
| TypeScript, Java, Kotlin 등 강타입 언어 개발 경험과 이해 | 강 | TypeScript 실무, Java와 Spring은 이썸테크와 멋쟁이사자처럼 과정 | 구조적 타이핑과 명목적 타이핑 차이, 런타임 타입 소거 (J1) |
| MySQL/PostgreSQL 테이블 설계, SQL, JOIN, Subquery | 강 (MySQL) / 약 (PostgreSQL) | MySQL, MariaDB 실무, Prisma N개 쿼리를 SubQuery 기반 단일 쿼리로 통합, MongoDB에서 MySQL로 정형화 마이그레이션 | PostgreSQL 차이 (J10) |
| Linux 기본 명령 | 중강 | Amazon Linux 2, Ubuntu 운영, 42서울 C와 Linux 과제, 리눅스마스터 2급 | 장애 확인 명령 흐름 (J9) |
| HTTP 이해, RESTful API 설계와 개발 | 강 | 전 경력 API 개발, FIDO 서버에서 WebAuthn 명세 분석 | 상태 코드, 멱등성, 에러 포맷 (J6) |
| Git과 GitHub, 브랜치 전략 | 중강 | GitHub Actions, Jenkins CI/CD 구축 | 전략 선택 기준 (J8) |
| Nest, JUnit 등으로 테스트 코드 작성 | 중강 | Jest, Mocha, Chai, SuperTest, JUnit 5 사용, 부트캠프 팀 프로젝트에서 통합과 단위 테스트 주도 | 무엇을 mock하고 무엇을 실제 DB로 검증할지 (J7) |
| OOP 기본 이해 | 중강 | 도메인별 모듈 분리, UseCase와 도메인 분리 | 역할, 책임, 협력의 예시 한 장면 (J3) |
| 레이어드 아키텍처 이해와 적용 | 강 | 모듈 중심 아키텍처 설계, Controller, UseCase, Domain, Repository 분리 | 과한 계층의 비용까지 (J2) |
| RDBMS 실행 계획 기반 인덱스, 쿼리 튜닝 | 강 | 복합 인덱스로 슬로우 쿼리 99.3% 개선, Prisma 쿼리 통합으로 API 응답 90% 향상 | 측정 조건 설명 (R3, R4) |

## 4. 우대 사항과 경력 조건 매칭

| 항목 | 매칭 | 근거 | 대응 |
|---|---|---|---|
| 경력 4년 이상 10년 이하 | 확인 필요 | 이력서 연월 합산은 이썸테크 6개월, 시솔지주 12개월, 트라이포드랩 28개월로 월 단위 근사 약 3년 10개월이다. 여기에 빠진 키노라이츠 약 2개월 반(2026.06.29~09.15)을 더하면 약 4년이다 | 사용자가 산정 기준과 이력서 미기재 기간을 확정한 뒤 답한다 |
| 대학교 졸업(4년) 이상 | 충족으로 보임 | 고려사이버대학교 정보관리보안학과 학사 | 학력 인정 기준은 채용 측 확인 |
| 전공 컴퓨터, 시스템공학 | 중 | 정보관리보안학과, 42서울에서 컴퓨터 구조, 운영체제, 네트워크 학습 | 전공보다 실무 근거로 답한다 |

## 5. 기술 스택 비교

| 공고와 공개 자료의 스택 | 내 경험 | 판정 |
|---|---|---|
| TypeScript, NestJS | 실무 사용 | 동일 |
| MySQL | 실무 사용 | 동일 |
| PostgreSQL | 사용 경험 없음 | 보강 필요 |
| Java, Kotlin (강타입 예시) | Java 과거 실무와 과제, Kotlin 없음 | 유사 |
| 테스트 프레임워크 (Nest, JUnit) | Jest, Mocha, SuperTest, JUnit 5 | 동일 |
| Git, GitHub | GitHub Actions 포함 사용 | 동일 |
| Linux | Amazon Linux 2, Ubuntu | 동일 |
| AI 활용 서비스 백엔드 | LLM 서비스 백엔드 경험 없음, 외부 API 연동과 비동기 처리 경험 | 유사 (전이). 개인 프로젝트의 검색 방식 정량 비교와 AI 도구 활용을 근거로 짧게 연결(R10, 운영 경험 아님) |
| 인프라, 메시징, 관측 | 공고 미기재. 본인은 AWS ECS, SQS, EventBridge, Grafana 계열 | 회사 스택 미확인 |
