# 한국모바일결제 1차, 체크리스트와 지원 서류 준비

> [[Interview-Prep-KoreaMobilePayment-1st|목차]].

## 1. 지원 서류 (공고 요구: 이력서, 장애 해결 경험 1가지, AI 활용 사례 1개, 관련 링크)

| 항목 | 후보 | 쓸 때 주의 |
|---|---|---|
| 장애 해결 경험 | Prisma 관계 조회 지연을 요청 추적, 실행 계획, 공식 문서로 좁혀 단일 쿼리로 바꾼 사례(이력서 수치 90%). 대안으로 외부 수집 배치 오류를 영향과 원인으로 나누고 자동 검증과 배포 전 검사를 추가한 사례(마스터 FIT 12) | 재현, 가설, 검증, 해결, 영향 범위 점검, 회고 순서로 쓴다. 내부 지표와 비공개 구조는 쓰지 않는다 |
| AI 활용 사례 | 팀 AI 협업 규약: AI가 건드릴 영역과 금지 영역을 규칙 문서로 명문화하고 작업 종료 시 스스로 검증하는 회귀 루프. 보조로 개인 출석부 프로젝트의 AI 협업 파이프라인 | 출석부는 존재와 정성 결론만 쓰고 정량 수치는 넣지 않는다. 검수와 채택 책임이 사람에게 있다는 점을 끝줄에 둔다 |
| 관련 링크 | 이력서의 GitHub, 블로그, LinkedIn, 하코 커뮤니티 발표 자료 | 비공개 저장소나 전 직장 코드 링크는 넣지 않는다. 공개 링크가 결과물 판단에 충분한지 사용자가 점검한다 |

- [ ] [사용자 확정 필요] 장애 사례 하나를 고른다.
- [ ] [사용자 확정 필요] AI 사례의 공개 가능한 산출물 링크가 있는지 확인한다.
- [x] 이력서 경력 표기를 고쳤다. 트라이포드랩은 2024.02~2026.05, 키노라이츠는 2026.06~2026.09로 적고 요약 문단의 현재 시제를 과거로 바꾼다(현재 이력서 PDF는 키노라이츠가 재직중, 요약이 현재는으로 시작). 원본 수정은 사용자가 한다.

## 2. 면접 시작 전

- [ ] 면접 일시, 형식, 참여 역할을 공식 채널로 확인했다 (역질문 마스터 F1).
- [ ] 참석자는 역할로만 적었다.
- [ ] 바로 앱을 설치하고 QR 결제와 멤버십 안내 화면을 직접 확인했다. 관찰한 사실만 말한다.
- [ ] 이직 사유, 퇴사 사유, 짧은 재직, 현재 활동 답변을 연습했다 ([[Interview-Prep-KoreaMobilePayment-1st-FIT|FIT 문서]] C3~C6).
- [ ] 핵심 역질문 2~3개(B1, D1, AI 검수 게이트)를 외웠다.

## 3. 보강이 필요한 기술 영역

| 영역 | 보강할 핵심 개념과 판단 기준 | 복습 |
|---|---|---|
| 결제 도메인 | 승인, 매입, 취소와 환불의 차이, 멱등성 키, 결과 불명확 상태, 웹훅 서명 검증, 금액 정수 저장, 대사 | [ ] |
| 정기결제 | 빌링키 발급과 저장 범위, 청구 주기 유일 키, 실패 사유별 재시도, 해지와 환불 정책 분리 | [ ] |
| 배포와 운영 | 되돌아가지 않는 부수효과, 확장, 이전, 축소 스키마 변경, 기능 플래그, digest 기반 롤백 | [ ] |
| 스케줄러와 큐 | @nestjs/schedule의 인스턴스별 실행, 단일 실행 보장, BullMQ 재시도와 중복 | [ ] |
| 프론트 | React Native 빌드와 스토어 배포 흐름, Next.js 라우팅과 API 호출 구조의 기본 | [ ] |
| 단말 연동 | 요청 ID 기반 재전송 멱등, 명령 확인 응답, heartbeat 관측 | [ ] |

## 4. 강하게 어필할 포인트

1. 운영 전 범위를 직접 해 봤다: ECS 전환, 멀티스테이지, 관측과 경보.
2. 동시성 정합성과 멱등 소비를 실제로 다뤘다: 결제와 충전의 불변식으로 곧바로 옮길 수 있다.
3. AI 협업 규약을 팀 단위로 만들었다: 공고의 AI로 만들고 사람이 검수한다는 방식과 같다.
4. 수치는 이력서의 공개 값만 쓰고, 측정 조건을 모르면 모른다고 말한다.

## 5. 답변 점검

- [ ] 외부 귀책 표현이 없다 (회사 사정, 비전, 동료 탓).
- [ ] 부정 단어를 먼저 꺼내지 않는다 (업무 강도, 보상).
- [ ] 결제 직접 연동 경험을 부풀리지 않는다. 원칙과 인접 경험으로 말한다.
- [ ] Codex, React Native, Next.js, 결제 단말은 경험 없음을 먼저 말한다.
- [ ] 답변 끝줄을 결제가 멈추지 않는 운영, 검수, 자동화 중 하나로 연결한다.

## 6. 공개 전 점검

- [x] 회사 사실에 공개 출처가 있거나 미확인으로 표시했다.
- [x] 제3자 실명, 연락처, 발화 원문이 없다.
- [x] 본인 처우 금액이 없다.
- [x] 전, 현 직장 비공개 정보와 내부 지표가 없다. 출석부 정량 수치가 없다.
- [ ] 이력서 수치의 측정 조건을 사용자가 말할 수 있는지 확인한다.
