## 0. 1차 전략

- **필수 스택 공백을 먼저 정리한다.** 필수는 Java와 Spring Boot 기반 MVC 개발인데, 최근 2년 반의 상용 운영은 NestJS다. Java와 Spring MVC 실무(이썸테크), Java 백엔드 과정과 Spring 멘토링은 사실대로 말하고, Spring Boot 상용 운영 경험처럼 부풀리지 않는다. 대신 계층 구조, 트랜잭션 경계, 성능 분석이 그대로 옮겨진다는 근거를 준비한다. [[Interview-Prep-TechLabs-1st-FIT|FIT]] C6.
- **가장 강한 연결은 정합성과 집계다.** 광고 트래킹과 정산, 리워드 적립은 이벤트가 중복되거나 늦어도 숫자가 맞아야 한다. 동시 요청 정합성(DB Lock), 멱등 소비와 DLQ, 주기 집계 리포트, 실행 계획 기반 조회 개선을 이 문제에 연결한다. 광고 도메인 실무는 없다고 먼저 인정한다.
- **실무자 면접이 대면이므로 화이트보드 설계가 나올 수 있다.** 광고 이벤트 수집, 리워드 중복 방지, 정산 대사를 요구사항 확인부터 시작하는 골격으로 3분 안에 설명하는 연습을 한다. [[Interview-Prep-TechLabs-1st-Service|서비스 맥락]] S1, S2, S3.
- **이직 사유 답변은 확정됐다(2026-09-29).** 퇴사 사유, 짧은 재직, 현재 활동 질문은 [[My-Motivation-Reasons]]의 현재 이직 사이클 답변을 그대로 쓴다. 직전 사이클(트라이포드랩에서 키노라이츠) 답변은 쓰지 않는다. [[Interview-Prep-TechLabs-1st-FIT|FIT]] C3, C4, C5.
- **경력 연수 표현을 맞춘다.** 상세 본문은 2년 이상이지만 트래커 검증 기록은 2~5년 요약 필드를 적었다. 이력서 재직 기간 합산은 약 3년 10개월이고, 마스터 자기소개에는 5년차 표현이 있다. 어떤 연수로 말할지 사용자가 확정한다.

## 1. 핵심 요약

| 축 | 한 줄 |
| --- | --- |
| 회사 | 운세 앱 점신과 미용 의료 마케팅을 운영하는 웰니스 플랫폼 기업으로 소개하며, 광고플랫폼사업부에서 SSP를 포함한 광고 플랫폼을 제공한다. (JD, 공식 사이트) |
| 역할 | 럭키버스 백엔드, 애드테크 솔루션 백엔드, 광고 데이터 분석과 트래킹과 정산 시스템, 사업팀 요청 처리와 시스템 개선 (JD) |
| 나의 연결 | 동시 요청 정합성, 이벤트 기반 자동화와 멱등 소비, 주기 집계 리포트, MySQL 성능 개선, AWS 인프라 전환과 관측 체계 (이력서) |
| 메시지 | 이벤트가 중복되고 늦게 와도 숫자가 맞도록, 실패와 재처리와 대조를 처음 설계에 넣는 백엔드 개발자 |

### 강점

1. MySQL 설계와 튜닝의 공개 성과. 복합 인덱스로 슬로우 쿼리 99.3% 개선, SubQuery 기반 단일 쿼리로 API 응답속도 90% 향상, Read Replica로 응답속도 40% 개선. 측정 조건을 설명할 수 있을 때만 말한다.
2. 수천 대 IoT 하드웨어 동시 요청의 Race Condition을 DB Lock으로 해결한 정합성 경험. 리워드 적립과 예산 차감에 같은 판단을 쓴다.
3. EventBridge와 SQS 기반 이벤트 처리, 멱등 소비와 DLQ. 조직 여건을 보고 Kafka 대신 관리형 큐를 고른 판단 근거.
4. IoT 상태를 주기적으로 집계해 알림톡과 이메일로 자동 통보한 리포트. 광고 일 집계와 정산 배치에 가장 가까운 경험.
5. AWS 우대 요건에 강함. 단일 NGINX에서 CloudFront, ELB, ECS(Fargate)로 전환, Docker 멀티스테이지로 이미지 909MB에서 513MB, 배포 3분 10초에서 2분 20초, Jenkins와 GitHub Actions CI/CD.
6. Grafana, Prometheus, Loki 관측 체계와 Grafana Alerting 장애 알림.
7. Java와 Spring MVC로 경력을 시작했고, Java 백엔드 과정 최우수 코드 선정과 카카오테크 캠퍼스 Spring 멘토 경험이 있다.

### 갭

1. **Spring Boot 상용 운영 경험 부족(필수).** 최근 주력은 NestJS와 TypeScript다. JPA 런타임 동작과 트랜잭션 프록시 경계를 복습한다.
2. **광고 도메인 경험 없음.** 트래킹, 어트리뷰션, 정산, 무효 트래픽, SSP와 DSP 구조는 개념 수준이다.
3. **Kafka, RabbitMQ 운영 경험 없음(우대).** SQS 경험과 선택 기준으로 전이한다.
4. **Kubernetes, IaC 경험 없음(우대).** ECS 경험까지만 말한다.
5. **프론트엔드 프레임워크 실무 없음(우대).**
6. **경력 연수 표현 미확정.** 이력서 PDF의 키노라이츠 재직중 표기와 요약 문단 현재 시제는 고쳐야 한다(트라이포드랩 재직은 2024.02~2026.05).

## 2. 우선 준비 사항

1. 현재 이직 사유, 짧은 재직, 현재 활동 답변 방향은 확정됐다(FIT C3, C4, C5). 이력서의 키노라이츠 재직중 표기를 2026.06~2026.09로, 요약 문단의 현재 시제를 과거로 고친다(원본 수정은 사용자 몫). 이미 제출한 이력서가 재직중일 수 있으니 경력 흐름을 말할 때 9월 중순에 마쳤다는 사실을 먼저 짧게 밝히고 C3 퇴사 답변으로 잇는다(FIT 참고). 개인 사업은 먼저 밝히지 않고, 직접 물으면 사실대로 답한다.
2. Spring MVC 요청 흐름, `@Transactional` 프록시와 롤백 규칙, JPA N+1을 NestJS와 대비해 말할 수 있게 복습한다. [[Interview-Prep-TechLabs-1st-Tech-JD|JD 기술]] J1, J2, J3, J8.
3. 광고 이벤트 수집, 리워드 중복 방지, 정산 대사를 화이트보드 골격으로 각각 3분 연습한다. [[Interview-Prep-TechLabs-1st-Service|서비스 맥락]] S1, S2, S3.
4. 이력서 수치 5개(99.3%, 90%, 40%, 909MB에서 513MB, 3분 10초에서 2분 20초)의 측정 조건과 본인 기여를 한 문장씩 준비한다.
5. 주기 집계 리포트의 실제 구현 세부를 사용자가 확인한다. [[Interview-Prep-TechLabs-1st-Tech-Resume|이력서 기술]] R8.
6. 점신 앱 또는 럭키버스를 직접 써 보고 관찰한 사실 한 문장을 만든다.
7. 이력서의 개발 지식 온톨로지 프로젝트는 키노라이츠 경력 아래에 있지만 개인 프로젝트다(사용자 확인). 면접에서 먼저 개인 프로젝트라고 밝히고, 이력서도 개인 프로젝트 항목으로 옮긴다(원본 수정은 사용자 몫). [[Interview-Prep-TechLabs-1st-Tech-Resume|이력서 기술]] R10.
8. 이력서의 골든 케이스 약 145건 문구 정정 필요(원본 수정은 사용자 몫). 145건 세트는 없고 실제는 74개 질문 비교와 94개 질문 리랭커 비교다. 면접에서 먼저 바로잡는다. [[Interview-Prep-TechLabs-1st-Tech-Resume|이력서 기술]] R10.

## 3. 역질문

[[My-Reverse-Questions]]에서 5개를 고르고 회사 특이 질문 2개를 더했다. 1차에서는 핵심 3개를 외우고 나머지는 흐름에 맞춰 고른다.

1. **초기 과제와 성공 기준 (B1)**: 합류 후 가장 먼저 책임질 과제와, 잘하고 있다고 판단할 기준은 무엇인가요?
2. **기술 경계와 신규 개발 비중 (C1)**: 이 포지션이 럭키버스와 애드테크 중 어느 서비스를 주로 맡고, 신규 개발과 기존 시스템 개선의 비중은 어느 정도인가요?
3. **데이터 경계와 검증 (C2)**: 광고 트래킹과 정산처럼 정합성이 중요한 경계는 현재 어떤 방식으로 검증하고 있나요?
4. **학습과 검증 (D2)**: 공고의 기술 중 제가 깊이를 더 쌓아야 할 부분을 어떤 작은 과제로 익히는 것이 가장 효과적일까요?
5. **다음 단계 형식 (F1)**: 이후 실무과제나 임원면접이 있다면 어떤 형식으로 진행되나요?
6. **회사 특이, 스택 구성**: 공고의 Java와 Spring Boot 외에 서비스별로 쓰는 언어나 프레임워크가 있는지, 우대사항의 Kafka와 Kubernetes는 현재 쓰고 있는지 계획인지 궁금합니다.
7. **회사 특이, 제휴 확장과 백엔드 과제**: 럭키버스가 여러 제휴 플랫폼으로 넓어지면서 백엔드에서 가장 신경 쓰는 부분이 파트너 연동, 리워드 정합성, 정산 중 어디인가요?

아껴둘 질문: 온콜과 장애 대응(E3), 연봉 밴드(A3)는 이후 단계에서.
