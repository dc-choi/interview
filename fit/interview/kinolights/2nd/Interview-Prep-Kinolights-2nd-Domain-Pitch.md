# 키노라이츠 2차, 도메인 오너십 피치

> 1차에서 이미 말한 검색과 콘텐츠 데이터 관심을 2차의 열정 카드로 정리했다. 공개 제품에서 확인한 사용자 문제와 내 경험만 연결한다.
> 실제 데이터 소스, 갱신 주기, 소유권, 팀의 기술 구조와 우선순위는 알 수 없으므로 회사 사실로 말하지 않고 질문으로 확인한다.

## 1. 방향

공개 제품에서 콘텐츠를 발견한 뒤 시청 가능 정보를 확인하는 흐름을 볼 수 있었다. 이 경험에서 내가 세운 가설은 다음과 같다.

- 통합검색의 신뢰는 화면에 보이는 시청 가능 정보가 실제 상태와 얼마나 잘 맞는지에 크게 좌우된다.
- 외부 정보는 공급 방식과 변경 빈도가 달라 검증, 변경 감지와 복구 경계가 중요할 수 있다.
- 검색과 추천은 목적지이고, 정확하고 최신인 콘텐츠 정보는 그 기반이 될 수 있다.

위 세 문장은 준비 가설이며, 실제 운영 방식이나 회사의 현재 과제를 뜻하지 않는다.

## 2. 내 경험 카드

| 연결할 경험 | 보존할 메커니즘 | 피할 내용 |
|---|---|---|
| 외부 데이터 연동 | 입력 계약, 변경 감지, 실패 분류, 재시도와 복구 경계를 설계한 경험 | 이전 회사의 연동 대상, 고객명, 호출량과 내부 구조 |
| 데이터 정합성 | 동시 갱신과 최신 상태 조회에서 트랜잭션, 실행계획과 검증 기준을 사용한 경험 | 운영 수치와 성능 전후값 |
| 인증과 권한 | 공개 표준을 읽고 인증 흐름, 권한과 감사 가능성을 설계한 경험 | 내부 구현 세부와 제3자 역할 |
| 비동기 처리 | 후속 작업의 실패 격리, 멱등성, 재시도와 DLQ를 설계한 경험 | 특정 채널, 거래와 고객 정보 |

## 3. 30초 피치

> 합류하면 콘텐츠 정보의 최신성과 신뢰를 만드는 문제를 가장 깊게 배우고 싶습니다. 공개 제품에서 작품을 찾고 시청 가능 정보를 확인하는 경험을 보며, 정보가 실제 상태와 어긋나는 순간 사용자 신뢰가 크게 흔들릴 수 있겠다고 생각했습니다. 저는 외부 입력의 변경을 검증하고, 실패를 분류해 재시도와 복구 경계를 설계한 경험이 있습니다. 그 경험을 바탕으로 실제 데이터 계약과 품질 기준을 먼저 배우고, 검색과 추천의 기반을 더 단단하게 만드는 데 기여하고 싶습니다.

## 4. 꼬리 질문 대비

### 왜 이것이 사용자 가치와 연결되는가

> 사용자는 작품 자체보다 어디에서 어떻게 볼 수 있는지도 함께 결정합니다. 정보가 최신이고 설명 가능한 상태여야 검색 결과를 신뢰하고 다음 행동으로 이어질 수 있습니다. 다만 어떤 품질 지표가 가장 중요한지는 팀의 실제 사용자 데이터와 운영 제약을 보고 판단해야 합니다.

### 어떻게 최신성을 유지할 것인가

> 변경 빈도와 실패 비용에 따라 갱신 우선순위를 다르게 두고, 입력 계약 검증, 변경 감지, 재시도와 수동 복구 경계를 설계하겠습니다. 푸시, 배치, 수집 방식의 선택은 실제 제공 조건과 데이터 계약을 확인한 뒤 결정하겠습니다.

### 왜 인증도 관심 있는가

> 인증은 사용자 신뢰와 권한 경계에 직접 닿는 문제입니다. 표준 문서부터 읽어 흐름을 설계했던 경험이 있어, 제품의 실제 요구와 위험 모델을 먼저 확인한 뒤 책임 있게 기여하고 싶습니다.

## 5. 온보딩 역질문

> 제가 합류하면 어떤 순서로 콘텐츠, 검색과 운영 도메인을 인수받게 되나요? 새 구성원이 실제 사용자 문제와 품질 기준을 배우는 방식도 궁금합니다.

## 6. 사용 원칙

- 1차에서 이미 말한 검색과 데이터 품질 관심 위에서만 확장한다.
- 30초 피치 뒤에는 대표가 더 묻는 경우에만 기술 세부를 보탠다.
- 내부 계획, 공개되지 않은 제휴, 조직 구조나 특정 면접관 발화를 근거로 말하지 않는다.
- 사용자 경험, 데이터 신뢰와 내 검증 경험을 연결하고, 실제 구조는 질문으로 닫는다.
