# 키노라이츠 2차, 공개 컬처 근거와 답변 매핑

> 2차 컬처 인터뷰를 준비하며 사용한 공개 근거와 내 답변의 연결을 기록한다. 구성원 실명, 연락처, 면접 중 들은 조직 운영과 발화 원문은 남기지 않는다.
> 공개 회사 사실은 당시 출처가 남은 자료만 쓴다. 최신 상태가 불명확한 내용은 현재 사실로 단정하지 않고 질문으로 바꾼다.

## 1. 근거와 사용 범위

| 근거 | 사용 방식 |
|---|---|
| [당시 공개 채용 공고](https://groupby.kr/positions/10649) | 역할에 필요한 책임 범위와 공개된 일하는 방식의 문구만 확인한다. |
| [KOFIC 공개 인터뷰](https://magazine.kofic.or.kr/webzine/web2/2593/pdsView.do) | 공개된 회사의 제품 방향과 창업 맥락을 이해하는 자료로만 쓴다. 제3자 실명이나 발화를 면접 답변에 인용하지 않는다. |
| [[Kinolights-Domain-OTT-Business-Models|OTT 도메인 문서]] | OTT 수익 모델, 공개 제품 표면과 출처가 있는 사업 맥락을 확인한다. |

## 2. 공개 공고와 내 카드의 매핑

| 공개적으로 확인한 축 | 내 답변 카드 |
|---|---|
| 빠른 개발과 안정적 운영을 함께 다루는 백엔드 역할 | 제품 규칙을 테스트로 고정하고, 관측과 복구 경계를 만든 경험 |
| 주도적으로 문제를 정의하고 해결하는 기대 | 문제, 가설, 검증과 재발 방지의 순서로 설명하는 방식 |
| 협업과 책임 있는 실행 | 사용자 영향과 되돌리기 비용을 함께 놓고, 결정 뒤 합의를 테스트와 문서로 고정한 경험 |
| AI 도구 활용에 열린 환경 | 반복 구현은 보조받되 설계, 검증과 최종 채택의 책임은 직접 가진다는 원칙 |

### 당시 공개 인재상에서 읽은 세 축

| 축 | 준비할 행동 근거 |
|---|---|
| 주도적 문제 해결 | 해결책부터 밀지 않고 문제, 사용자 영향과 판단 기준을 먼저 정의한 경험을 말한다. |
| 높은 책임감 | 근거가 있으면 반대 의견을 내되, 결정 뒤에는 제약 안에서 최선의 실행과 복구를 책임진다. |
| 협업 | 리더십과 팔로워십을 고정된 지위가 아니라 상황에 맞는 역할로 설명하고, 내가 정한 것과 팀이 정한 것을 구분한다. |

이 어휘를 외워서 반복하기보다 실제 갈등과 합의 사례 하나로 보여 준다. 공개 페이지에 없거나 시점이 불명확한 내부 평가 기준으로 확대 해석하지 않는다.

### 공개 제품에서 확인한 대화 소재

- 작품 검색 결과에서 시청 가능한 서비스와 정액제, 무료, 대여, 구매 같은 접근 방식을 함께 보여 준다.
- 신호등 평가는 취향의 호불호를, 별점은 작품에 대한 평가를 표현하는 서로 다른 사용자 신호로 이해했다.
- 콘텐츠 이야기는 실제로 본 작품과 사용 경험만 말한다. 작품 지식을 과장하거나 공개 화면만 보고 내부 추천, 수집 구조를 추정하지 않는다.

## 3. 컬처핏 답변의 톤 기준

### 주도성

혼자 정답을 밀어붙이는 태도가 아니라, 문제를 정확히 정의하고 근거, 선택과 책임을 명확히 하는 행동으로 설명한다. 내가 결정한 것과 팀이 함께 정한 것을 구분하고 과장하지 않는다.

### 책임감

실패를 외부 탓으로 설명하지 않는다. 당시 제약 아래의 판단, 놓친 위험, 수정한 기준과 다음 적용을 말한다. 비판이 필요하면 사용자 영향, 비용이나 복구 가능성 같은 근거를 먼저 둔다.

### 협업

반대 의견을 없애는 것이 아니라 목적과 판단 기준을 맞추는 과정으로 설명한다. 기획 의도, 화면 계약, 테스트와 문서를 통해 해석 차이를 줄인 경험을 쓴다.

### 장기 기여

도구 이름이나 회사 규모가 아니라 제품의 사용자 문제, 운영 품질과 학습할 도메인을 기준으로 말한다. 실제 팀 구성, 온보딩 방식과 장기 우선순위는 면접에서 확인할 질문이다.

## 4. 출처 위생과 금지선

- 공개 작성물의 저자나 구성원을 이름으로 언급하지 않는다.
- 시점이 없는 블로그나 예전 숫자를 현재 사실처럼 말하지 않는다.
- 공개 인터뷰도 사실 확인의 실마리로만 쓰고, 회사의 현재 계획이나 내부 구조로 확대 해석하지 않는다.
- 제품의 데이터 수집, 갱신, 검색 구조는 공고나 서비스 표면만으로 알 수 없으므로 질문으로 남긴다.
- 실제 면접관의 발화, 일정 안내, 평가 기준, 다른 전형 상태와 처우 금액은 답변의 근거로 섞지 않는다. 일정과 본인 전형 기록 자체는 회고와 트래커에 보존한다.

## 5. 2차에서 확인할 질문

1. 제품이 앞으로 가장 중요하게 해결할 사용자 문제는 무엇인가요?
2. 새 구성원이 제품, 도메인과 운영 맥락을 배우는 순서는 어떻게 되나요?
3. 콘텐츠 정보 품질에서 지금 가장 어려운 기준은 무엇인가요?
4. 제 역할이 사용자 결과와 사업 목표에 연결되는 방식을 어떻게 판단하시나요?
