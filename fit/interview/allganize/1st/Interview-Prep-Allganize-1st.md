## 1. 역할 해석 (공고 원문 기준)

- 공고는 FDE를 고객 현장에서 문제를 파악하고 기술로 실질적인 변화를 만드는 엔지니어로 설명한다. FDE(SW)는 현장 인사이트를 프로덕트팀과 공유해 AI 솔루션의 성능과 방향을 발전시키고, FDE(Infra)는 고객사 on-prem 환경의 배포와 운영을 맡는다고 구분한다.
- 주요 업무는 고객과 비즈니스 과제 정의, AI 기반 해결 방안 설계, 현장 인사이트의 제품 환류, 프로젝트 전 과정 주도와 요구사항의 기술 결과물화 세 가지다.
- 공고에 FDE는 상황에 따라 고객사에서 업무 지원이 있다고 적혀 있다. 상주 기간, 출장 빈도와 지역은 공개되지 않았다.
- 이 역할은 제품 백엔드 개발자 채용이 아니다. 면접관은 코드 깊이보다 모호한 고객 문제를 정의하고, 제약 속에서 동작하는 결과물로 좁히고, 그 경험을 제품팀이 쓸 수 있는 언어로 돌려주는 능력을 볼 가능성이 높다. 이 해석은 공고 문장에서 추론한 것이며 면접에서 역질문으로 검증한다.

## 2. 핵심 요약

**강점 (직접 연결되는 경험)**

- 고객 요구로 시작한 일을 끝까지 책임진 경험: 시솔지주에서 고객사 On-Premise 환경 구축을 위해 AWS 기반 서비스를 옮긴 마이그레이션, 트라이포드랩에서 대형 고객사 PoC를 위한 도메인 모듈 분리 설계.
- 명세를 직접 읽고 판단한 경험: WebAuthn 명세를 분석해 FIDO 아키텍처를 설계하고 인증을 통과했으며, 오픈소스의 명세 불일치를 이슈로 제기했다.
- 운영 문제를 재현하고 좁히는 방식: 동시성, 비동기 처리, 슬로우 쿼리, 관측성. 고객 현장 장애 대응에 그대로 옮길 수 있는 문제 해결 순서다.
- AI 코딩 도구를 팀 규약으로 만든 경험: 우대사항의 AI 코딩 도구 활용과 대규모 codebase 분석에 직접 대응한다.
- 42서울 C와 Linux 과제, 리눅스마스터 2급, Amazon Linux 2와 Ubuntu 운영 경험: 자격요건의 Linux/Unix 환경에 대응한다.

**갭 (정직하게 인정하고 전이 근거를 말할 것)**

- Python 실무 경험이 이력서에 없다. 공고는 Python 또는 그에 준하는 경험을 요구하므로 TypeScript, Java 실무를 준하는 경험으로 제시하되 Python 학습 계획을 구체적으로 준비한다.
- LLM, RAG를 제품이나 고객 프로젝트에 적용한 경험이 없다. AI 도구 사용자로서의 경험과 RAG 설계 원리 이해를 구분해서 말한다.
- Kubernetes 운영 경험이 없다. ECS 기반 컨테이너 운영과 배포 경로 설계 경험에서 전이한다.
- 고객 대면 프로젝트 리드 경험이 제한적이다. 고객 요구에서 출발한 마이그레이션과 PoC 설계는 있으나, 고객과 직접 요구사항을 정의하고 일정을 협상한 경험의 범위는 [사용자 확정 필요]로 둔다.

## 3. 면접 전략

- 첫 3분은 백엔드 개발자가 왜 FDE인가에 대한 답을 자기소개 안에 넣는다. 이 질문이 오지 않아도 면접관은 머릿속으로 묻고 있다.
- 모든 경험 답변을 고객 문제 정의, 제약, 선택, 검증, 제품 환류의 순서로 말한다. 기술 디테일은 꼬리질문이 들어올 때만 깊게 들어간다.
- Python, RAG, Kubernetes 갭은 먼저 인정하고, 전이되는 원리와 합류 전후 학습 계획을 한 문장씩 붙인다. 써 본 것처럼 말하지 않는다.
- 사전 과제가 있으면 1차 면접은 과제 설명과 방어로 시작할 가능성이 높다. 과제를 받으면 [[Interview-Prep-Allganize-1st-Checklist|체크리스트]]의 과제 슬롯을 먼저 채운다.
- 고객사 근무 가능 조건은 자격요건이다. 가능 범위를 사용자가 확정하기 전에는 답변을 만들지 않는다.

## 4. 지원 판단을 위한 자기 확인

`fit/AGENTS.md`의 원칙대로 회사가 내 가치를 높이는지보다 이 자리에서 무엇을 증명하고 싶은지를 먼저 정한다. 아래는 답변 문장이 아니라 사용자가 면접 전에 스스로 답할 질문이다.

- 이 역할에서 증명하고 싶은 것: [사용자 확정 필요]. 후보는 고객 문제를 AI 결과물로 좁히는 능력, 온프레미스 환경의 제약 속 배포와 운영, 현장 피드백을 제품 개선으로 연결하는 능력이다.
- 트래커 비고에는 제품 백엔드가 아닌 고객 대응형 역할이라 우선순위가 낮다고 적혀 있다. 지원을 확정한다면 기존 커리어 스탠스(Node.js와 TypeScript 백엔드 우선)와 어떻게 연결되는지 먼저 정리한다.
- [[Self-Analysis]]의 새로움은 한 번에 하나 원칙과 비교하면, 이 역할은 새 산업(엔터프라이즈 AI), 새 언어(Python), 새 역할(고객 대면 FDE)이 겹친다. 익숙한 문제 유형(정합성, 운영, 장애 대응)과 검토 구조가 남는지를 역질문으로 확인한다.

## 5. 미해결 확인 사항

- **재직 기간 표기 (확정)**: 트라이포드랩 2024.02~2026.05, 키노라이츠 2026.06.29~2026.09.15로 맞춘다. 이력서 PDF에는 키노라이츠가 이미 있으나 "2026.06 - 재직중 (4개월)"이고 요약 문단이 현재 시제다. 이력서의 재직중 표기를 2026.06~2026.09로, 요약 문단을 과거 시제로 고치는 원본 수정은 사용자 몫이다. 이미 제출한 이력서가 재직중일 수 있으므로 면접에서 경력 흐름을 말할 때 9월 중순에 마쳤다는 사실을 먼저 짧게 밝히고 Service 문서 C3 퇴사 답변으로 잇는다. 면접 답변은 종료월을 이력서 연월 기준으로만 말한다.
- **현재 역할과 이직 사유 (확정)**: 키노라이츠 수습 기간 중 본채용으로 이어지지 않았고, 답변은 [[My-Motivation-Reasons]] 정본을 fork한 [[Interview-Prep-Allganize-1st-Service|컬처핏 문서]] C3을 쓴다. 자기소개 첫 문장에는 현재 소속을 넣지 않는다.
- **고객사 근무 가능 범위**: 상주, 출장 가능 기간과 지역.
- **사업 병행 여부의 공개 범위 (확정)**: 개인 사업과 1인 대표 활동은 먼저 밝히지 않고, 직접 물으면 사실대로 답한다.
- **지원 상태**: 지원 여부, 서류 결과, 사전 과제 수령 여부, 면접일.
- **회사 사실**: FDE 조직 규모, SW와 Infra의 실제 업무 비율, Python 외 사용 스택, 한 명이 동시에 맡는 고객 수는 공개 자료로 확인되지 않았다. 역질문으로 남긴다.
- **개인 프로젝트 위치 (확정)**: 개발 지식 온톨로지 프로젝트가 이력서 PDF에는 키노라이츠 경력 아래에 적혀 있으나 개인 프로젝트다. 면접에서 먼저 개인 프로젝트라고 밝히고, 이력서에서도 개인 프로젝트 항목으로 옮기는 것을 권한다(원본 수정은 사용자 몫). 답변은 Tech-Resume R10.
- **이력서 145건 문구 정정 필요**: 이력서의 골든 케이스 약 145건 문구는 부정확하다. 실제는 74개 질문으로 검색 방식을, 그 74개를 포함한 94개 질문으로 리랭커를 비교했다(원본 수정은 사용자 몫). 면접에서 물으면 먼저 바로잡는다(Tech-Resume R10).
