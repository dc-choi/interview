# 민감 질문 답변 가이드

> 민감한 질문에는 사실을 과장하거나 숨기지 않되, 개인 정보와 전 직장 내부 정보는 공개하지 않는다. 현재 이직 준비가 시작되지 않았다면 미래 이직 사유를 미리 확정하지 않는다.

## 위험 질문과 답변 원칙

| 주제 | 답변 원칙 | 연결 문서 |
| --- | --- | --- |
| 초기 경력의 짧은 역할 | 선택의 배움과 현재의 행동을 설명하고 기간은 반복하지 않는다. | [[My-Motivation-Reasons]] |
| 고용 변화와 공백 | 사실 범위에서 학습과 다음 행동을 말하고, 개인 사정은 공개하지 않는다. | [[My-Motivation-Reasons]] |
| 현재 역할의 변화 이유 | 사용자가 다음 이직 사유를 확정한 뒤에만 답변을 만든다. | [[My-Motivation-Reasons]] |
| 큰 커리어 목표 | 직함보다 책임질 문제와 팀에 남길 영향을 설명한다. | [[My-FIT-Answers]] |
| 품질 사고 | 원인, 즉시 대응, 재발 방지와 검증을 구분한다. | [[My-FIT-Answers]] |
| AI 도구 활용 | 위임 범위와 검증 책임을 분명히 한다. | [[My-FIT-Answers]] |
| 업무 강도 | 헌신을 약속하는 대신 우선순위와 지속 가능한 운영 방식을 묻는다. | [[My-FIT-Answers]] |
| 공개 글과 평판 | 타인이나 이전 조직을 비난하지 않고, 현재의 소통 기준과 행동 변화만 말한다. | [[My-Motivation-Reasons]] |

## 위험한 표현과 안전한 전환

| 피할 표현 | 답변의 중심 |
| --- | --- |
| 전망이 없어서 나왔다 | 프로젝트 단위 경험 뒤 한 서비스를 장기적으로 개선하고 운영하는 책임을 원했다. |
| 체계나 사수가 없었다 | 스스로 공식 자료와 실험으로 온보딩한 경험, 다음에는 리뷰와 협업 안에서 더 깊게 성장하려는 선택을 말한다. |
| 회사가 어려워져서 나왔다 | 사업 종료나 고용 변화의 사실은 짧게 말하고, 이후 회사 단계와 역할 범위를 확인하는 기준을 만든 행동으로 닫는다. |
| 조건이나 보상 때문에 옮긴다 | 역할의 책임과 기술 깊이, 다음 환경에서 증명할 역량을 설명한다. 개인 처우 금액은 말하지 않는다. |
| 트래픽 경험이 없다 | 실제로 책임진 규모와 제약을 과장하지 않고, 그 안에서 해결한 정합성, 실패 복구와 운영 문제를 설명한다. |
| AI가 다 해준다 | 사람이 정한 명세, 검증 경계와 최종 채택 책임을 구분한다. |
| 업무 강도가 걱정된다 | 성과를 지속시키는 우선순위, 장애 대응과 회복 방식이 어떻게 운영되는지 묻는다. |
| 특정 상사나 동료 때문에 힘들었다 | 당시 내 대응에서 배운 점과 지금 바꾼 소통 행동을 말한다. |

## 공백기 답변

공백의 길이보다 그 시간을 어떻게 이해하고 설명하는지가 중요하다. 활동을 길게 나열해 방어하지 말고, 쉰 이유, 그 기간에 정리하거나 실행한 한 가지, 다음 선택에 미친 영향을 짧게 연결한다.

- 사실을 숨기거나 의미를 과장하지 않는다.
- 개인 사정의 구체 내용은 공개하지 않아도 된다.
- 학습이나 프로젝트를 말했다면 실제 산출물과 검증 가능한 행동만 근거로 든다.
- 아직 스스로 설명하기 어려운 기간이라면 활동을 꾸미기보다 현재 확인 가능한 사실과 배운 기준까지만 말한다.

## 공통 답변 구조

1. 사실을 짧게 인정한다.
2. 필요한 맥락만 제공한다.
3. 배운 점과 현재의 행동 변화를 말한다.
4. 지원 회사의 공개된 문제와 연결한다.

근속 기간과 전형 단계는 필요한 범위에서 사실대로 말하고 기록할 수 있다. 개인 처우 금액, 비공개 평가와 조직 정보, 가족의 구체적인 개인정보는 답변에 넣지 않는다. 답변이 길어져 변명처럼 들리지 않도록 핵심만 말하고, 추가 질문이 있을 때만 검증 가능한 사실을 보탠다.

## 전달 점검

- 한 질문에는 결론, 필요한 맥락, 행동 변화 순서로 답한다.
- 과거의 감정적 공개 글을 질문받으면 기억나지 않는다고 피하지 말고, 당시 미숙함과 현재의 게시 기준을 설명한다.
- 수치가 필요하면 공개 가능한 근거와 측정 조건이 있는 값만 말한다. 기억에 의존한 수치로 답을 강하게 보이게 만들지 않는다.
- 답변이 끝나면 추가로 확인할 부분이 있는지 짧게 묻고, 같은 변명을 반복하지 않는다.
