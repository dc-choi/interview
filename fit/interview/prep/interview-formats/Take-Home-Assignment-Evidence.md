# 과제 전형의 위험 검증과 기술 선택 근거

과제 기능을 구현한 뒤에는 핵심 기능이 실패할 조건과 기술 선택의 이유를 설명한다. 다음은 제출 준비를 위한 점검 제안이다. 특정 기술의 사용이나 테스트 수가 합격을 보장한다는 평가 기준이 아니며, 회사가 제시한 요구사항과 제출 지침을 우선한다.

## 핵심 기능의 위험부터 고른다

동작 시연과 실패 조건의 검증은 다르다. 제한된 시간에는 과제의 중심 업무에서 잘못되면 영향이 큰 조건을 먼저 확인한다.

| 중심 기능 | 확인할 위험 | 제출물에 남길 근거 예시 |
| --- | --- | --- |
| 조회와 검색 | 느린 쿼리, 반복 조회, 오래된 결과 | 입력 데이터와 실행 조건, 측정한 응답 시간, 병목 가설과 개선 전후 결과 |
| 결제나 계약 상태 변경 | 중복 요청, 동시 실행, 일부 처리만 성공 | 중복과 동시 요청의 기대 결과, 상태 불변조건, 트랜잭션 범위와 실패 경로 테스트 |
| 외부 API 연동 | 응답 유실 뒤 재시도, 외부 성공과 내부 기록 불일치 | 실패를 재현한 방법, 재시도 정책, 결과 확인과 복구 범위 |

표는 과제별로 선택할 예시다. 조회가 있다는 이유만으로 캐시를 추가하지 않는다. 병목과 최신성 요구를 확인한 뒤 도입 여부를 정하고, 도입하면 무효화 조건과 감수하는 지연을 설명한다. 구현하지 않은 대안은 개선 후보로 표시한다.

멱등성 키가 있다는 이유만으로 모든 동시성 문제가 해결됐다고 말하지 않는다. 예를 들어 2026-10-23 확인한 Stripe API v1은 실행 시작 뒤 결과를 저장하며, 입력 검증 실패나 실행 중인 요청과의 충돌에서는 멱등 결과를 저장하지 않는다. 키와 재시도의 계약, DB 상태 변경의 보호 범위는 따로 확인한다. 다른 결제 API나 Stripe API v2에 이 세부 동작을 그대로 적용하지 않는다.

## 선택 이유를 요구사항과 연결한다

기술 이름보다 다음 연결을 짧게 기록한다. 이력서에서 사용한 도구와 다른 선택도 설명할 수 있지만 익숙함이나 일정만 적고 끝내지 않는다.

1. **요구사항:** 무엇을 보장해야 했는가.
2. **제약:** 시간, 데이터 규모, 운영 환경과 직접 확인한 조건은 무엇인가.
3. **대안과 선택:** 어떤 방식을 비교했고 왜 현재 방식이 적합했는가.
4. **감수한 비용:** 복잡성, 운영 부담과 보장하지 못한 범위는 무엇인가.
5. **검증과 재검토:** 어떤 결과로 확인했고 어떤 조건에서 선택을 바꿀 것인가.

중요한 결정만 README나 짧은 [[ADR|설계 결정 기록]]에 남긴다. 문서 분량을 늘리기 위한 별도 설계 계층이나 미사용 기술을 추가하지 않는다. AI가 작성한 코드도 같은 기준으로 설명하고, 실행하지 않은 검사는 미검증으로 적는다.

## 제출 전 설명 연습

### 핵심 기능이 정상 동작한다는 근거는 무엇인가

- **질문 의도:** 구현 여부와 검증 범위를 구분할 수 있는지 확인한다.
- **답변 골격:** 핵심 요구사항, 실패 위험, 실행한 검사, 확인한 결과와 남은 한계 순으로 설명한다.
- **흔한 오답:** 테스트가 통과했으니 전체 시스템이 안전하다고 말한다.
- **꼬리질문:** 같은 요청 두 개가 동시에 오거나 외부 응답이 끊기면 무엇이 달라지는가.
- **학습 정본:** [[Requirements-Traceability|요구사항 추적성]], [[Test-Pyramid|테스트 범위와 계층]], [[Idempotency-Key|멱등성 키]].

### 왜 이 기술을 선택했는가

- **질문 의도:** 도구 선호와 요구사항에 근거한 선택을 구분한다.
- **답변 골격:** 요구사항과 제약, 비교한 대안, 선택의 이익과 비용, 검증 결과를 연결한다.
- **판단 기준:** 현재 문제를 해결하는지, 제한된 시간에 검증 가능한지, 추가 운영 부담을 감당할 수 있는지 확인한다.
- **흔한 오답:** 유명해서 선택했다거나 이전에 써 봤다는 이유만 제시한다.
- **꼬리질문:** 트래픽, 정합성 요구나 운영 인력이 바뀌면 어느 선택부터 재검토하겠는가.
- **학습 정본:** [[ADR|설계 결정 기록]], [[Cache-Invalidation|캐시 무효화]].
