## 0. 1차 전략

- **1차는 직무 면접이다.** 공식 FAQ가 1차를 직무 중심이라고 밝힌다. FIT 답변은 짧게 준비하고, 시간은 기술과 서비스 설계 문답에 쓴다. 다만 이직 사유와 짧은 재직 질문은 1차에서도 나올 수 있으므로 확정된 F3, F4 답변을 먼저 연습한다.
- **팀의 두 문제에 답을 맞춘다.** 공고는 이 팀의 일을 재생 요청을 어디로 보낼지 정하는 일과, 그 소비를 어떤 기준으로 남기고 해석할지 정하는 일로 설명한다. 앞쪽은 정합성 있는 상태 판단과 장애 시 전환, 뒤쪽은 이벤트 정의와 데이터 계약이다. 내 경험 중 동시성 정합성, 이벤트 기반 비동기 처리, 관측과 경보가 두 문제에 각각 걸린다.
- **가장 큰 갭은 언어와 도메인이다.** 필수요건이 Kotlin 또는 Java 기반 개발 경험과 Spring Framework 사용 경험인데, 최근 실무는 TypeScript와 NestJS다. Java와 Spring 실무는 이썸테크 시기의 Spring MVC 마이그레이션이 이력서에 있고, Spring Boot와 JPA는 부트캠프와 멘토링 범위로 적혀 있다. 과장하지 않고, 전이되는 설계 판단과 전환 계획을 구체적으로 말한다.
- **미디어 도메인은 경험이 없다.** HLS, DASH, CDN, 라이브 스트리밍은 개념과 판단 기준까지만 말하고, 운영해 본 것처럼 말하지 않는다.
- **새 팀이라는 점을 기회로 연결한다.** 공고는 새로 만들어지는 조직이고 정해진 것보다 정할 것이 많다고 적는다. 빈 영역에서 기준을 세우고 문서화한 경험(모듈 경계 설계, 팀 AI 협업 규약)을 이 맥락에 연결한다.
- **이직 사유는 확정됐다.** [[Interview-Prep-Tving-1st-FIT|FIT 문서]] F3은 [[My-Motivation-Reasons]] 현재 사이클 답변을 fork했다. 직전 사이클 답변을 현재 사유로 옮기지 않는다.

## 1. 핵심 요약

| 축 | 한 줄 |
| --- | --- |
| 회사 | 티빙 Technology 조직은 영상 스트리밍 기술을 바탕으로 다양한 디바이스의 시청 환경, 대규모 스트리밍 성능 개선과 글로벌 확장 가능한 아키텍처를 만든다고 소개한다. (채용 사이트) |
| 팀 | Media API Platform은 사용자가 콘텐츠를 실제로 소비하는 구간을 담당하는 새 조직이다. 라이브, 쇼츠, 뉴스 등 미디어 도메인 API, 재생 경로 라우팅, 시청 로그 도메인을 함께 맡는다. (JD) |
| 나의 연결 | 동시 요청 정합성(DB Lock), 이벤트 기반 비동기 처리(EventBridge, SQS), 조회 성능 개선, 인프라 전환(CloudFront, ELB, ECS), 관측과 경보(Grafana, Prometheus, Loki), 팀 AI 협업 규약 (이력서) |
| 메시지 | 실패와 재시도, 복구와 관측을 처음 설계에 넣고, 기준이 없는 영역에서 계약과 검증 경로를 먼저 세우는 백엔드 개발자 |

### 강점

1. 수천 대 IoT 하드웨어의 동시 요청에서 DB Lock으로 Race Condition을 해결하고 정합성을 지킨 경험. 순간 급증 요청의 정합성 문제와 같은 유형이다.
2. Kafka 도입 한계를 고려해 EventBridge와 SQS 기반 이벤트 아키텍처를 설계한 경험. 브로커를 비교해 선택한 근거를 말할 수 있다.
3. 단일 NGINX 서버에서 CloudFront, ELB, ECS(Fargate)로 전환하고 RDS Read Replica로 읽기 부하를 분산한 경험. 캐시와 전달 계층을 직접 구성해 봤다.
4. Grafana, Prometheus, Loki 기반 모니터링과 로깅, Grafana Alerting 경보를 구축한 경험. 시청 데이터 품질 모니터링과 장애 조기 탐지에 연결된다.
5. RDB 성능 최적화의 공개 성과. 복합 인덱스로 슬로우 쿼리 99.3% 개선, Prisma N개 쿼리를 단일 쿼리로 통합해 API 응답속도 90% 향상 (이력서 수치, 측정 조건을 설명할 수 있을 때만 말한다).
6. 팀 AI 협업 규약을 표준화하고 작업 종료 시 품질을 검증하는 회귀 루프를 만든 경험. 공고의 AI One team, AI 도구 활용과 맞닿는다.

### 갭

1. **Kotlin 실무 경험 없음, Java와 Spring 최근 실무 공백.** 필수요건이다. 전환 근거와 학습 계획을 구체적으로 준비한다.
2. **미디어 도메인 경험 없음.** HLS, DASH, CDN 운영, 멀티 CDN, 라이브 백엔드, EPG와 편성 모두 우대사항이며 직접 경험이 없다.
3. **Kafka 운영 경험 없음.** 선택 기준 비교까지만 했다. 파티션, 순서, 컨슈머 그룹, 재처리를 원리 수준으로 준비한다.
4. **대규모 로그 파이프라인과 스키마 버저닝 경험 없음.** 관측 로그 설계 경험을 전이하되, 분석용 이벤트 파이프라인은 확인할 항목으로 말한다.
5. **Kubernetes 운영 경험 없음.** ECS Fargate 운영까지만 말한다.
6. **트래픽 규모 경험의 경계.** 대규모 동시 시청 트래픽은 겪지 않았다. 규모를 부풀리지 않고 책임진 범위의 판단을 말한다.

## 2. 우선 준비 사항

1. 이직 사유, 짧은 재직, 현재 활동 답변(FIT F3, F4, F5)을 30초 안에 말하도록 연습한다. 이력서 PDF에는 키노라이츠가 이미 있고(2026-09-29 확인), 트라이포드랩 재직은 2024.02~2026.05다. 이력서의 키노라이츠 재직중 표기를 2026.06~2026.09로, 요약 문단의 현재 시제를 과거로 고쳐야 한다(실제 근무는 2026-09-15 종료). 이력서 원본 수정은 사용자 몫이다.
2. Kotlin, Java, Spring 전환 답변을 2분 안에 말한다. [[Interview-Prep-Tving-1st-Tech-JD|JD 기술]] J1, J2.
3. 재생 경로 라우팅 설계 답변 골격을 화이트보드로 그린다. [[Interview-Prep-Tving-1st-Service|서비스 맥락]] S1, S2.
4. 시청 로그 스키마, 버저닝, 데이터 계약 골격을 연습한다. [[Interview-Prep-Tving-1st-Service|서비스 맥락]] S4, S5, S6.
5. Kafka 기본(파티션과 순서, 오프셋 커밋, 재처리와 DLT)을 입에 붙인다. [[Interview-Prep-Tving-1st-Tech-JD|JD 기술]] J3, J4.
6. 이력서 수치(99.3%, 90%, 40%, 909MB에서 513MB, 3분 10초에서 2분 20초)의 측정 조건과 본인 기여 범위를 한 문장씩 준비한다.
7. 티빙 앱에서 라이브, 쇼츠, 뉴스 화면을 직접 써 보고 관찰한 사실 한 문장만 준비한다. 써 보지 않은 기능은 써 봤다고 말하지 않는다.

## 3. 역질문

[[My-Reverse-Questions]]에서 5개를 고르고 회사 특이 질문 2개를 더했다. 핵심 3개(1, 2, 6)는 외우고 나머지는 흐름에 맞춰 고른다.

1. **초기 과제와 성공 기준 (B1)**: 새로 만들어지는 팀에서 합류 후 가장 먼저 책임질 과제와, 잘하고 있다고 판단할 기준은 무엇인가요?
2. **기술 경계 (C1)**: Media API Platform이 직접 소유하는 서비스 경계는 어디이고, 콘텐츠 메타, 서비스 플랫폼, 추천과 지표 팀과는 어느 지점에서 맞닿나요?
3. **데이터 경계 (C2)**: 시청 로그의 정합성이 중요한 경계는 어디이고, 지금은 어떤 방식으로 검증하고 있나요?
4. **관측성과 품질 기준 (C3)**: 재생 실패나 버퍼링 같은 사용자 영향을 어떤 신호로 감지하고, 해결 뒤에는 어떤 재발 방지 과정을 거치나요?
5. **학습과 검증 (D2)**: Kotlin과 미디어 도메인처럼 제가 아직 깊이가 부족한 부분은 어떤 작은 과제로 검증하며 익히는 것이 가장 효과적일까요?
6. **회사 특이, 경로 결정의 입력**: 재생 경로를 고를 때 지역, 디바이스, 권리 조건 외에 CDN 품질 신호는 어떤 형태로 들어오고, 전환 판단은 서버와 플레이어 중 어디에 두고 있나요?
7. **회사 특이, 라이브 온콜**: 라이브는 되돌릴 시간이 없다고 적어 주셨는데, 큰 라이브 이벤트 전후의 준비와 장애 대응, 회복은 팀에서 어떻게 운영하나요? (E3 변형)

아껴둘 질문: 연봉 밴드(A3), 레거시 비중, Kubernetes 사용 범위는 2차 이후.
