## 1. 핵심 판단

**이 역할이 원하는 사람**: 외부 연동이 실패하고 중복되는 것을 일상으로 받아들이고, 기존 흐름을 이해한 뒤 조금씩 안전하게 고치며, 그 과정을 문서로 남기는 사람. 필요하면 관리자 화면도 손대는 넓은 범위의 백엔드 개발자다.

**강점**

- 업무 문장(연동 실패, 중복 처리, 재시도)이 기술 카드 1, 2와 그대로 겹친다. 동시성 잠금, 소비자 멱등성, DLQ와 수동 확인 경로를 실제로 다뤘다.
- 도메인이 이어진다. 시솔지주 국제 배송 서비스의 배송 정보 스크래핑, 환율 배치, 외부 API 연동과 트라이포드랩의 재고, 발주 자동화, 알림 리포트가 공고의 해외 구매처, 배송, 주문, 알림 자동화와 맞닿는다.
- 우대 사항 다수가 강 매칭이다: NestJS, Docker와 Jenkins, AWS와 온프레미스 이전, AI 생성 코드 검토.
- MySQL 쿼리 개선은 공개 수치(슬로우 쿼리 99.3%, 응답 90%, Read Replica 40%)로 설명할 수 있다.

**갭**

- React 화면 개발 실무가 없다. 자격 요건 중 유일한 약 항목이라 먼저 물어볼 가능성이 높다.
- Next.js, 브라우저 자동화(Puppeteer, Playwright), Azure 경험이 없다.
- 결제는 원칙과 환불 정책 조율 사례로 말할 수 있지만 PG 직접 연동 범위는 확인되지 않았다.
- 퇴사와 이직 사유, 짧은 재직 기간, 공백 답변은 동기 마스터의 현재 사이클 답변으로 확정했다(2026-09-29). 30초 안에 끝내고 해명을 덧붙이지 않는 것이 관건이다.

## 2. 면접 전략

- **연동 실패 이야기로 대화를 끌고 간다**: 자기소개 끝줄과 지원 동기 첫 이유를 공고의 연동 실패, 중복, 재시도에 맞췄다. 기술 꼬리는 R1, R2, J1~J3으로 받는다.
- **갭은 인정, 전이 근거, 학습 계획 순서로 짧게**: React는 없다고 먼저 말하고, API 계약 협업 경험과 입사 전 실습 계획으로 닫는다. 아는 척하지 않는다.
- **수치는 이력서 공개 값만**: 측정 대상을 한 문장으로 붙이고, 조건을 모르면 모른다고 말한다. 사이드 프로젝트는 존재와 정성적 결론만 말한다.
- **가정을 먼저 말한다**: 회사의 연동 대상과 구조는 미확인이다. 설계 질문에는 이렇게 가정하겠다고 먼저 밝힌다.
- **민감 질문은 확정된 문장만**: 즉흥으로 사유를 만들지 않는다. 외부 귀책 단어와 회사 평가를 쓰지 않는다.
- **역질문으로 역할을 확인한다**: 실무진 면접이 사실상 마지막 기술 확인일 수 있으므로 초기 과제와 성공 기준, 연동 실패 처리 현황, 화면 개발 비중을 묻는다.

## 3. 우선 준비 순서

1. FIT C1~C3 답변을 소리 내어 30초씩 말하기. 남은 `[사용자 확정 필요]` 슬롯은 계약직 수용 여부다.
2. J1~J4를 소리 내어 3분씩 말하기. 연동 실패 분류, 중복 방지, 재시도, 결제 불일치는 이 역할의 핵심이다.
3. J7 React 갭 답변과 기본 개념(props, state 스냅숏, key) 복습, 작은 관리자 화면 실습 시작.
4. R3, R4, R7 수치의 측정 대상 한 문장씩 준비. R6 번역 70%는 측정 기준을 확인하기 전에는 말하지 않는다.
5. 셀록홈즈 홈페이지 재확인, 가능하면 무료 체험.
6. 역질문 1~3번 암기.
