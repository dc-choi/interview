# 비단팝팝 1차 면접 — 회사 심화 조사

> 상위 TOC: [[Interview-Prep-Bdanpoppop|비단팝팝 1차 면접 준비]]

## 1. 공개 사실과 미확인 사항의 경계

이 문서는 2026-05의 면접 준비 기록이다. 제품 출시와 공개 기능, 토큰증권 제도 일정은 2026-08-27에 공개 출처로 다시 확인했다. 반면 실제 고용 주체, 법인 간 운영 관계, 합류 팀 규모, 내부 기술 구조, 투자와 실적은 이 문서에서 공식 근거를 충분히 확인하지 못했으므로 사실로 단정하지 않는다.

| 확인할 주제 | 확인 방법 |
| --- | --- |
| 실제 고용 주체와 합류 조직 | 공식 계약 문서와 채용 절차의 서면 안내 |
| 제품과 백엔드 역할의 연결 | 최신 공고, 공식 제품 안내와 면접의 역할 설명 |
| 기술 결정과 운영 책임 | 코드 리뷰, 배포, 장애 대응의 실제 경계에 관한 역질문 |
| 도메인 연동과 규제 적용 범위 | 최신 공식 공시와 법령, 필요한 인가의 공식 안내 |

## 2. 공개 제품 사실, 2026-08-27 확인

| 사실 | 공개 근거와 시점 |
|---|---|
| 팝팝 공식 출시일은 2025-09-25다. | 비단팝팝 공식 홈페이지 뉴스룸과 출시 보도 |
| 구매하거나 선물 받은 기프트카드를 다른 브랜드 카드로 교환하거나 재선물할 수 있다. | 2025-09-25 출시 보도 |
| 출시 시점 보도에는 33개 브랜드, 1,700여 종과 소액권을 모아 고액권으로 바꾸는 기능이 소개됐다. | 2025-09-25 디지틀조선일보와 동아일보 보도 |
| 2025-12-22 비단 팝팝 공개 시점 보도에는 40개 브랜드, 2,000여 종과 상품권 교환 기능이 소개됐다. | 2025-12-22 서울신문 보도 |

브랜드와 상품 수는 서로 다른 공개 시점의 스냅숏이다. 현재 수량이나 실제 백엔드 구조로 확대 해석하지 않는다. 공식 홈페이지는 팝팝을 상품 간 교환과 선물 흐름을 제공하는 플랫폼으로 소개하지만, 법인 간 기술 운영 관계나 특정 블록체인 구현을 확인해 주지는 않는다.

## 3. 당시 공고를 읽어 만든 서비스 가설

- 모바일 디지털 자산 또는 교환 흐름을 다룬다면, 동시 요청, 중복 처리, 외부 연동 실패와 사용자 상태 표시는 중요한 설계 질문이 된다.
- 공개 자료에 언급된 블록체인 또는 Web3 관련 표현은 실제 사용 기술이나 서비스 범위를 증명하지 않는다.
- 따라서 상품권, 소유권 이전, 거래 정산과 같은 표현은 면접 답변의 가정형 예시로만 사용하고, 실제 설계를 아는 것처럼 말하지 않는다.

## 4. 토큰증권 제도 스냅숏, 2026-08-27 확인

- 2023-02 금융위원회는 토큰증권 발행과 유통 규율체계 정비방안을 발표했다.
- 2026-01-15 전자증권법과 자본시장법 개정안이 국회 본회의를 통과했다.
- 2026-03-04 금융위원회는 토큰증권 협의체를 시작했고, 당시 공식 안내는 제도화 법 시행 예정일을 2027-02-04로 명시했다.
- 2026-05-15 협의체 회의에서는 발행, 유통, 인프라와 투자자 보호를 포함한 하위 제도 설계를 계속 논의했다.

이 일정은 토큰증권 제도 전체의 공개 상태다. 비단팝팝 서비스가 증권 발행, 유통이나 결제에서 어떤 역할을 하는지, 어떤 인가가 필요한지는 이 자료만으로 확인할 수 없다. 서비스별 적용 범위는 공식 공시와 인가 자료가 있을 때 별도로 판단한다.

## 5. 채용 공고를 읽는 원칙

- 공고에 적힌 역할, 책임, 요구 역량은 지원자가 준비할 근거로 사용한다.
- 비공개 연락이나 개별 대화에서 받은 평가, 채용 속도, 조직 계획은 외부 문서에 남기지 않는다.
- 문화 적합성은 문구만으로 단정하지 않고, 코드 리뷰, 기술 의사결정, 운영 책임, 피드백 방식에 관한 질문으로 검증한다.
- 평가 기준과 채용 절차는 공식 공개 안내 범위에서만 확인한다.

## 6. 도메인 학습 — 면접 전 최소한 알아둘 것

| 주제 | 학습 포인트 |
|------|-----------|
| **STO** | 증권을 분산원장 기반으로 발행하거나 관리하는 제도와 기술의 교차 영역이다. 현행 법령과 세부 요건을 공식 출처로 확인한다. |
| **RWA** | 실물 또는 외부 자산을 디지털 토큰으로 표현하는 구조다. 증권성, 공시와 투자자 보호는 별도로 검토한다. |
| **거래 중개와 정산** | 거래의 상태 전이, 기록, 취소와 복구가 분명해야 한다. 인가와 책임 범위는 서비스별로 다르다. |
| **디지털 교환 흐름** | 중복 요청, 만료, 외부 제공자 실패와 사용자 상태 표시를 설계 질문으로 준비한다. |
| **블록체인 연동 패턴** | RPC 호출, 이벤트 수신, 확정성, 재시도, nonce와 키 관리 같은 일반 패턴을 학습하되 실제 체인과 연동 방식은 확인 질문으로 둔다. |

## 7. 리스크, 체크 포인트

- 고용 조건과 보상은 개인별 협상 정보이므로 공개 문서에 수치나 추정을 남기지 않는다. 서면 조건을 받은 뒤 개인 기록에서 검토한다.
- 법인 관계, 사업 관계와 인가 상태는 최신 공식 공시, 공고와 법령으로 확인하고 면접 대화만으로 결론 내리지 않는다.
- 합류 팀의 규모와 책임 범위는 공개 공고와 면접의 공식 설명을 구분해 확인한다.
