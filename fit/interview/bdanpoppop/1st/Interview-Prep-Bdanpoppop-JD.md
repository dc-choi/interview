## 당시 면접의 준비 초점

- 동시성, 데이터 조회, 비동기 처리, 운영 관측성을 실제 사례로 설명한다.
- 자산 교환, 결제 또는 블록체인 연동은 실제 서비스 구조가 아니라 가정형 시스템 설계 질문으로 다룬다.
- 자동화와 AI 활용은 사람의 검토 경계, 검증 데이터, 실패와 롤백 경로까지 말할 수 있게 준비한다.

## 역할을 읽는 기준

| 확인할 영역 | 준비 방향 |
|---|---|
| API와 데이터 모델 | 동시성, 트랜잭션 경계, 실패 복구를 실제 사례로 설명한다. |
| 데이터 저장과 조회 | 실행계획, 인덱스, 측정 조건, 재측정 기준을 함께 설명한다. |
| 비동기 처리 | 멱등성, 재시도, DLQ, 상태 전이와 운영자 개입 경로를 준비한다. |
| 운영과 배포 | 관측성, 점진 배포, 장애 대응, 비용과 복잡성의 트레이드오프를 설명한다. |
| 도메인 우대 지식 | 모르는 영역은 아는 척하지 않고, 전이 가능한 패턴과 학습 계획을 제시한다. |

## 채용 측이 확인할 수 있는 본인 답변

| 질문 주제 | 답변 요약 |
| --- | --- |
| 반복 업무 자동화 | 핵심 상태 변경을 먼저 확정하고, 후속 처리만 비동기로 분리했다. 소비자는 멱등하게 만들고 최종 실패는 별도 확인 경로로 보냈다. |
| 안정적 운영 | 로그, 메트릭과 알림을 사용자 영향과 연결해 원인을 좁혔다. 내부 임계값이나 운영 수치는 공개하지 않는다. |
| ORM 관계 조회 | 관계 로딩을 N+1로 단정하지 않고 당시 버전, 설정과 생성 SQL을 확인해 다중 쿼리의 왕복 비용을 진단했다. 로딩 전략 변경 전후는 같은 조건에서 비교했고 내부 수치는 공개하지 않는다. |
| AI 활용 | 정확도가 불확실한 자동화는 검증 데이터와 사람의 최종 검토를 두고, 예외는 안전하게 되돌리는 흐름을 설계했다. |

## FIT 답변 구조

1. 공개 공고의 사용자 문제나 거래 흐름을 한 문장으로 요약한다.
2. 이전 경험 중 동시성, 비동기 처리, 운영 신뢰성처럼 구조가 같은 사례 하나를 고른다.
3. 문제, 선택, 대안, 검증, 한계 순으로 설명한다.
4. 미경험 도메인은 첫 기간에 학습하고 검증할 방법으로 마무리한다.

안녕하세요, 백엔드 개발자 [이름]입니다. 여러 요청이 데이터를 갱신하는 환경에서 정합성을 지키고, 반복 운영 흐름을 비동기로 분리하며, 관측과 실행계획을 바탕으로 병목을 개선해 왔습니다. 빠르게 구현하는 것보다 실패를 복구할 수 있는 구조를 설계하는 데 강점이 있습니다. 당시 공개 공고의 백엔드 역할에서도 이 판단 기준을 기여로 연결할 수 있다고 판단했습니다.
