## 공개 JD와 회사 분석

JD는 TikTok과 글로벌 크리에이터 등 외부 플랫폼 데이터를 연동하는 SaaS 제품 개발, 기획부터 배포까지의 참여, 성능과 반복 문제 해결, AI 도구의 적극 사용을 요구한다. 아래 회사/포지션 사실은 2026-10-01 확인한 [공개 JD](https://www.wanted.co.kr/wd/389639) 기준이다.

| 항목 | 확인된 내용과 한계 |
| --- | --- |
| 서비스와 도메인 | TikTok 기반 글로벌 소셜커머스, 외부 플랫폼 연동 SaaS |
| 회사 소개 | TikTok 코리아 공식 파트너, 북미 중심 글로벌 확장과 뉴욕 사무소를 회사가 설명한다. 독립적인 사업 성과 검증과 구분한다 |
| 사업 모델 | SaaS 개발은 명시돼 있으나 구독/거래 수수료 구성과 과금 단위는 미확인 |
| 사업 단계와 규모 | 투자 단계, 재무, 제품별 고객 규모, 개발팀 구성과 실제 트래픽 미확인 |
| 경력 | 공고 필터는 3~8년, 본문은 3년 이상 또는 그에 준하는 역량 |
| 절차 | 서류 → 1차 → 2차 → 처우 → 합격, 수습 3개월 |
| 근무와 마감 | 서울 강남구 테헤란로 151, 상시 채용. 근무 방식과 면접 형식 미확인 |

**역할 해석**: 외부 데이터를 안정적으로 받아 고객이 쓸 수 있는 결과로 연결하고, 반복 업무를 줄이는 백엔드가 핵심으로 보인다. 이는 JD에서 도출한 준비 가설이며 실제 첫 과제는 역질문으로 확인한다.

## 자기소개와 동기

### 1분 자기소개

> 안녕하세요, 백엔드 개발자 [이름]입니다. Node.js와 TypeScript로 서비스를 설계부터 운영까지 맡아 왔습니다. 트라이포드랩에서는 NestJS 기반 재고 관리 서비스에서 동시 갱신의 정합성을 DB 잠금과 짧은 트랜잭션으로 지키고, 후속 발주 흐름을 EventBridge와 SQS로 자동화했습니다. 느린 조회는 실행 계획과 실제 SQL을 확인해 개선했고, 로그와 메트릭을 연결해 운영 문제를 확인할 수 있게 했습니다. 최근 역할에서는 검색 API 전환과 외부 데이터 수집의 실패 처리도 다뤘습니다. 변경할 때는 사용자 영향, 실패와 복구 경계를 먼저 확인합니다. 올세일에서도 외부 데이터 연동과 비동기 처리를 고객이 신뢰할 수 있는 결과로 연결하는 데 기여하고 싶습니다.

### 지원 동기

> 공고에서 외부 플랫폼 데이터를 SaaS 제품으로 연결하고 기획부터 운영까지 참여한다는 점에 관심이 갔습니다. 저는 재고와 발주, 외부 정보 배치를 다루면서 정상 처리보다 실패와 재시도, 데이터가 오래됐을 때의 결과를 설계하는 것이 중요하다는 점을 배웠습니다. TikTok 도메인 경험은 없지만 TypeScript, NestJS와 큐 기반 운영 경험을 바탕으로 연동 실패와 반복 업무를 줄이는 데 기여할 수 있다고 생각합니다. 먼저 실제 고객 흐름과 첫 과제의 완료 기준을 맞추고, 작은 변경으로 결과를 검증하며 맡는 범위를 넓히고 싶습니다.

### 짧은 재직과 현재 이직 사유, 30초

> 올해 6월 말 합류해 검색과 데이터 수집을 맡았는데, 팀이 기대하는 일하는 방식과 제 방식의 차이를 수습 기간 안에 좁히지 못해 본채용으로 이어지지 않았습니다. 돌이켜 보면 완료 조건을 먼저 맞추지 않고 제 판단으로 진행했고, 검증 결과를 공유하는 것도 늦었습니다. 그 뒤로는 합류 초기에 기대하는 결과와 완료 기준부터 합의하고, 진행 상황을 근거와 함께 먼저 공유하는 것을 기본으로 삼고 있습니다.

2026-09-29 확정한 [[My-Motivation-Reasons]]를 fork했다. 근무는 9월 15일에 끝났다. 사업 활동을 먼저 소개하지 않지만 겸업/사업 여부를 직접 물으면 사실대로 답한다. 현재 활동은 지난 경험의 회고와 다음 역할 준비로 짧게 답하고 퇴사 해명을 이어 붙이지 않는다.

## 역질문, 공통 4개와 회사 특이 2개

1. 합류 후 가장 먼저 책임질 과제와 첫 90일에 잘하고 있다고 판단할 기준은 무엇인가요? (마스터 B1)
2. 새 구성원이 제품을 이해하고 첫 변경을 배포하기까지 어떤 검토와 피드백이 있나요? (D1)
3. 현재 팀은 어떤 역할로 구성돼 있고 이 포지션은 누구와 기술/제품 결정을 함께 하나요? (A4)
4. 오류, 지연, 적체 같은 신호로 사용자 영향을 어떻게 감지하고 해결 뒤 어떤 재발 방지를 하나요? (C3)
5. 공고에 SQS와 BullMQ가 함께 있는데 각각 어떤 작업을 맡으며 실패와 재처리의 책임은 어떻게 나누나요?
6. 외부 플랫폼 연동에서 지금 고객이 가장 불편해하는 것은 데이터 신선도, 권한 연결, 작업 실패 중 무엇이고 그 개선을 어떤 결과로 확인하나요?

우선 1, 5, 6을 고르고 답변에 따라 2~4를 보충한다. 투자/재무의 미확인은 역할 범위를 확인할 이유이며 부정적인 회사 평가의 근거가 아니다. 기준: [[My-Reverse-Questions]].
