# 비누커머스 2차 면접 회고

| 항목 | 내용 |

| 회사, 차수 | 비누커머스 2차 면접 |
| 참여 역할 | 인사담당자, 경영 역할, 대표 역할 |
| 일시와 형식 | 원기록에 별도 기록이 없어 미확인 |
| 결과 | 불합격, 고용 조건 협의 단계까지 진행 |

> 회사와 차수, 받은 질문과 내 답변은 보존한다. 제3자의 이름, 연락처, 원문 발화, 개인 처우 금액과 비공개 회사 정보는 기록하지 않는다.

## 진행 흐름, 실제 받은 질문과 답변 요약

### 자기소개와 커리어 검증

- **Q. 1분 자기소개와 초기 커리어 선택은?** 초기 프로젝트 중심 경험에서 제품 운영 경험을 찾게 된 이유와, 개발자로 다시 선택한 학습 과정을 설명했다.
- **Q. 이전 직장을 떠난 이유와 공백기는?** 당시에는 첫 경험을 역할 전망 부족으로, 다음 경험을 회사 종료라는 외부 상황으로 설명했다. 이직 사유가 외부 귀책으로 들릴 여지가 있었다.
- **Q. 학습 과정이 커리어 선택에 어떤 영향을 줬는가?** 동기부여를 다시 얻고 개발자로 계속 일하겠다고 결정한 과정을 답했다.

#### 당시 답변의 실제 흐름과 현재 교정

1. 첫 역할을 떠난 이유에는 SI 업무에서 장기 전망을 찾기 어려웠다고 답했다. 당시 생각을 보존하되, 현재는 외부 환경 평가보다 제품 운영 책임을 직접 맡고 싶었던 내 선택과 그 뒤의 행동을 먼저 설명한다.
2. 공백기에는 진로를 다시 고민했고 42서울 학습 과정에서 동기를 회복해 개발자로 계속 일하기로 결정했다고 답했다.
3. 다음 역할을 떠난 이유에는 회사가 종료됐다는 사실을 앞세웠다. 현재는 종료 사실을 짧게 두고, 이후 재무와 사업 단계, 역할 범위를 미리 확인하는 선택 기준을 만들었다는 배움으로 닫는다.
4. 당시 답변을 현재 모범답안으로 덮지 않는다. 외부 귀책으로 들릴 수 있었던 표현과 이를 고친 기준을 함께 남긴다.

### 지원 동기와 사업 임팩트

- **Q. 왜 이 서비스와 커머스 도메인인가?** 사용자로서의 경험과 만족, 물류 백엔드 경험을 앞단 B2C 커머스 관심으로 확장한 흐름을 설명했다.
- **Q. 기술이 사업에 준 영향은 무엇인가?** 처음에는 사용성 개선을 말했지만, 비용과 사업 영향까지 설명해 달라는 후속 질문을 받았다. 이후 클라우드 비용을 줄이고 운영 효율을 높인 경험으로 답했다.

- 당시 지원 동기는 서비스 사용자 경험에서 시작해, 물류의 뒷단을 다룬 경험을 소비자 앞단의 구매 경험으로 확장하고 싶다는 흐름이었다.
- 사업 임팩트 질문에는 처음 사용성 개선을 답했다. 경영 역할의 참여자는 매출이나 비용과의 연결을 더 설명해 달라는 요지로 재질문했고, 클라우드 비용과 운영 효율을 개선한 경험으로 바꿔 답했다.
- 현재 교정: 비공개 비용 수치는 남기지 않고 변경 전 문제, 기술적 선택, 비용 또는 운영 결과와 확인 방법의 인과 관계를 설명한다.

### 기술, 소통과 문화

- **Q. 성능을 개선한 사례는?** ORM 기반 조회 경로를 개선해 응답 성능을 크게 높인 사례를 설명했다.
- **Q. 비기술 직군에게 기술 스택을 설명해 달라.** 개념, 예시와 비유를 사용해 전달했다.
- **Q. 기획자와 프론트엔드 동료와 어떻게 소통하는가?** 기획 의도를 먼저 확인하고 이해를 재확인하며, 기술 용어를 풀어 설명하고 API 문서를 상세히 남긴다고 답했다.
- **Q. 회사 가치 중 무엇과 맞는가?** 객관적 판단을 선택하고, 비용 개선 사례를 근거로 들었다.
- **Q. 어릴 때 별명은 무엇이었는가?** 똥철과 동물철권이라고 답했고, 친근하고 유들유들하게 보이는 이미지와 연결해 설명했다.
- **Q. 스스로의 강점과 약점은?** 친근한 관계를 만드는 편이지만 T 성향이라 개발자 같다는 말을 듣고, 일부 사람은 어렵게 느낄 수 있다고 답했다. 당시에는 이를 인지하고 부드럽게 말하려 노력한다는 수준에 머물렀다. 다음에는 실제로 소통을 바꾼 사례까지 붙인다.

#### 기술과 문화 질문의 세부 기록

1. 이전 조직의 문화에는 직급 구분이 약하고 의견을 적극적으로 내는 수평적 환경이었다고 답했다.
2. 이상적인 회사에는 공동 목적을 가진 사람들이 소통으로 서로의 필요를 조정하는 조직이라고 답했다.
3. 기획자와 대화할 때는 요청의 의도를 먼저 묻고 내가 이해한 내용을 다시 확인한 뒤, 시스템이 가능한 범위를 기술 용어 없이 설명한다고 답했다.
4. 프론트엔드 동료에게는 API 문서를 상세히 제공하고 계약 변경을 명확히 공유한다고 답했다.
5. 회사가 제시한 여러 가치 중 객관적 판단을 골랐고, 비용 개선 사례를 근거로 연결했다.
6. 대표 역할의 참여자는 성능 개선 사례를 짧게 확인했다. 당시에는 Prisma 관계 조회 방식을 바꿔 응답 시간을 크게 줄인 경험을 답했다. 현재는 내부 전후 수치를 빼고 생성 SQL과 실행 계획, 지연 비교로 검증한 과정까지 설명한다.
7. 이어 기술 스택을 비기술 참여자에게 설명해 달라는 요청을 받았다. 개념을 나열하지 않고 역할, 예시와 비유를 사용했고 상대가 집중하는 반응을 확인했다.
8. 어린 시절 별명 질문에는 똥철과 동물철권이라고 답했다. 본인의 당시 답변이므로 삭제하지 않고, 친근하고 유연한 인상과 연결한 판단까지 보존한다.
9. 스스로 차갑게 보일 수 있다는 약점에는 인지는 솔직했지만 행동 변화의 증거가 약했다. 다음에는 상대의 이해를 재확인하고 표현을 바꿔 협업한 실제 사례로 닫는다.

### 향후 방향과 고용 조건

- **Q. 5년 뒤와 장기 커리어 목표는?** 개발 리드로 성장하고 장기적으로 CTO 역할을 목표로 한다고 답했다.
- 결과 일정과 인수인계 가능 시점을 물었다. 이후 고용 조건 협의 단계로 진행됐지만, 개인 처우 금액과 세부 복지는 이 회고에 남기지 않는다.

- 마무리에서 5년 뒤의 모습을 묻는 질문에는 당시 예상으로 8년차가 되어 개발 리드가 되고 싶다고 답했고, 장기 목표에는 CTO 역할을 말했다.
- 결과 안내 시점을 묻고 왜 궁금한지 확인받자, 합격하면 현재 역할의 인수인계를 조율해야 하기 때문이라고 답했다. 다음에는 조급함으로 들리지 않도록 다음 단계 안내 시점을 중립적으로 확인한다.
- 대표와 경영 역할 참여자가 나간 뒤 인사담당자와 고용 조건을 논의했다. 조건 협의까지 진행된 사실은 보존하되 개인 처우 금액, 세부 복지와 제3자 발화는 남기지 않는다.

## 잘 작동한 답변

1. 물류 백엔드 경험을 B2C 커머스 관심으로 연결한 지원 동기.
2. 기술 선택을 비용과 운영 효율이라는 사업 임팩트로 설명한 사례.
3. ORM 기반 성능 개선 경험.
4. 비기술 직군도 이해할 수 있게 기술을 비유로 설명한 방식.
5. 기획과 프론트엔드에 맞춘 구체적인 소통 방식.

## 보완할 점과 탈락 가설

불합격 통보만으로 원인을 확정할 수 없다. 아래는 다음 면접에서 통제할 수 있는 개선 항목이다.

1. 이직 사유는 외부 상황보다 내 판단, 배운 점과 다음 선택 기준을 먼저 말한다.
2. 소통 방식의 약점은 인식만 말하지 말고, 경청과 표현을 바꾼 실제 사례를 붙인다.
3. 결과 일정은 조급함으로 들리지 않게 다음 단계 안내 시점만 중립적으로 묻는다.
4. 조건 협의 단계에서는 금액을 공개 기록에 남기지 않고, 본인이 중요하게 보는 근무 조건과 우선순위를 미리 정리한다.

## 이후 지원 시 원칙

- 같은 기업군이나 비슷한 역할에 다시 지원할 때는 평가 정보 공유를 추측하지 않고, 당시 지원서와 현재 공고, 공개된 역할 요구를 새로 비교한다.
- 이직 사유, 소통 약점과 책임 범위에 관한 답변은 자기 책임, 학습과 현재 적용 구조로 다시 준비한다.
- 경력 연차보다 실제로 맡은 책임, 기술 결정, 운영 경험을 사례로 보여 준다.

## 당시 감정 기록

- 면접 직후 감정은 원기록에 별도로 남아 있지 않아 추정하지 않는다. 고용 조건 협의 단계까지 진행한 뒤 불합격했다는 사실과 당시 판단만 보존한다.

## 당시 결정

- 이 면접은 지원 동기, 기술 사례와 전달력은 잘 작동했지만, 이직 사유와 소통 약점의 마무리는 더 보완해야 한다는 기록으로 남긴다.
- 비누랩스 재지원은 당시 보류했다. 공개 공고의 5년 이상 요건과 현재 책임 범위를 다시 비교하고, 이직 사유와 소통 약점 답변을 실제 행동 변화로 보완한 뒤 재검토한다.
- 계열사 평가 정보 공유 가능성은 확인되지 않았으므로 판단 근거로 쓰지 않는다.
