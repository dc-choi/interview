## 0. 이 공고가 보는 사람

공고 소개문이 직접 적은 문제는 세 가지다. 서비스 사이의 책임과 상태 소유, 같은 요청이 두 번 들어왔을 때의 판단 기준, 그리고 에이전트에게 반복 작업을 맡기되 결과를 어디까지 믿고 어떻게 되돌릴지다. 자격요건 첫 줄은 기술이 아니라 담당 밖 동료의 문제를 끝까지 같이 푸는 태도다.

**페르소나**: Kotlin/Spring 마이크로서비스를 운영하면서 PHP 레거시를 도메인 경계 단위로 옮기고, 서비스 경계에서 생긴 장애를 데이터, 인프라, 배포까지 따라가 해결하며, 한 번 푼 문제를 skill과 workflow로 남겨 팀이 재사용하게 만드는 엔지니어.

## 1. 핵심 전략

1. **메인 서사는 경계와 정합성**: 동시 갱신 잠금, 이벤트 기반 발주 자동화, 멱등 소비, 조회 병목을 서비스 경계와 상태 소유 문제로 다시 말한다. 이 공고의 소개문이 묻는 질문과 가장 직접 겹친다.
2. **AI 위임과 검증 책임**: 이력서의 팀 AI 협업 규약(영역 명문화, 종료 시 자기 검증 회귀 루프)을 공고의 skill, workflow, 검증과 롤백 설계 요구에 그대로 연결한다. 이 축은 강점이다.
3. **Kotlin 갭은 먼저 인정**: Kotlin 실무는 없고 Java/Spring 실무는 2020년 공공 프로젝트와 교육, 멘토링 범위다. 숨기지 않고, 트랜잭션, 프록시, ORM이 만든 SQL을 검증해 온 방식이 JVM으로 전이되는 근거와 온보딩 계획을 함께 말한다.
4. **전환 경험을 무중단 전환 언어로**: JSP/JDBC에서 Spring/MyBatis로의 이전, MongoDB에서 MySQL로의 데이터 이관, 단일 NGINX에서 CloudFront, ELB, ECS로의 인프라 전환을 공고의 도메인 경계 설계, 데이터 이관, 무중단 전환에 매핑한다. 세부 이관 방식은 기억으로 채우지 않는다.
5. **동료 문제에 들어간 사례**: 외부 오픈소스의 명세 불일치를 재현과 명세 대조로 끝까지 추적해 이슈로 올린 경험, 멘토링과 코드 리뷰 문화를 담당 밖 문제 해결 시그널로 쓴다.

## 3. 사용자 확정이 필요한 슬롯

- **현재 역할과 이직 사유 (확정, 2026-09-29)**: 퇴사 사유, 짧은 재직, 공백 답변은 [[My-Motivation-Reasons]] 현재 사이클 정본을 fork해 [[Interview-Prep-Kmong-1st-FIT|FIT 문서]] 자기소개, C4, C5, C6에 반영했다. 자기소개 첫 문장에 현재 소속은 넣지 않고, 개인 사업은 먼저 밝히지 않으며 직접 물으면 사실대로 답한다.
- **이력서 표기 (확정)**: 트라이포드랩 재직은 2024.02~2026.05다. 이력서 PDF에는 키노라이츠가 이미 있으나 "2026.06 - 재직중 (4개월)"이고 요약 문단이 "현재는"으로 시작한다. 실제 근무는 2026-09-15에 끝났으므로 표기를 2026.06~2026.09로, 요약 문단을 과거 시제로 고친다(원본 수정은 사용자 몫). 정정 전에는 면접에서 9월 중순에 마쳤다고 먼저 밝힌다.
- **이력서 원본 이동 권고**: 개발 지식 온톨로지와 컨텍스트 검색 MCP 프로젝트는 이력서에서 키노라이츠 경력 아래에 있지만 개인 프로젝트다(사용자 확인). 이력서를 개인 프로젝트 항목으로 옮기고(원본 수정은 사용자 몫), 정정 전에는 면접에서 먼저 개인 프로젝트라고 밝힌다.
- **이력서 145건 문구 정정 필요**: 이력서의 골든 케이스 약 145건 문구는 부정확하다(145건 세트 없음, 실제는 74개와 94개 질문). 원본 수정은 사용자 몫이고, 정정 전에는 면접에서 R9 정정 문장으로 먼저 바로잡는다.
- **경력 연차**: 이력서 기간을 합산하면 5년에 미달할 수 있다. 공고의 5년 이상 기준에 대한 답은 사용자가 산정 기준을 확인한 뒤 확정한다.
- **크몽 사용 경험**: 구매자나 판매자로 써 본 적이 있는지 확인되지 않았다. 없으면 면접 전 공개 화면을 직접 둘러보고 관찰한 사실만 말한다.
