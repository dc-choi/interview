# 더블유클럽 1차, 과제 대비와 체크리스트

> 상위 문서: [[Interview-Prep-WClub-1st|더블유클럽 1차 준비]]. 과제 내용은 공고에 공개된 요약만 적는다. 실제 과제를 받은 뒤 과제 원문, 코드, 저장소 경로와 평가 피드백 원문은 이 저장소에 남기지 않는다.

## 공개된 과제 형식

- 3일 유료 과제: AI가 만든 샘플 저장소를 받아 문제를 찾고 백엔드까지 보완해 배포 가능한 상태로 만든다. 과제비가 지급되며 실제 회원 데이터는 쓰지 않는다고 안내된다.
- 2시간 라이브 과제: 요구사항을 받아 AI로 구현하고 검수, 수정, 배포 판단까지 함께 진행한다.

## 3일 과제 작업 순서

| 시점 | 할 일 | 남길 산출물 |
|---|---|---|
| 1일차 오전 | 실행과 테스트가 되는지 확인하고 요구사항과 가정을 정리 | 가정 목록, 실행 방법 |
| 1일차 | 위험 순서로 전수 점검: 인가, 입력 검증, 트랜잭션과 동시성, 멱등성, 비밀 노출, 응답 과다, 마이그레이션 | 발견 목록(심각도, 재현 방법, 영향) |
| 2일차 | 심각도 높은 순서로 수정. 수정마다 실패하던 테스트를 먼저 추가 | 결함별 테스트와 수정 커밋 |
| 3일차 오전 | 배포 가능성 점검: 환경 변수 분리, 마이그레이션 순서, 헬스체크, 로그와 오류 응답 형식 | 배포 절차와 롤백 방법 |
| 3일차 오후 | 남은 위험과 하지 않은 것을 명시 | README 또는 리포트 |

- 원칙: 모든 결함을 고치려 하지 않는다. 심각도 판단 기준과 고치지 않은 이유를 쓰는 것이 판단력을 보여준다.
- AI 활용: 탐색과 반복 수정은 맡기되, 발견 목록의 우선순위와 수정 채택은 직접 결정하고 그 근거를 커밋 메시지나 리포트에 남긴다.
- 커밋은 결함 하나에 하나씩 작게 나눠 리뷰 가능한 형태로 남긴다.

## 2시간 라이브 과제 진행

| 구간 | 시간 | 할 일 |
|---|---|---|
| 요구 명확화 | 10분 | 모호한 단어를 되묻고, 답이 없으면 가정을 말하고 적는다 |
| 설계와 지시 | 15분 | 데이터 모델, API, 실패 경로를 먼저 정하고 AI에게 작업 단위로 지시 |
| 구현과 검수 | 70분 | AI 결과를 인가, 트랜잭션, 입력 검증 순서로 읽고 고친다. 생각을 말로 출력한다 |
| 배포 판단 | 15분 | 배포해도 되는지, 무엇을 막아야 하는지, 롤백 경로는 무엇인지 말한다 |
| 회고 | 10분 | 남은 위험과 실서비스라면 추가할 것 |

- 탈락 신호: 요구를 확인하지 않고 바로 생성시키기, AI 결과를 읽지 않고 붙이기, 침묵.
- 막히면 두 가지 선택지를 말로 비교하고 면접관과 대화로 전환한다.

- [ ] 공개 가능한 서비스, GitHub, PR 링크를 확보했다. 전, 현 직장 비공개 저장소는 링크하지 않는다.
- [ ] 장애 해결 경험 1가지를 원인, 대응, 재발 방지로 정리했다.
- [ ] 출석부 관련 서술에는 정확한 사용 수치를 넣지 않았다.
- [ ] 이력서의 키노라이츠 재직중 표기를 2026.06~2026.09로, 요약 문단의 현재 시제를 과거로 고쳤다(트라이포드랩은 2024.02~2026.05, 원본 수정은 사용자 몫).

## 강하게 어필할 포인트

- 동시성 정합성, 비동기 실패 경로, 관측과 배포 전환을 설계부터 운영까지 맡은 경험
- 명세를 대조해 오픈소스 결함을 찾은 FIDO 경험. AI 결과물 검수와 같은 태도로 연결한다.
- AI 협업 규약과 자기 검증 루프. 규칙을 강제 층으로 내리는 기준을 함께 말한다.
