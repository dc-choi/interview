## 0. 1차 전략

- **포지션의 성격부터 맞춘다.** 공고는 이 자리를 관리만 하는 리더가 아닌 Hands-on 시니어로 설명한다. 아키텍처 방향 제시와 직접 구현을 한 흐름으로 말한다. 리드 경험은 공식 팀장 경력으로 부풀리지 않고, 설계 결정, 규약 표준화, 코드 리뷰와 멘토링이라는 실제 범위로 말한다.
- **가장 강한 연결은 기기 데이터와 운영이다.** 트라이포드랩에서 IoT 하드웨어 입력의 동시 갱신 정합성, 이벤트 기반 자동화, 기기 상태 리포트, 관측 체계를 다뤘다. OUTBODY가 현장 측정 결과를 서비스 데이터로 이어간다는 공개 설명과 문제 유형이 겹친다. 단, 피트릭스의 측정 기기와 서버 연동 방식은 공개되지 않았으므로 추정하지 않고 질문으로 확인한다.
- **갭은 인정, 전이, 확인의 3단으로 답한다.** Azure, Koa, FastAPI, Kubernetes는 직접 운영 경험이 없다. AWS와 Express, ECS에서 판단한 기준을 옮기고, 실제 구성은 입사 후 무엇부터 확인할지로 닫는다.
- **이직 사유는 현재 사이클 확정 답변을 쓴다.** 퇴사 사유, 짧은 재직, 현재 활동 질문은 반드시 나올 수 있다. [[Interview-Prep-Fitrix-1st-FIT|FIT 문서]]의 F3, F4, F5는 [[My-Motivation-Reasons]]의 현재 이직 사이클(2026-09-29 확정)을 fork했다. 과거 사이클 답변을 그대로 말하지 않는다.
- **경력 연수 질문에 대비한다.** 필수요건이 5년 이상인데, 이력서 재직 기간만 합산하면 5년에 못 미치게 읽힐 수 있다. 산정 기준을 사용자가 확정하고, 연수보다 책임 범위와 결과로 답을 준비한다.

## 1. 핵심 요약

| 축 | 한 줄 |
| --- | --- |
| 회사 | 현대자동차 사내벤처에서 2020년 스핀오프한 디지털 헬스케어 기업. 신체정보 기반 헬스케어 플랫폼 OUTBODY를 만든다. (JD) |
| 역할 | Node.js 백엔드와 API 설계와 개발, OUTBODY 서비스와 신체 데이터 DB 설계와 최적화, Azure 인프라, 기술 방향과 코드 리뷰 주도, 장애 분석, 로깅과 모니터링, CI/CD, AI 개발 도구 활용 (JD) |
| 나의 연결 | Node.js(Express, NestJS) 상용 서비스 설계와 운영, IoT 입력 정합성, 이벤트 기반 자동화, MySQL 성능 개선, Grafana, Prometheus, Loki 관측 구축, 팀 AI 협업 규약 (이력서) |
| 메시지 | 실패와 재시도, 복구와 관측을 처음 설계에 넣고, 방향을 제시하는 데 그치지 않고 직접 코드와 검증으로 닫는 개발자 |

### 강점

1. Node.js 상용 서비스의 설계부터 운영까지 직접 책임진 경험. Express(시솔지주)와 NestJS(트라이포드랩).
2. IoT 기기 입력의 동시성 정합성과 기기 상태 집계 리포트. 신체 측정 데이터를 다루는 서비스와 문제 유형이 가깝다.
3. MySQL 설계와 튜닝의 공개 성과. 복합 인덱스로 슬로우 쿼리 99.3% 개선, Prisma N개 쿼리를 단일 쿼리로 통합해 API 응답속도 90% 향상, Read Replica로 응답속도 40% 개선 (이력서 수치, 측정 조건을 설명할 수 있을 때만 말한다).
4. 로깅과 모니터링 인프라를 직접 구축하고 경보 정책을 세운 경험. JD 주요업무와 우대사항에 모두 있다.
5. 단일 NGINX 서버에서 CloudFront, ELB, ECS(Fargate)로 전환한 초기 구축부터 확장 단계 경험.
6. AI 도구를 개인 생산성이 아니라 팀 규약과 회귀 검증 루프로 표준화한 경험. 생성 코드의 품질 판단 책임을 설명할 수 있다.

### 갭

1. **Azure 직접 운영 경험 없음.** AWS 경험을 서비스 대응 관계와 판단 기준으로 전이한다.
2. **Koa, FastAPI 실무 경험 없음.** Koa는 Express와 같은 Node.js 미들웨어 모델의 차이로 설명 가능하다. Python과 FastAPI는 이력서에 없다.
3. **Kubernetes 운영 경험 없음(우대).** ECS Fargate 운영 경험까지만 말한다.
4. **공식 팀 리드 경력 없음.** 기술 방향 주도와 코드 리뷰 주도 기대에 대해 실제로 한 범위를 정확히 말해야 한다.
5. **경력 연수 경계.** 5년 이상 요건 대비 산정 기준 확정 필요.
6. **헬스케어 도메인과 규제 경험 없음.** 개인정보와 건강 관련 정보의 보호 원칙은 설명하되 법적 판단은 단정하지 않는다.

## 2. 우선 준비 사항

1. 현재 이직 사유, 키노라이츠 짧은 재직, 현재 활동 답변은 확정됐다(FIT 문서 F3, F4, F5). 면접 전에 소리 내어 30초 안에 말하는지 연습한다.
2. 트라이포드랩 재직은 2024.02~2026.05로 확정됐다. 이력서 PDF의 키노라이츠는 "2026.06 - 재직중 (4개월)"이고 요약 문단이 현재 시제이므로, 2026.06~2026.09로 표기하고 요약을 과거 시제로 고친다(원본 수정은 사용자 몫). 경력 연수 산정 기준은 아직 남았다.
3. 이력서 수치 5개(99.3%, 90%, 40%, 909MB에서 513MB, 3분 10초에서 2분 20초)의 측정 조건과 본인 기여 범위를 한 문장씩 준비한다.
4. Azure 대응 표와 Koa 미들웨어 차이를 입에 붙인다. [[Interview-Prep-Fitrix-1st-Tech-JD|JD 기술 질문]] J1, J2.
5. 신체 측정 데이터 모델링 답변 골격을 연습한다. [[Interview-Prep-Fitrix-1st-Service|서비스 맥락]] S1.
6. 코드 리뷰 주도 방식과 개발 기준 수립을 경험 기반으로 2분 안에 말한다. [[Interview-Prep-Fitrix-1st-FIT|FIT]] F6.

## 3. 역질문

[[My-Reverse-Questions]]에서 5개를 고르고 회사 특이 질문 2개를 더했다. 1차에서는 핵심 3개를 외우고 나머지는 흐름에 맞춰 고른다.

1. **초기 과제와 성공 기준 (B1)**: 합류 후 가장 먼저 책임질 과제와, 잘하고 있다고 판단할 기준은 무엇인가요?
2. **팀 구성과 협업 경계 (A4)**: 현재 백엔드와 인접 직군은 어떤 역할로 구성돼 있고, 이 포지션은 누구와 어떤 결정을 함께 하나요?
3. **기술 결정 방식 (B2)**: 아키텍처 변경이나 도구 도입은 어떤 근거와 문서로 결정하고, 반대 의견은 어떻게 다루나요?
4. **관측성과 품질 기준 (C3)**: 사용자 영향이 있는 장애를 어떤 신호로 감지하고, 해결 뒤에는 어떤 재발 방지 과정을 거치나요?
5. **사용자 문제와 우선순위 (A1)**: 이 역할이 가장 먼저 해결해야 할 사용자 문제는 무엇이고, 지금 우선순위가 높은 이유는 무엇인가요?
6. **회사 특이, 데이터 흐름과 서비스 경계**: 현장에서 측정한 결과가 서버와 STUDIO, MOBILE까지 이어지는 흐름에서 Node.js 서버와 공고에 있는 FastAPI가 각각 어떤 역할을 맡고 있나요?
7. **회사 특이, 해외 확장과 인프라**: 해외 서비스가 늘어날 때 데이터 저장 위치, 리전, 개인정보 요구사항은 어떤 기준으로 나누고 있고, Azure를 선택한 배경은 무엇인가요?

아껴둘 질문: 레거시 영역과 개선 우선순위, Kubernetes 사용 여부, 온콜 방식(E3), 연봉 밴드(A3)는 2차 이후.
