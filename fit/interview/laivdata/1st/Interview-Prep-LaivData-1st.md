## 4. 핵심 전략

1. **메인 서사**: 고객사 PoC 요구가 자주 바뀌는 환경에서 도메인별 모듈 경계를 세워 변경을 흡수하고, 운영 안정성(동시성, 이벤트, 관측)까지 책임진 백엔드 경험. 공고의 PoC와 플랫폼 공통 역량 추상화에 가장 직접 연결된다.
2. **AI는 도구 경험과 제품 경험을 분리**: 팀 AI 협업 규약과 회귀 루프는 강점이지만 LLM Agent 서비스 구현은 없다고 먼저 밝힌 뒤, 결정론 검증, 실패 분류, 멱등성 같은 백엔드 원리가 Agent 품질과 운영에 어떻게 옮겨지는지로 답한다.
3. **실패 유형 분류의 언어를 맞춘다**: 공고의 환각, 오답, 도구 실패, 권한 오류 분류는 외부 연동의 영구 오류와 일시 오류 분리, DLQ, 멱등성 경험과 같은 사고다.
4. **풀스택 갭은 정면으로**: React와 FastAPI는 없다고 말하고, 첫 과제 범위와 학습 순서를 역질문으로 확인한다.
5. **역할의 실제 모양 확인**: 개발, 기획, eval이 섞인 공고이므로 실제 비중과 성공 기준을 반드시 묻는다.

## 5. 강점, 갭, 우선 준비

**강점**

- 고객사 PoC를 위한 모듈 중심 아키텍처와 잦은 요구 변경 수용(이력서 공개 항목)
- 운영 안정성 축: DB 잠금 기반 동시성, EventBridge와 SQS 이벤트 처리, 실행 계획 기반 성능 개선, Grafana, Prometheus, Loki 관측
- 에이전틱 코딩을 팀 규약과 자동 검증 루프로 만든 경험, 명세 대조와 오픈소스 이슈 제기로 보인 검증 습관

**갭**

- LLM Agent 제품 개발, Multi-Agent 오케스트레이션, eval 파이프라인 실무 없음. 다만 개인 프로젝트(개발 지식 온톨로지, 평가 질문 74개와 94개로 검색 방식과 리랭커 비교)를 품질 평가 근거로 쓴다(Resume QA R9)
- React, FastAPI, Python 실무 없음
- Kubernetes 운영 없음, 금융 도메인 없음
- 원티드 경력 필터(6~13년)와 이력서 연차의 차이, 기획 산출물(PRD, KPI) 작성 경험의 깊이

**우선 준비 (면접 일정이 잡히기 전 순서)**

1. 확정된 이직 사유 답변을 30초 안에 말하고 트라이포드랩 경험으로 넘어가는 연습, 제출 이력서의 키노라이츠 재직중 표기와 현재 시제 수정(사용자 몫): [[Interview-Prep-LaivData-1st-FIT#3. 이직 사유와 현재 상태|FIT 3절]]
2. Agent 실패 유형과 멱등성 연결 답변, eval 게이트 설계 답변 암기가 아닌 흐름 연습: [[Interview-Prep-LaivData-1st-JD-QA|JD QA]] J2, J3
