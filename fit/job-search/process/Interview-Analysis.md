# 면접 탈락 원인 분석

> 2025년 초부터 2026-06-29 입사 전까지 진행한 이직 사이클의 완료된 회고다. 회사, 차수, 날짜, 결과, 받은 질문과 본인 답변의 요약은 보존한다. 제3자는 역할로만 적고 연락처, 개인 처우 금액, 비공개 회사 정보와 제3자 발화 원문은 기록하지 않는다.
> 현재 지원 계획이나 다음 이직 판단에 그대로 쓰지 않는다. 현재 업무와 학습 우선순위는 [[Current-Goals-and-Roadmap]]을 따른다.

## 분석 범위

- 최초 분석: 2026-04-10
- 기록 범위: 2025년 초부터 2026-06
- 최초 분석 스냅샷의 1차 면접: 통과 9, 탈락 12, 포기 5, 포기 제외 통과율 약 43%. 당시 분석 문서에는 통과 10, 약 45%로 적었으나 트래커 재집계 결과 9가 맞다.
- 종료 시점 트래커의 1차 면접: 통과 11, 탈락 15, 포기 5, 회사 사정 취소 1, 다른 선택으로 종료 1. 포기, 취소와 종료를 제외한 통과율은 약 42%다.
- 최초 분석 스냅샷의 2차 면접: 6전 0승 6패. 종료 시점 트래커에는 키노라이츠 통과와 액션파워 탈락이 추가돼 통과 1, 탈락 7이다.
- 당시 `준비 부족`으로 분류한 사례: 5건

통과율과 원인 분류는 당시 본인 기록에 따른 회고이며 회사의 공식 평가가 아니다. 피드백을 받지 못한 원인은 `미확인` 또는 가설로 둔다.

### 당시 해석

- 포기 5건은 스마일드래곤, 군돌이, 구름, 코액터스, 테이텀시큐리티였다.
- 당시 집계한 전체 서류 통과율은 약 9%였지만, 2024년 말의 이력서 개선 전 지원이 섞여 있어 이후 사이클의 실력을 그대로 나타내지 않는다고 판단했다.
- 최초 분석 당시에는 포기 제외 1차 통과율을 약 45%로 집계했고(트래커 재집계 시 약 43%), 준비한 면접의 결과를 근거로 면접 실력 자체가 전반적인 문제는 아니라고 봤다.
- 공식 피드백이 없는 회사의 탈락 원인을 경쟁률, 기술 격차나 문화 적합성 하나로 단정할 수 없다.

### 비누커머스 2차 기록

- 형식: 컬처핏과 임원 면접
- 참석 역할: 경영진, 경영 지원 역할, 채용담당자
- 받은 질문 요약: 퇴사 사유, 공백기, 지원 동기, 사업적 영향, 조직문화, 소통 방식, 커리어 목표
- 기술 질문 요약: 성능 개선 경험, 비개발자에게 기술을 설명한 경험
- 본인 답변 요약: ORM 쿼리 구조를 개선해 API 응답을 줄인 경험과 상대의 배경에 맞춰 기술 용어를 바꾼 경험을 설명했다.
- 결과: 처우 협의 단계까지 진행했으나 최종 탈락
- 해석: 공식 탈락 사유를 받지 않았으므로 컬처핏이나 인상 때문이라고 단정하지 않는다.

## 당시 종합 결론

### 준비 부족으로 분류한 5건

| 단계 | 기업 | 본인 평가 |
| --- | --- | --- |
| 1차 | 두핸즈 | 기술 면접 준비 부족 |
| 1차 | 패러다임시프트 | 기술 면접 준비 부족 |
| 1차 | 알파코드 | 면접 준비 부족 |
| 2차 | 모니모니 | 준비 부족 |
| 2차 | 호패 | 추가 기술 검증 준비 부족 |

당시 기록에서 가장 직접 바꿀 수 있는 공통점은 기회마다 준비 강도가 달랐다는 점이었다. 다만 결과가 적은 표본과 공식 피드백이 없는 사례가 많으므로 면접 실력이나 특정 약점을 확정하는 통계로 쓰지 않는다.

### 당시 근본 원인 가설

1. 면접 기회 자체가 적어 한 번의 통제 밖 변수에 결과가 크게 흔들렸다.
2. 적은 모수 안에서 면접 진행 문제와 적합도 불일치의 영향이 커졌다.
3. 2차 면접의 구조적 약점으로 확정하기보다, 준비 강도를 일정하게 유지하며 표본을 더 확보해야 한다고 판단했다.

### 당시 액션 플랜

> 종료된 이직 사이클의 실행안이며 현재 적용하지 않는다.

1. 진행 중인 기업 5곳 이상을 유지해 한 번의 결과에 과도하게 흔들리지 않는다.
2. 면접마다 JD, 이력서, 기술과 서비스 맥락을 사전에 점검한다.
3. 사전 안내 없이 나오는 코딩 과제에도 대응할 수 있도록 기본 연습을 유지한다.
4. 개선된 이력서를 기준으로 JD 맞춤 지원을 이어간다.

## 라이브 코딩 패턴 회고

> 2026-05-12에 추가한 관찰이다. 회사의 평가가 아니라 본인의 진행 방식과 답변에 대한 회고다.

### 히로인스

- 전형: 커피챗, 라이브 코딩, 컬처핏 순서
- 과제 요약: 데이터가 적은 초기 사용자를 위한 추천 피드를 설계하고 구현하는 문제
- 본인 행동: 초기 사용자, 관계 데이터, 유사 주제, 추천 개수와 정렬 기준을 정의하지 않은 채 구현을 시작했다.
- 놓친 점: 콜드 스타트 문제를 언급하지 않았고 대안을 비교하기 전에 한 접근으로 들어갔다. 막힌 뒤 사고 과정을 충분히 설명하지 못했다.
- 결과와 판단: 탈락, 문제 정의와 진행 설명 프로세스는 통제 가능한 개선점으로 분류했다.
- 당시 개선안: [[Live-Coding-Process|5단계 프로세스]]를 문제 명확화 5분, 제약 정리 5분, 접근 비교 5분, 구현 40분, 개선안 설명 5분으로 연습한다.

### 두핸즈

- 전형: 1차 기술 면접, 분산 락 심층 질문 포함
- 본인 답변: 포트폴리오의 분산 락 선택과 적용은 비교적 잘 설명했다고 평가했다.
- 결과: 탈락
- 당시 가설: MSA와 Kubernetes 실무 경험의 간극, 다뤄본 규모의 차이, 경쟁자 우위, 회사가 강조한 근본 탐구 방식과 답변의 연결 부족 순으로 가능성을 검토했다.
- 불확실성: 공식 피드백이 없어 경험 격차, 경쟁자와 문화 적합성 가운데 어느 요인이 실제로 작용했는지 확인할 수 없다.
- 당시 개선안: NestJS MSA와 Kubernetes 기초를 2개월 목표로 보강하고, MSA 전환 중인 회사를 학습 환경으로 우선 검토하며 답변을 `문제 정의, 원인, 선택, 결과, 한계` 순서로 재배치한다.

### 세 면접에서 남긴 패턴

- 와이즐리와 호패에서는 예상보다 즉각적인 코딩 또는 추가 기술 대응이 필요했고, 히로인스에서는 라이브 코딩 전형을 경험했다.
- 알고리즘 외에도 요구사항이 모호한 실무형 문제가 있었고, 구현 전에 질문과 제약을 말로 확정하는 습관이 부족했다.
- 당시 대응안은 [[System-Design-Practice-Topics|연습 주제 카탈로그]] 15개를 3주 안에 한 번씩, 60분 제한으로 말하면서 풀고 매회 자기 회고를 남기는 것이었다.

## 재사용 규칙

- 회사와 결과 이력은 과거 사실로 보존한다.
- 받은 질문과 본인 답변은 요약하고, 제3자의 표현은 원문으로 옮기지 않는다.
- 공식 피드백이 없는 탈락 원인은 가설로 표시한다.
- 현재 목표나 다음 이직 전략은 이 문서가 아니라 [[Current-Goals-and-Roadmap]]에서 결정한다.
