# 코딩테스트 준비 전략

## 기본 원칙

- 지원하는 회사의 언어로 시험을 치르는 것이 유리 (가이드라인 확인)
- 주요 평가: 구현 능력, 문제 해결 능력, 기본적인 CS/알고리즘 평가
- 기술 면접을 위한 첫 관문 — 채용의 허들로 제일 많은 지원자들이 탈락하는 단계
- 1차 필터링을 하겠다는 의도가 강하게 작용하는 관문
- 필터 강도: 한 면접관의 경험치로는 서류 합격률을 약 10%로 볼 때 코딩 테스트까지 통과하는 비율이 약 2~3%로 떨어진다. 공식 통계가 아니고 비율의 모수(전체 지원자인지 서류 통과자인지)도 분명하지 않으므로 규모 감각으로만 쓴다.

## 준비 방법

- 짧게 풀 수 있는 퀴즈 문제부터 점차 복잡한 문제까지 단계별 접근
- 빈출이 높은 것을 정복하되, 각 단계별 하-중-상까지 순차적으로 해결
- 문제를 이해하는 것이 첫 관문
- 시간 복잡도와 테스트 패스까지 고려해야 함
- 반드시 회고를 거쳐 더 좋은 방향은 없었는지 리뷰

### 무작정 공부하기 어렵다면
- 기본적인 프로그래밍 언어를 숙달한 후 아래 사항 집중
- CS에 대한 공고한 이해, 자료구조, 알고리즘
- 여러 유형의 퀴즈 풀이, 동영상, 관련 서적 학습

### 유의할 점
- 3개월 정도는 집중적으로 공부해야 함
- 주객이 전도되지 않게 너무 많은 시간 투자는 부담
- 자료구조의 이해는 필수
- 간단한 퀴즈성 문제로 머리를 말랑말랑하게 한 뒤 본격적인 준비
- CS 지식을 공고히 하고 언어 구사 능력을 키우는 것에 초점
- 자료를 정리하고 타인의 인사이트를 얻을 수 있는 **팀 스터디 형태** 추천
  - 시간 예산: Easy에서 Medium까지의 풀이와 리뷰는 팀 스터디로 한 달 안에 끝내는 것을 목표로 하고, 난이도 상은 주변 동료나 선배의 과외 또는 유료 강좌로 보완한다.
  - 사이클: 4~5명이 같은 문제를 각자 다른 방식으로 풀고 1주 단위로 리뷰하는 사이클을 4주 정도 돌리면 중급까지 올라갈 수 있다는 것이 한 면접관의 경험이다. 알고리즘 스터디는 온라인으로 해도 된다.

## 단계별 접근 전략

### 1단계: 자신감을 심는 단계
- 쉬운 문제 위주, 많은 사람이 이미 풀어 본 입문 문제 묶음으로 머리를 말랑하게 하고 자신감을 얻는다
- 간단한 알고리즘 퀴즈나 계산
- 프로젝트 오일러 — 수학 문제를 코드로 푸는 문제 모음으로, 앞번호(1~100번)부터 푼다

### 2단계: 핵심 자료구조와 알고리즘 숙지
- 정렬, 자료구조, 유명 알고리즘 단계별 정복
- 문제의 유형이나 풀이 패턴 학습 — 패턴별로 묶인 인기 문제집 목록을 따라가고, 막히면 다른 사이트의 같은 유형 문제로 우회한다

### 3단계: 본격적인 훈련
- 서적이나 동영상 참고, 이때부터 그룹 스터디를 운영한다
- 중고급 난이도 풀이가 중요
- **중상급 문제에 도달해야 합격권**
- 학습 순서: 강의나 서적으로 먼저 개념을 잡고, 스터디를 한 번 돌려 본 뒤, 부족하면 유료 알고리즘 강의와 문제로 보완한다

강의가 1, 2단계 자료로 추천한 백준 온라인 저지(BOJ)는 2026-04-28 서비스를 종료했고, 2026-09-30 확인 기준 사이트에는 채점 서비스 준비 중 안내만 있다. 인수 소식은 보도됐지만 재개 시점은 공지되지 않았다. 강의가 말하는 입문 묶음(CLASS)과 골드, 플래티넘 같은 난이도 등급을 매기던 solved.ac도 BOJ 문제를 기준으로 했으므로, 지금은 아래 연습 사이트의 난이도 체계로 단계를 잡고 BOJ 재개 여부는 공식 안내로 다시 확인한다.

## 실무형 구현 문제 사다리와 검수 기준

난이도가 점점 오르는 대표 문제로 중급까지 훈련하는 목록이다. 직접 타이핑하며 로직을 이해하고, 참고 풀이를 보면 왜 그 로직인지 유추한 뒤 더 나은 방법이 없는지 다시 푼다.

| 순서 | 문제 | 보는 것 | 확장 |
|---|---|---|---|
| 1 | 문자열 뒤집기 | 기본 문자열 처리(표준 라이브러리 또는 역순 순회) | |
| 2 | 대소문자를 무시한 회문 판정 | 문자열 처리와 논리 | |
| 3 | 10개 이상 정수 배열에서 최솟값의 인덱스와 값 | 배열 탐색, 값과 인덱스 동시 관리 | 중간값, 최댓값 |
| 4 | 음수, 양수, 0의 개수를 소수점 6자리 비율로 출력 | 순회, 조건 분기, 비율 계산과 출력 형식 | |
| 5 | 12시간제(AM/PM) 시각을 24시간제로 변환 | 문자열 처리, 조건문 | |
| 6 | 작성 시각(YYYYMMDD HHMMSS)을 현재와 비교해 N분 전, N시간 전, 며칠 전으로 표기 | 날짜와 시간 형식, 분기 설계, 코드 스타일, 예외 처리와 입력 검증 | |
| 7 | 소괄호, 중괄호, 대괄호의 짝과 여닫는 순서 검증 | 스택 이해와 구현 | |
| 8 | 라운드 로빈 로드밸런서: 요청마다 다음 서버, 끝에서 처음으로 | 로드밸런싱 동작 이해 | 동시 요청의 동시성과 최적화 |
| 9 | 키별 메모리 캐시, 3초 뒤 만료(TTL)와 GET | 자료구조 선택 | thread-safe 캐시, LRU와 LFU 교체 정책 |

- 9번은 레벨 1 수준의 쉬운 문제로 분류되지만, 자료구조를 모르고 풀면 코드가 난잡해지고 동작하더라도 검수에서 탈락한다는 것이 한 면접관의 경고다. 쉬운 문제에서도 평가의 핵심은 어떤 자료구조를 왜 골랐는가다.
- 자동 채점은 숨겨진 테스트 케이스의 통과만 본다([[Algorithm-Practice#코딩 테스트의 채점 방식|채점 방식]]). 통과한 코드를 사람이 다시 검수하거나 면접에서 풀이를 리뷰하는 회사도 있어, 이때는 시간, 공간 복잡도와 함께 분기 구조, 입력 검증, 예외 처리와 가독성까지 본다. 6번처럼 실무 기능을 옮긴 문제가 특히 그렇다.
- 연결 정본: 라운드 로빈의 한계와 대안은 [[Load-Balancer|로드밸런서]], LRU 구현(hash map과 doubly linked list)과 eviction 동시성은 [[Algorithm-Practice#백엔드에서의 연결|백엔드에서의 연결]], 만료의 의미는 [[TTL]], 스택과 큐는 [[Linear-Data-Structures|선형 자료구조]], 복잡도 등급은 [[Algorithm-Complexity|시간복잡도와 공간복잡도]].

## 코딩테스트 복기

코딩테스트를 패스했다면 면접 자리에서 리뷰하는 시간을 가질 수 있다.

- 왜 이 방식으로 풀었는가? → 면접관의 질문에 대비
- 문제의 해결과정, 복잡도 설명 → 본인의 풀이 복기
- 최선의 자료구조는 무엇인가? 다른 풀이 방식은 없는가? → 더 나은 해법 제시

## 분류별 필수 지식

영역마다 먼저 필요한 선수 지식이 있다. 기초가 부족하면 주니어 시기에 이 영역을 집중해서 공부한다.

| 영역 | 항목 | 선수 지식 |
|---|---|---|
| 정렬 알고리즘 | 병합정렬, 버블정렬, 퀵정렬, 힙정렬, 삽입정렬 | 배열, 재귀 |
| 자료구조 | 이진트리, B트리, 스택, 큐, 우선순위큐, 연결리스트, 연결해쉬맵, 해쉬테이블 | 포인터(참조), 메모리 관리, 기본 알고리즘, 복잡도 |
| 검색 알고리즘 | 선형검색, 이진검색 | |
| 그래프 탐색 알고리즘 | DFS, BFS, [[Topological-Sort\|위상 정렬]] | 그래프 이론, 재귀, 스택, 큐 |
| 문제해결 전략 | 백트래킹, 완전탐색, 투포인터, 분할정복, DP, 그리디 ([[Problem-Solving-Techniques\|문제 해결 기법]]) | |
| 캐시 교체 알고리즘 | LRU, LFU | |
| 최단경로 알고리즘 | 다익스트라, 벨만-포드 | |

## 핵심 습관

- 문제를 이해하는 단계가 가장 어렵다 — 문제 이해력 자체를 훈련한다
- 매일매일 꾸준함이 중요
- 단계별로 리뷰와 회고, 실제 코딩 테스트를 본 뒤에도 리뷰와 회고
- 둘 이상 모여 공유
- 알고리즘 전문 사이트를 통한 훈련의 반복과 스터디
- 복잡도를 고려하고 테스트 검증 필수
- 인터넷에 공유되는 유명한 문제들도 도전
- 다양한 문제를 풀며 비슷한 패턴끼리 카테고리로 묶고, 실패한 문제에 다시 도전한다
- 제한 시간 안에 해법을 빨리 제시하고 푸는 훈련과 손코딩 훈련(해외 준비만이 아니라 국내 준비에도)

### 피해야 할 습관

- 낮은 난이도만 풀거나 한 사이트만 푸는 것 — 사이트마다 문제 형식과 입출력 방식이 달라 한곳에만 익숙하면 다른 환경에서 흔들린다. 여러 사이트 경험을 쌓는다.
- AI 도구에 풀이 전체를 맡기는 것 — 실력이 늘지 않는다. 도움은 메서드 이름이나 의사 코드 수준으로 제한한다([[AI-Handicap-Learning|AI 접바둑 학습]]의 대리 대국과 접바둑 구분을 코딩 테스트에 적용한 형태).

## 남은 기간별 준비 운영 (강사 경험칙)

코딩 테스트 강사 한 명의 경험칙이며 채택된 결정이 아니다. 지원 일정, 허용 언어와 가용 시간을 확인한 뒤 고른다.

- **언어는 남은 기간으로 정한다**: 시험까지 2주 안팎이면 새 언어를 배우지 말고 쓰던 언어로 준비한다. 한 달 이상 남았고 지원 회사가 허용하면, 표준 라이브러리로 로직이 짧아지고 상위 난이도 참고 풀이가 많은 언어로 옮기는 선택지를 검토한다. 강의는 C++(next_permutation, sort, lower_bound, upper_bound)을 권하고, 알고리즘용 C++는 다른 언어 경험이 있으면 3일에서 2주면 익히며 이후 다른 언어로 옮길 때는 push_back과 push 같은 대응만 익히면 된다고 본다. 강의가 든 언어별 속도와 대회 사용률 수치는 출처가 제시되지 않아 옮기지 않는다. 작성법은 [[Cpp-Coding-Test-Workflow|C++ 코딩 테스트 워크플로]].
- **JavaScript나 TypeScript로 간다면**: 표준 내장 객체에 우선순위 큐, 덱과 이분 탐색 함수가 없다(MDN 기준). 힙, 인덱스 포인터로 만든 큐와 lower bound를 미리 손에 익혀 둔다.
- **직장인 주간 리듬**: 아침에 문제를 출력하거나 메모해 두고 출퇴근 같은 자투리 시간에 머릿속으로 풀이를 구상한다(손코딩). 퇴근 후 1~2시간에 구상한 풀이를 구현해 평일 하루 1~3문제, 주말에는 카페처럼 집중되는 장소에서 시간을 정해 하루 5문제를 목표로 한다. 이 리듬을 2~3개월 유지하면 웬만한 코딩 테스트를 통과한 사례가 많았다는 관찰이다.
- **예제는 직접 타이핑한다**: 복사해 붙이지 말고 include나 import 같은 첫 줄부터 친다. 시험 환경에 템플릿이 주어지지 않을 수 있고 타자 속도와 기억이 함께 는다. 이해와 일부 암기를 병행한다.
- **준비 축의 순서**: 한 강사가 여러 대기업 공고에서 뽑은 축은 프로젝트, 알고리즘, CS, 오픈소스 기여다. 모두 부족하면 알고리즘부터 시작해 프로젝트, CS 순으로 가고, CS는 하루 30분에서 1시간씩 병행하며, 오픈소스는 앞의 셋이 갖춰진 뒤 도전한다.
  - 알고리즘: 누적합, 구현, 그래프, DFS와 BFS, 트리 순회, DP 같은 필수 개념을 먼저 익히고 중상 난이도 문제를 최소 160개 이상 푼다(강사 기준은 solved.ac 골드~플래티넘).
  - 프로젝트: 공고의 지원 자격뿐 아니라 우대 사항까지 기준으로 기술을 고르고, 강점으로 내세울 기술은 깊게 판다([[Job-Search-Strategy|이직 전략]]의 공고 역산과 같은 축).
  - 오픈소스: GitHub star 1만 이상 프로젝트 기여를 목표로 두되, 관련성 높은 작은 프로젝트에서 이슈 분석, 코드 분석, PR 제출 순으로 시작한다.
  - 비전공이나 학력 차이는 인정하고 더 많은 노력으로 메운다는 태도를 강조한다([[Non-CS-Major-Developer|비전공 개발자]]).

## 해외 취업 목표

- 기간을 정해 계획을 가지고 단계별 실력 향상
- 기출 문제를 빠르게 풀어낼 수 있어야 함
- 반복 훈련과 손 코딩
- 완전한 코드가 아니라도 의사 코드를 써서 설명하는 훈련
