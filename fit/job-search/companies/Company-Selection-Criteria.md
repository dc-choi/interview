# 개발자 회사 선택 기준

연봉, 사무실, 네임밸류만으로 회사를 고르면 2년 후 "왜 왔지?"라는 질문을 마주한다. 중요한 건 **성장 환경의 질**이며, 그건 **조직마다 다르고 심지어 같은 회사 안에서도 팀마다 다르다**("진리의 팀바팀"). 회사 전체 브랜드보다 **지원 팀의 문화**를 검증하는 것이 필수.

## 평가 축 4가지

### 1. 보상, 복지

기본이자 협상 가능한 정량 요소.
- **연봉 구성**: 베이스 / 성과급 / 스톡, RSU / 사이닝 보너스
- **복리후생**: 교육비, 도서비, 컨퍼런스, 장비 지원
- **근무 형태**: 원격, 하이브리드, 출근, 유연 근무
- 주의: 총보상(TC) 기준 비교. 베이스만 비교하면 왜곡

### 2. 동료의 질

"훌륭한 동료가 곧 복지"라는 격언이 자주 인용되는 이유. **동료와의 일상 협업은 중요한 학습 원천**이다.

- **시니어 비율** — 팀 안에 배울 만한 사람이 있는가
- **채용 기준** — "이 팀이 어떤 사람을 데려오는가"가 미래의 팀 수준
- **이직률** — 6개월, 1년 차 이탈률은 조직 상태의 선행 지표
- **면접관 인상** — 같이 일하고 싶은가를 본인이 역으로 평가

### 3. 제품, 트래픽

기술적 성장의 밀도는 **문제의 난이도**에서 온다.

- **자체 서비스 vs 대행, SI** — 자체 제품은 장기적 도메인 축적
- **트래픽 규모** — 대용량 경험은 시니어 커리어의 레버리지
- **기술 스택의 업계 포지션** — 업계 표준인가, 갈라파고스인가
- **확장성, 안정성 요구** — 단순 CRUD인지 분산, 고가용인지
- 주의: "대용량 트래픽 경험"이라는 환상의 함정 → [[Large-Scale-Traffic-Experience]]

### 4. 리더십, 문화

"극단에 치우친 리더보다는 **균형을 잘 잡는 리더**"가 건강한 조직을 만든다.

- **개발-사업 밸런스** — CTO가 사업만 보는지, 기술만 보는지, 둘 다 보는지
- **결정 구조** — 톱다운 vs 합의형. 본인 성향과 매치
- **실패 허용** — 실험, 실패가 학습으로 처리되는가, 개인 책임으로 돌아가는가
- **CEO, CTO 배경** — 개발자 출신 여부가 의사결정 품질에 영향

## 면접에서 확인할 구체 질문

### 개발팀 팀장에게

- 팀의 시니어/주니어 비율은?
- 팀 규모는? (6명 전후가 관리, 협업에 유리하다는 경험칙)
- 코드 리뷰는 어떻게 진행되나요? 필수인가요, 권장인가요?
- 자동화(CI/CD, 테스트, 배포)는 어디까지?
- 온보딩 기간에 기대하는 바는?

### 리더(CTO/실장)에게

- 개발 조직의 향후 1~2년 로드맵은?
- 개발-사업의 의사결정 밸런스는?
- 기술 부채 관리 방식은?
- CTO 본인의 개발 베이스는?

### 팀 문화 검증

- 토론 문화가 개방적인가, 연공서열인가?
- 교육, 컨퍼런스 지원이 실제로 쓰이는가?
- 일정 관리는 합리적인가(번다운, 추정, 버퍼)?
- **실패 사례**를 들려달라 — 어떻게 대처했는지

구조화된 체크리스트를 역질문으로 바꿔 쓰면 감에 의존하지 않고 팀을 비교할 수 있다. 점수 자체보다 빠진 항목이 무엇이고 왜 빠졌는지를 묻는다.

- **The Joel Test (2000)**: 소스 관리, 한 번에 빌드, 일일 빌드, 버그 DB, 새 코드보다 버그 수정 우선, 최신 일정, 스펙, 조용한 작업 환경, 돈으로 살 수 있는 최고의 도구, 테스터, 면접에서 코드 작성, 복도 사용성 테스트의 12개 예/아니오 질문. 지금은 대부분 당연해진 항목이라 기본 위생 점검용이다.
- **The Pragmatic Engineer Test (2021)**: 엔지니어 전원의 지분이나 이익 공유, 엔지니어가 기여하는 로드맵, 다른 IC와 직접 협업, 코드 리뷰와 테스트의 일상화, CI와 엔지니어의 직접 배포, 내부 오픈소스, 건강한 온콜, 개발 배경의 매니저, 경력 레벨(엔지니어 10명 이상), IC와 매니저 병렬 트랙(30명 이상), 피드백 문화, 성장 투자의 12개 질문. 규모 조건이 붙은 항목은 회사 단계에 맞지 않으면 감점하지 않는다.
- **국내 개발 문화 12항목 (2022 설문)**: 코딩 테스트 면접, 개인 장비 선택 자율, 팀 개발 환경 선택 자율, 코드 리뷰와 테스트, 개발자가 기여하는 로드맵과 백로그, CI/CD, 사내 소스 저장소 공유, API 기반 연동, 기술을 이해하는 팀장, 개발자 레벨과 경력 관리, 참여형 지식 공유, DevRel 활동.

## 성장 환경의 구조적 조건

개발자가 성장하기 좋은 회사는 다음이 **구조적으로** 구비되어 있다.

- **도전적 과제** — 70% 시간이 "해본 적 있는 일"에만 쓰이면 정체
- **빠른 피드백 루프** — 코드 리뷰, 모니터링, 장애 리뷰로 학습이 축적
- **자율성 + 책임** — 자기 영역을 소유하되 결과로 평가
- **명확한 경력 경로** — 시니어, 스태프, 프린시펄 같은 트랙이 실존
- **실패를 학습으로** — Blameless Postmortem 문화

## 시그널: 이 회사는 피하라

- JD가 모호하거나 여러 역할을 섞어놓음 (책임 불명확)
- 면접관이 질문에 방어적, 감정적
- 평가 기준, 승진 기준 설명 회피
- 이직률 질문에 "괜찮다"만 반복 (구체 숫자 없음)
- 야근 빈도가 상시화되어 있다는 뉘앙스
- 주니어 비율이 과반 (시니어 밑천이 없음)
- 연봉만 강조하고 **성장, 문화** 질문에 답을 못 함
- **같은 단일 직무 공고**가 수개월째 거의 그대로 다시 올라옴 — 사람이 계속 나가거나 누가 와도 버티기 어려운 자리일 수 있어 전임자가 떠난 이유를 묻는다. 여러 직무의 공고가 수개월 꾸준히 올라오는 것은 반대로 성장 신호일 수 있으니 둘을 구분한다
- 연봉을 **범위로도 공개하지 않고** 내규나 면접 후 협의만 반복함 — 정보 비대칭을 회사 쪽에 두려는 신호일 수 있다. 처우 단계 전에 대략의 밴드를 먼저 묻는다
- **익명 리뷰 평점이 매우 낮음** — 컷오프가 아니라 조사 트리거로 쓴다. 불만이 큰 사람이 더 많이 쓰는 표본 편향, 작은 회사의 적은 리뷰 수, 오래된 리뷰를 감안하고 같은 불만이 여러 해 반복되는지를 본다. 5점 만점 2.5 이하를 거르라는 실무 경험칙도 있지만 검증된 기준은 아니다
- 자세한 구조적 판별은 [[Toxic-Org-Detection|독성 조직 판별 프레임]]

## 단계별 접근

| 단계 | 확인 |
|---|---|
| **공고 분석** | JD의 R&R, 기술 스택, 업무 범위. 너무 광범위하면 경계 |
| **회사 정보** | 제품, 트래픽, 재무(스타트업이면 런웨이) |
| **1차 인터뷰** | 팀 분위기, 면접관 성향, 기본 커뮤니케이션 |
| **2차, 대면** | 리더 철학, 기술 결정 구조, 온보딩 |
| **Offer 협상** | TC, 성장 약속, 근무 조건 |
| **Reference Check** | 가능하면 재직자, 퇴직자 1:1 대화 |

## 스타트업의 성장과 생존 여력을 나눠 확인한다

투자 유치나 인원 증가만으로 회사의 안정성과 지원 직무의 성장 기회를 확정하지 않는다. 공개 성장 지표를 출발점으로 삼되, 면접에서는 현재 자금 상태와 사업 변화에 대한 대응을 따로 확인한다.

- **런웨이와 현금 소진**: 현재 보유 현금과 순현금 소진 속도에서 남은 운영 기간을 묻는다. 과거 누적 투자액을 현재 가용 현금으로 간주하지 않는다.
- **후속 자금 계획**: 다음 투자 유치가 필요한 시점과 그 전까지 달성할 목표를 확인한다. 투자 유치가 늦어지거나 매출 전망이 달라질 때의 대응도 묻는다.
- **사업의 적응력**: 시장 변화가 고객 수요와 매출에 어떤 영향을 주었고, 회사가 무엇을 바꾸었는지 구체적인 사례를 요청한다.
- **설명의 균형**: 창업자와 리더가 기회뿐 아니라 위험과 아직 모르는 점도 설명하는지 본다. 전형이 진행되면서 질문을 구체화한다.

모든 지원자에게 맞는 런웨이 합격선을 정하지 않는다. 본인의 위험 감수 범위와 역할 기대를 함께 비교하며, 답변받지 못한 값은 미확인으로 남긴다. 아래는 이 기준을 직무 선택에 연결하는 질문 예시다.

> 이 채용은 어떤 사업 목표를 위해 열렸고, 입사 후 첫 3개월에 제가 맡을 결과는 무엇인가요? 다음 자금 조달이 늦어지면 팀의 우선순위는 어떻게 달라지나요?

## 수용 전 최종 검토

Offer를 받은 후 **24~48시간 냉정 검토**.

- 현 직장 불만이 **새 회사의 장점**과 연결되는가, 아니면 탈출만인가. 지금 회사에서 못 배운 것을 그곳에서 배울 수 있는지로 도피와 성장을 가른다
- **직속 매니저**가 누구이며 어떤 방식으로 일하는가. 가능하면 최종 수락 전에 한 번 대화한다
- 그 자리가 **왜 비었는가** — 신설인지 충원인지, 충원이면 전임자가 떠난 이유를 묻는다
- 조직도에서 팀의 위치와 **보고 라인** — 누구에게 보고하는지가 맡을 문제의 크기와 성장 속도를 좌우한다
- 보상 구성의 **비중** — 기본급 대 인센티브 비율과 인센티브의 지급 조건을 서면으로 확인한다
- 실제 **평가 방식과 KPI** — 무엇으로 평가받는지 모르면 무엇을 잘해야 할지도 모른다
- **외부 평판** — 익명 리뷰는 표본이 치우칠 수 있어 여러 경로와 재직자 대화로 교차 확인한다
- **배울 사람** — 공개 프로필이나 발표로 팀에 배울 만한 사람이 있는지 확인한다
- 최종 합격과 처우 확정 전까지 **이직 사실을 발설하지 않았는가**
- 2년 후 이 회사에서 **어떤 스킬**이 생길지 구체적으로 그릴 수 있는가
- 팀장, 동료와 **주 1회 이상** 대화하며 성장을 논할 수 있는가
- 실패, 이직이 **블랙마크**가 아닌 **학습**으로 간주되는가
- **7축 자기 점수** — 동료와 리더, 규모, 보상, 조직문화, 도메인, 배울 사람과 체계, 데이터 기반 의사결정과 AX(AI 전환) 수준에 1~5점을 매긴다. 제안을 받기 전에 본인에게 가장 중요한 TOP3를 정해 두고, TOP3가 낮은 회사는 다른 점수가 높아도 거르는 필터로 쓴다. 기준을 나중에 정하면 이미 끌리는 회사를 합리화하기 쉽다
- **정서적 보상** — 금전 외에 자율성(일하는 방식과 시간, 휴가와 퇴근의 눈치, 업무 외 연락), 성장(시장 가치가 오르는 경험, 배울 사람), 인정(구체적 인정, 의견 존중, 실수를 비난보다 해결과 재발 방지로 다루는가), 의미(일이 누군가에게 도움이 되는가)를 현 직장과 비교한다. 입사 전에는 면접과 재직자 대화로 세운 가설일 뿐임을 기억한다

## 면접 체크포인트

- 회사 브랜드가 아닌 **지원 팀** 단위로 평가했는가
- 4가지 평가 축(보상, 동료, 제품, 리더십)에 각각 점수를 매겨보았는가
- 면접에서 **역질문 10개 이상**을 준비했는가
- 성장 환경의 구조적 조건 5가지 중 몇 개가 충족되는가
- 피해야 할 시그널이 2개 이상 감지되면 재고려
