# 드레퓌스 기술 습득 모형

Hubert Dreyfus와 Stuart Dreyfus가 제안한 기술 습득 모형은 경험이 쌓이면서 판단 방식이 어떻게 달라지는지 설명한다. 아래 단계 요약은 Stuart Dreyfus의 2004년 논문을 따른다. 개발자 직급, 연차, 생산성 배수나 코칭 자격을 인증하는 표는 아니다.

## 5단계 요약

| 단계 | 모형에서 강조하는 판단 방식 |
|---|---|
| **Novice (초심자)** | 맥락과 분리된 특징과 명시적인 규칙에 의존한다 |
| **Advanced Beginner (고급 입문자)** | 경험한 사례에서 상황에 따른 특징을 알아보기 시작한다 |
| **Competent (중급자)** | 계획과 관점을 선택해 중요한 요소를 추리고 결과에 책임을 느낀다 |
| **Proficient (숙련자)** | 중요한 상황과 목표를 직관적으로 파악하되 실행 방법은 분석해 결정한다 |
| **Expert (전문가)** | 익숙한 영역의 미묘한 상황을 구별하고 적절한 대응을 직관적으로 선택한다 |

Expert가 모든 맥락을 완벽하게 안다는 뜻은 아니다. 원문도 익숙하지 않은 상황에서의 전문가와 평소 숙련 수행을 구분한다.

## 모형을 적용할 범위를 먼저 정한다

실무에서는 사람 전체에 등급 하나를 붙이기보다 어떤 과제에서 판단을 관찰하는지 명시한다. 예를 들어 API 구현 경험과 보안 설계 경험은 다를 수 있다. 아래는 모형을 참고한 개발 업무 적용 제안이며, 논문에서 검증한 개발자 평가 도구는 아니다.

1. **과제와 조건**: 어떤 기술, 업무와 제약에서 평가하는지 정한다.
2. **관찰 근거**: 해결 과정, 대안과 실패 조건, 실제 결과를 확인한다.
3. **지원 수준**: 독립적으로 맡길 부분과 리뷰가 필요한 부분을 합의한다.
4. **재확인**: 다른 과제와 이후의 수행에서도 판단이 유지되는지 확인한다.

문서 없이 1시간 안에 리팩터링하거나 세 질문에 모두 답했다고 특정 단계로 확정하지 않는다. 필요한 자료를 정확히 찾고 적용하는 능력도 실무에서 관찰할 대상이다.

## Competent를 코칭 자격선으로 쓰지 않는다

계획과 우선순위를 세우는 능력은 실무에서 중요하다. 그러나 이 모형만으로 Competent 이전에는 다른 사람을 가르칠 수 없고, 이후에는 잘 가르친다는 결론을 내릴 수 없다.

동료 학습과 설명은 자신이 이해한 좁은 범위에서도 시도할 수 있다. 설명의 정확성, 학습자의 수준과 피드백을 확인하고, 모르는 내용은 검토를 요청한다. 높은 수행 능력과 좋은 교육 능력을 별도로 평가한다.

## 학습 지원을 고르는 질문

- **규칙과 예제가 필요한가**: 시작 과제를 작게 나누고 결과를 확인할 예제를 제공한다.
- **상황별 차이를 놓치는가**: 비슷해 보이지만 다른 결과가 나는 사례를 비교한다.
- **우선순위를 정하기 어려운가**: 선택한 계획과 버린 대안, 판단을 바꿀 조건을 설명한다.
- **익숙한 판단에 의존하는가**: 낯선 제약에서는 측정, 문서와 다른 사람의 리뷰로 다시 확인한다.

이 질문은 학습 지원을 선택하기 위한 제안이다. 교과서 10권 암기, 무조건적인 모방이나 신입의 2년 이내 단계 통과를 공통 요건으로 삼지 않는다. 타인의 코드를 검토할 때는 공개 권한과 보안 조건을 지킨다.

## 팀 기여는 실제 결과로 확인한다

리뷰, 문서화와 실패 예방이 팀에 도움이 되는지 관찰할 수 있다. 다만 모형에서 팀 생산성 1.5~3배, 실수 절반 감소나 적정 인원 비율이 도출되는 것은 아니다.

검토할 근거의 예시는 반복 오류 감소, 변경에 필요한 시간과 지원 범위다. 작업 난이도와 팀 조건이 함께 바뀌었다면 한 사람의 역량만으로 결과를 설명하지 않는다. 구체적인 관찰은 [[Competence-Identification|개발 역량 판별]]과 연결한다.

## 국내 경력 등급과 비교할 때

경력 연수와 숙련을 같은 것으로 보지 않는 참고 틀로 사용할 수 있다. 국내 자격, 경력 관리와 등급 제도의 현재 기준은 별도 공식 자료로 확인한다. 과거 등급 기준이나 가정한 경력 분포에서 현재 개발자의 숙련 비율을 계산하지 않는다.

## 자기 점검

- 어떤 과제에서 혼자 판단할 수 있고 어느 부분에서 도움이 필요한가.
- 규칙을 적용한 이유와 적용하지 않을 조건을 설명할 수 있는가.
- 익숙한 상황의 직관을 새로운 환경에 그대로 적용하지 않았는가.
- 타인에게 설명한 내용이 정확하고 도움이 됐는지 확인했는가.
