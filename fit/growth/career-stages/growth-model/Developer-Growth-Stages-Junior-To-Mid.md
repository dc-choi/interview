# 주니어 → 미드레벨 전환 7단계

연차 1~3년에 **구체적으로 연습해야 할 행동 체크리스트**. [[Developer-Growth-Stages|성장 단계 모델]]과 교차 적용.

## 1. 시니어 피드백 경청

- 처음엔 방어적 감정이 들 수 있음 — **받아들이는 근육**을 기르는 게 우선
- 리뷰어의 기준을 모방하다 어느 순간 내 기준으로 내재화
- **아프고 빠른 피드백** 이 친절하고 모호한 피드백보다 낫다

## 2. 코딩-테스트-리팩터-테스트 이중 검증

- 작동하는 코드에서 끝내지 말고 **개선 루프** 1회 더
- 작동 단계가 끝난 후 테스트는 경계 케이스까지

## 3. 스스로 결정 내리기

- 모호한 상황에서 본인 판단으로 작은 결정 누적 → **결정 근육**
- 완벽을 기다리다 결정을 미루면 생산성 손실
- 작은 결정을 틀리며 **판단 능력을 복리**로 키움

## 4. 진행, 기대치, 문제 소통

- 현재 상태, 남은 리스크, 필요한 도움을 **선제적으로** 전달
- "사고는 감추지 말고 먼저 알린다" — 신뢰의 근간
- 실시간 공유가 사후 보고보다 항상 싸다

## 5. Git 숙련

- 단순 commit/push가 아니라 **rebase, cherry-pick, bisect, reflog**까지
- 오픈소스 PR, 대형 레포 커밋 히스토리 읽기로 학습

## 6. 실수에서 배우기

- 실수를 **학습 소재로** 다룸 — 포스트모템 습관
- "다시 안 하겠다"가 아니라 **구조적 방지책** 도출
- 실수 로그를 개인 위키에 쌓기

## 7. 360도 관점

- 단순 구현자를 넘어 **비즈니스, 사용자, 운영** 관점까지
- 기대 이상의 산출물을 만드는 개발자로 전환
- 이 7번째 단계가 미드레벨 이상을 가른다
- 성숙도의 구체 신호는 **니즈 재정의** — 요청을 그대로 구현하지 않고 진짜 니즈를 파악해 더 싼 대안(신규 개발 대신 기존 기능 활용)을 제시하는 것. 직무 불문 공통 패턴으로, 기획자 성장 단계에서도 같은 분기점이 나타난다

## 연차는 쌓였지만 신입처럼 일하는 신호

연차가 쌓이면 맡은 일을 정확히 하는 것에 더해 없던 일을 만들고 일을 잘 넘기는 것까지 기대받는다. 아래 신호는 3번(결정)과 4번(소통)이 연차만큼 자라지 않았다는 뜻이다.

| 신호 | 전환 행동 |
|---|---|
| 시키는 일만 정확히 한다 | 요청 범위 밖에서 함께 보면 좋을 것 하나를 덧붙이고 이유를 적는다 |
| 회의에서 말하지 않는다 | 확신이 없으면 주장 대신 질문으로 연다. 이 방향이면 이 경우는 어떻게 처리되는지 묻는다 |
| 내 일이 아니면 관심이 없다 | 옆 팀의 주간 자료를 훑어 내 일이 전체에서 어디에 있고 왜 중요한지 설명할 수 있게 한다 |
| 보고 대신 확인만 받는다 | 결정을 먼저 하고 확인받는다. 이렇게 진행하려는데 문제가 있으면 알려 달라고 말하면 책임의 위치가 바뀐다 |
| 후배의 일을 대신 해 준다 | 한 번은 옆에서 과정을 보여 주고 다음부터 맡긴다. 위임하는 업무의 양과 질이 연차의 기준이 된다 |
