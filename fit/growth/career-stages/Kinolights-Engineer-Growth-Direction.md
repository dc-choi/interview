# 키노라이츠에서의 엔지니어 성장 방향

2026-06-29 입사 뒤 첫 90일을 위해 세운 당시 개인 성장 계획이다. 2026-09-01 퇴사 결정 이후에는 현재 우선순위의 정본으로 사용하지 않고, 당시의 가설과 행동 기준을 보존하는 기록으로 둔다.

이 문서는 역량 부족을 판정하는 평가표가 아니다. 이미 가진 기술적 강점을 제품 맥락, 협업과 결과 확인까지 확장하기 위한 개인 행동 계획이다. 현재 우선순위와 학습 전환 조건은 [[Current-Goals-and-Roadmap|현재 목표와 통합 로드맵]]이 정본이다.

## 당시 상태

- 당시에는 키노라이츠 적응과 맡은 일을 결과 확인까지 독립적으로 끝내는 것을 최우선으로 뒀다.
- 2026-08 자기평가에서는 기술 문제를 구조화하고 구현하는 기반은 이미 있다고 봤다. 다음 과제는 판단의 맥락과 위험을 필요한 시점에 공유하는 습관이다.
- 실제 업무의 내용, 팀 피드백, 내부 일정과 운영 결과는 회사의 승인된 기록에서만 관리한다. 이 문서에는 공개 가능한 개인 원칙과 확인 기준만 남긴다.

## 이미 가진 기반

- 복잡한 기술 문제를 구조화하고 끝까지 파고드는 힘
- 코드, 문서와 측정 가능한 근거를 선호하는 판단 방식
- 혼자 탐색하고 구현까지 진행할 수 있는 실행력
- 동료 피드백을 주고받으며 문제를 해결한 경험
- 모르는 영역을 빠르게 학습하고 따라잡는 끈기

42서울에서 쌓은 동료 학습과 문제 해결 경험은 유효하다. 제품팀에서는 여기에 직군 간 언어 번역, 우선순위 파악, 의사결정 과정 공유와 결과 확인이 더해진다. 초기 적응의 어려움은 기존 강점의 부정이 아니라 적용 범위가 넓어지는 과정으로 본다.

## 검증할 성장 가설

커뮤니케이션 양을 무작정 늘리기보다 목적, 열린 결정, 위험과 결과를 필요한 시점에 연결하면 협업 결과가 좋아진다. 입사 초기에는 다음 행동을 반복하고 실제 피드백과 결과로만 효과를 판단한다.

1. 작업을 받으면 구현 방법보다 먼저 목적, 우선순위, 성공 조건과 완료 범위를 확인한다.
2. 결론을 기다리지 않고 열린 결정, 필요한 판단과 품질 또는 일정 위험을 조기에 공유한다.
3. 설명 대상에 맞춰 사용자 영향, 계약, 선택 근거, 복구 경계와 필요한 결정을 다르게 정리한다.
4. 병합이나 배포를 완료로 보지 않고 즉시 확인, 관찰 후 확인, 아직 측정 불가를 구분해 다음 확인 조건을 남긴다.

## 업무 루프

### 시작 전

- 왜 지금 필요한지와 해결하려는 문제를 설명할 수 있는가
- 성공 조건, 보호 조건, 인수 기준과 완료 범위를 확인했는가
- 소비자 영향, 의존성, 호환성, 배포와 복구 경계를 확인했는가
- 내가 결정할 부분과 다른 역할의 판단이 필요한 부분을 나눴는가

### 진행 중

상태 공유는 목표와 현재 상태, 확인된 사실과 검증 범위, 필요한 결정 또는 위험, 다음 행동과 확인 조건의 네 항목으로 짧게 남긴다. 범위나 성공 조건이 바뀌거나 되돌리기 어려운 선택을 하기 전에는 결론을 기다리지 않고 관련 역할에 알린다.

### 완료 후

- 무엇이 달라졌는지와 확인한 범위를 설명한다.
- 결과를 즉시 확인, 관찰 후 확인, 아직 측정 불가로 구분한다.
- 미확인 결과에는 대리 근거, 남은 위험과 다시 확인할 조건을 남긴다.
- 필요한 결정과 상태는 승인된 팀 기록에 갱신한다.

## 증거와 회고의 기준

계획한 횟수나 문서 작성 자체는 성과가 아니다. 실행 여부와 효과는 확인 가능한 기록, 역할 기반 피드백과 결과 확인으로만 갱신한다. 월간 점검에서는 다음을 묻는다.

- 구현 전에 목적과 완료 조건을 확인한 작업은 무엇인가
- 늦은 공유로 생긴 재작업과 이른 공유로 줄인 위험은 무엇인가
- 다른 역할이 별도 확인 없이 현재 상태와 필요한 결정을 이해할 수 있었는가
- 역할별로 번역한 기술 설명이 다른 판단에 실제 도움이 되었는가
- 기술 기여를 팀의 목표와 연결해 설명할 근거가 남았는가
- 결과와 불확실성, 다음 확인 시점이 남은 작업은 무엇인가
- 다음 기간에 유지하거나 바꿀 행동 하나는 무엇인가

## 2026-08-06에 세운 4주 실험 기록

당시 계획 기간은 2026-08-06부터 2026-09-02까지였다. 아래 표는 실행 완료 기록이 아니라 그날 세운 계획의 스냅숏이다. 실제 실행 시작일과 완료 여부는 이 저장소에서 확인되지 않으므로 추정해 채우지 않는다.

| 기간 | 계획한 행동 | 남기기로 한 증거 |
|---|---|---|
| 1주차 | 맡은 작업 3건에서 시작 전 질문에 답한다 | 목적, 우선순위 근거, 인수 기준과 완료 조건 |
| 2주차 | 열린 결정이나 의존성을 최소 2번 조기에 공유하고 승인된 팀 기록을 갱신한다 | 결정 시점, 실제로 받은 답과 갱신한 상태 |
| 3주차 | 완료한 작업 1건의 결과 상태를 구분해 정리한다 | 즉시 확인, 관찰 후 확인 또는 측정 불가와 후속 조치 |
| 4주차 | 리더 또는 협업 역할에게 개선점 하나를 요청한다 | 역할 기반 피드백 요약과 다음 기간에 유지할 행동 하나 |

횟수 자체가 목표는 아니었다. 늦게 발견한 계약이나 인수 기준으로 인한 재작업이 줄었는지, 다른 역할의 판단 시점이 앞당겨졌는지, 배포 뒤 결과와 불확실성 및 다음 확인 시점이 남았는지를 관찰하기 위한 최소 실험량이었다.

공개 문서에는 개인 원칙과 독립 재현 결과만 남긴다. 회사, 제품, 고객, 사람, 내부 도구, 원문 수치, 일정과 운영 상세는 승인된 기록으로 분리하며, 확인하지 못한 결과를 추정하지 않는다.
