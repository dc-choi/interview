# 추천시스템을 만들기 위한 기반 로드맵

2026-11-02 사용자 결정: 기존 로드맵을 아카이브하고 학습은 추천시스템을 직접 만드는 데 필요한 기반에 집중한다. 사용자는 Python 기초부터 필요하다고 밝혔다. `status: active`는 현재 학습 방향으로 채택했다는 뜻이며 단계별 학습 완료를 뜻하지 않는다.

## 목표와 시작점

**사용자와 아이템의 데이터를 읽고, 추천 점수를 계산하며, 결과를 평가하는 작은 추천시스템을 스스로 만들고 설명한다.**

- 출발점은 Python 기초다. 백엔드 경험을 Python, 수학과 머신러닝의 숙련으로 간주하지 않는다.
- 수학의 이전 기록은 교재 0단계 시작 전이다. 필요한 계산과 개념을 직접 풀며 현재 이해 수준을 확인한다.
- 아래 순서는 이 목표에 맞춘 실행안이다. 날짜별 일정은 아니며 막히는 개념에 따라 학습 단위를 조정한다.
- 대학원 입학 목표와 지원 조건은 [[2027-AI-Masters-Plan]]에서 별도로 관리한다. 공인영어와 서류 요건을 없애는 결정이 아니다.
- 기존 교재와 지식 문서는 필요한 절을 찾아 쓰는 참고 자료다. 아카이브의 전체 과정이나 예전 전환 조건을 다시 수행하지 않는다.

## 전체 흐름

| 단계 | 익힐 기반 | 추천시스템에 연결되는 결과 |
|---|---|---|
| 0 | Python 문법과 파일 처리 | 사용자별 평점 데이터를 읽고 집계하는 프로그램 |
| 1 | NumPy, pandas와 데이터 구조 | 사용자, 아이템, 평점과 시간을 확인하고 분할한 데이터 |
| 2 | 필요한 수학 | 벡터 유사도, 평균과 분산, 손실과 기울기를 손과 코드로 계산 |
| 3 | 머신러닝 학습과 검증 | 작은 모델을 학습하고 과적합과 데이터 누수를 구분 |
| 4 | 추천시스템 기본 모델과 평가 | 인기 기반, 아이템 기반 협업 필터링과 행렬분해 비교 |
| 5 | 하나의 실행 흐름으로 연결 | 사용자 ID를 넣으면 상위 K개 아이템과 점수가 나오는 로컬 프로그램 |

0단계는 작은 인공 데이터로 시작한다. 기초를 익힌 뒤 같은 공개 데이터셋을 계속 사용해 도구와 주제를 불필요하게 바꾸지 않는다. 1단계부터 평가용 데이터를 분리하고, 4단계에서 모델을 바꾸기 전에 평가 방법부터 고정한다.

## 0단계: Python으로 데이터를 다룬다

- 변수와 기본 자료형, 리스트, 딕셔너리, 집합, 인덱스와 슬라이싱.
- 조건문, 반복문, 함수의 입력과 반환, 정렬과 집계.
- 모듈, 가상환경과 패키지, 파일 읽기, CSV/TSV와 예외 메시지 읽기.
- TypeScript의 배열과 객체에 대응하는 개념을 비교하되 Python 문법과 실행 결과를 직접 확인한다.

**연습:** 직접 만든 사용자, 아이템과 평점 10행을 파일에서 읽고 사용자별 평점 수와 평균을 계산한다. 잘못된 숫자와 빈 필드를 어떻게 처리했는지 설명한다.

- [ ] 짧은 프로그램을 직접 작성해 실행하고, 입력부터 출력까지 설명한다.
- [ ] 입력 한 행을 바꿨을 때 예상한 결과와 실제 결과를 비교한다.

첫 학습은 변수, 리스트와 딕셔너리로 평점 몇 개를 표현하는 것부터 시작한다. 처음부터 모든 문법을 외우거나 추천시스템 프레임워크를 설치하지 않는다. 기본 자료는 [Python 공식 튜토리얼](https://docs.python.org/3/tutorial/)의 자료형, 제어문, 함수와 입출력 절을 사용한다.

## 1단계: 추천시스템 데이터와 배열을 이해한다

- NumPy의 배열, `shape`, 축, 인덱싱과 간단한 집계.
- pandas의 표 읽기, 필터, 결측과 중복 확인, `groupby`, 정렬과 조인.
- 사용자 ID, 아이템 ID, 평점과 timestamp의 역할. ID를 모델 배열의 인덱스에 매핑하는 이유.
- 평점은 명시적 평가다. 평점 없는 쌍을 싫어함이나 0점으로 바꾸지 않는다.

**연습:** MovieLens 100K의 평점 파일을 읽고 사용자 수, 아이템 수, 평점 분포와 시간 범위를 계산한다. 파일의 행 순서를 시간 순서로 가정하지 않고 timestamp를 확인한다. 이 단계의 전체 데이터 요약은 탐색용이며 모델의 인기도나 특징으로 재사용하지 않는다.

- [ ] 표의 한 행과 사용자-아이템 행렬의 한 칸이 무엇인지 설명한다.
- [ ] 학습, 검증과 테스트용 기간을 나누고 각 구간의 행 수와 겹침 여부를 확인한다.

데이터는 [GroupLens 배포본](https://grouplens.org/datasets/movielens/100k/)을 사용한다. [README](https://files.grouplens.org/datasets/movielens/ml-100k-README.txt)의 이용 조건을 확인하고 원본 데이터를 공개 저장소에 재배포하지 않는다. 사용자 인구통계 정보는 첫 실습에 필요하지 않다.

## 2단계: 계산과 모델을 이해할 수학을 익힌다

| 기반 | 범위 | 연결할 작은 계산 |
|---|---|---|
| 기초 계산과 함수 | 분수, 비율, 평균, 변수, 함수와 시그마. 지수와 로그는 필요한 식에서 보충 | 사용자별 평균과 평점 오차 |
| 선형대수 | 벡터, 행렬, 전치, 내적, 크기, 행렬곱 | 아이템 벡터의 유사도와 사용자-아이템 점수 |
| 확률과 통계 | 확률, 조건부확률, 기대값, 분산, 표본과 편향 | 평점이 적은 아이템의 평균을 과신하는 이유 |
| 미분과 최적화 | 미분, 편미분, 연쇄법칙, 기울기와 학습률 | 오차를 줄이도록 파라미터를 한 번 갱신 |

구입한 《개발자를 위한 필수 수학》의 해당 절을 활용한다. 이산수학은 집합과 필요한 표기처럼 실제 계산을 막는 부분을 보충한다. 두 교재 전체 완독을 다음 단계의 조건으로 두지 않는다.

- [ ] 작은 벡터의 내적과 코사인 유사도를 손으로 계산하고 NumPy 결과와 비교한다.
- [ ] 작은 제곱오차의 기울기를 구하고 파라미터 한 번의 갱신이 예측을 어떻게 바꾸는지 설명한다.

수학과 코드는 같은 개념을 확인하는 두 방법이다. 손계산이 막히면 그 계산만 보강하고, 수학을 끝내기 전에는 코딩을 할 수 없다는 식으로 분리하지 않는다.

## 3단계: 머신러닝의 학습과 검증을 이해한다

- 입력 특징, 목표값, 파라미터, 예측과 손실함수.
- 작은 선형회귀로 경사하강법, 학습률, 과적합과 규제를 확인한다.
- 학습 데이터는 파라미터를 정하고, 검증 데이터는 설정을 고르며, 테스트 데이터는 선택이 끝난 뒤 평가한다.
- 전처리 통계와 특징도 학습 구간에서만 계산한다. 미래 평점이나 테스트 결과를 모델 선택에 사용하지 않는다.

**연습:** 작은 인공 데이터의 선형회귀를 NumPy로 학습하고 손계산 한 단계와 비교한다. 학습 오차와 검증 오차를 따로 남긴다. 머신러닝 전체 알고리즘 목록을 학습하지 않고 추천시스템 모델의 학습을 이해하는 데 필요한 개념에 집중한다.

- [ ] 예측, 손실 계산과 파라미터 갱신을 직접 설명한다.
- [ ] 학습 오차가 작아도 검증 결과가 나빠지는 예와 데이터 누수의 예를 구분한다.

## 4단계: 추천시스템 기본 모델을 비교한다

1. **인기 기반:** 학습 구간의 높은 평점 횟수로 순위를 만드는 비교 기준을 둔다.
2. **아이템 기반 협업 필터링:** 함께 평가된 아이템의 패턴으로 유사도를 구하고 사용자 이력과 결합한다. 미관측 값과 관측된 낮은 평점을 구분한다.
3. **행렬분해:** 사용자와 아이템의 벡터 내적으로 평점을 예측한다. 관측 평점의 제곱오차와 규제로 학습하고, 임베딩과 손실의 연결을 설명한다.

처음에는 작은 행렬로 계산을 확인한 뒤 같은 데이터에 적용한다. 콘텐츠 기반 방법은 장르 벡터의 유사도 예시로 이해하되 별도 대형 프로젝트로 늘리지 않는다. 수학적 원리는 [[Recommendation-System-Modeling-Foundations]]와 [Google 행렬분해 설명](https://developers.google.com/machine-learning/recommendation/collaborative/matrix)을 참고한다.

**모델보다 먼저 고정할 비교 기준:**

- 동일한 시간 경계의 학습, 검증과 테스트를 사용한다. 이번 기초 실습에서는 검증 후 재학습하지 않고 학습 구간에서 만든 모델을 최종 테스트에 사용한다.
- 초기 실험은 학습 구간에서 관측된 아이템을 고정 후보로 둔다. 사용자별 과거 평가 아이템을 제외하며, 검증과 테스트의 정답을 보고 후보를 골라내지 않는다.
- 점수와 사용자 특징에는 해당 평가 기간 시작 전에 확보한 정보만 사용한다. 검증 때는 학습 이력, 테스트 때는 검증 기간까지의 이력으로 이미 평가한 아이템을 제외한다.
- 학습 시점에 없던 사용자에는 학습 구간의 인기 목록을 사용한다. 고정 후보 밖 아이템 수와 해당 정답 수는 별도로 보고해 신규 아이템 추천 능력으로 오해하지 않는다.
- 예를 들어 평점 4 이상을 관련 아이템으로 정의하고, 고정 후보 안의 미평가 아이템에 대한 Recall@10과 NDCG@10을 비교한다. 이는 실습용 정의이며 실제 클릭이나 구매 선호의 증거가 아니다.
- 관련 아이템이 없는 평가 사용자는 지표 평균에서 제외하고 그 수를 보고한다. 후보가 10개보다 적은 경우와 동점 처리 규칙도 함께 고정한다.
- 모든 모델에 같은 후보, 관련도와 평가 사용자를 적용한다. 검증으로 설정을 선택한 뒤 테스트는 최종 확인에 사용한다.

- [ ] 작은 정답 목록으로 Recall과 NDCG를 손으로 계산해 코드와 대조한다.
- [ ] 세 모델의 결과, 인기 기준보다 나빠지는 사례와 새 사용자 처리 방법을 설명한다. 개선 자체를 통과 조건으로 강요하지 않는다.

평점 예측 오차와 상위 목록 품질은 다르다. MovieLens 오프라인 평가만으로 실제 사용자 만족이나 온라인 서비스 효과를 입증했다고 말하지 않는다.

## 5단계: 작은 추천시스템으로 연결한다

**완료 형태:** 파일 읽기, 전처리, 모델 학습, 후보 점수 계산, 상위 K개 선택과 평가를 다시 실행할 수 있는 로컬 프로그램.

- 사용자 ID를 입력하면 아이템 ID와 점수를 반환한다. 이미 평가한 아이템 제외와 새 사용자 처리가 동작한다.
- 데이터 버전, 분할 기준, 난수 시드와 실행 환경, 사용한 모델 설정을 기록한다.
- 같은 작은 입력의 결과를 다시 확인하고, 모델을 바꿨을 때 같은 평가 기준으로 비교한다.

- [ ] 한 사용자의 데이터가 추천 목록이 되기까지의 흐름을 문서 없이 설명한다.
- [ ] 한 명령 흐름으로 실행하고 결과, 한계와 다음에 개선할 문제 하나를 남긴다.

웹 UI, 클라우드 배포, 검색 엔진과 분산 인프라는 첫 완료 조건에 넣지 않는다. 딥러닝, Two-Tower, 순차 추천시스템과 LLM 기반 추천시스템은 이 기반을 만든 뒤 연구 관심과 부족한 부분에 따라 검토한다.

## 진행 기록과 복습

현재 완료된 단계는 없다. 첫 학습 단위는 0단계의 Python 자료형과 작은 평점 데이터 표현이다. 계획 등록을 실제 실습 시작으로 기록하지 않는다.

각 단위에서 짧게 설명하고 직접 계산하거나 실행한다. 통과한 내용은 후속 학습에서 간격을 두고 1~2회 회상하거나 적용하며, 틀린 부분만 보충한다. 이해를 확인할 설명과 실습이 산출물이고 블로그 발행은 필수 조건이 아니다.
