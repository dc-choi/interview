# Learning Domain Rules

이 파일은 `fit/growth/learning/`의 학습 계획, 로드맵, 우선순위와 진행 판단에 적용한다.

ORM 관련 학습 우선순위를 다룰 때는 `tech/AGENTS.md`도 읽는다.

## 학습 원칙

- **대학원 진학 집중:** 2026-11-02 사용자는 구직을 중단하고 아르바이트로 자금을 마련하면서 2027학년도 후기 추천시스템 대학원 진학 준비에 집중하기로 했다. 이후 사용자는 기존 로드맵을 아카이브하고 추천시스템을 직접 만드는 데 필요한 기반에만 학습을 집중하도록 정했다. Python 기초부터 필요하다는 자가 진단을 출발점으로 삼는다. 대학원 지원 절차는 별도로 관리하며 DevOps, Node.js와 범용 백엔드 및 자격증을 경쟁 목표로 되살리지 않는다. 세부 학습 순서, 시간과 실제 진도는 정본에서 확인한다.
- **판단을 위한 학습 로드맵:** 지식 저장소에 축적한 내용을 사용자가 이해하고 직접 판단에 활용할 수 있도록 학습 로드맵을 유지한다. 개발과 대표 역할의 이전 계획은 아카이브로 보존하고 현재 추천시스템 구현 기반 계획에 경쟁하는 실행 경로를 새로 열지 않는다. 관련 지식 원문에 학습 목적, 순서와 이해 확인 방법을 연결하며, 로드맵에 남긴 전체 범위와 현재 실행할 진도는 구분한다.
- **대표 역할의 학습 맥락:** 대표 역할의 기술과 운영 지식은 기반으로 보존하되 현재 학습의 주축은 추천시스템 구현 기반이다. 사업 관련 판단이 요청되면 프로젝트 맥락을 조회하고, 별도 요청 없이 로컬 프로젝트 목록이나 추천 지도를 상시 문서화하지 않는다. 지식 보완으로 새 정규 트랙이나 제품 실험이 자동 활성화되지는 않는다.
- **개발 기반 유지:** 2026-09-22 사용자는 기존 개발자 커리어 학습 로드맵도 자신의 기반이므로 계속 유지하도록 요청했다. 대표 역할의 브랜딩, 마케팅, 경제와 재무 학습은 이 기반에 추가하는 영역이며 기존 개발 로드맵을 폐기하거나 대체하는 이유가 아니다. 2026-11-02 결정에 따라 로드맵은 아카이브로 유지하며, 보존을 개별 트랙 재개로 해석하지 않는다.
- **이해와 구현 확인**: 현재 학습의 산출물은 개념 설명, 손계산, 작은 구현과 평가다. 개념 입력과 반복 연습을 필수 과정으로 인정하고 블로그 발행을 별도 목표로 요구하지 않는다.
- **단일 주축 원칙**: 현재 학습 주축은 추천시스템 구현 기반이다. Python, 데이터 처리, 수학과 머신러닝은 하나의 구현 목표에 필요한 구성 요소로 다룬다. 대학원 공인영어와 서류 준비는 지원 계획에서 별도로 관리한다. 한 번에 집중할 학습 단위는 실제 이해 수준에 맞춰 정한다. 실무에서 만난 짧은 보충은 공개 로드맵 진도로 계산하지 않는다. 주일학교 출석부는 사용자가 별도로 활성화하기 전까지 선택지 보존 범위를 넘어 운영하거나 학습 실습 대상으로 열지 않는다. 사업 실험이 활성화되더라도 학습 진도가 아니라 제품 운영으로 관리한다.
- **업무 연계 기술 우선**: 실무에서 필요한 기술은 미래 투자와 범용 학습보다 먼저 다룰 수 있다. 학습 트랙의 선택과 시간 배분은 개인의 결정이며 회사 지시나 평가 기준으로 표현하지 않는다. 구체적인 조직 스택, 과제와 내부 사용 방식은 공개 로드맵에 기록하지 않는다.
- **공통 실무 기반**: GraphQL, Redis와 Git은 별도 정규 목표가 아니라 개인이 반복 학습할 기반이다. 공개 예제와 로컬 실습으로 요청 흐름, key 설계와 Git ref 변화를 추적하고 작은 설명이나 안전한 복구 결과로 빈칸을 닫는다.
- **그 밖의 기술**: JS, TS, Node.js, gRPC, Kafka와 그 밖의 기술도 실제 필요가 생기면 미래 투자보다 먼저 다룬다. 별도 정규 트랙을 동시에 열거나 읽은 분량을 숙련으로 계산하지 않는다.
- **검증**: AI는 자료 탐색, 설명과 검산에 활용하되 중요한 결론은 소스, 실행 결과나 계산으로 확인한다.
- **전체 그림 우선 이해형**: 부분 개념보다 전체 아키텍처가 먼저 보여야 이해가 붙는다. 2026-07-14 OpenSearch 학습에서 확인한 방식대로 전체 구조를 먼저 보고 세부 내용을 학습한 다음 문서를 보지 않고 구조를 재현한다.
- **학습 단위별 확인**: 추천시스템 구현에 필요한 다음 개념을 현재 이해 수준과 연결한다. 단계를 마쳤다고 아카이브의 DevOps, 검색과 Node.js 트랙으로 전환하지 않는다. 아카이브의 연도와 일정은 과거 계획이며 현재 마감일이 아니다.
- **용어:** 추천시스템을 가리킬 때는 추천으로 줄이지 않고 추천시스템이라고 쓴다.

## 학습 상태와 계획의 정본

- AI 석사 진학의 사용자 결정과 검토 상태는 `2027-AI-Masters-Plan.md`에서 관리한다. 후보 제한, 지원 결정과 실제 진학을 구분하고, AI의 추천을 사용자 확정 우선순위로 바꾸지 않는다.
- 생활과 업무의 우선순위, 트랙 선택과 자격증 전환 조건은 `fit/growth/Current-Goals-and-Roadmap.md`를 참조한다. 과거 전환기의 조건을 현재 역할에 그대로 적용하지 않고 최신 사용자 설명과 대조한다.
- 현재 학습의 정본은 `roadmaps/Recommender-System-Foundations-Roadmap.md`이며 `roadmaps/roadmaps.md`에서 연결한다. 이전 계획과 체크포인트는 `roadmaps/archive/Archived-Learning-Roadmaps.md`에서 찾는다. 문서 보존을 학습 완료로 기록하지 않는다.
- 기존 수학 전체 과정은 `roadmaps/archive/2026-H2-Math-Roadmap.md`, DevOps 실습은 `roadmaps/archive/2027-DevOps-Practical-Roadmap.md`에 보존한다. `tech/database/nosql/opensearch/OpenSearch.md`를 포함한 기술 지식 원문은 참고 자료이며 현재 학습의 필수 선행 경로가 아니다.
- 정본의 상태는 확인된 진행만 갱신하고, 지침 정리를 이유로 기존 학습 범위를 삭제하거나 트랙을 재개하지 않는다.

## 집중도별 학습 모드

- 집중할 수 있는 시간에는 글쓰기나 현재 선택한 트랙의 개념 이해와 손계산처럼 깊이가 필요한 일을 한다.
- 자투리 시간에는 짧은 강의, 책 복습, 이미 푼 문제와 용어 복습을 한다. 새로운 개념은 시작하지 않는다.
- 기술 강의는 짧은 챕터, 훑기와 복습 같은 자투리 시간 적합도로 판단한다. 깊은 집중이 필요하면 별도의 집중 시간으로 옮긴다. 수학에서는 손으로 풀이 과정을 남기는 것을 아웃풋으로 인정한다.

## 학습 상태 판단

- 저장소의 `status: done` 수량과 문서 완성 비율을 숙련도 프록시로 사용하지 않는다. 이는 문서 상태이지 숙련도가 아니다.
- 사용자가 CS는 밀린다고 자가 진단했다. 정리된 문서가 있어도 면접이나 글에서 스스로 설명하지 못하면 숙련으로 보지 않는다. 숫자만 보고 CS 강의가 필요 없다고 결론 내리지 않는다.
- 학습 우선순위를 제안하기 전에 자가 진단을 묻거나 해당 주제가 말이나 글로 바로 나오는지 확인한다. 문서 수는 맥락 참고로만 사용한다.

## CS 학습 이유

- CS를 배우는 이유는 웹 인프라의 논리적 흐름과 구조 이해, 비용과 성능 효율, 장애와 디버깅, 설계 의사결정의 언어를 확보하기 위해서다. ORM 이상 쿼리, 커넥션 풀 고갈과 GC처럼 추상화가 새는 문제에서는 밑단 지식이 원인 파악의 근거가 된다.
- AI는 코드 초안과 반복 작업을 보조할 수 있지만, 무엇을 왜 만들지와 결과를 검증하는 책임은 개발자에게 있다는 멘토링 합의를 따른다.
- 학습 깊이는 해당 CS 주제가 실제 설계 의사결정으로 말이나 글에 나오는지를 기준으로 정한다. 인덱스 내부 구조를 외우는 데서 끝내지 않고 특정 쿼리에 그 인덱스를 선택한 이유를 설명할 수 있어야 한다. 메시지 브로커 비교와 ORM 실행 계획 검증처럼 조건, 대안과 측정 결과를 연결한다.
