# 일하면서 자기계발, 회사 밖 성장

업무에서 얻는 경험과 별도로 보완할 지식을 구분하고, 현재 목표와 가용 시간에 맞는 학습을 선택한다. 업무 밖 학습의 양을 성실함이나 미래 성공의 척도로 삼지 않는다. 아래 방법은 상황에 맞춰 검토할 제안이며, 모든 개발자에게 같은 생활 방식을 요구하는 규칙은 아니다.

## 핵심 명제

- **실무와 학습 연결**: 실무에서도 새로운 문제를 배우고 검증할 수 있다. 반복 업무만으로 채워지지 않는 부분은 별도 학습으로 보완한다.
- **적용으로 확인**: 읽은 분량보다 현재 문제를 설명하고 해결하는 능력이 달라졌는지 본다.
- **자기 점검**: 모르는 부분뿐 아니라 시간, 건강, 돌봄과 자원 제약도 확인한다. 실행하지 못한 이유를 나태로 단정하지 않는다.
- **환경도 선택 대상**: 현재 환경의 개선을 시도할 수 있지만, 그것이 이직을 검토하기 위한 필수 선행 조건은 아니다.

## 커리어 오너십 — 회사는 내 기술력을 사는 고객

회사를 고객처럼 생각하는 비유는 자신이 제공하는 가치를 돌아보는 데 사용할 수 있다. 다만 실제 고용관계의 책임을 개인에게 모두 넘기는 비유로 사용하지 않는다.

- **개인이 선택한 학습**: 관심 분야 탐색과 커리어 준비는 목표와 비용을 스스로 검토한다.
- **업무에 필요한 지원**: 온보딩, 업무 수행에 필요한 교육과 합의된 지원은 조직의 역할과 함께 확인한다. 모든 교육비와 시간을 개인 부담으로 간주하지 않는다.
- **지원 조건 확인**: 자발적 학습과 회사가 지시한 교육을 구분하고, 계약, 취업규칙과 적용 법령에 따른 시간과 비용 처리를 확인한다.
- **멘토의 역할 합의**: 질문 응답, 코드 리뷰와 학습 설계 중 어디까지 돕는지 합의한다. 사수의 존재만으로 지원을 보장하거나 교육 역할이 전혀 없다고 단정하지 않는다.

지원 문화는 [[Company-Selection-Criteria|회사 선택 기준]]의 일부다. 자신이 선택할 수 있는 행동과 조직에 필요한 조건을 함께 살피는 것이 커리어 오너십이다. 관련 관점은 [[Software-Craftsmanship-Professionalism|소프트웨어 장인정신과 프로페셔널리즘]]에서 이어진다.

## 자기계발의 8가지 방법

### 1. 구체적 목표

예를 들어 영어 실력을 높인다는 목표를 짧은 기술 문서를 읽고 적용 조건을 설명하는 과제로 바꾼다. 목표가 아직 탐색 단계라면 작은 시도 후 무엇이 필요한지 다시 정한다.

### 2. 알아차림 (Self-Awareness)

무엇이 부족한지, 무엇을 고치고 싶은지 주기적으로 점검한다. 한 주축을 정하고 다른 필요는 짧은 보충으로 구분하면 진행을 추적하기 쉽다.

### 3. 시간 관리

하루 30분은 시작 가능한 예시이지 최소 의무 시간이 아니다. 집중이 필요한 작업과 자투리 시간의 복습을 구분하고, 휴식이 필요한 날에는 양을 줄인다. 현재 채택한 학습 트랙과 진행 상태는 로드맵에서 확인한다.

### 4. 직장-집 거리 최소화

통근 시간과 피로가 학습 여유에 미치는 영향을 고려한다. 원격 근무 여부와 주거 비용, 가족 일정 등을 함께 비교하며 공통 통근 상한을 정하지 않는다.

### 5. 지속성

학습 기간은 주제와 출발점에 따라 다르다. 다시 점검할 시점을 정하고 기억, 설명과 실제 적용이 달라졌는지 확인한다.

### 6. 느슨한 진행

완벽주의는 지치게 한다. **가늘고 길게** — 다이어트 중에 원하는 음식을 가끔 먹듯.

### 7. 즐거움 추구

흥미와 지속 가능성을 고려하되, 현재 목표에 필요한 연습과 피드백이 포함돼 있는지도 본다.

### 8. 저비용 자원 활용

유튜브, 팟캐스트, 무료 강의, 도서관. 비싼 도구 = 동기부여가 아니다.

공공 학습 플랫폼도 있다. [KOCW 대학공개강의](http://www.kocw.net), [서울시 평생학습포털](https://sll.seoul.go.kr), [경기도 평생학습포털 GSEEK](https://www.gseek.kr), [네이버 비즈니스 스쿨](https://bizschool.naver.com), [전 국민의 평생학교 EBS](https://home.ebs.co.kr/lifelong/main), 1인 사업자에게는 [서울특별시 소상공인아카데미](https://edu.seoulsbdc.or.kr)와 [소상공인시장진흥공단의 소상공인 지식배움터](https://edu.sbiz.or.kr)가 있다. 강좌별 비용과 수강 자격은 각 사이트에서 확인한다(2026-09-30 사이트 접속 확인). 사이트 목록보다 무엇을 어떤 순서로 배울지 스스로 커리큘럼을 짜는 일이 더 어렵고 중요하다.

## SI/레거시 환경에서 벗어나기

SI나 레거시라는 분류만으로 성장 가능성을 판단하지 않는다. 맡는 문제, 피드백, 운영 책임과 개선 권한을 확인한다. 오래된 시스템에서도 재사용할 역량을 쌓을 수 있고, 최신 기술 조직에서도 학습이 제한될 수 있다.

### 환경을 검토할 신호

- 반복되는 문제를 개선할 권한과 지원이 부족하다.
- 리뷰와 피드백을 얻기 어렵고, 중요한 결정의 이유를 배울 경로가 없다.
- 현재 쌓는 경험과 원하는 역할의 요구가 멀어지고 있다.
- 건강과 생활에 미치는 부담을 조정하기 어렵다.

### 이동 전 확인과 준비

원하는 역할의 실제 요구를 보고 경험으로 증명할 부분과 새로 배울 부분을 나눈다. 준비 기간은 개인마다 다르므로 최소 1~2년 같은 공통 기한을 두지 않는다. 선배 개발자 수만으로 성장 환경을 판단하지 않고 리뷰 시간과 의사결정 참여 기회를 확인한다.

개인 프로젝트, 공개 글과 커뮤니티는 경험을 설명할 선택지다. 회사 코드, 고객 데이터나 내부 정보를 허가 없이 공개하지 않는다.

### 당장 이동하지 않을 때

현재 권한 안에서 테스트, 리뷰나 배포 절차의 작은 개선을 제안할 수 있다. 효과와 비용을 확인하고 지원이 필요한 부분을 협의한다. 조직을 바꾸지 못했다는 사실을 개인의 의지 부족으로 해석하지 않는다.

## 클린 코드 연습

읽기 쉬운 코드뿐 아니라 요구 충족, 실패 처리와 변경 안전성을 함께 연습한다. 개인 프로젝트는 실험장이 될 수 있고, 업무 안에서 허용된 개선도 학습 기회다. 책의 규칙을 기계적으로 적용하기보다 실제 변경과 리뷰에서 장단점을 확인한다.

## 영어 학습: 복리 효과

여기서 복리는 자료 접근과 반복 학습의 누적을 설명하는 비유다. 영어를 공부하면 개발 실력이 일정 비율로 증가한다는 검증된 인과관계나 수익률을 뜻하지 않는다.

### 연구가 보여 주는 범위

Prat 등의 2020년 연구는 36명이 45분씩 10회 Python을 학습한 결과의 개인차를 조사했다. 초록의 언어 적성 17%, 유동 추론과 작업 기억 34%는 여러 학습 결과 변수에 걸친 설명 분산 요약이다. Python 학습 속도 하나의 고정 기여율이나 영어 공부의 효과 크기가 아니다. 상관과 예측 결과를 특정 훈련의 인과 효과로 바꾸지 않는다.

Ivanova 등의 2020년 fMRI 연구에서는 Python과 ScratchJr 코드 이해에 다중요구(MD) 체계가 강하게 반응했고, 자연어 체계의 반응은 약하거나 없었다. 따라서 코드 읽기와 영어 읽기가 같은 뇌 영역을 쓴다는 설명으로 영어 학습 효과를 보장할 수 없다. 이 연구 역시 모든 프로그래밍 과제와 학습 단계의 뇌 기제를 확정한 것은 아니다.

### 구체적 실천

- 필요한 공식 자료를 원문과 번역으로 대조하고, 조건과 예외를 자기 말로 설명한다.
- 영어 이슈나 리뷰가 필요한 환경에서는 실제로 전달할 문장을 작성하고 피드백을 받는다.
- 커밋과 문서의 언어는 협업 규칙과 독자에 맞춘다. 영어 사용 자체를 실력의 척도로 삼지 않는다.
- 듣기와 말하기가 필요하면 [[English-Learning-Phonics|영어 학습과 발음 훈련]]의 과제별 선택을 참고한다.

### 작업 기억과 실제 과제

작업 기억과 학습 결과의 관련성만으로 기억 훈련이 개발 능력을 높인다고 결론 내리지 않는다. 문서 내용을 재구성해 설명하거나 실제 코드를 추적하는 연습은 해당 과제의 이해로 평가한다.

## 커뮤니티 참여

회사 밖에서 다른 경험과 피드백을 얻을 수 있다. 외부 커뮤니티에도 이해관계와 공개 범위가 있으므로 조언의 맥락을 확인한다.

- 외부에 고민을 공유할 때 익명 처리만으로 충분하다고 가정하지 않고 기밀과 개인 식별 가능성을 확인한다
- 발표, 운영, 조직 경험으로 **회사가 주지 않는 역할**을 연습
- 맞는 커뮤니티가 없으면 **직접 창설** — "목마른 사람이 우물 판다"
- 시작부터 완벽할 필요 없음 — 부족한 부분은 구성원이 채워감

## 업계 네트워킹의 실익

- 이력서, 포트폴리오를 외부인과 리뷰 → 시장 기준 캘리브레이션
- 강의, 웨비나, 컨퍼런스 참가로 **자연스러운 인맥**
- **헤드헌터, 리쿠르터와 장기 관계** — 예상치 못한 좋은 기회의 주요 경로
- 이직 시기가 아닐 때도 유지 — 구직 후 급조는 늦다

## 회고의 완성은 Action Item

회고가 단순 다짐에 그치면 효과가 없다. **실행 가능한 수준의 액션 아이템**을 도출해야 루프가 완성.

- 예: 다음 스프린트에 반복된 결제 실패를 재현하는 테스트를 추가하고 수정 전 실패, 수정 후 통과를 확인한다. 커버리지 수치만으로 개선을 판정하지 않는다.
- 주 단위 15분처럼 작은 회고를 시도하고 필요에 따라 조정한다
- 팀에도 반복적으로 본인 방향성을 공유 → 조직이 적응

## 흔한 함정

- **목표 과부하**: 동시에 감당할 수 있는 범위인지 확인하고 주축을 정한다
- **완벽주의** — 30%만 해도 지속 + 시작 > 100% 완성도 1회
- **이직의 자동 해결 기대**: 바뀔 조건과 남을 조건을 확인하되 현재 환경을 먼저 고쳐야 한다는 의무는 두지 않는다
- **동료와의 비교** — 성장 속도는 개인차 큼. 자기 기준과 어제의 나에 비교 ([[Peer-Comparison-Anxiety|동료 비교 불안]])
- **학습이 출력으로 이어지지 않음** — 글, 코드, 발표로 **내보내는 습관**이 학습 각인

## 면접 체크포인트

- 본인의 **회사 밖 성장 루프** 2~3개를 구체 예시로 말할 수 있는가
- 자기계발 8가지 중 지속 중인 것 **2~3개**
- 영어 자료 활용의 구체 사례(최근 읽은 공식 문서, 영문 블로그)
- 실패한 자기계발 시도 + 거기서 얻은 교훈
- 현재 환경에서 시도한 **자기주도적 개선** 사례
