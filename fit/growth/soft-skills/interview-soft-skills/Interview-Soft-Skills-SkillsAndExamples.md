# 인성면접 가이드 — 예시 질문, 탈락 요인, 체크리스트

## 인성면접 예시 질문과 해석

### 질문 1: 팀 프로젝트에서 기여 역량과 동료에게 바라는 역량
> 업무를 할 때 어떤 요소를 중요한 가치로 생각하는지, **자기 객관화** 파악

### 질문 2: 쇼핑몰 장바구니→주문/결제 프로세스 설명
> 회원, 장바구니, 쿠폰, 상품 관리, 주문, 결제, 배송, 반품, 환불, CS, 정산에 대한 **업무 파악 능력**

정상 흐름 설명을 넘어 **엣지 케이스 이해의 깊이**를 본다. 주문 페이지에 트래픽이 몰리면 무엇이 일어나고 어떻게 풀지 같은 파생 질문도 정상 프로세스가 아니라 예외 상황의 대처를 묻는다. 예를 들어 결제 대행사 장애로 결제가 실패하면 다른 결제 대행사로 결제를 유도하는 이중화를 설명할 수 있어야 한다. 단, 대체 경로로 넘기는 것은 원 거래가 실패로 확정된 경우로 한정한다. 타임아웃처럼 승인 결과가 불명확한 건은 결제 상태 조회와 대사로 먼저 닫아야 이중 결제를 막는다 ([[Payment-Reconciliation-Worker|결제 대사 worker]], [[External-API-Integration-Patterns|외부 API 연동 실전 패턴]]).

### 질문 3: 좋은 코드, 견고한 소프트웨어가 무엇인가?
> 꾸준한 관심을 가지고 **개발자로서 성장을 지속하는지** 확인. 스스로 고민을 많이 해봐야 함

주니어와 시니어 모두 받는 질문이다. 원전을 참고해 자기 정의를 세워 둔다. 예를 들어 코드를 주된 문서로 보는 관점(Code as Documentation)은 코드만이 유일한 문서라는 뜻이 아니라, 코드가 문서로 읽히려면 명확성에 노력을 들이고 동료 피드백을 받아야 한다는 뜻이다 ([[Code-Quality-Criteria|코드 품질 기준]]).

### 질문 4: 동료 코드가 배포마다 버그/장애를 유발하면?
> 실수를 방지하기 위한 **제도적인 장치**에 대한 고민 (코드 리뷰, 테스트, CI/CD 게이트 등)

### 질문 5: 새 기술 적용 vs 일정 부족, 본인의 입장과 설득 방법
> 기술, 품질, 일정 간의 **트레이드오프** 조정과 합리적인 안을 찾아가는 방법

### 질문 6: 어려웠던 문제 해결, 동료에 긍정적 영향을 미친 사례
> 조직에 **좋은 영향력**을 미치는 사람인가, 임팩트 있는 업무를 어떻게 해결했는가

### 질문 7: 데일리 미팅에 매번 지각하고 핑계를 대는 동료에게 어떻게 변화를 당부하겠는가?
> **팀워크와 문제 해결 태도**. 정답보다 문제 인식부터 해결책까지 합리적이고 이성적으로 도달하는 과정을 본다. 개인을 비난하기보다 팀의 일하는 방식과 그라운드 룰로 풀고, 그 기준이 보편타당한지, 회사 입장과 어떻게 조율하는지, 근본 해결이 어려우면 어떤 대안을 두는지까지 말한다. 지각이나 버그 양산 같은 문제에 그라운드 룰을 세워 본 실제 경험이 있으면 강한 근거가 된다

### 질문 8: 퇴사자의 코드에서 시스템 접근 정보가 하드코딩된 것을 발견했다면?
> 개발 프로세스 부재가 만든 **보안 위험의 인식과 우선순위 판단**. 고객 정보 유출로 이어질 수 있으면 최우선 과제로 두고, 이를 근거로 의사결정권자를 설득한다. 노출된 자격증명의 폐기와 교체, 저장소 히스토리 전체 스캔, 접근 기록 확인이 먼저이고 ([[Hardcoded-Credentials|하드코딩된 자격증명]]), 이어서 중앙집중형 시크릿 관리를 담당 애플리케이션에 먼저 적용해 검증한 뒤 전사 사용법으로 정리해 전파한다 ([[Secret-Management|시크릿 관리]])

## 소프트웨어 품질관리와 기술부채

### 품질과 시간의 트레이드오프
- 모든 업무에는 데드라인이 존재하며, 일정 지연은 비용
- 개인의 입장과 회사의 입장 중 무엇이 우선인가를 항상 고려

### 기술부채 관리 영역
- 소스포비아 (코드 공포증) 해소
- 업무 속도 저하 원인 분석
- 결함/버그 추적 관리
- 히스토리 관리
- 테스트 및 자동화
- 아키텍처 개선
- 코딩 가이드, 코드 리뷰 가이드 배포

## 기술면접 탈락 요인과 사례

### 자주 나오는 탈락 사유
1. **기술 스택은 일치하지만 구사 수준/이해도가 기준 미달**
   - 이력서에 적혀 있는 건 많은데 정작 꼬리 질문에서 막힘
2. **이력서에 적은 내용을 증명하지 못하는 경우**
   - "주도했다" / "최적화했다" / "설계했다"의 실제 근거가 나오지 않음
3. **주장은 있으나 실전에서 증명 불가**
   - "클린 아키텍처를 중시합니다" → 왜 그게 필요했는지, 실제로 어떻게 적용했는지 설명 불가
4. **연차 대비 아키텍처/인프라 지식 부족**
   - 3년차가 DB 인덱스 / 트랜잭션 격리 수준을 모름
   - 5년차가 로드밸런서 / 캐시 계층 설계를 못 함
5. **기술적 답변이 모호하고 장황해서 커뮤니케이션이 어려운 경우**
   - 질문의 핵심을 파악 못 하고 주변만 맴돔
6. **분명히 잘 아는 것 같은데 대답을 잘 못하는 경우**
   - 공부는 되어 있는데 **설명 훈련**이 안 됨 → "아는 것"과 "설명할 수 있는 것"은 다름

### 왜 이런 사례들이 나오는가
- 기본적으로 **업무를 통해 성장하는 것이 가장 중요**
- "이걸 왜 쓰게 되었는가?"에 대한 **근본적인 호기심**이 있어야 함
- 사용하는 기술셋을 **내 것으로 만들려는 노력**이 있어야 함
- 업무에서 그런 기회가 없다면 **스터디, 개인/팀 프로젝트**로 개발과 운영 이슈를 직접 고민하고 해결해본 경험을 쌓아야 함

### 답변에서 드러나는 탈락 패턴
빈도로는 기술 스택은 맞지만 구사 수준이 기준에 살짝 못 미치는 경우가 가장 많고, 이력서 내용을 증명하지 못하는 경우, 연차 대비 아키텍처와 인프라 지식이 부족한 경우가 뒤를 잇는다는 면접관 관찰이 있다(대형 서비스 기업일수록 레벨별 기준이 높다). 지식은 탄탄한데 소프트 스킬로 전달하지 못하는 경우도 잦다.
- **기회가 없었다는 답**: 이미 세팅된 기술로 일해 도입 이유를 모르고, 원래 그렇게 개발되어 있어 바꾸거나 새로 적용할 기회가 없었다고 답하면 자기 이력과 노력이 매력 없다고 고백하는 것과 같다. 의사결정자가 아니었어도 왜 그 기술을 쓰는지 파고든 흔적을 보여야 한다.
- **운영 공백**: 개발만 해서 운영에서 생기는 문제를 모르거나 그 반대인 경우다. 운영 이슈가 기술면접의 절반 가까이를 차지한다고 보는 면접관도 있고, 장애 추적과 해결 경험을 물으면 답하지 못하는 지원자가 많다.
- **장황함의 원인**: 겪지 못한 영역은 관심이 없어 모르고, 해 온 일도 깊게 파지 않아 모호하게 알면 답이 길어진다. 사유 5의 증상은 대개 여기서 온다.
- **주장과 증거의 불일치**: 열정적인 개발자라고 소개했다면 노력의 결과물이 보여야 한다. 오픈소스에 관심이 많다고 썼는데 활동 내역이 빈약하거나 적용 경험이 없으면 오히려 감점이다. 실무에 적용해 문제를 푼 경험 없이 공부만 한 것이 채용 이유가 되는지 냉정하게 본다.

### 기초 체력
- **CS, 알고리즘, 네트워크, 자료구조, 주력 언어, 프레임워크**
- 이걸 **설명할 수 있는 소프트 스킬**을 갖추어야 함 — 아는 것만으로는 부족
- 면접관은 지원자의 설명을 통해서만 판단할 수 있음

### 탈락했을 때 점검 체크리스트
- [ ] 어떤 질문에서 막혔는가? (기술? 경험? 태도?)
- [ ] 이력서에 쓰인 내용을 꼬리 질문 3단계까지 답할 수 있는가?
- [ ] 같은 질문이 다시 나오면 답할 수 있도록 노트 정리했는가?
- [ ] 연차 대비 부족한 영역이 무엇인지 객관적으로 확인했는가?
- [ ] 다음 면접 전까지 보강할 1~2개 핵심 주제를 정했는가?
- [ ] 쓰고 있는 주요 기술마다 도입 이유를 설명할 수 있는가?
- [ ] 최근 장애나 운영 이슈 하나를 추적부터 재발 방지까지 말할 수 있는가?
- [ ] 이력서의 열정, 관심 주장마다 결과물이나 적용 사례가 있는가?

## 인성면접 주의사항 체크리스트

- [ ] 이론적 내용이나 전체 과정을 머릿속에서 정리
- [ ] 리더십, 그라운드룰에 대한 이해
- [ ] 회사의 문화, 인재상을 미리 찾아서 정리
- [ ] 실수를 방지하기 위한 제도적인 장치 고민
- [ ] 일정과 품질의 트레이드오프 고려
- [ ] 내 직무의 역량이나 열정 정리
- [ ] 조직의 컬처핏, 협업이나 커뮤니케이션 사례
- [ ] 동료들에게 긍정적인 영향을 미친 사례 준비
- [ ] **외워서 말하지 않기** — 동작 방식, 운용 방식, 문제 해결 경험을 정리해두고 **말로 설명하는 훈련**
