# 현재 목표와 통합 로드맵

키노라이츠 적응을 최우선으로 하면서 생활과 장기 개발자 성장 목표를 함께 잃지 않기 위한 상위 계획이다. 모든 목표를 동시에 실행하지 않고 성격에 따라 운영 방식을 나눈다.

## 현재 기준

- 이직 목표는 2026-06-29 키노라이츠 입사로 완료했다. 현재 서류 지원은 하지 않는다.
- 현재 가장 중요한 결과는 키노라이츠의 팀 맥락을 익히고 맡은 일을 독립적으로 끝내는 것이다.
- 기술 학습은 현재 결과에 연결되는 주제를 먼저 고른다. 현재 개인 학습의 1순위는 검색이며, 2026-08-10부터 검색 학습이 집중 자리를 점유한다. 이는 현재 역할과의 연결성을 근거로 내가 선택한 개인 학습이며, 회사의 지시나 평가 기준을 뜻하지 않는다.
- GraphQL, Redis와 Git은 검색보다 앞선 별도 목표가 아니라 실무에서 반복되는 빈칸을 닫는 공통 기반이다.
- 수학은 정규 개인 학습 트랙 지위를 보존하되 0단계 시작 전에서 보류 중이다. DevOps는 미래 역할을 위한 투자이며 검색과 현재 역할 기술보다 앞세우지 않는다.
- JS, TS와 Node.js를 시작으로 한 범용 백엔드 목표도 보존한다. 전문화 경로와 동시에 정규 진도를 열지 않는다.
- 주일학교 출석부는 퇴사 후 실행할 수 있는 조건부 선택지다. 재직 중에는 현재 Free Core의 최소 운영, 장애와 보안 대응, 데이터 보호 및 프로젝트 고정비 절감만 수행하고 신규 기능, 마케팅과 유료 실험은 열지 않는다. 자발적으로 유입된 신규 조직의 현재 기능 사용은 막지 않지만 능동적 모집과 수동 온보딩은 하지 않는다. 퇴사를 실제로 확정하고 사용자가 활성화를 명시한 경우에만 실험 준비를 열며, 준비 확인 뒤 시작일과 종료일을 동시에 확정한 한시적 사업 실험을 시작한다.
- 개인 고정비 절감은 퇴사 후 선택 가능한 기간을 늘리는 준비다. 개인 비용 금액은 이 저장소에 기록하지 않고 출석부의 프로젝트 비용 및 손익과 분리한다.

## 목표 지도

| 영역 | 목표 | 운영 방식 |
|---|---|---|
| 현재 본업 | 키노라이츠 적응과 결과 만들기 | 입사 초기에는 맡은 일을 결과 확인까지 독립적으로 끝내는 것을 최우선으로 함 |
| 역할 연계 개인 학습 | 검색 | 현재 역할과의 연결성을 근거로 선택, 현재 집중 자리 점유 |
| 공통 학습 기반 | GraphQL, Redis, Git | 실제 업무에서 만난 빈칸은 공개 예제와 로컬 실습으로 재현해 닫음 |
| 심화 학습 | 수학 기초 | 단일 정규 트랙, 0단계 시작 전 보류 |

| 미완료 학습 자료 | 밀린 기술 책과 강의, GitHub 기록 | 선택한 심화 트랙에 필요한 자료만 한 번에 하나 |
| 그 밖의 응용 기술 | 현재 책임과 반복 사용 스택 | 필요가 확인되면 미래 투자와 일반 백로그보다 먼저 학습 |
| 미래 역할 투자 | DevOps, Terraform → Kubernetes | 더 급한 응용 기술 빈칸과 업무 부담을 먼저 확인한 뒤 단일 트랙으로 선택 |
| 자격 증명 | AWS, Kubernetes와 정보처리기사 | 선행 실습과 필요성 확인 뒤 한 번에 하나 |
| 생활 유지 | 집에서 운동, 미독 자기계발서 읽기 | 작은 최소 습관 |
| 생활 프로젝트 | 운전면허, 전세 알아보기 | 둘 중 하나만 활성화 |
| 관찰 목록 | [마케팅 학습 자료](https://pudufu.s3.ap-northeast-2.amazonaws.com/index.html) | 제품 배포와 유입 문제가 생길 때 검토 |
| 조건부 제품 선택지 | 주일학교 출석부 | 재직 중 최소 운영과 프로젝트 고정비 절감, 전환 gate 후 준비 확인과 제한된 기간의 실험 시작 |

## 전체 WIP 상한

키노라이츠 근무 시간 밖의 개인 활동은 다음 두 자리만 사용한다.

1. 유지 자리: 운동은 유지하고, 독서와 커리어 아웃풋 중 하나만 그 주에 선택한다.
2. 집중 자리: 수학, 현재 역할과 연결해 개인적으로 선택한 응용 기술 학습과 생활 프로젝트 중 하나만 활성화한다.

키노라이츠 업무 회복이 필요하면 집중 자리를 비운다. 실무에 필요한 기술 학습을 집중 자리에 둘 수 있지만, Task 중 만난 빈칸 보충만으로는 새 정규 트랙을 열지 않는다. 2026-08-10부터 검색 학습이 집중 자리를 점유하고 수학은 보류 상태다. 새 주제를 열려면 활성 주제를 닫거나 보류하고, 후보가 경합하면 그 시점에 우선순위를 다시 정한다. 재직 중 출석부의 선택지 보존 작업은 집중 자리를 점유하지 않고 필요한 최소 운영과 비용 조정만 처리한다. 퇴사를 확정한 뒤 사용자가 출석부 활성화를 명시하면 현재 트랙의 위치를 기록하고 전체 WIP를 다시 계획한 뒤 제한된 기간의 실험 자리를 정한다. 놓친 활동을 다음 주에 더하지 않는다.

## 운영 바구니

### 1. 당장 해야 하는 일

고정 목록이 아니라 이번 주나 다음 주에 마감되거나 다른 사람의 일을 막는 항목만 둔다.

| 할 일 | 마감 | 완료 조건 | 다음 행동 하나 | 의존하는 사람/자료 | 예상 시간 |
|---|---|---|---|---|---|

- 키노라이츠 업무의 실제 상태는 회사의 공식 Task에서 관리한다.
- 개인 필수 항목을 별도로 추가하지 않는다. 유지 자리와 집중 자리에서 고른 다음 행동만 이번 주 필수 항목이 되며, 새 항목을 넣으려면 둘 중 하나를 교체한다.
- 현재 집중 자리의 다음 행동은 [[OpenSearch#시작 전: 실물 익히기|OpenSearch 시작 전 gate]]의 첫 요청으로 local cluster root 응답을 확인하고 설명하는 것이다. 기한과 예상 시간은 아직 정하지 않아 당장 해야 하는 일 표에는 넣지 않는다.

### 2. 지속적으로 유지하는 일

2026-08 기준 첫 4주 동안 아래 최소 기준을 시험하고 월간 회고에서 조정하기로 했다. 실행 여부는 회고 근거 없이 완료로 간주하지 않는다.

- 집 운동은 주 2회, 회당 20분을 기준으로 삼고 못 한 횟수를 다음 주에 보충하지 않는다.
- 독서는 주 2회 20분, 커리어 아웃풋은 주 1회 중 하나만 그 주의 선택 유지 활동으로 고른다.
- 자기계발서를 고르면 한 번에 한 권만 읽고, 완독 수보다 현재 문제에 적용할 문장 하나를 남긴다.
- 커리어 아웃풋을 고르면 10분 말하기 또는 한 페이지 쓰기로 현재 학습이나 업무를 내부 세부 없이 설명한다.
- 집중 자리 활동은 역할 연계 개인 학습이 점유 중이면 퇴근 후 우선으로 진행하고, 다른 개인 트랙이 점유 중이면 업무 부담이 낮은 주에만 1회 또는 2회 진행하며, 밀린 진도를 압축하지 않는다.

말하기와 쓰기는 별도 강의를 하나 더 여는 일이 아니다. 이미 다룬 내용을 설명해 이해의 빈칸을 찾는 유지 습관이다. 정식 블로그 글은 해당 기술이 정규 트랙이거나 집중 자리를 점유한 역할 연계 개인 학습일 때 공개 가능한 범위에서 완성한다.

전체 글감은 [[Career-Technical-Output-Backlog|커리어 기술 아웃풋 백로그]]에 보관한다. 목록 전체를 일정으로 바꾸지 않고 선택한 개인 트랙이나 공개 가능한 독립 재현과 연결된 초안 하나만 꺼낸다.

밀린 기술 책과 강의는 완주 자체를 별도 목표로 병행하지 않는다. 현재 심화 트랙의 gate를 닫는 데 필요한 자료 하나만 고르고, 실험, 설명이나 작은 구현을 GitHub 기록으로 남긴 뒤 다음 자료를 연다.

### 3. 단일 심화 트랙

현재 집중 학습은 검색이다. [[2026-H2-Math-Roadmap|수학 기초]]은 정규 개인 학습의 재개 대상이지만 0단계 시작 전에서 보류 중이며, 기록과 재개 조건은 해당 문서의 진행 상태 절을 따른다. 현재 검색 학습은 이 gate를 기다리지 않고 먼저 진행한다. 별도 커리큘럼을 동시에 열지는 않으며 업무 부담이 크면 활성 학습을 보류하고 현재 위치를 기록한다.

수학 2단계 gate와 첫 90일 회고를 모두 마치면 첫 선택 gate를 연다. 이후 각 모듈의 성공선을 닫을 때마다 아래 순서로 후보를 다시 만든다.

1. 다음 계획 기간의 역할 책임과 직접 연결해 개인적으로 선택할 응용 기술
   - 현재 1순위인 검색
   - 검색 업무와 다른 Task에서 만난 GraphQL과 Redis의 미완료 빈칸
   - 현재 Task나 반복 책임에 연결된 JS, TS, Node.js, gRPC, Kafka와 그 밖의 기술
2. 긴급한 응용 기술 빈칸이 없고 미래 역할에 투자할 여력이 있을 때 [[2027-DevOps-Practical-Roadmap|DevOps]]
   - Terraform 성공선을 먼저 닫고 다시 선택한 경우에만 Kubernetes로 진행
3. 범용 백엔드 대기열의 다음 미완료 모듈
   - [[Node-Core-Output-Roadmap|JS, TS와 Node.js 코어]]
   - CS, OOP, 디자인 패턴과 헥사고날 및 클린 아키텍처
   - 시스템 디자인
   - MySQL
4. 새 트랙을 열지 않고 현재 책임과 회복에 집중

역할 연계 응용 기술, 미래 DevOps 투자, 범용 백엔드 대기열 순서로 비교한다. 응용 기술 안에서는 현재 검색 학습 gate를 먼저 닫고, 그 과정에서 막힌 빈칸, 사용 빈도와 결과 영향을 비교한다. GraphQL과 Redis는 심화 후보가 될 수 있지만 검색보다 높은 별도 1순위는 아니다. Git은 정규 트랙 후보로 올리지 않고 실제 상황과 맞는 [[git#상황별 작은 gate|작은 gate]] 하나만 닫는다.

Node.js가 현재 역할 책임과 직접 연결되면 응용 기술 후보로 올라가고, 그렇지 않으면 범용 백엔드 대기열에 남는다. gRPC, Kafka, 검색과 추천도 반복 책임과 학습 필요가 확인되면 응용 기술 후보로 올린다. DevOps 역시 현재 역할에 필요해지면 미래 투자와 분리해 필요한 범위만 우선 보충한다.

### 4. 생활 프로젝트와 조건부 제품 선택지

운전면허와 전세는 같은 기간에 함께 열지 않는다. 필요 시점, 비용과 준비 시간을 확인해 하나를 4주짜리 생활 프로젝트로 올리며, 그 기간에는 집중 자리를 점유하던 트랙을 보류한다.

주일학교 출석부는 재직 중 활성 제품 트랙으로 병행하지 않는다. 현재 Free Core의 최소 운영, 장애와 보안 대응, 데이터 보호 및 프로젝트 고정비 절감만 수행해 퇴사 후 실행할 선택지를 보존한다. 자발적으로 유입된 신규 조직의 현재 기능 사용은 막지 않지만 능동적 모집과 수동 온보딩은 하지 않는다. 개인 고정비 절감은 퇴사 후 선택 가능한 기간을 늘리는 별도 준비이며 프로젝트 손익에 섞지 않는다.

퇴사를 실제로 확정하고 사용자가 출석부 활성화를 명시한 때를 전환 gate로 삼는다. gate를 통과하면 진행 중인 개인 트랙의 위치를 기록하고 출석부의 현재 상태와 계측 준비를 먼저 확인한다. 준비가 끝나면 실험 시작일과 종료일을 동시에 정하고, 종료일에는 연장부터 논의하지 않고 장기 옵션을 판정한다. 정확한 실험 기간은 공개 승인 전 이 저장소에 다시 적지 않으며 활성화 시 보호된 운영 기록에 고정한다. 퇴사 가능성을 검토하는 상태만으로는 신규 기능, 마케팅과 유료 실험을 시작하지 않는다.

## 업무 연계 기술 우선 원칙

실무에 필요한 기술은 미래 투자나 호기심보다 먼저 다루되 모두를 동시에 공부하지 않는다. 현재는 검색 학습을 먼저 진행하고, 실제 Task에서 만나는 기술 빈칸 하나를 아래 흐름으로 닫는다.

```text
현재 업무 문제
  → 필요한 개념과 도구만 확인
  → Task, PR, QA 또는 운영 결과
  → 공개 가능한 작은 설명이나 결정 기록
  → 집중 자리 트랙의 현재 위치로 복귀
```

- GraphQL은 실제 요청 하나의 schema, resolver와 하위 데이터 흐름을 추적하고 오류, 인증, nullability 또는 N+1 중 해당 문제의 경계를 설명할 수 있을 때 빈칸 하나를 닫는다. 공개 문서에는 구조와 원리를 일반화해 남긴다.
- Redis는 실제 key의 정본, 자료구조, TTL, 무효화와 실패 시 동작을 추적하고 정확성, race condition 또는 stampede 중 해당 문제의 경계를 설명할 수 있을 때 빈칸 하나를 닫는다. 공개 문서에는 내부 key와 운영값을 남기지 않는다.
- Git은 현재 commit graph, working tree/index, local/remote ref와 upstream 상태를 먼저 읽고 merge, rebase, cherry-pick 또는 복구 선택의 이유를 설명할 수 있을 때 빈칸 하나를 닫는다. 실습 gate는 [[git#실무 학습 순서|Git 실무 학습 순서]]를 따른다.
- GraphQL, Redis와 Git은 반복 사용이 확인된 공통 실무 기반이다. 업무에서 얻은 근거를 비식별화한 한 페이지 설명이나 10분 말하기로 남기되 검색보다 앞선 별도 대형 커리큘럼을 열지 않는다.
- 그 밖의 기술은 현재 책임에 필요하거나 독립된 업무에서 같은 빈칸이 반복되면 개인 심화 후보로 올린다. 실제 우선순위와 회사의 평가 기준을 공개 문서에서 추정하지 않는다.

사용했다는 사실이나 문서를 읽었다는 사실만으로 숙련 또는 로드맵 통과로 계산하지 않는다.

## 미래 DevOps 방향

DevOps는 현재 역할에 필요한 응용 기술보다 앞서는 당장 과제가 아니라 미래 역할을 위한 투자다. 업무 결과와 회복을 해치지 않는 선택 gate에서만 열고, Terraform으로 인프라 변경과 상태를 먼저 다룬 뒤 gate를 다시 통과하면 Kubernetes로 배포와 운영을 확장한다. 미래에 Terraform이나 Kubernetes가 현재 책임에 필요해지면 이 순서를 기다리지 않고 업무 연계 기술 우선 원칙으로 필요한 범위만 먼저 해결한다.

## 자격증 전환 조건

- AWS 자격증은 [[2027-DevOps-Practical-Roadmap|DevOps 핵심 실습]]으로 배포, 관측과 복구를 검증한 뒤 업무 필요와 시험 범위를 보고 판단한다.
- Kubernetes 자격증은 로컬 Kubernetes와 실제 운영 빈칸을 확인한 뒤 판단한다.
- 정보처리기사는 기술사 경로의 필요성과 시험 일정을 확인한 시점에만 연다. 준비 기간에는 다른 정규 심화 트랙을 멈춘다.
- 세 자격증을 동시에 준비하지 않는다.

## 첫 90일 운영

2026-06-29을 1일차로 센 90일째인 2026-09-26까지는 다음을 우선한다.

- 맡은 작업 하나의 사용자 목적, 요청과 데이터 흐름, 소비자 영향, QA, 배포와 롤백을 설명한다.
- 리더, PM과 시니어 개발자의 기대 결과와 완료 조건을 면담 뒤 확인한다.
- 작은 업무라도 배포와 결과 확인까지 한 사이클을 닫는다.
- 기술 학습은 현재 선택한 검색 학습 gate를 먼저 돕는다. GraphQL, Redis와 Git은 역할 수행 중 발견한 빈칸을 공개 예제와 로컬 실습으로 닫고 작은 설명을 남기되 별도 개인 커리큘럼은 열지 않는다.
- 수학은 보류 상태이며, Node.js 정규 트랙과 자격증 준비는 열지 않는다.
- DevOps는 미래 투자로 대기시키고 역할 적응과 더 급한 응용 기술을 밀어내지 않는다.
- 운전면허와 전세는 기본적으로 대기한다.
- 주일학교 출석부는 현재 Free Core의 최소 운영과 프로젝트 고정비 절감으로 선택지만 보존하고, 능동적 모집, 수동 온보딩, 신규 기능, 마케팅과 유료 실험은 열지 않는다.

## 월간 회고

- 키노라이츠에서 새로 독립적으로 끝낸 업무 단위는 무엇인가
- 다른 역할의 결정이 필요했던 지점을 얼마나 일찍 공유했는가
- 다음 달의 업무와 생활 부담은 어느 정도인가
- 현재 심화 트랙을 유지할 개인 선택 근거가 있는가, 역할과의 연결은 아직 유효한가, 보류 중인 트랙은 재개 조건을 충족했는가
- 현재 검색 결과를 막은 빈칸과 GraphQL/Redis/Git에서 반복된 빈칸은 각각 무엇인가
- 미래 DevOps 투자가 더 급한 응용 기술이나 회복을 밀어내고 있지 않은가
- 운동과 읽기 기준이 지속 가능했는가
- 이번 달 관계, 신앙, 생활에서 남은 것 하나가 있는가. 내용은 이 저장소가 아니라 별도 비공개 기록에 남긴다
- 새 목표를 열려면 무엇을 닫거나 보류해야 하는가
