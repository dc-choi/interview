# 현재 목표와 통합 로드맵

키노라이츠 퇴사 전환을 안전하게 마무리하고 경력 정리와 회사 밖 선택지를 순차적으로 실행하기 위한 상위 계획이다. 모든 목표를 동시에 실행하지 않고 성격에 따라 운영 방식을 나눈다.

## 현재 기준

- 사용자는 2026-09-01 키노라이츠 퇴사를 결정했다. 공식 통보 여부와 마지막 근무일은 확인되지 않았으므로 이미 퇴사한 것으로 간주하지 않는다.
- 남은 회사 일은 장기 적응 목표가 아니라 약속한 범위와 인수인계를 닫는 전환 의무로 관리한다. 평판과 에너지를 보존하면서 마무리한다.
- 다음 이직 지원을 지금 시작하는지는 확인되지 않았다. 현재 첫 개인 행동은 지금까지의 경력과 프로젝트 증거를 한 번 정리하는 것이다.
- 2026-08-10 당시 역할 연결을 근거로 시작한 검색 학습은 퇴사 결정으로 보류했다. 완료 처리하지 않고 [[OpenSearch#시작 전: 실물 익히기|현재 gate]]를 재개 지점으로 보존한다.
- 수학, DevOps와 SRE, JS, TS와 Node.js를 시작으로 한 범용 백엔드 학습은 후보로 보존한다. 퇴사 결정만으로 어느 트랙도 자동 시작하지 않는다.
- GraphQL, Redis와 Git을 포함해 남은 업무와 인계에 필요한 기술 보충은 정규 학습 진도로 계산하지 않는다.
- 주일학교 출석부 활성화는 퇴사 결정과 별개의 선택이다. 사용자가 활성화를 명시하기 전에는 Free Core의 최소 운영, 장애와 보안 대응, 데이터 보호 및 프로젝트 고정비 절감만 수행한다.
- 개인 고정비 절감은 퇴사 후 선택 가능한 기간을 늘리는 준비다. 개인 비용 금액은 이 저장소에 기록하지 않고 출석부의 프로젝트 비용 및 손익과 분리한다.

## 전체 WIP 상한

퇴사 전환 기간의 개인 활동은 다음 두 자리만 사용한다.

1. 유지 자리: 운동은 유지하고, 독서와 커리어 아웃풋 중 하나만 그 주에 선택한다.
2. 집중 자리: 정규 기술 학습, 생활 프로젝트와 회사 밖 선택지 실험 중 하나만 활성화한다.

남은 업무와 인계 또는 회복에 여력이 필요하면 집중 자리를 비운다. 검색 학습은 현재 위치를 기록하고 보류했으며 다음 선택 전까지 대체 트랙을 열지 않는다. 출석부의 선택지 보존 작업은 집중 자리를 점유하지 않고 필요한 최소 운영과 비용 조정만 처리한다. 사용자가 출석부 활성화를 명시하면 전체 WIP를 다시 계획한 뒤 제한된 기간의 실험 자리를 정한다. 놓친 활동을 다음 주에 더하지 않는다.

## 운영 바구니

### 1. 당장 해야 하는 일

고정 목록이 아니라 이번 주나 다음 주에 마감되거나 다른 사람의 일을 막는 항목만 둔다.

| 할 일 | 마감 | 완료 조건 | 다음 행동 하나 | 의존하는 사람/자료 | 예상 시간 |
|---|---|---|---|---|---|

- 남은 회사 업무와 퇴사 절차의 실제 상태는 회사의 공식 기록에서 관리한다.
- 개인 필수 항목을 별도로 추가하지 않는다. 유지 자리와 집중 자리에서 고른 다음 행동만 이번 주 필수 항목이 되며, 새 항목을 넣으려면 둘 중 하나를 교체한다.
- 현재 유지 자리의 다음 행동은 [[Performance-Evidence-Playbook|성과 증거 기준]]에 따라 경력과 프로젝트 목록을 만들고 각 항목의 직접 맡은 문제, 판단, 결과와 한계를 표시하는 것이다. 기한과 예상 시간은 아직 정하지 않아 당장 해야 하는 일 표에는 넣지 않는다.

### 2. 지속적으로 유지하는 일

퇴사 전환 기간에는 아래 최소 기준을 시험하고 월간 회고에서 조정한다. 실행 여부는 회고 근거 없이 완료로 간주하지 않는다.

- 집 운동은 주 2회, 회당 20분을 기준으로 삼고 못 한 횟수를 다음 주에 보충하지 않는다.
- 독서는 주 2회 20분, 커리어 아웃풋은 주 1회 중 하나만 그 주의 선택 유지 활동으로 고른다.
- 자기계발서를 고르면 한 번에 한 권만 읽고, 완독 수보다 현재 문제에 적용할 문장 하나를 남긴다.
- 커리어 아웃풋을 고르면 10분 말하기 또는 한 페이지 쓰기로 현재 학습이나 업무를 내부 세부 없이 설명한다.
- 집중 자리는 전환 의무와 회복을 확인한 뒤에만 열고, 업무 부담이 낮은 주에 1회 또는 2회 진행하며 밀린 진도를 압축하지 않는다.

말하기와 쓰기는 별도 강의를 하나 더 여는 일이 아니다. 이미 다룬 내용을 설명해 이해의 빈칸을 찾는 유지 습관이다. 정식 블로그 글은 해당 기술이 선택한 정규 트랙이나 공개 가능한 독립 재현과 연결될 때 완성한다.

전체 글감은 [[Career-Technical-Output-Backlog|커리어 기술 아웃풋 백로그]]에 보관한다. 목록 전체를 일정으로 바꾸지 않고 선택한 개인 트랙이나 공개 가능한 독립 재현과 연결된 초안 하나만 꺼낸다.

밀린 기술 책과 강의는 완주 자체를 별도 목표로 병행하지 않는다. 다음에 선택한 심화 트랙의 gate를 닫는 데 필요한 자료 하나만 고르고, 실험, 설명이나 작은 구현을 GitHub 기록으로 남긴 뒤 다음 자료를 연다.

### 3. 단일 심화 트랙

현재 활성 정규 학습 트랙은 없다. 검색은 완료가 아니라 보류이며 [[OpenSearch#시작 전: 실물 익히기|시작 전 gate]]를 재개 지점으로 보존한다. [[2026-H2-Math-Roadmap|수학 기초]]도 0단계 시작 전에서 보류 중이다.

다음 집중 자리는 아래 전환 gate를 모두 확인한 뒤 하나만 선택한다.

1. 남은 업무와 인계 범위를 확인한다.
2. 공개 가능한 경력과 프로젝트 증거를 한 번 정리한다.
3. 회복 상태, 주간 가용 시간과 이미 수락한 의무를 확인한다.
4. 독립 검색, [[2027-DevOps-Practical-Roadmap|DevOps와 SRE]], [[2026-H2-Math-Roadmap|수학]], [[Node-Core-Output-Roadmap|JS, TS와 Node.js 코어]] 또는 새 트랙 없음 중 하나를 고른다.

각 성공선을 닫을 때마다 같은 gate로 돌아온다. 남은 업무와 인계에 필요한 GraphQL, Redis, Git과 그 밖의 기술은 최소 범위만 보충하고 정규 트랙으로 자동 승격하지 않는다. 퇴사 결정만으로 구직이나 출석부 실험을 활성화하지 않는다.

### 4. 생활 프로젝트와 조건부 제품 선택지

운전면허와 전세는 같은 기간에 함께 열지 않는다. 필요 시점, 비용과 준비 시간을 확인해 하나를 4주짜리 생활 프로젝트로 올리며, 그 기간에는 집중 자리를 점유하던 트랙을 보류한다.

주일학교 출석부는 사용자가 별도로 활성화하기 전까지 Free Core의 최소 운영, 장애와 보안 대응, 데이터 보호 및 프로젝트 고정비 절감만 수행한다. 자발적으로 유입된 신규 조직의 현재 기능 사용은 막지 않지만 능동적 모집과 수동 온보딩은 하지 않는다. 개인 고정비 절감은 퇴사 후 선택 가능한 기간을 늘리는 별도 준비이며 프로젝트 손익에 섞지 않는다.

사용자가 출석부 활성화를 명시한 때를 제품 전환 gate로 삼는다. gate를 통과하면 진행 중인 개인 트랙의 위치를 기록하고 출석부의 현재 상태와 계측 준비를 먼저 확인한다. 준비가 끝나면 실험 시작일과 종료일을 동시에 정하고, 종료일에는 연장부터 논의하지 않고 장기 옵션을 판정한다. 정확한 실험 기간은 공개 승인 전 이 저장소에 다시 적지 않으며 활성화 시 보호된 운영 기록에 고정한다. 퇴사 결정만으로 신규 기능, 마케팅과 유료 실험을 시작하지 않는다.

## 회사 밖 선택지 대기열

아래 항목은 동시에 실행할 일정이 아니라 기존 WIP 상한과 전환 gate를 따르는 순차 후보다. 경력 정리는 유지 자리를 사용하고, 외주, 부업과 자동 매매는 집중 자리를 사용한다. 이미 수락한 외주가 있다면 선택 후보가 아닌 기존 의무로 보고 집중 자리를 다시 계획한다. 출석부 수익화는 별도 제품 전환 gate를 따른다. 각 후보는 시작일과 종료일, 성공 및 중단 기준을 함께 정하고 개인 수입, 비용과 계약 세부는 공개 vault에 기록하지 않는다.

1. 지금까지의 경력과 프로젝트 증거를 유지 자리의 커리어 아웃풋으로 정리한다. [[Performance-Evidence-Playbook|성과 증거 기준]]에 따라 직접 맡은 문제, 판단, 결과와 한계를 남기고 이력서 본문은 Notion 정본에서 관리한다.
2. 이미 수락한 외주가 있다면 약속한 범위까지 완료한다. 신규 외주는 범위, 일정, 보상 조건과 유지보수 부담이 명확한 한 건만 선택한다.
3. 지인에게 들은 부업 아이디어는 법적 조건, 플랫폼 정책, 초기 비용과 시간 부담을 확인한 뒤 작은 검증 하나만 연다.
4. 출석부의 카카오와 쿠팡 광고 및 제휴 후보는 제품 전환 gate와 재개 준비를 통과한 뒤 제한된 수익화 실험으로 판단한다. 활성화 시점의 정책, 사용자 영향과 측정 경계를 다시 확인한다.
5. 자동 매매 개발은 장기 기술 실험 후보로 두고 과거 데이터 백테스트와 모의 매매를 먼저 검증한다. 실거래 여부는 결과와 위험 경계를 별도로 확인한 뒤 결정한다.

## 퇴사 전환 중 기술 보충 원칙

남은 업무와 인계에 필요한 기술은 미래 투자나 호기심보다 먼저 다루되 최소 범위만 보충한다. 이를 새 정규 트랙으로 만들지 않고 아래 흐름으로 빈칸 하나를 닫는다.

```text
남은 업무 문제 또는 인계 위험
  → 원인, 영향 범위와 보호할 조건 확인
  → 필요한 개념과 최소 안전장치 결정
  → Task, PR, QA와 배포 또는 적용
  → 관측 결과, 복구 경계와 남은 위험 확인
  → 공개 가능한 문제, 판단, 결과와 한계 기록
  → 전환 의무와 회복 상태로 복귀
```

- GraphQL은 실제 요청 하나의 schema, resolver와 하위 데이터 흐름을 추적하고 오류, 인증, nullability 또는 N+1 중 해당 문제의 경계를 설명할 수 있을 때 빈칸 하나를 닫는다. 공개 문서에는 구조와 원리를 일반화해 남긴다.
- Redis는 실제 key의 정본, 자료구조, TTL, 무효화와 실패 시 동작을 추적하고 정확성, race condition 또는 stampede 중 해당 문제의 경계를 설명할 수 있을 때 빈칸 하나를 닫는다. 공개 문서에는 내부 key와 운영값을 남기지 않는다.
- Git은 현재 commit graph, working tree/index, local/remote ref와 upstream 상태를 먼저 읽고 merge, rebase, cherry-pick 또는 복구 선택의 이유를 설명할 수 있을 때 빈칸 하나를 닫는다. 실습 gate는 [[git#실무 학습 순서|Git 실무 학습 순서]]를 따른다.
- GraphQL, Redis와 Git은 반복 사용이 확인된 공통 실무 기반이다. 업무에서 얻은 근거를 비식별화한 한 페이지 설명이나 10분 말하기로 남기되 별도 대형 커리큘럼을 열지 않는다.
- 백엔드 업무에서는 배포와 롤백, 로그와 지표 및 알림, 실패와 복구, 런북과 회고 중 해당 문제에 필요한 한 경계를 결과 확인까지 닫는다. 실제 결과를 확인하지 못하면 예방 효과를 추정하지 않고 다음 확인 조건만 남긴다.
- 그 밖의 기술은 남은 책임과 인계에 필요하면 최소 범위만 보충하고, 다음 역할이나 독립 프로젝트에서 같은 빈칸이 반복될 때 개인 심화 후보로 올린다. 회사의 평가 기준을 공개 문서에서 추정하지 않는다.

사용했다는 사실이나 문서를 읽었다는 사실만으로 숙련 또는 로드맵 통과로 계산하지 않는다.

## 미래 DevOps 방향

지금 축적할 것은 도구 목록보다 백엔드 문제 또는 위험 발견, 안전한 변경, 배포, 관측, 복구와 재발 방지를 끝까지 닫은 증거다. 이는 데이터 흐름과 애플리케이션을 이해하는 DevOps와 SRE 역할로 이어지고, 이후 플랫폼 엔지니어링으로 확장할 수 있는 기반이지만 별도 정규 트랙을 열지는 않는다.

정식 DevOps 학습은 전환 의무와 회복을 해치지 않는 선택 gate에서만 연다. [[2027-DevOps-Practical-Roadmap|실전 로드맵]]에서 Linux 진단과 Terraform으로 인프라 변경 및 상태를 먼저 다루고, 최소 성공선을 닫은 뒤 다시 선택한 경우에만 Kubernetes, CI/CD와 SRE 및 복구로 확장한다. 남은 업무와 인계에 해당 기술이 필요하면 이 순서를 기다리지 않고 필요한 범위만 보충한다.

## 자격증 전환 조건

- AWS 자격증은 [[2027-DevOps-Practical-Roadmap|DevOps 핵심 실습]]으로 배포, 관측과 복구를 검증한 뒤 업무 필요와 시험 범위를 보고 판단한다.
- Kubernetes 자격증은 로컬 Kubernetes와 실제 운영 빈칸을 확인한 뒤 판단한다.
- 정보처리기사는 기술사 경로의 필요성과 시험 일정을 확인한 시점에만 연다. 준비 기간에는 다른 정규 심화 트랙을 멈춘다.
- 세 자격증을 동시에 준비하지 않는다.

## 퇴사 전환 운영

실제 마지막 근무일까지 다음을 우선한다. 마지막 근무일은 아직 확인되지 않았으므로 날짜를 추정하지 않는다.

- 이미 맡은 일과 합의한 범위를 확인하고, 새 장기 과제를 임의로 넓히지 않는다.
- 인계 대상마다 현재 상태, 결정 근거, 남은 위험, 다음 행동과 확인 방법을 남긴다.
- 회사 내부 사실과 공식 절차는 승인된 기록에서 관리하고 공개 문서에는 일반화한 경력 증거만 남긴다.
- 검색 학습은 현재 위치를 보존하고, 인계에 필요한 기술만 최소 범위로 보충한다.
- 경력과 프로젝트 증거를 한 번 정리하되 확인하지 못한 결과를 성과로 만들지 않는다.
- 구직, 출석부 실험과 다음 정규 학습은 각각 별도 결정 전까지 열지 않는다.
- 수면, 운동과 회복을 해치는 추가 약속은 받지 않고 이미 수락한 의무부터 확인한다.

## 월간 회고

- 남은 약속과 인계 범위는 무엇이며 다음 사람이 확인할 수 있는 상태인가
- 공개 가능한 경력 증거에서 문제, 판단, 결과와 한계가 구분됐는가
- 현재 회복 상태, 주간 가용 시간과 이미 수락한 의무는 무엇인가
- 보류한 검색을 포함해 다음 집중 자리 하나를 선택할 근거가 생겼는가, 아니면 비워 두는 편이 나은가
- DevOps와 SRE, 수학, Node.js, 독립 검색 중 지금 필요한 하나가 있는가
- 구직이나 출석부 실험을 별도로 시작하기로 결정했는가
- 운동과 읽기 기준이 지속 가능했는가
- 새 목표를 열려면 무엇을 닫거나 보류해야 하는가
