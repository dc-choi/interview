# 현재 목표와 통합 로드맵

키노라이츠 적응을 최우선으로 하면서 생활과 장기 개발자 성장 목표를 함께 잃지 않기 위한 상위 계획이다. 모든 목표를 동시에 실행하지 않고 성격에 따라 운영 방식을 나눈다.

## 현재 기준

- 이직 목표는 2026-06-29 키노라이츠 입사로 완료했다. 현재 서류 지원은 하지 않는다.
- 현재 가장 중요한 결과는 키노라이츠의 팀 맥락을 익히고 맡은 일을 독립적으로 끝내는 것이다.
- 기술 학습은 회사에서 실제로 쓰고 현재 결과에 연결되는 스택을 항상 먼저 고른다. 현재 역할 기술의 1순위는 검색이다.
- GraphQL, Redis와 Git은 검색보다 앞선 별도 목표가 아니라 실무에서 자주 쓰이므로 꾸준히 빈칸을 닫아야 하는 공통 기반이다.
- 수학은 현재 개인 학습 주축으로 보존한다. DevOps는 미래 역할을 위한 투자이며 검색과 다른 회사 기술보다 앞세우지 않는다.
- JS, TS와 Node.js를 시작으로 한 범용 백엔드 목표도 보존한다. 다만 전문화 경로와 동시에 정규 진도를 열지 않는다.
- 주일학교 출석부는 전체 TODO의 최하위 우선순위다. 사용자가 우선순위를 다시 올리기 전에는 시작하지 않는다.

## 전체 WIP 상한

키노라이츠 업무 이외의 개인 활동은 다음 두 자리만 사용한다.

1. 유지 자리: 운동은 유지하고, 독서와 커리어 아웃풋 중 하나만 그 주에 선택한다.
2. 집중 자리: 수학과 생활 프로젝트 중 하나만 활성화한다.

키노라이츠 업무 회복이 필요하면 집중 자리를 비운다. 운전면허나 전세를 활성화하면 수학은 현재 위치를 기록하고 보류한다. 주일학교 출석부는 이 자리의 후보가 아니다. 놓친 활동을 다음 주에 더하지 않는다.

## 운영 바구니

### 1. 당장 해야 하는 일

고정 목록이 아니라 이번 주나 다음 주에 마감되거나 다른 사람의 일을 막는 항목만 둔다.

| 할 일 | 마감 | 완료 조건 | 다음 행동 하나 | 의존하는 사람/자료 | 예상 시간 |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

- 키노라이츠 업무의 실제 상태는 회사의 공식 Task에서 관리한다.
- 개인 필수 항목을 별도로 추가하지 않는다. 유지 자리와 집중 자리에서 고른 다음 행동만 이번 주 필수 항목이 되며, 새 항목을 넣으려면 둘 중 하나를 교체한다.

### 2. 지속적으로 유지하는 일

첫 4주는 아래를 최소 기준으로 시험하고 월간 회고에서 조정한다.

- 집 운동: 주 2회, 회당 20분. 못 한 횟수를 다음 주에 보충하지 않는다.
- 선택 유지 활동: 자기계발서 주 2회 20분 또는 커리어 아웃풋 주 1회 중 하나를 고른다.
- 자기계발서를 고르면 한 번에 한 권만 읽고, 완독 수보다 현재 문제에 적용할 문장 하나를 남긴다.
- 커리어 아웃풋을 고르면 10분 말하기 또는 한 페이지 쓰기로 현재 학습이나 업무를 자료 없이 설명한다.
- 정규 심화 학습: 업무 부담이 낮은 주에만 1회 또는 2회 진행하고, 밀린 진도를 압축하지 않는다.

말하기와 쓰기는 별도 강의를 하나 더 여는 일이 아니다. 이미 다룬 내용을 설명해 이해의 빈칸을 찾는 유지 습관이다. 정식 블로그 글은 해당 기술이 정규 트랙일 때 완성한다.

전체 글감은 [[Career-Technical-Output-Backlog|커리어 기술 아웃풋 백로그]]에 보관한다. 목록 전체를 일정으로 바꾸지 않고 현재 회사 업무나 선택한 개인 트랙과 연결된 초안 하나만 꺼낸다.

밀린 기술 책과 강의는 완주 자체를 별도 목표로 병행하지 않는다. 현재 심화 트랙의 gate를 닫는 데 필요한 자료 하나만 고르고, 실험, 설명이나 작은 구현을 GitHub 기록으로 남긴 뒤 다음 자료를 연다.

### 3. 단일 심화 트랙

현재 정규 개인 학습 트랙은 [[2026-H2-Math-Roadmap|수학 기초]]다. 회사 기술은 이 gate를 기다리지 않고 현재 업무를 끝내는 데 필요한 만큼 먼저 학습한다. 별도 커리큘럼을 동시에 열지는 않으며 업무 부담이 크면 수학 속도를 낮추거나 현재 위치를 기록하고 보류한다.

수학 2단계 gate와 첫 90일 회고를 모두 마치면 첫 선택 gate를 연다. 이후 각 모듈의 성공선을 닫을 때마다 아래 순서로 후보를 다시 만든다.

1. 다음 계획 기간의 키노라이츠 책임과 직접 연결된 회사 기술
   - 현재 1순위인 검색
   - 검색 업무와 다른 Task에서 만난 GraphQL과 Redis의 미완료 빈칸
   - 현재 Task나 반복 책임에 연결된 JS, TS, Node.js, gRPC, Kafka와 그 밖의 기술
2. 긴급한 회사 기술 빈칸이 없고 미래 역할에 투자할 여력이 있을 때 [[2027-DevOps-Practical-Roadmap|DevOps]]
   - Terraform 성공선을 먼저 닫고 다시 선택한 경우에만 Kubernetes로 진행
3. 범용 백엔드 대기열의 다음 미완료 모듈
   - [[Node-Core-Output-Roadmap|JS, TS와 Node.js 코어]]
   - CS, OOP, 디자인 패턴과 헥사고날 및 클린 아키텍처
   - 시스템 디자인
   - MySQL
4. 새 트랙을 열지 않고 현재 책임과 회복에 집중

회사 기술, 미래 DevOps 투자, 범용 백엔드 대기열 순서로 우선한다. 회사 기술 안에서는 현재 맡은 검색 결과를 먼저 만들고, 그 과정에서 Task를 막는 빈칸, 사용 빈도와 결과 영향을 비교한다. GraphQL과 Redis는 심화 후보가 될 수 있지만 검색보다 높은 별도 1순위는 아니다. Git은 정규 트랙 후보로 올리지 않고 실제 상황과 맞는 [[git#상황별 작은 gate|작은 gate]] 하나만 닫는다.

Node.js가 현재 회사 업무와 직접 연결되면 1순위 회사 기술로 올라가고, 그렇지 않으면 범용 백엔드 대기열에 남는다. gRPC, Kafka, 검색과 추천도 실제 Task나 반복 책임이 생기면 회사 기술 후보로 올린다. DevOps 역시 회사의 현재 책임이 되면 미래 투자에서 회사 기술로 재분류한다.

### 4. 생활 프로젝트와 최하위 백로그

운전면허와 전세는 같은 기간에 함께 열지 않는다. 필요 시점, 비용과 준비 시간을 확인해 하나를 4주짜리 생활 프로젝트로 올리며, 그 기간에는 수학을 보류한다.

주일학교 출석부의 브랜딩, 마케팅, 기획, 설계, 개발과 운영은 전체 TODO의 마지막에 둔다. 현재 학습의 실습 무대나 집중 자리로 사용하지 않는다. 사용자가 우선순위를 명시적으로 다시 올린 경우에만 별도 계획을 만든다.

## 회사 기술 우선 원칙

회사에서 쓰는 기술은 미래 투자나 호기심보다 먼저 다루되 모두를 동시에 공부하지 않는다. 현재는 검색 업무를 가장 먼저 끝내고, 그 과정과 다른 Task에서 만나는 기술 빈칸 하나를 아래 흐름으로 닫는다.

```text
현재 업무 문제
  → 필요한 개념과 도구만 확인
  → Task, PR, QA 또는 운영 결과
  → 공개 가능한 작은 설명이나 결정 기록
  → 현재 정규 트랙으로 복귀
```

- GraphQL은 실제 요청 하나의 schema, resolver와 하위 데이터 흐름을 추적하고 오류, 인증, nullability 또는 N+1 중 해당 문제의 경계를 설명할 수 있을 때 빈칸 하나를 닫는다.
- Redis는 실제 key의 정본, 자료구조, TTL, 무효화와 실패 시 동작을 추적하고 정확성, race condition 또는 stampede 중 해당 문제의 경계를 설명할 수 있을 때 빈칸 하나를 닫는다.
- Git은 현재 commit graph, working tree/index, local/remote ref와 upstream 상태를 먼저 읽고 merge, rebase, cherry-pick 또는 복구 선택의 이유를 설명할 수 있을 때 빈칸 하나를 닫는다. 실습 gate는 [[git#실무 학습 순서|Git 실무 학습 순서]]를 따른다.
- GraphQL, Redis와 Git은 반복 사용이 확인된 공통 실무 기반이다. 업무에서 얻은 근거를 비식별화한 한 페이지 설명이나 10분 말하기로 남기되 검색보다 앞선 별도 대형 커리큘럼을 열지 않는다.
- 그 밖의 회사 기술은 현재 Task에 필요하거나 독립된 업무 두 건 이상에서 같은 빈칸이 반복되거나 리더가 반복 책임으로 확인하면 심화 후보로 올린다.

사용했다는 사실이나 문서를 읽었다는 사실만으로 숙련 또는 로드맵 통과로 계산하지 않는다.

## 미래 DevOps 방향

DevOps는 현재 회사 기술보다 앞서는 당장 과제가 아니라 미래 역할을 위한 투자다. 회사 결과와 회복을 해치지 않는 선택 gate에서만 열고, Terraform으로 인프라 변경과 상태를 먼저 다룬 뒤 gate를 다시 통과하면 Kubernetes로 배포와 운영을 확장한다. 미래에 회사 업무가 Terraform이나 Kubernetes를 요구하면 이 순서를 기다리지 않고 회사 기술 우선 원칙으로 필요한 범위를 먼저 해결한다.

## 자격증 전환 조건

- AWS 자격증은 [[2027-DevOps-Practical-Roadmap|DevOps 핵심 실습]]으로 배포, 관측과 복구를 검증한 뒤 업무 필요와 시험 범위를 보고 판단한다.
- Kubernetes 자격증은 로컬 Kubernetes와 실제 운영 빈칸을 확인한 뒤 판단한다.
- 정보처리기사는 기술사 경로의 필요성과 시험 일정을 확인한 시점에만 연다. 준비 기간에는 다른 정규 심화 트랙을 멈춘다.
- 세 자격증을 동시에 준비하지 않는다.

## 첫 90일 운영

2026-09-27까지는 다음을 우선한다.

- 맡은 작업 하나의 사용자 목적, 요청과 데이터 흐름, 소비자 영향, QA, 배포와 롤백을 설명한다.
- 리더, PM과 시니어 개발자의 기대 결과와 완료 조건을 면담 뒤 확인한다.
- 작은 업무라도 배포와 결과 확인까지 한 사이클을 닫는다.
- 기술 학습은 현재 검색 업무를 먼저 돕는다. GraphQL, Redis와 Git은 맡은 흐름에서 만난 빈칸을 닫고 공개 가능한 작은 설명을 남기되 별도 개인 커리큘럼은 열지 않는다.
- 수학은 가능한 주에만 진행하고, Node.js 정규 트랙과 자격증 준비는 열지 않는다.
- DevOps는 미래 투자로 대기시키고 현재 회사 기술과 적응을 밀어내지 않는다.
- 운전면허와 전세는 기본적으로 대기한다.
- 주일학교 출석부는 이보다도 낮은 최하위 백로그로 유지한다.

## 월간 회고

- 키노라이츠에서 새로 독립적으로 끝낸 업무 단위는 무엇인가
- 다른 역할의 결정이 필요했던 지점을 얼마나 일찍 공유했는가
- 다음 달의 업무와 생활 부담은 어느 정도인가
- 현재 심화 트랙을 유지할 근거가 있는가
- 현재 검색 결과를 막은 빈칸과 GraphQL/Redis/Git에서 반복된 빈칸은 각각 무엇인가
- 미래 DevOps 투자가 회사 기술이나 회복을 밀어내고 있지 않은가
- 운동과 읽기 기준이 지속 가능했는가
- 새 목표를 열려면 무엇을 닫거나 보류해야 하는가
