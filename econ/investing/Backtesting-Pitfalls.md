# 백테스트의 함정

> 한 줄 요약: 백테스트는 과거 데이터에 규칙을 적용한 가상 성과다. 조건을 여러 번 바꿔 가며 얻은 좋은 숫자는 우연을 골라낸 결과일 가능성이 크므로, 편향 제거, 비용 반영, 시도 횟수를 고려한 표본 외 검증을 거치기 전에는 초과수익(edge)의 근거로 보지 않는다.

이 문서는 개념 정리이며 투자 권유가 아니다.

## 1. 정의와 mental model

**백테스트**는 투자 전략을 과거 시장 상황에 적용해 그 전략이 당시 운용됐다면 어땠을지를 보여주는 시뮬레이션이다. 실제 돈이 움직인 기록이 아니므로 결과는 가상 성과(hypothetical performance)다. 미국 SEC의 투자자문업자 광고 규정(Marketing Rule)도 가상 성과를 어느 포트폴리오도 실제로 달성하지 않은 성과로 정의하고, 전략을 실제로 쓰지 않은 과거 기간의 데이터에 적용한 백테스트 성과를 명시적으로 포함한다.

mental model은 **검색 과정이 결과를 만든다**는 것이다.

- 규칙 하나를 한 번 검증한 결과와, 수십 개 규칙을 돌려 가장 좋은 것 하나를 보여준 결과는 같은 숫자라도 의미가 다르다.
- 무작위 보행(random walk) 데이터에서도 매개변수 조합을 충분히 탐색하면 표본 안에서 훌륭해 보이는 최적 전략이 나오고, 이 전략은 다른 데이터에서 대체로 무너진다. 예측 불가능한 데이터에서조차 좋은 백테스트를 만들 수 있다는 점이 핵심이다.
- 따라서 백테스트 결과를 읽을 때는 숫자와 함께 **몇 번 시도했는가, 어떤 데이터로, 어떤 비용 가정으로**를 같이 물어야 한다.

## 2. AI 코딩 에이전트와 자동화가 바꾸는 것

AI 코딩 에이전트로 시세와 수급 데이터를 매일 스캔하고, 조건을 말로 설명하면 백테스트 스크립트를 몇 분 안에 받는 흐름이 가능해졌다. 자동화 자체는 데이터 수집과 반복 점검의 비용을 줄이는 유용한 도구다. 다만 판단에 주는 영향은 두 방향이다.

- **시도 비용 하락은 과최적화 위험 상승과 같다.** 조건을 하나 더 붙여 다시 돌리는 비용이 거의 0이 되면 시도 횟수가 쉽게 늘고, 그중 가장 좋은 결과를 고르는 순간 데이터 스누핑이 된다.
- **생성된 코드의 정합성은 따로 검증해야 한다.** 날짜 정렬, 시차 이동(shift), 상장폐지 종목 처리 같은 작은 실수가 곧바로 미래 정보 누수나 생존 편향으로 이어진다. 결과가 좋을수록 코드를 의심하는 편이 안전하다.
- **분석 요약은 증거가 아니다.** 자동 생성된 코멘트나 요약은 입력 데이터와 가정 위에서만 의미가 있다.

## 3. 결과를 부풀리는 주요 편향

| 편향 | 무슨 일이 일어나나 | 점검 방법 |
|---|---|---|
| 미래 정보 누수(look-ahead bias) | 신호 계산 시점에 아직 알 수 없던 데이터(장 마감 뒤 공표 데이터, 사후 수정된 재무 수치, 당일 종가)를 사용 | 모든 입력에 사용 가능 시각을 붙이고, 신호 시각 이후 체결로만 매매 |
| 생존 편향(survivorship bias) | 현재 살아남은 종목만으로 과거를 검증해 상장폐지, 합병, 부실 종목이 빠짐 | 해당 시점에 실제 거래 가능했던 종목 전체(point-in-time universe) 사용 |
| 과최적화와 데이터 스누핑 | 조건과 매개변수를 반복 조정해 과거 잡음에 맞춤 | 시도 횟수 기록, 가설을 먼저 정하고 검증 |
| 다중 검정(multiple testing) | 많은 규칙을 검정하면 우연히 유의해 보이는 결과가 반드시 나옴 | 시도 횟수를 반영한 유의성 기준 적용 |
| 비용 누락 | 수수료, 세금, 호가 차이(스프레드), 슬리피지, 시장 충격 제외 | 보수적 비용 가정으로 재계산, 회전율 확인 |
| 선택적 제시(cherry-picking) | 성과 좋은 기간이나 종목만 보여줌 | 전체 기간과 하락장 구간 결과 요구 |

생존 편향은 실증 연구에서도 확인된 문제다. 살아남은 표본만 남기면 변동성과 수익률의 관계 때문에 실제로 없는 수익 예측 가능성이 나타나 보일 수 있다.

비용은 짧게 자주 사고파는 전략일수록 결정적이다. 국내에서는 주권 양도에 증권거래세가 부과되며, 세율은 법령 개정으로 달라질 수 있으므로 백테스트 기간마다 당시 세율을 적용해야 한다. 평균 수익률 몇 퍼센트짜리 전략은 왕복 비용과 체결 가격 차이만으로 상당 부분이 사라질 수 있다.

## 4. 표본 외 검증과 그 한계

- **표본 외 검증(out-of-sample, hold-out)**: 데이터를 나눠 한쪽에서 규칙을 만들고 다른 쪽에서 확인한다. 필요하지만 충분하지 않다. 표본 외 결과를 보고 다시 규칙을 고치면 그 구간도 사실상 학습 데이터가 되고, 시도 횟수를 통제하지 않으면 두 구간 모두에서 좋아 보이는 전략도 찾아낼 수 있다.
- **워크포워드 검증(walk-forward)**: 과거 구간으로 규칙을 정하고 바로 다음 구간에서 성과를 기록한 뒤 창을 앞으로 옮기며 반복한다. 실제 운용 순서를 흉내 내 미래 정보 누수를 줄이지만, 한 가지 역사적 경로만 검증하므로 시도 횟수 문제는 여전히 남는다.
- **시도 횟수를 반영한 평가**: 학계에서는 여러 방법이 제안돼 있다. 조합 대칭 교차검증(CSCV)으로 백테스트 과최적화 확률(PBO)을 추정하는 방법, 시도 횟수와 비정규성을 반영해 샤프 비율을 할인하는 Deflated Sharpe Ratio, 수백 개 요인이 검정된 현실을 감안해 새 요인의 t값 기준을 2.0보다 높은 3.0 수준으로 올려야 한다는 다중 검정 관점이 대표적이다.
- **실거래 기록(paper trading, 소액 실거래)**: 가상 성과 대신 실제 체결과 비용이 반영된 기록이 쌓여야 비교할 수 있다. 가상 성과를 받으면 실제 과거 운용 성과가 무엇인지 물어보라는 것이 SEC 투자자 교육 자료의 권고다.

## 5. 예시: 승률과 평균 수익률만 있는 결과

수급 조건 백테스트를 가정하자. 특정 투자자 유형이 며칠 연속 순매수한 종목을 다음 날 사서 며칠 보유하는 규칙이 승률 50%대 후반, 평균 수익 2%대로 나왔고, 조건을 하나 더 붙이자 승률과 평균 수익이 함께 올랐다. 이 숫자만으로 알 수 없는 것은 다음과 같다.

- **기준 비교**: 같은 보유 기간에 시장 지수나 무작위 종목을 샀을 때도 비슷한 승률과 수익이 나왔는가. 상승장 구간이면 대부분의 매수 규칙이 좋아 보인다.
- **분포와 위험**: 평균 수익률은 소수의 큰 수익에 끌려갈 수 있다. 손실 크기, 최대 낙폭, 수익의 표준편차가 없으면 위험 대비 성과를 판단할 수 없다.
- **표본의 독립성**: 보유 기간이 겹치는 신호는 서로 독립이 아니어서 체감 표본 수보다 실제 정보량이 적다.
- **조건 추가의 의미**: 조건을 붙여 성과가 좋아졌다는 사실은 시도가 한 번 더 늘었다는 뜻이기도 하다. 조건을 붙일수록 표본이 줄어 우연의 영향이 커진다.
- **실행 가능성**: 신호에 쓴 수급 데이터가 매수 시점에 실제로 공개돼 있었는지, 체결 가격이 시가인지 종가인지, 거래량이 적은 종목에서 원하는 가격에 살 수 있었는지.

사례: 공개 SNS 게시물에서 AI 코딩 에이전트로 이런 규칙(기관 3일 연속 순매수 종목을 다음 날 매수해 5일 보유)의 백테스트를 90초 만에 만들고, 조건 추가 전후로 승률 58.3%에서 63.7%, 평균 수익 2.1%에서 2.8%가 나왔다는 예가 소개됐다. 이 수치는 작성자 주장이며 재현하거나 검증하지 않았고, 거래비용, 생존 편향, 시도 횟수에 대한 정보가 없어 위 점검 항목 어느 것도 판단할 수 없다.

장기 적립 시뮬레이션도 같은 함정에 빠진다. 월 10만원을 40년 적립할 때 월 복리 단순 계산으로 연 19%면 약 119억원, 10%면 약 6억원, 7%면 약 2.6억원이라, 평균 수익률 가정 하나로 결과가 수십 배 흔들린다. 2배 레버리지 ETF의 역사적 평균 수익률을 그대로 넣은 계산이라면 다음을 먼저 확인한다.
- **산술평균 대신 기하평균**: 적립금이 불어나는 속도는 기하평균이 정한다. +50% 뒤 −50%는 산술평균 0%지만 연 기하평균은 약 −13.4%이고, 변동성이 클수록 차이가 벌어진다.
- **레버리지의 경로 의존성**: QLD는 나스닥 100 지수 일간 수익률의 2배를 목표로 하며, 운용사도 하루를 넘는 보유 기간의 수익률은 목표 배수와 크게 다를 수 있고 변동성이 높을수록 불리하다고 밝힌다.
- **최악 구간과 순서 위험**: 평균 대신 최대 낙폭과 가장 나빴던 시작 시점의 경로를 넣는다. 적립 후반에 큰 하락이 오면 쌓인 금액 전체가 맞는다.
- **배당 성장 가정**: 배당 ETF의 미래 월배당 추정은 과거 배당 성장률이 수십 년 이어진다는 가정이다. 배당 삭감과 성장 둔화 경로를 함께 계산한다.

## 6. 백테스트 다음: 자동 주문의 가드레일

증권사와 거래소 API로 잔고, 시세와 주문을 코드로 다루는 일은 어렵지 않다. 예를 들어 토스증권 Open API 문서는 국내와 미국 주식의 시세, 계좌와 보유 종목, 주문 REST API와 실시간 웹소켓을 제공한다. 병목은 연결이 아니라 무엇을 언제 사고팔지 정한 규칙이고, 그 규칙은 앞 절의 검증을 거친 것이어야 한다. 검증 안 된 규칙을 자동화하면 손실만 빨라진다.

- **키 권한 최소화**: 업비트는 API 키 발급 때 자산 조회, 주문, 출금 기능을 골라 부여하고, 주문하기나 출금하기를 쓰는 키는 IP 주소 등록이 필수다. 출금 권한을 빼면 키가 유출돼도 외부 출금 경로는 막히지만, 주문 권한만으로도 손실을 낼 수 있으므로 키 보관과 IP 제한은 그대로 필요하다.
- **호출 한도**: 한도를 넘기면 429 응답을 받는다. 바이낸스는 429 뒤에도 물러서지 않고 반복 위반하면 IP를 자동 차단(418)하며, 차단 시간은 반복 위반에 따라 2분에서 3일까지 늘어난다. `Retry-After` 대기와 재시도 간격 증가를 처음부터 설계한다.
- **사람 승인 단계**: 규칙은 판정과 주문 제안까지만 하고 사람이 승인해야 주문이 나가게 하면, 코드 오류와 비정상 시세가 곧바로 주문으로 번지는 것을 막는다. 사례: 매일 장 초반 보유 손익과 200일 이동평균 조건을 판정해 알림을 보내고, 한 번의 승인 뒤 주기적으로 도는 집행기가 주문하며 체결 로그를 남기는 구성이 공개됐다.
- **실시간 시세**: 짧은 주기 판단에는 REST 반복 조회보다 웹소켓 구독이 맞다. 다만 데이터가 빨라져도 분할 매수 같은 규칙이 추세장과 횡보장에서 다르게 작동하는 한계는 그대로다.
- **금액 한도**: 자동 주문 계좌에는 잃어도 감당할 수 있는 금액만 두고, 주문당, 일별 금액 한도를 코드에 건다.

## 7. 트레이드오프와 한계

- 백테스트는 버릴 아이디어를 빨리 걸러내는 도구로는 가치가 크다. 나쁜 결과는 대체로 믿을 만하고, 좋은 결과는 추가 검증의 출발점일 뿐이다.
- 편향을 모두 제거해도 과거 시장 구조, 참여자, 제도가 미래에 유지된다는 보장은 없다. 학술 연구로 공개된 수익 예측 변수 97개를 추적한 연구에서는 포트폴리오 수익이 표본 내 기간 대비 표본 외 기간에 26%, 논문 공개 뒤에 58% 낮았다.
- 엄격한 검증에는 point-in-time 데이터, 상장폐지 이력, 체결 모형이 필요해 개인이 갖추기 어렵다. 갖추지 못한 부분은 결과의 한계로 명시한다.
- 시도 횟수 보정 기법도 전제가 있다. 기록되지 않은 시도, 머릿속에서 먼저 걸러낸 아이디어는 보정에 들어가지 않는다.
- 규칙 기반 전략은 감정적 매매를 줄이는 장점이 있어 [[Behavioral-Biases-Risk|행동 편향과 리스크 관리]]와 맞닿지만, 좋은 백테스트 숫자는 오히려 과신 편향을 키울 수 있다.

- [ ] 지금까지 시도한 조건과 매개변수 조합 수를 기록하고 있는가
- [ ] 모든 입력 데이터의 공개 시각과 체결 시각의 순서를 확인했는가
- [ ] 상장폐지와 합병 종목이 포함된 시점별 종목 집합을 썼는가
- [ ] 수수료, 세금, 스프레드, 슬리피지를 보수적으로 반영했는가
- [ ] 시장 지수나 무작위 선택 같은 기준과 비교했는가
- [ ] 최대 낙폭, 손실 분포, 표본 수를 함께 봤는가
- [ ] 검증 구간을 한 번만 사용했고, 그 결과를 보고 규칙을 다시 고치지 않았는가
- [ ] AI가 생성한 백테스트 코드의 날짜 처리와 시차 이동을 직접 검토했는가
- [ ] 결과를 실제 돈을 넣을 근거가 아니라 다음 검증 단계의 근거로만 쓰고 있는가
