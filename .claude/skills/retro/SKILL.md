# 회고

데일리, 주간, 월간, 행사나 프로젝트 종료 회고를 대화형으로 진행하고, 사용자가 확인한 사실과 결정만 기록한다. 회고는 다음 주기 행동 하나로 닫는다.

## 시작 전 로드

1. 루트 `CLAUDE.md`, `fit/CLAUDE.md`, `fit/growth/habits/Retrospective-Methods.md`와 `fit/growth/retrospectives/회고(Retrospectives).md`를 읽는다.
2. 회고 주제와 유형에 맞는 정본만 추가로 읽는다.
   - 성장 우선순위, WIP나 습관을 다루는 데일리, 주간 및 월간 회고: `fit/growth/Current-Goals-and-Roadmap.md`
   - 키노라이츠 업무 및 커리어 월간 회고: 위 로드맵의 월간 회고, `fit/growth/career-stages/Kinolights-Engineer-Growth-Direction.md`의 진행 중인 행동 실험과 월간 점검, `fit/growth/Kinolights-Performance-Playbook.md`의 기록 루프와 점검 시점
   - 행사나 프로젝트 종료: 사용자가 지정한 계획, 결과와 피드백 자료 및 대상 경로의 `CLAUDE.md`
3. 학습 주제나 트랙 상태를 판단할 때만 `fit/growth/learning/CLAUDE.md`와 해당 로드맵을 읽는다.
4. 같은 대상이나 기간의 기존 회고와 작업 트리 상태를 확인한다. 다른 변경은 수정하거나 함께 묶지 않는다.

면접 회고는 기존 `fit/interview/` 구조와 면접 도메인 지침을 따르고 일반 회고 폴더로 옮기지 않는다.

## 유형과 범위 확정

- 사용자가 유형, 기간이나 대상을 지정하면 그대로 따른다.
- 데일리는 사용자가 지정한 날짜를 따르고, 날짜가 없으면 현재 날짜를 기본으로 제안한다. 하루가 끝나지 않았다면 지금까지의 회고임을 밝힌다.
- `TIL`이나 `Today I Learned` 요청은 데일리 회고로 다룬다. 이미 작성된 학습 메모나 자료를 주제 문서로 정리하는 요청은 `memo`의 범위다.
- 주간은 가장 최근에 끝난 주, 월간은 가장 최근에 끝난 달력월을 기본으로 제안한다.
- 행사나 프로젝트 회고는 대상, 완료 시점과 기대했던 결과를 확인한다.
- 해석이 기록 범위를 바꿀 때만 한 문장으로 확인한다.
- 실제 업무 상태와 사내 근거는 사용자에게 묻는다. vault 문서, 커밋 수와 `status: done` 수를 성과나 숙련도로 해석하지 않는다.

## 대화 진행

한 번에 최대 세 질문만 묻고, 답을 짧게 정리해 확인받은 뒤 다음 블록으로 간다.

1. 기대와 사실: 무엇을 하려 했고 실제로 무엇이 일어났는가
2. 결과와 피드백: 확인된 결과, 차이, 감정과 받은 피드백은 무엇인가
3. 원인과 배움: 무엇을 유지하고 멈추거나 바꿀 것인가
4. 결정: 다음 주기에 실행할 행동 하나와 확인 시점은 무엇인가

- 데일리 회고는 TIL을 기본으로 오늘의 사건, 감정, 배움과 다음 행동을 짧게 본다.
- 주간 회고는 KPT를 기본으로 현재 WIP와 회복 가능성을 함께 본다.
- 월간 회고는 주제에 맞는 정본의 현재 질문만 조합하고 질문 목록을 스킬에 복제하지 않는다.
- 행사나 프로젝트 회고는 프로세스 개선이면 CSS, 경험과 감정까지 다루면 4L을 기본으로 삼는다.
- 답을 대신 만들거나 빈칸을 추정하지 않는다. 확인되지 않은 항목은 `미확인`으로 둔다.
- 후보가 여러 개면 파격적 집중에 따라 행동 하나를 먼저 고른다.

## 기록 경계

- 이 저장소의 일반 성장 회고는 `fit/CLAUDE.md`가 지정한 `fit/growth/retrospectives/`의 유형별 폴더에 기록한다.
- 관계, 신앙과 생활의 구체적인 내용은 공개 저장소에 기록하지 않는다. 별도 비공개 회고 여부와 운동, 독서처럼 공개 정본에서 이미 관리하는 습관의 상태 및 공개 가능한 결정은 남길 수 있다.
- 별도 비공개 저장소나 문서를 자동으로 만들지 않는다. 사용자가 명시적으로 요청할 때만 다룬다.
- 타인의 실명과 연락처, 본인의 처우 금액, 내부 링크, 사내 Task ID, 비공개 운영 수치와 민감한 운영 정보를 쓰지 않는다.
- 공개할 수 없는 결과는 상태만 일반화하고 추정값으로 대체하지 않는다.

## 파일 생성

같은 회고가 있으면 새 파일보다 기존 파일을 갱신한다.

- 데일리: `daily/Daily-Retro-YYYY-MM-DD.md`
- 주간: `weekly/Weekly-Retro-YYYY-Www.md`
- 월간: `monthly/Monthly-Retro-YYYY-MM.md`
- 행사: `events/Event-Retro-YYYY-MM-DD-{주제}.md`
- 프로젝트나 마일스톤: `projects/Project-Retro-YYYY-MM-DD-{주제}.md`

주제에는 경로 구분자를 쓰지 않고 공백과 파일명에 부적합한 문자를 하이픈으로 정규화한다.

```yaml
---
tags: [fit, growth, retrospective, {daily|weekly|monthly|event|project}]
status: done
category: "Fit - 성장"
aliases: ["회고를 식별하는 이름"]
---
```

본문은 190줄 안에서 기대와 범위, 사실과 결과, 배움과 피드백, 다음 행동, 관련 문서 순서로 쓴다. 새 파일은 해당 유형 폴더의 인덱스에 실존 링크로 추가한다.

## 확정된 결정 반영

- WIP, 유지 기준이나 집중 자리가 바뀌면 `Current-Goals-and-Roadmap.md`의 해당 정본만 갱신한다.
- 학습 트랙 상태가 바뀌면 가장 구체적인 로드맵을 먼저 갱신하고 참조 문서의 상태 표현만 동기화한다.
- 커리어 스탠스가 바뀌면 `fit/AGENTS.md`를 갱신한다.
- 행사나 프로젝트의 후속 문서는 사용자가 확정한 행동이 직접 영향을 줄 때만 최소 수정한다.
- 기술 사례 전환, 비공개 기록 생성, 커밋과 푸시는 사용자가 별도로 요청할 때만 수행한다.

## 완료 확인

- 다음 행동 하나와 확인 시점이 명확한가
- 사실, 해석과 미확인이 구분됐는가
- PII, 비공개 정보와 사적 생활의 상세 내용이 공개 파일에 없는가
- 파일명, 인덱스 링크와 문서 길이가 규칙을 지키는가
- 수정 파일만 `git diff --check`를 통과하는가

끝에는 결정, 남은 미확인과 변경한 파일만 간단히 보고한다.
